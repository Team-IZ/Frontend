# UX 행동 규범 (기능명세서 v8에서 전수 추출한 노출·표현·정보밀도 통제 규정)

이 문서는 기능명세서 v8의 처리 로직·비즈니스 규칙·비고·예외 case에 흩어져 있는 **화면 표현 통제 규정**을 전수 추출한 것이다. 색상·레이아웃(design-system-anchor.md)과 별개로, **무엇을 어떻게 보여주면 안 되는가**를 규정한다. 모든 화면정의서·와이어프레임은 이 규범을 위반하면 안 되며, 각 화면정의서는 자신에게 해당하는 규칙을 "## UX 준수 규칙" 섹션에 명시해야 한다.

## A. 용어·라벨링 — 낙인 방지 (자동화 편향 Skitka 1999 · 낙인 효과 Becker 1963)

| # | 규칙 | 근거 FR |
|---|---|---|
| A1 | **'프리라이더' 명칭 사용 금지.** UI 전면에서 서술형 표현 '기여·이해도 불균형' 또는 '기여 패턴 편차'만 사용한다. v7에서 기능명 자체가 "프리라이더 의심 뷰" → "기여·이해도 불균형 분석 뷰"로 변경됨. 확정형 라벨 요청이 와도 서술형으로 변환(DASH-11 case5) | ENG-04, DASH-11 |
| A2 | **확정형 명사 라벨은 근거 트레이스 동반 없이 단독 노출 금지.** 모든 시그널 라벨(위험 포함)은 "어느 축이 언제부터" 식 근거 문구와 한 세트로만 렌더링 | ENG-04, DASH-10 case6 |
| A3 | **기여량 단독 표시·판정 금지.** 기여 지표는 항상 이해도 점수와 교차해서만 표시. 기여량 데이터만 존재하면 후보 표시 자체를 차단 | MEAS-02A, ENG-04, DASH-11 case1 |
| A4 | **등급(소유/표면/미흡)은 최종 회차에만 부여·표시.** 중간 회차는 추이·시그널만 | ENG-02 |
| A5 | **확정 표현 금지, 권고형 문구만.** 개입 타이밍 등 운영 문구는 "과도한 확정 표현을 제거하고 권고형 문구로 변환" | DASH-05 |
| A6 | **안정성 배지는 이진 상태(안정/재검토)만, 임의 문구 금지.** 배지는 매니저의 다음 행동과 연결될 때만 의미 있음(안정=진행, 재검토=DASH-16 진입) | DASH-09 (Q10) |
| A7 | **표본 부족 시 시스템 확정 판단 생성 금지** — 단 매니저의 수동 선택까지 막지 않음(기본값 '모니터링 유지' + 오버라이드 가능) | DASH-08 |

## B. 온디맨드·정보 밀도 — 한 화면에 다 펼치지 않는다

| # | 규칙 | 근거 FR |
|---|---|---|
| B1 | **클릭 전 근거 데이터 렌더링 금지.** 리포트 수치의 상세 근거는 해당 수치 클릭 시에만 패널로 로드(성능·정보과다 방지, Q17 채택 확정). 클릭 전 근거 렌더링 요청은 차단 | RPT-05 |
| B2 | **벤치마크 비교는 온디맨드 패널.** 카드에는 칩만, 상세 비교는 클릭 시 | DASH-04 |
| B3 | **면담 체크리스트는 자동 생성 금지, 온디맨드 필수.** 매니저의 명시적 '면담 질문 추출' 클릭에만 생성 | RPT-03 |
| B4 | **요약 우선 + 상세는 링크/진입.** 매니저 화면용 요약 문구와 상세 근거 링크를 분리 생성. 카드에는 핵심 근거 1줄, 전체 맥락은 DASH-16(교육생 상세) 진입으로 | DASH-05, 카드 패턴 |
| B5 | **교육생 상세(SC-M06)는 통합 표시하되 탭/패널로 구획** — 추이·세션전문·근거·귀속·개입이력을 한 화면에 평면 나열하지 않는다 | DASH-16 |

## C. 근거 필수 — 근거 없는 수치·순위·추천 금지

| # | 규칙 | 근거 FR |
|---|---|---|
| C1 | **근거 없는 수치 노출 차단.** 리포트의 모든 수치는 근거와 연결, 불일치 시 패널 노출 차단 | RPT-01 case2, RPT-05 case3 |
| C2 | **근거 문구 없는 순위 표시 금지.** 우선순위 카드에는 N위·실제 값·수식 구성요소·사유 문구를 함께 표시 | DASH-03 |
| C3 | **근거 없는 추천·질문 생성 금지.** 개입 추천은 '유형 — 트리 경로 근거' 형태로만 | INTV-01, RPT-03 |
| C4 | **근거 trace 없는 시그널은 노출 자체를 차단** | DASH-10 case1 |
| C5 | **회차 종속 통계는 기준 회차를 반드시 명시한다.** 기수 평균·기수 표준편차·백분위(하위/상위 N%)·상대 위치는 모두 **회차 due_at 시점 스냅샷**이므로 회차마다 값이 다르다. "기수 평균 78점"처럼 스칼라로 적으면 (a) 매니저가 상수로 오독하고 (b) **백엔드가 전 회차 평균으로 구현해 S·Priority 전체가 틀어진다.** 표기 규칙: 값마다 "6회차 기수 평균 78점" 또는 섹션 상단에 "N회차 종료 기준"을 선언(SC-M08 방식) | DASH-04(steps 1-2), DASH-03(step 4), DASH-10(step 2) |
| C6 | **기수 평균은 회차 단위로 부재할 수 있다 — 전체/전무로 처리 금지.** DASH-04 case2("due_at 시점 확정 점수 부재 시 비교값 비표시")는 **특정 회차만** 발동한다. 비교선·비교값은 해당 회차 구간만 끊고 나머지 회차는 유지하며, 끊긴 구간에 사유를 표시한다 | DASH-04 case2, DASH-10 case3 |

## F. 채점 축·배점·회차 독립성 (ENG-01, MEAS-02B) — 의미 규범

| # | 규칙 | 근거 FR |
|---|---|---|
| F1 | **채점 5축은 ENG-01이 정의한 것만 쓴다 — 창작 금지.** `코드이해 · 설계논리 · 대안비교 · 반례대응 · 자기수정`. 화면·문구·차트·표 어디서도 다른 축 이름(설계/구현/테스트/협업/설명력 등)을 만들지 않는다. **실제로 창작해서 제품의 핵심 측정 대상이 통째로 틀렸다** | ENG-01 step2, 비즈니스 규칙 |
| F2 | **배점은 축당 1~5점, 총 25점 만점.** 개인 축 점수는 정수 1~5, 기수 평균·총점 평균은 소수 허용(집계값). **100점 스케일 금지** | ENG-01 step4, 비즈니스 규칙 |
| F3 | **채점 축과 지표를 구분한다.** `이해도`는 ENG-01 5축 종합점수의 별칭이므로 사용 가능(DASH-11 step1·3에 "ENG-01 이해도 점수"·"이해도 축"). 그러나 `참여도·팀진행률·응시율`은 DASH-01의 **운영 지표**, `설명력·성장률`은 DASH-12의 **에이스 판정 지표**, `기여 편차`는 ENG-03의 **독립 개념**이다 — 이 넷을 채점 5축 자리에 넣지 않는다 | DASH-01, DASH-11, DASH-12, ENG-03 |
| F4 | **축별 점수에는 근거 구간(evidence span)이 반드시 동반된다.** 근거 미탐지 축은 점수 확정 중단(case1), 근거 부재 시 결과 폐기 후 재채점(case2) | ENG-01 step4·5 |
| F5 | **회차 측정은 매 회차 독립.** 이전 회차 DP·세션 결과를 입력으로 쓰지 않고 **해당 회차 커밋 스냅샷만**으로 추출. 화면에 "신규 커밋 기준 · 이전 회차 컨텍스트 미사용" 명시 | MEAS-02B 규칙, 서비스플로우 v3 |

## D. 교육생 노출 통제

| # | 규칙 | 근거 FR |
|---|---|---|
| D1 | **루브릭·채점 근거·프롬프트는 교육생 비노출**(매니저 전용). 직접 노출은 다음 회차 게이밍 유발 | ENG-01, MEAS-07, RPT-02, DASH-09 |

| D5 | **GOV-03 공개범위(전체/요약/비공개) 설정을 모든 교육생 노출 지점에서 준수** | GOV-03 |

## E. 자동확정 금지 (GOV-02) — 화면 표현에 미치는 영향

| # | 규칙 | 근거 FR |
|---|---|---|
| E1 | **AI 생성 결과는 항상 '추천/제안' 상태로 표시**, 확정은 매니저 액션 버튼으로만. 자동확정 UI(자동 저장·자동 적용) 금지 | GOV-02, CUR-02 |
| E2 | **모순 문구 금지 — 카드에서 조용히 사라지지 않음.** 개입 타이밍 문구는 항상 표시하되 상태만 전환 | DASH-05 |
| E3 | **이의 기각에는 사유 필수**(사유 미입력 시 제출 차단) | GOV-01 |

---

**적용 방법:** 각 화면정의서는 위 규칙 중 자신에게 해당하는 것을 "## UX 준수 규칙" 섹션에 규칙 번호(A1, B1...)로 인용하고, 와이어프레임이 그 규칙을 어떻게 구현했는지 한 줄씩 명시한다. 해당 없는 화면(예: 인증 화면)은 "해당 규칙 없음"으로 표기한다.
