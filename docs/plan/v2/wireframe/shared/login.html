AU-01 · 공통 · 비로그인

로그인

v1 구조 그대로다. 레이아웃(좌 브랜드 · 우 폼)과 문구 규칙이 바뀌지 않았고, 브랜드 카피에서 죽은 개념(5축 채점 · 소크라틱)만 지금 명제로 갈아 끼웠다. 바뀐 것은 하나 — 미인증(이메일 인증)이 미활성(초대 활성화)로 대체됐다.

  • 하나의 로그인이다. 역할별로 나누면 사용자가 자기 역할을 알아야 로그인할 수 있는데, 역할은 내부 개념이다. 서버가 판정해 초기 화면으로 보낸다.
  • 회원가입 링크가 없다. 계정은 전부 초대로 생긴다(AU-02).
  • 어느 쪽이 틀렸는지 말하지 않는다. 이메일만 맞다고 알려주면 어떤 주소가 가입돼 있는지 알려주는 셈이다. 연속 실패 시 남은 시도 횟수도 노출하지 않는다.
  • 계정을 잠그지 않는다 — 지연만 준다. 명단에 전원 이메일이 있으니 잠금을 두면 아무나 남을 못 들어오게 만들 수 있고(3번 틀리면 끝), 풀어 줄 화면도 사람도 없다. 비밀번호를 잊은 사람의 정상 경로는 재설정(AU-03)이다. 무차별 대입은 재시도 간격을 늘리는 것으로 막는다.
  • 이메일 인증 단계가 없다. 초대 링크 클릭이 곧 이메일 소유 증명이라(AU-02) 미활성 계정에는 초대 메일을 다시 보낸다 — 인증 메일이 아니다.
  • 알림은 비밀번호 아래 · 버튼 위다. 폼 위쪽에 두면 알림이 뜰 때 그 아래 전부가 밀려난다 — 재시도할 때마다 입력 필드가 커서 밑에서 움직인다. 지금 자리는 방금 누른 버튼과 다시 칠 비밀번호 사이라 시선을 옮길 필요가 없다. 빈 값·형식 오류처럼 필드에 귀속되는 것만 필드 아래에 붙인다.
  • 폼 박스 높이를 고정했다(440px). 위치만 옮기면 절반만 해결된다 — 폼이 세로 중앙 정렬이라 알림이 뜨면 박스가 커져 중앙이 다시 계산되고 제목까지 위로 올라간다. 높이를 박아 두니 아래 8개 상태의 시작 위치가 전부 같다. 값의 근거는 가장 긴 상태(알림 2줄 + 재발송 링크)다.
  • AUTH-03 예외를 아래에 전량 그렸다. 단 둘은 묶었다 — 토큰 발급 실패 · 롤백 · 쿠키 실패는 사용자에게 같은 문구고(할 수 있는 일이 재시도 하나뿐인데 원인을 나누면 내부 사정을 알려주는 것 말고 하는 일이 없다), 잠금 발생 · 잠금 재진입은 잠금을 안 쓰기로 해서 지연 하나로 합쳤다. 계약(에러코드 · API · 부수효과)은 정의 문서 §6에 있다.

AUTH-03 예외
1자격 불일치AUTH_INVALID이메일 또는 비밀번호가 올바르지 않습니다→ 재입력 · 어느 쪽이 틀렸는지 말하지 않는다#bad
2·3연속 실패 지연AUTH_THROTTLED
+ retryAfter		시도가 너무 잦습니다. {n}초 후 다시 시도해 주세요 · 대기 창 동안 제출 비활성→ 대기 · 남은 시도 횟수는 노출하지 않는다#throttled
4미활성 계정AUTH_UNVERIFIED초대 링크로 먼저 계정을 활성화해 주세요 + [초대 메일 다시 받기]→ 재발송 · 인증 메일이 아니다#inactive
5정지된 계정AUTH_INACTIVE사용이 중지된 계정입니다 + 문의→ 문의#suspended
6토큰 발급 실패AUTH_TOKEN_ISSUE일시적 오류입니다. 잠시 후 다시 시도하세요→ 재시도#sysfail
7롤백AUTH_ROLLBACK상동 — 로그인 미완료 처리→ 재시도#sysfail
8쿠키 설정 실패AUTH_COOKIE상동 — 서버가 DB 토큰 폐기 후 실패 처리→ 재시도#sysfail
9권한 컨텍스트 결여AUTH_NO_CONTEXT계정 권한 설정에 문제가 있습니다 + 문의→ 문의 · role·org_id 부재로 로그인 차단#noctx
· 문구는 계약값이다. 그대로 쓴다 — 요약하면 구현할 때 각자 달라지고, 계정 열거 방지 같은 보안 규칙이 문구에 실려 있어 바꾸면 규칙이 깨진다.
· 에러코드는 프론트 타입과 같은 값(src/features/auth/authTypes.ts). 문서와 코드가 다른 이름을 쓰면 매핑표가 하나 더 생긴다.
· 6·7·8은 목업이 한 장이다(#sysfail). 서버는 셋을 구분해 처리·기록하지만 사용자가 할 수 있는 일은 재시도 하나뿐이라 화면은 하나 — 그림 3장은 같은 그림이다.
· 2·3은 한 행으로 합쳤다. v1은 잠금 발생·잠금 재진입 2행이었는데 v2는 계정을 잠그지 않는다 — 명단에 전원 이메일이 있어 잠금이 남을 못 들어오게 만드는 수단이 되고, 풀어 줄 화면도 사람도 없다.
· 왜 그렇게 정했는지는 정의 문서에 있다 — 잠금을 안 쓰는 이유 · 감추는 것 · 알림 위치 근거.
