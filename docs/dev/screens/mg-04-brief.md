## MG04-1 · MG-04 면담 브리프 구현 — 정의서·와이어에 없는 빈틈 5건 판단

- **배경:** MG-03 다음 로드맵인 MG-04(면담 브리프)를 정의서(`docs/plan/v2/definition/MG-04-interview-brief.md`)·와이어(`manager/interview-brief.html`)만 보고 신규 구현. 정의서·와이어가 예시로 든 케이스(김민준 DECLINE·한지우 첫 면담·오세림 무효 응시)는 그대로 옮겼지만, 이 화면을 실제로 열 수 있는 MG-03 mock 케이스 7개(PLANNED 상태 전부) 중 나머지 4개(이서준·최유나 1차·최유나 3차)는 두 문서 어디에도 없어 이 세션이 직접 채웠다.
- **판단:**
  1. **"첫 면담"은 회차 번호가 아니라 "이 학생에게 DONE 면담 기록이 있는가"로 재정의했다.** 와이어 #first 장면은 회차 라벨이 "미프 2차"인데 이 저장소엔 그 회차가 없다 — 라벨을 억지로 맞추는 대신 `findPriorInterview`(현재 회차보다 이전 회차 중 같은 학생의 DONE 케이스 탐색)로 판정을 일반화했다. 그 결과 한지우(`iv-3-5`, 3차에서 처음 등장)가 자연히 "첫 면담" 조건을 만족한다.
  2. **①의 여는 말 문장(비교형/비비교형)은 위험 유형이 아니라 위 "첫 면담" 판정으로 갈린다.** 한지우는 DECLINE(0→2, from이 있음)인데도 비교 문장을 안 쓴다 — 헤더 배지의 "0→2" 숫자는 원본 그대로 두고, ①의 문장만 이전 면담 유무로 고른다. 지속 저점(LOW_PERSISTENT)은 `from`이 없어 비교 문장을 쓸 때 지난·이번 모두 같은 `lowCount`를 넣는다(이서준 `iv-3-3`).
  3. **막힌 개념 목록(`CASE_CONCEPTS`)을 이 파일에 새로 만들었다** — 정의서 §4는 "세션·교안 섹션"에서 읽는다고 했지만 이 레포에 세션-면담 연동이 없다. "Graph 구성"을 김민준 말고 최유나(`iv-3-2`)에게도 겹쳐 반 문제(9-6, "반 절반 이상") 서술이 앞뒤가 맞게 했다. 교안 위치("N장 P–Q쪽")는 `curriculum/mockData.ts`를 참조하지 않았다 — `interviews/mockData.ts` 머리말이 이미 정한 "역할 간 mock cross-import 전례 없음" 원칙을 그대로 따라, 표시용 문자열을 이 파일에 독립적으로 붙였다.
  4. **"설명·표현 어려움"의 ④ 목적지는 정의서·와이어 어디에도 예시가 없다.** 나머지 6개 원인은 표나 장면에 하나씩 있는데 이것만 없어, "개념은 아는데 표현이 안 되는" 경우로 보고 매니저가 다음 면담에서 직접 다시 설명해 보게 하는 것(매니저 소관, 전달만이 아님)으로 채웠다. **팀장님 확인이 필요하면 알려달라고 다음 세션 인계에 남긴다.**
  5. **③ 원인을 하나도 안 골랐을 때 ④ 자리는 와이어 원문("③에서 고르면 보낼 곳이 나타납니다")을 그대로 쓰고, 정의서 6절의 별도 문구("고르지 않아도 저장할 수 있어요…")는 따로 안 만들었다** — 저장 자체를 막지 않는 것으로 그 뜻이 이미 충족된다고 판단.
  6. **"코드 매칭 0" 개념 제외·각주(정의서 6절)는 구현하지 않았다** — 이번 7개 케이스 어디에도 해당 예시가 없어 검증 방법이 없다. `ConceptRef.zeroMatch?` 필드만 남겨 뒀다.
  7. **"저장 실패"(#savefail) 모달은 화면·핸들러를 정의서·와이어대로 만들되, mock이 강제로 실패시키지는 않는다** — 이 파일의 다른 mock API(`excludeCase`·`undoExclude`·`resolveVoid`)도 전부 항상 성공하는 이 레포 기존 관례를 그대로 따랐다.
  8. **MG-03 mock 데이터 하나를 이 세션에서 고쳤다** — `iv-2-2`(김민준 2차 DONE) `interview.nextAction`을 `null`→`'담당 기능 흐름 그려오기'`로. 와이어 #brief 장면의 "지난 면담(6/22)에서 정한 것" 예시가 이 케이스를 인용하는데 원래 값이 `null`이라 인용할 게 없었다. 부수 효과로 MG-03 목록의 2차 "마지막 활동" 열도 "없음"→해당 문구로 바뀐다(회귀가 아니라 실제 있어야 할 값이 채워진 것).
- **검산:** `/tmp` 격리 복사(레포 전체) → `tsc --noEmit -p tsconfig.app.json`·`-p tsconfig.node.json` 둘 다 통과, `prettier --check` 통과(1차 포맷 오류 2개 파일 → `--write` 반영 후 재검증 통과), `node scripts/check-design.mjs` 통과. `oxlint`·`vite build`는 이 샌드박스의 알려진 네이티브 바인딩 문제로 실행 불가. **브라우저 렌더 확인은 아직 안 함** — 다음으로 미룬다.
- **목적·효과:** MG-04가 placeholder에서 실제 화면으로 바뀐다. `InterviewListScreen`의 `[브리프 열기]`가 실제 데이터를 채운 브리프로 연결되고, 저장하면 케이스 상태가 예정→종결로 바뀌어 MG-03 목록에도 반영된다.

**같은 세션 이어서(렌더 전 사용자 피드백) — 용어·표기 6건 반영:**

- 블록 번호를 원문자(①②③④)에서 일반 숫자(1·2·3·4)로 — 파란 원 배지 안에서 크기·정렬이 안 맞는다는 지적. `size-5` 원 안에서 `text-xs leading-none tabular-nums`로 다시 맞췄다.
- **③ "들은 것"→"원인", ④ "보낼 곳"→"조치"로 개명.** 사용자가 "애매하다"며 추천을 요청 — 정의서 원문이 이 두 블록을 이미 "원인 체크박스"·"라우팅 스위치"로 부르고 있어(§3), 그 어휘를 그대로 화면 라벨로 올렸다. "조치"는 각 목적지 줄의 "매니저/전달만" 오너 표시와도 자연스럽게 맞는다(누가 조치하는지).
- 기록 카드 "어디로 보냈나" 힌트 오탈자 수정 — `&#9314;`(③)로 잘못 옮겨져 있던 걸 원문 `&#9315;`(④)로. 실제로도 이 값은 ④(조치) 선택 결과를 합친 것이라 ④가 맞다.
- 기록 필드 라벨 변경 — "무엇 때문이라고 했나"→"원인"(③ 블록 이름과 짝을 맞춤, 칩은 분류·텍스트는 서술), "다음에 할 것"→"추후 계획"(저장 확인 모달 문구도 같이 바꿈).
- **검산:** `/tmp` 격리 재검증 — `tsc --noEmit`(app·node)·`prettier --check`·`check-design.mjs` 전부 통과(포맷 수정 없이 1차 통과). 브라우저 렌더 확인은 여전히 다음으로 미룬다.

**같은 세션 이어서 — 기록 카드 라벨 겹침·시각 구분 3건:**

- **③ 블록 제목 "원인"과 기록 카드 필드 라벨 "원인"이 겹친다는 지적 — 기록 카드 쪽을 "상세 사유"로 바꿨다.** ③은 정의서 어휘를 그대로 쓴 구조적 분류(칩)이고, 기록 카드 쪽은 매니저가 직접 타이핑하는 서술(학생이 뭐라고 설명했는지)이라 내용 성격이 다르다 — 같은 이름을 쓰면 "칩 선택이 자동으로 여기 들어가나?"는 오해가 생긴다. ④ "조치"는 기록 카드 필드도 같은 이름으로 남겼다 — 이쪽은 실제로 ④의 내용을 그대로 미러링하는 자동 필드라 이름이 같아도 오해가 없다(구분은 "4에서 자동 반영" 힌트가 한다).
- 기록 카드 "어디로 보냈나" → **"조치"**로, 힌트 "4에서 자동" → **"4에서 자동 반영"**으로(사용자 지시, XX 자리 추천).
- **직접 입력 칸과 자동 채움 칸의 시각 구분이 없다는 지적** — 자동 채움 칸(조치)만 배경을 `bg-surface-2`(입력칸과 동일)에서 `bg-input/60`(공용 `Textarea.tsx`가 비활성 상태에 이미 쓰는 `disabled:bg-input/50`과 같은 토큰)로 바꾸고 `cursor-not-allowed`·`aria-readonly`를 추가했다 — 새 색을 만들지 않고 이 레포가 이미 "못 건드리는 입력"에 쓰는 관례를 그대로 가져왔다.

## MG04-2 · 종결(DONE) 후에도 브리프를 다시 열 수 있게 — 정의서·와이어 밖 흐름을 사용자 지시로 추가

- **배경:** MG-03 목록에서 상태가 종결이면 `RowActions`가 `null`을 반환해 액션 열이 통째로 비었다(브리프 열기·제외 둘 다 안 보임). 사용자가 스크린샷을 보고 "특별한 이유가 없으면 종결 후에도 브리프를 열거나 제외할 수 있게 하자, 다시 열면 이전에 쓴 내용이 그대로 있어야 한다"고 지시. 정의서 7절은 "약속 이행 추적은 하지 않는다"만 말할 뿐 재오픈 자체를 막지 않는다 — 막아야 할 근거를 찾지 못해 그대로 열었다.
- **판단:**
  - **브리프 재오픈은 허용.** `InterviewListScreen`의 `RowActions`가 DONE에도 `[브리프 수정]` 버튼(ghost, PLANNED의 primary "브리프 열기"와 구분)을 그린다. `InterviewBriefScreen`은 `mockData.ts`의 새 필드 `InterviewCase.interview.causes`·`.why`(기존엔 `date`·`nextAction`만 저장했다)를 읽어 `BriefData.savedRecord`로 내려주고, `BriefSheet`가 `useState` 초깃값으로 그대로 복원한다. 저장 버튼 문구도 `savedRecord` 유무로 "저장하고 종결"/"저장"을 가른다(이미 종결된 걸 또 "종결"이라고 하면 거짓 신호가 된다).
  - **제외는 DONE에 추가하지 않았다 — 이건 사용자 지시를 그대로 안 따르고 되돌린 지점이다.** "제외"는 정의서 §6에서 "예정" 케이스를 이번 회차 대상 큐에서 빼는 동작이다(9-4, 되돌릴 수 있다). 이미 면담이 끝난(DONE) 케이스를 "제외"한다는 게 상태 모델상 의미가 없다 — 종결과 제외가 동시에 성립하는 상태를 만들 이유도 없고, `excludeCase`가 그 전이를 처리하지도 않는다. "특별한 이유가 없으면"이라는 사용자의 단서를 이 판단으로 충족했다고 보고, 반대하면 되돌린다.
  - `saveInterviewBrief`의 상태 가드를 `status === 'PLANNED'`에서 `status !== 'EXCLUDED'`로 넓혔다 — DONE 케이스를 다시 저장해도 상태는 그대로 DONE, 제외된 케이스만 저장 자체가 막힌다(제외 후 브리프로 못 돌아오는 것과 같은 이유).
- **검산:** `/tmp` 격리 재검증 — `tsc --noEmit`(app·node)·`prettier --check`·`check-design.mjs` 전부 1차 통과. 브라우저 렌더 확인은 다음으로 미룬다.
- **목적·효과:** 종결된 면담도 다시 열어 원인·상세 사유·추후 계획을 고칠 수 있다. 잘못 적었거나 면담 후 새로 알게 된 내용을 반영할 방법이 생긴다.

## MG04-3 · "전체 이력"·이름 클릭이 D-1(조회 권한 없음)으로 막히던 문제 — `trainees/mockData.ts`에 9명 추가(사용자 승인)

- **배경:** MG-04 브리프의 "전체 이력 ↗", MG-03 목록의 이름 클릭이 전부 `TraineeDetailScreen`의 D-1 안내("조회 권한 없는 교육생입니다")로 막힌다는 스크린샷 제보. 원인 확인: `features/manager/interviews/mockData.ts`가 쓰는 `traineeId`(`t-kim-minjun` 등)가 `features/manager/trainees/mockData.ts`의 실제 `TRAINEES` id(`t-1`~`t-12`, 완전히 다른 12명)와 처음부터 안 맞았다 — D-1 자체는 MG-06이 의도한 대로 정상 동작 중이었고, **이번 세션이 만든 버그가 아니라 MG-03 때부터 있던 두 mock 데이터 간극**이다.
- **판단:** `trainees/mockData.ts`는 최근 주요 커밋이 팀장님(jxxnixx) 것이라(`git log --follow`) CLAUDE.md §7에 따라 확인 없이 고치지 않고 먼저 사용자에게 3가지 선택지를 제시 — ① 9명 새로 추가(기존 12명은 안 건드림) ② 그대로 둠(알려진 한계로 안내만) ③ 팀장님께 먼저 확인. **사용자가 ①을 선택.** `TRAINEES` 배열 끝에 면담 화면이 실제로 참조하는 9명(이서준·최유나·김민준·오세림·한지우·박도현·강윤서·정하늘·서지훈)을 인터뷰 mock과 **같은 id·이름**으로 새로 추가했다. 기존 `t-1`~`t-12` 12명은 이름·값 전부 그대로 — diff는 순수 추가만(삭제 0줄).
- **범위를 좁힌 지점:** `rounds`(회차 격자)·`TRAINEE_DETAIL_OVERLAY`(MG-06 타임라인)는 채우지 않았다. `getTraineeDetailOverlay`가 오버레이 없는 id를 `{ timeline: [] }`로 이미 정상 처리하므로(§6 "아직 응시한 회차가 없습니다"), 9명은 상세 화면에 진입은 되지만 회차 격자·타임라인은 빈 상태로 보인다 — 면담 화면의 죽은 링크를 살리는 목적엔 이 정도로 충분하고, 9명분 회차·타임라인을 새로 지어내는 건 이번 요청 범위 밖이라 판단했다.
- **검산:** `/tmp` 격리 재검증 — `tsc --noEmit`(app·node)·`prettier --check`·`check-design.mjs` 전부 1차 통과. 브라우저 렌더 확인은 다음으로 미룬다.
- **목적·효과:** MG-03·MG-04의 이름·"전체 이력" 링크 9명 전부가 이제 실제 상세 화면으로 연결된다(회차·타임라인은 빈 상태).

## MG04-4 · 무효 응시 "시스템이 본 것"이 브리프 재오픈 후 사라지던 문제 — `voidEvidence`·`voidConfirmed` 분리

- **배경:** 사용자가 오세림(무효 응시) 브리프를 열었더니 목업엔 있는 "시스템이 본 것"(무응답·복사·응답 시간) 박스가 안 보인다고 지적. 원인 확인: MG-03의 `resolveVoid('KEEP')`이 "그대로 두기"를 고르면 `c.voidEvidence`를 지워버렸다(MG-03 당시엔 "재확인 대상에서 뺀다"는 뜻으로 지운 것) — 그 값을 MG-04 브리프도 그대로 읽고 있어서, 이미 확인된 무효 응시 케이스는 증거 자체가 없어 박스가 렌더되지 않았다.
- **판단:** 하나의 필드가 "증거 데이터"와 "확인 여부 플래그" 두 역할을 겸하던 게 근본 원인이라 판단, `InterviewCase`에 `voidConfirmed?: boolean`을 신설해 역할을 분리했다. `voidEvidence`는 이제 절대 안 지운다(브리프가 몇 번을 다시 열어도 "시스템이 본 것"을 보여줄 수 있다). `resolveVoid('KEEP')`은 `voidEvidence = undefined` 대신 `voidConfirmed = true`. MG-03 쪽에서 `voidEvidence` 유무로 판단하던 자리 3곳(`RowActions`의 "무효 확인" 게이트, `LastActivityCell`의 "확인 완료" 표시, `RiskReason`에 넘기는 `voidResolved`)을 전부 `voidConfirmed` 기준으로 바꿨다 — 동작(무효 확인 버튼이 한 번만 뜨는 것 등)은 그대로다, 데이터 모델만 정리됐다.
- **검산:** `/tmp` 격리 재검증 — `tsc --noEmit`(app·node)·`prettier --check`·`check-design.mjs` 전부 1차 통과.
- **목적·효과:** 무효 응시 브리프는 "그대로 두기"로 확인된 뒤에도 다시 열 때마다 시스템이 관찰한 근거를 그대로 보여준다. MG-03의 기존 동작(확인 게이트·완료 표시)은 회귀 없이 유지.

## MG04-5 · MG-04 브리프 전체화면(사이드바 가림) 설계를 번복 — `ConsoleShell`로 통일(정의서 §2 오버라이드)

- **배경:** MG-04 정의서 §2는 "형태: 전체화면 · 사이드바 가림"을 명시적으로 규정했고, TR-03 검증 세션과 같은 논리("화면이 다르게 생긴 것 자체가 지금 작업 중이라는 신호")로 이 세션이 그대로 구현했다(MG04-1). 렌더 스크린샷을 본 사용자가 "다른 매니저 화면은 다 셸이 있는데 브리프만 앱 자체가 사라지는 느낌이라 어색하다"고 지적.
- **판단:** 이건 구현 디테일이 아니라 **정의서가 명시한 설계를 뒤집는 것**이라 바로 고치지 않고 3가지 선택지(① 절충 — 상단바만 남기고 사이드바만 가림 ② 통일 — ConsoleShell로 감싼다 ③ 정의서대로 유지)를 제시했다. **사용자가 ②를 선택.**
- **반영:** `InterviewBriefScreen.tsx`를 `ConsoleShell role="manager"`로 감쌌다. 기존 전체화면 모드바(52px 고정 바, 사이드바 없이 앱 배경을 직접 칠하던 구조)를 걷어내고, 다른 상세 화면(교안 상세 등)이 쓰는 패턴 그대로 `PageHeader`(sr-only 제목·breadcrumb) + `← 목록으로 (저장 안 함)` 링크 + 이름·반·위험배지·회차 정보 줄로 바꿨다. "나가는 길"(목록으로·취소 버튼)은 그대로 유지 — 사이드바를 가리는 것과 별개로 "매니저 도구라 잘못 열 수 있다"는 정의서 §2의 취지 자체는 유효하다고 판단해서다. 4블록·기록 카드·저장/취소·다이얼로그 등 콘텐츠 쪽은 손대지 않았다(폭 상한 820px만 유지).
- **범위:** `docs/plan/v2/definition/MG-04-interview-brief.md` 원문은 고치지 않았다 — 이 레포는 정의서 번복을 decision-log로 기록하고 정의서 자체는 최초 설계 근거로 남겨두는 관례다(MG08-1·MG08-8 등 기존 사례와 동일).
- **검산:** `/tmp` 격리 재검증 — `tsc --noEmit`(app·node)·`prettier --check`·`check-design.mjs` 전부 1차 통과. 브라우저 렌더 확인은 다음으로 미룬다.
- **목적·효과:** 브리프도 다른 매니저 화면과 같은 셸(사이드바·헤더)을 유지한 채 열린다 — 앱을 벗어난 느낌 없이, 그래도 "지금 이 사람 면담 중"이라는 신호는 이름·위험배지·나가는 링크로 계속 준다.

## MG04-6 · 상단 정보 줄 축소 + 목록 필터 세션 유지 + 여는 말 위험 유형별 재작성

세 지적을 한 세션에서 반영, 근거를 한 항목에 묶는다(서로 이어지는 지적이라).

- **① 상단이 지저분하다** — breadcrumb("면담 › 7기 › A반")과 우측 회차 요약
  ("미프 3차 · 2단 이하 1 → 2")을 뺐다. 남긴 건 뒤로가기(아이콘 버튼으로 교체,
  기존 "← 목록으로 (저장 안 함)" 텍스트 링크 대신 `Curriculum` 상세 화면과 같은
  `ArrowLeft` 아이콘 버튼 — `aria-label`로 "저장 안 함" 경고는 스크린리더용으로
  남겼다) · 이름 · 반·기수 · 위험 배지뿐이다. 회차·판정 숫자를 뺀 이유는 ①
  여는 말이 이미 그 숫자를 자연스러운 문장으로 말해줘서 중복이었다고 판단해서다.
- **② 뒤로가기 시 필터 유지, 새로고침하면 초기화, 기본 회차는 마지막 회차** —
  `filterState.ts`에 모듈 전역 변수(`sessionFilters`)를 신설해 `InterviewListScreen`
  이 마운트될 때 거기서 초깃값을 읽고 변경마다 다시 쓴다. `localStorage`가 아니라
  모듈 전역을 쓴 이유는 요구 자체가 "SPA 안에서는 남고 새로고침하면 사라진다"라
  `localStorage`(새로고침에도 남음)·URL 쿼리(둘 다 남음) 둘 다 안 맞아서다. 기본
  회차 `'3'` 하드코딩은 `ROUND_OPTIONS[ROUND_OPTIONS.length - 1].value`(가장 마지막
  회차)로 바꿨다 — 회차가 늘어도 다시 안 고쳐도 된다.
- **③ 여는 말이 다 비슷하고 어색하다** — "점수 얘기를 하려는 게 아니라, ~"류
  정형화된 변명 문구를 전부 뺐다. 전엔 "이전 면담 유무"로 비교/비비교 두 템플릿만
  썼는데, **위험 유형 4종(무효 응시·단계 하락·지속 저점·관찰) 각각 고정 문장**으로
  다시 썼다(사용자 지시 — 무효 응시·단계 하락·지속 저점 3종을 직접 요청, 관찰은
  같은 설계 원칙을 적용해 이번 세션이 같이 채웠다). `mockData.ts`의 `openingLine()`
  이 숫자만 계산해 내려주고, 문장 자체는 `InterviewBriefScreen.tsx`의
  `renderOpeningLine()`이 고정 템플릿으로 갖는다(LLM 0회 원칙 유지). "지난 면담
  유무"는 이제 여는 말과 무관하다 — 그 정보는 원래도 별도 줄("⚠ 지난 면담(날짜)에서
  정한 것")이 담당하고 있어서, 여는 말 자체는 위험 유형만 보고 결정해도 정보
  손실이 없다.
- **검산:** `/tmp` 격리 재검증 — `tsc --noEmit`(app·node)·`prettier --check`·
  `check-design.mjs` 전부 1차 통과.
- **목적·효과:** 상단이 이름·위험 배지 중심으로 단순해지고, 목록 화면을 오가도
  작업 맥락(회차·필터)을 잃지 않는다. 여는 말은 케이스마다 실제로 다르게 들린다.
