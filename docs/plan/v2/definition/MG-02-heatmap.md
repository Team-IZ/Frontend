### 셀에는 값만, 라벨은 튀는 셀에만 — v1 방식

v1 히트맵은 셀이 대부분 **맨 숫자**였고 `취약 / 주의`는 평균 행과 눈에 띄는 셀에만
달렸다. 그게 맞다 — **전부 달면 라벨이 배경이 되어 아무것도 강조되지 않는다.**

| 값 | 라벨 |
|---|---|
| `< 2.5` | 취약 |
| `2.5 ~ 2.7` | 주의 |
| 그 위 | 없음 |
| **개인 셀** | **없음** — 2단 이하가 다수라 라벨이 배경이 된다. 색 + 셀 테두리로 충분 |

`무엇을 / 왜 그렇게` 같은 단계 서술도 셀에서 뺐다. **셀마다 문장을 반복하면 셀이
넓어지고 표가 가로로 늘어나 비교가 안 된다.** 히트맵은 **한눈에 훑는 표**이지 읽는
표가 아니다. 셀 폭 **92px 고정**, 열 너비에 맞춰 늘리지 않는다.

**단계 뜻은 개인 뷰 표 아래 한 줄**로만 둔다 — `1단 무엇을 · 2단 왜 그렇게 · 3단 다른
방법 · 4단 언제 깨지나`. 반·팀 뷰는 평균이라 필요 없다. 상시 세로 목록으로 띄우면
**매번 읽는 정보가 아닌데 화면 예산을 상시로 쓴다.**

### 좌상단에 축 안내 · y축 폭 150px 고정

`개념 1 / 개념 2 / 개념 3`만 있으면 **그 열이 무엇인지 모른다.** 표 좌상단(비는 칸)에
축을 쓴다.

```
세로 팀 › 팀원          개념 1        개념 2       개념 3
가로 이 회차의 검증 개념 3건  HITL Trigger  Graph 구성   State 관리
```

**y축 칸은 150px 고정**이다. 안 그러면 `담당 반`·`김민준`·`4팀`의 글자 길이가 달라
**화면마다 히트맵 시작 x가 움직인다** — 계층을 오갈 때 표가 좌우로 흔들려 시선이 매번
다시 찾는다. 범례와 단계 안내도 같은 160px 들여쓰기로 첫 셀에 맞춘다.

### 글자 크기 — 셀 밖 텍스트는 12px 이상

10~11px로 깔았다가 올렸다. 히트맵 자체가 작고 주변 텍스트가 다 회색이라 **읽히지
않는 장식**이 됐다.

| | 전 | 후 |
|---|---|---|
| x축 개념명 | 12px 보통 | **13px 굵게** |
| 행 그룹 안내 | 10px 대문자 | **12px** |
| 위험 배지 | 10px | **12px** |
| 범례 · 단계 안내 | 11px | **12px** |

**셀 안 `under` 밑줄도 지웠다** — 2단 이하 표시였는데 색이 이미 같은 말을 하고, 일부
셀에만 그어져 무슨 뜻인지 알 수 없는 장식이었다.

### 범례는 히트맵 바로 아래 — 툴바 오른쪽이 아니라

**범례는 표를 읽는 열쇠라 표에서 멀어질수록 표 → 범례 → 표 왕복이 생긴다.** 오른쪽
카드에 넣었다가 툴바 오른쪽 끝으로, 다시 **히트맵 바로 아래**로 옮겼다 — 이 화면의
히트맵은 3열이라 폭이 좁고 왼쪽에 붙어 있어서, **툴바 오른쪽 끝은 표에서 가장 먼
자리**였다.

### 판정은 표 아래 한 줄

세 자리를 다 시도해 보고 아래로 정했다.

| 자리 | 문제 |
|---|---|
| 표 **위** | 표보다 먼저 읽혀 **표를 볼 이유를 뺏는다.** 아래 표가 확인용으로 밀린다 |
| 표 **오른쪽** | 268px 안에서 문장이 4~5줄로 꺾여 빽빽해지고, 표 폭이 줄어든다 |
| 표 **아래** | **읽는 순서가 곧 시선 순서** — 빨간 셀을 발견하고 바로 아래에서 그게 뭔지 확인한다 |

```
[프로젝트 미프3차▾] [반별|팀|개인] [정렬▾] [⚠반 문제만]   취약 ■■■■■ 양호  ▨ 문항 없음

          개념1      개념2      개념3
담당 반    2.8       2.5 주의    3.3
A반        2.6 주의  [1.9 취약]  3.4
C반        2.8        2.4 취약   3.2
B반        3.0        2.6 주의   3.3
─────────────────────────────────────────────────────
⚠ A반 · Graph 구성  23명 중 12명이 2단 이하 — 절반을 넘어 반 문제
                                    [A반 자세히 보기] [오퍼레이터에게 공유]
```

한 줄 + 액션이라 **발견 → 확인 → 행동**이 끊기지 않는다.

### 판정은 세어지는 것만

사이드에 *"개념 자체가 어려웠을 가능성이 커요"* 같은 문장을 썼다가 지웠다. **그건
원인 추정이고, 추정하려면 지금 없는 데이터가 필요하다** — 교안 난이도, 다른 기수 비교,
선수 개념 이력. 없는 데이터로 쓴 문장은 **화면이 아는 척하는 것**이다.

다만 **세어지는 것에서 멈추면 안 된다.** `23명 중 12명`만 쓰면 매니저가 그게 무슨
뜻인지 다시 해석해야 한다 — **그래서 뭘 하라는 것까지** 말한다.

| 뷰 | 판정 |
|---|---|
| 반별 | **A반 · Graph 구성이 반 문제** — 23명 중 12명이 2단 이하. 절반을 넘어 **개인 위험 사유에서 빠지고 반 전체 안내 대상**. 개인을 부르기 전에 팀별로 먼저 확인 |
| 팀 | **네 팀 모두 절반 초과 — 팀 문제가 아니다.** 팀별 면담이 아니라 **반 전체 안내**가 맞고, 개인 면담에서 이 개념을 사유로 쓰지 않는다 |
| 개인 | **김민준·이서준 단계 하락** — 0개 → 2개. **Graph 구성은 반 문제라 빼면** 남는 건 **HITL Trigger 하나**. 면담은 그것부터 |
| 다시 보기 | **2명 회복** — 리포트만 보고 스스로 오르는 개념이라 면담에선 다른 걸 먼저. **위 평균은 1차 기준** |

경계는 그대로다 — **어디서 막혔나 + 그래서 뭘 하나**는 쓰고, **왜 막혔나**는 안 쓴다.
앞의 둘은 이 화면의 값과 판정 규칙에서 나오지만, 원인은 화면 밖에 있다.

PRODUCT.md — **어디서 막혔는가는 말하고 왜 막혔는가는 말하지 않는다.** 원인은 화면
밖에 있고 매니저가 물어봐야 안다. 판정은 **어디서**까지만 말하고 버튼으로 넘긴다.

### 와이어프레임 각주는 화면 밖에

`· 열은 그 회차의 검증 개념 3건입니다…` 같은 설명을 앱 본문 안에 뒀다가 뺐다. **그건
실제 UI에 나갈 글이 아니라 리뷰어용 메모**인데, 브라우저 크롬 안에 있으면 사용자가
읽어야 할 글처럼 보인다. 목업에서는 **크롬 밖 회색 주석**으로 내린다.

### 각 계층마다 선택 필터와 정렬

`반별`은 사실상 **담당 반 전체 뷰**다. 계층을 내려갈수록 대상이 좁아지므로 **그 계층에서
필요한 선택 도구**를 툴바에 둔다.

| 화면 | 툴바 |
|---|---|
| **반별** | 프로젝트 · 계층 · **정렬**(낮은 순) · **⚠ 반 문제만** |
| **팀** | 〃 · **반 select** · 정렬 |
| **개인** | 〃 · **반 · 팀 select** · 정렬 · **위험만** |

**드릴다운으로만 내려가게 하면 매번 위에서부터 눌러야 한다.** select가 있으면 반·팀을
바로 바꾼다.

**툴바 크기는 프로젝트 목록과 같다** — 알약형 34px, 12px. 프로젝트 select만 13px 굵게로
한 단계 크다(이 화면의 변수라서).

### 회차 비교 토글 자리에 프로젝트 select

v1은 `현재 상태 / 회차 비교` 토글이었다. v2는 **축이 달라져서** 그 자리를 select가 쓴다.

| | v1 | v2 |
|---|---|---|
| 열 | L1~L5 **5축 고정** (이해 깊이 파생) | **그 회차의 검증 개념 3건** |
| 회차 | 비교 모드로 두 회차 | **하나씩** |

**축이 프로젝트마다 다르므로 select가 필수다.** 미프 1차의 `HITL`과 2차의 `Service`를
나란히 두면 비교 가능한 것처럼 보인다(6-3). 미프 8~10회면 열이 24~30개가 되는 문제도
같이 사라진다.

**회차 간 변화는 교육생 상세 타임라인**(MG-06)에서 본다.

### 값 — 개인은 그대로, 팀·반만 평균

| 행 | 값 |
|---|---|
| **개인** | 도달 단계 **그대로**(0~4). 평균이 아니다 |
| 팀 · 반 | 평균 (소수점 1자리) |

**5-3이 평균을 금지한 것은 위험 판정**이고, 히트맵은 **패턴 탐색**이라 팀·반 평균을 쓴다.
다만 개인 행까지 평균을 내면 그 사람의 판정값이 흐려지므로 **개인은 원값**이다.

**팀·반 평균은 판정에 쓰지 않는다** — 어느 열이 낮은지 눈으로 찾는 용도다.

### 색 스케일 — 여기서 확정하고 MG-06이 물려받는다

| | 값 | 색 |
|---|---|---|
| **―** | 코드에 없음 · 문항 없음 | **회색 사선.** 숫자가 아니다 |
| 0 | 응답 없음 · 무성의 | 진한 주황 |
| 1 | 무엇을 하는지까지 | 주황 |
| 2 | 왜 그렇게 했는지까지 | 옅은 주황 |

| 3 | 다른 방법까지 | 옅은 초록 |
| 4 | 언제 깨지는지까지 | 초록 |

**`―`는 숫자와 다른 기호·다른 무늬다**(F3·F4). 사선 패턴을 써서 색약이어도 갈린다 —
미실시를 0점으로 읽히게 하면 안 된다.

**색과 숫자를 둘 다 쓴다** — 색만 쓰면 정확한 값을 못 읽고, 숫자만 쓰면 패턴이 안 보인다.

**2단 이하에는 밑줄을 긋는다.** 경계가 세로선이 될 수 없다 — 값이 열이 아니라 셀에
있기 때문이다. 색 농담만으로는 "다시 보기 대상인가"가 안 잡히므로 **밑줄로 한 번 더**
표시한다(F4). 팀·반 평균 행은 옅은 밑줄이다 — 판정값이 아니라서.

### 드릴다운 — 줌 브레드크럼으로 3단

`보기 [반별] › 팀 › 개인`. 한 화면에 계층을 쌓지 않고 **화면이 바뀐다.**

| 화면 | 상단 행 | 아래 행 | 값 |
|---|---|---|---|
| **① 반별** (시작) | 담당 반 평균 | **담당 반들** | 평균 |
| **② 팀** | 그 반 평균 | 팀들 | 평균 |
| **③ 개인** | 팀 평균 | 팀원 | **도달 단계 그대로** |

**첫 화면이 반 비교인 이유:** 담당 반이 여럿이면 *"어느 반이 처지나"* 가 먼저다. 반이
하나면 ①이 생략되고 ②부터 시작한다.

**오퍼레이터는 앞에 기수가 하나 더 붙어 4단**이다 — `기수 › 반 › 팀 › 개인`.

### 다시 보기는 필터가 아니라 셀 표식

**15번 #3**: 재시험 포함/미포함 필터 폐기 → **셀에 개선 표식(↑)만**.

조직 단위 수치는 1차만 쓰지만(11절), 다시 보기 결과를 아예 안 보여주면 매니저가
*"시켰는데 어떻게 됐지"* 를 알 수 없다. **개인 셀에 `↑`** 를 붙이고, **반·팀 평균과 위험
판정은 1차 값 그대로** 둔다 — 다시 보기는 못한 사람만 보므로 섞으면 평균이 위로 밀린다.

### 집단 미달 — 배너와 셀 둘 다

**15번 #9**(미정이던 것)를 여기서 정한다.

| | |
|---|---|
| **배너** | 놓치지 않게. 상단에 인원과 조치 |
| **셀 테두리 + 열 머리 ⚠** | **어느 열인지** 알게 |

배너만 두면 표에서 그 열을 다시 찾아야 하고, 셀만 표시하면 스크롤 밖에 있을 때 놓친다.

### 위험 유형은 배지로

9-2의 **단계 하락 · 지속 저점**은 직전 회차와 비교해 나오는 값이라, 이 화면이 한 회차만
보여도 **판정 결과는 배지로 실을 수 있다.** 오른쪽 끝 열에 둔다.

전이 자체(어느 회차에서 떨어졌는지)는 **교육생 상세 타임라인**에서 본다.



## 4. 데이터

회차 × 개념 × (반·팀·개인) 도달 단계. **집단 미달**(반 절반 이상 미달)인 열은 열 머리에 표시.
