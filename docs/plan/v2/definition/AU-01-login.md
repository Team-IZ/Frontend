# AU-01 · 로그인

> **v1 구조 유지.** 레이아웃·문구 규칙 그대로.
> **바뀐 것은 하나** — `미인증(이메일 인증)`이 `미활성(초대 활성화)`로 대체된다. v2는 초대 링크 클릭이 이메일 소유 증명이라 **별도 인증 메일 단계가 없다**(AU-02 §1).

## 1. 한 줄

**하나의 로그인.** 역할별로 나누지 않는다 — 나누면 사용자가 자기 역할을 알아야 로그인할 수 있는데, 역할은 내부 개념이다.

## 2. 진입 · 이탈

| | |
|---|---|
| 진입 | `/shared/login` · 미로그인 상태로 보호된 경로 접근 · 활성화/재설정 완료 후 · 로그아웃 후 |
| 이탈 | **서버가 역할을 판정해 초기 화면으로 보낸다.** 클라이언트는 역할→화면 매핑을 갖지 않는다 |

**초기 화면은 응답의 `initialScreen`을 그대로 따른다** — 슈퍼어드민 SA-01 · 오퍼레이터 OP-01 · 매니저 MG-01 · 교육생 TR-01. 클라이언트가 이 표를 갖고 분기하면 역할이 늘 때 화면이 먼저 틀린다.

## 3. 뷰

```
┌ 브랜드 패널 ─────────┬ 폼 ────────────────────────┐
│   ◆ RealiZe          │  로그인                     │
│                     │  [알림 슬롯]                │
│                     │  이메일   [               ] │
│                     │  비밀번호 [               ] │
│                     │                    [로그인] │
│                     │  비밀번호를 잊으셨나요?      │
└─────────────────────┴─────────────────────────────┘
```

**회원가입 링크가 없다.** 계정은 전부 초대로 생긴다(AU-02).
**알림 슬롯은 상태가 있을 때만 나타난다** — 자리를 비워 두지 않는다(빈 칸이 남으면 폼이 밀린다).

## 4. 데이터

이메일 · 비밀번호. 역할과 초기 경로는 응답으로 받는다.

**화면이 갖지 않는 것** — `refreshToken`(Set-Cookie · HttpOnly라 화면에서 접근 불가) · 실패 횟수 · 잠금 상태. 전부 서버가 관리한다.

## 5. 액션

| 액션 | 오퍼레이션 | 보내는 것 | 받는 것 · 부수효과 |
|---|---|---|---|
| 로그인 | `POST /auth/login` | `{ email, password }` | `{ accessToken, role, initialScreen }` · `Set-Cookie refreshToken`(Secure·HttpOnly) · 실패 시 **실패 횟수 증가**, 임계 초과 시 **잠금(만료시각 기록)** · **감사 로그**(성공·실패·시각·대상) |
| 초대 메일 재발송 | `POST /auth/resend-invite` | `{ email }` | 재발송. **계정 존재 여부와 무관하게 동일 응답** |
| 비밀번호 재설정 | 화면 전이 | — | → AU-03 |

**실패는 화면을 벗어나지 않는다.** 재설정으로 자동 이동하지 않고, 사용자가 링크를 눌러야만 AU-03으로 간다.

## 6. 상태 — 왜 그렇게 정했나

> **케이스 표(번호 · 에러코드 · 문구 · 다음 행동)는 목업에 있다** — [`shared/login.html#cases`](../wireframe/shared/login.html#cases).
> 여기 두면 아무도 안 본다. **표는 목업 한 곳에만 두고**, 이 절은 그 표로 설명이 안 되는 것만 적는다.
> 두 곳에 같은 표를 두면 화면을 고칠 때 하나만 고쳐지고 그때부터 어느 쪽이 맞는지 모른다.

**9는 로그인 자체를 막는다.** `role`·`org_id`가 없으면 어디로 보낼지 정할 수 없고, 통과시키면 권한 없는 화면에 들어간다.

### 계정을 잠그지 않는다 — 지연만 준다

**v1은 실패 임계 초과 시 계정 잠금**이었다(case2 잠금 발생 / case3 잠금 재진입 · 2행). v2는 **지연 1행**으로 합친다.

| | |
|---|---|
| **잠금은 남을 공격하는 수단이 된다** | 계정은 초대 기반이고 **명단(OP-06)에 전원 이메일이 있다.** 잠금을 두면 아무나 남의 주소로 3번 틀려서 **그 사람을 못 들어오게 만들 수 있다.** 250명이 같이 쓰는 부트캠프에서 이건 가정이 아니라 시간문제다 |
| **풀어 줄 사람도 화면도 없다** | v1은 case3을 `관리자 문의`로 넘겼는데, 잠금 해제 화면이 어디에도 없다. 결국 오퍼레이터 수작업이 되고 회차마다 반복된다 |
| **정상 경로가 이미 있다** | 비밀번호를 잊은 사람은 재설정(AU-03)으로 간다. 잠금은 그 사람을 막을 뿐 도와주지 않는다 |
| **막아야 할 것은 지연으로 막힌다** | 무차별 대입은 **재시도 간격을 늘리면** 성립하지 않는다. 계정을 잠글 필요가 없다 |

**대기 시간은 알려준다.** 아래 「감추는 것」과 달리 이건 감출 정보가 아니고, 없으면 사용자가 언제 되는지 몰라 계속 두드린다.

### 감추는 것 — 어기면 보안 구멍

| | |
|---|---|
| **어느 쪽이 틀렸는지 말하지 않는다** | 이메일만 맞다고 알려주면 어떤 주소가 가입돼 있는지 알려주는 셈이다(계정 열거) |
| **남은 시도 횟수를 노출하지 않는다** | 임계값을 알려주면 그 직전까지 시도하고 멈추는 것이 가능해진다 |
| **재발송은 계정이 없어도 같은 응답** | 응답이 다르면 그것으로 가입 여부를 캐낼 수 있다 |

### 알림 위치 — 비밀번호 아래 · 버튼 위

| | |
|---|---|
| **폼 위쪽에 두지 않는다** | 알림이 뜨면 그 아래 전부가 밀려난다 — 재시도할 때마다 입력 필드가 커서 밑에서 움직인다 |
| **지금 자리의 이유** | 방금 누른 버튼과 다시 칠 비밀번호 **사이**다 — 시선을 옮길 필요가 없다 |
| **필드 아래에 붙이는 것** | 빈 값·형식처럼 **그 필드에 귀속되는 오류만.** 자격 불일치는 어느 쪽이 틀렸는지 말하지 않기로 했으므로 필드에 붙일 수 없다 |
| **읽어 주기** | 알림 영역은 `role="alert"` — 위치와 무관하게 스크린리더가 뜨는 즉시 읽어야 한다 |

**폼 박스 높이를 고정한다 — `min-height: 440px`.**
위치만 옮기면 절반만 해결된다. 폼은 세로 중앙 정렬이라 **알림이 뜨면 박스가 커져 중앙이 다시 계산되고, `로그인` 제목과 입력 필드가 위로 올라간다.** 높이를 박아 두면 알림이 있든 없든 시작 위치가 같다.

| | |
|---|---|
| 440px의 근거 | **가장 긴 상태**(알림 2줄 + 재발송 링크 = `#inactive`) 기준. 더 긴 알림을 넣으면 이 값을 올려야 한다 |
| 검증 | 8개 상태 전부 제목 y좌표 **동일**(1300px 뷰포트에서 719px). 알림 유무·줄 수와 무관 |
| 뷰포트가 바뀌면 | 중앙 정렬은 유지되니 화면 높이에 따라 폼 전체는 위아래로 움직인다. **막으려는 것은 같은 화면에서 상태가 바뀔 때 흔들리는 것**이다 |

## 7. 안 하는 것

| | 왜 |
|---|---|
| 회원가입 | 초대 기반(AU-02) |
| 역할 선택 | 서버가 판정한다 |
| 이메일 인증 단계 | **v2에서 없앴다** — 초대 링크 클릭이 소유 증명(AU-02 §1) |
| 소셜 로그인 · 2FA | 명세에 없음 |

## v1 대조 (SC-A01) — 검수 결과

> v1을 그대로 가져오지 않는다. **v2에서 성립하는 것만** 남긴다.

| v1 | 판정 | |
|---|---|---|
| 예외 case 전량 매핑 | **그대로** | 위 §6. v1의 핵심 자산이고 코드도 이미 구현돼 있다 |
| case4 `미인증`(이메일 인증 필요 + 인증 메일 재발송) | **고침** | v2는 인증 메일 단계가 없다(AU-02 §1) → `미활성`(초대 활성화) + 초대 메일 재발송. 그대로 뒀으면 **없는 기능을 명세**하게 된다 |
| case2·3 **계정 잠금** | **버림** | 지연으로 대체 — 위 「계정을 잠그지 않는다」. 명단에 전원 이메일이 있어 **잠금이 남을 막는 수단**이 되고, 해제 화면이 없다 |
| case6·7·8 각각 1행 | **유지 · 목업은 1장** | 명세가 세 case를 나눠 정의하므로 계약 행은 3개, 사용자 표현은 1종 |
| 역할별 초기화면(3계층) | **고침** | v2는 4계층 — 오퍼레이터가 들어간다 |
| 중앙 카드 레이아웃 | **버림** | v2는 좌 브랜드·우 폼 분할(이미 적용) |
| 표현 규범 A1~A8 "해당 없음" | **그대로** | 측정·수치가 없는 화면 |

### v2 초안에서 채운 것

| | |
|---|---|
| 제출 중 상태 없음 | → 추가. **코드에는 이미 있었다**(`isSubmitting` · `로그인 중…`) — 문서·목업만 빠져 있었다 |
| 시스템 오류 · 권한 컨텍스트 없음 | → 추가(`#sysfail` · `#noctx`). 코드는 구현돼 있었는데 문서·목업에만 없었다 |
| 알림이 폼 상단 | → **비밀번호 아래 · 버튼 위**. 상단이면 알림이 뜰 때 입력 필드가 밀린다 |

### 코드 쪽에 남은 불일치 (별건)

| 위치 | 문제 |
|---|---|
| `authTypes.ts` `Role` | `SUPERADMIN │ MANAGER │ TRAINEE` — **`OPERATOR`가 없다**(v1 3계층 그대로) |
| `authTypes.ts` `AuthErrorCode` | `AUTH_LOCKED_NEW` · `AUTH_LOCKED` · `lockedUntil` → **`AUTH_THROTTLED` + `retryAfter`** 로 교체해야 한다(잠금 폐기) |
| `authStates.ts` `AUTH_UNVERIFIED` | 문구가 `이메일 인증이 필요합니다` — v2에서 없앤 개념 |
| `LoginScreen.tsx` `resendVerification` | 인증 메일 재발송 → **초대 메일 재발송**으로 바꿔야 한다 |
| `InlineAlert` 위치 | `LoginScreen.tsx`에서 `TextField` **앞**에 있다 → 비밀번호 뒤·버튼 앞으로 |
