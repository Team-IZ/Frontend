> 여기는 **값이 오기 전·안 올 때·이상하게 올 때** 화면이 무엇을 하는가를 다룬다.

> 화면마다 다른 것은 1단계(상황 목록)뿐이고 나머지는 그대로 쓴다.
>
> | 이 문서 | 무엇을 **어떤 순서로** 하나 · **[이미 정해진 화면 규칙](#화면-규칙--이미-정해진-것들)**(A~L) |
> |---|---|

## 0. 전제 — 왜 이 단계가 따로 있나

연동을 마친 화면은 **정상 경로에서만 검증된 상태**다. 실제 사용자는 그 경로로만 다니지
않는다 — 서버가 자고, 기수에 회차가 없고, 권한이 없고, 자정을 넘겨 켜 둔 채 방치한다.

OP-01에서 실제로 나온 것들이다.

| 겉보기 | 실제 |
|---|---|
| "들어가자마자 빨간 에러가 떠요" | 조회는 **200**이었다. 아직 집계된 회차가 없을 뿐 |
| "느려요" | 8.1초. 그중 **6.6초는 안 기다려도 되는 것**이었다 |
| "숫자가 이상해요" | 같은 기수 인원을 **네 API가 다르게** 세고 있었다 |

셋 다 **연동 테스트로는 안 걸린다.** 값이 오긴 왔기 때문이다.

## 화면이 크면 **쪼개서 돌린다**

OP-01~05는 한 화면이 한 덩어리였다. OP-06은 **탭이 여섯**이고, 그대로 다루면 두 가지가
무너진다 — 1단계 축 목록이 수십 줄이 되어 아무도 안 읽고, 5단계에서 **어디까지 봤는지**를
잃어버린다(OP-04에서 7개 회차 중 3개만 보고 "다 봤다"고 적은 적이 있다).

**탭 하나를 화면 하나로 취급한다.**

```
공통(한 번만)   머리 · 탭 줄 · 스코프 · 진입 타임라인 · 탭 전환
탭 A            축 → 실측 → 판정 → 고침        ← 여기까지 끝내고 문서에 적는다
탭 B            축 → 실측 → 판정 → 고침
…
```

| | |
|---|---|
| **순서** | ① 진입 기본 탭(사용자가 먼저 본다) ② **쓰기가 있는 탭**(사고가 크다) ③ 나머지 |
| **기록 시점** | **탭 하나 끝날 때마다** 문서에 적는다. 다 하고 적으면 앞의 것을 잊는다 |
| **공통은 한 번** | 탭마다 다시 재지 않는다 — 대신 **탭 전환 자체**를 축으로 따로 둔다 |

**탭 전환이 별도 축인 이유** — OP-04에서 화면을 죽인 크래시가 거기 있었다. 탭 안을
아무리 봐도 안 나오고 **탭을 옮기는 순간**에만 났다.

## 발견 하나를 처리하는 법 — **모든 단계에서 여기로 돌아온다**

이 판정은 단계가 아니라 **발견 하나마다 도는 루프**다. 2단계(측정)에서도, 4단계(고치다
나온 이상 신호)에서도, 5단계(플로우 관찰)에서도 나온다 — 어디서 나왔든 여기로 온다.

**한 번의 관찰에서 주인이 갈린다.** OP-01·02의 플로우 관찰 하나가 네 갈래였다.

| 발견 | 판정 |
|---|---|
| 진입 직후 빨간 실패 화면 | ① 우리 코드 |
| 헤더가 `기수 7기`라고 거짓말 | ① 우리 코드(공용 파일은 안 건드리고) |
| `login → me` 직렬 1.3초 | **⑤ 다른 레포**(`features/auth`) |
| `class-progress`가 `projects` 뒤에 순차 | ⑥ 백엔드 |

---

### 누가 고칠 것인가 — **요청서는 마지막 수단이다**

발견 하나마다 이 순서로 내려간다. **위에서 걸리면 거기서 끝낸다.**

```
① 우리 코드로 되나          → 된다면 여기서 끝. 대부분 여기서 끝난다
② 이미 있는 응답에 값이 있나 → 다른 엔드포인트가 이미 주고 있을 수 있다
③ 스웨거에 다른 API가 있나   → 82개 전수로 본다. "못 찾은 것"과 "없는 것"은 다르다
④ 문서에 답이 있나          → 이전 요청서·결정 기록에 이미 답이 나갔을 수 있다
⑤ 다른 레포 영역인가        → auth·슈퍼어드민이면 요청서가 아니라 **그쪽에 알린다**
──────────────────────────────────────────────────────────────
⑥ 그래도 안 되면            → 백엔드 요청서
```

### 각 단계에서 실제로 한 일

**① 우리 코드로 되나** — 대부분 여기서 끝난다.

| 처음 보기 | 실제 |
|---|---|
| "서버가 빈 값을 준다" | 화면이 `isLoading`으로 「아직」을 판정하고 있었다 |
| "응답 필드가 이상하다" | 한 변수를 바꿔 다시 재니 정상이었다(OP-02 `sameCurriculumOnly`) |
| "기수 조회가 캐시가 안 된다" | 측정 스크립트가 앞 화면을 덜 기다린 것이었다 |

**세 건 다 요청서에 올릴 뻔했다.**

**② 이미 있는 응답에 값이 있나**

```bash
curl -s "$BASE/api/v0/..." -H "Authorization: Bearer $TOKEN" | python3 -m json.tool | grep -i "찾는필드"
```

OP-01에서 `/projects`(4.6초)를 빼려고 봤더니, `risk-trainees`가 이미 `projectId` ·
`projectName` · `cohortRoundNo` · `totalRegisteredRoundCount`를 갖고 있었다 — **다섯 중
넷이 이미 있었다.** 없는 것은 `startDate` 하나뿐이라 요청이 훨씬 작아졌다.

**③ 스웨거에 다른 API가 있나 — 전수로 본다**

```bash
curl -s "$BASE/v3/api-docs" -o /tmp/live.json
python3 -c "
import json; d=json.load(open('/tmp/live.json'))
print('경로', len(d['paths']))
for p, ops in sorted(d['paths'].items()):
    if '찾는것' in p.lower():
        for m,o in ops.items():
            if m in ('get','post','put','patch','delete'): print(f'{m.upper():6} {p}  {o.get(\"summary\",\"\")}')"
```

**로컬 스펙과도 대조한다** — 우리 파일이 낡아서 못 찾는 것일 수 있다. OP-01에서 82개
전수를 보고 로컬과 차이 0인 것을 확인한 뒤에야 *"없다"* 고 쓸 수 있었다.

**④ 문서에 답이 있나**

```bash
grep -rn "찾는것" docs/dev/backend/ docs/dev/api/ docs/dev/decision-log.md
```

이전 요청서에서 이미 물었고 답이 왔을 수 있다. 같은 것을 두 번 물으면 저쪽이 컨텍스트를
다시 잡아야 한다.

**⑤ 다른 레포 영역인가 — 요청서가 아니라 그쪽에 알린다**

| 영역 | 누구 |
|---|---|
| `features/auth` · `features/superadmin` | **`IZ-frontend`** |
| `components/ui` · `shells` · `lib` · `api/_contract` | 공유 — **추가만, 수정은 조율** |
| `features/operator` | 우리 |

OP-01의 `login → me` 직렬 1.3초가 이 경우다. **백엔드 문제가 아니라 프론트 문제인데
우리 레포가 아니다** — 요청서에 쓰면 엉뚱한 곳으로 간다.

**⑥ 그래도 안 되면 요청서**

`docs/dev/backend/backend-api-requests-N.md`. 넣을 것은 다음 절에.

> **⚠ 화면 하나마다 보내지 않는다.** OP 전수를 훑고 **한 번에 묶어야** 저쪽이 우선순위를
> 정할 수 있다. 그때까지는 상황 문서에 *"요청서로 나간다"* 로 적어 두고 모은다.

### 화면이 혼자 못 푸는 것은 요청서로

프론트에서 못 고치는 것은 **실측 근거와 함께** 백엔드 요청서로 넘긴다
(`docs/dev/backend/backend-api-requests-N.md`).

| 넣는 것 | OP-01 예 |
|---|---|
| 관측 — 숫자와 응답 원문 | TTFB 표 · `server: envoy` 헤더 |
| **없다는 증명** | 스웨거 82개 전수 확인, 로컬 스펙과 동일 |
| 대조군 | 단건 상세는 2.1초(목록보다 2.5초 빠름) |
| 왜 화면이 못 푸나 | `rounds[]`에 `status`·`startDate`가 없다 |
| 요청과 **대안** | `projects/current` 신설 · 어려우면 필드 2개 |
| 재현 명령 | 붙여넣어 바로 돌아가는 `curl` |

**"고쳐 주세요"가 아니라 "이렇게 관측됐고 이래서 우리가 못 푼다"** 로 쓴다. 정의를 묻는
것이면(Q) 값을 통일해 달라고 하지 않는다 — 모르는 채 화면을 맞추면 틀린다.

## 화면 규칙 — **이미 정해진 것들**

> **이 절은 매번 다시 듣지 않으려고 있다.** OP-01~06을 하면서 사용자가 직접 지시해 고친
> 것들이다. 새 화면(매니저·교육생)에서 **똑같은 지적을 다시 받는다면 여기를 안 본 것**이다.
>
> 3단계(판단)와 5-2단계(렌더 확인)에서 이 목록을 옆에 두고 대조한다. **여기 있는 것은
> 판단 대상이 아니다 — 이미 답이 나온 것이라 그대로 따른다.**

### A. 표·목록 배치 — **전 제품 공통 4단**

리스트/표가 있는 화면은 **전부 이 배치**다. 기준 화면은 교육생 리스트와 운영 관리 탭들이다.

```
┌ 헤더    제목 + 총 개수(좌) ····························· [+ 추가](우)
├ 툴바    [🔍 검색] [필터▾] [필터▾] [정렬▾]  ← 전부 좌측    (우측 비움)
├ 표      …
└ 푸터    1–20 / 48명(좌) ····· ‹ 1 2 3 ›(중앙) ····· (우 비움)
```

| | 규칙 | 왜 |
|---|---|---|
| `+ 추가` | **제목 줄 오른쪽.** 필터 줄에 넣지 않는다 | 필터 줄은 화면마다 같아야 하고, 행을 선택해도 추가 버튼이 사라지면 안 된다 |
| 총 개수 | **제목 옆**에 진하게(`교육생 48명`) | 착지 즉시 규모를 안다. 단 위에 메트릭 카드로 총계가 있으면 **생략**(중복) |
| 툴바 | 검색·필터·정렬 **전부 좌측** · 우측은 비운다 | 우측은 필터가 늘어날 자리다 |
| 범위 개수 | **푸터 왼쪽**(툴바 우측 아님) | 페이저를 설명하는 값이라 페이저 옆에 있어야 한다 |
| 선택 벌크 | **하단 도킹 바**가 슬라이드로 올라온다 | 필터 줄을 덮어 바꾸는 방식(top-swap)은 **고르면서 거르는** 우리 화면과 안 맞는다 |
| 벌크 바 색 | 중립 표면(흰+그림자) + accent 주액션 | 파란 블록 전체는 경보로 읽힌다 |
| 전체 선택 | 「이 페이지 20 선택 · 필터 전체 N 선택」 둘로 가른다 | 대용량에서 둘은 다른 뜻이다 |

⚠ **목업·와이어 안에 dev 주석을 남기지 않는다.**

### B. 화면 뼈대 — **한 뷰포트에 담는다**

**세로로 블록 5~6개를 쌓아 긴 스크롤을 만들지 않는다**(요약→분포→추이→취약→개입 식).

| 쓸 것 | 언제 |
|---|---|
| **마스터-디테일** | 좌 목록/목차 → 우에 **그 하나만**. 나머지 섹션은 **숨긴다** |
| **서브탭** | 우측 디테일이 길 때 |
| **탭 vs 페이지** | 한 대상의 여러 측면이면 **탭** · 대등한 별개 화면이면 **사이드바 하위 페이지** |

⚠ **목차는 앵커 스크롤이 아니라 섹션 전환이다.** 리포트처럼 문서형이어도 마찬가지다 —
스크롤이 튀면 지금 어디인지가 사라진다.

⚠ **섹션이 쌓여 길어질 조짐이면 탭으로 나눈다.** 「개요를 항상 보이게」 하려고 스트립을
위에 올리다 페이지가 길어진 적이 있고, 되돌렸다.

### C. 액션 — **누르면 뭐가 되는지까지 그린다**

버튼·링크가 있으면 **그것을 눌렀을 때 뜨는 것**(폼·패널·모달·화면 전이·결과 상태)을
**처음부터 같이** 만든다. 버튼만 두고 결과를 안 그리면 누르는 순간 아무 일도 안 일어난다.

**버튼 줄 배치** — 실제로 지적받아 고친 형태다.

```
제목 ···························· [아이콘 다시 분석] [🗑 삭제]
                                                    ↑ 되돌릴 수 없는 것이 바깥·빨강
```

| | 규칙 |
|---|---|
| 순서 | **되돌릴 수 없는 것이 가장 오른쪽**(삭제·빨강). 그 왼쪽에 다음 액션 |
| 없을 때 | 삭제가 없으면 **그 자리를 다음 액션이 차지**한다 |
| 묶음 | 액션은 **한 `div`로 감싼다** — `justify-between`의 형제로 두면 버튼이 늘 때 **가운데로 밀린다**(실제로 「다시 분석」이 화면 한가운데 있었다) |
| 아이콘 | **모든 버튼 왼쪽에 아이콘**(생성 버튼과 같은 모양) |

⚠ **못 하는 일은 버튼을 안 그린다.** 서버가 막을 것이 확실하면(예: 쓰는 곳이 있는 자원의
삭제) 눌리게 두지 않는다. 단 **모르는 동안에도 안 그린다** — 아래 E.

### D. 값을 화면에 쓰는 법

| | 규칙 | 실패했던 것 |
|---|---|---|
| **접미사** | 사람이 `반`·`차` 같은 꼬리를 **직접 치게 하지 않는다.** 입력은 `A`, 저장·표시는 `A반` | 자리표시자가 `K반`이라 그렇게 치는 뜻이 됐고, 빠뜨린 사람이 `A`라는 반을 만들어 목록에서 혼자 다른 모양이 됐다 |
| **조사** | **값 뒤에 조사를 붙이지 않는다.** 고정 명사 뒤로 옮기고 값은 뒤에 나열 | `{이름}가 {교안}으로`는 받침에 따라 갈리는데 **서버가 주는 이름이라 미리 모른다** |
| **모르는 값** | `null`·빈 문자열이 화면에서 무엇이 되는지 본다 | `NaN%` · `· H반` · 분모 없는 비율 |
| **0과 없음** | **다른 말이다.** `0`은 값이고 `—`는 모름 | 「전체 0반」이라고 **모르는 것을 0으로 단언**했다 |
| **반복되는 열** | 머리가 이미 말한 값을 열로 반복하지 않는다 | 「9기」 섹션 아래 `9기`가 여덟 번 |

### E. 표가 다시 불러오는 동안 — **비우지 않는다**

**조건(필터·검색·정렬·페이지)을 바꿔도 표를 비우지 않는다.** 캐시 라이브러리 기본값은
조건이 바뀌면 **다른 캐시 키**가 되어 빈 상태를 그린다 — 화면이 통째로 깜빡인다.

```ts
// _shared/listQuery.ts — 목록 조회는 전부 이걸 쓴다
export const listQueryOptions = { placeholderData: keepPreviousData }
```

**그런데 흐리게만 두면 안 된다.** 실측에서 조건 하나를 바꾸면 5~9초가 걸리는데, 그동안:

```
상태 필터: 「종료 (5)」     ← 내가 방금 고른 것
표:        1행              ← 직전 조건의 결과
그 사이:   흐림만           ← 이게 무슨 뜻인지 아무도 말 안 한다
```

**개수와 표가 서로 다른 말을 하는 화면**이 되고, 사용자는 「필터가 잘못 걸렸나」로 읽는다.
그래서 `StaleBlock`이 셋을 같이 한다 — **덮고 · 못 누르게 하고 · 「불러오는 중」이라고
말한다**(`aria-busy`도 같이). 옛 행을 눌러 다른 상세로 가는 사고까지 막는다.

| 언제 | 무엇 |
|---|---|
| **첫 진입**(값이 아예 없다) | **스켈레톤** — 도착할 화면 모양으로, 높이는 **실측값** |
| **조건 변경**(옛 값이 있다) | `StaleBlock` — 덮고 말한다 |
| **뒤에서 갱신**(사용자가 안 시켰다) | **아무것도 안 그린다** |

⚠ **`isLoading`으로 판정하지 않는다.** `enabled: false`인 동안 `isLoading`은 `false`라
그 분기가 안 그려진다. **데이터 유무로 가른다**(`!data && !isError`).

⚠ **`?? []`를 쓰지 않는다** — 「모른다」가 「없다」가 된다. 실제로 26개가 쓰는 교안에서
`연결된 프로젝트 0` · 「없습니다」 · **삭제 버튼 노출** · **「영향이 없습니다」**(3521명이
이미 응시)까지 나왔다. `undefined`를 그대로 들고 다니면 쓰는 쪽이 **셋을 갈라야만**
컴파일된다.

⚠ **탭 이름 옆 숫자를 두지 않는다.** 조회가 도착해야 아는 값인데 탭 줄은 진입 즉시
그려진다 — 0으로 메우면 거짓말이고, 늦게 나타나면 **탭 줄 폭이 튄다.** 그 수는 **탭을
열면 머리가 크게 말한다.**

### F. 고르는 목록에는 **고를 수 있는 것만**

배정·연결처럼 **후보를 고르는 자리**는 자격을 서버 조건으로 좁힌다.

- 매니저 배정 후보 → **인증이 끝난 사람만**
- 프로젝트에 연결할 교안 → **분석이 끝난 것만**

고를 수 없는 것을 목록에 넣고 **누른 뒤에 막으면**, 그 시점에는 이미 무엇을 하려던 건지
잊는다. 후보가 0이면 **그 이유를 문장으로 쓴다**(빈 목록만 두지 않는다).

### G. 일하는 방식 — 사용자가 반복해서 말한 것

| | |
|---|---|
| **계획 먼저** | 코드를 짜기 전에 **기존 구조를 파악하고 계획**을 세운다. 짜고 나서 구조 문제를 발견하지 않는다 |
| **눌러서 확인** | 코드만 읽고 「됐다」고 적지 않는다. **화면을 띄워 하나하나 눌러 본다** — 5·5-2단계가 그것이다 |
| **반영부터** | 화면 산출물은 제안·질문 먼저가 아니라 **반영(렌더)하고 나서** 「괜찮냐」를 묻는다. 사용자는 렌더로만 검토한다 |
| **커밋** | **요청받았을 때만.** 앞 작업의 허가가 다음으로 이어지지 않는다. 이슈·PR도 같다 |
| **요청서** | 차수 번호는 **사용자가 지정**한다. 커밋한 요청서는 **동결** — 이후 발견은 새 차수로 |
| **기획 문서** | 레거시다. **꼭 따르지 않아도 된다** — 화면이 맞다고 판단되면 근거를 적고 바꾼다 |

### H. 되돌릴 수 없는 것 — **확인 모달**

**설정을 바꾸는 액션은 전부 확인 모달을 거친다**(팀장 지시). 「저장」이 바로 요청을 보내지
않는다. 정지·재활성처럼 **되돌릴 수 있는 것도 포함**이다 — 범위를 좁히면 어디까지가
「설정」인지 매번 다투게 된다.

| | 규칙 |
|---|---|
| 문구 | **무엇이 일어나는지 쓴다.** `정말 하시겠습니까?`는 판단 근거를 안 준다 |
| 대상 | 제목에 **무엇을** 바꾸는지 넣는다(`A반을 B반으로 바꿀까요?`) |
| 결과 | 되돌릴 수 없으면 그 사실을 **굵게**(`되돌릴 수 없습니다`) |
| 실시간 경고와 | **합치지 않는다** — 입력 중 경고(`둘 다 비우면 미설정이 됩니다`)와 제출 직전 게이트는 **시점이 다르다** |
| 실패했을 때 | **모달을 안 닫는다** — 실패 사실이 그 자리에 남아야 한다 |

⚠ **막을 것은 모달이 아니라 애초에 막는다.** 「자기 자신 정지」·「단가 미설정 모델을 채점
모델로」처럼 **하면 안 되는 것**은 확인을 받는 게 아니라 **버튼을 잠그고 이유를 쓴다.**

### I. 실패 문구 — **원인을 추측하지 않는다**

`errorCopy(error, { subject, action })`가 **서버 코드로** 문구를 정한다. `catch`에서 곧장
문구를 만들면 **서로 다른 실패가 한 문장으로 뭉개진다.**

```
실제로 났던 것 — 두 실패가 같은 문구였다
  413 (파일 6.9MB)                  → "PDF 파일인지 확인해 주세요"   🔴
  409 CURRICULUM_TITLE_DUPLICATED   → "PDF 파일인지 확인해 주세요"   🔴
```

| | 규칙 |
|---|---|
| **`retry`** | **다시 눌러서 결과가 바뀔 때만** 준다. 권한 없음·이름 중복에 재시도를 주면 같은 실패를 반복시킨다 |
| **고칠 곳** | 정해져 있으면 **그 입력란을 짚는다**(`aria-invalid` + 인라인 문구). 배너만으로는 어디를 고칠지 눈으로 찾아야 한다 |
| **고치기 시작하면** | **표시를 거둔다** — 지적한 값을 바꾸는 중에 빨간 테두리가 남으면 「고쳐도 안 된다」로 읽힌다 |
| **코드가 없으면** | 상태 코드로 가른다(413처럼 앞단이 자른 것은 우리 `code`가 없다) |
| **「아직」과 「실패」** | 다르다. 데이터가 없는 것을 빨간 실패로 그리지 않는다 |
| **오프라인** | 「서버 문제」라고 하지 않는다 |

### J. 스코프는 **URL이 갖는다**

기수·탭처럼 **화면의 범위를 정하는 값**은 `useState`가 아니라 주소에 있다.

```
/operator/admin/classes?cohort=10기      ← 링크 하나가 「10기의 반 탭」을 가리킨다
```

| | 왜 |
|---|---|
| 딥링크 | 다른 화면이 **특정 탭·기수로** 보낼 수 있어야 한다(OP-01 「조치 필요」가 그렇게 한다) |
| 새로고침·뒤로 | 따라온다 |
| **화면을 옮길 때** | **쿼리를 같이 들고 간다.** 탭을 누르면 `?cohort=`가 사라져 기본값으로 되돌아간 적이 있다 — 스위처는 10기인데 조회는 9기로 나갔다 |
| 목록↔상세 | 왕복에도 유지한다. 상세가 그 값으로 화면을 가른다면 특히 |
| 같은 축 두 개 금지 | 헤더 스위처가 있으면 화면 안에 또 두지 않는다 — 어느 쪽이 이기는지 안 보인다 |

⚠ **URL 값이 목록에 없으면 기본값으로 떨어진다** — 남이 보낸 링크의 기수가 지워졌을 수 있다.

### K. 입력 — 한글과 페이저

| | 규칙 |
|---|---|
| **한글 조합** | Enter로 확정하는 입력은 **조합 중 키를 무시**한다. 안 막으면 `ㅂㅂㅂ`와 잔여 조각 `ㅇ`이 **각각 저장**된다(브라우저가 keydown을 두 번 보낸다) |
| **입력값을 바깥에 올리기** | 조합 중 값을 URL·전역 스토어에 곧바로 쓰면 타이핑이 끊긴다. **입력값과 조회값을 가른다**(디바운스) |
| **페이저** | 접는 규칙은 `getPageRange` 하나가 갖는다 — 화면마다 다시 만들지 않는다(CI가 검산) |
| **범위 개수** | `1–20 / 48명`. 필터 **후** 수다 — 머리의 전체 수와 다른 값이라 섞지 않는다 |

### L. 이 규칙들을 **CI가 지킨다**

문서는 지켜지지 않는다. 되돌아가면 아픈 것만 스크립트로 굳혀 뒀다.

```
check:design       색·간격 토큰 · 대비
check:async        조회 분기에 isPending 금지 등
check:error-copy   실패 문구 규칙(retry 포함)
check:korean-input 조합 중 Enter
check:pagination   페이저 접기
check:admin        운영 관리 도메인 규칙 · 업로드 상한
check:project      검증 개념 3건
```

**새 화면에서 같은 종류의 사고를 고쳤으면 여기에 한 줄 더한다** — 그래야 다음 사람이 안
밟는다. 「문서에 적었다」는 재발을 못 막는다.

## 1단계 · 상황을 전수로 적는다

**결과물** — `docs/dev/screens/{화면}-situations.md`

먼저 **무엇이 달라질 수 있나**를 축으로 나눈다. 화면마다 다르지만 만드는 방법은 같다.

### 축을 뽑는 법

이 화면이 부르는 조회를 전부 그린다. **순서와 의존을 그린다** — 여기서 성능 문제의 절반이
보인다.

```
useCohortId()        GET /cohorts                     ─┐ 이게 끝나야
useDashboard()                                        ─┘ 나머지가 시작한다
  ├─ risk      GET .../analytics/risk-trainees
  ├─ todos     GET .../analytics/actions
  └─ pipeline  GET .../projects            ─┐ 순차
               GET /projects/{pid}/class-progress ─┘
```

그다음 조회마다 **응답이 가질 수 있는 상태**를 적는다. 성공/실패가 아니라 **데이터 상태**다.

```
축 B. 회차 상태
  B1 RUNNING 하나        B2 RUNNING 없고 PLANNED   B3 전부 CLOSED
  B4 회차가 0개          B5 RUNNING이 둘 이상
```

**조합 수를 계산해 적는다**(OP-01은 2,400개였다). 전부 못 보므로 2단계에서 **실제로 갈리는
지점**만 추린다는 것을 문서가 스스로 말하게 한다.

**컨트롤 수도 여기서 센다** — 필터·검색·정렬·버튼·탭이 몇 개인지(OP-06은 여섯 탭 합쳐
**71종**). 5단계에서 그 수만큼 결과 줄이 나와야 「전수」라고 쓸 수 있다.
어떻게 도는지는 [5단계 · 컨트롤](#컨트롤은-적지-말고-눌러-본다)에 있다.

### 공통 축 — 화면마다 다시 생각하지 않는다

3절은 **그대로 복사해서 채운다.** 여섯 갈래다.

| | 무엇을 묻나 |
|---|---|
| 네트워크·인프라 | 오프라인 · 콜드 스타트 · 타임아웃 · 느린 3G · 프록시 한계 |
| 인증·세션 | 토큰 만료 · 리프레시 실패 · **탭 두 개에서 동시에 401** · 권한 없는 자원 |
| 시간·타이밍 | **자정 넘김** · 서버 UTC ↔ 로컬 · 브라우저 시계 오차 · 마감 직후 |
| 사용자 조작 | 로딩 중 이탈 · **재시도 연타** · 뒤로가기 · 스코프 전환 · 확대 200% |
| 표현·성능 | 첫 진입 · 목록이 아주 길 때 · 이름이 아주 길 때 · 다크 모드 |
| 접근성 | 스크린 리더 로딩·실패 · **색으로 순위·상태(대비를 잰다)** · 키보드 이동 · 숫자 낭독 |
| **값의 빈 구석** | **`0` · `null` · 빈 문자열** — 형식은 맞는데 값이 없다. 나눗셈이 `NaN`이 되고(`NaN%`), 이어 붙인 구분자만 남는다(`· H반`) |

## 2단계 · 실제로 물어본다 — 추측하지 않는다

**이 단계가 이 절차의 핵심이다.** 1단계는 "그럴 수 있다"이고 2단계는 "실제로 그렇다"다.

### 서버에 직접 묻는다

```bash
TOKEN=$(curl -s -X POST "$BASE/api/v0/auth/login" -H 'Content-Type: application/json' \
  -d '{"email":"operator@example.com","password":"..."}' | python3 -c 'import json,sys;print(json.load(sys.stdin)["accessToken"])')
curl -s "$BASE/api/v0/..." -H "Authorization: Bearer $TOKEN" | python3 -m json.tool
```

**경계 데이터를 가진 기수를 찾아 쓴다.** OP-01은 9기(RUNNING·집계 있음)와 10기
(PLANNED·집계 0)를 같이 봤고, 10기에서 「아직」이 「실패」로 그려지는 것이 나왔다.

### 시간을 잰다 — 느낌으로 말하지 않는다

```bash
curl -s -o /dev/null -w '%{time_connect}  %{time_starttransfer}  %{time_total}  %{size_download}B\n' "$URL"
```

`time_connect`(네트워크)와 `time_starttransfer`(TTFB=서버 계산)를 **갈라서** 본다.
OP-01의 `/projects`는 연결 79ms·TTFB 4.62초·2.4KB였다 — **네트워크도 크기도 아니고 서버
계산**이라는 증거가 이 한 줄에서 나왔다.

**변수를 바꿔 가며 잰다.**

```
회차 7개 5.28s / 6개 4.22s / 6개 4.00s   → 개수에 비례하지 않는다
?status=RUNNING(1건) 4.48s               → 필터로도 안 줄어든다
?size=1              5.03s               → 무시된다
```

여기까지 나오면 "느리다"가 아니라 **"요청과 무관한 고정 집계를 돌고 있다"** 고 말할 수 있다.

### 브라우저에서 잰다 — 서버 시간과 화면 시간은 다르다

블록·구역이 **각각 언제 나타나는지**, 그리고 **레이아웃이 움직이는지**를 잰다.

```js
// 레이아웃 시프트
new PerformanceObserver(l => { for (const e of l.getEntries())
  if (!e.hadRecentInput) console.log(Math.round(performance.now()), e.value)
}).observe({ type: 'layout-shift', buffered: true })

// 블록 높이·위치 추적
setInterval(() => console.log([...document.querySelectorAll('main [data-slot="card"]')]
  .map(c => Math.round(c.getBoundingClientRect().top))), 120)
```

OP-01에서 CLS 0.0445 · **마지막 이동이 8.7초**가 나왔다 — 사용자가 읽고 있을 때 화면이
움직인다는 뜻이고, 이건 서버 시간만 봐서는 절대 안 보인다.

### 응답을 가로채 이상 상황을 만든다

정상 데이터로는 못 보는 상태를 **실제 화면에서** 본다.

```js
// 조회는 200인데 그릴 것이 없는 상태
await page.route(u => u.pathname.includes('/analytics/risk-trainees'), async r => {
  const res = await r.fetch(); const j = await res.json()
  j.rounds = j.rounds.map(x => ({ ...x, aggregationStatus: 'NOT_STARTED' }))
  await r.fulfill({ status: 200, contentType: 'application/json', body: JSON.stringify(j) })
})

// 권한 없음 · 서버 오류를 동시에
await page.route('**/analytics/actions**', r => r.fulfill({ status: 500, contentType: 'application/json',
  body: JSON.stringify({ status: 500, code: 'INTERNAL_SERVER_ERROR', message: 'x' }) }))
```

**여기서 대부분의 거짓말이 잡힌다.**

⚠ **가로채기가 실제로 먹었는지 먼저 본다.** 필드명을 틀리면 원본이 그대로 흘러가
**정상 화면이 나오는데**, 그걸 보고 *"빈 상태 처리 잘 돼 있음"* 이라고 적게 된다 —
OP-05에서 `classRiskRates`로 썼는데 실제 필드는 `classRisk`였다. 가로챈 직후
**바꾼 값이 화면에 보이는지** 한 번 확인하고 나서 판정한다.

### 코드가 **사실이라고 적어 둔 것**을 재 본다

주석·타입·변수 이름은 **그때의 관찰이거나 그때의 기대**다. 3개월 뒤엔 둘 다 아닐 수 있다.

```
"정렬은 나쁜 순(이미 이렇게 정렬된 데이터가 온다)"   ← ClassOps.tsx 주석
실제                                              반 이름순 (최악이 4번째·11번째)
```

**「서버가 ~해 준다」는 문장은 전부 후보다.** 정렬·기본값·필수 여부·개수 상한 —
그 문장 하나 때문에 화면이 아무 방어도 안 하고 있을 수 있다.

### 브라우저가 원인을 가린다 — **curl로 다시 묻는다**

브라우저에는 프록시·CORS·재시도가 겹쳐 있어서, **원인과 전혀 다른 증상**이 보인다.

| 브라우저가 보여준 것 | 실제 원인 |
|---|---|
| 개념 후보가 무한 로딩. 네트워크 탭에 **요청이 나가지도 않음** | 서버가 **무응답**(60초 초과). 프리플라이트가 502로 죽어 `net::ERR_FAILED`가 되고, 그러면 실제 요청이 안 나간다 |
| 진입 때 조회 하나가 랜덤하게 실패 | `Promise.all`로 **동시에** 나가서 프록시가 죽인다 |

**「요청이 안 나간다」는 결론에 도달했으면 거의 틀렸다.** 같은 URL을 curl로 직접 쳐 본다 —
거기서 200이 2초에 오면 화면 문제, 60초를 넘기면 서버 문제다. 갈리는 데 1분이면 된다.

### 「안 맞는다」고 쓰기 전에 **부분합으로 한 번 더 센다**

숫자 셋이 안 맞아 보이면 **셋이 같은 것을 세는지부터** 의심한다. 요청서에 *"산술이
안 맞습니다"* 라고 쓰는 순간 그건 **버그 신고**가 되고, 틀리면 저쪽 시간을 버린다.

OP-06에서 `209` · `225 − 17 = 208`을 보고 off-by-one으로 읽었다. **조합 필터로
부분합을 세니 전부 맞았다.**

```
전체 225   = 활성 209 + 초대 대기 1 + 비활성 15
미배정 17  = 활성  13 + 초대 대기 1 + 비활성  3
반 배정 208 = 225 − 17               ← 반별 합계와도 일치
활성 209   = 미배정 활성 13 + 배정 활성 196
```

**209와 208이 1 차이인 것은 우연이었다** — 「활성 계정」과 「반 배정」은 애초에 다른 값이다.

| 재는 법 | |
|---|---|
| 필터가 있으면 | **조합으로 부분합**을 세서 전체와 맞춰 본다 |
| 없으면 | 다른 엔드포인트의 같은 뜻 필드를 찾아 교차 검산 |
| 그래도 안 맞으면 | 그때 **「이 값이 무엇을 세나」를 묻는다** — 「틀렸다」가 아니라 |

OP-02의 `sameCurriculumOnly`도 같은 실수였다(재보니 서버가 맞았다). **두 번 겪었다.**

### 전수로 잰다 — **한 건은 표본이 아니다**

교안 하나가 무응답이라고 *"이 API가 고장났다"* 라고 적을 뻔했다. 7종 전부를 돌리니
갈렸다.

```
pageCount = null  →  5종 전부 60초 타임아웃
pageCount = 120·38 →  2종 전부 200 (2.0~2.5초)
```

**상관이 완전하면 그것이 원인의 이름이다.** 「`/sections`가 느리다」가 아니라
**「분석 전 교안에서만 무응답」** 이라고 쓸 수 있게 되고, 이건 요청서에서 완전히
다른 요청이 된다(고쳐 달라 → 상태 필드를 달라 + 즉시 응답해 달라).

목록·선택지처럼 **항목이 여럿인 것은 전부 돌린다.** 반복문 한 줄이다.

### 측정 대상을 확인한다 — **틀린 값을 믿고 고치면 없는 병을 고친다**

「회차 셀렉트만 글자가 회색」이라는 보고를 재려고 버튼의 `color`를 읽었는데,
**버튼과 그 안 자식이 다른 색**이라 값이 뒤섞였다. 실제로는 자리표시자(「고르세요」)만
회색이 맞았고, 값은 셋 다 검정이었다.

```js
// ✗ 컨테이너를 재면 자식의 색을 못 본다
getComputedStyle(button).color
// ○ 글자를 담은 **가장 안쪽** 요소를 잰다
[...button.querySelectorAll('*')].filter(e => !e.children.length && e.textContent.trim())
```

높이도 같다 — 스켈레톤을 실제 표와 맞출 때 `table.parentElement`를 쟀다가 26px이
어긋났다. **무엇을 쟀는지 한 번 출력해 보고 나서 그 값을 쓴다.**

### 스펙이 사실인지 확인한다

```bash
curl -s "$BASE/v3/api-docs" -o /tmp/live.json   # 실서버 스웨거
# 로컬 api/openapi.json 과 경로·필드를 대조한다
```

OP-01에서 `readinessCounts`가 **스펙엔 `required`인데 응답에 없어** 목록이 흰 화면이 됐다.
스펙을 믿고 짠 코드가 죽은 것이다.

## 3단계 · 판단은 기준을 세워 놓고 한다

> **먼저 [「발견 하나를 처리하는 법」](#발견-하나를-처리하는-법--모든-단계에서-여기로-돌아온다)으로
> 주인을 가른다.** 우리 것이 아니면 여기까지 올 필요가 없다.

우리가 고칠 것이면 **바로 코드를 쓰지 않는다.** 안을 여럿 두고 같은 기준으로 잰다.

### 기준 — 순서가 곧 가중치다

| | |
|---|---|
| 1 · **거짓말을 하나** | 화면이 사실이 아닌 것을 주장하면 최우선 |
| 2 · **원인이 있는 곳에서 고치나** | 증상만 덮으면 다음 사람이 또 만난다 |
| 3 · **이미 있는 것을 쓰나** | 새 개념은 유지비가 붙는다 |
| 4 · **저쪽 레포와 충돌하나** | 공용 파일 수정은 조용한 사고 |

### 쓰기 전에 있는 것부터 찾는다

```bash
grep -rn "패턴" src/features src/components src/lib | sed 's|src/||'
```

OP-01에서 이렇게 찾아 쓴 것들이다.

| 필요했던 것 | 이미 있던 것 |
|---|---|
| 「없음」 표기 | `—` 패턴이 6곳에 (`RoundGridTable` · `StatusTab` · …) |
| 실패 문구 | `lib/errorCopy` |
| 자리표시자 | `ui/Skeleton` · `TableSkeleton`의 "실측해서 박는다" 방식 |
| 이전 결과 유지 | `_shared/listQuery` |
| 회차 선택 근거 표시 | `Section`의 `note` prop |

**새 파일은 하나였다**(`BlockSkeleton`). 나머지는 전부 있는 것으로 됐다.

### 안을 표로 늘어놓고 하나를 고른다

```
| 안 | 내용 | 판정 |
| A · 최소 높이 고정 | min-h-[80px] | 데이터가 늘면 또 어긋남 |
| B · 실제 모양 스켈레톤 | 블록마다 자기 모양 | ✅ |
| C · 셋 다 올 때까지 대기 | 원래대로 | 8.8초 스피너로 회귀 |
| D · 늦는 블록을 아래로 | 순서 변경 | 정보 위계가 응답 속도에 끌려간다 |
```

**버린 안과 그 이유를 남긴다.** D를 버린 근거("조치 필요가 주인공인 것이 이 화면의 설계다")가
없으면 다음 사람이 같은 제안을 다시 한다.

## 4단계 · 고친다 — 한 번에 하나씩, 매번 다시 잰다

**고칠 때마다 2단계 측정을 다시 돌린다.** OP-01에서 이것 때문에 잡은 것들이다.

| 언제 | 무엇이 나왔나 |
|---|---|
| 쿼리를 나눈 뒤 | 푸터가 앞서 감(1쪽 데이터에 `21–30`이라고 씀) |
| 스켈레톤을 넣은 뒤 | **CLS가 오히려 올라감**(0.0445 → 0.0939) |
| 그 원인을 캐다가 | **진입 1.3초 동안 블록 셋이 전부 "불러오지 못했습니다"** ← 사용자가 말한 그 문제 |

**세 번째가 핵심이다.** 스켈레톤을 넣지 않았으면 CLS가 안 올라갔고, 안 올라갔으면 그
1.3초를 안 봤을 것이다. **고치다가 나온 이상 신호를 그냥 넘기지 않는다.**

### 고친 것이 만든 회귀를 **바로 다시 본다**

이 절차에서 가장 많이 나오는 새 버그의 출처는 **직전에 내가 한 수정**이다.
OP-03 한 화면에서 둘이 나왔다.

| 무엇을 고쳤나 | 무엇이 깨졌나 | 어떻게 알았나 |
|---|---|---|
| 툴바가 두 줄로 접혀 트리거 폭을 박았다 | **팝업까지 좁아져** 열어도 교안 이름을 못 읽는다(항목 폭 214px) | 고친 뒤 **드롭다운을 열어 봤다** |
| 조건을 URL로 옮겼다(뒤로가기 보존) | 글자마다 히스토리가 바뀌어 **한글 조합이 깨졌다** — `미니` 대신 `ㅁㅣㄴㅣ미니` | 사용자가 발견 |

**규칙은 하나다 — 고친 그 컨트롤을 다시 만져 본다.** 폭을 바꿨으면 열어 보고, 상태를
옮겼으면 타이핑해 보고, 정렬을 고쳤으면 다른 정렬도 눌러 본다. 두 번째 줄이 사용자에게
먼저 발견된 것은 **입력을 「값이 바뀌나」로만 확인하고 「어떻게 쳐지나」를 안 봤기**
때문이다.

### 같은 것이 **다른 화면에도** 있는지 훑는다

한 화면에서 고칠 값어치가 있으면 대개 다른 화면에도 있다. 고친 직후에 **그 패턴을
grep한다** — 나중에 하면 안 한다.

| OP-03에서 고친 것 | 훑으니 |
|---|---|
| 흐림만으로는 조건 전환을 못 알린다 | `staleProps`가 **6화면**에 있었다 → 전부 `StaleBlock`으로 |
| `Promise.all`이 프록시에서 죽는다 | `grep -rn "Promise.all" src/features/operator` → 진입 조회 하나가 더 있었다 |
| 툴바 이름표 형태 | OP-02와 같은 것 → `components/common/ControlLabel`로 올렸다 |

**같은 모양을 두 번 적으면 다음 화면에서 셋이 된다.** 두 번째로 쓰는 순간이 공용으로
올릴 때다(async-states §8).

### 자주 나오는 함정

| 함정 | 왜 |
|---|---|
| `isLoading`으로 「아직」을 판정 | `enabled: false`면 거짓이다 — **상류를 기다리는 것을 실패로 그린다** |
| 스켈레톤 높이를 눈대중으로 | OP-01은 133px, `TableSkeleton`도 처음에 어긋났다. **실제에서 재서 박는다** |
| 파생값으로 「없음」 판정 | `ratio`가 아니라 `graded > 0`(원인이 되는 값)으로 |
| 성공/실패 두 상태만 | 「아직」이 없으면 200을 실패라고 말하게 된다 |
| 컨트롤 폭을 박고 팝업을 안 봄 | 트리거만 좁히면 **팝업까지 좁아진다** — 열어서 확인한다 |
| 입력값을 URL·전역에 바로 반영 | 글자마다 리렌더가 나 **한글 조합이 깨진다.** 입력은 로컬이 들고 **멈춘 뒤에** 올린다 |

## 5단계 · 플로우를 탄다 — 클릭한 순간부터 프레임 단위로

> 여기서 나온 것도 **[「발견 하나를 처리하는 법」](#발견-하나를-처리하는-법--모든-단계에서-여기로-돌아온다)으로
> 판정한다.** 실제로 한 번의 관찰에서 우리 것 둘 · 다른 레포 하나 · 백엔드 하나가 나왔다.

**이것이 체크리스트보다 먼저다.** 둘은 다른 것을 잡는다.

| | 잡히는 것 |
|---|---|
| 상태별 체크리스트(5-2) | 각 상태가 **올바른가** |
| **플로우 관찰(여기)** | 상태들이 **이어질 때 사용자가 무엇을 보는가** |

전환에서만 보이는 것이 있다. OP-02에서 이렇게 나왔다 — **URL로 직접 들어가면 안 나오고,
사이드바를 클릭해야** 나온다.

```
[76ms]   ⚠ 분석 결과가 표시되지 않았습니다  [다시 시도]   ← 빨간 실패 화면이 1.8초
[2.5s]   (스피너)
[7s]     실제 표
```

같은 화면을 URL 직접 진입으로 재고 *"성능 문제없음 · CLS 0.0009"* 라고 적은 직후였다.
**정상 경로가 아니라 실제 경로를 타야 한다.**

### 어떻게 하나

**사용자가 하는 그대로** — 로그인하고, 앞 화면이 완전히 뜰 때까지 기다리고, 사이드바를
클릭한다. 그리고 클릭 순간부터 시각을 찍어 가며 본문을 캡처한다.

```js
// 앞 화면을 끝까지 기다린다 — 덜 기다리면 캐시가 안 차 있어 없는 문제를 만든다
await page.waitForTimeout(11000)

const t0 = Date.now()
await page.locator('a[href="/operator/analysis"]').first().click()

let prev = ''
for (const ms of [0, 150, 300, 500, 800, 1200, 1800, 2500, 3500, 5000, 7000, 9500]) {
  const wait = ms - (Date.now() - t0); if (wait > 0) await page.waitForTimeout(wait)
  const el = Date.now() - t0
  const txt = (await page.locator('main').innerText()).replace(/\s+/g, ' ').trim()
  await page.screenshot({ path: `flow/t${String(el).padStart(5, '0')}.png` })
  if (txt !== prev) { console.log(`[${el}ms]`, txt.slice(0, 200)); prev = txt }
}
```

**앞 화면을 끝까지 기다리는 것이 중요하다.** OP-02에서 4초만 기다렸다가 `/cohorts`가 아직
안 끝난 상태로 클릭했고, 그 바람에 **"기수 조회가 캐시가 안 된다"는 없는 문제**를 1분간
쫓았다. 캐시는 정상이었다(재호출 0건).

### 주소로 가지 말고 **눌러서 간다**

`page.goto('/projects/:id/status')`는 편하지만 **사용자가 겪는 상태를 안 밟는다.**

| | 캐시 | 결과 |
|---|---|---|
| 주소로 직접 | 없음 | 정상 |
| **목록 → 상세 → 탭 클릭** | **있음** | **화면이 통째로 죽음** |

OP-04의 크래시가 그랬다 — 개요 탭이 형제 회차를 불러 캐시를 남기는데, 다른 탭을 누르면
조회만 꺼지고 **캐시는 남아** 변환 함수가 없는 조건을 읽었다. 주소로만 재는 동안에는
7개 회차 × 3탭을 다 돌려도 한 번도 안 나왔다.

**`goto`는 딥링크·새로고침 축을 볼 때만 쓴다.** 나머지는 사이드바부터 클릭해서 간다.

### 막힌 검증이 쌓이면 **그 원인부터 뚫는다**

*"이 기수엔 데이터가 없어서 못 봤다"* 가 **두 개를 넘으면 멈춘다.** 데이터 문제가 아니라
**화면이 그 상태로 갈 길을 안 준 것**일 때가 많다.

OP-05에서 셋이 막혀 있었다 — 발행 전 기수 화면 · 확정 기수의 내보내기 · 우수 교육생
툴바(0명이면 안 그려진다). 원인이 하나였다: **기수 스위처가 진행 중 기수 하나만 줬다.**
그 하나를 열자 셋이 한 번에 풀렸고, **거기서 새 버그가 또 나왔다**(확정 기수에서만 보이는
원시 타임스탬프 — 진행 중 기수는 그 값이 `null`이라 분기를 안 탔다).

**미검증 목록은 남기는 것으로 끝내지 말고, 길어지면 그 자체를 하나의 발견으로 다룬다.**

### 대상이 여럿이면 **전부**, 빈 결과는 **실패다**

OP-04에서 회차 7개 중 3개만 보고 *"상태별로 다 확인"* 이라고 적었다. 더 나쁜 것은
**빈 출력 두 칸을 「재실행이 흔들린 것」이라고 적고 넘어간 것**이다 — 그건 결과가 아니라
**측정 실패**다. 다시 돌려야 한다(2단계에 이미 있는 규칙인데 화면 검증에서 안 지켰다).

```
□ 목록에 있는 항목을 전부 돌렸나 (일부를 「대표」로 고르지 않았나)
□ 빈 칸·타임아웃이 하나라도 있으면 → 결과로 적지 않고 다시 돌린다
□ 세 번 돌려도 같으면 그때 「이 조건에서 안 뜬다」가 발견이 된다
```

### 탭·모드가 여럿이면 **각각 돌린다**

한 탭에서 고친 것이 다른 탭에 자동으로 적용되지 않는다. OP-02에서 회차 흐름 탭을 다 고치고
**기수 간 비교 탭에는 같은 관찰을 안 돌렸는데**, 거기에 §진입-직후-실패-화면과 **똑같은
코드**가 그대로 남아 있었다.

```
□ 탭마다        진입 · 전환
□ 계층·모드마다   반별 ↔ 팀 같은 전환
□ 빈 상태에서    조작했을 때
□ 컨트롤마다     실제로 눌러 본다  ← 아래
```

### 컨트롤은 **적지 말고 눌러 본다**

1단계에서 축으로 적어 두는 것(`반 선택: 없음 / 1개 / 여러 개`)은 **목록일 뿐이다.**
OP-02에서 그 축을 적어 놓고 실제로 안 눌렀는데, 눌러 보니 **버튼 하나가 아무 일도 안 하고
있었다**(§전체-선택-해제).

응답을 가로채 보는 **상태**(로딩·빈·실패)와 **조작**은 다른 축이다. 조작은 가로채기로 안
나온다 — 눌러야 나온다.

#### 시작 전에 **컨트롤을 센다**

**세지 않으면 「다 눌렀다」를 말할 수 없다.** OP-04에서 회차 7개 중 3개만 보고 "다 봤다"고
적은 적이 있고, OP-06에서는 다이얼로그를 열고 Esc만 누른 뒤 「전수」라고 썼다.

```
OP-06   여섯 탭 합쳐 71종   (기수 11 · 반 16 · 명단 19 · 매니저 9 · 교안 14 · 비용 2)
교안    39종                (목록 12 · 등록 모달 12 · 상세 8 · 명단 CSV 7)
```

**화면마다 이 수를 먼저 적고 시작한다.** 끝나면 그 수만큼 결과 줄이 있어야 한다 —
문서에 `✅ 컨트롤 19종 전수`라고 쓰려면 19줄이 있어야 한다.

#### 선택지는 **열어서 읽는다 — 코드에서 베끼지 않는다**

드롭다운 항목을 소스에서 옮겨 적으면 **화면에 실제로 뜨는 것과 다를 수 있다.**
자동화든 손이든 **연 다음 DOM에서 읽어** 그걸로 돈다.

```js
await trigger.click()
const opts = await page.locator('[role="option"]:visible').allInnerTexts()
for (const v of opts) { /* 하나씩 고르고 결과를 잰다 */ }
```

⚠ **`:visible`을 안 붙이면 닫힌 목록을 잡는다** — 실제로 클릭이 30초 타임아웃 났다.

이렇게 하면 **선택지가 늘어난 것도 저절로 잡힌다.** 교안 상태 필터는 `전체 · 완료 ·
분석 중 · 분석 실패 · 분석 전` 다섯인데, 코드만 보면 「분석 중」이 `PENDING`+`RUNNING`
두 값을 보내는 한 줄인 것을 놓치기 쉽다.

#### 조합은 **곱이 아니라 축별 전량 + 서로 걸리는 쌍**

전 조합은 못 돈다(OP-01은 2,400개였다). 실제로 한 것은 이렇다.

| | 무엇 | 예 |
|---|---|---|
| **① 축별 전량** | 각 셀렉트의 **모든 선택지**를 하나씩 | 상태 5종 · 정렬 3종 · 반 11종 |
| **② 서로 걸리는 쌍만** | 한쪽이 다른 쪽 결과를 바꾸는 것 | 검색 + 상태 · 기수 + 반 |
| **③ 경계** | 0건 · 1건 · 상한 · 마지막 페이지 | `1반 0명` · 1000명 |
| **④ 되돌리기** | 「전체」로 돌아왔을 때 처음과 같나 | 필터 해제 |

**곱이 필요한 순간은 따로 있다** — ②에 해당하는 쌍이 실제로 갈리는지 확인할 때만.
명단 탭은 셀렉트 셋(반 11 · 계정 4 · 정렬 2 = 88 조합)이지만 **17번**으로 끝냈다.

#### 개수는 **더해서 맞춰 본다**

필터별 결과를 따로 보고 넘어가면 **틀린 것을 못 본다.** 합이 머리의 총계와 맞아야 한다.

```
전체 16 · 완료 5 · 분석 중 0 · 분석 실패 10 · 분석 전 1
        5 + 0 + 10 + 1 = 16 ✅   ← 머리의 「16개」와 일치
```

안 맞으면 **둘 중 하나가 다른 것을 세고 있다.** OP-06에서 `209`와 `225 − 17 = 208`을 보고
off-by-one으로 읽었는데, 조합 필터로 다시 세니 **분류가 다른 것**이었다.

#### 요청 수를 같이 본다

| 눌렀을 때 | 기대 |
|---|---|
| 값을 **바꾼다** | 요청 1건 |
| **같은 값**을 다시 고른다 | **요청 0건**(캐시) |
| 읽기만 하는 조작 전부 | **쓰기 요청 0건** |

**「요청 0건」이 항상 정상은 아니다** — 캐시 히트일 수도, 버튼이 죽은 것일 수도 있다.
그래서 **요청 수와 화면 상태를 같이** 적는다. 반대로 **읽기 단계에서 쓰기 요청이 하나라도
나가면 그 자체가 발견**이다.

⚠ **입력 칸은 요청이 나가는 시점이 다르다** — 디바운스가 있으면 타이핑마다가 아니라
멈춘 뒤 1건이다. 「글자마다 나간다」면 그것이 버그다.

#### 다이얼로그는 **열고 닫기만 하면 안 본 것이다**

OP-06에서 「컨트롤 71종 전수 ✅ · 쓰기 0건」이라고 적었다. 실제로는 **다이얼로그를 열고
`Esc`만 눌렀다.** 사용자가 직접 눌러 보니 그 안에서 **여덟 건이 나왔다** — 비활성화가
409로 거절되고, 재발송이 빈 배열을 보내 400이 나고, CSV 판정이 서버와 달랐다.
**전부 「확인」을 눌러야 나오는 것들이다.**

「되돌릴 수 없는 쓰기라 안 눌렀다」는 그때는 맞는 판단이었지만, **그렇다고 「전수」라고
쓰면 안 된다.** 둘은 다른 말이다.

- **되돌릴 수 있는 쓰기는 누른다.** 배정→되돌리기, 초대→취소, 비활성화(테스트 계정)
- **못 누르는 것은 「미측정」으로 남긴다.** ✅ 옆에 적지 않는다
- **되돌릴 수 없는 것도 실패 경로는 볼 수 있다.** 응답을 가로채 `409`·`400`을 만들면
  **서버를 안 건드리고** 화면이 무슨 말을 하는지 본다(실제로 반 생성 실패 3종을 그렇게 쟀다)

#### 버튼 이름이 겹치면 **어느 것을 눌렀는지 남긴다**

`.first()`로 「반 배정 →」을 잡았는데 머리의 **「반 배정하기 →」**가 걸렸다. 그래서
「고른 사람이 안 넘어간다」고 적었는데 **화면은 처음부터 정상이었다.** 누른 요소의
실제 텍스트를 로그에 같이 찍는다.

```js
const btn = panel.locator('button').filter({ hasText: '반 배정' })
console.log('후보', await btn.allInnerTexts())   // ['반 배정하기 →', '반 배정 →']
```

```js
// 요청이 실제로 나가나 · 화면이 실제로 바뀌나를 같이 본다
let reqs = []
page.on('request', r => { if (r.url().includes('/analytics/')) reqs.push(r.url()) })

const step = async (label, fn) => {
  reqs = []; await fn(); await page.waitForTimeout(3000)
  console.log(label, `요청 ${reqs.length}건`, await snapshot())   // 트리거 라벨 · 표 행 수 · 체크 상태
}
```

**「요청 0건」이 항상 버그는 아니다** — 캐시 히트일 수 있다. 그래서 **요청 수와 화면 상태를
같이** 본다. 캐시면 화면이 즉시 맞고, 버그면 화면이 안 바뀌거나 엉뚱하게 바뀐다.

| 눌러 볼 것 |
|---|
| **다중 선택** — 하나 고르기 · 여러 개 · **전부 해제** · 마지막 하나 해제 |
| **범위 선택** — 시작 > 끝로 뒤집기 · 양끝 같게 |
| **모드 전환** — 전환 후 이전 선택이 남나 · 돌아왔을 때 복원되나 |
| **정렬** — 바꾸면 요청이 나가나 · 기준선 행이 정렬에 끼나 |
| **되돌리기** — 「전체 보기」·「필터 해제」가 실제로 되돌리나 |
| **텍스트 입력** — **한글로 친다**(아래) · 공백만 · 지우기 버튼 · 아주 긴 값 |
| **드롭다운을 연다** — 값만 보지 말고 **열어서** 항목이 읽히는지 · 잠긴 항목에 이유가 있는지 |

#### 한글 입력은 **조합 중**을 따로 본다

`type('미니')`로는 안 나온다 — Playwright가 완성된 글자를 넣기 때문이다. 실제 IME는
`ㅁ → 미 → 민 → 미니`처럼 **조합 버퍼**를 거치는데, 그 사이에 컴포넌트가 다시 그려지면
**조합이 끊겨 자모가 확정 문자로 남는다.**

```js
const cdp = await page.context().newCDPSession(page)
for (const ch of ['ㅁ','ㅣ','ㄴ','ㅣ']) {
  await cdp.send('Input.imeSetComposition', { text: ch, selectionStart: 1, selectionEnd: 1 })
  await page.waitForTimeout(120)
}
await cdp.send('Input.insertText', { text: '미니' })
// 인풋 값이 '미니'가 아니라 'ㅁㅣㄴㅣ미니'면 조합 중에 리렌더가 났다는 뜻이다
```

**원인은 대개 「입력값을 곧바로 바깥에 올리는 것」이다** — URL·전역 스토어·상위 상태.
입력칸은 **로컬 값을 그리고**, 디바운스로 **멈춘 뒤에만** 밖으로 올린다.

> 검색 버튼을 다는 것으로는 **안 고쳐진다.** 버튼은 요청 수를 줄이는 도구인데
> 조합 깨짐은 요청이 아니라 **리렌더** 때문이다. 원인이 아닌 곳을 고치는 예로 기억해 둔다.

#### 되돌릴 수 없는 쓰기는 **어디까지 볼지 미리 정한다**

회차 생성은 실행하면 되돌릴 수 없다 — 삭제해도 이름·순번이 점유된 채 남는다(9차 §10).
실서버에서 함부로 누를 수 없으므로 **범위를 정하고, 안 한 것은 안 했다고 적는다.**

| 눌러도 되는 것 | 실행 전까지 |
|---|---|
| 열기 · 필수 검증 · 잠금 상태 · 로딩 표시 · Escape·취소 | 여기까지 본다 |
| 제출 · 부분 성공 · 중복 이름 409 | **미검증으로 남긴다** — 문서에 그렇게 쓴다 |

**「테스트 못 했다」를 적는 것이 안 적는 것보다 낫다.** 다음 사람이 그 자리를 안다.
막혀서 못 한 것이면(예: 후보가 안 와서 개념을 못 고름) **그것 자체가 요청서 항목이다.**

#### 자주 나오는 것

**같은 뜻인데 다른 상태**가 제일 흔하다. OP-02의 `classIds`가 그랬다.

```
[]        → 서버에 안 보냄 = 전체
[9개 id]  → 9개 명시 = 결국 전체
```

두 값이 같은 뜻이라 그 사이를 오가는 버튼은 **화면을 안 바꾸면서 요청만 냈고**, 반대
방향은 캐시라 **요청도 안 났다.** 하나씩 지워 나가다 마지막을 지우면 `[]`가 되어 **전부
선택으로 튀었다.**

→ **「전체」를 나타내는 값은 하나여야 한다.** 그리고 그 상태로 되돌리는 버튼은 **이미 그
상태면 그리지 않는다**(E7 — 누를 수 없는 컨트롤은 장식이다).

### 무엇을 보나

| 보는 것 | OP-02에서 나온 것 |
|---|---|
| **첫 프레임에 무엇이 있나** | 빨간 실패 화면(§위) |
| 문자열이 조립되다 깨지나 | 빵부스러기 `분석 › › 회차 흐름` — 기수 이름 자리가 빔 |
| **자리표시자가 거짓말하나** | 헤더가 `기수 7기` — 실제로는 9기. **오퍼레이터 5화면 전부** |
| 빈 구간이 얼마나 되나 | 0~2.5초 본문이 통째로 빔 |
| 값이 도착할 때 무엇이 움직이나 | (4단계 CLS와 이어짐) |

### 자주 나오는 것

| 증상 | 원인 |
|---|---|
| 진입 직후 실패 화면 | `isError \|\| !data`로 갈랐다 — **값이 아직 없는 것은 실패가 아니다** |
| `A › › B` | 조각을 `??  ''`로 채우고 이었다 — **있는 것만 `filter(Boolean).join()`** |
| 자리표시자가 뜬 뒤 바뀜 | 공용 셸의 기본값(`'7기'`·`'김도현'`). **모르면 안 그리는 편이 낫다** |

## 5-2단계 · 상태별로 본다

**렌더 확인은 선택이 아니다.** 코드만 봐서는 절대 안 나오는 것들이 있다.

| OP-01에서 렌더로만 잡힌 것 |
|---|
| `ErrorState` 버튼 두 개가 **세로로 쌓임**(둘 다 주요 액션처럼 보임) |
| 툴바가 **「전체 0반」** — 모르는 것을 0으로 단언 |
| 리포트 헤더가 **7기**인데 본문은 **9기** |
| 반 비교의 `분석에서 보기 ↗`가 **데이터 없어도** 떠 있음 |

### 확인 순서

```
□ 첫 진입 — 스켈레톤이 올 것과 같은 자리인가 (CLS 0에 가까운가)
□ 조건 변경 — 표가 사라지지 않는가
□ 데이터 없음 — 「아직」인가 「실패」인가, 버튼이 맞는가
□ 실패 — status별로 다른 말을 하는가, 재시도가 의미 있을 때만 있는가
□ 오프라인 — "서버 문제"라고 하지 않는가
□ 재시도 연타 — 막히는가
□ 링크 — 갈 곳이 있을 때만 있는가
□ 값이 없음 — `0`·`null`·빈 문자열이 화면에서 무엇이 되나 (`NaN%`·`· H반`)
□ 색으로 순위·상태를 말하면 — **대비를 계산해서** 잰다(눈으로 판단하지 않는다)
□ **「화면 규칙」 A~L과 대조** — 표 4단 배치 · 액션 줄 순서·아이콘 · 접미사/조사 ·
  로딩 중 표 · 탭 숫자 · 후보 목록 · 확인 모달 · 실패 문구(재시도) · `?cohort=` 유지
```

**대비는 반드시 계산한다.** OP-05에서 우수 횟수 배지를 `bg-success/40`으로 흐리게
빼고 있었는데 흰 글자 대비가 **1.8**이었다(기준 4.5). 눈으로는 "연한 초록에 흰 글자"라
그럴듯해 보인다. 단계를 늘리려던 참이라 **그대로 갔으면 못 읽는 배지를 넷 더 만들 뻔했다.**

```js
// 배경이 oklab·color-mix면 문자열로 못 잰다 — 캔버스에 칠해서 실제 픽셀을 읽는다
const ctx = document.createElement('canvas').getContext('2d')
ctx.fillStyle = getComputedStyle(el).backgroundColor
ctx.fillRect(0, 0, 1, 1)
const [r, g, b] = ctx.getImageData(0, 0, 1, 1).data
```

**dev 프리뷰(`/operator/__async`)에 넣는다.** 실제 화면 모양 그대로 전/후를 나란히 두면
말로 설명할 필요가 없어진다.

## 한 장 요약

**고치기 전에 → 「화면 규칙 — 이미 정해진 것들」**(A~L). 거기 있는 것은 **판단 대상이
아니다** — 표 배치 · 뼈대 · 액션 줄 · 값 표기 · 로딩 중 표 · 후보 목록 · 일하는 방식 ·
확인 모달 · 실패 문구 · URL 스코프 · 한글 입력 · CI 가드
발견이 나올 때마다 → **「발견 하나를 처리하는 법」**(누가 고칠 것인가 6단 판정)
화면이 크면 → **탭 하나를 화면 하나로.** 공통은 한 번, 탭마다 끝날 때 적는다

```
1. 적는다    조회 흐름 → 축 → 조합 수 → 공통 6갈래(복사해서 채운다)
2. 잰다      curl(TTFB·변수) · 브라우저(CLS·도착 시각) · 응답 가로채기 · 스펙 대조
             ├ 브라우저가 이상하면 **curl로 다시** — 프록시·CORS가 원인을 가린다
             ├ 항목이 여럿이면 **전수로** — 한 건은 표본이 아니다
             ├ **무엇을 쟀는지** 확인 — 컨테이너를 재면 자식의 값을 못 본다
             ├ 가로채기는 **먹었는지 먼저** — 안 먹으면 정상 화면을 보고 통과라 적는다
             ├ 숫자가 안 맞아 보이면 **부분합으로 한 번 더** — 다른 것을 세는 중일 수 있다
             └ 코드가 **사실이라고 적어 둔 것**을 재 본다(「서버가 ~해 준다」)
3. 고른다    안 여럿 → 기준 4개로 판정 → 있는 것부터 찾기
4. 고친다    하나씩 · 매번 다시 재기 · 이상 신호 안 넘기기
             ├ **내가 방금 만든 회귀**를 먼저 본다 — 고친 그 컨트롤을 다시 만진다
             └ 같은 것이 **다른 화면에도** 있는지 그 자리에서 grep
5. 탄다      **클릭한 순간부터 프레임 단위로** — 전환에서만 보이는 것이 있다
             ├ **주소로 가지 말고 눌러서** — 캐시가 있는 경로에서만 나는 사고가 있다
             ├ 탭·모드가 여럿이면 각각 · 컨트롤은 적지 말고 **눌러 본다**
             │   **먼저 센다**(71종) → 선택지는 **열어서 읽고**(코드에서 베끼지 않는다)
             │   → **축별 전량 + 걸리는 쌍**(곱은 안 돈다) → 개수는 **더해서 검산**
             │   → **요청 수를 같이**(같은 값 재선택은 0건 · 읽기에 쓰기 0건)
             ├ 텍스트 입력은 **한글 조합**으로 · 드롭다운은 **열어서**
             ├ 대상이 여럿이면 **전부** · **빈 결과는 결과가 아니라 실패다**
             ├ 미검증이 둘을 넘으면 **그 원인부터 뚫는다**(대개 화면이 길을 안 준 것)
             └ 되돌릴 수 없는 쓰기는 범위를 정하고 **안 한 것을 적는다**
5-2. 본다    상태별 렌더 확인 9개 · **대비는 계산으로** · 프리뷰에 전/후
6. 남긴다    ✅로 · 규칙은 CI로
```

**이 순서가 중요한 이유** — 2단계(측정) 없이 3단계(판단)로 가면 **추측으로 고치게 된다.**
OP-01에서 "느리다"는 인상이 실제로는 *"블록 셋이 한 쿼리로 묶여 있어 1.5초에 온 것이
6.6초를 더 기다린다"* 였고, 그건 재보기 전에는 아무도 몰랐다.

**5단계를 빼먹지 않는 이유** — OP-02를 URL 직접 진입으로 재고 *"성능 문제없음 · CLS
0.0009"* 라고 적은 **직후에**, 사이드바 클릭으로 들어가니 **1.8초짜리 빨간 실패 화면**이
있었다. 상태별로는 다 맞았는데 **상태가 이어지는 순간**이 틀려 있었다.
