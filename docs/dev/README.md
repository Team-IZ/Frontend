## 아키텍처 · 결정 기록

- [**응답이 안 올 때 — 요청 예산과 흰 화면**](request-timeouts.md) — **응답이 안 오면 화면이 영원히 기다렸다.** 원인 3겹(백엔드 무응답 · 타임아웃 0개 · `return null`) · **타임아웃을 10초가 아니라 90초로 잡은 이유**(콜드스타트 76초) · 예산 초과를 재시도에서 뺀 근거 · 배포 후 실측 검증 · **같은 일이 또 생기면 볼 4단계**
- [**API 없이 화면 만들기**](mock-first-screens.md) — **화면 하나를 시작할 때 이것부터 본다.** 착수 점검 → 목업 값 옮기기 → 목/경계 구조 → 완료 판정
- [**OpenAPI(스웨거)가 뭔가**](api/openapi-basics.md) — **"스웨거가 뭔데요?" 부터인 사람은 여기부터(15분, 사전 지식 0).** OpenAPI가 뭐고 왜 있나 · 누가 만드나 · 문서 구조 · `$ref`·`enum`·`required` · **다섯 가지 용도**와 우리가 쓰는 것
- [**API 붙이는 법**](api/api-usage.md) — **서버에 연결할 때 이것부터 본다(10분).** 화면에서 쓰는 법 · 명령 3개 · 폴더 구조 · 손대면 안 되는 것 · 자주 막히는 것
- [**목을 걷어내고 실서버에 붙이는 법**](api/integration-process.md) — **목으로 만든 화면을 연동할 때 이것부터(15분).** 스펙 받기 → 화면 읽기 → **대조표(여기가 핵심)** → 어댑터 → 목 삭제 → 실계정 확인 · `사용 가능`인 것만 호출 · 교육생 3화면에서 실제로 밟은 순서와 함정
- [**화면을 단단하게 만드는 법**](screen-hardening.md) — **연동이 끝난 화면을 다음 단계로 올릴 때 이것부터.** 상황 전수 → 실측 → 판단 → 수정 → 렌더 확인 → 기록. OP-01에서 끝까지 돌려 본 절차라 **나머지 화면도 이대로** 하면 된다. ⭐ **「화면 규칙 — 이미 정해진 것들」(A~L)을 먼저 본다** — OP-01~06에서 사용자가 직접 지시해 고친 것 전부(표 4단 배치·마스터디테일·액션 줄 순서와 아이콘·「반」 접미사·조사·**조건 바꿔도 표 안 비우기**(StaleBlock)·`?? []` 금지·탭 숫자 금지·후보 목록·**설정 변경엔 확인 모달**·실패 문구는 `errorCopy`가(재시도는 결과가 바뀔 때만)·**스코프는 URL이**(`?cohort=`를 들고 다닌다)·한글 조합·CI 가드 7종·계획 먼저·눌러서 확인·커밋은 요청 시). **거기 있는 것은 판단 대상이 아니다**
- [**파일 업로드 — 명단 CSV · 교안 PDF**](file-upload-csv-pdf.md) — **팀 공유용 한 장.** CSV는 이제 **엑셀 기본 저장(CP949)·열 순서 무관**으로 올라간다(서버가 넓혔는데 화면이 막고 있었다 · 서버와 6/6 일치 확인). PDF는 **4.5MB가 천장**이고 그 근거(Lambda 6MB ÷ base64 ×4/3 · 이분 탐색 실측)와 화면 동작. **눌러 보고 나온 버그 6건** — 413·제목중복이 「PDF 파일인지 확인해 주세요」로 뭉개지던 것, 실패 배너가 탭·재오픈에 남던 것, **등록 직후 「분석 실패」라 해 놓고 실제로는 분석 중**이라 시킨 대로 누르면 돌던 분석을 버리던 것. 남은 것 — 4.5MB 초과는 presigned S3(백엔드) · Vercel 한도 미측정
