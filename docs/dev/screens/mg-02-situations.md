# MG-02 히트맵 — 상황 기록

실계정(이담 · 매니저 · 9기 C반)으로 `docs/dev/screen-hardening.md` 절차를 한 바퀴 돌렸다.

## 1. 조회와 의존 — **3단 직렬이다**

```
GET /members/me/enrollments                 2.5s   ─┐ cohortId가 나와야
GET /cohorts/{id}/trainees?size=1           7.9s   ─┤ 회차(projectId+roundId)가 나오고
GET /cohorts/{id}/analytics/heatmap         2.4s   ─┘ 그래야 격자를 부른다
```

명부를 빌려 쓰는 이유는 **히트맵 회차 선택지를 주는 조회가 없어서**다. 히트맵은
`projectId`와 `assessmentRoundId`를 **둘 다** 필수로 받는데, 그 짝을 함께 주는 것이
명부의 `rounds[]`뿐이다.

## 2. 실측

### 응답 시간 (담당 반 C반 26명 · 개념 3 · 팀 6)

| 조회 | TTFB | 크기 |
|---|---|---|
| `/members/me/enrollments` | 2.52s | 125B |
| **`/cohorts/{id}/trainees?size=1`** | **7.89s · 6.22s** | 3.2KB |
| `/analytics/heatmap` CLASS | 2.56s · 2.07s | 1.7KB |
| `/analytics/heatmap` TEAM | 2.40s | 3.6KB |
| `/interviews/rounds` (참고) | 1.54s · 1.17s | 861B |

`size=1`인데도 7.9초다 — 32차 R9와 같은 관측이다.

### 플로우 (대시보드 → 사이드바 클릭, 프레임 단위)

```
[150ms]    툴바만 (회차 없음 · 격자 없음)
[2.5s]     빵부스러기에 기수가 붙음 (히트맵 › 9기)
[12.0s]    회차·격자 전부
```

**첫 격자까지 12초.** CLS는 0이라 화면이 흔들리지는 않는다.

### 스코프 파라미터 — 계층마다 필수가 다르다

```
level=TEAM     반 없이 → 400 HEATMAP_SCOPE_INVALID
level=TRAINEE  팀 없이 → 400 (반만으로는 부족하다)
```

### 가로채기 — 빈 상태·실패

| 만든 상태 | 화면이 한 말 | 판정 |
|---|---|---|
| `concepts: []` | 「이 회차는 아직 결과가 없어요」 | ✅ |
| `rows: []` (개념은 있음) | 격자 머리 + 「이 범위에는 아직 결과가 없습니다」 | ✅ |
| `500` | 「불러오지 못했습니다 · 다시 시도」 | ✅ |

## 3. 고친 것 — 전부 우리 코드다

### 🔴 툴바 「팀」·「팀원」 버튼이 400에서 못 빠져나왔다

`navigation`은 **지금 계층보다 위**의 선택지만 준다 — `CLASS`에서는 통째로 비어
온다. 아래 단계 항목은 `rows[]`에 있고 그 `rowId`가 곧 `classroomId`·`teamId`다.

화면이 빈 `navigation`에서 기본값을 찾고 있었다. 그래서 계층만 바뀌고 스코프는 빈
채로 나가 400이 되는데, 채울 값은 영영 안 온다(그 요청이 실패했으므로).

**고침** — 본 것을 기억한다(`knownClassrooms`·`knownTeams`). 계층을 내릴 때는
스코프를 먼저 채우고 바꾸고, 팀 목록을 아직 모르면 「팀원」 버튼을 **잠그고 왜인지
말한다**(팀 격자를 한 번 봐야 생긴다).

### 🔴 회차를 바꿔도 팀이 그대로 따라갔다

팀은 **프로젝트에 매인다** — 회차마다 다시 짠다. 그런데 다른 회차의 `teamId`를
넣으면 서버가 **400이 아니라 200 + 빈 결과**를 준다.

```
5차 회차 + 6차 팀 id  →  200, rows: [], summary: null, scope.teamName 없음
```

그대로 두면 화면이 「이 범위에는 아직 결과가 없습니다」라고 말한다 — **거짓말이다.**
없는 게 아니라 그 팀이 이 회차에 없는 것이다.

**고침** — 회차를 바꾸면 팀을 비우고 `TEAM` 계층으로 내려온다. 반은 기수 소속이라
그대로 쓴다. 반을 바꿀 때도 같다(이전 팀은 다른 반 소속이다).

### 회귀 확인

고친 컨트롤을 다시 눌렀다.

```
진입(CLASS)        「팀원」 잠김 · 반 격자 · 히트맵 › 9기
CLASS에서 팀원      아무 일 없음(잠김이 맞다)
팀                 히트맵 › 9기 › C반 · 반 select 자동 채움 · 6팀
팀 → 팀원           히트맵 › 9기 › C반 › 2팀 · 팀 select 자동 채움
회차 6차 → 5차      팀원 → 팀으로 내려옴 · 팀 select 사라짐 · 7팀 · 개념이 바뀜
```

## 4. 요청서로 나가는 것 (32차)

### 히트맵 회차 선택지 때문에 7.9초 명부를 빌려 쓴다

`/interviews/rounds`가 **1.2초**에 같은 `assessmentRoundId` 6건을 준다(id도 일치).
그런데 **`projectId`가 없어** 히트맵을 부를 수 없다.

그 응답에 `projectId` 한 칸이 붙으면 첫 진입이 **12초 → 5초**가 된다(명부 7.9초가
빠지고, 기수 조회와 병렬로도 돌 수 있다).

### 다른 회차의 `teamId`가 400이 아니라 200 + 빈 결과다

화면 쪽은 막았지만, 「없다」와 「이 회차 것이 아니다」가 같은 응답으로 오면 화면이
어느 쪽인지 말할 수 없다.

## 5. 미검증

- **반이 여럿인 매니저** — 이 계정은 C반 하나뿐이라 반 select 전환을 못 눌러 봤다
  (코드 경로는 회차 전환과 같다)
- **`다시 보기`(`attemptView=REVIEW`)** — 이 기수에 다시 보기 데이터가 있는지 확인
  안 했다. 토글은 눌러 봤지만 값이 갈리는지는 못 봤다
- **콜드 스타트** — 측정 중 서버가 자는 상황을 만나지 못했다
- **오측 하나** — `/enrollments`(잘못된 경로)로 110초를 재고 「무응답」이라고 쓸
  뻔했다. 실제 경로는 `/members/me/enrollments`다(2.5초). 스펙에서 경로를 확인하고
  나서 다시 쟀다
