# 파킹랏
- 공용 매니저 와이어프레임(dashboard 등 ~10개) 좌측 nav의 옛 "기수 구성" → 삭제, 총괄 셸에만 "운영 관리" 표기하는 nav 스윕 (D67·D68 후속). ※담당 매니저가 "기수 구성/프로젝트"를 보는지 = RBAC 미확정, 사용자 확인 필요(D77 구현 중 재확인).
- D77 후속: 프로젝트 생성 폼(FB-F5, 총괄 권한) + 팀 편성 골라담기 상세 뷰 미구현. 워크스페이스는 조회/구조까지만.
- D77 후속: 10개 매니저 화면 chrome의 준비/실행/분석 그룹핑 미반영(project-workspace 셸에만 정식 반영).
- 제품 nav 깊이 정책(검토 필요): 목업 내부 사이드바에 하위메뉴(토글) 도입 여부. 결론 방향 — 사이드바=장소(명사)지 액션(동사)이 아니므로 "프로젝트 생성/편집" 같은 액션은 nav 잎사귀 금지(버튼·배지로 게이팅). 예외는 **운영관리(총괄, 가끔 쓰는 설정)만** 장소성 하위메뉴(기수/반/명단/매니저) 허용. 데일리 영역(분석진단·교육생·개입·리포트)은 얕은 nav 유지. '한눈에 관리'는 nav 깊이가 아니라 overview 화면으로. (쇼케이스 사이드바 ≠ 제품 사이드바 — 전자는 리뷰용 전수 열거라 깊어도 됨.)
