# OP-06 · 운영 관리 — 탭 5 + 배정 모드

## 1. 한 줄

**조직을 세팅한다.** 기수·반·명단·매니저·교안·비용.

## 2. 진입 · 이탈

좌측 네비. `반·명단`의 `[배정]` → **모드**.

## 3. 뷰

```
운영 관리
[ 기수 ] [ 반·명단 ] [ 매니저 ] [ 교안 ] [ 비용 ]
```

| 탭 | 범위 | 내용 |
|---|---|---|
| **기수** | 기관 전체 | 목록 · 생성 · 종료 |
| **반·명단** | **선택 기수** | 반 목록 + 명단 · `[배정]` → 모드 |
| **매니저** | 기관 전체 | 초대 · 반 배정 · 정지 |
| **교안** | 기관 전체 | 목록 · 등록 · 재분석 · 가르친 항목 |
| **비용** | **선택 기수** | 기관 총량 + 기수/반 |

**상단 기수 스위처가 범위를 정한다.** 반·명단·비용은 "지금 고른 기수"이고, 매니저와
교안만 기관 전체다 — **매니저는 기수를 옮겨 다니고 교안은 여러 기수가 같이 쓴다.**

**`반`과 `명단`을 한 탭으로 합친다.** 반을 만드는 것과 명단을 넣는 것은 한 흐름인데
탭이 갈리면 계속 오간다 — 반 하나를 추가하고 바로 그 반에 사람을 넣는 것이 실제 동선이다.

### 명단 추가 — CSV 일괄 / 직접 입력

| | 언제 | 검증 |
|---|---|---|
| **CSV** | 최초 수십~수백 명 | 유효 n · 중복 제외 n · 형식 오류 행 번호 |
| **직접 입력** | 지각 등록 1~2명 | 형식·중복을 그 자리에서 |

**기관 도메인 밖 주소는 등록되지 않는다.** 등록과 동시에 활성화 초대가 나간다.

### 매니저 초대 — 권한 선택이 없다

이메일 + **담당 반**만 받는다. 총괄/담당이 폐기되어 매니저가 한 종류뿐이고, 무엇을 볼
수 있는지는 **담당 반**이 정한다.

**퇴사한 매니저를 지우지 않고 정지로 남긴다.** 담당 반 배정이 **기간형 이력**이라 6기
A반 담당이 누구였는지가 그 계정에 붙어 있다 — 지우면 지난 기수의 기록이 끊긴다.

### 배정 — 모드

```
반 배정 · 7기 · 미배정 3명                              [닫기]

좌 반 레일                       우 미배정 명단
──────────────────              ──────────────────────────
A반  25 / 25 정원  박지현        ☑ 한도현   활성    직전 —
B반  25 / 25 정원  이도윤        ☑ 정하늘   초대됨  직전 —
F반  22 → 24 / 25  담당 없음 ⚠   ☐ 오지훈   활성    직전 6기 C반
                                 ← 왼쪽 반을 누르면 그 자리에서 들어감
```

**표가 아니라 작업이라 모드로 연다.** 반마다 인원과 담당을 보면서 골라야 하고, 250명을
한 번에 끝내지 않는다 — 좌우가 동시에 보여야 반복 배정이 된다.

#### 상태 4개 — 이 화면의 설계는 상태 전이에 있다

| 상태 | 레일 | 오른쪽 |
|---|---|---|
| **① 진입 (0명 선택)** | **흐림** + `먼저 교육생을 고르세요` | 명단 |
| **② 선택** | 활성 + **`22 → 24 / 25` 미리보기** | 벌크바(붙어 있음) |
| **③ 배정 직후** | 흐림 + `방금 +2` | **되돌리기 토스트** · 목록에서 그 사람들이 빠짐 |
| **④ 미배정 0** | 흐림 | 완료 상태 + `[완료]` 강조 |

**즉시 실행 + 되돌리기.** 확인 모달을 세우면 반복 배정이 안 되고(250명을 스무 번 나눠
넣는다), 안 세우면 잘못 누른 25명을 손으로 되돌려야 한다. **토스트에 누가 어느 반에
들어갔는지 이름으로 적고 한 번에 물릴 수 있게 한다.**

**정원을 같이 적는다.** `25명`만 있으면 더 넣어도 되는지 판단할 수 없다. 고른 순간
**결과를 미리 보여준다**(`22 → 24 / 25`) — 넣기 전에 알면 되돌릴 일이 줄어든다.

**정원 초과를 막지는 않는다.** 중도 합류·반 통폐합으로 실제로 생기고, 막으면 운영이
멈춘다 — 넘는다는 사실만 알린다.

**선택은 모드로 이월된다.** 명단에서 2명 고르고 `반 배정 →`을 누르면 그 선택을 들고
간다 — 리셋되면 방금 한 일을 다시 해야 한다.

**`직전 기수` 열을 둔다.** 재수강생을 같은 반에 다시 넣을지 판단하는 근거다.

**이미 배정된 사람을 옮기는 것도 여기서 된다.** `범위` 필터를 **전체**로 바꾸면 현재
소속 열이 생긴다 — 반 통폐합처럼 여러 명을 한꺼번에 옮길 때 쓴다. 한 명만 옮기는 것은
명단 탭의 `반 변경`이 빠르다.

### 교안 탭

```
교안 목록 → 교안 상세 — 탭 2
             ├ 섹션            좌 섹션 목록 → 우 그 섹션이 가르친 항목
             └ 연결된 프로젝트   이 교안을 쓰는 회차 · 안전장치
```

**목록 열**: 교안 · 버전 · 섹션 수 · 가르친 항목 수 · 연결된 프로젝트 · 분석 상태.

#### 파이프라인 산출에서 무엇을 보여주고 무엇을 버리나

**교안 분석 단계가 내놓는 것은 `질문에 사용할 teaches` 하나다.** 화면은 그 목록을
읽기 좋게 보여주는 것까지다.

| 버리는 것 | 왜 |
|---|---|
| 노드·관계 수 · 청크 수 · extractor 이름 | 운영자가 그 숫자로 할 일이 없다 |
| 관계 타입 영문명 | 내부 용어 |
| 섹션 테이블과 항목 목록을 **따로** | 같은 데이터의 두 뷰다(D1) — 마스터-디테일 하나로 합친다 |
| **참고 자료 링크** | 만들지 않는다 |

| 남기는 것 | 어디에 쓰나 |
|---|---|
| 섹션 이름 + **페이지 범위** | 리포트·면담이 가리키는 교안 위치가 이 값이다 |
| 항목 이름 + **정의 한 줄** | 프로젝트에서 3개를 고를 때 무엇을 묻게 될지 판단하는 근거 |

#### `연결된 프로젝트` — 조회가 아니라 안전장치다

프로젝트가 교안을 고르는 관계의 **역방향**이라 D1에 걸릴 것 같지만, 여기 있는 것은
**회차 목록이 아니라 그 교안에 대한 제약**이다. 행을 눌러도 프로젝트 화면으로 넘어갈 뿐
여기서 고치지 않는다.

| 넣는 이유 | |
|---|---|
| **다시 분석** | 섹션이 합쳐지거나 쪽 번호가 달라진다 → **이미 발행된 리포트의 교안 위치가 어긋난다** |
| **새 버전 업로드** | 응시 중인 회차의 문항은 지금 버전 기준으로 만들어져 있다 |
| 회차별로 **어떤 항목을 골랐는지** | 다음 회차에 바꿀 때의 근거 |

**응시가 시작된 회차가 있으면 재분석에 확인 모달을 세운다.** 이미 응시한 학생의 문항과
리포트는 그대로 두고, **새 분석 결과는 다음에 만드는 회차부터** 적용한다.

## 4. 데이터

기수·반·명단·매니저 배정(기간형 이력) · 교안 분석 결과(섹션 · 페이지 · 가르친 항목 ·
정의) · 기수/반별 사용량.

## 5. 액션

생성·초대·배정·정지 · 명단 CSV·직접 등록 · 교안 등록/재분석/파일 교체.

## 6. 상태 — 왜 그렇게 정했나

> **케이스 표는 목업에 있다** — [`operator/admin.html#cases`](../wireframe/operator/admin.html#cases).

### CSV는 한 줄 때문에 전체를 막지 않는다

| | |
|---|---|
| **유효 행** | 등록한다 |
| **이미 등록된 이메일** | 건너뛴다 |
| **형식 오류** | **행 번호로** 알린다 |

수백 명 파일을 한 줄 때문에 통째로 되돌리면 아무도 안 쓴다. **도메인 밖 주소는 등록 차단**이다.

### 배정은 표가 아니라 작업이라 모드로 연다

여러 번 반복하는 동안 **좌우(반·미배정 인원)가 동시에** 보여야 한다. 배정 직후에는 **되돌리기**를 남긴다 — 잘못 넣으면 그 학생이 엉뚱한 반에서 회차를 시작한다.

### 매니저 초대에 권한 선택이 없다

총괄/담당이 폐기되어 **매니저는 한 종류**다. 고를 것은 **반 배정**뿐이다.

### 교안 재분석은 쓰는 회차를 먼저 보여준다

이미 응시한 문항과 리포트는 **그대로 두고**, 새 결과는 **다음 회차부터** 적용한다 — 지난 회차 결과가 바뀌면 회차 간 비교가 깨진다.

**분석 실패한 교안은 프로젝트에 연결할 수 없다**(OP-03의 `교안에 항목 0`).

### 오퍼레이터 계정은 여기서 다루지 않는다

초대·정지는 **슈퍼어드민**(SA-02) 소관이다. 이 화면은 **매니저**까지만 다룬다.
## 7. 안 하는 것

| | 어디에 |
|---|---|
| 프로젝트 생성 · 교안 연결 · 질문 항목 확정 | **OP-03 · OP-04**(기수마다 6~8번 반복이라 여기 묻지 않는다) |
| 학생 개인 조회 | **OP-02 드릴다운** |
| 매니저용 교안 열람 | **MG-09 뷰어**(링크 전용) |
| 팀 편성 | **MG-08**(반 배정까지가 여기, 팀은 회차마다 매니저가) |
| **모델별 단가** | **SA-03**(플랫폼이 정하고 기관은 티어 이름만 본다) |
