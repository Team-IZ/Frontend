# TR-03 검증 세션 — 상황 전수와 실측

> 절차는 [screen-hardening.md](../screen-hardening.md). 연동이 끝난 화면을 **값이 오기
> 전·안 올 때·이상하게 올 때**까지 단단하게 만든다.
>
> 계정은 `trainee01@example.com`(로그인 화면 `교육생` 버튼) — **실제 응시 중**이라 세션
> 내부 상태를 소모 없이 볼 수 있다. 실측일 2026-08-18.

---

## 0. 왜 이 화면이 까다로운가

**되돌릴 수 없는 화면이다.** 다른 화면은 잘못 그려도 새로고침하면 되는데, 여기는

- 시작 버튼을 누르면 60분 시계가 돌기 시작하고 계정이 소모된다
- 힌트를 열면 되돌릴 수 없다(질문당 2개)
- 문제 상한(20분)이 지나면 서버가 그 문제를 닫는다 — **화면을 열어 두기만 해도** 지나간다

그래서 **틀린 값을 그리는 것보다 안 그리는 게 나은 자리**가 많다.

## 1. 축

### 조회 순서

```
GET /assessment-sessions/current      ─┐ 이게 끝나야
  ├ 204 → 사유는 홈에서 (GET /assessment-rounds)
  └ 200 → GET /problems/{currentProblemNo}   ─┘ 나머지가 시작한다

쓰기: POST /start · /answers · /hints · /activity
```

### 축 A. 세션 상태

```
A1 READY (시작 전)        A2 IN_PROGRESS (진행 중·복귀)
A3 204 (없음) × 사유 6종   A4 조회 실패
```

### 축 B. 문제 상태

```
B1 turns 0 · current 있음 (막 들어옴)   B2 turns N · current 있음 (답 쌓는 중)
B3 current 없음 (문제 닫힘)             B4 problemNo가 낡음 → 409
```

### 축 C. 질문 상태

```
C1 hintsLeft 2 (아직 안 씀)   C2 hintsLeft 1   C3 hintsLeft 0 (소진)
C4 shownHints 있음 (복원)     C5 lastTurnOfSession
```

### 축 D. 코드 패널

```
D1 파일이 짧다   D2 파일이 아주 길다(243줄 실측)
D3 references 없음   D4 CALLER 여럿   D5 필드가 null인 reference
```

### 축 E. 공통 (하드닝 문서 6갈래)

네트워크 · 인증 · 시간 · 사용자 조작 · 표현/성능 · 접근성 · **값의 빈 구석**

조합은 수백 가지다. 아래는 **실제로 갈리는 지점**만 잰 것이다.

## 2. 실측

### 2-1. 🔴 줄 번호가 47칸 밀려 있었다 — 고침

**가장 큰 발견.** 스펙을 잘못 읽었다.

| 필드 | 스펙 원문 | 우리가 한 것 |
|---|---|---|
| `snippet` | **문제를 낸 파일 전체** | 〃 |
| `lineStart` | **강조할 구간 시작(파일 기준 절대 줄 번호)** | 🔴 스니펫이 시작하는 줄로 오해 |

스니펫 첫 줄에 `lineStart`(48)를 붙이고 있었다. 실제 파일은 243줄이고 1번 줄부터
오므로 **모든 줄이 47칸 밀렸다.**

```
받은 것   snippet 243줄 · code.lineStart 48 · lineEnd 51
잘못      48 ~ 290 으로 번호가 매겨짐 (하이라이트도 엉뚱한 줄)
고침 후   1 ~ 243 · 강조 48~51 (서버가 준 구간과 일치)
```

> 시드 데이터(4줄 · `lineStart 20`)에서는 우연히 티가 안 났다. **실제 데이터를 보고서야
> 드러났다** — 37차 R4로 "서버 데이터가 어긋난다"고 보냈던 건이 사실은 이쪽 오해였다.
> 39차에서 정정한다.

### 2-2. 🔴 긴 파일에서 강조가 화면 밖이었다 — 고침

243줄이 오는데 강조는 48번 줄이다. 자동 스크롤이 없어 **학생이 스크롤로 찾아야 했고**,
그 시간이 첫 타이핑 지연(`firstKeystrokeDelayMs`)으로 기록된다.

질문이 바뀔 때마다 강조 줄을 **위에서 1/4 지점**에 놓는다(맨 위에 붙이면 앞 문맥이 안
보인다). 실측 — `scrollTop 1148` · 보이는 첫 줄 43 · 강조 48~51.

### 2-3. 🟡 호출부가 없는 위치를 가리켰다 — 고침

```json
{"type":"CALLER","path":"…/CohortController.java","lineStart":1,"lineEnd":1}
{"type":"CURRICULUM_EVIDENCE","path":null,"lineStart":null,"lineEnd":null}
```

- `CALLER`는 **다른 파일**을 가리키면서 줄이 `1~1`이다 → `CohortController.java:1`은
  없는 위치다. 구간이 한 줄뿐이면 **위치를 말하지 않고 파일 이름만** 보여준다.
- `CURRICULUM_EVIDENCE`는 필드가 전부 `null`이다(스키마상 필수인데도) → `path`가 없는
  참조는 버린다.

### 2-4. ✅ 아직 안 온 문제도 `PROBLEM_ALREADY_CLOSED`

| 요청 | 응답 |
|---|---|
| 지난 문제 | `409 PROBLEM_ALREADY_CLOSED` |
| **아직 안 온 문제(2, 3)** | **`409 PROBLEM_ALREADY_CLOSED`** (같은 코드) |
| 범위 밖(0, 99) | `400 VALIDATION_FAILED` |

같은 코드지만 **화면이 하는 일이 같아서 문제가 되지 않는다** — 어느 쪽이든 커서를
서버에게 다시 물어 따라간다. 무한 루프도 안 난다: 커서가 그대로면 상태가 안 바뀌어
재조회가 트리거되지 않는다.

### 2-5. ✅ 힌트 소진 상태가 제대로 그려진다

이 계정이 `hintsUsed 2 · hintsLeft 0`이다.

```
버튼          없음 ✅
문구          "더 이상 설명해 드릴 수 없어요. 아는 만큼만 써 주세요." ✅
이미 연 힌트   2개 복원 ✅ (shownHints)
```

### 2-6. ✅ 그 밖

| 축 | 결과 |
|---|---|
| 짧은 답변 경고 | ✅ "조금 더 써 볼까요? 지금은 짧아요" |
| 붙여넣기 차단 | ✅ 막힘 |
| 좁은 화면(640px) | ✅ 가로 넘침 없음 · 버튼 살아 있음 |
| 응답 시간 | `GET /current` 1.4초 · `GET /problems` 1.6초 |

## 3. 못 밝힌 것

| 무엇 | 왜 |
|---|---|
| **실제 창 전환 이탈** | Playwright에서 `visibilitychange`·`blur`·`focus`가 **하나도 안 뜬다**(직접 계측). 우리 처리 경로가 도는 것까지만 확인했고 **사람이 손으로 봐야 한다** |
| **신호가 서버에 쌓이는지** | 되읽는 API가 없다(전수 확인). `204`까지가 전부 — 39차 R1 |
| **답변 제출 이후 전 구간** | `POST /answers`가 90초에 끊긴다(37차 R1). 전환·종료 화면을 실데이터로 못 봤다 |
