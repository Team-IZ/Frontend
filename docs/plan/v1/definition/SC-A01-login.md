# SC-A01 · 로그인

> 소스: 기능명세서 v8 AUTH-03(주) + 수렴/발산 흐름 AUTH-01·02·05·06·04.
> 배치: P0 · 진입 순서 1번(전 화면 공통 관문). 이 화면에서 **정의서 포맷·디자인 토큰·와이어프레임 컨벤션을 확정**한다.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 역할 | 공통(슈퍼어드민 / 매니저 / 교육생) — **역할은 서버가 판정**, 사용자가 선택하지 않음 |
| 진입 경로 | 접속 진입점 / SC-A02(가입·활성화) 완료 후 → / 이메일 인증(AUTH-02)·활성화(AUTH-06) 메일 → / 로그아웃(AUTH-04) 후 → |
| 연계 FR | **AUTH-03(로그인·주)**, AUTH-02(미인증 재발송), AUTH-05(비밀번호 찾기 진입), AUTH-01·06(가입·활성화 도착점), 전역: AUTH-09(RBAC 컨텍스트 발급), SYS-02(org_id 컨텍스트) |
| 이번 배치 범위 | 이메일/비밀번호 로그인, 역할별 초기화면 라우팅, 로그인 실패 재입력(v8), 계정 잠금/미인증/비활성 안내, 비밀번호 찾기 진입 |
| 후속 확장 | SSO/OAuth 로그인(미정), 2FA(미정) — 현재 명세에 없음, "해당 없음" |
| 만들지 않음 | **공개 회원가입 링크 없음** — 계정은 초대 기반(AUTH-01 유효 초대 토큰 / AUTH-06 명단 외 활성화 불가) |

## 2. 목적 & UX 설계 근거

- **단일 관문, 역할 자동 분기.** AUTH-03 처리로직 6단계는 인증 성공 시 `역할별 초기화면`을 반환한다 → 화면은 역할 선택 UI를 두지 않고, 서버 응답으로 매니저는 SC-M01, 교육생은 SC-T01로 **자동 라우팅**. 역할 선택 드롭다운을 두면 계정 열거·오분기 위험이 생긴다.
- **실패는 같은 화면에서 재입력(v8).** AUTH-03 비고 "변경(v8): 로그인 실패 시 로그인 화면 복귀 — 비밀번호 재설정 자동 이동 없음". 실패 시 화면을 벗어나지 않고 인라인 알림 + 재입력. 비밀번호 재설정은 **사용자가 '비밀번호 찾기'를 눌러야만** SC-A03로 간다(AUTH-05는 사용자 선택 경로).
- **계정 존재를 노출하지 않는다.** AUTH-03 case1 "동일 오류 메시지", AUTH-05 case1 "계정 존재 여부 노출 안 함". 아이디 틀림/비번 틀림을 구분해 보여주면 계정 열거 공격 표면이 된다 → **하나의 문구**로 통일.
- **차단 사유는 행동으로 연결한다.** 잠금·미인증·비활성은 각각 다음 행동(대기·재발송·관리자 문의)이 다르므로 문구를 구분(단, 인증 실패와는 섞지 않음).
- 중앙 카드 유지: 방법론상 "인증·단순 목록은 중앙 카드 유지"(뷰 패턴을 바꿀 이유 없음).

## 3. 정보 구조 & 레이아웃

**데스크톱 2단 분할 레이아웃**(웹 기준). 좌 브랜드 패널 + 우 폼 패널.

**좌 · 브랜드 패널(`BrandPanel`):** `Wordmark` + 마케팅 리드("코드 이해도를 검증합니다") + 설명문 + 하단 meta. 제품 정체성 전달(폼과 시각 분리).

**우 · 폼 패널(`AuthForm`):** 위→아래:
1. 제목 "로그인" + 보조 문구
2. `InlineAlert` 슬롯 — 상태 발생 시에만 노출(에러/잠금/미인증)
3. `TextField` 이메일
4. `PasswordField` 비밀번호 (표시 토글)
5. `PrimaryButton` "로그인" (전체 폭)
6. `TextLink` "비밀번호를 잊으셨나요?" → SC-A03

**반응형(웹 기준 · 모바일은 변형):**
- **데스크톱(기본):** 좌 브랜드 패널 + 우 폼 2단 분할.
- **모바일(반응형):** 브랜드 패널 축소/상단 이동, 폼 단일 컬럼 세로 스택. 별도 화면 아님 — 같은 컴포넌트의 반응형.

와이어프레임과 1:1 대응(§10).

|---|---|---|---|
| 이메일 | email (입력) | AUTH-03 입력 | `TextField`(type=email, required) |
| 비밀번호 | password (입력, 화면 미저장) | AUTH-03 입력 | `PasswordField`(표시 토글) |

## 5. 화면 액션 → 데이터/API 요구사항 (백엔드 착수 근거)

| 액션 | 트리거 | 오퍼레이션 | 요청 데이터 | 응답 · 부수효과 | 관련 FR | 검증 · 권한 규칙 |
|---|---|---|---|---|---|---|
| 로그인 제출 | 버튼 클릭 / Enter | `POST /auth/login` (세션 생성) | `{ email, password }` | `{ accessToken, role, initialScreen }` + **Set-Cookie refreshToken(Secure·HttpOnly, TTL 7d)** + 실패 시 **실패 카운트 증가**·임계 초과 시 **계정 잠금(만료시각 기록)** + **AuditLog(로그인 성공/실패·시각·대상)** | AUTH-03 | 미인증·미활성·잠금 계정 차단 / 실패 임계 초과 시 일시 잠금 / **성공/실패 동일 오류 문구(계정 열거 방지)** / role·org_id 부재 시 차단 |

| 비밀번호 찾기 이동 | 링크 클릭 | 화면 전이(무API) | — | → **SC-A03** | AUTH-05 | — |
| 로그인 성공 라우팅 | 응답 수신 | 클라이언트 라우팅 | `initialScreen`/`role` | 매니저 → **SC-M01** · 교육생 → **SC-T01** · 슈퍼어드민 → **SC-S01** | AUTH-03 | 서버 판정 역할로만 분기 |

## 6. 상태별 UI (예외 case 전량 1:1 — 게이트 A)

공통 상태 + **AUTH-03 예외 9 case**를 상태 행으로 전량 매핑. (비주얼은 정상+지배 상태만 와이어프레임화, 나머지는 이 표가 계약 — v1/v2 분리)

| # | 상태 | 트리거(명세 case) | 화면 표현 | 다음 행동 |
|---|---|---|---|---|
| — | 정상(입력 전) | 진입 | 빈 폼, 알림 없음 | 입력 |
| — | 제출 중(로딩) | 버튼 클릭 후 | 버튼 로딩·입력 잠금 | 대기 |
| — | 성공 | 인증 통과 | 즉시 라우팅(화면 이탈) | SC-M01/T01/S01 |
| 1 | 인증 실패 | case1 이메일/비번 불일치 | `InlineAlert danger` **"이메일 또는 비밀번호를 확인해주세요."**(단일 문구) | 재입력(화면 유지) |
| 2 | 잠금 발생 | case2 실패 임계 초과 | `InlineAlert warning` "여러 번 실패하여 계정이 잠겼습니다. {만료시각} 이후 다시 시도하세요." | 대기 |
| 3 | 잠금 상태 진입 | case3 잠금 계정 로그인 | 상동(만료시각 안내) · 제출 버튼 비활성 | 대기 / 관리자 문의 |
| 4 | 미인증 계정 | case4 미인증 | `InlineAlert info` "이메일 인증이 필요합니다." + **[인증 메일 재발송]** 링크 | 재발송 |
| 5 | 비활성 계정 | case5 비활성 | `InlineAlert danger` "이용할 수 없는 계정입니다. 관리자에게 문의하세요." | 관리자 문의 |

| 7 | 시스템 오류(롤백) | case7 Refresh 발급·DB 실패 → 전체 롤백 | 상동(로그인 미완료 처리) | 재시도 |
| 8 | 시스템 오류(쿠키) | case8 Refresh Cookie 설정 실패 | 상동(서버가 DB 토큰 폐기 후 실패 처리) | 재시도 |
| 9 | 권한 컨텍스트 결여 | case9 role/org_id 부재 | `InlineAlert danger` "계정 권한 설정에 문제가 있습니다. 관리자에게 문의하세요." | 관리자 문의 |

## 7. 인터랙션 & 화면 전이

- 로그인 성공 → (서버 role) 매니저 `SC-M01` / 교육생 `SC-T01` / 슈퍼어드민 `SC-S01`.
- 로그인 실패(case1~9) → **SC-A01 유지**(재입력). 자동 이동 없음(v8).
- "비밀번호를 잊으셨나요?" → `SC-A03`.
- 미인증(case4) 재발송 → SC-A01 유지, 안내 문구 갱신.
- (도착 흐름) SC-A02 가입/활성화 완료·AUTH-04 로그아웃 → SC-A01.

## 9. UX 준수 규칙

| 규칙 | 이 화면에서의 구현 | 근거 |
|---|---|---|
| 보안: 계정 열거 방지 | 성공/실패·존재/부재를 **단일 오류 문구**로 통일(case1, 재발송) | AUTH-03 case1, AUTH-05 case1 |
| 차단 상태는 행동으로 | 잠금(대기)·미인증(재발송)·비활성/권한(문의)을 구분 문구 | AUTH-03 case2~5·9 |
| 초대 기반 계정 | 공개 회원가입 링크 없음 | AUTH-01, AUTH-06 |
| 실패 시 화면 유지(v8) | 비번재설정 자동이동 금지, 사용자 선택 링크로만 | AUTH-03 v8, AUTH-05 |
| RBAC/격리 컨텍스트 | role·org_id 부재 시 로그인 차단(case9), 성공 시 인증 컨텍스트 발급 | AUTH-09, SYS-02 |
| 표현 규범 A1~A8 | **해당 없음** — 측정/시그널/수치 표시가 없는 화면(명시적으로 닫음) | — |
