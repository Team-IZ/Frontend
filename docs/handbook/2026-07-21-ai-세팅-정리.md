## 2. 진단 — 상시 발동 지침이 4겹

매 응답에 무조건 걸리는 층:

1. **ponytail (full)** — "설명이 코드보다 길면 설명을 지워라"
2. **session-discipline.sh** — "매 응답 첫 줄에 단계와 게이트를 적어라"
3. **superpowers** — "응답 전 무조건 스킬부터 확인해라"
4. **karpathy-guidelines** — 과설계 금지 · 수술적 변경 (ponytail과 내용 80% 중복)

문제 두 가지.

**충돌** — 1번은 짧게 쓰라 하고 2번은 머리말을 붙이라 한다. 3번은 답하기 전에 도구를 한 번 더 태운다. 서로 반대 방향으로 당긴다.

**희석** — 상시 지침이 늘수록 개별 지침의 구속력이 떨어진다. 4번은 1번이 이미 한 말을 반복하므로 컨텍스트만 먹고 새 정보는 0.

**팀 공유 불가** — 규약의 대부분(표 배치 표준 · 화면 규격 · 커밋 금지)이 `~/.claude` 개인 메모리에 있다. 팀원이 이 레포를 클론하면 아무것도 물려받지 못한다. 레포에 `CLAUDE.md`가 없다.

## 3. 최강 조합

```
상시 발동 1개      ponytail (full)            — 과설계 브레이크
프로젝트 규율 1개   CLAUDE.md                  — 팀 공유 가능한 유일한 층
도구 1개           playwright MCP             — 목업을 눈으로 검증
명시 호출 N개      superpowers · impeccable   — 필요할 때만 /호출
```

**원칙: 상시 발동은 1개까지. 나머지는 전부 명시 호출용.**

### 왜 이 구성인가

- **ponytail만 상시** — 이 프로젝트의 실패 모드는 "코드를 못 짜는 것"이 아니라 "문서·목업이 계속 불어나는 것"이다. 거기에 직접 걸리는 브레이크는 ponytail 하나뿐. 방법론 총합 4번 조항("문서가 코드보다 무거워지면 멈추고 만들 것")과 같은 철학이다.
- **karpathy는 버린다** — ponytail과 같은 말. 둘 중 하나만.
- **superpowers는 무기고로만** — `brainstorming`(새 화면 설계 전) · `systematic-debugging`(버그) · `writing-plans`(구현 착수) 세 개는 실제로 값어치를 한다. 하지만 "매 응답 전 스킬 확인" 강제는 그 셋을 쓰려고 나머지 11개 비용을 매번 내는 구조다.
- **playwright MCP는 핵심** — 스크린샷으로 목업을 검토하는 게 실제 워크플로다. 도구지 지침이 아니라서 희석 문제도 없다.
- **session-discipline.sh는 CLAUDE.md로 흡수** — 훅으로 매번 주입할 이유가 없다. CLAUDE.md에 쓰면 같은 효과에 팀 공유까지 된다.

### 우선순위 (충돌 시)

```
CLAUDE.md  >  스킬/플러그인 지침  >  기본 동작
```

CLAUDE.md가 가장 위다. 그래서 superpowers의 상시 강제도 CLAUDE.md 한 줄로 무력화할 수 있다.

## 4. 적용 절차

1. **`andrej-karpathy-skills` 비활성** — `/plugin` → 해제. ponytail과 중복.
2. **`CLAUDE.md` 생성** — 아래 세 곳을 한 파일로 합친다.
   - `session-discipline.sh`의 규율 4개
   - `~/.claude` 메모리 중 프로젝트 규약(표 배치 표준 · 마스터-디테일 규격 · 커밋 금지 · 결정 로그 위치)
   - "스킬은 명시 호출 시에만" 한 줄
3. **`session-discipline.sh` 제거** — 2번이 끝난 뒤. `.claude/settings.local.json`의 SessionStart 훅 블록도 같이 삭제.
4. **권한 목록 정리** — `settings.local.json` allow 약 170줄 중 대부분이 화면정의서 작업 중 승인한 일회성 `perl -0pi -e` / `pkill` / 스크린샷 명령이다. `/fewer-permission-prompts`로 재생성.

3번까지 하면 상시 발동이 ponytail 하나로 정리되고, 응답 첫 줄의 단계 선언은 CLAUDE.md 관할로 넘어간다.

## 5. 다음에 판단할 때 쓰는 기준

새 플러그인·스킬을 볼 때 이 순서로 자른다.

1. **상시 발동인가?** → 이미 ponytail이 있다. 대체할 만큼 나은 게 아니면 탈락.
2. **기존 것과 겹치는가?** → 겹치면 하나만. 둘 다 켜면 둘 다 약해진다.
3. **이 단계에서 발동할 일이 있는가?** → 화면정의서 단계에서 TDD·worktree 스킬은 죽은 무게다. 코딩 들어갈 때 켠다.
4. **도구인가 지침인가?** → 도구(MCP)는 희석 문제가 없다. 지침은 있다.

객관적 "최고 세팅" 순위표 같은 건 없다. 플러그인은 많이 깔수록 나빠진다는 것만 확실하다.
