## 1. 🔴 R1 — 미응시인 셀에 값이 옵니다

**1차 · C반 6팀 · 윤지우**입니다.

```jsonc
// GET .../analytics/heatmap?...&level=TRAINEE&teamId={6팀}
{ "rowName": "윤지우", "cells": [
    { "problemNo": 1, "value": 3, "status": "NOT_ATTENDED" },
    { "problemNo": 2, "value": 2, "status": "NOT_ATTENDED" },
    { "problemNo": 3, "value": 0, "status": "NOT_ATTENDED" }
]}
```

같은 응답의 합계가 이 사람을 **미응시로 세고 있습니다.**

```jsonc
"summary": { "memberCount": 4, "cells": [
  { "problemNo": 1, "validCount": 3, "notAttendedCount": 1, ... }
]}
```

### 화면이 「3단 · 2단 · 0단」을 그렸습니다

저희 빈 셀 판정이 `validCount === 0`이었는데, **개인 셀은 `validCount`가 항상 `null`**이라
그 분기를 안 탔습니다. 그래서 미응시인 사람에게 도달 단계가 찍혔고, 매니저는 응시한
것으로 읽습니다 — 반 평균과도 어긋납니다(그 사람은 평균에서 빠져 있습니다).

**저희 쪽은 고쳤습니다** — `status`를 값보다 먼저 봅니다.

```
합계·반·팀 셀   validCount 0        아무도 유효 응시를 안 했다
개인 셀        status NOT_ATTENDED  그 사람이 안 봤다
```

### 여쭙는 것

`value`가 **무엇을 뜻하는 값**인지 알고 싶습니다.

- 미응시인데 3·2·0이 나온 것이 **지난 회차 값**이거나 **계산 중간값**이라면, 화면이
  실수로 그릴 수 있으니 **`null`로 주시는 편**이 안전합니다
- 뜻이 있는 값이라면 그게 무엇인지 알려 주시면 화면이 그에 맞게 그리겠습니다

**같은 자리에 무효(`CONFIRMED_INVALID`)도 있습니다**(2차 2팀 심예린) — 그쪽도 같은
질문입니다.

### 재현

```bash

?projectId=043fa888-6bcf-5fc4-a26d-94d787fb1df6\
&assessmentRoundId=4fe959b8-825b-5ce4-adf3-a8f80632aef0\
```

## 2. 🟠 R2 — 인원과 행이 안 맞는데 이유가 응답에 없습니다

**여러 회차에서 납니다.** 아래는 1차 · C반 1팀입니다.

```
summary.memberCount        5
summary.cells[].validCount 4
summary.cells[].notAttendedCount   0
summary.cells[].invalidCount       0
summary.cells[].interruptedCount   0

rows                       4명 (백은우 · 손지안 · 임윤슬 · 최육교)
navigation.teams[1팀].memberCount   5
```

**5명인데 4명만 옵니다.** 그런데 빠진 1명이 `notAttended`·`invalid`·`interrupted`
**어디에도 안 잡힙니다**(전부 0). 세 카운터로는 `5 - 4 = 1`을 설명할 수 없습니다.

> 참고 — 그 1명(한유진)은 **2차부터는 정상적으로 나옵니다**(1팀 5명 전원). 회차마다
> 명단이 다른 것 자체는 이상하지 않은데, **그 사실을 응답이 말해 주지 않는 것**이
> 문제입니다.

**4차 4팀에서도 같은 것이 납니다**(`memberCount 4` · `rows 3`). 1차 단발이 아닙니다.

**08-18에 여섯 회차 × 모든 팀을 다시 돌렸습니다** — 두 자리만 어긋나고 나머지는 맞습니다.

```
1차 1팀   행 4 / memberCount 5   미응시 0 · 무효 0 · 중단 0    ← 1명이 세 카운터 어디에도 없다
4차 4팀   행 3 / memberCount 4   미응시 0 · 무효 0 · 중단 0
그 밖     전부 일치 ✅
```

### 화면이 「전체 5명」이라 쓰고 4행만 보여줬습니다

한 명이 증발한 것처럼 보입니다. **저희는 「4 / 5명」으로 바꾸고** 마우스를 올리면
「1명은 이 회차 명단에 없습니다」가 나오게 해 뒀습니다 — 다만 **저희가 지어낸 문구**라,
실제 사유(중도 이탈·회차 미배정·다른 반으로 이동 등)와 다를 수 있습니다.

### 요청

`memberCount`가 **무엇을 세는지** 확정해 주시면 좋겠습니다. 둘 중 하나면 화면이
정확해집니다.

| 안 | 내용 |
|---|---|
| ① `memberCount`를 **이 회차 명단 기준**으로 | 그러면 `rows.length`와 항상 같아집니다 |
| ② 차이를 세는 카운터를 하나 더 | `notInRoundCount` 같은 자리 — 화면이 사유를 지어내지 않아도 됩니다 |

## 3. 🟠 R3 — 팀 하나가 통째로 빠진 회차가 있습니다

**2차 · C반 · 팀 계층**입니다.

```
summary.memberCount 26
summary.cells[]     validCount 20 · notAttended 1 · invalid 1        (합 22)

rows  1팀 5 · 2팀 5 · 3팀 4 · 5팀 4 · 6팀 4                          (합 22)
      ← 4팀이 없습니다
```

**26 − 22 = 4명**이 어느 줄에도 없습니다. 1차에서는 같은 반에 **1~6팀이 전부** 왔고
합이 26이었습니다(5+5+4+4+4+4).

**여섯 회차를 전부 돌리니 두 회차에서 납니다 — 빠지는 팀이 서로 다릅니다.**
아래는 **2026-08-18 재확인** 값이고, 첫 측정(08-17)과 같습니다.

```
1차   팀 6개 · 합 26 = memberCount 26   ✅   [1,2,3,4,5,6팀]
2차   팀 5개 · 합 22 ≠ memberCount 26   🔴   [1,2,3,5,6팀]   ← 4팀 없음 · 4명이 어디에도 없다
3차   팀 6개 · 합 26 = memberCount 26   ✅
4차   팀 6개 · 합 26 = memberCount 26   ✅
5차   팀 6개 · 합 26 = memberCount 26   ✅
6차   팀 5개 · 합 21 ≠ memberCount 26   🔴   [2,3,4,5,6팀]   ← 1팀 없음 · 5명이 어디에도 없다
```

**팀이 없어진 것이 아닙니다** — 4팀은 3·4·5차에 정상으로 오고(문유진·백서준·유재윤·
최윤슬), 1팀도 1~5차에 정상입니다. **특정 회차 응답에서만 빠집니다.**

`memberCount`는 여섯 회차 모두 26으로 같습니다.

### 화면에서는 이렇게 보입니다

머리가 「전체 26명」인데 팀을 다 더하면 22명이라, 매니저가 세어 보면 안 맞습니다.
팀 드롭다운에도 4팀이 없어 **그 팀으로 들어갈 방법이 없습니다.**

R2와 같은 종류로 보입니다 — **빠진 인원이 어느 카운터에도 안 잡힙니다.**

### 여쭙는 것

- 2차에 **4팀이 실제로 없는 것**인지(그 회차에 편성되지 않았다) 확인 부탁드립니다
- 없는 것이 맞다면 `memberCount`가 26인 이유가 궁금합니다 — 그 회차에 팀이 없는
  4명을 세고 있다면, R2의 ①·② 중 하나로 함께 풀릴 것 같습니다

### 재현

```bash
curl -s "$API/api/v0/cohorts/$COHORT/analytics/heatmap\
?projectId=9e092e21-8343-5aae-86cb-2fdf3b3580be\
&assessmentRoundId=3e4e4ee8-4ae3-5013-8cd7-92c1c47ee39d\
&level=TEAM&classroomId=c8b9022b-cef0-4f5f-952f-04642058e326" \

```

## 6. 🔴 R4 — 32차 R1이 아직 재현됩니다

회신은 기준을 `outcome_judged_at`으로 옮겨 **「`items`가 있는데 `PENDING`인 조합이
구조적으로 나올 수 없다」**고 했는데, 같은 회차에서 그대로 납니다.

```jsonc
// GET /api/v0/interviews?assessmentRoundId={5차}
"round":  { "resultStatus": "PENDING", "publishedAt": null },
"total":  4,
"counts": { "PLANNED": 4, "DONE": 0, "EXCLUDED": 0 },
```

### 33차 R1(프록시의 404) — 교육생 상세에서 다시 만났습니다

「앱은 404를 내고 프록시가 삼킨다」고 하셔서, 새 요청은 아니고 **사례만 보탭니다.**

```
GET /cohorts/{9기}/trainees/00000000-0000-4000-8000-000000000000
  → 무응답 (node 헤더 타임아웃 · 브라우저에서도 75초 뒤 실패로 떨어짐)
```

화면에서는 이렇게 보입니다.

```
0초 ──────────────── 75초 ────────────
스켈레톤 그대로       「교육생 정보를 불러오지 못했습니다」
```

저희 화면은 **404 `MANAGER_SCOPE_NOT_FOUND`를 받으면** 「담당하는 반의 교육생만 볼 수
있습니다」라고 말하도록 이미 갈라 두었는데, 응답이 안 오니 **그 안내가 한 번도 안 뜹니다**
— 75초를 기다린 끝에 엉뚱하게 「불러오지 못했습니다」가 나옵니다.

담당 밖의 **실재하는** 교육생으로는 확인하지 못했습니다 — 매니저 토큰으로는 담당 반 밖
교육생의 id를 얻을 방법이 없어서입니다(그게 스코프의 목적이기도 합니다). 그쪽은 32차
R3처럼 정상 404일 수도 있습니다.

**교안(MG-09)에서도 같은 것이 재현됩니다** — 32차 R12로 이미 올린 자리인데, 이번에
다시 재도 그대로입니다.

```
GET /curricula/{없는 UUID}            → 30초에서 저희가 끊었습니다 (무응답)
GET /curricula/{없는 UUID}/sections   → 30초에서 저희가 끊었습니다 (무응답)
GET /curricula/not-a-uuid             → 1.11초 400            ✅ 형식 오류는 정상입니다
```

**형식이 틀리면 1.1초에 400이 오는데, 형식이 맞고 없는 값이면 답이 없습니다.** 세 화면
(교육생 상세·교안 상세·교안 섹션)에서 같은 증상이라, 33차 R1이 풀리면 셋이 함께 풀릴
것으로 보고 따로 요청드리지 않습니다.
