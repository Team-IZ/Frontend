# MG-07 · 프로젝트 목록 (매니저)

## 1. 한 줄

담당 반이 지금 어느 회차에 있고 **무엇이 밀렸는지** 본다.

> **오퍼레이터와 같은 목록, 담당 반 범위**다(18번 3-5). 같은 표이지만 답하는 질문이
> 다르다 — OP-03은 *"무엇으로 잴 것인가"* 이고 여기는 *"내 반이 어디까지 왔나"* 다.

## 2. 진입 · 이탈

좌측 네비 → 행 클릭 → **MG-08**.

### 교안과 검증 개념을 한 열에 2줄로

칩으로 그렸다가 텍스트로 바꿨다. **교안은 프로젝트당 여러 개 붙을 수 있고**(14번 4-3)
개념은 3건이라, **둘을 각각 칩으로 쓰면 행이 무한정 높아진다.**

합칠 근거는 14번 4-3에 있다 — *"확정한 3건은 **출처 교안과 섹션을 달고 다닌다**."*
**개념이 어느 교안에서 왔는지가 같이 읽히는 정보**다.

```
AI_LLMOps v2 · Streamlit 실습 v1 · FastAPI 기초 v3     ← 교안 3개여도 한 줄
HITL Trigger · Graph 구성 · State 관리
```

**2줄 고정**이다. 위가 출처, 아래가 무엇을 물었나.

### 담당 반이 여럿인 경우

매니저는 A·B·C반 담당일 수 있다. **합계만 쓰면 A반은 다 냈는데 C반이 밀린 상황을
못 본다.**

| | |
|---|---|
| 진행 | 합계 + **뒤처진 반**(`58/71` · `C반이 12/23`) |
| 조치 | **반 이름을 붙인다**(`A반 미제출 2팀` · `C반 분석 실패 1팀`) |
| 툴바 | **반 필터** — 한 반만 보면 조치에서 반 이름이 빠진다(스코프가 이미 그 반이라 반복) |

**반별 상세는 MG-08 `제출 현황`** 이 답한다. 목록에 반을 펼치면 **행이 반 수만큼
늘어나** 회차 목록이 아니게 된다.

### 상태 열이 필요하다

한때 *"`진행` 열이 이미 단계를 말한다"* 며 뺐다가 되돌렸다. **툴바에 `상태` 필터가
있는데 열이 없으면 무엇을 필터하는지 알 수 없다** — 필터의 대상은 화면에 있어야 한다.

### 빅프의 앵커는 검증 개념이 아니다

6-2가 갈라 놓았다.

| | 미프 | 빅프 |
|---|---|---|
| 앵커 | **검증 개념**(교안 기반) | **본인 커밋 영역** |
| 선별 | 교안 교집합 | **기존 정적 스캐너** |

**시작 전에는 회차 번호가 없다.** 첫 회차 시점이 *"첫 동작하는 코드가 나온 시점"* 이라
학생마다 다르다(10-2) — `1/3회차`가 아니라 **`총 3회`** 로 쓴다.

**빅프는 사람마다 3개가 다르므로** 한 값으로 열에 넣을 수 없다 — `본인 커밋 영역 —
사람마다 다름`으로 쓴다. **교안도 쓰지 않으므로** `—`가 아니라 **`교안 해당 없음`**
이다(`—`은 *"아직 없음"* 으로 읽힌다).

**열 이름은 `검증 개념 3건`으로 둔다** — `앵커`는 14번 내부 용어이고 목록 대부분이
미프다.

### OP-03과 통일하지 않은 것

**시간 방향이 반대**라 세 가지는 달라야 한다(자세한 비교는 OP-03 3-2).

| | 매니저 | 오퍼레이터 |
|---|---|---|
| 기본 정렬 | **최신순** — 지금 회차를 본다 | **준비 필요 순** — 예정 회차를 본다 |
| 조치 단위 | **사람·팀**(`A반 미제출 2팀`) | **설계**(`개념 3건 확정`) |
| 진행 | **실수**(`58/71`) — 13명이 독촉 대상 | **비율**(`86%`) — 개인을 못 본다 |

**예정 회차가 매니저에게는 빈 행이고 오퍼레이터에게는 가장 급한 행**이다.

### 미프·빅프는 동시에 진행 중일 수 없다

10-2 — *"**미프·빅프는 순차다.** 미프가 앞에서 몇 개월, 빅프가 마지막 8주.
**일정 충돌이 없다.**"* 목업에서 둘을 동시 진행으로 그렸다가 고쳤다.

### 진행은 파이프라인 현재 단계 하나만

정의서 초안은 `응시 19/23`만 있었는데 **회차마다 볼 지점이 다르다.**

| 회차가 어디 있나 | 진행 열 |
|---|---|
| 마감 전 | **제출** `62/75` |
| 분석 중 | **분석** `59/62` |
| 응시 창 | **응시** `58/71` |
| 종료 후 | **리포트** `발행 완료` |

**단계 이름 + 값을 한 열에 같이 쓴다.** 네 값을 다 늘어놓으면 다섯 줄을 훑을 때
**지금 어디인지**가 안 보이고, 값만 쓰면 그게 제출인지 응시인지 모른다.

### `조치` 열이 이 화면의 질문에 답한다

정의서 첫 줄이 *"무엇이 밀렸는지 본다"* 인데 **그 열이 없었다.**

```
미제출 2팀 · 분석 실패 1팀     ← 진행 중 회차
면담 4명 · 다시 보기 3명       ← 종료된 회차
—                            ← 정상(축하 문구를 넣지 않는다)
```

### 검증 개념은 읽기 값 — 경고도 띄우지 않는다

OP-03은 미확정 회차에 `⚠ 항목 미확정`을 띄운다. **오퍼레이터는 확정할 수 있기 때문**이다.
여기서는 `—`만 쓴다 — **할 수 없는 일을 알려도 할 일이 안 생기고**, 경고만 쌓인다.

**제출 마감이 비어 있는 것도 사실 그대로** 둔다. 일정은 오퍼레이터가 정한다.

### 담당 반이 여러 개면 합계

매니저는 A·B·C반 담당일 수 있다. **목록에 반을 펼치면 행이 반 수만큼 늘어나** 회차
목록이 아니게 된다 — 반별 내역은 **MG-08 `제출 현황`** 이 답한다.

헤더에 스코프를 쓴다(`담당 A·B·C반 · 75명`).

### 빅프는 회차 번호를 함께 쓴다

미프는 **회차 1개 = 프로젝트 1개**인데 **빅프는 3회차**다(10-2 — 첫 기능 동작 · +2주 ·
마감). 같은 표에서 `진행`의 뜻이 달라지므로 빅프 행에 `1/3회차 · 첫 기능 동작`을 붙인다.

## 4. 데이터

회차명 · 유형 · **연결 교안(여러 개) + 검증 개념 3건**(읽기, 한 열) · 제출 마감 ·
**현재 단계 + 값 + 뒤처진 반**(담당 반 합계) · **조치**(반 이름 + 미제출·분석 실패·면담) ·
상태.

**빅프는 회차 번호와 시점**을 함께 읽고, **앵커가 사람마다 다르다**(6-2).
