## 2. 목적 & UX 설계 근거

- **교안은 프로젝트가 아니라 기수 자산이다(D85·B10·D91).** 프로젝트 하위 탭에 넣으면 공유 자산이 프로젝트마다 쪼개지고 버전·승인 상태머신이 중복된다. 그래서 **상단 독립 메뉴**(대시보드·프로젝트·리포트 동렬), 교안·버전 키로 등록하는 **콘텐츠 라이브러리**.
- **프로젝트 ↔ 교안 = 기본은 기수 전체 자동, 링크는 선택적 좁히기다(D103, D91 기본값 뒤집기).** 교안은 기수 자산(D85)이라 **기수가 자연스러운 검색 경계**(3기 교안이 7기 학생에게 갈 일 없음). 학생이 특정 주제에서 막히면 그 주제를 다루는 섹션은 관련 교안에만 있어(주제 매칭이 이미 내용 오염을 막음), **프로젝트 링크 없이도 기수 전체에서 정확히 찾는다.** 종합 프로젝트(여러 교안·섹션이 다 필요)가 이 기본 동작으로 자연히 해결된다. **링크는 예외 도구** — 프론트/백엔드가 섞인 기수에서 특정 프로젝트를 특정 교안으로만 좁히고 싶을 때만. **미링크 = "안내 없음"이 아니라 "기수 전체 검색"**(D103 핵심, 옛 D91 "미연결=생략"이 만든 침묵 실패 제거). 안내가 정말 안 나가는 건 그 기수에 관련 주제 교안이 하나도 없을 때뿐이고, 그건 "교안을 더 올려야 한다"는 유용한 신호(커버리지).
- **문제 출제(교안→문제 생성)는 보류 유지(P2 이하·D85·D91).** 이 제품은 "자기 코드 메타인지"를 재는데(내용 독립·차별점), 교안 내용 퀴즈 생성은 **콘텐츠 지식 시험**이라 방향이 반대·커모디티. 교안 역할은 **위치 안내 소비까지만**, 측정 생성 안 함.
- **화면은 3개(D103 통합).** 목록(컬렉션)·등록(폼)·**교안 상세**(구조·섹션 주제·커버리지 통합). 구 '교안 연결' 탭은 사실상 '교안 구성'과 중복(둘 다 섹션↔주제 편집)이라 교안 상세 1화면으로 합침. 프로젝트 링크는 필수 액션이 아니게 돼(기본이 기수 전체 자동) 교안 쪽엔 링크 UI 불필요, 범위 좁히기 저작은 프로젝트 개요에만(D98).
- **섹션 주제 = AI 기본값 + 사람 편집 — 자동완성 패턴(D102, D96·D100 신뢰도 노출 모델과 D101 전량 수동 모두 재검토).** 매칭은 두 단계로 분리: ① 교안 쪽 = "각 섹션이 무슨 **주제**를 다루나"(교안 내재 속성, 프로젝트 무관, 교안당 1회) ② 리포트 시점 = "학생이 막힌 주제를 가진 섹션 검색". 교안 쪽은 **AI가 추출 키워드로 주제 칩을 미리 채우고, 총괄은 훑어보고 틀린 것만** 고친다. 신뢰도·"AI 제안" 배지는 화면에 절대 안 보인다(폼 자동완성처럼) — 최종 정확도는 사람이 훑으므로 100%, AI는 시간만 아껴준다. 자동확정 금지(GOV-02)는 측정에만 적용, 이 화면과 무관.
- **위치 안내까지만, 처방형 콘텐츠 배제(MEAS-07).** 학생 (주제,축) 취약 → 그 주제 섹션을 [범위: 링크 교안 or 기수 전체]에서 검색 → 축 규칙(D94)으로 섹션 내 위치 안내. 교안→문제 생성은 **보류**(차별성 희석, D85). 주제 매칭 0건이면 위치 안내만 생략(정상).
- **구현 범위는 PDF 1경로.** pptx/docx/스캔본은 실제 유입 확인 후 착수(보류).

## 3. 정보 구조 & 레이아웃 (매니저 앱 셸 · 데스크톱)

**3화면(메뉴 하나당 화면 하나 · 해시 라우팅, project-workspace/report와 동일 · D103 통합).**

**① 교안 목록(CUR-03 · 컬렉션·상태 머신):** 표 배치 표준(헤더 제목+총개수 좌 / +등록 우, 툴바 좌: 검색·추출상태·주제지정 필터, 푸터 범위 좌+페이저 중앙).
- 행: 교안명·유형·버전·**추출 상태 배지**·**주제 지정 배지**(N/M 섹션)·적용 프로젝트·최종 수정
- 추출 상태 머신: UPLOADED → EXTRACTING → EXTRACTED / EXTRACTION_FAILED (매핑 승인 상태는 D103에서 폐기 — 주제 지정은 섹션 단위 N/M로 표시)

**② 교안 등록(CUR-03 · 업로드):** PDF 드롭존 + 메타(교안명·주제·유형·버전) 폼. 업로드 성공 → UPLOADED → 구조 추출 자동 시작(EXTRACTING). 동일 교안 수정 시 기존 버전 보존.

**③ 교안 상세(CUR-01+CUR-02 통합 · 1화면 · D103):** 목록 행 클릭 → 진입. 위→아래:
- **섹션·주제 표**(구 '교안 구성'): 섹션명·페이지·**다루는 주제 칩**(AI가 추출 키워드로 자동 채움, 총괄이 틀린 칩만 ✕ / +추가). 추출 내부(신뢰도 스칼라·refine·청크·폴백)는 telemetry라 감춤. 실패 시 재분석(총괄).
- **커버리지 요약**: "이 기수 프로젝트 측정 주제 N개 중 M개 커버 · 미커버 주제 → 교안 추가 권장." 자동 계산·매니저 액션 없음(읽기).
- **범위 좁히기 안내**: 특정 프로젝트만 이 교안으로 한정하려면 [프로젝트] 개요에서. 지정 안 하면 기수 전체 교안에서 자동 검색(기본).
- **축→노드타입 고정 규칙**(반례대응→주의·반례 / 코드이해→개념 / 대안비교→비교 / 자기수정→복구 / 의사소통=대상 아님) — 편집 대상 아님(고정).
- **학생별 정확 위치 = 리포트 시점 검색**(D94 유지): 학생이 (주제,축) 취약 → 그 주제 섹션을 [범위] 안에서 검색 → 축 규칙으로 섹션 내 위치.

반응형: 웹 기준.

## 7. 인터랙션 & 화면 전이

- 목록 [+교안 등록] → 등록 폼 → 업로드 → UPLOADED→EXTRACTING → 교안 상세(자동 진입).
- 교안 상세: AI가 채운 섹션 주제 칩을 총괄이 훑고 틀린 것만 ✕/+추가. 즉시 저장, 별도 확정 액션 없음.
- 지정된 주제 → **SC-T05/SC-M08 리포트 "취약축→교안 위치 안내"** 소비(MEAS-07): 학생 (주제,축) → [범위: 프로젝트 한정 교안 or 기수 전체] 섹션 검색. 리포트 "교안 화면 ▸" → 교안 상세 역참조(D86).
- EXTRACTION_FAILED → 재분석 또는 삭제만.
- **선행조건(flow):** 교안 등록·**섹션 주제 확인**은 **회차 시작 전 완료**. 프로젝트 링크는 선택(안 하면 기수 전체 자동). 그 기수에 관련 주제 교안이 하나도 없을 때만 T05 위치 안내 생략(측정·피드백은 그대로·§3 교차계약 3·10).
- **환류:** 주제 변경 이력을 전역 `AuditLog`에 기록(누가·언제·무엇을, `source`로 AI초안/사람편집 구분). 화면 노출용 자기학습·정답라벨 축적은 없음(D102) — `source`는 운영 지표(AI 초안이 얼마나 자주 고쳐지는지)로만 오프라인 참고, 사용자 화면 기능 아님.
