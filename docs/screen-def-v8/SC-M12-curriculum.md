## 2. 목적 & UX 설계 근거

- **교안은 프로젝트가 아니라 기수 자산이다(D85·B10·D91).** 프로젝트 하위 탭에 넣으면 공유 자산이 프로젝트마다 쪼개지고 버전·승인 상태머신이 중복된다. 그래서 **상단 독립 메뉴**(대시보드·프로젝트·리포트 동렬), 교안·버전 키로 등록하는 **콘텐츠 라이브러리**.
- **프로젝트 ↔ 교안 = 선택적 다대다 참조다(D91 · 소유 아님).** ~~"한 기수의 여러 프로젝트가 교안을 공통 참조"~~(초기 서술 오류 정정): 한 기수라도 과목 국면이 다르면(예: 1월 프론트 / 2월 백엔드) 프로젝트마다 맞는 교안이 **다르다**. **측정 5축은 내용 독립이지만 처방(교안 위치 안내)은 내용 의존** — 백엔드 프로젝트에서 반례대응 취약 학생에게 프론트 교안을 주면 무의미. 그래서 **프로젝트 생성 시 총괄이 관련 교안을 링크**(다대다, 비워도 됨). MEAS-07은 [프로젝트→링크된 교안]→[매핑(CUR-02)→페이지] 2단으로 정확한 위치 해결. **미연결 프로젝트도 정상** — 그 경우 위치 안내만 생략(측정·피드백은 그대로). 소유가 아니라 참조라 0개·공유·무관 전부 성립.
- **문제 출제(교안→문제 생성)는 보류 유지(P2 이하·D85·D91).** 이 제품은 "자기 코드 메타인지"를 재는데(내용 독립·차별점), 교안 내용 퀴즈 생성은 **콘텐츠 지식 시험**이라 방향이 반대·커모디티. 교안 역할은 **위치 안내 소비까지만**, 측정 생성 안 함.
- **파이프라인은 3단, 화면은 4개(메뉴=화면).** 등록·구조추출(CUR-01) → 교안 연결(CUR-02, 매니저 직접 태깅) → 태그된 섹션이 리포트 위치 안내(MEAS-07)로 소비. 목록(컬렉션)·등록(폼)·구조추출(결과)·교안연결(태깅)을 각각 독립 화면으로 분리(긴 스크롤 금지).
- **AI 자동 매칭 대신 매니저 직접 태깅 — 규모 재평가(D101, D96·D100 매칭 메커니즘 철회).** 교안 1개당 섹션 4~6개 · 프로젝트 1개당 기술영역 3~4개 = 매칭 대상 십수 개 조합. AI/자동화가 이기는 조건은 사람이 감당 못 할 규모일 때인데, 이 규모는 사람이 한 번에 감당한다 — 신뢰도 점수·자동/생략/미커버 3상태·오버라이드 UI를 만드는 건 **과설계**였다. 등록 시 이미 "주제·설명"을 훑어 채우는 총괄이 섹션마다 체크박스 몇 개 더 누르는 건 추가 노동이 거의 0이고, **직접 체크가 AI 추천 검토보다 빠르고 항상 정확**하다(확률이 없으니 틀릴 여지가 없음). 자동확정 금지(GOV-02)는 측정(채점·위험 판정)에만 적용되는 규칙이라 이 화면과는 애초에 무관 — 사람이 직접 정하는 값에 "자동확정 금지"는 해당 사항 없음.
- **위치 안내까지만, 처방형 콘텐츠 배제(MEAS-07).** 태그된 섹션은 리포트에서 "취약축→교안 X페이지" 위치 안내로만 소비. 교안→문제 생성은 **보류**(차별성 희석, D85). 미링크·미태그면 위치 안내만 생략.
- **구현 범위는 PDF 1경로.** pptx/docx/스캔본은 실제 유입 확인 후 착수(보류).

## 3. 정보 구조 & 레이아웃 (매니저 앱 셸 · 데스크톱)

**4화면(메뉴 하나당 화면 하나 · 해시 라우팅, project-workspace/report와 동일).**

**① 교안 목록(CUR-03 · 컬렉션·상태 머신):** 표 배치 표준(헤더 제목+총개수 좌 / +등록 우, 툴바 좌: 검색·과정·추출상태·매핑검수 필터, 푸터 범위 좌+페이저 중앙).
- 행: 교안명·과정/차수·유형·버전·**추출 상태 배지**·**매핑 검수 배지**·최종 수정
- 상태 머신: UPLOADED → EXTRACTING → EXTRACTED / EXTRACTION_FAILED → MAPPING_PENDING → REVIEW_PENDING → APPROVED

**② 교안 등록(CUR-03 · 업로드):** PDF 드롭존 + 메타(과정·차수·주제·유형·버전) 폼. 업로드 성공 → UPLOADED → 구조 추출 자동 시작(EXTRACTING). 동일 교안 수정 시 기존 버전 보존.

**③ 교안 구성(CUR-01, 구 '구조 추출' · D93 매니저 관점):** 매니저용 목차 — 처리 상태 한 줄 + **섹션·페이지·주요 주제 표**. 추출 처리 내부(신뢰도 스칼라·refine 감사·청크·폴백 배지)는 엔지니어링 telemetry라 감춤. 실패 시 재분석(총괄).

**④ 교안 연결(CUR-02 · D94 기술영역 다리 + D101 매니저 직접 태깅):** ~~축→모듈 직접 매핑~~은 범주 오류(5축=내용 독립). **기술영역(주제)↔교안 섹션**을 총괄이 체크박스로 직접 태깅(AI 추천·신뢰도 없음):
- 좌 **기술영역 목록**(프로젝트 DP 유래·DASH-15, 상태: ✓N개 섹션 태그됨 · 미태그)
- 우 **"이 기술영역을 다루는 섹션 체크"**: 이 교안의 전체 섹션을 체크리스트로 나열(섹션명·페이지·추출된 키워드 칩만 참고 표시) — 총괄이 해당하는 섹션을 직접 체크. 체크 즉시 저장
- 하단 **축→노드타입 고정 규칙**(반례대응→주의·반례 / 코드이해→개념 / 대안비교→비교 / 자기수정→복구 / 의사소통=대상 아님) — 태깅 대상 아님(고정)
- **학생별 정확 위치 = 리포트 시점 검색**(태그된 기술영역→섹션 범위 내). 태깅이 안정·유한한 뼈대를 만들고, 무한 인스턴스는 규칙+검색이 처리(D94 유지, 매칭 방식 변경과 무관).

## 7. 인터랙션 & 화면 전이

- 목록 [+교안 등록] → 등록 폼 → 업로드 → UPLOADED→EXTRACTING → 구조 추출 결과(자동).
- 구조 추출 EXTRACTED → 교안 연결 탭에서 기술영역↔섹션 **자동 매핑**(고신뢰 자동 연결·저신뢰 자동 생략). 매니저는 필요 시 오버라이드만.
- 자동/오버라이드 연결 매핑 → **SC-T05/SC-M08 리포트 "취약축→교안 위치 안내"** 소비(MEAS-07). 리포트 "교안 화면 ▸" → 교안 연결 화면 역참조(D86 크로스 전환).
- EXTRACTION_FAILED → 재처리 또는 삭제만.
- **선행조건(flow):** 교안 등록·교안↔프로젝트 링크는 **회차 시작 전 완료**. 미링크 프로젝트나 저신뢰 생략 매핑은 T05 위치 안내만 생략(측정·피드백은 그대로·§3 교차계약 3·10). 승인 노동은 선행조건 아님(자동 연결).
- **환류(적합성 라벨·D100):** 매니저 오버라이드 로그(위치 틀림/맞음 정답 라벨) → 임계값 사후 보정. 회복 성과 채점은 효과 축이라 불채택(D100 정정).
