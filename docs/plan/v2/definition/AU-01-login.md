# AU-01 · 로그인

> **v1 그대로.** 바뀐 것 없음.

## 1. 한 줄

**하나의 로그인.** 역할별로 나누지 않는다 — 나누면 사용자가 자기 역할을 알아야 로그인할 수 있는데, 역할은 내부 개념이다.

## 2. 진입 · 이탈

| | |
|---|---|
| 진입 | `/shared/login` · 미로그인 상태로 보호된 경로 접근 · 활성화/재설정 완료 후 |
| 이탈 | **서버가 역할을 판정해 초기 화면으로 보낸다.** 클라이언트는 역할→화면 매핑을 갖지 않는다 |

## 3. 뷰

```
┌ 브랜드 패널 ─────────┬ 폼 ────────────────────────┐
│   ◆ IZ-Get          │  로그인                     │
│                     │  이메일   [               ] │
│                     │  비밀번호 [               ] │
│                     │                    [로그인] │
│                     │  비밀번호를 잊으셨나요?      │
└─────────────────────┴─────────────────────────────┘
```

**회원가입 링크가 없다.** 계정은 전부 초대로 생긴다(AU-02).

## 4. 데이터

이메일 · 비밀번호. 역할과 초기 경로는 응답으로 받는다.

## 5. 액션

로그인 · 비밀번호 재설정(AU-03).

## 6. 상태

| | |
|---|---|
| 자격 불일치 | `이메일 또는 비밀번호가 올바르지 않습니다` — **어느 쪽이 틀렸는지 말하지 않는다** |
| 미활성 계정 | `초대 링크로 먼저 계정을 활성화해 주세요` + 재발송 |
| 정지된 계정 | `사용이 중지된 계정입니다` + 문의 |
| 연속 실패 | 지연. 남은 시도 횟수는 노출하지 않는다 |

## 7. 안 하는 것

회원가입 · 역할 선택 · 소셜 로그인(미정).
