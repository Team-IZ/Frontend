# 개입 관리 재설계 — 팀 의견 수렴 결과

> **확정.** 14·15번에 반영 완료(7절).
> 14번 §16에서 "추후 논의"로 뺐던 것. 팀원 5명(박종호·박진용·강민수·김만서·손진원)의 의견을 받아 정리했다.
> 현재 목업(`manager/intervention.html`)은 전부 임시다 — 5개 개입 유형·취약 축 요약은 14번에서 죽은 개념 위에 서 있다.
>
> **적정 수준을 지킨다.** 이 제품의 핵심은 이해도 검증이고, 개입은 **검증 결과가 행동으로 이어지는 마지막 한 뼘**이지 별도 제품이 아니다.

## 0. 이 설계를 지배하는 한 문장

> ### 매니저는 강사가 아니다. 그래서 면담은 기술 대화가 아니라 **라우팅 대화**다.

매니저는 교육과정을 다 아는 사람이 아니라 **학생을 관리하는 사람**이다. 전공자인지도 알 수 없다(김만서).

**그러면 면담에서 코드 이야기를 할 수 없다.** *"이 함수 무슨 일 하나요?"* 라고 물어도 **매니저는 학생의 답이 맞는지 판단할 수 없다.** 판단 못 하는 질문은 면담을 "학생이 뭐라고 길게 말했고 매니저는 고개를 끄덕인" 자리로 만든다. 그건 안부 대화보다 나쁘다 — 뭔가 한 것 같은 착각이 남는다.

**명세가 이미 같은 말을 하고 있었다.**

| 근거 | 내용 |
|---|---|
| **06번 RBAC** | 역할은 `SUPER_ADMIN` / `MANAGER` / `TRAINEE` **3개뿐. 강사 계정이 없다** |
| **GOV-03** | *"교육생 공개는 **매니저 중개 발췌만**. **처방형 콘텐츠 금지 · 위치 안내까지**"* |
| **김만서** | *"매니저는 강사의 노하우를 전달해주는 **징검다리**"* |

**"위치 안내까지"가 매니저 역할의 정의다.** 가르치는 것이 아니라 **어디로 가야 하는지 알려주는 것.**

## 1. 다섯 명이 사실상 같은 말을 하고 있다

강민수의 관찰이 정확하다 — *"다 비슷비슷한 내용"*. 중복을 걷어내면 덩어리가 셋이다.

| 덩어리 | 누가 | 무엇 |
|---|---|---|
| **A. 유형을 없애고 면담 하나로** | 박종호 · 강민수 | 5개 중 실행 가능한 건 면담뿐. 화면명도 바꾼다 |
| **B. 면담 준비를 시스템이 대신한다** | **강민수 · 손진원 · 박종호** | 세 사람이 독립적으로 **같은 화면 한 장**을 그렸다 |
| **C. 면담 후에 무엇을 남기나** | 박진용 · 김만서 · 강민수 | 작은 목표 1개 · 학습 자료 · 기록 3칸 |

**B가 압도적으로 크다.** 셋이 따로 도달했다는 건 문제가 실재한다는 뜻이다 — *매니저가 준비 없이 들어가서 "요즘 어때요"로 끝난다.*

**다만 B의 내용은 재검토가 필요했다.** 강민수의 5칸 중 *"무슨 질문부터 — 기초 부족형이면 '이 함수 무슨 일 하나요?'"* 는 **강사의 질문**이다. 이 항목이 이번 재설계에서 빠진다.

**반대로 박종호의 진행 순서는 처음부터 옳았다.**

```
점수 추이 중립적 공유  →  자기 인식  →  원인 공유  →  회복 행동 권유
```

**기술 질문이 하나도 없다.** 전부 매니저가 답을 평가할 필요 없는 단계다. 이 골격을 그대로 쓴다.

## 2. 매니저가 할 수 있는 것과 없는 것

| | 매니저가 할 수 있다 | 왜 |
|---|---|---|
| **사실 전달** | 데이터가 말하는 것을 중립적으로 읽어준다 | 해석이 아니라 낭독. 기술 지식 불필요 |
| **원인 듣기** | 왜 막혔는지 **학생 입으로** 듣는다 | 답을 평가할 필요가 없다. 듣고 분류만 |
| **연결** | 교안 위치·강사 Q&A·기관 상담으로 보낸다 | 이게 "위치 안내까지"(GOV-03) |
| **약속과 추적** | 다음에 할 것 하나를 정하고 다음 회차에 확인한다 | **관리자의 본업** |

| | 매니저가 할 수 없다 | 대신 누가 |
|---|---|---|
| 코드 질문하고 답을 평가 | 맞는지 모른다 | **시스템이 이미 했다**(검증 세션) |
| 개념 설명 | 전공자가 아닐 수 있다 | 교안 · 강사 |
| 학습 방법 처방 | 기술적 판단 | 강사 |

**이 표가 브리프의 설계도다.** 왼쪽 표의 네 줄이 브리프 네 칸이 되고, 오른쪽 표는 화면에서 **매니저가 손대지 못하게** 만든다.

> **그래서 배너 문구도 바뀐다.**
> ~~"설명하지 말고 질문하세요"~~ → **"코드 이야기는 하지 마세요. 왜 막혔는지만 들으세요."**
>
> 이전 문구는 소크라테스식 기술 문답을 하라는 말로 읽힌다. **그것도 매니저가 못 하는 일이다.**

## 3. 세 관점

### ① 교육 도메인 — 면담의 교육적 산출물은 "이해"가 아니라 "경로"다

면담 30분으로 학생이 개념을 이해하게 만들 수는 없다. **그건 교안과 강사와 학생 본인의 시간이 하는 일**이다.

면담이 실제로 바꿀 수 있는 건 하나다 — **학생이 다음 한 주를 어디에 쓰는가.**

> 김만서의 진단이 이 지점을 정확히 짚었다. *"부캠의 가장 큰 문제점: 일정이 빡빡하고 속도가 빠름 → 결국 주말을 반납하는 방법밖에 없음 → **효율적으로 시간 사용하도록 도와줘야 함**."*
>
> **면담의 산출물은 "그 주말을 어디에 쓸지"다.** 이해가 아니라 배분이다. 그리고 배분은 매니저가 할 수 있는 일이다.

**어디에 쓸지는 데이터가 정해준다.** 3개 개념 중 어디서 막혔는지가 이미 나와 있다 — 김만서의 예시 그대로: *상속은 재시험 봐도 실패 → 상속 위주로 공부하도록.* **개념 이름을 짚는 데는 전공 지식이 필요 없다.**

**원인 분류는 자동화하지 않는다.** 시스템은 **어디서** 막혔는지만 알고 **왜**는 화면 밖이다. 14번 9-2에서 "기초 공백" 대신 "지속 저점"으로 부르기로 한 것과 같은 판단이다 — *원인을 이름에 박으면 진단을 건너뛰고 처방부터 한다.*

→ 박종호의 원인 목록은 **면담 중 학생과 함께 고르는 체크박스**로 살린다. 그가 쓴 표현 그대로 *"교육생과 공동 판단"*.

**박진용의 낙인 프레임 회피가 여기 붙는다** — *"점수가 아니라 이 개념 하나에 대한 이야기"*. 14번이 화면에서 숫자를 전부 뺐으므로(v1.1) 이미 정합한다. 브리프 첫 줄이 사람이 아니라 **개념**을 가리키게 쓴다.

### ② 매니징(운영) — 이 규모에서 실제로 도는가

**숫자를 맞춘다.** 손진원이 *"한 반 40~50명"*이라 했는데 14번 부록 B 기준은 **반 25명 × 10반**이다.

```
25명 · 회차당 위험(2단 이하 2개 이상) 20% 가정 → 5명
미프 8회 · 간격 4~7일  →  주 1~2건
```

**주 1~2건에 칸반 3열은 안 맞는다.** 칸반은 열마다 카드가 쌓여 막힌 열이 보일 때 값을 한다.

**다만 박종호가 칸반으로 잡으려 한 문제는 진짜다** — *"완료된 면담과 대기·진행 중인 면담이 섞여 있다"*. 그건 **상태 정의로 푼다.**

| 이전 | 제안 | 왜 |
|---|---|---|
| 대기 | **예정** | 같음 |
| **진행 중** | **후속 필요** | "진행 중"은 면담하는 30분 동안만 존재하고 그동안 매니저는 화면을 안 본다. 관리 대상은 박종호 본인이 말한 *"해결하지 못한 면담"* |
| 완료 | **종결** | 같음 |

**완료율 %는 넣지 않는다.** 매니저 평가 지표가 되면 **15분짜리 형식 면담으로 숫자를 채우는 행동**이 나온다. 회복 여부는 다음 회차 도달 단계가 이미 말해준다.

→ 대신 **`대기 최장 N일`**. 완료율은 잘한 것을 자랑하는 숫자고, 대기 일수는 **놓친 학생을 찾아주는 숫자**다.

**주·월 필터를 넣지 않는 이유:** 이 제품의 모든 판정이 **프로젝트 회차 단위**다(14번 12-2). 주·월 축을 더하면 *"이번 주 면담"*과 *"미프 3차 면담"*이 서로 다른 집합이 되어 매니저가 두 축을 맞춰야 한다. 6개월이 길다는 지적은 **회차 필터**로 해결된다.

**손진원 브리프의 절반은 지금 만들 수 없다.**

| 항목 | 데이터 |
|---|---|
| 코드 이해도 변화 · AI 평가 결과 · 반복 오답 | ✅ 있다 |
| 프로젝트 기여도 | △ **빅프만** (14번 6-2) |
| **Git 활동 · 출석 · 과제 수행 · 협업 감소** | ❌ **수집하지 않는다** |

**손진원이 옳은 지점은 따로 있다** — *"왜 위험하다고 판단했는지를 함께 제공해야 매니저가 신뢰한다"*. 이건 데이터 없이도 지킬 수 있고 14번의 `evidence` 서술이 그 재료다.

### ③ 기획 — 어디까지가 이번 범위인가

**기준 하나로 자른다.**

> **있는 데이터를 한 장으로 모으는 것까지가 범위. 새 데이터를 만들기 시작하면 범위 밖.**

| | |
|---|---|
| **범위 안** | 브리프(모으기) · 기록 3칸(가벼운 새 입력) · 목록·상태(정리) |
| **범위 밖** | 미니 재작성 과제(**새 제출물 + 채점 정책**) · AI 설명 모드(**새 세션 종류 + 비용 축**) · 강사 Q&A 연동(**시스템에 강사 계정이 없다**) |

**LLM을 쓰지 않는다.** 브리프의 칸이 전부 **이미 저장된 값의 재배치**다. 유일하게 새로 쓰는 문장은 **중립 공유 문구**인데, 위험 유형 2종 × 고정 템플릿이면 끝난다.

> LLM으로 생성하면 위험 학생 × 회차만큼 호출이 붙고 13-3 토큰 한도에 축이 하나 생긴다. **얻는 건 문체뿐이고, 읽는 사람은 매니저 한 명이다.**

**명세 제약 하나를 지킨다 — `RPT-03 면담체크리스트: 온디맨드 필수 · 자동생성 금지`.** 브리프는 목록에서 **[브리프 열기]를 눌렀을 때** 만든다. 전원 자동 생성은 명세 위반이고, 안 쓸 브리프를 미리 만드는 낭비이기도 하다.

**명칭:** `개입 관리` → **`면담`**. 유형이 하나뿐이면 상위 개념이 필요 없다. 14번 9절의 "개입"은 판정 쪽 용어로 남긴다.

## 4. 제안 — 화면 두 장

### 4-1. 면담 목록

```
면담                                        [미프 3차 ▾]

  ⚠ 대기 최장 6일                           예정 4 · 후속 필요 2 · 종결 9

  ● 예정        김OO   [지속 저점]   2단미달 2/3    대기 6일   [브리프 열기]
  ● 예정        이OO   [단계 하락]   0/3 → 2/3     대기 2일   [브리프 열기]
  ◐ 후속 필요   박OO   [단계 하락]   1차 면담 7/21 · "다음에 할 것" 미확인
  ✓ 종결        최OO   [지속 저점]   면담 7/18 · 다음 회차 3단 회복 ↑
```

| | |
|---|---|
| 필터 | **프로젝트 회차** (주·월 아님) |
| 상태 | 예정 / **후속 필요** / 종결 |
| 지표 | **대기 최장 N일** (완료율 아님) |
| 생성 | **[브리프 열기] 클릭 시** (RPT-03 온디맨드 필수·자동생성 금지) |

**대상 지정은 자동이다.** 14번 9-2 위험 유형이 켜지면 `예정`으로 올라온다. 제외는 체크 해제.

### 4-2. 면담 브리프 — 매니저가 낭독·경청·라우팅만 하면 되는 한 장

```
┌──────────────────────────────────────────────────────────────┐
│  코드 이야기는 하지 마세요. 왜 막혔는지만 들으세요.           │ ← 고정
└──────────────────────────────────────────────────────────────┘

① 이렇게 여세요                              [그대로 읽으면 됩니다]

   "지난 회차에는 3개 중 마지막까지 간 게 2개였는데, 이번에는 0개였어요.
    점수 얘기를 하려는 게 아니라, 무엇이 달라졌는지 같이 보려고 불렀어요."

   막힌 개념 —  HITL Trigger 조건 · Graph 구성
   (개념 이름만 읽어주세요. 설명은 하지 않아도 됩니다)

② 이것만 물어보세요                    [답이 맞는지 판단할 필요 없음]

   · 이전 프로젝트와 비교해서 가장 달랐던 점이 뭐였어요?
   · 이번에 어떤 역할을 맡았어요?
   · 만들면서 제일 자신 없던 부분은요?
   · 답하기 어려웠던 게 코드 때문이었어요, 설명하는 방식 때문이었어요?

   ⚠ 학생이 기술 질문을 하면 → "그건 강사님께 가져가 보죠"로 넘기세요

③ 들은 걸 여기 체크하세요 — 학생과 함께

   □ 개념 이해 부족    □ 담당 범위 밖    □ 구현 시간 부족
   □ 설명·표현 어려움  □ 난이도 상승     □ 팀 의존   □ 컨디션·심리

④ 체크한 것에 따라 여기로 보내세요            ← ③을 고르면 자동으로 뜸

   개념 이해 부족   → 교안 3장 36~46쪽 · 강사 Q&A 안내
   담당 범위 밖     → 다음 프로젝트 역할 분담에서 조정        (매니저)
   구현 시간 부족   → 재시험 창 안내 · 다음 회차 일정 확인    (매니저)
   설명·표현        → 리포트 다시 읽고 재시험 응시            (매니저)
   난이도 상승      → 반 절반 이상이면 개인 아님 → 기관 보고  (14번 9-6)
   팀 의존          → 다음 팀 편성 시 고려                    (매니저)
   컨디션·심리      → 기관 상담 채널로 연결                   (전달만)

──────────────────────────────────────────────────────────────
기록  □ 무엇 때문이라고 했나  □ 어디로 보냈나  □ 다음에 할 것   [저장]
```

**②의 질문이 전부 박종호의 개방형 질문이다.** 공통점 하나 — **매니저가 답을 채점할 필요가 없다.** 학생이 말하고 매니저는 ③에 체크한다.

**④가 이번 재설계의 핵심이다.** 원인 체크박스가 **분류 라벨이 아니라 라우팅 스위치**다.

| | |
|---|---|
| 이전 발상 | 원인을 분류한다 → 그래서 뭘 하지? |
| **지금** | 원인을 고르면 **목적지가 뜬다.** 매니저는 보내기만 하면 된다 |

**목적지가 매니저 권한 지도와 일치한다.** 표의 오른쪽 괄호가 그것이다 — **직접 할 수 있는 것(일정·팀·재시험)과 전달만 하는 것(강사·상담)**이 갈라져 있다. 매니저가 자기 권한 밖 일을 떠안는 것을 막는다.

> **강사 계정은 시스템에 없다**(06번). ④의 `강사 Q&A 안내`는 **문구를 띄우는 것까지**이고 실제 연결은 기관 프로세스다. 시스템이 못 하는 걸 하는 척하지 않는다.

**⑤(건네줄 것)를 별도 칸으로 두지 않았다.** 교안 위치가 ④ 첫 줄에 이미 들어 있다 — **목적지와 준비물은 같은 것**이라 칸을 나누면 매니저가 두 번 본다.

### 4-3. 기록 3칸 — 칸 이름이 바뀐다

강민수 안(`막힌 지점 / 학생 반응 / 다음에 할 것`)에서 첫 칸을 바꿨다.

| 이전 | 지금 | 왜 |
|---|---|---|
| 어디서 막혔나 | **무엇 때문이라고 했나** | 어디서 막혔는지는 **시스템이 이미 안다.** 매니저가 옮겨 적을 이유가 없다 |
| 학생 반응 | **어디로 보냈나** | ④의 선택이 자동으로 채워진다. 다음 회차에 "갔는지" 확인할 대상 |
| 다음에 할 것 | 그대로 | 박진용의 "작은 목표 하나"가 여기 들어간다 |

**`다음에 할 것`이 다음 회차 브리프 ①칸 위에 ⚠와 함께 뜬다.** 이게 없으면 면담이 매번 처음부터 시작한다.

## 6. v2로 미루는 것

| | 왜 미루나 |
|---|---|
| **미니 재작성 과제**(박진용) | **교육적으로 가장 강력하다.** AI가 짜준 코드를 손으로 다시 짜게 하는 건 읽고 설명하는 걸로 안 고쳐지는 문제를 정면으로 친다. 다만 새 제출물 · 채점 정책 · 미제출 처리가 딸려온다 |
| **AI 설명 모드 세션**(박진용) | **매니저가 못 하는 기술 설명을 유일하게 대신할 수 있는 후보다.** 세션 인프라 재활용이라 싸 보이지만, 설명 모드에서 들은 걸 재시험에 그대로 쓰는 경로를 먼저 정리해야 한다(11절 답안지 문제와 같은 구조) |
| **강사 노하우 수집 체계**(김만서) | 본인도 *"기능적 구현보다 방법론"*이라 했다. 시스템은 교안 위치 안내까지만 한다 |

> **v2 우선순위는 AI 설명 모드가 위다.** "매니저는 기술을 못 가르친다"는 이번 결론이 그대로 **그 기능의 존재 이유**가 된다. 매니저가 못 하는 자리를 사람으로 못 메우면 시스템이 메우는 수밖에 없다.
