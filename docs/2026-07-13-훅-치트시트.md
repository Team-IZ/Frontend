# 훅 치트시트 — 반사적으로 쓸 것만

`작업-방법론-총합.md`의 알맹이만. 각론(왜 그런지)은 원문 참고.

## 질문형 훅
- 순서 정할 때: **"A를 B보다 나중에 하면, A의 결과가 B를 무효로 만드는가?"**
- 지금 나온 말 처리할 때: **"이 말이 맞다면, 지금까지 한 작업이 무효가 되는가?"** → 맞으면 STOP, 아니면 PARK, **모르겠으면 STOP**
- 생산자(LLM/백엔드) 판정: ① 정답이 열려있나 → ② 틀리면 누가 잡나 → ③ 결정론으로 같은 품질 나오나
- 겸직 병합 테스트: **"두 역할을 한 사람이 겸하면, 급할 때 어느 쪽이 밀리는가?"**

## Trust-but-verify — 최고 위험 1건 (통과해도 배치가 깨끗한 건 아님)
- "고쳤다" → diff 직접 읽기
- 숫자를 댔다 → 가장 무거운 값 하나 계산기로 검산
- "전부 고쳤다" → grep 한 줄 직접 돌리기

## 복붙 프롬프트
- 새 프로젝트 시작 6-STEP 템플릿 — `작업-방법론-총합.md §6`
- 매 응답 첫 줄 규율 문단 — `§5` (이제 SessionStart 훅으로 자동 주입됨, 아래 참고)
- 역할 명시 지정: "지금부터 OO로서만 봐"

## 체크리스트/기법
- 검증 가능한 규칙화: 규칙 + `grep ... | sort -u` 검사 명령어 쌍
- 감사 심각도 3단계: 느낌 깨짐(상) / 눈에 띔(중) / 다듬기(하)
- ERD 처음 읽는 순서: 왜 쪼갰나 체감 → 사례 하나 추적 → 반복 패턴 묶기 → 공통 요소 짚기 → 의도 vs 오류 구분
- 단위 설계 근거 3문: 존재 이유 / 항목 이유 / 관계
