# SC-M03 · 측정 계획 (체크포인트 · 추출범위 · 검증포커스 · 응시현황)

> **⚠ D78 흡수 + D90 권한 분리:** 이 화면은 `manager/project-workspace.html`의 `#plan` 탭(SC-M03 프로젝트 컨텍스트 진입)으로 실장 흡수됨 — 와이어프레임 실물은 §10 참조. **권한 경계(D90, FB-F5):** PLAN-01(체크포인트)이 두 층으로 쪼개짐 — **회차 수·최종 회차(측정 구조 골격) = 총괄 설계**(자동 파생+조정) / **측정일·오픈 실행 = 담당**(반 진도에 맞춰 언제, 반마다 다른 운영이라 총괄이 다 못 함). PLAN-03(검증 포커스=질문 초점)도 측정 축이라 **총괄**. PLAN-04(응시 현황·독촉)는 모니터링·개입 카테고리라 **담당**. **PLAN-02(추출 범위) = 담당**(D90 후속 확정, §11) — 측정 축이 아니라 회차 실행 파라미터로 판단.
> 소스: 기능명세서 v8 PLAN-01(체크포인트 일정), PLAN-02(추출 범위), PLAN-03(검증 포커스), PLAN-04(응시 현황·독촉).
> 배치: P0(PLAN-01·02)/P1(03·04) · 진입 순서 6번. 매니저 앱 셸 공유(SC-M02).

## 2. 목적 & UX 설계 근거

- **측정의 언제·무엇을·어디에 초점을 정한다.** 체크포인트(언제)·추출범위(무엇을 분석)·포커스(어디에 가중). 이 셋이 정해져야 교육생 측정이 돌아간다.
- **검증 포커스는 교육생 비노출(A4).** PLAN-03: focus_area는 교육생 화면·API 응답에서 제외 — 미리 알면 게이밍. → 포커스 설정 영역에 **"교육생 비공개" 배지**를 명시.
- **최종 회차는 단 1건(PLAN-01).** 등급은 최종 회차에만 부여(B3). is_final을 명확히 표시·단일 강제.
- **추출범위 기본값은 안전하게.** 개인 프로젝트는 전체코드 권장 기본(PLAN-02). 본인커밋기여분은 AUTH-07 검증 이메일 있을 때만.
- **응시 현황은 회차별 모니터링.** 진행 중 회차의 미응시를 집계·독촉(중복 독촉 제한). 회차 종속(체크포인트에서 진입).

## 3. 정보 구조 & 레이아웃 (매니저 앱 셸 · 데스크톱)

**4탭:**
1. **체크포인트(PLAN-01):** 회차 목록(회차·**최종 배지** · 측정일 · 응시 기한 · **질문 수(예산 N)** · **응시 진행(N/M)** · **포커스 설정 여부** · 상태) + [회차 추가] + 행 액션(수정·삭제·응시 보기, 데이터 있는 회차 삭제 경고). **질문 수는 회차별 설정·기본 4**(전 학생 동일=비교 가능성, 개인차는 세션 depth 적응, D28). 응시 진행·포커스 컬럼이 응시 현황·검증 포커스 탭과 연결.
2. **추출 범위(PLAN-02):** 프로젝트별 extract_scope(전체코드/본인커밋기여분) · 개인=전체코드 권장 기본 · 기여분석 가용 표시.
3. **검증 포커스(PLAN-03):** 회차별 포커스 영역(칩 다중) + **[교육생 비공개] 배지**.
4. **응시 현황(PLAN-04):** 회차 선택 + **반·상태 필터(미응시만)** → 학생·반·제출·세션·완료 상태 · **미응시 벌크 독촉**(중복 제한). 미응시만 필터 → 전체 선택 → 독촉.

반응형: 웹 기준.

## 11. PLAN-02(추출 범위) 권한 확정 — D90 후속

D90(FB-F5)은 체크포인트·검증 포커스·응시 현황의 총괄/담당 경계만 확정했고 추출 범위는 미포함이었으나, 사용자 확인으로 **담당**으로 확정: extract_scope(전체코드/본인커밋기여분)는 측정 축(무엇을 잴지)이 아니라 **회차 실행 파라미터**(팀·레포처럼 프로젝트·회차마다 바뀌는 운영값)로 판단. 체크포인트 지정 모달(담당 소유) 내 오버라이드 필드로 위치 확정.
