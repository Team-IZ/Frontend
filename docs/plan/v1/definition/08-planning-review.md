## Part 1 이번 라운드 결정 요약

검토 대상이 된 결정들. 맥락 없이 이 문서를 읽는 사람을 위한 요약이다.

### 1-1. 호칭

| 이전 | 변경 |
|---|---|
| 슈퍼어드민 | 서비스 업체 (Superadmin) |
| **총괄 매니저** | **기관 운영자 (Operator)** |
| 담당 매니저 | 매니저 (Manager) |
| 교육생 | 교육생 (Trainee) |

### 1-2. 미프 / 빅프 이원화

| | 미니프로젝트(미프) | 빅프로젝트(빅프) |
|---|---|---|
| 성격 | 교안에서 배운 것을 적용 | 출제 문제가 교안과 무관할 수 있음 |
| 주제 | 팀 간 **동일 주제** | 팀별 상이 |
| 이해 범위 | 팀플이어도 **전체 코드 이해** | **자기 코드 영역만** 이해 |
| 기간 | 보통 1주 이내 | 장기 |
| 체크포인트 | **프로젝트 자체 = 1체크포인트** (회차 개념 제거) | **개발 주차별** (기획·디자인·발표 주 제외, 매니저 재량) |
| 성적 | **성취도 판단의 기준** | **최종 성적 미반영** (단 리포트에는 포함) |
| 점수 용도 | 위험 학생 발견 → 매니저 개입 / 우수 학생 → 운영자 인지 | 성실 참여·수행 여부 검증 |

### 1-3. 측정·채점

- 문항 수 **3문제 고정** (기존 유동 입력 폐기).
- **문제별로 채점하고 문제별 보고서를 쓴다.**
- **재시험 부활**, 첫 시험과 동일 문제. **문제 단위로 재시험.**
- 모범답안 **제외** (학생마다 꼬리질문이 달라져 DB·토큰 한계).
- 기여·이해도 불균형 개념 **삭제** (미프가 커밋 기여 기반이 아니므로).

### 1-4. 리포트

- 학생 리포트 = **3문제 종합 리포트 + 3문제 전체 문답 과정 + 문제별 L1~L3 상세 피드백**(어디가 문제인지 + 교안 참고 위치).
- 첫 시험 버전과 재시험 버전을 **둘 다** 보여준다.
- **교육생 리포트 아카이브 화면 신설** — 프로젝트별로 자기 문답과 받은 리포트를 열람.
- 프로젝트 리포트(매니저용) = **미프별 리포트 + 빅프 최종 리포트**. 체크포인트 리포트 삭제. 빅프를 회차별로 나누지 않음.

### 1-5. 화면

- 개별 상세 · 종합: 참여 프로젝트의 **팀 평균 vs 개인 점수를 5축별 각각** 표시.
- 개별 상세 · 세션: 문답 **AI 요약 → 핵심 추출**만. 실제 문답 내용은 넣지 않는 버전으로 먼저 만든다.
- 개별 상세 · 개입: **개입 버튼 추가.**
- 히트맵: **기술영역 히트맵 삭제.** 이해 단계 히트맵만 남김.
- 히트맵 드릴다운 — 운영자는 기수→반→프로젝트별 팀→학생, 매니저는 담당 반→팀→학생.
- 히트맵 시그널 클릭 → 해당 단위의 위험 시그널 상세.
- 히트맵에 재시험 결과 **포함/미포함 버전** 구분.

### 1-6. 위험·우수 통합 View

- 에이스 → **우수 교육생**으로 명칭 변경. **종합 우수는 산출하지 않고 영역별만.**
- 위험/우수 **탭 분리 폐지 → 하나의 테이블**에서 필터·정렬.
- 매니저는 담당 반만, 운영자는 전체 + 반 필터. 둘 다 **프로젝트별 select 필터**.
- row 클릭 → 상세 페이지에서 구체적 근거.
- 유형 **호버 시 상세 설명 View**.

## Part 2 구조적 충돌

### R-01 · 치명 · 미프 문제가 반 전체로 샌다

지금 설계에서 문제 유출을 막는 장치가 하나도 없다.

- 미프 팀원 4명이 **같은 레포**를 제출한다 → 같은 코드 → 생성되는 L1 질문이 서로 유사하다.
- 미프는 **주제까지 동일**하다 → 팀이 달라도 코드 구조가 비슷하다 → 질문도 비슷하다.
- **문제 수가 3개 고정**이라 문제 공간이 작다.
- 결정적으로 **재시험은 아예 동일 문제**다.

오전에 응시한 학생이 오후 응시자에게 "1번은 이거 물어본다"를 알려주면 측정이 끝난다. 이건 부정행위 대응 이슈가 아니라 **설계 결함**이다. 지금 문서 어디에도 방어 장치가 없다.

풀 방향 세 가지이고, 셋 다 지금 정해야 한다.

| 방향 | 내용 | 평가 |
|---|---|---|
| 동시 응시 창 강제 | 체크포인트 세션을 같은 시간대에 일괄 진행 | 가장 확실하나 운영이 못 버틴다 |
| **문제 풀 N개에서 3개 추출** | 축 커버리지를 유지한 채 랜덤 | **권고** — "3문제 고정"은 개수 고정이지 문항 고정이 아니어야 한다 |
| **개인별 코드 앵커 분리** | 같은 레포라도 학생마다 다른 파일/함수를 근거 구간으로 잡아 질문 생성 | **권고** |

**권고: 2 + 3 병행.**

### R-02 · 치명 · "미프는 동일 주제라 팀 간 비교가 쉽다"는 전제가 틀렸다

성취도 판단 전체가 이 전제 위에 서 있어서 짚는다.

점수를 비교 가능하게 만드는 건 주제 동일성이 아니라 **동일 루브릭 + 동일 축 + 캘리브레이션된 채점자**다. 같은 주제여도 구현이 다르면 질문이 달라지고, 질문이 다르면 이미 비교 대상이 아니다. 역으로 주제가 달라도 루브릭이 같고 채점 스케일이 보정돼 있으면 비교된다.

**근거를 옮겨야 한다.** "미프라서 비교 가능"이 아니라 **"루브릭·캘리브레이션이 있어서 비교 가능"**이다. 이걸 옮기면 R-03의 절대/상대 논쟁도 자동으로 풀린다.

### R-03 · 치명 · 절대 vs 상대 — 두 개의 다른 문제를 하나로 묶어서 헤매고 있다

두 입장을 분해하면 이렇다.

| 입장 | 실제로 말하는 것 | 문제의 종류 |
|---|---|---|
| 상대 지지 | "모델이 바뀌면 점수 스케일이 흔들린다" | **계측기 문제** |
| 절대 지지 | "다 못해도 아무도 위험이 아니면 제품 목적이 무너진다" | **평가 설계 문제** |

**계측기가 흔들린다고 평가 방식을 상대로 바꾸는 건 잘못된 대응이다.** 온도계가 부정확하면 온도계를 보정하지, "오늘 평균보다 높으면 더움"으로 정의를 바꾸지 않는다. 상대로 가는 순간 코호트 전체가 못 따라와도 위험 학생이 0명이 된다.

**결론: 절대 기준이 1급, 상대는 화면 표시용 보조.**

| 판정 | 기준 |
|---|---|
| 재시험 트리거 | **절대 미달** (준거참조). 반이 잘해도 못한 사람은 봐야 한다 |
| 위험 판별 | **절대 미달 OR (경계권 + 코호트 대비 하위 편차)**. 상대는 절대의 보완이지 대체가 아니다 |
| 우수 판별 | **절대 상위 AND 코호트 상위** (둘 다 만족) |

**전제 조건 두 가지:**

1. **골든셋 캘리브레이션을 필수 인프라로 승격.** 사람이 채점한 기준 답변 세트를 만들어 두고, 모델·프롬프트·루브릭이 바뀔 때마다 돌려 스케일을 보정한다. 원래 ENG-05(채점 재현성)가 하려던 일인데 지금 "누가 사람 채점을 하는가"가 비어 있다 → R-27.
2. **5축 각 1~5점의 행동 기준(anchor)이 문서로 존재해야 한다.** "3점 = 무엇을 할 수 있는 상태"가 글로 정의돼 있지 않으면 절대 기준은 말만 절대고 실제로는 모델 기분이다 → Q3.

### R-04 · 치명 · 재시험이 무엇을 측정하는지 정의돼 있지 않다

기존 명세는 "재응시 기능 없음"이었고 D118이 측정 무결성을 이유로 잠금까지 걸어놨다. 부활 자체는 반대하지 않는다. 다만 지금 정의로는 성립하지 않는다.

- 학생은 **1차 리포트로 자기 약점을 학습한 뒤** 재시험을 본다. 그럼 재시험이 재는 건 "이해도"가 아니라 **"피드백 후 학습 능력"**이다. 다른 구인(construct)이다.
- L1이 같아도 답변이 개선되면 **L2·L3 경로가 완전히 달라진다.** "똑같은 문제"라는 말이 실제로는 성립하지 않는다. 1차와 2차는 서로 다른 대화이고, 두 점수는 같은 자를 댄 값이 아니다.

먼저 정할 건 UI가 아니라 성격이다.

| 성격 | 귀결 |
|---|---|
| **측정으로 쓴다** | 동일 문제는 안 된다(같은 풀·다른 문항). 재시험 점수가 1차를 대체하는지 병기인지 정해야 한다 |
| **학습으로 쓴다** | 이름을 "복습 세션"으로 바꾸고 점수를 아예 내지 않는 게 맞다. 점수를 내면 반드시 누군가 비교한다 |

문제 단위 재시험으로 범위가 좁혀지면서 이 문제는 상당히 완화됐다(R-13 참조). 하지만 "동일 문항"이 남아 있는 한 미해결이다.

### R-05 · 중요 · 재시험 포함 평균은 통계적으로 오염된 값이다 — 필터로 해결할 문제가 아니다

"포함 버전/미포함 버전 나눠서 필터" 방향은 위험하다.

재시험은 **하위권만 선별적으로** 본다. 그 개선치를 평균에 섞으면 모집단이 달라져서 하위권 개선분만 평균을 위로 밀어 올린다. 반 간 비교, 기수 간 비교가 전부 깨진다.

**권고: 기본값은 첫 시험만.** 이것이 그 조직 단위의 대표값이다. 재시험은 평균에 섞지 말고 셀 안에 개선 표식(↑) 정도로 얹거나, "재시험 응시자 개선 현황"이라는 별도 뷰로 완전히 분리한다.

두 값을 나란히 놓으면 매니저가 매번 "어느 게 진짜지"를 판단해야 한다. 그건 UI로 못 푼다.

### R-06 · 치명 · 회차를 없앴는데 회차에 매달려 있던 규범들이 정리되지 않았다

미프에서 회차를 제거한 결정 자체는 맞다. 그런데 기존 규범 다수가 "회차" 축 위에 서 있다.

| 기존 규범 | 회차 제거 후 상태 |
|---|---|
| B2 회차 독립성 | 프로젝트 독립성으로 재정의 필요 |
| **B3 최종 등급은 최종 회차만** | **최종 등급을 무엇으로 내는지가 사라졌다 — 미정** |
| DASH-04 회차별 due_at 스냅샷 | 프로젝트별 스냅샷으로 재정의 |
| **INTV-06 회복 Δ = 현재 − 직전 회차** | **미프마다 주제·난이도가 다르다 → Δ가 학습 효과인지 난이도 차이인지 구분 불가** |

특히 두 번째와 네 번째가 심각하다.

- 빅프가 성적 미반영이면 **최종 성적은 미프들로만 산출**되는데, 미프 여러 개의 무엇으로 내는지(평균 / 최종 미프 / 상승 추이) 어디에도 없다.
- 난이도가 다른 미프 간의 Δ로 "회복했다"를 자동 판정하는 건 근거가 없다 → R-11로 이어진다.

### R-07 · 중요 · "기여·이해도 불균형 삭제"가 사실상 철회됐다 → 파이프라인 존치

지난 라운드 결정은 이랬다.

> 기여 이해도 불균형 개념 자체를 삭제하기로 하였음. (…) 미프는 팀플이어도 커밋 기여 기반이 아닌 전체 코드 이해도를 측정하기 때문에.

그런데 이번 유형 체계는 이렇다.

| | 유형 | 기반 |
|---|---|---|
| 위험 | 점수 하락 | 미프 |
| 위험 | 기초 공백 | 미프 |
| 위험 | **빅프 - 기여도↑ • 이해도↓** | **기여×이해 교차** |
| 위험 | **빅프 - 기여도 • 이해도 ↓** | **기여×이해 교차** |
| 우수 | 고점 유지 | 미프 |
| 우수 | **빅프 - 기여도•이해도 높음** | **기여×이해 교차** |

위험 4개 중 2개, 우수 2개 중 1개가 정확히 기여도×이해도 교차 판정이다. **삭제한 게 아니라 미프에서 빼고 빅프로 옮긴 것**이다.

나쁜 결정이 아니다. 오히려 원래 그 자리가 맞다 — 빅프는 자기 코드 영역만 이해하는 활동이므로 기여 축이 의미를 가진다. 다만 결과가 있다.

**커밋 귀속 파이프라인을 잘라낼 수 없다.** 지난 라운드에서 삭제 후보로 올렸던 것들이 전부 빅프 전용으로 살아남는다.

| FR·엔티티 | 미프 | 빅프 |
|---|---|---|
| AUTH-07 커밋 이메일 검증 | 끔 | **켬 (선행 필수)** |
| MEAS-02A 기여 분석 | 끔 | **켬** |
| ContributionMap | 미생성 | **생성** |
| ENG-03 기여 편차 | 끔 | **켬** |
| PLAN-02 추출 범위 | **전체 코드 고정** | **본인 커밋 기여분 고정** |

즉 **삭제가 아니라 프로젝트 유형별 자동 분기**다. PLAN-02는 매니저가 고르는 설정이 아니라 유형에서 자동 결정되는 값으로 바꾸면 **설정 화면 하나가 사라진다.**

### R-08 · 중요 · "빅프는 성적에 사용 X"가 실질적으로 무의미해졌다

빅프 데이터로 학생을 위험/우수로 분류하고, 그 분류가 개입 대상 선정으로 이어진다. **성적보다 학생에게 미치는 영향이 오히려 클 수 있다.** "성적 미반영"이라는 말을 그대로 두면 나중에 반드시 분쟁이 생긴다.

**정확한 표현으로 교체:**

> 빅프는 **최종 성적 산출에서 제외한다. 단 위험·우수 판정과 리포트에는 사용한다.**

이렇게 쓰면 지금 설계와 일치하고, 학생에게 설명할 때도 정직하다.

> 참고 — 지난 라운드에서는 "빅프는 점수를 내지 말고 통과/관찰필요 2단계로 가라"고 권고했으나, 이번 결정(빅프 이해도 채점 수행)으로 방향이 확정됐다. 그 결정을 존중하되 위 재정의가 따라와야 한다.

### R-09 · 중요 · 빅프 체크포인트는 커밋 이메일 검증을 선행 조건으로 걸어야 한다

기여도가 빅프 위험 판정의 절반을 차지한다. 커밋 귀속이 틀리면 오판이다. 기존 A8(미검증 커밋 이메일은 귀속 분석서 경고 표기)로는 부족하다 — 경고를 띄우는 게 아니라 **검증 완료 전에는 빅프 체크포인트를 열지 않아야** 한다.

미프에서는 필요 없으므로 **빅프에만** 건다.

### R-10 · 치명 · 학생에게 점수를 보여주는지가 재시험과 충돌한다

D115가 "결과 리포트 = 서술형 + 이해 상태, **점수 표기 금지**"로 확정돼 있다. 그런데 이제 재시험 대상 선정 기준이 점수다.

**학생은 자기가 왜 재시험을 보는지 알아야 하는데, 점수를 못 보여주면 뭐라고 설명하나?**

그리고 "히트맵도 두 버전 다 보여줌" 문장이 애매하다.

- **학생에게 히트맵을 보여준다는 뜻이라면** 학생이 자기 위치를 반 평균 대비로 보게 되고, A6(교육생 공개는 매니저 중개 발췌만)과 낙인 방지 원칙에 정면으로 부딪힌다.
- 매니저 히트맵에 두 버전을 반영한다는 뜻이면 문제없다.

확인 필요 → Q2.

### R-11 · 중요 · 개입 관리는 축소해야 한다

냉정하게 보면 지금 개입 관리는 CRM 흉내이고, 매니저가 이 화면에 **다시 들어올 이유가 약하다.** 생성 → 상태 전이 → 효과 판정은 전부 매니저에게 일을 늘리는 방향이다.

**자동 효과 판정(INTV-06: Δ≥1 AND post≥3)은 삭제를 권한다.** R-06에서 봤듯 미프 간 Δ의 신뢰성이 없다. 근거 없는 판정을 자동으로 찍는 건 A2 위반이기도 하다. 매니저가 종료할 때 한 줄 메모로 대체하는 게 정직하다.

**독립 화면은 "아직 안 끝난 내 개입" 할 일 목록 하나로 축소.** 나머지는 교육생 상세의 타임라인 한 줄로 내린다. "개별 상세 · 개입에도 개입 버튼 추가"라는 이번 결정이 이미 그 방향이다.

### R-12 · 중요 · 문제별 채점과 5축의 관계가 D108과 충돌할 수 있다

D108이 "**문항을 축에 1:1 매핑 금지**"였다. 지금은 문제별로 채점하고 보고서를 쓴다. 두 구조가 양립하려면 둘 중 하나여야 한다.

| 안 | 구조 | 판정 |
|---|---|---|
| **A (권고)** | 문제별 = **단일 점수 + 서술 피드백**만. 5축은 **3문제 전체를 놓고 한 번만** 산출 | D108과 양립 |
| B | 문제별로 5축을 각각 매김 | **D108 위반.** 문제 하나에서 "자기수정"이 관측 안 되면 결측투성이 |

**A를 권고한다.** 그리고 A로 가면 **문제 하나만 재시험 봤을 때 5축을 다시 계산할 수 없다**(3문제 전체가 필요하므로). 즉 재시험은 문제별 점수만 갱신하고 5축은 1차 값을 유지하는 게 구조적으로 맞다. R-13의 권고와 맞물린다.

**추가 미결:** 3문제 × depth3에서 **관측되지 않은 축**(예: 반례 대응 상황이 안 나옴)을 결측으로 볼지 감점으로 볼지가 없다. A3(표본 부족 시 가짜 수치 금지)와 직결된다.

### R-13 · 중요 · 문제 단위 재시험 — 방향은 좋으나 합성 점수 문제가 남는다

3문제 중 못한 것만 다시 보는 건 학습 처방으로 정확하고 비용도 1/3이다. R-04의 "다른 구인을 잰다" 문제도 범위가 좁혀져 상당히 완화된다. 다만 세 가지가 미해결이다.

**① 재시험 후 그 체크포인트의 점수는 무엇인가?**
1차 2문제 + 2차 1문제를 합성한 값인가? 그렇다면 **서로 다른 시점의 데이터가 섞인 점수**다. 그 합성 점수가 위험·우수 판정에 들어가면 재시험 본 학생만 유리해지고, R-05의 선택 편향이 문제 단위로 내려오면서 더 지저분해진다.

> **권고: 판정과 히트맵의 기본값은 1차 점수 고정.** 재시험 결과는 그 학생 리포트와 개선 이력에만 반영하고 집계에 섞지 않는다.

**② 재시험 대상 문제 선정 기준이 없다.** 문제별 점수 몇 점 미만인가? 3문제 다 미달이면 3개 다 보나?

**③ 문제 단위 재시험이 문제 유출을 악화시킨다.** R-01의 연장이다. 재시험이 특정 문제로 좁혀지면 "나 2번 재시험 봐"라는 정보가 돌고, 다른 학생이 2번만 집중 대비한다. 미프는 주제가 동일해서 문제도 비슷하다.

> **재시험은 같은 풀에서 다른 문항으로 가야 한다.** 이게 안 되면 재시험 점수는 어떤 판정에도 쓸 수 없다.

### R-14 · 중요 · 교안 매핑이 부가 기능에서 리포트 필수 입력으로 승격됐다

"교안의 어디를 참고하면 좋을지"가 리포트 구성 요소로 확정됐다. 그런데 기존 계약(00-source-analysis §3-3)은 "교안 매핑 미승인 시 교안 위치 안내 생략"이다. **이제 생략하면 리포트의 핵심 절반이 빠진다.**

정해야 할 것 둘:

1. **교안 등록·매핑을 기수 개설의 선행 필수 조건으로 승격**할 것인가. 지금은 선택이다.
2. **빅프 리포트에도 교안 위치가 들어가는가.** 빅프는 교안 무관이므로 논리적으로는 안 들어가야 한다. 그러면 빅프 리포트는 미프 리포트와 구성이 다르다 — 명시해야 한다 (R-24).

## Part 3 위험·우수 유형 체계

### R-15 · 중요 · "각 회차 점수 4, 5점 유지" — 회차를 없앴다. 그리고 최소 표본이 필요하다

우수 유형 정의에 회차가 남아 있다. 미프에서 회차를 제거하고 프로젝트=체크포인트로 통일했으므로 **"각 미프에서 4~5점 유지"**로 읽어야 한다. 그러면 판정에 최소 표본이 필요하다.

| 유형 | 성립에 필요한 미프 수 |
|---|---|
| 고점 유지 | 최소 2~3개 (1개로 "유지"는 성립 안 함) |
| 점수 하락 | 최소 2개 |
| 기초 공백 (지속적으로 낮음) | 최소 2~3개 |

**결과: 첫 미프 직후에는 위험·우수 목록이 텅 빈다.**

규범상으로는 정확하다(B4 1회차 단독 판정 금지, A3 표본 부족 시 가짜 수치 금지). 하지만 제품 목적이 "못 따라오는 학생 조기 발견"인데 조기에 아무도 안 잡히면 목적 미달이다.

> **권고: 확정 유형과 별도로 "1차 관찰"이라는 약한 신호를 하나 둔다.** 첫 미프에서 저점인 학생을 유형 없이 관찰 대상으로만 띄우고, 두 번째 미프에서 확정 유형으로 승격시킨다. 규범을 깨지 않으면서 초반 공백이 메워진다.

각 유형이 몇 개 미프부터 켜지는지를 지금 명시해야 한다.

### R-16 · 중요 · "기초 공백"은 원인을 이름에 박았다

빼신 두 개("설명-산출 갭", "깊이 고착")가 안 와닿는다는 판단은 정확하다. 그런데 남은 것 중 하나가 같은 병을 앓고 있다.

**데이터가 말해주는 건 "점수가 계속 낮다"(결과)이지 "기초가 비어 있다"(원인)가 아니다.** 점수가 계속 낮은 이유는 기초 부족일 수도, 참여 부족일 수도, 언어 표현력 문제일 수도 있다. **원인을 이름에 박으면 매니저가 진단을 건너뛰고 처방부터 한다.** A1(확정형 낙인 라벨 단독 노출 금지)이 막으려던 것과 같은 구조다.

> **권고: 이름을 결과로 바꾼다 — "지속 저점".** 호버 설명에 "여러 미프에서 계속 낮은 점수. 원인은 개별 확인 필요"라고 쓰면 매니저가 상세로 들어갈 이유도 생긴다.

### R-17 · 보완 · 빅프 유형 두 개는 이름이 아니라 조건식이다

`빅프 - 기여도↑ • 이해도↓`는 화살표를 읽어야 뜻이 오는 라벨이다. 테이블 한 행에 배지로 들어가기엔 길다. 호버 설명을 붙이기로 했으니 이름은 짧게 가도 된다.

| 지금 | 제안 | 실제 상황 |
|---|---|---|
| 빅프 - 기여도↑ • 이해도↓ | **코드 대비 이해 부족** | 코드는 나오는데 설명을 못 함 |
| 빅프 - 기여도 • 이해도 ↓ | **참여 저조** | 코드도 이해도 없음 |
| 빅프 - 기여도•이해도 높음 | **주도 기여** | 둘 다 높음 |

**두 번째를 특히 짚는다.** 기여도와 이해도가 둘 다 낮은 건 "학습 위험"이 아니라 **"이탈 신호"**다. 대응이 완전히 다르다 — 학습 지원이 아니라 출석·동기 관리이고, 담당 매니저가 아니라 운영 관리자가 알아야 할 수도 있다.

유형을 나눈 이유가 대응이 달라서라면, 이 하나는 다른 유형들과 같은 리스트에 있는 게 맞는지부터 재고할 만하다.

### R-18 · 중요 · 유형이 배타인지 중복 가능한지가 안 정해졌다

한 학생이 미프에서 "점수 하락"이면서 빅프에서 "코드 대비 이해 부족"일 수 있다. 지극히 흔한 조합이다.

| 방식 | 필요한 후속 결정 |
|---|---|
| 배타 | 우선순위 규칙 (어느 쪽을 대표 유형으로 보여줄지) |
| 중복 허용 | 한 행에 배지 2~3개 → **정렬 기준이 무엇인가** |

기존 INTV-01 추천이 Decision List(if-elif 배타)였는데, 그건 "무엇을 할까"라 배타가 맞았다. 위험 유형은 "무슨 상태인가"라 중복이 자연스럽다.

> **권고: 중복 허용 + 정렬은 별도의 위험도 점수.** 유형은 라벨이고 정렬은 숫자여야 테이블이 성립한다. **그 위험도 점수를 무엇으로 낼지가 아직 없다.**

## Part 4 통합 View

탭 분리를 없앤 것, 프로젝트별 select를 넣은 것 둘 다 정확하다. 특히 "프론트 에이스가 클라우드 위험 학생일 수도"라는 관찰이 좋다. 그런데 그 관찰에 딸린 함의와 빠진 것이 있다.

### R-19 · 중요 · 프로젝트를 안 고른 "전체" 상태의 동작이 없다

한 학생이 미프에선 정상, 빅프에선 위험이면 이 리스트에 어떻게 나오나?

| 방식 | 문제 |
|---|---|
| 프로젝트마다 행 하나 (중복 행) | 30명 반이 100행이 된다 |
| 학생당 한 행 + 유형 배지 여러 개 | "어느 프로젝트에서"가 사라진다 |

> **권고: 프로젝트 선택을 필수로 만든다.** 진입 시 최근 프로젝트가 기본 선택된 상태로 열리고, "전체"라는 선택지를 아예 두지 않는다. 프로젝트마다 판정이 달라진다는 게 이 화면의 전제인데, 그렇다면 프로젝트 없는 통합 판정은 애초에 의미가 없다.

### R-20 · 중요 · 기본 정렬과 기본 필터가 없다

위험과 우수를 한 테이블에 넣으면 위험도순 정렬 시 우수 학생이 맨 아래로 밀려 안 보인다. 통합한 의미가 사라진다.

> **권고: 열면 위험만 보이고 정렬은 위험도순.** 우수는 세그먼트 토글로 전환한다.

통합의 이득은 "같은 화면·같은 필터·같은 상세 페이지를 쓴다"는 것이지 "한 화면에 동시에 보인다"가 아니다.

### R-21 · 보완 · 매니저가 우수 학생에게 할 수 있는 액션이 없다

멘토도 발표도 안 시키기로 했고, 목적은 **운영 관리자가 알고 있는 것**이었다. 그렇다면 담당 매니저 화면에서는 우수 필터를 아예 빼는 것도 선택지다.

넣는다면 **"매니저는 이걸 보고 무엇을 하는가"에 답이 있어야 한다.**

### R-22 · 보완 · 프로젝트가 사실상 기술 영역의 프록시다 → 라벨을 달자

기술영역 히트맵을 별도 축으로 없앤 건 맞는 판단인데, 영역 정보 자체는 프로젝트에 내재돼 있다("미프 3차 = 클라우드").

> **권고: 프로젝트에 영역 라벨을 단다.** "미프 3차"보다 "미프 3차 · 클라우드"가 훨씬 읽힌다. 별도 태깅 체계 없이 프로젝트 생성 시 문자열 하나면 되고, 나중에 "이 학생은 클라우드 계열에서 반복적으로 약하다"까지 자연스럽게 나온다. 값싼 개선이다.

## Part 5 리포트

학생은 전문(전체 문답 + L1~L3 상세 피드백), 매니저는 요약. **이 비대칭 자체는 정확하다.** 학생은 자기 것 하나를 깊게 보고 매니저는 30명을 얕게 본다.

### R-23 · 중요 · 화면에서 빼는 것과 저장하지 않는 것을 구분해야 한다

> 여기서는 실제 문답 내용이 굳이 없어도 됨. 없는 버전으로 일단 만들고, 필요해 보이면 나중에 추가하기.

화면 결정으로는 동의한다. 다만 **원문은 반드시 저장하되 화면에만 안 띄우는 것**이어야 한다.

- 나중에 추가하기로 했을 때 과거 데이터가 없으면 만들 수 없다.
- 채점 이의나 오작동 조사 때 원문이 없으면 아무것도 못 한다.

학생 리포트에는 어차피 전문이 들어가므로 데이터는 이미 있다. 매니저 화면에서 그 경로를 안 여는 것뿐이다.

### R-24 · 중요 · 빅프 리포트 구성이 미정이다

"결과 리포트: 문제 3개의 종합 리포트 + ..."가 미프 리포트인지 빅프도 포함인지 불명확하다. 확정 필요:

- 빅프 체크포인트도 3문제 검증 세션 구조인가?
- 빅프 리포트에 점수가 표시되는가? (R-08의 재정의와 연결)
- 빅프 리포트에 교안 참고 위치가 들어가는가? (R-14)

**한 가지 더 — A5 경계 확인.** 학생에게 전체 문답 + "어디가 틀렸는지" 상세 피드백을 주는데, 기존 A5(채점 근거·루브릭은 매니저 전용)와의 경계가 어디인가. "네 답변의 이 부분이 부족하다"는 채점 근거의 일종이다. 루브릭 자체는 안 보이지만 사실상 채점 논리가 노출된다. **재시험이 동일 문제라면 이건 정답을 알려주고 다시 보게 하는 것**이 된다 (R-01·R-13-③과 겹침).

## Part 6 아무도 언급 안 한 빠진 것

### R-25 · 치명 · 미응시·결시 처리가 없다

체크포인트에 안 들어온 학생을 0점으로 볼지 결측으로 볼지가 없다.

- 0점이면 평균이 오염된다.
- 결측이면 위험 신호를 놓친다.

> **권고: 결측 처리 + 별도 "미응시" 상태를 위험 목록에 1급으로 노출.** 못하는 것보다 안 하는 게 더 위험한 신호다.

기존 PLAN-04(응시현황·독촉)가 있었으나 새 구조(회차 제거·프로젝트 단위)에서 재정의가 필요하다.

### R-26 · 중요 · 부정행위 최소 방어가 없다

- 세션 중 다른 LLM으로 답변 생성
- 재시험 때 1차 리포트를 옆에 켜두기 (동일 문제면 기본값이 된다)
- R-01의 문제 유출

완전 차단은 불가능하지만 **답변 소요 시간·붙여넣기 감지** 정도의 신호는 남겨야 한다.

아예 안 할 거면 **"안 한다"를 명시적으로 결정하고 넘어가야** 한다. 지금처럼 언급이 없는 상태가 제일 나쁘다.

### R-27 · 치명 · 골든셋을 누가 만드는지가 없다

R-03 캘리브레이션의 전제인데 **사람 채점자 확보 계획이 없다.** 이게 없으면 절대 기준 노선 자체를 재검토해야 한다.

정할 것: 누가 / 몇 건 / 언제 갱신 / 모델 교체 시 재실행 트리거.

### R-28 · 중요 · 기관 운영자(Operator) nav가 갱신되지 않았다

D67이 "총괄 nav = 담당 nav + 운영관리 하나"였다. 그런데 이제 운영자가 **기수 전체 히트맵·우수 학생·반 필터**를 본다. 운영자 전용 화면 목록을 다시 그려야 한다.

호칭 변경(총괄 매니저 → 기관 운영자)도 D63·D64·D66·D67·D68과 와이어프레임 `manager/lead-only/` 경로 전반에 반영이 필요하다.

### R-29 · 보완 · 기수 종료 후 정책이 없다

수료생이 자기 리포트를 계속 볼 수 있나? 포트폴리오 가치가 있는데 지금 보존 정책이 SYS-01의 soft-delete뿐이다. 리포트 아카이브 화면을 신설하기로 한 이상 더 중요해졌다.

**추가:** GOV-03 열람 범위(전체/요약/비공개)가 아카이브에도 걸리나? 과거 회차를 나중에 비공개로 바꾸면 이미 본 리포트는 어떻게 되나? **열람 범위의 시점 고정(스냅샷) 여부**가 미정이다.

### R-30 · 보완 · 알림 이벤트가 늘었다

AUTH-10(알림·전역)에 추가 필요:

- 리포트 발행
- 재시험 대상 통보
- 재시험 마감 임박
- 빅프 체크포인트 도래

### R-31 · 중요 · 규모 감각이 없다

기수당 미프 몇 개, 빅프 몇 주, 반 정원, 기수 정원. 이게 없으면 **히트맵 열 개수도 페이징도 못 정한다.** R-15의 최소 표본 판단에도 직결된다.

## Part 7 AI 비용·모델

지적하신 방향은 대부분 맞다. 빠진 것과 결론을 덧붙인다.

### R-32 · 치명 · 세션당 토큰 상한이 없다

대화형이라 학생이 장문을 반복하면 한 세션 비용이 몇 배로 뛴다. **상한과 초과 시 동작**(강제 종료 / 요약 압축 / 매니저 알림)을 정해야 하고, 이건 비용 사고로 직결되므로 우선순위가 높다.

### R-33 · 중요 · 비용 가시성 범위

> **권고**
> - **서비스 업체(Superadmin)** = 전 기관 · 모델별 단가 · 절대량/증감량
> - **기관 운영자(Operator)** = 자기 기관 총량 + 기수/반 단위
> - **매니저** = 안 봄

매니저에게 비용을 보여주면 "비싸니까 세션 짧게"라는 잘못된 압력이 생긴다.

### R-34 · 중요 · "키가 유출된 교육생"의 의미가 불명확하다

학생이 **자기 API 키를 넣는 구조**인지, 플랫폼이 대신 호출하고 **학생 단위로 사용량만 귀속**하는 구조인지에 따라 설계가 완전히 달라진다.

- 전자면: 키 관리·회수·유출 대응 전체가 필요하다.
- 후자면: 학생별 사용량 집계 + 이상 사용 탐지 + 상한만 있으면 된다.

확인 필요 → Q13.

### R-35 · 중요 · 모델 선택을 운영자에게 모델명으로 노출하면 안 된다

운영자가 특정 모델 두 개 중 뭐가 나은지 판단할 수 있는 사람이 아니다. 그리고 **채점 모델을 기관별로 다르게 두면 기관 간·반 간 점수 비교가 원천적으로 불가능해지고, 캘리브레이션을 기관 수만큼 돌려야 한다.**

> **권고**
>
> | 파이프라인 | 정책 |
> |---|---|
> | **채점** | **플랫폼 고정.** 서비스 업체만 변경, 변경 시 전 기관 재캘리브레이션. 협상 불가 영역 |
> | **질문 생성·요약** | **티어 추상화로 노출** — "정확도 우선 / 균형 / 비용 우선" 3티어만 보이고, 티어↔모델 매핑은 플랫폼이 관리 |
>
> 이러면 Nvidia Build가 모델을 deprecate해도 **매핑만 갈아끼우면 되고 기관은 아무것도 안 한다.** 지금 겪는 모델 수명 문제의 정공법이다.

**추가:** Score에 `model_version`·`prompt_version`·`rubric_version`은 이미 저장하기로 돼 있다. 여기에 **`calibration_version`을 추가**해야 한다. 캘리브레이션 버전이 다른 점수끼리는 화면에서 비교를 막아야 한다.

## Part 10 "정할 것"에 대한 권고안

추측 대신, 제가 기획한다면 이렇게 정하겠다는 안이다.

### ① 요구사항 입력 vs 교안 섹션 선택 → 프로젝트 유형에 따라 다르다

둘 중 하나를 고르는 문제가 아니다.

| | 방식 | 이유 |
|---|---|---|
| **미프** | **교안 섹션 선택 (필수)** | 교안 적용이 목적이고 "학습 목표가 평가와 연결돼야 한다"는 게 이 제품의 핵심 논리다. 이래야 논리가 닫힌다 |
| **빅프** | **자유 입력** | 교안 무관 |

**덧붙임 — 학습목표(LearningObjective)를 명시적 엔티티로 신설하라.**

교안 섹션 → 학습목표 → 문제 → 축 → 리포트가 한 줄로 추적되면, "이 학생이 무엇을 이해 못 했나"가 5축이라는 추상어가 아니라 **교안의 그 단원**으로 나온다. 이게 제품의 실질 가치이고 지금 빠져 있다. R-14(교안 매핑 필수 승격)와 함께 묶어서 결정해야 한다.

### ② 관심 학생 즐겨찾기 → 넣는다. 단 개인 북마크(비공유)

싸고 효과가 크다. 공유 태그로 만들면 사실상 요주의 명단이 되어 낙인 문제가 생기고, 매니저 교체 시 인수인계 이슈가 붙는다.

### ③ 개입 유형의 교육학적 근거 → 지금 정하지 마라

운영 데이터가 0건인 상태에서 유형 체계를 정교화하면 나중에 전부 버린다.

> 지금은 **자유 텍스트 + 최소 태그 3개**(면담 / 학습지원 / 관찰)로 두고, 6개월 뒤 실제 기록을 보고 유형을 역추출한다.

지금 정하는 건 근거 없는 확정이다. R-11(개입 관리 축소)과 같은 맥락이다.

> 단, n=7·단일 모델·단일 채점 회차다. 모델을 바꾸면 이 평균이 어디로 움직이는지는 **아직 아무 데이터도 없다**(13-7).

### 13-2 · 치명 · R-36 · 코드_이해와 설계_논리는 같은 것을 두 번 세고 있다

두 축의 점수를 세션별로 나란히 놓으면:

| 세션 | 코드_이해 | 설계_논리 | 차이 |
|---|---|---|---|
| 김만서 | 3 | 3 | 0 |
| 김연주 | 3 | 3 | 0 |
| 박종호 | 5 | 4 | 1 |
| 박진용 A | 1 | 1 | 0 |
| 박진용 B | 5 | 5 | 0 |
| 손진원 A | 3 | 4 | 1 |
| 손진원 B | 3 | 3 | 0 |

**7세션 중 5세션이 완전 동일, 나머지 2세션도 차이 1.** 사실상 상관계수 1.0이다.

원인은 채점 로그에 그대로 찍혀 있다 — **두 축이 학생의 동일한 문장을 근거로 인용한다.** 실제 예(손진원 B):

> **코드_이해 3점** 근거: "베이지안 평점 계산할때 m이 전체 도서 평균이 필요해서 allBooks를 쓴겁니다…"
> **설계_논리 3점** 근거: "베이지안 평점 계산할때 m이 전체 도서 평균이 필요해서 allBooks를 쓴겁니다…"

동일 인용이 김만서·박진용 A에서도 확인된다.

**구조적 원인:** L1 질문이 "무엇을 하는가"와 "왜 그렇게 했는가"를 **한 문장에 묶어서** 묻는다. 답변이 하나니까 근거도 하나고, 채점도 같아진다.

**귀결이 큽니다.** 25점 만점·5축 동일 가중 구조에서 **L1이 10점(40%)을 가져가는데 독립 신호는 1개**다. 즉 지금 총점은 L1 이해도에 40% 가중을 준 값이다. 의도한 설계가 아니다.

### 13-3 · 치명 · R-37 · 질문이 답을 포함하고 있다 (대안_비교 무효)

손진원 B의 L3 질문 원문:

> …어떤 아키텍처적 변경을 제안하시겠습니까? **예를 들어, 1) 서버에서 m 값을 캐싱하고 엔드포인트로 제공하거나, 2) 클라이언트에서 필요한 시점에만 m을 요청하는 Lazy 로딩 방식을 쓰거나, 3) 아예 Bayesian 평점 계산을 서버 측 이벤트에서 비동기로 업데이트하는 방식으로 변경할 수 있습니다.**

학생 답변:

> 저는 **3번**, 서버에서 리뷰 작성 시점에 평점을 비동기로 업데이트하는 방식이 제일 나을거같습니다.

채점 결과: **대안_비교 5점** — "구체적인 기술적 대안(3번)을 즉시 제시하고…"

**학생은 대안을 제시하지 않았다. AI가 준 3지선다에서 골랐다.** 그리고 만점을 받았다.

반대편 사례: 김만서 L3 질문에는 선택지가 없었고, 학생은 아무 대안도 못 냈고 **대안_비교 1점**을 받았다.

**즉 대안_비교 점수는 "그 질문에 우연히 보기가 붙었는가"에 좌우된다.** 손진원 A의 L3에도 `(예: Context API + useMemo …)` 힌트가 있었다. 통제되지 않은 변수이고, **이 축은 현재 상태로는 판정에 쓸 수 없다.**

### 13-4 · 치명 · R-38 · 자기_수정은 잘한 학생에게서 조직적으로 누락된다

손진원 A 세션은 **3턴만에 종료**됐고 판정은 `소유`(defended)였다. 채점 로그:

> **자기_수정 미검증** — 이 세션은 REFLECTION 레벨까지 진행되지 않아 채점하지 않았습니다 (조기 방어 성공했거나, 세션이 그 전에 종료됨).

**조기 방어에 성공한 학생 = R 턴에 도달하지 않음 = 자기_수정 미측정.** 그런데 자기_수정은 5축 중 하나이고 총점에 들어간다.

결과: **`소유` 학생은 4축, `표면` 학생은 5축으로 채점된다.** 평균을 내든 합을 내든 두 집단의 점수는 같은 자로 잰 값이 아니다. 위험·우수 판별이 이 위에 서 있다.

### 13-5 · 치명 · R-39 · 무성의 응답과 실력 부족을 구분하지 못한다

박진용은 같은 날 두 세션을 봤고 결과가 **전 축 1점 / 전 축 4~5점**으로 갈렸다.

전 축 1점 세션의 실제 답변:

| 턴 | 답변 |
|---|---|
| L1 | "시간이라는 형식이 깨지지 않기 위해서입니다." (1문장) |
| L2 | "엔티티의 재사용성과 일관성이 높아졌다고 생각합니다." (1문장) |
| R | **질문 문장을 그대로 붙여넣음** — "엔티티의 책임과 DTO의 책임을 분리하는 것이 왜 중요한지, 그리고 그렇게 했더라면 지금과 비교해 어떤 점이 달라졌을지 구체적으로 생각" |

채점기는 이를 "기초 공백" 계열로 읽는다(자기_수정 1점 사유 = "답변이 텅 비어 있음"). 하지만 실제로 일어난 일은 **무성의 응시**다. 같은 학생이 다른 세션에서 전 축 4~5점을 받았다.

**→ R-16(“기초 공백”은 원인을 이름에 박았다)이 실측으로 확정된다.** 그리고 R-25(미응시 처리)는 범위를 넓혀야 한다 — 결시뿐 아니라 **형식적 응시**를 분리해야 한다. 지금 구조로는 무성의한 학생이 "기초가 없는 학생"으로 분류되어 잘못된 개입을 받는다.

**최소 방어:** 답변 길이·소요 시간·질문문 복붙 여부는 이미 다 가지고 있는 데이터다. 임계 미달 시 채점하지 말고 `무효 응시`로 빼는 게 맞다.

### 13-6 · 중요 · R-40 · 채점 파이프라인 실패율 (1/8)

강민수 세션은 트랜스크립트만 있고 **채점 결과 블록이 통째로 없다.** 문서에 `[]` 빈 배열만 남아 있다. 8세션 중 1건 = 12.5%.

ENG-01 예외 case 3(일부 축 채점 실패 → 실패 축만 독립 재채점)이 명세에는 있으나, 실제로는 전체가 비었다. **재시도·실패 가시화가 구현돼 있는지 확인이 필요하다.** 매니저 화면에서 "채점 안 됨"이 조용히 빈칸으로 보이면 안 된다.

### 13-7 · 중요 · R-41 · 모델 비교 데이터가 0건이다

8세션 전부 `stepfun-ai/step-3.5-flash` 단일 모델이다. **R-35(채점 모델 고정 vs 선택)와 Q28을 뒷받침할 데이터가 아직 없다.**

가장 값싼 실험: **이미 있는 8세션 로그를 다른 모델 2개로 재채점**한다. 학생을 다시 부를 필요가 없고, 세션 생성 비용도 안 든다. 채점 프롬프트만 다시 돌리면 된다.

- 축별 평균이 얼마나 이동하는지 → 스케일 보정 필요량
- 같은 세션의 순위가 뒤집히는지 → 상대평가로도 못 구제되는지

**이 실험 하나가 Q28·R-03·R-35를 동시에 닫는다. 반나절이면 된다.**

### 13-7b · R-44 · 5축 루브릭 앵커는 이미 존재한다 (Q3 = 예) — 단 자기_수정 채점이 불일치

채점 근거문에 **루브릭 레벨 서술구가 그대로 새어나온다.** 관측된 칸만 역추출하면 이렇다.

| 축 | 1점 | 2점 | 3점 | 4점 | 5점 |
|---|---|---|---|---|---|
| 코드_이해 | "그냥 이렇게 했습니다" · 질문과 무관/텅 빔 | ? | 구성요소는 인지하나 **연결 관계 설명 불가** | **흐름은 맞지만** 일부 연결 불명확 | 흐름을 정확히 설명 |
| 설계_논리 | 왜 이렇게 했는지 **설명 자체를 못함** | ? | **"이렇게 하면 될 것 같아서"** 수준 · 제약조건 연결 약함 | 의도는 설명하나 제약 연결이 비명시적 | 의도–제약을 명확히 연결 |
| 대안_비교 | **대안이라는 개념 자체를 이해 못함** | ? | 대안의 존재는 인정하나 **구체화 못함** | ? | **구체적 기술 대안을 즉시 제시** |
| 반례_대응 | **반례를 던져도 이해 불가** | 반례 인지하나 **"문제없다"고 주장**·대응 안 함 | ? | **즉각 인지는 아니나 이해 후 대응** | **스스로 먼저 인지** |
| 자기_수정 | 4신호 **0개** | ? | ? | 4신호 3~4개 | 4신호 4개 **스스로** |

**→ Q3(앵커 존재?)은 "예"다.** 15-5 재설계 시 이 앵커를 버리지 말고 4축으로 재배치하면 된다. 다만 **원문 파일이 필요하다** — 위 표의 `?` 칸(특히 2점 전체)은 관측되지 않아 비어 있고, 앵커 없는 레벨은 채점이 흔들린다.

**동시에 발견된 불일치 (ENG-05 재현성 문제의 실사례):**

| 세션 | 채점 근거 | 점수 |
|---|---|---|
| 박진용 B | 오류인식·이유·새판단 3신호. **"구체적 개선안은 제시하지 않아 4점"** | **4점** |
| 김만서 | **"4개 신호 전부 제시"** | **4점** |
| 손진원 B | **"4개를 모두 스스로 제시"** | **5점** |

**3신호와 4신호가 같은 4점**을 받았고, **같은 4신호가 4점과 5점으로 갈렸다.** 팀 제안서의 정의("4신호 충족 개수")대로라면 김만서는 5점이어야 한다. 차이를 만든 건 `스스로`라는 수식어인데 **이 조건은 정의에 없다.**

→ **자기_수정 앵커를 "신호 개수 × 자발성" 2차원으로 명시하거나, 자발성을 빼고 개수만으로 고정해야 한다.** 지금은 채점기가 매번 다르게 판단한다.

### 13-10. 테스트 당시 엔진 실측 (2026-07-27, `team-iz.github.io/AI/lab/code-qna`)

> 8세션을 만들어낸 **그 당시 파이프라인**을 직접 확인했다. 재설계 대상이 아니라 **13-1~13-9의 원인 규명 근거**다.
> 소스: `shared/p03-engine.js` · `lab/prompt_manifest.json` · `cognition/two_tier_scan.py`

#### ① 정정 — 테스트는 **적응형이 맞았다**

앞서 "L2·L3가 원본 코드만 보고 생성됐다"고 적었으나 **틀렸다.** 매니페스트의 L2 템플릿에 학생 트랜스크립트가 들어간다.

> `## 이미 물어본 질문 …{transcript}` / `지금까지의 턴별 판정: {verdict_note}` / **"방금 답변에서 부족했던 근거·구체성을 정확히 겨냥하세요."**

실제 세션에서도 확인된다 — 강민수 L1 답변 말미 **"권한 변경이 즉시 반영 안 됨이 단점"** → L2 질문 **"권한 변경 시 즉시 반영되지 않는 문제가 있습니다. 이 문제를 해결하기 위해…"** 로 학생의 결론을 그대로 받아 파고든다.

**→ 적응성은 이미 구현돼 있다.** Part 15-4는 "없는 것을 만들기"가 아니라 **"자유 생성을 분기 사다리로 규율하기"** 로 목적이 바뀐다.

#### ② R-36의 진짜 원인 — 코드_이해를 묻는 질문이 아예 없다

매니페스트 `axis_level_map`이 **코드_이해와 설계_논리를 둘 다 `["l1"]`** 에 걸고 있다(중복 확정). 그런데 진짜 문제는 그게 아니다.

L2 템플릿이 L1의 성격을 명시한다:

> **"앞선 질문은 '왜 이렇게 설계했는가'를 물었습니다."**

실제 8세션 L1 질문 전수가 **"왜/이유/배경/목적"** 을 묻는다. 그런데 루브릭은:

| 축 | 5점 앵커 | 질문이 그걸 묻나 |
|---|---|---|
| 코드_이해 | **구성 요소 간 관계와 데이터 흐름을 정확히 설명** (WHAT/HOW) | **아니오 — 물어본 적 없음** |
| 설계_논리 | 설계 의도와 제약조건을 연결해 설명 (WHY) | 예 |

**→ 코드_이해는 "물어보지도 않은 것"을 채점하고 있었다.** 그래서 설계_논리 답변을 같이 읽고 같은 점수가 나온 것이다.

**교정이 훨씬 싸진다.** 축을 지울 게 아니라 **L1이 WHAT을 묻게 하고 WHY를 L2로 넘기면** 두 축 다 살아난다. 루브릭 앵커는 이미 잘 쓰여 있어 **한 글자도 안 고쳐도 된다.** → Part 15-5의 4축 안을 **5축 유지 + 턴 재배치**로 바꾸는 근거(15-5 개정 참조).

#### ③ 에스컬레이션이 실패 기반 — 자기_수정은 실패자만 측정된다 (R-38 심화)

L3·R 템플릿의 첫 문장:

> L3: **"트레이드오프 반례에도 학생이 방어하지 못했습니다."**
> R: **"극단 시나리오에도 학생이 방어하지 못했습니다."**

**즉 R에 도달했다는 것 자체가 "L1·L2·L3를 전부 못 막았다"는 뜻이다.** 방어에 성공하면 조기 종료되어 R에 가지 않는다(손진원 A).

결과가 13-4보다 나쁘다.

- **조기 방어자(잘한 학생)** = 자기_수정 미측정 → 4축 평균
- **끝까지 간 학생(못한 학생)** = 자기_수정 측정 → 5축 평균

그리고 이 5번째 축이 **구제 점수로 작동한다.** 손진원 B는 L1·L2·L3를 다 뚫렸지만 자기_수정 5점을 받아 평균이 올라갔다. **두 집단의 총점은 비교 불가일 뿐 아니라, 못한 쪽에 보정이 붙는 방향이다.**

#### ④ R-44의 원인 — 자기_수정 5점 조건이 구조적으로 판정 불가

루브릭 원문:

> **5점:** 4개 신호 전부 **스스로** 제시
> **4점:** 자기오류인식 포함 **3개 이상**

김만서는 근거문에 "4개 신호 전부 제시"라고 적히고도 **4점**을 받았다. 루브릭대로면 5점이다. 갈린 지점은 **`스스로`** 하나뿐인데 —

**R 질문 자체가 유도하도록 설계돼 있다.** p03-4 템플릿: *"학생이 스스로 '이 부분은 이렇게 바꿨어야 했다'는 결론에 도달하도록 **유도하는** 확인 질문"*

유도된 답변에서 "스스로"를 판정하는 것은 원리적으로 불가능하다. **5점 칸을 `4개 신호 전부`로 바꾸고 자발성 조건을 빼야 한다.**

#### ⑤ DP(문항 소재)는 LLM이 아니라 정적 분석기가 뽑는다

P02는 **LLM 호출 0회**다. `cognition/two_tier_scan.py` + `judgment/score_findings.py`가 Pyodide로 브라우저에서 돌며 코드 패턴을 찾는다. 테스트 문서에 찍힌 `cognition-isolation:Header.jsx` · `architecture-diffusion:apiResponse.ts` · `repeated-pattern:duplicate-definition:…` 가 그 **finding 유형**이다.

**→ 문항 소재가 "코드 스멜"이지 "학습목표"가 아니다.** 13-0 한계표에 4번 항목을 추가한 이유이고, Part 15의 학습목표 앵커 전환이 필요한 **가장 직접적인 근거**다. 난이도가 통제되지 않은 것도 여기서 온다 — 스캐너가 찾은 결함의 난이도는 아무도 정하지 않는다.

#### ⑥ 답변 분류기는 이미 있고 공짜다

p03-5는 **LLM이 아니라 결정론적 정규식**(`isolation_classifier` / `reflection_signal`)이고, 매니페스트에 *"v1에서는 읽기 전용"* 이라고 적혀 있다.

**→ Part 15-4의 분기 사다리에 필요한 분류기가 이미 구현돼 있고 비용이 0이다.** 지금은 결과를 읽기만 하고 분기에 쓰지 않는다. **분기에 연결하는 것만으로 15-4가 성립한다.**

### 13-8. 잘 작동하는 것 (건드리지 말 것)

- **질문의 코드 종속성.** L1~L3 전부 파일명·함수명·코드 라인을 직접 인용하고, 원본 없이는 답할 수 없다. MEAS-06의 핵심 규칙이 실제로 지켜지고 있다. **이 시스템의 가장 강한 부분이다.**
- **근거 인용 강제.** 모든 축 점수에 학생 답변 원문이 인용돼 있다. A2(근거 없는 수치 금지)가 코드로 지켜지고 있다.
- **evidence 서술 품질.** 비전공자 매니저가 읽어도 이해 가능한 수준이다 — R-23(AI 요약만 노출)의 전제가 확인됐다.

### 13-9 · 보완 · R-42 · 실제 교안 PDF가 AES 암호화돼 있다

제공된 `AI_Kubernetes와 CICD_교안.pdf`(76쪽)는 **AES-128 암호화(`/V 4 /R 4`, StmF/StrF 적용)** 상태다. 목차·본문 스트림이 전부 암호화되어 일반 텍스트 추출이 실패한다.

CUR-01(PDF 구조 추출)이 **실제 교안에서 바로 막힐 수 있다.** 기관에서 받는 교안이 대부분 DRM 걸린 배포본이라면 이건 예외 처리가 아니라 기본 경로다. 확인 필요:

- 암호 해제본을 받을 수 있는가, 아니면 업로드 시 **"암호 걸린 PDF"를 명시적으로 거부**해야 하는가.
- 후자라면 CUR-01 예외 case에 추가하고, 업로드 화면에 사전 검사를 넣어야 한다.

## Part 14 질문 순서·축 매핑 재설계 (팀 제안에 대한 답)

### 14-1. 들어온 제안

> 질문 순서를 **L1 → L2 → L3**로만 한정하고, **자기수정을 L2+L3로** 판단해도 되는가?

### 14-2. 결론 — 안 된다. 단 지금 구조를 유지하라는 뜻은 아니다

**자기수정을 L2+L3에서 판정할 수 없는 이유는 데이터에 있다.** 김만서 세션이 정확한 반례다.

| 턴 | 학생 행동 | 점수 |
|---|---|---|
| L3 | 반례(클래스 오분류)를 받고 **"아닙니다. 킥보드인지를 확인하고가 먼저입니다"** 라고 방어 | 반례_대응 **2점** |
| R | **"일단 해당 문제는 저희도 인지를 했습니다. 그렇기에 연속적인 촬영을 하고 threshold와…"** — 오류인식·이유·새판단·개선안 4신호 전부 제시 | 자기_수정 **4점** |

**L2·L3에서는 방어했고, R에서 수정했다.** L2+L3만 보면 이 학생의 자기수정 능력은 관측되지 않는다 — 오히려 "반례를 인정 안 하는 학생"으로 읽힌다.

구조적으로도 그렇다. **L2·L3는 매번 새 주제를 던지지 같은 주장을 다시 흔들지 않는다.** 자기수정은 "자기가 방금 한 말을 뒤집는가"인데, 그걸 관측하려면 **같은 주장으로 되돌아오는 턴**이 필요하다. R이 그 역할이다.

### 14-3. 그런데 진짜 문제는 R이 아니다

팀이 R을 의심한 건 방향이 반쯤 맞다. 다만 실제 결함은 다른 곳에 있다.

| 축 | 실측 상태 | 판정 |
|---|---|---|
| 코드_이해 · 설계_논리 | 근거 인용 동일, 점수 5/7 완전 일치 | **중복 — 1개로 합치거나 질문을 쪼개야 함** (13-2) |
| 대안_비교 | 질문에 보기가 붙으면 만점, 없으면 1점 | **오염 — 현 상태로 판정 사용 불가** (13-3) |
| 반례_대응 | L2·L3 모두에서 관측, 분포 정상 | 정상 |
| 자기_수정 | 분산 최대(1.57)로 **가장 잘 변별**. 단 상위권 미측정 | **살려야 함. 대신 누락을 고쳐야 함** (13-4) |

**자기_수정은 5축 중 변별력이 가장 높다.** 지우자는 제안이 들어온 축이 실은 가장 쓸모 있는 축이다.

### 14-4 · R-43 · 구현이 명세와 반대로 돌고 있다

기능명세서 MEAS-06 처리 로직:

> 6. **대안·트레이드오프·실패 조건 중심 L2** 후속 질문
> 7. **극단 입력·장애·반례 중심 L3** 질문 및 Self Reflection 수행

실제 생성된 질문(손진원 B):

| 턴 | 실제 내용 | 명세상 | 실제 |
|---|---|---|---|
| L2 | "allBooks가 stale일 때… 어떤 설계를 선택하시겠습니까" | 대안 | **반례** |
| L3 | "10,000권 규모라면… 1)·2)·3) 중 어떤 변경을" | 반례 | **대안** |

**L2와 L3의 역할이 뒤바뀌어 구현됐다.** 채점기도 그에 맞춰 반례를 L2에서, 대안을 L3에서 뽑고 있다. 어느 쪽이 맞는지 정하고 명세·구현·채점 매핑을 일치시켜야 한다.

> 참고로 **뒤바뀐 쪽이 교육적으로 더 낫다.** 반례를 먼저 던져 흔들고(L2), 그 뒤 대안을 요구하는(L3) 순서가 인지적으로 자연스럽다. 명세를 구현에 맞추는 방향을 권한다.

### 14-5. 권고안 — 4턴 유지, 축 매핑만 교정

턴을 줄이는 게 아니라 **축을 줄이고 근거 턴을 분리**한다. 세션 비용은 그대로이고 채점 호출은 오히려 줄어든다.

> ⚠️ **아래 표는 13-10 실측 전에 쓴 초안이다. 최종안은 15-5를 볼 것** — 루브릭 원문 확인 결과 축을 지울 필요가 없어졌다. 이 표는 논의 경로 기록으로만 남긴다.

| 축 | 근거 턴 | 초안 | 최종(15-5) |
|---|---|---|---|
| 코드_이해 | L1 | 유지 | 유지 + **L1을 WHAT 질문으로 교정** |
| 설계_논리 | L1 | ~~삭제~~ | **유지 · L2로 이동** |
| 대안_비교 | L3 | 근거 턴 축소 | L3 · 보기 제거 |
| 반례_대응 | L2 | 근거 턴 축소 | **유지 · L3** |
| 자기_수정 | R | 전원 필수화 | 동일 + **"스스로" 조건 삭제** |

**같이 가야 하는 것 셋:**

1. **L1 질문에서 "무엇을/왜"를 한 문장에 묶지 않는다.** 설계_논리를 흡수했으므로 L1은 "왜 그렇게 했는가"에 집중하면 된다.
2. **대안 요구 질문에 예시 보기를 넣지 않는다.** 프롬프트 한 줄이면 되고, 이게 13-3의 유일한 근본 해결이다.
3. **R 턴 필수화.** 조기 방어(`소유`) 세션도 R을 한 번 태운다. 턴이 1개 늘지만, 그래야 전원이 같은 축 수로 채점된다.

### 14-6. 난이도 조절·포커스 — 지금 노브를 만들지 마라

팀에서 "난이도 조절과 포커스를 둬야 하는 항목이 고려 안 됐다"는 지적이 있었다. 맞는 지적이지만 **지금 노브를 만드는 건 이르다.**

**진짜 문제는 난이도가 아니라 축 오염(13-2·13-3)이다.** 오염된 축 위에 난이도 노브를 얹으면 무엇이 바뀌었는지 해석할 수 없게 된다. **14-5를 먼저 하고, 그다음에 재측정해서 그때도 난이도가 문제면 노브를 단다.**

## Part 15 측정 방법론 재설계 — 학습목표 앵커 방식

> Part 13의 한계와 Part 14의 축 문제를 함께 푸는 **단일 재설계안**이다.
> 팀 질문 "난이도 조절과 포커스를 어떻게 잡나"에 대한 답이기도 하다.

### 15-1. 진단 — 난이도를 못 잡는 이유는 노브가 없어서가 아니다

지금 파이프라인의 출발점은 **코드**다.

```
코드 → DP 추출 → 질문 생성 → 채점
```

코드에서 질문을 뽑으면 **난이도가 코드의 복잡도에 종속**된다. 학생이 우연히 어려운 걸 짰으면 어려운 질문을 받고, 단순하게 짰으면 쉬운 질문을 받는다. **잘 짤수록 불리하다.**

그리고 "적정 난이도"를 판단할 **기준이 시스템 안에 없다.** 노브를 달아도 매니저가 무엇을 기준으로 상/중/하를 고를지 알 수 없다. 실측 테스트가 어려웠던 것도 같은 이유다 — 교안과 무관한 코드에서 뽑았으니 **비교 기준 자체가 없었다.**

**포커스(PLAN-03)도 같은 병이다.** "검증 포커스"가 추상어로 남아 있어 매니저가 무엇을 입력해야 할지 모른다.

### 15-2. 전환 — 코드가 아니라 학습목표에서 출발한다

팀이 이미 세운 원칙이 답을 갖고 있다.

> **학습 목표가 평가와 연결이 되어야 개념 이해 여부를 판단할 수 있다.**

이 원칙을 파이프라인 순서로 옮기면 된다.

```
학습목표 → 그 목표가 코드에 나타난 지점 탐색 → 질문 생성 → 채점
              (코드는 출발점이 아니라 근거 표면)
```

**한 번의 전환으로 다섯 개가 동시에 풀린다.**

| 문제 | 학습목표 앵커가 푸는 방식 |
|---|---|
| **난이도** | 학습목표 수준이 곧 난이도 상한. **안 배운 건 안 묻는다.** 노브 불필요 |
| **포커스(PLAN-03)** | = 이번 체크포인트에서 검증할 학습목표 3개 선택. 추상어가 구체 항목이 됨 |
| **R-02 비교 가능성** | 팀이 달라도 **같은 학습목표를 물으므로** 비교 성립. "동일 주제라서"가 아니라 "동일 목표라서" |
| **R-14 교안 위치 안내** | 역방향 매핑 파이프라인 불필요. 질문이 이미 목표에서 나왔으므로 **출처가 자동으로 따라온다** |
| **미프/빅프 분기** | 미프=학습목표 앵커(교안 기반), 빅프=코드 앵커(교안 무관). 두 트랙의 차이가 구조로 설명됨 |

### 15-3 · 최우선 · 학습목표는 매니저가 5줄 입력한다 (PDF 파싱 아님)

여기서 과설계 함정이 있다. "학습목표 = 교안에서 자동 추출"로 가면 **CUR-01 PDF 파이프라인에 전체가 물린다.** 그리고 실제 교안은 암호화돼 있다(R-42).

**v1은 텍스트 입력 필드 하나다.**

> 프로젝트 생성 화면 → **"이번 프로젝트 학습목표"** 3~5줄 입력
> 예: `Deployment와 Service의 역할 분리` / `CI 파이프라인에서 이미지 태깅 전략` / `롤링 업데이트 시 무중단 조건`

- 매니저는 이미 이걸 알고 있다. **원래 강의계획서에 있는 내용**이다.
- 개발량 = 텍스트 필드 + 배열 저장. **반나절.**
- 교안 자동 추출(CUR-01)은 나중에 **이 필드를 채워주는 보조 기능**으로 붙이면 된다. 순서가 이래야 한다.

> **선행 관계가 뒤집힌다.** 지금은 `교안 등록 → 매핑 승인 → 질문 생성`이라 교안이 없으면 아무것도 안 된다. 바꾸면 `학습목표 입력 → 질문 생성`이고, 교안은 **위치 안내를 풍부하게 하는 부가 입력**이 된다. Q19(교안을 기수 개설 선행 필수로 승격?)의 답이 **"아니오"** 로 바뀐다.

### 15-4. 적응형 질문 — 생성이 아니라 분기로 만든다

팀 지적대로 후속 질문이 학생 답변에 반응해야 한다. 다만 **완전 자유 생성은 비교 가능성을 죽인다.** 학생마다 다른 길을 가면 점수를 나란히 놓을 수 없다.

**해법: 분기는 고정, 문장은 생성.**

이미 있는 `SURFACE / PARTIAL / DEFENDED` 분류를 그대로 쓴다.

| 직전 답변 분류 | 다음 턴의 **의도** | 방향 |
|---|---|---|
| **DEFENDED** | 전이 질문 — "다른 상황이면 그 선택이 유지되나" | ↑ 위로 |
| **PARTIAL** | 구체화 요구 — "방금 말한 것을 코드에서 짚어보라" | → 옆으로 |
| **SURFACE** | 근거 제시 후 재질문 — "이 줄을 보면 어떤가" | ↓ 아래로 |

**질문 의도는 표에서 결정되고, 문장만 LLM이 쓴다.** 그래서 모든 학생이 같은 **의도 사다리** 위에 있고, 문장은 각자의 답변·코드에 맞춰진다.

**핵심 부산물 — 경로 자체가 측정값이다.**

같은 L3 도달이라도 `DEFENDED→DEFENDED→DEFENDED`로 온 학생과 `SURFACE→힌트→PARTIAL→힌트→도달`한 학생은 다르다. 지금은 최종 답변 품질만 채점하는데, **몇 번 끌어줘야 갔는지**가 실은 더 강한 신호다. 이건 추가 LLM 호출 없이 이미 있는 분류값으로 산출된다.

> **자력도** = 힌트 없이 진행한 턴 수 ÷ 전체 턴 수. 위험 판정에 5축 점수보다 잘 맞을 가능성이 높다. 파일럿에서 함께 계측할 것.

### 15-5. 채점 — 4턴 4축 1:1

Part 14의 결론을 15-4 구조 위에 확정한다. **5축을 4턴에 얹으면 반드시 하나가 겹치고, 그게 R-36의 원인이었다.** 알면서 재현하지 않는다.

> **개정 (13-10 실측 반영):** 처음에는 4축으로 줄이자고 했으나, **루브릭 원문을 확인한 결과 축을 지울 필요가 없다.** 앵커 25칸이 이미 잘 쓰여 있고 5축이 서로 다른 것을 재고 있다. 문제는 축이 아니라 **질문이 축을 안 물어본 것**이었다(13-10②). → **5축 유지 + 질문 교정**으로 바꾼다. 루브릭·리포트·히트맵을 건드리지 않아도 되므로 2주 일정에도 유리하다.

| 축 | 근거 턴 | 질문이 물어야 하는 것 | 변경 |
|---|---|---|---|
| **코드_이해** | **L1** | **무엇을/어떻게** — 구성요소 관계·데이터 흐름 | **L1을 WHAT 질문으로 교정** (지금은 WHY만 물음) |
| **설계_논리** | **L2** | **왜** — 의도와 제약조건의 연결 | L1 → L2로 이동 |
| **반례_대응** | **L3** | 반례를 던졌을 때 인지·대응하는가 | L2+L3 → L3 |
| **대안_비교** | **L3** | 대안의 구체성 | L2+L3 → L3 (반례_대응과 같은 턴, 기준이 다름) |
| **자기_수정** | **R** | 4신호 (**"스스로" 조건 삭제** — 13-10④) | R 전원 필수화 |

**25점 만점 유지.** 코드_이해와 설계_논리가 **다른 턴을 읽게 되는 것**이 R-36의 근본 해결이다.

**반례_대응·대안_비교는 같은 L3를 공유하지만 남긴다.** 실측에서 두 축은 7세션 중 4세션에서 값이 달랐다 — 코드_이해/설계_논리 쌍(5/7 완전 일치)과 달리 **실제로 다른 것을 재고 있다.** 루브릭 앵커도 명확히 다르다(반례=인지 시점, 대안=구체성). 근거 턴 공유 자체가 문제가 아니라, **질문이 한쪽만 묻는 것**이 문제였다 → L3 질문이 반례 제시와 대안 요구를 **모두** 포함하도록 규율한다.

**비용:** 테스트 당시 엔진은 이미 **5축을 1회 tool call로** 채점하고 있었고(`grade_interview_answer`), 진행되지 않은 레벨의 축은 스키마에서 제외한다. 즉 ENG-01 명세의 '축별 원자 평가 5회 호출'은 **현행 구현과 다르다.** 명세를 구현에 맞추면 된다 — 축이 서로 다른 턴을 읽으면 후광효과가 입력 단계에서 차단되므로 1회 호출이 정당화된다.

**같이 가야 하는 프롬프트 규율 셋** (전부 프롬프트 몇 줄):

1. **대안 요구 질문에 예시 보기를 넣지 않는다.** R-37의 유일한 근본 해결.
2. **L1에서 "무엇을/왜"를 한 문장에 묶지 않는다.** L1은 "무엇"만, "왜"는 L2로. R-36의 원인 제거.
3. **R 턴은 전원 필수.** 조기 방어자도 태운다. R-38 해결.

### 15-6. 미프 / 빅프 트랙 분리

| | 미프 | 빅프 |
|---|---|---|
| **앵커** | **학습목표** (매니저 입력 3~5) | **코드** (현행 방식) |
| **문제 3개** | 학습목표 3개 = 문제 3개 | 코드 DP 3개 |
| **난이도** | 학습목표가 상한 — 자동 | 학생 코드 종속 — 통제 안 함 |
| **범위** | 전체 코드 | 본인 커밋 기여분 |
| **비교** | 팀·반 간 **비교 가능** (동일 목표) | **비교 안 함** |
| **성적** | 성취도 판정 근거 | 미반영 — 참여·수행 확인 |
| **기여도 축** | 없음 | 있음 (R-07) |

**"빅프는 비교하지 않는다"를 명시적 설계 결정으로 못 박아야 한다.** 코드 앵커는 난이도가 통제되지 않으므로 점수 간 비교가 성립하지 않는다. R-08의 재정의("성적 제외, 판정·리포트에는 사용")를 여기서 한 번 더 좁혀야 한다 — 빅프 점수는 **개인 내 추이**로만 쓰고 **학생 간 비교에 쓰지 않는다.**

### 15-8. 이 설계가 남기는 것 / 포기하는 것

**포기:**
- 난이도 상/중/하 노브 — 만들지 않는다. 학습목표가 대신한다.
- 반례_대응 축 — 대안_비교로 흡수.
- 교안 등록을 기수 개설 선행 필수로 승격 — 하지 않는다(15-3).
- 빅프 점수의 학생 간 비교 — 구조적으로 포기.

**남김 (건드리지 않음):**
- 질문의 코드 종속성 — 실측에서 가장 잘 작동한 부분(13-8).
- 근거 인용 강제 — A2의 코드 수준 집행.
- L1→L2→L3→R 4턴 — 턴 수를 줄이지 않는다.
- `SURFACE/PARTIAL/DEFENDED` 분류 — 이제 분기의 축으로 승격.
