검증 세션 — 전체화면

자기 코드의 한 지점에 대해, 그 자리에서, 왜 그렇게 됐는지 말하는 시간. 나브도 나가는 링크도 없다.

  • 단계 카운터를 보여주지 않는다. 계단은 학생마다 어디까지 가는지 다르고 막히면 거기서 끝난다 — 3/4단계처럼 쓰면 남은 개수를 약속하는 셈이라 거짓 진행률이 된다. 확정된 값인 문제 2/3만 쓴다.
  • 남은 시간이 아니라 경과 시간. 시간은 안내이고 강제로 끊지 않으므로 카운트다운을 두면 강제처럼 읽힌다.
  • 내부 용어를 쓰지 않는다. L2 설계논리 같은 표기는 화면에 없다.
  • 힌트는 "다시 설명해 주세요"다. 질문을 다르게 말할 뿐 코드 위치도 선택지도 주지 않고, 불이익이 없다는 것을 버튼 옆에 적는다.
  • 창 이탈은 막지 않고 기록한다. 막으면 우회하고, 기록하면 매니저가 본다. 복귀했을 때 한 번만 알린다.
  • 한 문제 = 한 화면. 세 문제는 서로 다른 개념이고 코드 지점도 파일도 다르다 — 같은 대화의 연속이 아니다. 끝난 문제는 다시 볼 수 없다: 지금 문제와 무관한 데 시간을 쓰고, "아까 그거 틀린 것 같은데"만 남는다.
  • 대화는 한 문제 안에서 쌓인다. 질문이 앞 답변을 파고들며 최대 네 번 이어지므로, 앞 질문과 내 답변이 위에 남아야 꼬리질문이라는 것이 보인다.
  • 코드는 왼쪽에 고정, 대화는 오른쪽. 학생은 코드를 보면서 답을 쓴다 — 위아래로 쌓으면 "설명 대상"과 "설명 쓰는 곳"이 멀어져 계속 스크롤하게 된다.
  • 코드는 블록 전체를 준다. 함수·클래스 단위로 자르고 지금 질문이 가리키는 줄만 하이라이트가 옮겨간다. 몇 줄만 떼어 주면 "어디랑 연결되는지"를 답할 수 없고, 반대로 레포 전체를 주면 이해도가 아니라 코드 찾는 속도를 재게 된다. 호출부는 접어 두고 필요할 때 편다.
  • 다시 보기는 같은 화면의 변형이다. 막힌 개념만 · 같은 문항 · 힌트 없음 · 결과는 기록에만. 힌트 버튼이 그냥 없으면 고장으로 보이므로 왜 없는지를 적는다 — 같은 문항이라 이미 설명을 들었다.
  • 제출은 되돌릴 수 없다. 세션 시작 때 한 번 고지하고 끝내지 않고, 제출 버튼 옆에 지금 이 행동이 일방향이라는 것을 계속 적는다. 마지막 답변만 라벨이 바뀌고 확인을 받는다.
