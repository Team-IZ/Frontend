# OP-05 리포트 — 일어날 수 있는 모든 상황

> **이 화면을 고치기 전에 이 문서를 본다.** 무엇이 일어날 수 있고, 지금 그중 무엇이
> 처리돼 있고, 무엇이 안 돼 있나.
>
> 화면의 설계 근거는 [op-05-report-progress.md](op-05-report-progress.md), 비동기 상태
> 표준은 [async-states.md](../async-states.md)가 갖는다. 여기는 **상황 목록과 실측 결과**다.
>
> **이 문서를 만든 절차는 [screen-hardening.md](../screen-hardening.md)에 있다.**
>
> 실측 — 2026-08-12 · 운영 계정 · 프록시 경유 · 실서버.

## 0. 이 화면의 성격

**앞의 넷과 근본이 다르다 — 이것은 탐색 도구가 아니라 문서다.**

| | OP-01~04 | OP-05 리포트 |
|---|---|---|
| 조회 | 화면 상태가 조회 조건 | **`cohortId` 하나** — 필터·드릴다운 없음 |
| 값 | 지금 값 | **발행 시점에 얼린 스냅샷** |
| 조회 수 | 여럿 | **하나** |
| 쓰기 | 있음 | **없음** — 읽기 전용 |
| 섹션 전환 | URL(탭이 경로에) | **로컬 state** — 딥링크할 일이 없다(정의서 §9) |
| 나가는 것 | 링크 | **인쇄(PDF) · CSV** |

여기서 처음 나오는 축이 셋이다.

1. **발행 전 상태가 정상이다.** 404 `COHORT_REPORT_NOT_FOUND`는 실패가 아니라 「아직」이다
   — `errorCopy`가 그 판정을 갖는다.
2. **확정 전에는 내보낼 수 없다.** `status`가 `IN_PROGRESS`면 값이 더 바뀐다.
3. **인쇄에는 안 보는 섹션까지 들어가야 한다.** 화면은 한 섹션만 보여주지만 PDF는
   문서 전체다 — `keepMounted` + `@media print`가 그것을 한다.

```
useReport(cohortId)  GET /reports/class-diagnosis?cohortId=
                     enabled: !!cohortId
```

## 2. 실측

### 2-0. 진입 타임라인

```
0ms      클릭 — 제목만, 본문은 백지
2250ms   GET /cohorts     200 (2216ms)  → 그제서야 스피너
4350ms   GET /reports/…   200 (2420ms)  → 본문
```

**2.25초 동안 아무 표시도 없었다.** 기수가 정해지기 전에는 `enabled: false`라
`isLoading`이 `false`이고, 그러면 `report.isLoading` 분기를 안 탄다 — OP-03에서
6초 백지를 만든 것과 **같은 뿌리**다(async-states §1-9). 그다음 2.1초는 스피너였다.

CLS 0.0001 — 밀림은 없다. 다만 **아무것도 없다가 한 번에 그려져서** 밀릴 것이 없었다.

### 2-1. 섹션 다섯 — 전부 정상 ✅

| 섹션 | 높이 | 상태 |
|---|---|---|
| 요약 | 426 | 지표 4 + 채점 범위 + 2단 이하 개념 |
| 회차별 | 539 | 회차 6 × 도달 5단 |
| 개념별 도달 분포 | 885 | 개념 7 · 교안순/회차순 전환 |
| 반 · 집단 미달 | 250 | 반별 위험자 + **집단 미달 0건**을 문장으로 |
| 우수 교육생 | 152 | **0명**을 문장으로 — 「아무도 들지 못했습니다」 |

**빈 상태가 둘 다 제대로 말한다** — 「0건」이 아니라 왜 비었는지를 쓴다.
`keepMounted` 확인 — 안 보는 패널도 5개 전부 마운트돼 있다.

### 2-2. 확정 전 잠금 ✅

### 2-1b. 컨트롤 전수 — **9조합 전부 눌러 봤다**

먼저 섹션별로 컨트롤을 세었다. **네 섹션은 컨트롤이 없다**(요약·회차별·반·집단 미달 ·
우수 교육생) — 문서라 읽기만 한다.

| 섹션 | 컨트롤 |
|---|---|
| 개념별 도달 분포 | 정렬 토글 2 + 필터 셀렉트 1 |
| 우수 교육생 | **0개** — 다만 코드에는 셀렉트 둘이 있다. **0명이라 툴바 자체가 안 그려진 것**이라 이번 기수에서는 못 눌렀다 |
| 나머지 셋 | 0개 |

**셀렉트가 정렬 모드에 따라 다른 축이 된다** — 교안순이면 교안 필터, 회차순이면 회차
필터로 바뀌고 라벨도 같이 바뀐다. 조합이 3 + 6 = **9개**다.

| 정렬 | 선택지 | 항목 수 | 검산 |
|---|---|---|---|
| 교안순 | 전체 2종 | 7 | |
| | Spring 백엔드 설계 v1 | 5 | |
| | Spring 테스트와 운영 v1 | 2 | **5 + 2 = 7** ✅ |
| 회차순 | 전체 5회 | 15 | |
| | 1~5차 각각 | 3씩 | **5 × 3 = 15** ✅ |

에러 0건. 필터가 걸리면 그때만 「N종 중 1종만 보고 있습니다 · PDF·CSV에는 전체가
교안순으로 들어갑니다」가 뜬다 — **화면 조작이 배포되는 문서를 바꾸지 않는다는 사실**을
그 자리에서 말한다.

> ⚠ **처음엔 「회차순 전체 15인데 교안별로는 3+3=6」이라고 적을 뻔했다.** 교안순에서 읽은
> 선택지 이름을 회차순에도 그대로 쓴 탓이다 — **모드가 바뀌면 선택지도 다시 세야 한다.**

섹션 왕복 4회에 추가 요청 **0건**(스냅샷이라 캐시가 정확하다). 새로고침하면 첫 섹션으로
돌아간다 — 섹션이 로컬 state라 의도된 동작이다(정의서 §9).

### 2-4. ⚠ 발행 전 기수에서 **응답이 오지 않는다**

기수 4개를 curl로 전수(55초 상한).

| 기수 | 상태 | 결과 |
|---|---|---|
| **10기** | **PLANNED** | **HTTP 000 · 55초 타임아웃** |
| 9기 | RUNNING | 200 · 2.00초 · `IN_PROGRESS` |
| 8기 | CLOSED | 200 · 2.83초 · `CONFIRMED` |
| 7기 | CLOSED | 200 · 2.46초 · `CONFIRMED` |

**18차 R1·R7·R8과 같은 패턴의 네 번째다**(21차 R1로 냈다) — 「보여 줄 데이터가 아직 없는 상태」에서만
매단다. 404 `COHORT_REPORT_NOT_FOUND`를 받으면 `errorCopy`가 「아직」으로 그리게
되어 있는데, **그 404가 오지 않아서** 그 분기에 도달하지 못한다.

지금 화면에서는 재현이 안 된다 — 헤더 기수 스위처가 `RUNNING` 기수 하나만 준다
(`stores/cohortScope`). **새 조직의 첫 기수는 `PLANNED`이므로 그때 걸린다.**

### 4-2. 기수 스위처를 열었다 — **막혀 있던 검증 셋이 한 번에 풀렸다**

세 가지를 못 보고 있었는데 원인이 하나였다: `stores/cohortScope`가 **진행 중 기수 하나만**
골라 주고 스위처에 목록을 안 넘겼다(`ConsoleShell`은 이미 `cohorts`·`onCohortChange`를
받고 있었다 — 화면이 안 넘긴 것이다).

**고른 값은 주소가 갖는다**(`?cohort=`) — async-states §5. 새로고침·뒤로가기가 따라오고
링크 하나가 「8기의 리포트」를 가리킨다. `replace`가 아니라 push다 — 기수를 바꾸는 것은
**다른 것을 보러 가는 것**이라 뒤로가기로 돌아올 수 있어야 한다(검색어 타이핑과 다르다).
주소에 있는 기수가 목록에 없으면 무시한다 — 남의 조직 id를 받아도 그것으로 조회하지 않는다.

기존 반환값은 그대로 두고 `cohorts`·`selectCohort`만 더했다 — 다섯 화면이 이미 쓰고 있다.

| 기수 | 상태 | 결과 |
|---|---|---|
| 10기 | PLANNED | **스켈레톤 + 12초 뒤 안내** — 21차 R1(무응답)를 화면에서 재현 ✅ |
| 9기 | RUNNING | `IN_PROGRESS` · 내보내기 **잠김** |
| 8기 | CLOSED | `CONFIRMED` · 내보내기 **열림** · 우수 교육생 29명 |
| 7기 | CLOSED | 〃 |

#### ✅ 우수 교육생 툴바 — 셀렉트 2개 × 15조합

9기는 0명이라 툴바 자체가 안 그려져서 못 눌렀던 것.

| 셀렉트 | 선택지 | 결과 |
|---|---|---|
| 반 | 전체 8개 + A~H반 | 전체 44행 → 반별 33~35행 |
| 회차 | 전체 6회 + 1~6차 우수 | 전체 34행 → 회차별 31~34행 |

#### ✅ CSV 실제 내려받기

`리포트-8기-2026-03-05.csv` — BOM 있음(엑셀 한글), 표지 4줄 + 섹션별 블록.

#### ⚠ 그래서 새로 잡힌 것 — 표지에 **원시 타임스탬프**

```
2026-03-05T00:00:00Z 미니프로젝트 전체 6회 완료 시점으로 고정
```

`publishedAt`만 ISO 타임스탬프고 `periodStart`·`periodEnd`는 날짜(`2025-09-01`)다 —
**같은 문서 안에서 두 형식이 섞여 있었다.** 시각이 `00:00:00Z`라 뜻도 없다.
`reportDate()`로 날짜만 쓴다 — 표지·CSV 내용·**파일명**이 같이 고쳐졌다.

**9기(진행 중)에서는 안 보였다** — `publishedAt`이 `null`이라 그 분기를 안 탄다.
확정된 기수를 열 방법이 없어서 못 본 것이다.

### 4-3. 표지 문구는 **하드코딩이 아니다**

```tsx
`${reportDate(publishedAt)} 미니프로젝트 전체 ${completedRounds}회 완료 시점으로 고정`
`미니프로젝트 ${completedRounds} / ${totalRounds}회 진행 중 · 아직 확정 전`
```

세 값 전부 서버에서 온다. 고정 문자열은 **「미니프로젝트」 하나**인데, 빅프로젝트가
제품에서 빠져 카테고리가 하나뿐이라 변수로 둘 것이 없다.

**필요한가 — 날짜는 필수, 「전체 N회 완료」는 부분 중복이다.**

| 조각 | 이 줄에만 있나 |
|---|---|
| `2026-03-05` | **그렇다** — 다른 곳엔 없다(CSV에만). 스냅샷 문서라 **언제 얼렸는지**가 없으면 지금 값인지 알 수 없다 |
| `고정` | **그렇다** — 이 문서가 더 안 바뀐다는 유일한 선언 |
| `전체 6회 완료` | 요약 섹션의 `미니프로젝트 6회 · 등록 6회 중`과 겹친다 |

겹치는 조각을 남긴 이유는 **「왜 그 날짜에 얼렸나」를 그 자리에서 답하기 위해서**다 —
빼면 `2026-03-05 시점으로 고정`이 되어 근거가 요약 섹션으로 흩어진다. 그대로 둔다.

### 4-4. 우수 횟수 색이 최상위들을 뭉갰다

`intensity(count, totalRounds)`가 `0.6`·`0.35`에서 끊어서 **6회(1.0)·5회(0.83)·4회(0.67)가
전부 같은 색**이었다. 가장 잘한 사람들이 서로 구분되지 않는다.

**흰 글자를 그대로 두고 흐리게 빼는 것은 안 된다** — 실측 대비:

| 예전 | 대비 |
|---|---|
| `bg-success` | 5.12 ✅ |
| `bg-success/70` | ~3.5 ❌ |
| `bg-success/40` | **1.8** ❌ |

연해지면 **글자색도 같이 바뀌어야 한다.**

| 우수 횟수 | 색 | 흰 글자 대비 |
|---|---|---|
| 우수 횟수 | 배경 | 글자 | 대비 |
|---|---|---|---|
| **6회 (1등)** | `rgb(26,125,82)` **채움** | 흰색 | 5.12 |
| 5회 | `rgb(137,183,156)` | `rgb(24,27,32)` | 7.66 |
| 4회 | `rgb(164,199,178)` | 〃 | 9.36 |
| 3회 | `rgb(190,215,200)` | 〃 | 11.30 |
| 2회 | `rgb(216,231,222)` | 〃 | 13.49 |

**방향을 두 번 뒤집었다.**

| | 결과 |
|---|---|
| ⓐ 바닥 고정 + 위를 어둡게(34%) | 1등이 `rgb(10,69,43)` — **거의 검정**, 초록으로 안 읽힘 |
| ⓑ 같은 방향, 폭만 16%로 | 검지는 않은데 **단계 차이가 안 보임**(띠가 좁다) |
| ⓒ **1등을 기준에 놓고 아래를 연하게** | 지금 |

ⓐ·ⓑ가 좁았던 이유는 **흰 글자를 유지하려 했기 때문**이다 — 바닥색(5.12)보다 밝히면
흰색 8%만 섞어도 4.49로 떨어진다. **이 표에서 중요한 것은 1등**이므로 1등을 기준에
놓고 아래를 빼면 그 제약이 사라진다. 연해진 쪽은 글자를 진하게 바꾼다.

**두 띠가 갈리는 것이 오히려 신호다** — 「채워진 배지 하나」가 곧 최고 기록이라
표를 훑을 때 1등이 먼저 눈에 든다.

**단계 수를 고정하지 않는다** — 그 기수에 실제로 있는 횟수만 줄 세우고 `color-mix`로
섞는다(`bg-success-700` 같은 계단 클래스는 런타임에 만들 수 없다).

#### ⚠ 그 과정에서 잡힌 것 — **눈금이 페이지마다 따로 잡혔다**

`StudentRows`가 **현재 페이지**와 **인쇄용 전체** 두 곳에서 불리는데 각자 눈금을 만들어,
**4회와 2회가 같은 색이고 3회가 4회보다 진했다**(실측). 눈금은 걸러진 명단 전체가
기준이라 부모가 한 번만 만든다 — 반·회차로 걸러도 그 안에서 1등이 가장 진하다.

### 4-5. 두 배치 문제

|---|---|---|
| ✅ | `기수 전체 16%` 라벨이 기준선 **오른쪽**에 서 있었다 — 어느 위치를 가리키는지 눈으로 재야 했다 | `translateX(-50%)`로 선 중앙에 |

### 4-6. ⚠ 서버 정렬을 믿고 있었다 — **두 표 다 알파벳순이었다**

`ClassOps.tsx` 주석에 *"정렬은 나쁜 순(이미 이렇게 정렬된 데이터가 온다)"* 이라고
적혀 있었는데 **실측은 반 이름순**이었다.

| | 서버가 준 순서 | 최악이 몇 번째 |
|---|---|---|
| 반별 위험자 비율 | A 17 · B 17 · C 16 · **D 21** · E 13 · F 17 · G 12 · H 19 | **4번째** |
| 집단 미달 11건 | A → H 알파벳 | **11번째**(H반 88%) |

**주석이 사실이라고 단정한 것을 아무도 안 재 봤다.** 화면에서 정렬한다.

#### 반별 위험자 비율 — 나쁜 순

D 21 · H 19 · B 17 · A 17 · F 17 · C 16 · E 13 · G 12. 비율이 같으면 반 이름순이라
조회마다 순서가 흔들리지 않는다.

#### 집단 미달 — 정렬 컨트롤은 **안 단다**

이 화면은 탐색 도구가 아니라 **문서**다(정의서 §4). 조작이 늘수록 화면과 PDF가 어긋나고
(개념별 분포 토글이 이미 *"PDF·CSV에는 전체가 교안순으로"* 경고를 달고 있다),
11행짜리 표에 정렬 UI는 콘텐츠보다 컨트롤이 커지는 쪽이다.

대신 **한 순서로 두 질문에 답한다.** 이 표에는 다른 질문 둘이 걸려 있다 —
①「어디가 제일 나쁜가」(비율 순) ②「같은 개념이 여러 반에서 반복되나」(개념끼리 붙어야
보인다 · 반복 배지). 비율로만 줄 세우면 ②가 흩어지고 개념으로만 묶으면 ①이 사라진다.

**개념을 그 개념의 최악 비율로 줄 세우고, 개념 안에서 다시 비율 순.**

```
트랜잭션 경계 설정 (최악 88%)   H 88 · E 86 · D 75 · F 74 · B 73 · C 71 · A 68 · G 56
테스트 경계와 대역 설계 (최악 60%) H 60 · E 58 · C 56
```

맨 위가 곧 최악이면서 같은 개념이 붙어 있다. 값 그대로의 순서라 E8(화면이 기준을
정하지 않는다)에 안 걸리고, 등수 숫자도 안 붙인다(E2).

### 4-7. 빈 상태 · 없는 값

| | 무엇 | 어떻게 |
|---|---|---|
| ✅ | **반별 위험자 비율에 데이터가 없으면 테두리만 남은 흰 상자** — `{overall && …}`만 걸려 있었다 | 「없음」(실선) + **사유를 갈라서** 쓴다(기준선 없음 / 반 0개) |

| ✅ | 집단 미달 「회차 · 반」이 **`· H반`** — 구분점만 매달림 | `round`가 빈 문자열로 온다(21차 Q3). 없는 값 자리에 구분자를 안 그린다 |
