# MG-01 · 매니저 대시보드 — 인박스

## 1. 한 줄

**오늘 누구부터 처리할지** 한 목록으로 준다. 지표판이 아니다.

> 매니저 스코프는 25명이다. 이 규모에서 평균·추이는 정보를 거의 주지 않는다 —
> 그럴 바에 명단을 본다. 집계가 값을 하는 것은 개인을 못 보는 오퍼레이터 쪽이다.

## 2. 진입 · 이탈

| | |
|---|---|
| 진입 | 로그인 직후 · 좌측 네비 |
| 이탈 | **행에서 바로 처리**하거나, 행 클릭 → 해당 화면 |

**대시보드를 거쳐 다른 화면에 가서 그 사람을 다시 찾는 동선을 만들지 않는다.**

## 3. 뷰

```
미프 3차 | 제출 23/25 · 응시 19/23 · 리포트 발행 전
                    제출 마감 07-16 18:00 · 응시 창은 개인별 24시간(분석 완료부터)
                                                          ← 한 줄. KPI 카드 아님

할 일  6                      [지난 방문 이후 7/26 14:20 이후] [전체]

 ① 마감이 있는 것

   ⚠ 무효 응시   오세림 C반  미프 3차 · 2문항 무응답   [면담 목록에서 확인]
 ③ 면담 대기
   ✎ 면담       최유나 C반  미프 2차 · 대기 6일             [브리프 열기]
   ✎ 면담       김민준 A반  미프 2차 · 대기 6일             [브리프 열기]
 ④ 미제출
   ▤ 미제출     3팀 4명    미프 3차 · 마감 내일 18:00  [팀 전원에게 독촉]
──────────────────────────────────────────────────────────────────
 ▾ 처리됨 3 · 지난 방문 이후
```

### 띠는 분류만 한다

`지나면 복구가 안 된다` `오늘 못 하면 내일 해도 된다` 같은 이유를 띠에 썼다가 지웠다.
**순서가 이미 우선순위를 말한다** — 이유까지 화면에 쓰면 매번 읽어야 하는 잔소리가 된다.
정렬 근거는 정의서에 남긴다.

### 행마다 회차를 적는다

대시보드에는 **회차 필터가 없다** — 지금 할 일을 모으는 화면이라 **미프 2차 것과 3차
것이 섞인다.**

| 어디서 오나 | |
|---|---|
| **직전 회차 리포트** | 다시 보기 · 면담 (리포트 발행과 함께 통보·판정) |
| **이번 회차** | 미제출 · 미응시 · 무효 응시 |

회차 표기가 없으면 **전부 이번 회차 것으로 읽힌다.**

### 시점이 서로 맞아야 한다

목업을 그리고 나서 시점을 대조하니 어긋나 있었다. `리포트 발행 전`인데 다시 보기와
면담이 있었던 것이다 — **둘 다 리포트 발행 시점에 생긴다**(11절 *"통보는 리포트와 동시"*,
9-2 판정도 그때).

```
미프 3차 제출 마감 07-16 18:00
  = 미프 2차 다시 보기 창 마감      ← 11절: 3일 또는 다음 제출일 중 빠른 쪽
미프 3차 응시   제출한 23명 중 19명 · 개인별 24h 창 진행 중
미프 3차 리포트  마감 후 발행이라 아직 전
면담           미프 2차 판정 기반 · 대기 6일
```

**응시 창에는 회차 공통 마감 시각이 없다.** 10-1이 *"24시간의 기산점은 제출이 아니라
코드 분석 완료"* 라고 정했기 때문이다 — 한 줄에는 **제출 마감**만 시각으로 쓴다.

### 이의제기 행을 만들지 않는다

18번 스케치에 있었지만 **14·16·17번 어디에도 이의 기능이 없다** — 접수 경로(학생 쪽)도
검토 화면도 상태도 정의된 적이 없다. 14번은 *"원문은 이의 조사의 입력"* 이라고만 한다.

**갈 곳 없는 큐를 대시보드에만 두지 않는다.** 기능이 생기면 그때 행 유형을 추가한다.

### 무효 응시는 알리기만 한다

MG-03에 `[무효 확인]` 모달을 이미 만들었다. 대시보드에도 확정 버튼을 두면 **같은 처리가
두 곳**이 된다 — 결과를 지우는 일이라 오탐 비용이 큰데(9-4) 처리 경로가 둘이면 근거를
안 보고 누를 수 있다.

**대시보드는 알리고 MG-03이 처리한다** — `[면담 목록에서 확인]`.

### 면담 행에 위험 유형 배지를 달지 않는다

달면 **MG-03 목록의 축소판**이 된다. 여기는 *"오늘 그중 급한 것"* 만 답하고 전체는
면담 메뉴가 답한다. 남기는 것은 **대기 일수** 하나다.

**정렬 = 마감이 있는 것부터**

| 순위 | | 왜 |
|---|---|---|
| 1 | 창이 닫히기 직전 (응시 D-3h · 재시험 D-1) | **지나면 복구가 안 된다** |
| 2 | 확인해야 판정이 확정되는 것 (무효 응시 · 이의제기) | 방치하면 잘못된 판정이 굳는다 |
| 3 | 면담 대기 (오래된 순) | 오늘 못 하면 내일 해도 된다 |
| 4 | 미제출 | 〃 |

## 4. 데이터

| 읽는다 | 출처 |
|---|---|
| 회차 진행(제출·응시·발행) | 프로젝트 |
| 응시 창 · 재시험 창 잔여 | 세션 일정 |
| 무효 응시 플래그 | 세션 판정(14번 9-4) |
| 위험 유형 · `2단미달 n/3` | 위험 판정(14번 9-2) |
| 면담 상태 · 대기 일수 | 면담 |

**쓰지 않는다.** 처리는 각 행의 액션이 대상 화면에서 한다(독촉 제외).

## 5. 액션

| | |
|---|---|
| `[브리프]` | **MG-04 모드**를 바로 연다 |
| `[독촉]` | 그 자리에서 발송 · 행에 `독촉함 · 방금`. **MG-08 규약 그대로** — 상태별 **고정 문구**, **미제출은 팀 전원 / 미응시는 개인**. 대시보드는 **단건**이라 모달이 없고 여러 명은 MG-08의 벌크 모달이 한다(**한 규약 · 두 진입점**) |
| `[면담 목록에서 확인]` | **MG-03**으로. 확정은 거기서만 |
| 이름 클릭 | **MG-06 교육생 상세** |
| `지난 방문 이후` | 기본값. **기준은 이 화면을 마지막으로 연 시각**이고 필터 옆에 그대로 적는다(`7/26 14:20 이후`). 끄면 전체 |

## 6. 상태

| | |
|---|---|
| 할 일 0 | `지난 방문 이후 새로 생긴 일이 없습니다` + **`전체`로 바꾸면 남은 일을 볼 수 있다**고 밝힌다 — 필터가 켜진 상태의 0을 "일이 없다"로 읽히게 두지 않는다 |
| 회차 없음 | `진행 중인 프로젝트가 없습니다` |
| 부분 실패 | 실패한 줄만 `불러오지 못함 · 다시` — 화면 전체를 비우지 않는다 |
