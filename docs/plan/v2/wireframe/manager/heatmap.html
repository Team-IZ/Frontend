히트맵 — 반이 어디서 무너졌나

이 화면이 답하는 질문은 하나 — 개인 문제인가, 반 문제인가. 만날 사람은 면담 목록이 이미 주므로, 여기서만 알 수 있는 것은 무너진 게 한 사람인지 반 전체인지다.

  • 절반 이상이 2단 이하면 화면이 "반 문제"라고 판정한다(9-6) — 셀 테두리 + 표 아래 한 줄. 매니저가 숫자를 세게 하면 반마다 기준이 달라진다.
  • 프로젝트 select가 이 화면의 변수다. 회차마다 열(검증 개념)이 통째로 바뀌므로 툴바 맨 왼쪽에 둔다.
  • 계층은 담당 반 → 팀 → 개인 3단(14번 12-3). 각 단계마다 선택 필터와 정렬을 둬서 바로 좁힐 수 있게 한다.
  • 셀에는 값만, 라벨은 튀는 셀에만(v1 방식). 전부 달면 라벨이 배경이 되어 아무것도 강조되지 않고, 셀마다 문장을 반복하면 표가 가로로 늘어나 비교가 안 된다.
  • 판정은 표 아래 한 줄. 위에 두면 표보다 먼저 읽혀 표를 볼 이유를 뺏고, 옆에 두면 268px 안에서 문장이 꺾여 빽빽해진다 — 아래면 읽는 순서가 곧 시선 순서다.
  • 판정은 세어지는 것 + 그래서 뭘 하라는 것까지. 23명 중 12명에서 멈추면 매니저가 다시 해석해야 한다 — 개인 사유에서 빠진다 · 반 전체 안내 대상이다까지 말한다. 원인 추정(왜 막혔나)은 데이터가 없으므로 쓰지 않는다.
  • 표 좌상단에 세로·가로가 무엇인지 쓴다. 개념 1·2·3만으로는 그 열의 정체를 알 수 없다.
  • y축 칸 폭 150px 고정. 안 그러면 담당 반과 김민준의 길이 차이로 화면마다 히트맵 위치가 달라진다. 범례·단계 안내도 같은 들여쓰기.
