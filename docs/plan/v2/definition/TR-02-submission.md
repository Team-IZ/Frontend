# TR-02 · 코드 제출

## 1. 한 줄

레포를 내고 **분석이 끝날 때까지의 상태**를 본다.

## 2. 진입 · 이탈

TR-01 카드 → 여기. 제출 후에는 홈으로 돌아가도 상태가 이어진다.

## 3. 뷰

```
← 홈

미프 3차 코드 제출                                마감 7/14 18:00

방식     ● GitHub URL     ○ ZIP 업로드
URL      https://github.com/team-a/miniproject-3
                                                        [제출]
──────────────────────────────────────────────────────────────
분석 상태     제출 → 분석 중 → 완료 / 실패      (진행률 % 없음)
제출한 내용   저장소 · 브랜치 · 최근 커밋
```

**요구사항 충족(P/F)은 이 화면에 없다.** `?` 판정은 매니저가 확인해야 확정되는데,
확정 전 판정을 학생에게 먼저 보여주면 **잘못된 정보를 주는 것**이 된다. → MG-08.

**진행률 막대를 두지 않는다.** 분석에 남은 시간은 알 수 없고, 모르는 값을 퍼센트로
보여주는 것은 거짓말이다. 상태와 **알림 약속**만 준다.

**제출 후에는 홈으로 보낸다.** 세션 시작 버튼은 홈 한 곳에만 둬서 진입점을 하나로 유지한다.

## 4. 데이터

제출 방식·URL·브랜치·커밋 · 분석 진행(대기 → 분석 중 → 완료/실패).

## 5. 액션

제출 · 재제출(세션 시작 전까지) · 실패 시 재시도.

## 6. 상태

| | |
|---|---|
| 커밋 이메일 미검증 | 안내 + 계속 진행 가능 |
| 이미 제출함 | 기존 제출 표시 + `다시 제출` |
| **세션 시작 후** | **재제출 잠금** — 문항이 그 코드로 만들어졌다 |
| 분석 실패 | 사유 + 재시도. 마감이 지났으면 매니저 문의 |

## 7. 안 하는 것

| | 어디에 |
|---|---|
| 이해도 결과 | **TR-04** |
| **요구사항 충족(P/F)** | **MG-08 › 제출 현황** — 확정 전 판정이라 학생에게 안 보인다 |
| 세션 시작 | **TR-01 홈** — 진입점은 하나 |
