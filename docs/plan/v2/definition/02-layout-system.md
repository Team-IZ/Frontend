# 레이아웃 시스템 — 폭 · 층 · 빈 상태 · 격자

> 화면마다 따로 정하다 보니 **같은 것이 다르게** 생겼다. 이 문서는 그 규칙 한 벌이다.
> [01-design-checklist.md](01-design-checklist.md)가 *"무엇을 그리나"* 라면 여기는 *"어떻게 생겼나"* 다.
>
> `⚠ 실제로 어긴 것` 은 v2 작업 중 일어난 일이다.

---

## 1. 좌표계 — 목업은 1920×1080이다

```css
:root{ --screen-w:1920px; --screen-h:1080px; --k:.6625 }  /* --k는 JS가 보이는 폭으로 계산 */
.viewport{ width:var(--screen-w); zoom:var(--k) }          /* 1920으로 그린 뒤 축소 */
.app{ height:var(--screen-h) }                             /* 뷰포트 높이 고정 */
```

**비율이 아니라 좌표계다.** 1232px 프레임에서 그리면 그 안의 384px 폼이 실제보다
1.56배 크게 보인다. **1920으로 그린 뒤 축소**해야 목업의 모든 px이 실제와 1:1이 된다.

> **⚠ 실제로 어긴 것.** `analysis` · `report` · `curriculum` 세 파일이 이 좌표계를 안 써서
> 뷰포트 높이가 **480~1346px로 제각각**이었다. 나머지는 전부 1080이었다.

### flex 아이템은 부모 높이를 안 지킨다

```css
.body{ display:flex; flex:1; min-height:0 }      /* min-height:0 이 없으면 */
.content{ flex:1; min-height:0; overflow:hidden } /* 내용에 밀려 부모 밖으로 자란다 */
```

> **⚠ 실제로 어긴 것.** `min-height:0` 이 없어 `.app` 은 1080인데 `.body` 가 1300으로
> 자랐다. **7개 뷰포트에서 데이터가 잘린 걸 모르고 있었다** — 스크롤도 안 생기니
> 눈으로는 안 보인다.

## 2. 폭 — 2층

**아래 값이 더 좁으면 그것이 이긴다.** 새 화면은 아무것도 안 해도 안전하고, 좁혀야 하는
화면만 예외를 선언한다.

| 층 | 폭 | 적용 |
|---|---|---|
| **1 · 셸 기본** | 하한 **920px** (`--w-min`) ~ 상한 **1280px** (`--w-app`) | 표·목록·대시보드 — 전 콘솔 화면 |
| **2 · 읽기·입력** | 620 / 640 / 720 / 820 / 860 / 920 | 제출 · 세션 · 히트맵 · 브리프 · 리포트 · 학생 홈 |

**1280을 고른 근거** — 1512(맥북 14)에서 본문 가용폭이 `1512 − 184(나브) − 64(패딩) = 1264px`다.
**팀이 실제로 쓰는 화면에서는 이 상한에 닿지 않고**, 1920 이상에서만 걸린다.

### 하한이 필요한 이유 — 상태마다 폭이 달라진다

상한만 있으면 **콘텐츠가 적을 때 블록이 제멋대로 줄어든다.** 같은 화면인데
회차가 4개면 768px, 5개면 878px, 데이터가 없으면 빈 상태가 1280px이 된다.
**화면을 옮겨 다니는 사람에게는 레이아웃이 바뀐 것으로 보인다** — 어디를 보던 중이었는지
매번 다시 찾아야 한다.

**920은 새 숫자가 아니다** — 2층 measure 중 가장 넓은 값이다. 하한을 2층 최댓값에 두면
1층과 2층 사이에 빈 구간이 생기지 않는다.

```css
.trscroll{ width:max-content; min-width:min(100%, var(--w-min)); max-width:100% }
.trtbl   { width:100% }              /* 표가 상자를 채운다 */
.empty   { width:min(100%, var(--w-min)) }   /* 빈 상태도 같은 상자 안 */
```

`min()` 을 쓰는 이유 — 창이 920보다 좁으면 하한이 **가로 스크롤을 만든다.** 그때는
하한을 포기하는 쪽이 맞다.

**2층을 선언한 화면은 예외다.** MG-02 히트맵은 720px를 명시적으로 골랐고, 그 화면 안에서
격자·빈 상태가 **모두 720**이라 일관성은 이미 지켜진다. 위 표의 첫 문장 그대로
**더 좁은 값이 이긴다.**

> **⚠ 실제로 어긴 것.** OP-02는 격자가 694~878px로 뷰마다 달랐고 빈 상태만 1280px이었다.
> → 격자 상자에 하한을 주고 **빈 상태를 같은 상자(`.trwrap`) 안에** 넣어 8개 뷰가 전부
> 920px · 같은 왼쪽 시작점이 됐다.

### 상한은 `.content` 가 아니라 자식에 건다

```css
.content{ background:var(--c-bg) }                       /* 배경은 꽉 채운다 */
.content > *{ max-width:var(--w-app); margin:0 auto }    /* 상한은 자식에 */
```

`.content` 자체를 좁히면 **배경이 같이 좁아져 캔버스와 이음선**이 생긴다.

> **⚠ 하마터면.** 높이를 잡으려고 `.content` 를 `display:flex; flex-direction:column` 으로
> 바꿨더니 **`margin:0 auto` 가 진짜 가운데 정렬로 동작**했다(flex 아이템에서는 auto 마진이
> 실제로 중앙 배치를 한다). MG-06 본문 전체가 가운데로 밀렸다.
> → **`.content` 는 블록으로 둔다.** 안쪽 영역 높이는 `max-height` 로 잡는다.

### 인증·학생 화면은 1층을 쓰지 않는다

인증 3화면은 **full-bleed**(H9), 학생 화면은 **읽기 measure**(620~920px)를 쓴다.
`--w-app` 이 없는 것이 정상이다.

## 3. 층 — 캔버스와 카드

| | 색 | 무엇 |
|---|---|---|
| **캔버스** | `--c-bg` #f4f5f7 | `.content` 배경. 항상 꽉 찬다 |
| **카드** | `--c-surface` #ffffff | 흰 바탕이 **필요한 것**에만 |

### 카드는 기본값이 아니다

| 카드 | 무엇 | 왜 |
|---|---|---|
| ⭕ | **행 구분선으로 읽는 표** | 회색 캔버스에서 1px 선이 안 보인다 |
| ⭕ | 입력 폼 · 모달 | 입력 영역은 바탕이 흰색이어야 한다 |
| ❌ | **자체 색을 가진 격자** — 히트맵 셀 · 분포 막대 · 비교 막대 | 셀이 이미 경계다. 카드를 씌우면 **중첩**이고(H7) 셀 색과 흰색이 두 겹으로 싸운다 |
| ❌ | 텍스트 한 줄 · 각주 | |

**중첩 카드는 항상 틀렸다.** 카드 안의 카드가 필요하면 그건 **구분선이나 여백**으로
풀어야 하는 문제다.

> **⚠ 실제로 어긴 것.** OP-05는 표가 **캔버스 위에 그냥** 놓여 행 구분선이 흐렸다.
> → 표만 `.rcard` 로 감싸고, 그 안의 분포 막대는 카드 없이 폭만 채운다.

## 4. 「없는 것」의 유형 — 3종

**"없다"는 한 가지가 아니다.** 데이터가 아직 안 온 것과, 다 보고 0건인 것과, 못 가져온
것은 **사용자가 할 일이 다르다.** 지금까지는 셋이 전부 같은 흰 박스였다.

우리 `src/components/ui/Empty.tsx` 주석이 이미 그 언어를 정해 뒀다 —
*"점선은 **'지금은 비었지만 채워질 자리'** 라는 뜻으로 **실선(=확정된 면)** 과 구분한다."*

| # | 유형 | 뜻 | 테두리 | 배경 | 액션 |
|---|---|---|---|---|---|
| **1** | **아직** `.wait` | 데이터가 **안 들어왔다** | **점선** | `--c-surface-2` | 없음 — **언제 채워지는지** 쓴다 |
| **2** | **없음**(기본) | 다 봤고 **0건이다** | **실선** | `--c-surface` | 필터면 **해제** · 미설정이면 **만들기** |
| **3** | **실패** `.fail` | **못 가져왔다** | **실선** | `--c-danger-soft` | **다시 시도** |

### 왜 1과 2를 시각으로 갈라야 하나

`면담 대상 0명`(**좋은 소식**)과 `아직 결과가 없어요`(**기다려야 함**)를 헷갈리면
**운영 판단이 틀린다.** 매니저에게 완전히 다른 뜻인데 지금까지 같은 박스였다.

| 유형 1 · 아직 | 유형 2 · 없음 |
|---|---|
| 이 회차는 아직 결과가 없어요 | 이번 회차 면담 대상이 없습니다 |
| 진행 중인 프로젝트가 없습니다(미프 4차 07-29 시작) | 지난 방문 이후 새로 생긴 일이 없습니다 |
| 아직 기록이 없어요 | `"김지"`와 맞는 사람이 없습니다 |
| 마감이 지나면 집계합니다 | 집단 미달 0건 |

### 부분 실패도 빈 상태가 아니다

전체는 있고 **일부만** 실패한 것이라 화면을 비우지 않는다 — **그 줄만** 유형 3 톤으로
표시하고 그 자리에 `다시 시도`를 둔다.

## 4-1. 빈 상태의 자리

> **① 정상 상태와 같은 폭.**
> **② 카드 안에 넣지 않는다 — 카드 자리를 대신한다.**

흰 카드 안에 흰 박스면 **중첩**이다(H7). 표가 있던 자리를 그대로 차지한다.
격자처럼 카드가 없는 화면이면 **캔버스 위 그 자리**를 같은 폭으로 채운다.

> **⚠ 실제로 어긴 것.** MG-02 히트맵은 **465px**인데 같은 자리의 빈 상태는
> **720px 흰 박스**였다. *"결과가 없는 회차가 있는 회차보다 크고 눈에 띄는"* 상태.
> → 히트맵을 `width:100%` 로 채워 **둘 다 720px**, 빈 상태는 유형 1(**점선**)로.

**"없음"만 쓰지 않는다** — **0건이 무엇을 뜻하는지**를 같이 쓴다. 그리고 **섹션을
숨기지 않는다** — 목차에서 사라지면 *"안 봤는지 없었는지"* 구분이 안 된다.

## 5. 격자·표 — 컨테이너 폭을 채운다

```css
.tbl{ width:100%; table-layout:fixed }
```

**열이 `auto` 면 이름 칸이 남는 폭을 다 먹는다.** 결과: 막대 앞이 비고 숫자 칸이 눌린다.

| 열 | 폭 |
|---|---|
| **첫 열**(이름·개념·회차) | **고정** — 264~300px |
| **시각 요소**(분포 막대·히트맵 셀) | **`auto` — 남는 폭을 가져간다** |
| 숫자·배지·액션 | 고정 — [표 열 폭 표준](01-design-checklist.md#표-열-폭-표준) |

**막대가 길수록 분포가 잘 읽힌다** — 남는 폭은 시각 요소에 준다.

> **⚠ 실제로 어긴 것.** OP-05에서 `검증 개념` 열이 `auto` 라 남는 폭을 전부 먹어
> **분포 막대 왼쪽이 비고** `133 / 234명` 이 92px에서 줄바꿈됐다.

## 6. 높이 — 한 뷰포트에 들어간다

**1080 안에 들어가야 한다.** 넘치면 `overflow:hidden` 에 잘려 **데이터가 소리 없이 사라진다.**

### 스크롤과 페이징을 같이 쓰지 않는다

| 내용 | 방식 |
|---|---|
| **개수가 정해진 것**(대시보드 섹션·요약 카드) | **간격을 줄여 맞춘다** |
| **페이징이 있는 목록** | **한 쪽이 뷰포트에 들어가는 행 수**로 자른다 |
| **진짜 길어지는 목록**(타임라인·팀 목록·섹션 목록) | 그 **영역만** `max-height` + `overflow-y:auto` |

> **⚠ 실제로 어긴 것.** OP-05 우수 명단을 20행/쪽으로 두니 **스크롤도 하고 페이징도**
> 해야 했다. → **13행/쪽**(41명 · 4쪽)으로 잘라 한 쪽이 한 뷰포트에 들어간다.

**목록 영역에 내부 스크롤을 줄 때도 `.content` 는 블록으로 둔다** — flex로 바꾸면 2절의
가운데 정렬 문제가 생긴다.

## 7. 색 — 눈금이 있는 것만

| | 눈금 | 램프 |
|---|---|---|
| **도달 단계 1~4단** | **기획에 정의됨** | `#df6150` → `#ec9a5c` → `#ecc95e` → `#a9cf8e` → `#57b083` |
| **위험자 비율** | **없음** | 값에 칠하지 않는다 — **기준선 대비 부호**(좋음/같음/나쁨)만 |
| 값이 없음 | | 해치 무늬 `repeating-linear-gradient(45deg, #eceef1, #e2e5ea)` |

**경계를 만들지 않는다** — `N% 이상이면 위험` 의 근거가 기획에 없으면 색으로도 쓰지 않는다.
자세한 것은 [OP-02 정의서 `셀 색 — 네 번 바꿨다`](OP-02-analysis.md).

**MG-02와 램프가 같아야 한다** — 오퍼레이터와 매니저가 **같은 회차를 두고 이야기**한다.
한쪽 화면의 붉은색이 다른 뜻이면 말이 안 통한다.

## 8. 각주 — 브라우저 크롬 밖

와이어프레임 설명은 **리뷰어용 메모**이지 실제 UI 카피가 아니다.

```
.rpage
  .sec-label      뷰포트 이름
  .viewport       ← 브라우저 크롬. 여기 안은 전부 실제 화면
  .note2          ← 설명은 여기
```

**목업만 보고 만들 수 있어야 한다** — 크롬 안에 기획 조항 번호(`9-2` · `14-1` · `F3`)나
설계 근거가 있으면 그것도 화면에 나가는 글로 읽힌다.

## 점검 — 화면 하나를 끝내기 전

| # | |
|---|---|
| 1 | 모든 뷰포트의 `.app` 이 **1080**인가? |
| 2 | `.content` 넘침이 **0**인가? (`scrollHeight − clientHeight`) |
| 3 | `.content` 가 **블록**인가? (flex면 가운데 정렬이 된다) |
| 4 | `.content > *` 에 **폭 상한**이 걸려 있는가? |
| 5 | 한 화면의 **모든 뷰**에서 본문 블록 폭이 **같은가?** 하한 **920** 아래로 내려가지 않는가? (2층 선언 화면은 그 값) |
| 6 | 빈 상태가 정상 상태와 **같은 폭**이고 **카드 안에 있지 않은**가? |
| 7 | 빈 상태가 **3종 중 어느 것**인지 정해져 있는가? (`아직`=점선 / `없음`=실선 / `실패`=danger) |
| 8 | 표가 `width:100%` + `table-layout:fixed` 인가? |
| 9 | 남는 폭을 **시각 요소**가 가져가는가? |
| 10 | **스크롤과 페이징을 같이** 쓰고 있지 않은가? |
| 11 | 각주가 **크롬 밖**에 있는가? |

### 기계로 훑는 법

```js
// 모든 뷰포트: 높이 고정 · 넘침 · 가운데 정렬 사고
document.querySelectorAll('.rpage').forEach(p => {
  p.classList.add('on');
  const app = p.querySelector('.app'), c = p.querySelector('.content');
  console.log(p.id, {
    높이: app.offsetHeight,                       // 1080 이어야
    넘침: c.scrollHeight - c.clientHeight,        // 0 이어야
    flex: getComputedStyle(c).display,            // block 이어야
  });
  p.classList.remove('on');
});

// 한 화면 안에서 본문 폭이 널뛰는가 — 값이 여러 개면 어긋난 것이다
const 폭 = new Set();
document.querySelectorAll('.rpage').forEach(p => {
  p.classList.add('on');
  const b = p.querySelector('.trscroll, .hmwrap, .rcard, .empty');
  if (b) 폭.add(Math.round(b.getBoundingClientRect().width / 0.6625));
  p.classList.remove('on');
});
console.log([...폭]);          // 값 하나여야 · 920 이상이어야(2층 선언 화면은 그 값)

// 빈 상태 3종이 제대로 갈렸는가
document.querySelectorAll('.rpage').forEach(p => p.classList.add('on'));
document.querySelectorAll('[class*="empty"]').forEach(e => {
  const cs = getComputedStyle(e);
  console.log(e.className, cs.borderTopStyle, cs.backgroundColor);
  // 아직 → dashed + surface-2 · 없음 → solid + 흰색 · 실패 → solid + danger-soft
});
```

**iframe으로 22개를 한 번에 돌린다** — 파일마다 열어 보면 빠뜨린다.
