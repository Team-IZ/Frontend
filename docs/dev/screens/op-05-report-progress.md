## 2. 파일 구조와 그 이유

```
features/operator/report/
├─ ReportScreen.tsx / .route.tsx
└─ _/
   ├─ api/{types,api,mockDb}.ts   admin과 같은 _/api 구조
   ├─ sections.ts                 섹션 제목·질문·순서 — 화면·인쇄·CSV가 같이 읽는 단일 원천
   ├─ labels.ts                   도달 단계 라벨·색, 리포트 전체 CSV 생성
   ├─ rules.ts                    페이지 크기 등 화면 전용 상수(⚠ 기획에 없음 명시)
   ├─ cohortScope.ts              COHORT_ID 상수
   ├─ useAsync.ts                 projects/useAsync.ts와 동형(도메인 경계상 복제)
   └─ components/
      ├─ AsyncState.tsx           Loading·LoadFailed
      ├─ ReportHead.tsx           표지줄(발행 시점 고정 문구 + PDF·CSV 액션)
      ├─ SectionHeading.tsx       섹션 제목 + 그 섹션이 답하는 질문
      ├─ ReportToolbar.tsx        섹션 안 컨트롤 줄 + ToolbarSelect
      ├─ DistributionBar.tsx      도달 단계 분포 막대 + 범례(개념별·회차별 공유)
      ├─ DiagnosisSummary.tsx     ① 요약
      ├─ RoundBreakdown.tsx       ② 회차별
      ├─ ConceptDistribution.tsx  ③ 개념별 도달 분포(본체)
      ├─ ClassOps.tsx             ④ 반별 위험자 비율 + 집단 미달
      └─ TopStudents.tsx          ⑤ 우수 교육생 표 + 페이지네이션 + CSV
```

**섹션 다섯은 나열이 아니라 순서다** — 넓은 단위에서 좁은 단위로:
`요약(전체) → 회차별(시간) → 개념별(내용) → 반·집단(집단) → 우수 교육생(개인)`.
처음엔 개념별이 회차별보다 앞이었는데(개념별이 "본체"라서) 읽는 순서로는 거꾸로였다 —
*"3차가 어려웠다"*(회차별)가 질문을 만들고 *"그 회차의 이 개념들 때문"*(개념별)이 답이
된다. 순서만 바꾸면 의도가 안 보이므로 **각 섹션이 앞 섹션이 남긴 물음을 받아 적는다**
(`sections.ts`의 `question`). 그 문장을 CSV 블록 제목도 그대로 쓴다.

**섹션 전환은 상단 가로 탭**(공용 `Tabs`, OP-06과 같은 모양)이고 URL이 아니라 **로컬
state**다 — 정의서 §4가 "나가는 링크가 없다"고 못박아서 딥링크할 화면이 없다. 좌측 세로
목차를 쓰다가 바꿨다: 목차가 196px를 상시 차지해 본체(개념별 표)가 그만큼 좁아졌는데,
이 문서에서 폭이 필요한 건 표지 다섯 줄짜리 목차가 아니다.

**탭이 없어지면서 `GrowthFlow.tsx`(미프→빅프 이동표 컴포넌트)를 파일째 삭제했다** —
빅프가 없으니 "이후" 상태가 없어 성장 지표 자체가 성립하지 않는다. `TopStudents.tsx`의
"빅프 최저 도달" 열도 같이 삭제했다(그 열만 없어지고 나머지 우수 판정 로직은 그대로).

## 3. 목 데이터 — 왜 이렇게 지었나

OP-05는 발행 시점 스냅샷이라 자체 데이터를 새로 지어야 하는데,
`mock-first-screens.md` §2-4가 "같은 회차는 화면마다 같은 값을 써야 한다"고 못박았다.

`features/operator/projects/mockDb.ts`(OP-03/04)의 "7기"를 보면 **미프 1·2차만 `DONE`**,
3차 `RUNNING`, 4차 `READY`, 5·6차 `PREP`다 — 등록된 회차는 6개뿐이고 전부 끝난 게
아니다. 그런데 리포트가 "본체"(개념별 도달 분포 확정)를 보여주려면 6차까지 발행된
**미래 시점**을 가정해야 한다.

**택한 방법:**
- 회차 수를 미래에 등록될 **6개**로 맞췄다.
- 개념 **이름**은 `projects/mockDb.ts` 카탈로그(AI_LLMOps·Kubernetes 기초·Streamlit
  실습)에서만 골랐다 — 새 이름을 짓지 않았다.
- 5·6차의 개념 **배정**은 `projects/mockDb.ts`에 아직 없는 정보라 이 파일이 처음
  만들었다(`_/api/mockDb.ts` 머리 주석에 명시). projects 쪽 회차가 실제로 6차까지
  끝나면 그 값으로 맞바꾼다.
- 도메인 경계상 런타임 참조는 못 해서 **값만 손으로 옮겼다** — 연동되면 이 문제
  자체가 사라진다(둘 다 서버가 준다).

**시나리오 스위치** — `REPORT_SCENARIO` 상수(`'IN_PROGRESS' | 'CONFIRMED'`)로 케이스
표를 갈아끼운다. 원래 `DIAGNOSIS_SCENARIO`·`OUTCOME_SCENARIO` 두 개였는데 탭이
하나로 합쳐지며 스위치도 하나로 줄었다. 실제 서버는 상태 하나만 내려주므로 연동 시
이 상수와 분기를 통째로 지운다(파일 머리에 표시).

**우수 교육생·반별 위험자·집단 미달은 `REPORT_SCENARIO === 'CONFIRMED'`에서만 채운다** —
이 셋의 목 데이터가 6회차 전부 끝났다는 전제로 지어져 있어서, `IN_PROGRESS`에서
그대로 보여주면 아직 없는 회차의 결과를 미리 보여주는 꼴이 된다.

## 5. 렌더 검증 — 완료

1920×1080·1512×982 두 폭에서 전 섹션 확인(오버플로 0). 인쇄는 **A4 실폭(794px)** 으로
뷰포트를 줄이고 `emulateMedia({media:'print'})`로 확인했다 — 다섯 섹션 전량 출력, 가로
넘침 0, 교안 필터를 걸어 놓아도 인쇄본은 교안 3종 전체, 우수 교육생 명단은 반 필터를
걸어 화면이 2명일 때도 인쇄 표는 24행. CSV는 실제로 내려받아 블록 순서·단위를 봤다.

**인쇄에서 두 번 조용히 틀렸던 자리** — 둘 다 화면만 보면 안 보인다.
1. `print-color-adjust: exact`가 레포에 아예 없었다. 없으면 분포 막대·위험 막대·배지가
   전부 무채색으로 찍힌다.
2. Base UI `keepMounted` 패널의 `hidden` 속성을 Tailwind preflight가
   `display:none !important`로 잠근다. `!important`는 **캐스케이드 레이어 우선순위가
   뒤집혀**(앞 레이어가 이기고, 레이어 밖이 가장 약하다) 레이어 밖 `@media print`로는
   못 푼다 — `@layer base` 안에 넣어야 한다. 안 그러면 **활성 섹션 하나만 인쇄된다.**

## 6. 남은 것 · 백엔드와 합의할 것

1. **회차별 도달 분포가 계약에 없다.** `ConceptDiagnosis.distribution`은 개념당 하나뿐
   (전 회차 합산)이라, 개념별 섹션을 **회차순**으로 볼 때 여러 회차에 쓰인 개념은 어느
   회차 아래에서든 같은 값을 보여준다 — 그 회차만의 성적이 아니다. 지금은 화면이 그
   사실을 문장으로 밝혀 두었고, 진짜 회차별 분해가 필요하면 계약에 회차별 분포가 생겨야
   한다. **PR에서 물어볼 1순위.**
2. **도달 단계가 4단인지 5단인지** — 토큰은 5단계(`reach-0`~`reach-4`)인데 OP-05 목업
   범례는 4단계만 쓴다. 목업을 따랐다. MG-02·OP-02가 실붙으면 실측 대조 필요.
3. 목 데이터의 5·6차 개념 배정은 `projects/mockDb.ts`에 아직 없어서 이 파일이 처음
   지었다. projects 쪽 회차가 실제로 6차까지 끝나면 그 값으로 맞바꾼다.
