# MG-04 면담 브리프 — 상황 전수

> **절차는 [screen-hardening.md](../screen-hardening.md).** 설계 판단은
> [mg-04-brief.md](mg-04-brief.md)에 있고, 여기는 **값이 오기 전·안 올 때·이상하게
> 올 때** 화면이 무엇을 하는가다.
>
> 공통 축(헤더·스코프·기수 이름)은 [mg-03-situations.md](mg-03-situations.md)에서
> 한 번 쟀다 — 여기서 다시 재지 않고 **이 화면 고유의 것**만 본다.
>
> 매니저 4화면 중 **쓰기가 가장 무겁다** — 브리프 생성(AI)과 저장(종결)이 있고,
> 저장은 케이스 상태를 `DONE`으로 바꾼다.

---

## 1. 조회 흐름

```
목록(MG-03) ── ?state={briefState} ──▶ 브리프

briefState가 NONE·FAILED  →  조회하지 않는다. [브리프 만들기]를 그린다
                              POST /interviews/{caseId}/brief   (AI 생성)
그 밖                      →  GET  /interviews/{caseId}/brief

저장                          PUT  /interviews/{caseId}/brief
                              → interventionKeys.all 무효화 · navigate(-1)
```

**`?state=`를 목록이 넘겨준다.** 없는 브리프를 `GET`하면 서버가 404를 내는데 **그 404가
지금 무응답**이라(30차 R1) 화면이 90초를 기다렸다 실패로 떨어진다 — 실측했다.
주소로 바로 들어오면 `state`가 없고, 그때는 **있다고 보고 조회한다**(흔한 경우이고,
없으면 실패 화면에서 [브리프 만들기]로 이어진다).

> ⚠ **이 화면은 입구가 둘이다** — 면담 목록(MG-03)과 대시보드(MG-01). 나가는 길·저장
> 완료가 전부 `navigate(-1)`인 이유이고, **캐시가 있는 경로**라 하드닝 §5가 경고한
> 사고가 나는 자리다(OP-04 크래시가 정확히 그 모양이었다).

## 2. 축

```
A. 진입 경로
  A1 목록에서 클릭(?state 있음)      A2 주소로 직접(?state 없음)
  A3 대시보드에서                    A4 뒤로가기로 되돌아옴

B. briefState
  B1 NONE(생성 전)      B2 FAILED(생성 실패)
  B3 DRAFT              B4 CONFIRMED(종결 후 재오픈)

C. 브리프 내용
  C1 일반(isVoid=false)              C2 무효 응시(isVoid=true)
  C3 firstInterview=true             C4 priorInterview 있음/없음
  C5 concepts=[] (서버 미구현)        C6 items가 4개/8개
  C7 openingRemark=null (FAILED)

D. 저장
  D1 원인 0건 저장          D2 원인 여럿          D3 추후 계획 빈 값(확인 모달)
  D4 저장 실패              D5 저장 중 이탈       D6 종결 후 재저장

E. 생성
  E1 생성 성공(AI)   E2 생성 실패   E3 생성 중 이탈   E4 연타

F. 값의 빈 구석
  F1 openingRemark null    F2 items []    F3 concepts []
  F4 savedRecord null      F5 priorInterview.nextAction null
```

**조합 수** — 4 × 4 × 7 × 6 × 4 × 5 = **13,440**. 2단계에서 갈리는 지점만 추린다.

## 3. 공통 축 (MG-03에서 잰 것은 참조만)

| | 이 화면 고유로 무엇을 묻나 |
|---|---|
| 네트워크·인프라 | **AI 생성 지연**(몇 초인지 미측정) · 생성 중 이탈 · 404 무응답 |
| 인증·세션 | 저장 직전 토큰 만료 — **적은 내용이 날아가나** |
| 시간·타이밍 | `nextActionConfirmedAt` 표시 · 종결 후 재오픈 시각 |
| 사용자 조작 | **원인 칩 토글** · 긴 서술 입력 · 저장 연타 · 취소 · 뒤로가기 |

## 4. 실측 · 판정 · 고침

### 4-1. ✅ 종결 후 다시 열면 **저장한 값이 안 보였다** (플로우 관찰 · 캐시)

저장 → 목록 복귀 → **다시 눌러서** 열었더니 입력칸이 전부 비어 있었다.

```
목록      08.16 면담 · 다음에 할 것 — "하드닝 저장 실패 테스트"   ← 맞다
브리프    상세 사유 ""  ·  추후 계획 ""  ·  고른 원인 []          ← 비었다
저장 버튼 「저장」                                                ← savedRecord가 있다는 뜻
```

**버튼과 입력칸이 서로 다른 데이터를 보고 있었다.**

**원인은 캐시다.** 저장이 `interventionKeys.all`을 무효화하면 캐시는 stale이 되지만
**데이터는 남아 있어**, 다시 열 때 옛 응답(`savedRecord: null`)이 즉시 반환된다.
`BriefSheet`가 그것으로 마운트되며 `useState` 초기값이 빈 값으로 굳고, 새 응답이
도착해도 초기값은 다시 잡히지 않는다.

**고침 — `key={JSON.stringify(brief.data.savedRecord)}`.** 저장된 값이 바뀌면
리마운트해 초기값을 다시 잡는다. 타이핑 중에는 `savedRecord`가 안 바뀌므로 입력이
날아가지 않는다.

> ⚠ **주소로 들어가면 안 나온다** — 캐시가 없어 처음부터 새 응답으로 마운트된다.
> 하드닝 §5가 「주소로 가지 말고 눌러서」라고 한 그 사고이고, OP-04 크래시와 같은
> 모양이다.

### 4-2. 🔴 `briefState: NONE`인 브리프를 `GET`하면 **60초 무응답**

```
GET /interviews/{NONE인 caseId}/brief    →  무응답 · 60002ms
GET /interviews/{FAILED}/brief           →  200 · 3067ms
GET /interviews/{CONFIRMED}/brief        →  200 · 1843ms
```

서버는 404를 내는데 **그 404가 앞단에서 삼켜진다**(29·30·32차 R1). 연동할 때
`?state=`로 우회한 것이 **추측이 아니라 실측으로 맞았다.**

**화면 실측** — 목록에서 [브리프 생성]을 누르면 **100ms에** 「아직 브리프가
없습니다」가 뜬다(조회를 아예 안 부른다).

### 4-3. AI 생성이 **24초** 걸린다

```
[150ms]    잠김=true  「만드는 중…」
[24001ms]  잠김=false  여는 말 + 질문 8개
```

그동안 화면은 **버튼 문구와 잠금뿐**이다. 진행 표시가 없어 24초는 길다 — 다만
서버가 AI를 부르는 시간이라 화면이 줄일 수는 없다.

> 스펙도 「AI 생성, 수 초 대기」라고만 적혀 있다. **수 초가 아니라 24초다.**

### 4-4. 🔴 질문 근거에 **내부 UUID가 노출된다**

```
문제 1 L3 인터뷰 (interviewSourceId 7d017b49-1095-49dd-a8c7-c8d135eb78ab) 기반 Q&A 질문
문제 2 L3 인터뷰 (interviewSourceId 9423d689-10ad-424e-ab4c-6ae688319c06) 기반 Q&A 질문
PERSISTENT_LOW 위험 사유에 기반한 확인 질문
```

`questionRationale`은 스펙상 **「매니저만 보는 근거」** 인데, UUID와 코드가 그대로
들어 있다. 매니저에게 아무 뜻이 없는 값이다.

**화면이 정규식으로 벗기지 않는다** — 서버가 만든 문장이라 구조가 바뀌면 깨지고,
어디까지가 개발자용인지 화면이 판정하게 된다. → §5

### 4-5. ✅ 빈 상세 사유가 `(기록 없음)`이라는 **글자로 입력칸에 들어왔다**

저장하고 다시 열어 보고 나왔다. 빈 문자열로 보냈는데 서버가 문구로 바꿔 저장한다.

```jsonc
보낸 것    { "why": "", … }
받은 것    { "why": "(기록 없음)", … }
```

입력칸에 **자리표시자가 아니라 실제 텍스트**로 들어 있어(실측 `value === "(기록 없음)"`),
매니저가 이어서 쓰려면 그 글자를 **먼저 지워야 한다.** 안 지우고 저장하면 「안 쓴 것」이
「그렇게 쓴 것」으로 굳는다.

**고침 — 어댑터에서 그 문구를 빈 값으로 되돌린다**(`emptyIfPlaceholder`). 스펙이
`why`를 「매니저가 타이핑한 서술」이라고 하므로 이 값은 사용자 입력이 아니다.
서버가 그대로 저장하게 바뀌면 그 줄만 지운다. → §5

> `nextAction`은 치환이 없었다 — 같은 요청에서 보낸 값이 그대로 왔다.

### 4-6. ✅ 정상으로 확인된 것

| 축 | 결과 |
|---|---|
| **생성 쓰기** | 24초 후 여는 말·질문 8개. 그동안 버튼 잠김 |
| **저장 쓰기** | 목록 복귀(4초) · 개수 갱신(예정 9→8, 종결 2→3) · 무효화 동작 |
| 저장 실패(500) | 「적으신 내용은 그대로 남아 있습니다」 + 입력 유지 + 다시 저장 |
| 추후 계획 빈 값 | 확인 모달 · 「돌아가서 적기」로 저장 안 하고 닫힘 |
| 원인 칩 7종 | 토글 · `aria-pressed` 반영 · 전부 해제하면 「원인을 고르면…」 복귀 |
| `CONFIRMED` + `savedRecord: null` | **정상** — 앞은 AI 생성 확정, 뒤는 매니저 입력. 다른 축이다 |
| `FAILED` 브리프 | `openingRemark: null` · `items: []` → 전용 화면(다시 만들기) |

## 6. 미검증

```
데이터      isVoid=true(무효 응시) 브리프가 시드에 없다 — 여는 말·질문이 통째로 다른 경로
가로채기    생성 실패(POST 500) — 저장 실패만 봤다
컨트롤      취소 버튼 · 뒤로가기(적은 것이 날아가는지) · 긴 서술 입력
접근성      모달 포커스 트랩 · 키보드로 칩 토글 · 스크린 리더
성능        질문 8개일 때 세로 길이 · 인쇄
```

> **✅ 이번에 채운 것** — 쓰기 2건(AI 생성 24초 · 저장) 실행 · 플로우 왕복(목록 →
> 브리프 → 저장 → 재오픈)에서 **캐시 사고 1건 + 서버 문구 유입 1건** · 저장 실패
