## 1. 🚨 R1 — **저희가 틀렸습니다.** 404만 안 옵니다

25차 §4에서 저희는 이렇게 적었습니다.

> *"프록시는 기수가 있는지 모른다 — URL 모양이 같다. 그리고 형식 400은 1초에 오므로
> 앱이 살아 있다. **따라서 프록시 층이 아니다.**"*

**두 관찰은 맞았지만 결론이 틀렸습니다.** 회신에서 지적해 주신 대로, 그 근거가 배제하는
것은 *「앞단이 요청 URL을 보고 가르는 경우」* 뿐입니다. **앞단이 응답 상태 코드를 보고**
처리를 달리하면 URL이 같아도 갈립니다.

### 짚어 주신 요청을 그대로 보냈습니다

```
GET /api/v0/definitely-not-a-real-path   →  무응답        ← 앱은 404를 냅니다
GET /api/v0/zzz-no-such-route            →  무응답        ← 같은 모양

── 대조군 (같은 시각 · 같은 토큰) ──
GET /api/v0/cohorts/not-a-uuid/projects  →  400 · 즉답
DELETE /api/v0/cohorts                   →  405 · 즉답
GET /api/v0/members/me                   →  200 · 즉답
```

**이 경로들은 DB를 한 번도 건드리지 않습니다.** 기수도 반도 교안도 조회하지 않습니다.
그런데 무응답이고, 같은 시각 400·405·200은 즉시 옵니다.

저희 25차 가설이 이것으로 전부 무너집니다.

| 25차에 적은 것 | 이번 측정 |
|---|---|
| "DB 조회까지 가서 「없음」이 확정되는 경로만 멈춘다" | ❌ **DB를 안 가는 404도 멈춥니다** |
| "예외를 던지기 전에 앱이 뭔가를 더 한다" | ❌ 할 것이 없는 경로도 멈춥니다 |
| — | ✅ **404라는 상태 자체가 조건입니다** |

### 부탁 — 앞단의 404 처리를 봐 주세요

이제 남은 곳은 **Lambda 프록시 / App Runner 설정**입니다. 백엔드 팀 저장소에는 그 코드가
없다고 하셨고, 저희도 접근 권한이 없습니다.

wake/sleep 프록시가 원본의 404를 「아직 라우트가 안 떴다」로 읽고 원본이 올라오기를
기다리는 구조라면 지금 증상과 정확히 같습니다.

**확인은 위 요청 하나면 됩니다** — 인증 토큰만 있으면 되고 DB도 안 탑니다.

```
GET /api/v0/definitely-not-a-real-path
```

이것이 404로 돌아오는 순간 25차 R4·R8이 같이 풀립니다. 저희 화면은 **404를 「아직」으로
그릴 준비가 이미 돼 있습니다**(18차부터 그 요청을 드려 왔습니다).

> 회신에서 넣어 주신 `NotFoundResponseTest` 3케이스는 **앱이 완결된 404를 만든다**는 것을
> 저희 쪽에서도 근거로 씁니다 — 앱 안에서 갈라지지 않는다는 것이 이 테스트로 고정됩니다.

## 2. 🟡 R2 — 반 이름에 「반」이 없는 행이 있습니다

9기 반 목록입니다.

```
1반 · 2 · 3 · 35반 · A반 · B반 · C반 · D반 · E반 · F반 · G반 · H반
```

**`2`와 `3`만 「반」이 없습니다.** 저희가 화면에서 이름을 만들 때 접미사를 붙이는데
(입력은 `A`, 저장은 `A반`), 그 규칙을 넣기 전에 만들어진 행으로 보입니다.

화면은 저장된 값을 그대로 그리므로 **목록에서 그 둘만 다른 모양**입니다. 지우거나
이름을 고쳐 주시면 좋겠습니다 — 저희가 `PATCH`로 고칠 수도 있지만, 시험 삼아 만든
것이면 지우는 편이 맞을 것 같아 여쭙니다.

> `35반`은 정상 형식이라 그대로 두었습니다.

### R7 — 저희 우회를 걷어냈습니다

이동이 안 되던 동안 화면이 **되돌리기를 먼저 부르고 배정을 이어 붙였습니다.** 지금은
배정 한 번으로 끝나서 그 두 단계를 지웠습니다(요청 2건 → 1건). *"사이에서 실패하면 그
사람들이 미배정으로 남는다"* 는 위험도 같이 사라졌습니다.

원인이 **DB CHECK에 없는 해제 사유 값**이었다는 설명이 저희 실측과 정확히 맞물립니다 —
`rollback`을 먼저 부르면 통과했던 것이 그 값(`IMMEDIATE_ROLLBACK`)을 쓰기 때문이었군요.

### Q1 — CSV는 「나」로 해 주셔서 저희가 할 일이 없어졌습니다

CP949·열 순서를 서버가 받아 주시면 **프런트 정규화(「가」)는 안 합니다.** 다만 화면이
지금은 **서버의 옛 규칙(`이름,이메일` 2열·UTF-8)을 그대로 지키고** 있어서, 넓어진 규칙을
화면이 먼저 막고 있습니다 — 배포되면 저희도 그 검사를 풀겠습니다.

**한 가지만 확인 부탁드립니다** — `.xlsx`도 받으시나요? Q1의 「다」는 답이 없어서요.
안 받으시면 화면이 「엑셀은 CSV로 저장해 주세요」라고 안내하겠습니다.

### Q2 — 팀 API는 저희가 안 건드립니다

전부 매니저 화면 것이라고 하셔서 오퍼레이터 쪽에서는 쓰지 않겠습니다.
`trainees/registrations/{batchRequestId}`가 저희 것이라는 답도 잘 받았습니다 — 등록
진행률 표시는 그 조회로 붙이겠습니다(지금은 동기 응답으로 충분해서 미룹니다).
