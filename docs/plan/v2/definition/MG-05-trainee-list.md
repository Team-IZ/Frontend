### 열 이름에 회차를 쓰지 않는다

회차는 **select에 이미 있다.** 열 이름은 **셀 3개가 무엇인지**를 말해야 한다 —
`개념 3건 도달`. 어느 개념인지는 히트맵의 같은 순서와 맞는다.

### 열이 두 종류로 갈린다

| | |
|---|---|
| **선택한 회차 값** | 개념 3건 도달 · 2단 이하 · 이번 회차 배지 |
| **회차를 걸친 값** | 우수 누적 |

**회차 select가 이 화면의 변수**다(히트맵과 같은 규약, 맨 왼쪽). 없으면 지난 회차를
볼 수 없다.

### 우수 누적은 회차 번호로 쓴다 — 개념이 아니다

한때 `우수 3회 · HITL Trigger · State 관리`라고 썼다가 고쳤다. **"개념에서 우수"라는
판정은 존재하지 않는다.**

> 9-3 — *"정렬 상위 1~2명. **3문제 중 최저값으로 비교한다.**"*

**3개를 다 잘해야 우수**이므로 특정 개념에 귀속시킬 수 없다. 히트맵 개념 이름을 가져다
붙인 것이 오류였다.

```
우수 3회 · 1·2·3차     ← 꾸준한 사람
우수 1회 · 5차          ← 한 번 튄 사람
우수 4회 · 1·2·5·7차
```

**회차 번호만 나열하니 미프가 8회여도 한 줄에 들어간다.** 팀 구성에 쓰는 정보는
**몇 번 · 언제**이고, 9-3의 근거(`4단 도달 · 힌트 0회`)는 MG-06에서 본다.

### 위험과 우수를 같이 본다

한때 위험 배지를 빼고 우수만 뒀다가 되돌렸다. 근거가 *"면담 목록과 모집단이 같다"*
였는데, **모집단이 같아도 용도가 다르다.**

| | |
|---|---|
| **MG-03 면담** | 이번 회차 위험자를 **처리**한다 · `[브리프 열기]` |
| **MG-05 명부** | 팀을 짤 때 **어디에 배치할지** 본다 · 브리프 버튼 없음 |

팀을 짜려면 *"누가 우수인가"* 만이 아니라 *"위험인 사람을 어디에 배치할까"* 도 필요하다
— **한쪽만 보여주면 팀 구성 판단이 반쪽**이 된다. 18번 3-4도 `위험 / 우수 배지`로 적었다.

**우수이면서 이번 회차에 위험일 수 있다.** 최유나가 그 경우다 — 누적과 이번 회차는
다른 값이라 열을 나눈다.

### 응시 상태 3종(14-1)

| | |
|---|---|
| **미응시** | 안 들어옴 |
| **무효 응시** | 들어왔지만 무성의(9-4) |
| **중단** | 하다가 나감 |

셋은 **원인도 처방도 다르다.** 하나로 묶으면 응시 창을 놓친 사람과 무성의하게 낸
사람이 같아 보인다.

## 4. v1과 목적이 바뀌었다

v1 SC-M11은 **4컬럼(이름·이메일·반·계정)** 뿐이었고, 측정 정보를 뺀 근거가 셋이었다.

| v1의 근거 | v2에서 |
|---|---|
| *"위험 우선순위는 대시보드 전담 · 역할 중복 방지"* | **여전히 맞다** — 위험 배지를 달지 않는다 |
| *"회차·제출 현황은 프로젝트 워크스페이스 소관"* | **여전히 맞다** — 제출 현황은 MG-08 |
| *"찾아서 상세로 가는 통로"* | **성립하지 않는다** |

**세 번째가 무너진 이유는 상세가 바뀌었기 때문이다.** v1 상세는 7컴포넌트 스택 + 3탭이라
명부가 그 입구로서 값을 했다. v2 상세는 **타임라인 하나**로 얇아졌고 **격자는 히트맵이,
위험 목록은 면담이** 가져갔다.

**통로로만 남으면 존재 이유가 없다** — 이름으로 찾는 일은 검색이, 위험자는 면담이,
개념별 취약은 히트맵이 이미 한다.

### 고유 가치는 우수 프로필이다

**위험자는 면담 목록이 받아가지만 우수는 아무 화면도 안 받는다** — 면담 대상이 아니기
때문이다. 9-3이 그 용도를 정해 뒀다.

> *"프로젝트별로 따로 뽑는다. 미프 6~8회 × 반당 1~2명이면 **프로젝트별 프로필**이 쌓인다.
> **팀 구성에 쓰는 것은 우수 명단이 아니라 그 프로필**이다."*

`HITL Trigger에서 우수`와 `인증 흐름에서 우수`는 **다른 사람**이다. 그래서 프로필 열에
**횟수와 개념**을 함께 쓴다.

### 팀 열이 없다 — v1에서 살린 판단

팀은 **프로젝트마다 재편성되는 유동값**이라 사람에 고정으로 붙일 수 없다. MG-06에서
회차 헤더로 옮긴 것과 같은 이유다.

### 계정 상태는 읽기만 한다

초대 대기·비활성은 **히트맵·면담·대시보드 어디에도 안 나온다** — 측정 대상이 아니기
때문이다. v1에서 그대로 살렸다.

**여기서 초대하거나 계정을 만들지 않는다.** 학생 계정과 반 배정은 **오퍼레이터 소관**
이다(18번 2-5 — OP-06 `반·명단` 탭이 *"반 목록 + 명단 · [배정] → 모드"*). **매니저는
담당 반을 받는 사람**이지 명단을 만드는 사람이 아니다.

**도달 단계 자리는 비운다.** 응시한 적이 없는 것을 `0단`으로 쓰면 **못한 것**이 된다.

### 즐겨찾기를 만들지 않는다 — 14-2를 뒤집었다

14-2가 *"넣는다. 개인 북마크(비공유)"* 로 정했지만 **v2에서 근거를 잃었다.**

| 14-2가 상정한 필요 | v2에서 |
|---|---|
| 관심 학생을 표시해 둔다 | **위험이 자동 판정**되어 면담 목록에 올라간다 |
| 시스템이 못 잡는 사람을 기억한다 | **면담 기록**에 쓰면 MG-06 타임라인에 남는다 |

**결정적인 것:** 북마크의 값은 **다른 곳에서 쓰일 때** 생긴다. 지금은 자기가 설정된
목록만 필터하는 **닫힌 고리**였다 — 대시보드가 즐겨찾기 학생 이벤트를 올려준다든지
해야 값이 생기는데 그건 새 범위다.

**25명은 표시하지 않아도 기억하는 규모**이기도 하다.

**★ 즐겨찾기는 개인 북마크(비공유).** 공유 태그로 만들면 요주의 명단이 되어 낙인
문제가 생기고 매니저 교체 시 인수인계 이슈가 붙는다.

## 5. 데이터

**선택한 회차** — 개념 3건 도달(**히트맵 행을 잘라 씀**) · `2단 이하 n/3` ·
위험 유형(9-2) / 우수(9-3) / 응시 상태 3종(14-1).
**회차를 걸친 값** — 우수 누적(**횟수 + 회차 번호**).
**회차 무관** — 이름 · 반 · 계정 상태(활성·초대 대기·비활성).

**팀·제출 현황은 없다**(4절).
