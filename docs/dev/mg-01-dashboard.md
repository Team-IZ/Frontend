## 결정 기록

## MG01-1 · 항목별 "해소" 신호를 확정한다: `면담`은 실제 종결, 나머지는 자기 신고(체크)

- **배경:** D56 C절 구현 뒤 사용자가 대시보드 `[체크]`(옛 `[연락함]`) 버튼 자체의 필요성을 재검토하자고 제기했다. 논의 과정에서 밴드별로 "무엇이 이 항목을 할 일 목록에서 없애는가"가 서로 다르다는 게 드러났다 — 하나로 뭉뚱그려 두면 나중에 API를 연동할 때 잘못된 자리(전부 자기 신고로)에 붙이기 쉽다.
- **판단 — 항목 종류에 따라 "해소" 메커니즘이 둘로 갈린다:**
  1. **`INTERVIEW`(면담 대기) — 실제 종결이 유일한 해소 신호다.** `[브리프 열기]`는 다른 화면(`interviews/*`)으로 이동만 할 뿐 그 자체로 아무것도 끝내지 않는다 — 그 화면에서 면담을 실제로 마치고 **종결 처리**해야 비로소 끝난다. API 연동 후에는 그 종결 이벤트가 대시보드 `ITEMS`에서 해당 항목을 지우고, `RESOLVED_HISTORY`에 `{kind:'INTERVIEW', doneFlag:'종결함 · 방금', nextAction}` 형태로 넣는다 — 이 스키마는 이미 목업 시드(`r-parkdohyun`)에 존재해서 새로 설계할 게 없다, 지금 정적으로 박아 둔 값을 실제 종결 이벤트가 채우도록 배선만 하면 된다.
  2. **`ABSENT`·`RETRY`·`UNSUBMITTED`·`ANALYSIS_FAILED` — 실제 신호(응시·제출)가 있지만, `[체크]`는 그와 별개인 자기 신고다.** 이 넷은 화면을 안 옮기고 이 화면 안에서 끝나므로(파일 머리말 "미응시·다시 보기·미제출·분석 실패는 다른 화면으로 안 옮긴다") 종결을 알려줄 별도 화면이 없다 — 대신 응시·제출이 실제로 일어나면(다른 시스템 이벤트) 그 자체가 해소 신호가 되어 항목이 사라져야 한다. `[체크]`는 그 실제 해소와 무관하게, "내가 이미 손을 썼다"는 매니저 개인 기록일 뿐이다(SubmissionTab 쪽은 이 자기 신고 기능 자체를 이미 제거함 — 옆 열만 봐도 충분하다는 판단, MG-08 쪽 결정). 대시보드는 여러 날짜에 걸친 여러 유형의 백로그를 다루므로 이 자기 신고를 남긴다.
- **근거:** 두 메커니즘을 하나로 착각하면(예: `[체크]`를 누르면 항목이 사라진다고 잘못 구현하면) 실제로 응시·제출·면담종결이 없었는데도 목록에서 빠져버려 매니저가 진짜 미해결 건을 놓친다 — "내가 확인했다"와 "문제가 실제로 풀렸다"는 다른 사실이고, 화면은 그 둘을 구분해서 보여줘야 한다.
- **목적·효과:** API 연동 시점에 배선을 어디에 걸어야 하는지(면담=종결 이벤트 구독, 나머지=응시/제출 이벤트 구독) 미리 못 박아 둔다 — 지금 목업은 두 메커니즘 다 아직 안 걸려 있다(면담은 원래 화면 전환만, 나머지 셋은 `[체크]`가 상태만 바꾸고 실제 응시·제출을 시뮬레이션하는 트리거가 mock에 없다).

## MG01-2 · 프로젝트 select 추가 + 회차별 세션 기억

- **배경:** 정의서상 "회차 필터가 없다"였는데, 교육생·히트맵·면담 화면과 형태를 맞추기 위해 프로젝트(회차) select를 추가했다. `RunLine.tsx` 안에 기존 회차 라벨 자리를 대신해 한 줄로 얹었다(별도 툴바 줄로 분리하지 않음 — 사용자 지시).
- **판단:**
  - 기본값은 `ROUND_OPTIONS`의 마지막 항목(가장 최근 생성된 프로젝트) — heatmap과 같은 규약.
  - `[브리프 열기]`로 면담 화면에 갔다가 뒤로가기로 돌아오면 방금 보던 회차를 유지해야 한다 — `useState` 기본값만으로는 재마운트 시 최신 회차로 리셋돼 버려서, 모듈 레벨 세션 변수(`dashboard/viewState.ts`, `heatmap/viewState.ts`와 동일 패턴)로 기억한다.
  - select 트리거는 `shrink-0`을 줘서 프로젝트 이름이 길어져도 잘리지 않게 했다(`flex flex-wrap` 행 안에서 다른 요소에 밀려 줄어드는 문제 수정).
  - 기본 회차(`mif-4`)는 아직 시나리오 데이터가 없어 진입 시 바로 빈 상태가 뜬다 — 실제로 그 프로젝트가 아직 시작 전이라는 뜻이므로 의도된 동작이다(데이터 있는 회차로 되돌려 보여주지 않음, heatmap과 같은 원칙).
- **근거:** 다른 매니저 화면과 다른 필터 UX를 쓰면 학습 비용이 든다 — 기존 패턴 재사용이 새 패턴보다 낫다.
- **목적·효과:** 대시보드도 프로젝트별로 볼 수 있게 되어 화면 간 조작 방식이 통일됐다.

## MG01-3 · "체크" 액션 표기·타임스탬프 정리

- **배경:** 버튼 라벨이 "연락함" → "팀 전원 연락함"으로 갈리다가, 실제로는 팀당 제출자가 한 명뿐이라 "전원"이 틀린 표현이었다. 완료 후 표시되던 "체크함 · 방금"도 시간이 지나도 "방금"에 고정돼 있었다.
- **판단:** 라벨은 "연락"이라는 말 자체를 빼고 "체크"로 통일(사용자 지시, 3차 수정 끝에 확정). 타임스탬프는 분 단위 정밀도가 필요 없다는 판단하에 일 단위 상대 표기(`checkedLabel`: 오늘/어제/N일 전)로 바꿨다 — `MOCK_TODAY` 고정값 기준으로 계산해 렌더가 매번 달라지지 않게 했다.
- **근거:** "전원"은 사실과 다른 정보를 준다(팀장 한 명만 제출). 분 단위 표기는 매니저가 신경 쓸 필요 없는 정밀도라 오히려 노이즈다.
- **목적·효과:** 라벨이 실제 동작(개인 신고)과 일치하게 됐고, 체크 시점을 하루 단위로 가늠할 수 있게 됐다.
