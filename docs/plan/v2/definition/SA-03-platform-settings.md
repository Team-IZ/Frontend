# SA-03 · 플랫폼 설정 — 탭 2

## 1. 한 줄

전 기관에 걸리는 **모델·단가·계정**을 관리한다.

## 2. 진입 · 이탈

**우상단 톱니.** 네비 자리를 주지 않는다 — 화면이라기보다 설정 항목이다.

## 3. 뷰

```
플랫폼 설정
[ 모델 · 단가 ] [ 슈퍼어드민 계정 ]
```

### 모델 · 단가

```
채점        고정 · claude-x         ← 전 기관 공통. 바꾸면 재캘리브레이션
질문 생성   정확도 우선 / 균형 / 비용 우선   3티어 ↔ 모델 매핑
단가        모델별 입력·출력 토큰 단가
```

**채점 모델은 플랫폼이 고정한다.** 기관이 바꿀 수 없다 — 바뀌면 점수를 비교할 수 없다.
**3티어 추상화**라 모델이 단종돼도 기관은 아무것도 하지 않는다.

**변경 시 경고:** 채점 모델을 바꾸면 **전 기관 재캘리브레이션**이 필요하고, 버전이 다른
결과끼리는 화면에서 비교를 막는다.

### 슈퍼어드민 계정

목록 · 초대 · 정지. **마지막 한 명은 정지할 수 없다.**

## 4. 데이터

티어↔모델 매핑 · 단가 · `calibration_version` · 슈퍼어드민 계정.

## 5. 액션

매핑 변경(확인 모달) · 단가 수정 · 계정 초대/정지.

## 6. 상태 — 왜 그렇게 정했나

> **케이스 표는 목업에 있다** — [`superadmin/console.html#cases-sa03`](../wireframe/superadmin/console.html#cases-sa03).

### 단가 미입력을 0으로 계산하지 않는다

0으로 합산하면 **청구액이 실제보다 작아 보인다.** 그 화면을 보고 예산이 남았다고 판단하면 그때부터 틀린 결정이 쌓인다 → `단가 미설정`으로 **표시하고 합산에서 뺀다.**

SA-02의 `사용량 집계 실패`와 같은 원칙 — **모르는 값을 0으로 쓰지 않는다.**

### 채점 모델 변경은 되돌릴 수 없다고 먼저 말한다

바꾸면 **전 기관 재캘리브레이션**이 필요하고, 버전이 다른 결과끼리는 비교가 성립하지 않는다. 확인 모달에서 그것을 말하고, 확정 후에는 화면이 비교를 막는다.

### 마지막 슈퍼어드민은 정지할 수 없다

SA-02의 `마지막 오퍼레이터`와 같은 이유 — **플랫폼에 들어갈 사람이 없어진다.** 이쪽은 풀어 줄 상위 권한이 아예 없어서 더 치명적이다.

## v1 대조 — 검수 결과

**v1에 이 화면이 없다.** SC-S01은 네비에 `슈퍼어드민 관리`를 두고 내부 초대만 다뤘고, **모델·단가는 개념 자체가 없었다.**

| | |
|---|---|
| **네비 → 우상단 톱니** | 계정 몇 개와 단가 표라 **화면이라기보다 설정 항목**이다. 네비 3개를 1개로 줄였다 |
| **모델·단가 신설** | 채점 모델을 플랫폼이 고정하고 기관은 **티어 이름만** 고른다 — 모델이 단종돼도 기관 쪽에서 할 일이 없다 |
| **v1 D12 슈퍼어드민 내부 초대** | **그대로** — 고객 가입 화면(AU-02)을 쓰지 않는다 |
