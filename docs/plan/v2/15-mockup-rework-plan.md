# 목업 재작업 계획

> **왜 필요한가:** [14번 종합 설계](14-verification-design.md)로 측정 구조가 바뀌면서 현재 목업 21개 중 **15개가 영향**을 받는다. 화면 정의를 다시 하기 전에 **무엇을 바꾸고 무엇을 먼저 정해야 하는지**를 정리한다.
>
> **이 문서는 계획이지 설계가 아니다.** 각 화면을 어떻게 그릴지는 해당 차수에서 정한다.

---

## 한 장 요약

| | 개수 | 화면 |
|---|---|---|
| 🔴 **재작성** | **7** | session · result · analysis · trainee-detail · report · project-workspace · **intervention(→면담)** |
| 🟡 **부분 수정** | **8** | dashboard · trainee-list · curriculum · console · program-admin · roster-assign · home · submission |
| 🟢 **신설** | **1** | 교육생 리포트 아카이브 |
| ⚫ **삭제** | **6** | 불균형 탭 · 기술영역 히트맵 · 체크포인트 리포트 · 문제수 입력칸 · 매니저 검증 3개 선택 · **개입 유형 5종** |
| ⚪ **무영향** | **5** | login · password-reset · signup · activation · onboarding |
| ⏸ **보류** | **0** | — ([16번](16-intervention-design.md)에서 해소) |

**작업 순서는 데이터 흐름 순이다.**

```
project-workspace → session → result·archive → trainee-detail → analysis → report → 나머지
```

**먼저 정해야 할 뷰 결정이 7건 있고, 그중 2건이 재작성 화면을 막고 있다**(4절). **14번 v1.1에서 3건이 해소됐다.**

## 2. 충돌 6건 — 전부 14번이 이긴다

| # | 어제 / 09번 | 14번 | 해소 |
|---|---|---|---|
| **1** | 개별상세에 **5축별** 팀평균 vs 개인 그래프 | 축 4개 + **계단이 주 판정** | **재설계.** 축이 아니라 **검증 개념별 도달 단계** 비교 (5-①) |
| **2** | 이해 단계 히트맵 **L1~L5** | 계단 **0~4** | 계단으로 대체 |
| **3** | 히트맵 **재시험 포함/미포함 필터** | 조직 단위 수치는 **1차만** | **필터 폐기.** 셀에 개선 표식(↑)만 |
| **4** | 리포트에 **문제별 점수** | **전 화면 점수 미표시**(v1.1) | 학생·매니저·운영자 **전부** 도달 단계 + 축별 서술. 0~5는 내부값 |
| **5** | 매니저가 체크포인트에서 **검증 3개 선택** | **운영자가 프로젝트 단위 확정**(v1.1) | 매니저 선택 UI **삭제** |
| **6** | 히트맵 열 = 개념 한 줄 | **열 머리 2단**(v1.1) | 프로젝트 / 개념 3개. 프로젝트가 행 드릴다운에서 빠짐 |

**1번이 가장 크다.** "5축별 그래프"는 어제 명시적으로 결정한 화면인데, 축이 4개가 되고 계단이 판정값이 되면서 성립하지 않는다.

**4번은 v1.1에서 범위가 커졌다.** 이전에는 "학생에게만 안 보여준다"였는데 이제 **매니저 화면에서도 뺀다.** trainee-detail·report의 "축별 점수" 표기가 전부 서술로 바뀐다.

## 4. 먼저 정해야 할 뷰 결정 7건

**이게 없으면 그릴 수 없다.**

| # | 미정 | 막고 있는 화면 |
|---|---|---|
| **1** | **개별상세 비교 그래프** — 5축 그래프가 죽었는데 무엇으로 대체하나 | trainee-detail |
| **3** | **위험 목록 행에 무엇을** — 유형 배지 · 2단미달 개수 · 도달 단계 · 힌트 횟수 중 무엇을 | analysis · dashboard |
| 4 | 세션 화면 **힌트 노출 방식** — 버튼? 자동? 남은 횟수 표시? | session |
| 5 | **전체화면 이탈 시** 무엇을 보여주나 — 경고 오버레이? 카운트? | session |
| 6 | **무효 응시를 학생에게 알리나** | session · result |
| 7 | **상세 해설 후공개**를 학생 화면에 어떻게 — 잠금 표시? | result |
| 9 | **집단 미달 표시 위치** — 히트맵 셀? 별도 배너? | analysis |

**1·3이 급하다.** 재작성 화면 두 개가 여기 걸려 있다. 나머지는 해당 차수에서 정해도 된다.

### v1.1에서 해소된 3건 — 번호는 유지한다

| # | 이었던 질문 | 답 |
|---|---|---|
| ~~2~~ | 히트맵 셀 값 — 평균 도달 단계? 도달률(%)? | **평균 도달 단계.** 열 머리 2단으로 확정(5-②) |
| ~~8~~ | 요구사항 P/F를 어느 화면에 | **입력은 project-workspace(교안과 별개 필드) · 결과는 submission** |

## 5. 급한 건에 대한 제안

### ① 개별상세 비교 그래프 — 축이 아니라 검증 개념으로

14번의 **"위험은 검증 개념 단위로 본다"** 와 정합한다.

```
미프 3차 · Kubernetes 기본 리소스
──────────────────────────────────────────────
Service 역할 분리      ███░░  3단    팀평균 2.4
Deployment 구성        ██░░░  2단    팀평균 3.1   ← 팀보다 낮음
ConfigMap / Secret     ████░  4단    팀평균 2.8
```

**5축 그래프보다 나은 이유:** 처방이 바로 나온다 — *"Deployment를 다시"*. 축 평균(`설계논리 3.2`)으로는 아무것도 못 한다.

### ② 히트맵 — 평균 도달 단계 (0~4) · 열 머리 2단 **[확정]**

도달률(%)보다 낫다. **계단이 판정값이고, %로 바꾸면 경계를 한 번 더 정해야 한다.**

```
        │        미프 2차         │        미프 3차         │
        │ Service  Deploy  Config │ HITL   Graph   State    │
────────┼─────────────────────────┼─────────────────────────┤
 A반    │  2.4      3.1     2.8   │  2.9     ―      3.2     │
 B반    │  1.8      2.9     3.0   │  2.2    2.7     2.6     │
         ↑ 셀 클릭 → 그 반 학생 목록      ↑ ― = 코드 매칭 0 (0단 아님)
```

**개념은 프로젝트마다 다른 3건이라 한 줄로 못 편다.** 프로젝트를 위층에 두면 가로가 시간축이 되고, 왼→오른쪽으로 읽는 것이 그대로 성장 추이다.

**프로젝트가 열로 올라가서 행 드릴다운이 4단이 된다** — 기수 → 반 → 팀 → 개인. 이전 계획의 5단(프로젝트 포함)은 폐기.

**폭 방어:** 미프 8회 × 3개념 = 24열. **프로젝트 단위 접기/펴기**로 기본은 최근 3개 프로젝트만 편다.

### ③ 위험 목록 행 — 정렬이 곧 표기

```
이OO   [지속 저점] [무효 응시]   2단미달 2/3   최저 1단 · 힌트 4회
김OO   [단계 하락]              2단미달 2/3   이전 0/3 → 이번 2/3
```

**사전식 정렬**(2단미달 개수 → 도달 단계 → 힌트 횟수)이므로 **화면에 보이는 순서대로 정렬된다.** 매니저가 왜 이 순서인지 물을 일이 없다.

**단계 하락 행에는 `이전 n/3 → 이번 n/3`을 같이 쓴다.** 유형 정의가 그 두 숫자의 비교라서(14번 9-2) 배지 근거가 행 안에서 끝난다. 호버 설명이 없어도 읽힌다.

## 6. 작업 순서 — 데이터 흐름 순

```
입력              측정          학생 결과          매니저 조회         요약
project-      →  session   →   result        →   trainee-detail  →  dashboard
workspace                      archive(신설)      analysis            trainee-list
                                                  report              curriculum
```

| 차수 | 화면 | 왜 이 순서인가 |
|---|---|---|
| **1** | **project-workspace** | 교안 연결 + **`teaches` 3건**이 모든 데이터의 시작점 |
| **2** | **session** | 가장 많이 바뀌고 **나머지 화면의 데이터 원천** |
| **3** | **result + 아카이브(신설)** | 세션 결과의 첫 소비처. **점수 미표시 원칙**을 여기서 검증 |
| **4** | **trainee-detail** | 매니저 조회의 최소 단위 |
| **5** | **analysis** | 집계 화면. 히트맵은 3·4가 정해져야 그린다 |
| **6** | **report** | 리포트 구성은 위 전부의 종합 |
| **7** | dashboard · trainee-list · curriculum | 부분 수정 |
| **8** | 호칭 일괄 · console · lead-only | 기계적 작업 |
| **9** | **intervention → 면담** | 브리프가 2~6차 데이터를 읽는다. 맨 뒤 |

> **session을 먼저 그리고 싶어지지만 project-workspace가 앞이다.** 검증 개념이 없으면 세션 화면에 **무엇을 물을지** 표시할 수가 없다.

## 7. 차수별 체크리스트

### 1차 · project-workspace

- [ ] 교안 연결을 **필수**로 (선택 → 필수). 없으면 그 자리에서 추가
- [ ] **교안 `teaches` 목록에서 3건 선택** — 프로젝트 생성 시, **기관 운영자**. 자유 입력 아님
- [ ] 3건 미만/초과 저장 차단 · 교안 미연결 시 목록 비활성
- [ ] **매니저 선택 UI 없음** — 체크포인트 실행 화면에서 3개 고르는 단계 삭제
- [ ] **문제 수 입력칸 제거** (3개 고정)
- [ ] 요구사항을 **줄 단위**로 입력 — **교안 필드와 시각적으로 분리**(다른 출처·다른 용도)
- [ ] 미프/빅프 구분 표시 — 빅프도 **3문제**

### 2차 · session

- [ ] **진입 조건** — 분석 완료 후 24시간. 화면에 **남은 시간**과 **분석 중** 상태를 구분해 표시
- [ ] **계단 진행** — L1·L2 필수 / L3·L4 선택. 미달 시 즉시 그 문제 종료
- [ ] **힌트 재진술 2회** — 노출 방식 결정 필요(**#4**). **감점 없음을 문구로 명시**
- [ ] **파일:라인 코드 블록**을 질문에 인용 (전체화면 전제)
- [ ] **전체화면 강제** + 이탈 시 처리(**#5**)
- [ ] **창 이탈 감지** — 횟수·지속시간을 **답변 단위로** 기록(세션 합계 아님)
- [ ] 이탈 중 **타이머 계속 흐름** — 일시정지 없음
- [ ] **붙여넣기 차단** + 시도 기록
- [ ] **질문 텍스트 선택 차단**
- [ ] 단계별 **시간 안내**(강제 종료 아님) · 세션 하드 상한 70분
- [ ] 답변 길이 **3~5문장 안내**
- [ ] 종료 문구 — `"이 부분은 리포트에서 자세히 설명해드릴게요"`
- [ ] 결정 필요: **#6** 무효 응시를 학생에게 알리나

### 3차 · result + 아카이브(신설)

- [ ] **점수 미표시.** 검증 개념별 도달 상태로
- [ ] 1차 / 재시험 **병기**
- [ ] **재시험 마감일 표시** — `3일 후` 와 `다음 프로젝트 제출일` 중 **빠른 쪽을 실제 날짜로**. 규칙을 학생에게 설명하지 않는다
- [ ] **막힌 만큼 두꺼운 피드백** — 해설 + 교안 위치
- [ ] **상세 해설 후공개** — 재시험 대상 문항은 재시험 후(**#7** 표현 방식)
- [ ] **아카이브 신설** — 프로젝트별 내 문답 + 받은 리포트
- [ ] 히트맵은 **학생에게 보여주지 않음**

### 4차 · trainee-detail

- [ ] 종합 탭 — **검증 개념별 비교 그래프**(**#1**)
- [ ] 세션 탭 — **AI 요약 + 핵심 추출만.** 원문 문답은 화면에 없음(저장은 함)
- [ ] **이탈 플래그가 붙은 문답만 예외로 펼쳐 보여줌** — 어느 답변인지 알아야 판단이 됨. 자동 판정은 없음
- [ ] 개입 탭 — **개입 버튼 추가**
- [ ] **귀속 탭 삭제** (미프는 기여도 미사용)
- [ ] 도달 단계 · 힌트 횟수 표기
- [ ] **축별 0~5 점수 자리에 `evidence` 서술을 넣는다** — 숫자 병기 없음

### 5차 · analysis

- [ ] **기여·이해도 불균형 탭 삭제**
- [ ] **기술영역 히트맵 삭제**
- [ ] **위험/우수 통합 테이블** — 프로젝트 **필수 선택**, 기본 위험만, 우수 토글
- [ ] **매니저에게도 우수 노출**
- [ ] 유형 **호버 시 상세 설명**
- [ ] **히트맵 열 머리 2단** — 위 프로젝트 / 아래 개념 3개. 셀 = 평균 도달 단계
- [ ] 프로젝트 단위 **접기/펴기** · 코드 매칭 0 셀은 **0단과 다른 색**
- [ ] **드릴다운(행)** — 운영자 4단(기수→반→팀→개인) / 매니저 3단(반→팀→개인). **프로젝트는 열이므로 뺀다**
- [ ] 셀·시그널 클릭 → 해당 단위 상세
- [ ] **집단 미달 표시**(**#9**) — 반 절반 이상 미달 시 개인 위험에서 제외
- [ ] 재시험 필터 없음 — **1차만.** 개선 표식(↑)만

### 6차 · report

- [ ] **체크포인트 리포트 탭 삭제**
- [ ] **미프별 리포트 + 빅프 최종 리포트** 구성
- [ ] 문제별 섹션 — 도달 단계 + 축별 서술. **숫자 없음**
- [ ] 매니저는 **담당 반 프로젝트만**

### 7차 · 부분 수정

- [ ] dashboard — 위험 카드(2단미달 **n/3**) · 무효 응시 · 우수. **하락은 `이전 → 이번` 병기**
- [ ] trainee-list — 사전식 정렬 · 도달 단계
- [ ] curriculum — 정제 결과(병합·제외 건수) · 형제 관계 · **`teaches` 목록**(프로젝트 생성에서 고르는 후보 원본) 
- [ ] home — 체크포인트 · **응시 창 상태(분석 중 / 응시 가능 + 남은 시간)** · 재시험 진입 + 마감일
- [ ] submission — 요구사항 P/F 결과 · 분석 진행 상태

### 8차 · 기계적 작업

- [ ] **호칭 일괄** — 총괄 매니저 → **기관 운영자(Operator)**
- [ ] **용어 일괄** — 화면·라벨의 `학습목표` → **`검증 개념`**. 목업 전체 grep
- [ ] **숫자 점수 잔존 grep** — `0~5` `축별 점수` 표기가 남은 화면 전수 확인
- [ ] console — 모델별 AI 비용
- [ ] lead-only 2개 — 호칭
- [ ] 와이어프레임 `index.html` 나브 정리 (`개입 관리` → `면담`)

### 9차 · intervention → 면담 ([16번](16-intervention-design.md))

- [ ] 화면명 **`개입 관리` → `면담`** · **개입 유형 5종 삭제** · 취약 축 요약 삭제 · 개입 차단 삭제
- [ ] **면담 목록** — 프로젝트 회차 필터 · 상태 3개(예정 / **후속 필요** / 종결) · **대기 최장 N일**(완료율 ❌)
- [ ] **브리프는 [열기] 눌렀을 때 생성** — RPT-03 자동생성 금지
- [ ] 브리프 ① **그대로 읽는 중립 문구** + 막힌 개념 이름만
- [ ] 브리프 ② **답을 채점할 필요 없는 질문만.** 코드 질문 ❌ · 학생이 기술 질문하면 강사로 넘기라는 안내
- [ ] 브리프 ③ 원인 체크(학생과 함께) → ④ **체크하면 목적지가 뜬다**(라우팅 스위치)
- [ ] 목적지에 **매니저 소관 / 전달만** 구분 표시 — 강사 계정은 시스템에 없음
- [ ] 상단 고정 배너 — `코드 이야기는 하지 마세요. 왜 막혔는지만 들으세요.`
- [ ] **기록 3칸** — 무엇 때문이라고 했나 / 어디로 보냈나 / 다음에 할 것 → 다음 회차 브리프 ①칸에 ⚠로 노출
- [ ] **LLM 0회** — 전부 저장된 값의 재배치 + 위험 유형 2종 템플릿

> **왜 마지막인가:** 브리프가 세션 결과·`evidence`·이탈 기록·위험 유형을 그대로 읽는다. 2~6차가 끝나야 그릴 수 있다.

## 8. 이 계획이 전제하는 것

**14번 문서의 검증 B(계단 위계 확인, 1시간)가 통과한다는 전제다.**

검증 B에서 위계가 무너지면 계단 구조가 바뀌고, 그러면 **2·3·4·5차가 전부 다시 그려져야 한다.** 1차(project-workspace)는 교안·`teaches` 중심이라 영향이 작다.

> **권장: 1차를 진행하면서 검증 B를 병행한다.** 1차는 계단 구조와 무관하므로 대기 시간이 낭비되지 않는다.
