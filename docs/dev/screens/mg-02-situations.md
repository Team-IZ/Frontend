# MG-02 히트맵 — 상황 기록

실계정(이담 · 매니저 · 9기 C반)으로 `docs/dev/screen-hardening.md` 절차를 한 바퀴 돌렸다.

## 1. 조회와 의존 — **3단 직렬이다**

```
GET /members/me/enrollments                 2.5s   ─┐ cohortId가 나와야
GET /cohorts/{id}/trainees?size=1           7.9s   ─┤ 회차(projectId+roundId)가 나오고
GET /cohorts/{id}/analytics/heatmap         2.4s   ─┘ 그래야 격자를 부른다
```

명부를 빌려 쓰는 이유는 **히트맵 회차 선택지를 주는 조회가 없어서**다. 히트맵은
`projectId`와 `assessmentRoundId`를 **둘 다** 필수로 받는데, 그 짝을 함께 주는 것이
명부의 `rounds[]`뿐이다.

## 2. 실측

### 응답 시간 (담당 반 C반 26명 · 개념 3 · 팀 6)

| 조회 | TTFB | 크기 |
|---|---|---|
| `/members/me/enrollments` | 2.52s | 125B |
| **`/cohorts/{id}/trainees?size=1`** | **7.89s · 6.22s** | 3.2KB |
| `/analytics/heatmap` CLASS | 2.56s · 2.07s | 1.7KB |
| `/analytics/heatmap` TEAM | 2.40s | 3.6KB |
| `/interviews/rounds` (참고) | 1.54s · 1.17s | 861B |

`size=1`인데도 7.9초다 — 32차 R9와 같은 관측이다.

### 플로우 (대시보드 → 사이드바 클릭, 프레임 단위)

```
[150ms]    툴바만 (회차 없음 · 격자 없음)
[2.5s]     빵부스러기에 기수가 붙음 (히트맵 › 9기)
[12.0s]    회차·격자 전부
```

**첫 격자까지 12초.** CLS는 0이라 화면이 흔들리지는 않는다.

### 스코프 파라미터 — 계층마다 필수가 다르다

```
level=TEAM     반 없이 → 400 HEATMAP_SCOPE_INVALID
level=TRAINEE  팀 없이 → 400 (반만으로는 부족하다)
```

### 가로채기 — 빈 상태·실패

| 만든 상태 | 화면이 한 말 | 판정 |
|---|---|---|
| `concepts: []` | 「이 회차는 아직 결과가 없어요」 | ✅ |
| `rows: []` (개념은 있음) | 격자 머리 + 「이 범위에는 아직 결과가 없습니다」 | ✅ |
| `500` | 「불러오지 못했습니다 · 다시 시도」 | ✅ |

## 3. 고친 것 — 전부 우리 코드다

### 🔴 툴바 「팀」·「팀원」 버튼이 400에서 못 빠져나왔다

`navigation`은 **지금 계층보다 위**의 선택지만 준다 — `CLASS`에서는 통째로 비어
온다. 아래 단계 항목은 `rows[]`에 있고 그 `rowId`가 곧 `classroomId`·`teamId`다.

화면이 빈 `navigation`에서 기본값을 찾고 있었다. 그래서 계층만 바뀌고 스코프는 빈
채로 나가 400이 되는데, 채울 값은 영영 안 온다(그 요청이 실패했으므로).

**고침** — 본 것을 기억한다(`knownClassrooms`·`knownTeams`). 계층을 내릴 때는
스코프를 먼저 채우고 바꾸고, 팀 목록을 아직 모르면 「팀원」 버튼을 **잠그고 왜인지
말한다**(팀 격자를 한 번 봐야 생긴다).

### 🔴 회차를 바꿔도 팀이 그대로 따라갔다

팀은 **프로젝트에 매인다** — 회차마다 다시 짠다. 그런데 다른 회차의 `teamId`를
넣으면 서버가 **400이 아니라 200 + 빈 결과**를 준다.

```
5차 회차 + 6차 팀 id  →  200, rows: [], summary: null, scope.teamName 없음
```

그대로 두면 화면이 「이 범위에는 아직 결과가 없습니다」라고 말한다 — **거짓말이다.**
없는 게 아니라 그 팀이 이 회차에 없는 것이다.

**고침** — 회차를 바꾸면 팀을 비우고 `TEAM` 계층으로 내려온다. 반은 기수 소속이라
그대로 쓴다. 반을 바꿀 때도 같다(이전 팀은 다른 반 소속이다).

### 회귀 확인

고친 컨트롤을 다시 눌렀다.

```
진입(CLASS)        「팀원」 잠김 · 반 격자 · 히트맵 › 9기
CLASS에서 팀원      아무 일 없음(잠김이 맞다)
팀                 히트맵 › 9기 › C반 · 반 select 자동 채움 · 6팀
팀 → 팀원           히트맵 › 9기 › C반 › 2팀 · 팀 select 자동 채움
회차 6차 → 5차      팀원 → 팀으로 내려옴 · 팀 select 사라짐 · 7팀 · 개념이 바뀜
```

## 4. 요청서로 나가는 것 (32차)

### 히트맵 회차 선택지 때문에 7.9초 명부를 빌려 쓴다

`/interviews/rounds`가 **1.2초**에 같은 `assessmentRoundId` 6건을 준다(id도 일치).
그런데 **`projectId`가 없어** 히트맵을 부를 수 없다.

그 응답에 `projectId` 한 칸이 붙으면 첫 진입이 **12초 → 5초**가 된다(명부 7.9초가
빠지고, 기수 조회와 병렬로도 돌 수 있다).

### 다른 회차의 `teamId`가 400이 아니라 200 + 빈 결과다

화면 쪽은 막았지만, 「없다」와 「이 회차 것이 아니다」가 같은 응답으로 오면 화면이
어느 쪽인지 말할 수 없다.

## 5. 미검증

- **반이 여럿인 매니저** — 이 계정은 C반 하나뿐이라 반 select 전환을 못 눌러 봤다
  (코드 경로는 회차 전환과 같다)
- **`다시 보기`(`attemptView=REVIEW`)** — 이 기수에 다시 보기 데이터가 있는지 확인
  안 했다. 토글은 눌러 봤지만 값이 갈리는지는 못 봤다
- **콜드 스타트** — 측정 중 서버가 자는 상황을 만나지 못했다
- **오측 하나** — `/enrollments`(잘못된 경로)로 110초를 재고 「무응답」이라고 쓸
  뻔했다. 실제 경로는 `/members/me/enrollments`다(2.5초). 스펙에서 경로를 확인하고
  나서 다시 쟀다

1차에서 **컨트롤을 세지 않고 「고쳤다」로 넘어간 것**을 다시 했다. `screen-hardening.md`에

### 컨트롤 5종 — 시작 전에 셌다

```
회차 select   6 선택지
계층 버튼     3 (반 · 팀 · 팀원)
반 select     1 (C반 — 이 계정은 담당 반이 하나다)
팀 select     5 (2~6팀)
도움말 팝오버  1
```

`다시 보기 / 최초 응시` 토글은 **뺐다**(아래).

### 축별 전량 + 걸리는 쌍 — 결과

| 축 | 돈 것 | 요청 | 쓰기 | 결과 |
|---|---|---|---|---|
| 회차 | **6/6** | 각 1건 | 0 | 트리거 라벨이 고른 값과 일치 · 열 4 · 행 2 |
| 계층 | **3/3** | 각 1건 | 0 | 반→팀(행 6)→팀원 |
| 팀 | **5/5** | 각 1건 | 0 | 빵부스러기 `› C반 › N팀` · 행 5 |
| **같은 값 재선택** | 회차 6차 | **0건** | 0 | 캐시 ✅ |
| **되돌리기** | 팀원 → 반 | 1건 | 0 | 빵부스러기·셀렉트가 처음 상태로 복원 ✅ |

**읽기 단계에서 쓰기 요청 0건** — 전 구간 확인.

### 🔴 다시 보기 토글을 뺐다

서버 파라미터(`attemptView`)가 있어 1차에서 토글로 그렸는데, **이 화면은 최초 성적만
본다**(사용자 지시). 히트맵이 답하는 질문은 「개인 문제인가, 반 문제인가」이고 다시 보기는
개인이 여는 보충이라, 반·팀 평균에 섞으면 같은 격자가 두 가지 뜻을 갖는다.

파라미터를 **아예 안 보낸다** — 스펙 기본값이 `INITIAL`이다.

### 🔴 첫 진입이 스피너였다 → 스켈레톤

화면 규칙 E·`async-states` §1-2 위반이었다. 스피너 자리(`py-16` 128px)와 실제 격자
(범례 17 + 표 148 + 주석 16 = 181px)가 달라 도착할 때 본문이 튄다.

**높이·폭을 실제 격자에서 재서 박았다** — 헤더 20 · 행 56 · y축 220 · 셀 184.
직전에 본 격자의 **개념 수·행 수를 기억해** 그대로 그린다(계층마다 다르다).

⚠ **`isPending`으로 판정하지 않는다** — 회차를 아직 못 받아 `enabled: false`인 동안
`isPending`이 거짓이라 빈 화면이 스친다. **값이 있나 없나**로 가른다.

### 🔴 조건을 바꾸는 동안 흐림만 뒀다 → `StaleBlock`

`staleProps`(`opacity-60`)만 걸려 있었다. 회차·계층을 바꾸면 2~3초가 걸리는데 그동안
툴바는 새 조건을, 격자는 옛 결과를 말한다 — 흐림은 그것을 설명하지 못한다.

`StaleBlock`은 오퍼레이터 안(`features/operator/_shared`)에 있어 레이어 린트 때문에
매니저가 쓸 수 없었다. **`components/common/`으로 올렸다**(D14 — 도메인이 갈리면 두
번째 사용에서 올린다). 오퍼레이터 8화면의 import도 함께 바꿨다.

### 🔴 잠긴 이유가 `title`에만 있었다

「팀원」은 팀 격자를 한 번 봐야 열리는데, 그 전에 누르면 **아무 일도 안 일어났다.**
`disabled` 버튼은 hover도 잘 안 먹어 `title`이 사실상 없는 것과 같았다 —
화면 규칙 E7(누를 수 없는 컨트롤은 장식이다)이 말하는 상태다.

**툴바 아래 한 줄로 말한다.** 실제로 상태에 따라 갈리는 것을 확인했다.

```
격자 로딩 중   「반 격자를 먼저 불러와야 합니다」   · 팀·팀원 잠김
반 격자 도착   「팀을 먼저 고르세요 — 팀 격자에서 팀을 누르면 열립니다」 · 팀원만 잠김
팀 격자 도착   안내 없음 · 전부 열림
```

## 미검증 (하드닝 2차)

- **반 select 전환** — 이 계정은 C반 하나뿐이라 선택지가 1개다. 반을 바꾸는 경로
  (팀 리셋 · 계층 강등)는 **회차 전환과 같은 코드**라 그쪽으로만 확인했다
- **스켈레톤 구간을 눈으로 못 봤다** — 서버가 빠를 때는 300ms 안에 격자가 와서
  포착되지 않았고, 느릴 때는 스켈레톤이 계속 떠 있는 것만 봤다. 높이가 실제와 맞는지는
  **실측값으로 만들었을 뿐 도착 순간의 점프를 재지 못했다**
- **경계** — 개념 0건(빈 회차)·행 0건은 가로채기로만 봤고 실제 그런 회차가 없다

## 하드닝 3차 — 조합 전수 42/42 (2026-08-17)

2차에서는 **축별 전량**(회차 6 + 계층 3 + 팀 5 = 14번)만 돌았다. 사용자 지시로
**곱한 조합을 전부** 돌았다 — 회차 6 × 계층 3 × 그 회차의 팀 전부 = **42조합**.
전부 Playwright 실제 클릭으로 눌렀다.

### 축별 전량으로는 안 나왔던 것 셋이 나왔다

#### 🔴 미응시자에게 도달 단계가 찍혔다

1차 6팀 윤지우가 `status: NOT_ATTENDED`인데 화면에 **`3단 · 2단 · 0단`**이 그려졌다.
매니저가 응시한 것으로 읽고, 반 평균과도 어긋난다(그 사람은 평균에서 빠져 있다).

**집계 셀과 개인 셀이 서로 다른 필드로 말한다.**

```
합계·반·팀 셀   validCount 0        아무도 유효 응시를 안 했다
개인 셀        status NOT_ATTENDED  그 사람이 안 봤다 (validCount는 늘 null)
```

`validCount === 0`만 보고 있어서 개인 셀은 그 분기를 아예 안 탔다. **상태를 값보다
먼저 본다.** 무효(`CONFIRMED_INVALID`)·중단(`SESSION_INCOMPLETE`)도 같이 걸린다.

확인 — 2차 2팀 심예린(무효) · 5차 다수(진행 중 회차라 미응시) 전부 `―`로 바뀌었다.

#### 🔴 명단에서 빠진 사람을 화면이 설명하지 않았다

1차 1팀은 `memberCount 5`인데 `rows`가 4개다. 「전체 5명」이라 쓰고 4행만 보여줘
**한 명이 증발한 것처럼** 보였다. `4 / 5명` + 툴팁으로 바꿨다.

**4차 4팀에서도 재현됐다**(`memberCount 4` · 행 3). 1차 단발이 아니다.

#### 🔴 그 수정이 반·팀 계층에서 회귀를 만들었다

2차 팀 격자에서 **「5 / 26명」**이 나왔다 — 행은 **팀**(5개)인데 `memberCount`는
**사람**(26명)이라 뜻이 안 맞는 숫자다. 처음에 계층을 안 가르고 넣은 탓이다.

**개인 계층에서만** 쓰도록 좁혔다. `validCount`로 세던 것도 **행 수**로 바꿨다 —
6팀은 `memberCount 4 · validCount 3`인데 행이 4개라(한 명이 미응시로 행에는 있다)
`validCount`를 쓰면 개인 행과 어긋난다.

### 회차별 결과

```
1차   8조합   ✅ 팀 6 · 인원 합 26 = 26        1팀 4/5명 (R2)
2차   7조합   ⚠ 팀 5 · 합 22 ≠ 26              4팀 없음  (R3) · 2팀 무효 1명
3차   8조합   ✅ 팀 6 · 합 26 = 26
4차   8조합   ✅ 팀 6 · 합 26 = 26              4팀 3/4명 (R2) · 3팀 홍소율 미응시
5차   7조합   ✅ 팀 6 · 합 26 = 26              진행 중이라 미응시 다수(3팀은 전원)
6차   6조합   ⚠ 팀 5 · 합 21 ≠ 26              1팀 없음  (R3)
```

**전 구간 쓰기 요청 0건.** GET은 조합당 1건, 같은 값 재선택은 0건(캐시).
빵부스러기·셀렉트 트리거가 매 조합에서 고른 값과 일치했다.
