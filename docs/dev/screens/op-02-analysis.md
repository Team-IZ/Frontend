## 2. 이 화면의 고유 질문은 하나다

오퍼레이터의 질문을 나열하면 **대부분 다른 화면이 답한다** — 지금 회차 상태(OP-01),
조치(OP-01), 반별 제출·응시율(OP-04), 교안(OP-06), 배정(OP-06). 그래서 히트맵을 그려도
반 비교표를 그려도 **다른 화면의 변형**이 된다.

**답이 없던 질문은 하나** — *"우리가 나아지고 있나."* OP-01은 **지금**만 본다.

그래서 여기에는 **무엇과 견줘야만 읽히는 값**만 둔다: 반 ↔ 기수 전체(회차 흐름) ·
7기 ↔ 6기(기수 간 비교).

## 3. 색 체계를 탭마다 갈랐다 — 램프 공유가 오히려 말을 깨뜨리고 있었다

정의서가 *"MG-02와 램프가 같아야 한다 — 오퍼레이터와 매니저가 **같은 회차를 두고
이야기**하는데 한쪽의 붉은색이 다른 뜻이면 말이 안 통한다"* 고 적어 뒀다.
**그런데 지금이 정확히 그 상태였다.**

| 화면 | 붉은색의 뜻 | 눈금 |
|---|---|---|
| MG-02 히트맵 | **도달 0단** | 절대 |
| OP-02 회차 흐름 | **기수보다 나쁨** | 상대 |

C반이 기수보다 1%p만 나빠도 붉고, 도달 0단이어도 붉다. *"빨간 거 봤어요?"* 가 서로
다른 것을 가리킨다 — **정의서가 막으려던 상황을 규칙 자체가 만들고 있었다.**

### 그리고 그 램프는 검증에서 떨어진다

5단 램프(도달 0~4단)를 색 검증기에 넣으면 5개 검사 중 4개가 FAIL이다.

```
명도 밴드 FAIL · 채도 하한 FAIL · 색각 분리 FAIL · 정상시야 하한 FAIL
worst 인접쌍 ΔE 9.4 (정상시야) — 15 미만은 하드 FAIL
```

### 판단 — 탭마다 색의 성격에 맞춘다

| 탭 | 값 | 색 | 근거 |
|---|---|---|---|
| **회차 흐름** | 기수 대비 **부호** | **청 ↔ 무채 ↔ 적** diverging | 중간점이 *"아무것도 아님"* 으로 읽혀야 한다 |
| **기수 간 비교** | 도달 **1~4단 절대** | **MG-02 램프 그대로** | 여기서만 같은 것을 재므로 공유가 성립한다 |

```
적↔녹 (지금)   색각 ΔE 6.8 — 6~8 하한 밴드. 보조 인코딩 필수
청↔적 (제안)   색각 ΔE 20.1 — 전 검사 PASS
```

**중간점을 노란 계열이 아니라 무채색으로 둔다.** diverging 중간점에 색상이 있으면
*"약간 나쁨"* 으로 읽힌다. 셀은 큰 면이므로 채도를 낮춰 쓴다(`info-soft` / 무채 /
`danger-soft`).

> **부수 효과 — 정의서가 원한 것이 오히려 이때 이뤄진다.** 두 화면의 색이 갈리면
> *"빨간 거"* 가 헷갈릴 일이 없고, 기수 간 비교 탭에서만 램프를 공유해 **그 탭은
> MG-02와 진짜로 말이 통한다.**

## 4. 목업에서 고친 것

### 범례가 5단인데 값은 3단이었다

```
목업 범례 : 기수보다 좋음 [■■■■■ 5칸 그라데이션] 기수보다 나쁨
실제 셀   : 좋음 · 같음 · 나쁨 — 3종
```

정의서가 *"색은 부호만 말한다 — 셋"*, *"5단계가 아니라 3단계인 것이 손해가 아니다"* 라
명시했는데 **범례만 5단으로 남았다.** 5칸 램프를 보면 *"중간값이 있다"* 고 읽고 없는
정밀도를 기대한다 — PRODUCT.md가 anti-reference로 적은 **가짜 정밀도**다.

**→ 3칸 + 각 칸에 라벨.** 색만 늘어놓으면 어느 쪽이 나쁜 쪽인지 유추해야 한다.

### 미집계 막대가 한 자리 수를 비율로 그렸다

`4명 중 미응시 2 · 무효 2` → 50/50 막대. **절대량이 사라지고 비율만 남는다.**
1명인 반과 5명인 반의 막대가 같은 폭이었다.

**→ 숫자 + 종류별 칩.** 총계는 숫자가, 쏠린 종류는 칩이 말한다. 개수와 무관하게 폭이
일정해 행끼리 비교된다.

> 처음엔 개수만큼 도트를 찍었는데 **기수 전체 행에서 16개**가 되어 세는 것이
> 불가능했다(렌더에서 걸렸다).

### 빈 셀에 텍스트가 두 줄이었다

`집계 전` + `리포트 미발행`이 한 칸에. E11(칸에 값 하나) 위반이고, 10×5 격자면 그
텍스트가 격자를 압도한다.

**→ 셀에는 한 줄, 뜻은 호버·포커스와 범례가.**

### 목업 `#dropout`을 안 그렸다

목업에 `중도 이탈` 뷰포트가 있는데 **정의서 §4-2가 그것을 명시적으로 철회했다** —
*"`중도 이탈`은 기획에 없는 개념이다. 문서의 `이탈`은 전부 세션 창 이탈이고 명부 상태는
`활성/초대 대기/비활성`뿐"*. 근거 있는 철회라 정의서를 따랐다. 분모 변화는 **미집계
열이 이미 설명한다.**

## 5. 계층 전환이 화면 전체를 바꾼다

**계층이 선택 방식을 정한다**(정의서 §3). 팀 번호는 **반 안에서만 유일**해서
(`C반 3팀` vs `D반 3팀`) 반이 여럿이면 같은 이름의 다른 팀이 한 표에 섞인다.

| 계층 | 반 선택 | 기준선 | 축 라벨 · 범례 |
|---|---|---|---|
| **반별** | **복수**(체크박스) | 기수 전체 | `기수보다 좋다 / 나쁘다` |
| **팀** | **단일**(라디오) + 팀 복수 | **그 반** | `C반보다 좋다 / 나쁘다` |

**기준선이 바뀌면 라벨도 같이 바뀐다** — 안 바꾸면 무엇과 비교한 색인지 알 수 없다.
빵부스러기도 `분석 › 7기 › C반 › 팀`으로 따라간다.

**컨트롤 모양이 곧 규칙이다.** 안내 문장을 쓰지 않는다(E10) — 체크박스면 복수,
라디오면 단일.

### 팀 계층에서만 실수를 같이 쓴다

**4명 팀에서 1명이면 25%라 비율이 튄다.** 반은 25명이라 그 문제가 없어서 붙이지 않는다.

E11(칸에 값 하나)의 예외다. 규칙의 이유가 *"칸마다 글자가 셋이면 색을 못 읽는다"* 인데,
여기는 **한 줄 더**이고 그것이 없으면 값 자체를 잘못 읽는다.

## 6. 목 데이터에서 고친 값

**목업 6팀 2차 `25%` → `0%`.** 5명의 25%는 1.25명이라 **애초에 나올 수 없는 값**이고,
그대로 두면 팀 합 7명 ≠ C반 2차 6명이 된다. 1·3차는 목업 그대로 합이 맞는다(4명 · 8명).

**팀 합 = 반 값**이 성립해야 한다 — 안 맞으면 같은 반을 두 계층이 다르게 말한다
(OP-01에서 기수↔반 합계로 같은 문제를 겪었다).

숫자로 말한다).

## 8. 구조에서 정한 것

### 안 보는 탭은 조회하지 않는다

```ts
const grid = useAsync(loadGrid, tab === 'rounds')
const compare = useAsync(loadCompare, tab === 'cohorts')
```

마운트됐다고 데이터가 필요한 것은 아니다 — 실측에서 탭 하나 진입에 조회 8건 중 5건이
이것이었다(mock-first §6-1). **탭당 1건**을 실측으로 확인했다.

### 탭을 URL에 두지 않는다

OP-06은 딥링크(조치 필요 → 특정 탭) 때문에 경로에 탭이 있지만, **여기로 들어오는
링크는 전부 기본 탭**이라 `useState`로 충분하다.

### 분모를 호버 전용으로 두지 않는다

E11이 *"칸에는 값 하나, 분모는 호버로"* 라고 정했지만 **호버는 터치·키보드에 없다.**
셀을 `tabIndex=0`으로 두고 `aria-label`에 분모를 넣어, 마우스든 Tab이든 스크린리더든
같은 내용이 나온다. 실측 **44개 셀 전부 포커스 가능**.

### 액션 버튼이 없다

나가는 길은 **데이터 자체**에 붙어 있다 — 열 머리는 그 회차 현황(OP-04), 계층 토글이
팀 드릴다운. 정의서가 판정 줄과 함께 버튼 7개를 전부 지운 것을 그대로 따랐다.

## 10-1. 처음 보는 사람 관점으로 다시 훑은 것 — 두 번째 패스

화면이 완성된 뒤 *"처음 이걸 딱 보는 사람이 봤을 때"* 를 기준으로 다시 쟀다. 격자는
도는데 **읽히지 않는** 문제가 남아 있었다.

### 이 표로 무엇을 판단하나 — 화면이 자기 질문을 안 말했다

축 라벨(`숫자 = 위험자 비율`)은 **읽는 법**이지 **왜 보는지**가 아니다. 격자만 주고
용도를 유추하게 두면 숫자를 훑다가 나간다. 탭마다 한 줄을 뒀다.

| 탭 | |
|---|---|
| 회차 흐름 | *기수와 견줘 어느 반이 계속 벗어나 있는지 봅니다 — 붉은 칸이 가로로 이어지면 그 반입니다* |
| 기수 간 비교 | *교안을 고친 것이 효과가 있었는지 봅니다 — 버전이 바뀐 개념의 값을 견줍니다* |

A8이 금지한 것은 *"화면의 숫자를 문장으로 다시 읽어주는 것"* 이라 걸리지 않는다 —
이건 숫자 해설이 아니라 **표의 용도**다. 다만 한 줄을 넘기면 그때부터 잔소리다.

### `위험자`가 무엇인지 화면에 없었다

이 화면에만 아홉 번 나오는 말인데 정의가 어디에도 없었다. 9-2 판정(`2단 이하 개념이
2개 이상`)을 모르면 `16%`가 무엇의 비율인지 알 수 없다.

**다만 매번 보일 필요는 없다** — 범례의 `?`로 접었다. 처음 보는 사람은 열고, 아는
사람은 안 본다.

### 빈칸이 표의 40%였다

기본 범위가 `1–4차` **상수**였는데 그건 목업 시점 데이터(1~3차 발행) 기준이었다.
발행이 둘뿐인 지금 그 상수를 쓰면 정의서 스스로 경고한 상태가 된다 — *"시작 전 회차를
열로 띄우면 값 없는 칸이 표 폭을 먹는다"*.

**상수를 규칙으로 바꿨다: `발행된 회차 전부 + 진행 중 1개`.** 회차가 6개든 8개든 값
없는 열이 하나를 넘지 않는다. **판정은 서버가 하고**(`appliedFrom/To`로 알려준다)
화면은 안 보내면 서버 기본을 받는다 — 화면이 계산하려면 회차 목록을 먼저 받아야 해서
조회가 두 번 나간다.

> **정의서 §4-3과 충돌한다** — 거기는 `1차 – 4차`로 못 박았다. 아직 안 고쳤다.

### 기준선 행이 기준선으로 안 보였다

색의 뜻이 전부 이 행 대비인데 **배경도 흰색이고 아래 선 1px뿐**이라 그냥 첫 번째
행처럼 보였다. 무엇과 비교한 색인지 표에서 알 수 없으면 격자가 성립하지 않는다.
→ `bg-surface-2` + 아래 2px + `아래 색의 기준` 한 줄.

### 계층 전환에서 선택이 샜다

```
반별(전체 10반) → [팀] → C반 팀 6개 → [반별] → C반 하나만   ← 안 돌아옴
```

`classNames` **한 변수를 두 계층이 공유**해서, 팀으로 갈 때 덮어쓴 값이 반별로 돌아와도
남았다. 사용자가 고른 적 없는 반이 필터로 걸린 것이다.

→ **계층별로 따로 기억한다**(`classNames` / `teamClass`). 정의서의 *"팀으로 바꾸면 반이
단일 선택이 된다"* 는 **팀 계층 안의 규칙**이지 반별 선택을 바꾸라는 말이 아니다.

**그리고 반을 자동으로 고르지 않는다.** 전에는 정렬 첫 행(C반)을 잡았는데 사용자 눈에는
임의로 보였다 — 팀 계층의 질문이 *"이 반 안에서 어느 팀이 무너졌나"* 라 **어느 반인지가
질문의 전제**다. 시스템이 대신 고르면 그것이 답인 줄 안다. 안 고른 상태로 두고 반 선택
팝오버를 연다.

### 분모가 화면에 없었다

`채점에서 빠져 분모가 줄었습니다`라고 써 놓고 **무엇에서 줄었는지**가 없었다. 셀의
`12%`가 `30/234`인데 234가 호버에만 있었다.

안 셋을 놓고 골랐다.

| | 안 | |
|---|---|---|
| A | 셀에 `12% (30/234)` | ❌ **E11 위반** — 칸에 글자 셋이면 색을 못 읽는다 |
| B | 미집계 열을 `16/250` | 🔺 열이 넓어진다 |
| **C** | **행 이름 열에 `25명 → 채점 21`** | ⭕ **이미 있는 자리** |

**분모는 행의 속성**이지 셀마다 다르지 않으므로 행 이름 열이 그 자리다. 격자 칸은
여전히 값 하나라 E11을 안 어긴다 — 행 머리는 격자가 아니다. 미집계 열 머리의 설명
줄은 중복이라 뺐다.

### 헤더에 설명 3층이 한 칸에 쌓여 있었다

```
C반 › 팀                       ← ① 이 표가 무엇인가
숫자 = 위험자 비율             ← ② 값이 무엇인가
2단 이하 개념이 2개 이상인 학생  ← ③ 그 말의 뜻
색 = C반보다 좋다 / 나쁘다      ← ② 색이 무엇인가
```

성격이 다른 셋이 같은 무게로 쌓여 있었다. **층을 갈라 각자 자기 자리로 보냈다.**

| 층 | 어디로 |
|---|---|
| 이 표가 무엇인가 | **좌상단**(여기 말고 갈 곳이 없다) |
| 값·색이 무엇인가 | **범례** — 축 라벨은 *"이 축이 뭐냐"*, 범례는 *"이 기호가 뭐냐"* 인데 둘 다 기호 설명이다 |
| 용어 정의 | **범례의 `?`** — 한 번 보면 되는 것 |

읽는 순서와도 맞는다 — 표를 보다 색이 궁금해지면 그때 아래를 본다. 좌상단이 4줄→2줄.

### 도달 단계가 무엇인지 없었다

`평균 도달 1단 → 4단`뿐이라 1단과 4단의 차이를 알 수 없었다. 14번 5절에 답이 있다.

```
L1 코드이해   미달 → 0단
L2 설계논리   미달 → 1단   ← 여기까지 필수
L3 대안비교   미달 → 2단   ← 여기부터 선택
L4 반례대응   도달/미달 → 4단/3단
```

**`2단 이하`가 기준인 이유가 여기 있다** — L2까지가 필수 구간이고 2단은 그 필수를 못
넘긴 자리다(9-1 — *"2단 이하인 검증 개념이 있으면 처방 대상"*).

램프 각 칸 아래에 라벨을 달았다. 색 램프에 축 라벨을 다는 것이라 새 요소가 아니고,
**필수/선택 구분이 임계값을 글이 아니라 그림으로 설명한다**(A7). 매니저 화면이 이미
같은 문구를 쓴다 — 같은 말이 두 화면에서 같아야 한다.

`0단`(응답 없음·무성의)은 뺐다 — 평균값이라 단독으로 나오지 않고 무효 응시는 애초에
평균에서 제외된다(14-1).
