# SC-T04 · 검증 세션 (코드 종속형)

> 소스: 기능명세서 v8 MEAS-06(코드 종속형 세션 진행). 세션 종료 후 ENG-01(5축 채점) 트리거(백엔드).
> 배치: P0 · 교육생 루프 3번. **제품의 핵심** — 제출 코드를 근거로 한 소크라틱 검증.

## 2. 목적 & UX 설계 근거

- **뷰 패턴: 컨텍스트 고정 패널 + 대화 패널.** "코드·문서 종속 질답"의 최적 패턴(방법론). 왼쪽에 **지금 질문의 근거 코드**(파일·함수·조각)를 고정, 오른쪽에 질문·답변 대화. 코드를 보지 않고는 답할 수 없는 질문이므로 컨텍스트가 항상 보여야 한다.
- **원본 코드 없이 정답 불가한 질문만(MEAS-06 규칙).** 근거 코드 조각을 강조 표시. 근거 없는 질문은 폐기.
- **depth를 투명하게, 채점은 불투명하게.** 진행(DP 2/5, 현재 depth L2, 남은 시간)은 보이되, **평가 결과(SURFACE 등)·점수는 절대 비노출**(A5) — 세션 중 자기 수준을 알면 방어적 게이밍.
- **방어 답변도 최소 L2 1회는 태운다.** 잘 답해도 후속 질문이 온다 → "끝났다" 오해 없게 진행 표시.
- **시간·depth 상한(코스트 가드).** 상한 초과 시 완료 DP 기준으로 저장(중단돼도 손실 최소). 단 **타이머는 평소 은은하게, 임박 시에만 경고색** — 이해도 측정에서 카운트다운은 시험 불안·성급한 답변을 유발하므로 표현을 절제(코스트 가드 기능은 유지).
- **중단 복구.** 네트워크 끊김 시 마지막 완료 턴부터 재개.

## 3. 정보 구조 & 레이아웃 (교육생 셸 · 데스크톱 2패널)

**0) 시작 전 — 기대치 게이트(신규):** 세션에 바로 던지지 않고 한 장으로 기대치를 세운다. 근거: 시험 불안은 답변을 방어적·성급하게 만들어 **측정 노이즈**가 된다. 단 **안심은 사실 위에서만** — 과잉 안심은 나중에 "속았다"는 신뢰 부채가 된다.
- ① **"맞히는 시험이 아니라 설명하는 자리"**(재프레이밍). ~~"시험이 아니에요"는 금지~~ — 이 세션은 매니저 개입 판단·최종 등급의 근거이고 재응시가 없으므로 **사실이 아니다**. 부정하지 말고 *평가 방식이 다르다*에 안심의 근거를 둔다.
- ② **결정지점 N곳 · 각 지점 보통 2단계**("잘 답해도 다음 단계가 이어진다" 명시 — 깊이가 실패 신호로 오독되는 것 차단, D109). 어휘는 "질문 N개"가 아니라 **결정지점**(D110).
- ③ **점수·평가 비노출**(A5) + **대화는 담당 매니저가 볼 수 있음 고지**. 고부담 평가에서 제3자 열람은 학생이 *시작 전에* 알아야 할 정보다.
- ④ **제한 시간을 "예상 소요"로 위장하지 않는다.** 시간 상한은 하드 캡이고 초과 시 남은 지점이 결과에서 빠지므로(V-4), "약 10~15분" 대신 **"제한 시간 15분(지점당 약 3분)"**으로 명시.
- ⑤ **중단 시 타이머 동작 명시** — "나가 있는 동안 시간은 멈춰요". 저장은 되는데 타이머가 도는지 마는지 모르면 안심 문구가 학생을 손해 보게 만든다.
- ⑥ **디바이스 안내** — 코드를 함께 봐야 하므로 PC·태블릿 권장(모바일 미대응, §3 반응형 참조).

**1) 상단 세션 바:** 회차·프로젝트 ·
- **결정지점 = 정직한 분수**(`결정지점 2 / 4`). ⚠️ **분모 계약: 세션 시작 시점에 확정된 *유효 DP 수*이지 예산 N이 아니다.** 예산 N=4인데 유효 DP가 3개만 확보되면(T02 A-5) 분모는 **3**이어야 한다 — N을 분모로 쓰면 "2/4"를 보여주고 3에서 끝나 **가짜 분모가 재발**한다(D110/D114이 제거하려던 바로 그 결함).
- **깊이 = 누적형 비분수 인디케이터**(`깊이 ●● 2단계째`) — depth는 **적응형**이라 분모를 표기하면 가짜 분모가 된다(D109·D26). "질문 2/5" 류 고정 분수 **금지**. ⚠️ **빈 칸을 미리 그리는 것도 금지** — `●●○`처럼 남은 칸을 렌더하면 시각적으로 완전한 2/3 분수가 되고, 3번째가 켜지는 순간 학생은 "기본은 2단계인데 나는 더 갔다 = 못했구나"로 읽어 **평가 비노출(A5)이 인디케이터로 샌다.** 현재 단계까지만 점이 늘어나는 누적형으로 그린다.
- **남은 시간**(평소 은은, 임박 시에만 경고색) · [나가기(저장됨)].

**2) 좌 패널(고정) — 코드 컨텍스트:** 파일명·함수명·**근거 코드 조각**(하이라이트) · 그 부분의 요구사항. 질문이 바뀌면 해당 근거 줄로 갱신.

**3) 우 패널 — 대화:** 질문 버블(각 버블에 **근거 줄 링크** `↳ auth/token.py:20`) · 답변 버블 · **결정지점 경계 구분선**(`결정지점 2 · 진행 중` — 전사를 코드 맥락 단위로 청킹) · 하단 **답변 입력**(textarea + 제출).
- **질문 생성 중**: 타이핑 인디케이터 + "다음 질문을 준비하고 있어요" + 입력 비활성(LLM 지연 완충, V-3·V-6도 동일 표시로 흡수).

**4) 종료 화면:** 완료(전 DP 소진) = "수고했어요 · 결과 정리 중"(5축 채점은 여기서 시작, D108) / 시간 상한(V-4) = "N개까지 저장했어요"(비난 없는 문구).

**레이아웃 규율(중요):** 세션은 **고정 높이 컨테이너 + 각 패널 자체 스크롤**. 페이지 전체가 스크롤되면 긴 코드가 들어올 때 **입력창이 화면 밖으로 밀려난다**(랩 실구동에서 발생·검증된 결함). 구현 시 `height:100dvh + overflow:hidden` + 각 패널 `overflow:auto`.

반응형: 웹 기준(2패널). 좁은 폭에서 코드 컨텍스트는 접히는 상단 드로어(현재 근거 줄 기본 노출).
