## 확인된 사실

- **다시 보기는 발행 + 3일 안에만 뜬다.** 267개를 훑어 `retryState≠NONE`이 0건이었는데,
  ~~서버가 옛 판정을 쓴다~~고 적었던 것은 **틀렸다.** 그 기수 리포트가 전부 30~58일 전
  발행이라 창이 지난 것뿐이다(`retryState=NONE`이 정상 동작).
  → 다시 보기를 보려면 **방금 끝낸 회차**가 필요하다.
- **3일 창을 화면이 계산하지 않는다.** 서버가 `retryDueAt`에 `발행일 + 3일`을 담아 준다.
  창이 지나면 `retryState`가 스스로 `NONE`이 되므로 날짜 비교는 하지 않는다.
  단 학생이 버튼을 누르면 **그 시각 + 3일**로 다시 잡힌다(세션의 `reviewDueAt`) — 두 값이
  다르다.
- **다시 보기 시작은 리포트 화면에서만 된다.** 홈의 `START_REVIEW`는 이미 연 것을
  이어서 하라는 자리다 — `reviewStatus`는 `POST /assessment-sessions/reviews`를 부른
  뒤에만 채워진다.
- **분석 실패 사유 둘은 회차 요약에 안 나온다.** `SESSION_PREPARATION_FAILED`와
  `EXTERNAL_JOB_ID_LOST`는 원장에 없고 조회할 때 계산되는 값이라
  `GET /submissions/{id}/analysis`로만 보인다. 홈이 `분석 중`에 머물러 보이면 이쪽을 봐야 한다.
- **분석 소요가 들쭉날쭉하다.** 같은 레포로 오전 2분, 저녁 12분+. 실패로 오판하지 말 것.
