# MG-04 · 면담 브리프 — 모드

## 1. 한 줄

면담 30분 동안 매니저가 **낭독 · 경청 · 라우팅**만 하면 되도록 한 장에 모은다.

> **매니저는 강사가 아니다.** 코드 질문을 던져도 학생 답이 맞는지 판단할 수 없다.
> 그래서 이 화면에는 기술 질문이 없다([16번](../16-intervention-design.md) 0절).

## 2. 진입 · 이탈

| | |
|---|---|
| 진입 | **MG-03 목록의 `[브리프 열기]`뿐.** MG-06에는 이 버튼이 없다 |
| 이탈 | `[저장]` → 목록으로. 상태가 **예정 → 종결**. `[취소]`로도 나갈 수 있다 |
| 형태 | **전체화면 · 사이드바 가림** |

**사이드바를 가리는 것이 핵심이다.** 화면이 다르게 생겼다는 것 자체가 "지금 작업 중"
이라는 신호다 — 검증 세션이 전체화면인 것과 같은 이유.

**다만 검증 세션과 달리 나가는 길이 있다.** 세션은 측정 중이라 이탈이 곧 오염이지만,
브리프는 **매니저 도구**라 잘못 열 수 있다. 좌상단 `← 목록으로 (저장 안 함)`.

### 매니저에게 지시하지 않는다

고정 배너(`코드 이야기는 하지 마세요`), 블록 배지(`그대로 읽으면 됩니다` ·
`답이 맞는지 판단할 필요 없음` · `학생과 함께`), 경고문(`기술 질문을 하면 강사님께
넘기세요`), 안내 캡션(`개념 이름만 읽어주세요`)을 **전부 뺐다.**

**화면이 매번 사용법을 가르치면 사용자를 신뢰하지 않는 것**이고, 두 번째 면담부터는
잔소리가 된다. 그리고 **설계 의도는 화면에 무엇이 없는지로 이미 드러난다** — 기술
질문이 없고 채점 UI가 없고 코드가 없다. 말로 반복할 이유가 없다.

블록 제목도 지시형에서 명사형으로 바꿨다.

| 전 | 후 |
|---|---|
| ① 이렇게 여세요 | **① 여는 말** |
| ② 이것만 물어보세요 | **② 질문** |
| ③ 들은 걸 여기 체크하세요 | **③ 들은 것** |
| ④ 체크한 것에 따라 여기로 보내세요 | **④ 보낼 곳** |

> **경계:** 히트맵(MG-02)의 판정 줄은 그대로 둔다. 거기는 **판정이 무엇을 뜻하는지**를
> 말하는 자리이고(`개인 사유에서 빠지고 반 전체 안내 대상`), 여기는 **매니저가 어떻게
> 행동할지**를 말하던 자리다. 앞은 정보이고 뒤는 훈수다.

**④가 이 화면의 핵심이다.** 원인 체크박스가 분류 라벨이 아니라 **라우팅 스위치**다.
목적지에 `매니저` / `전달만`을 붙여 **자기 권한 밖 일을 떠안지 않게** 한다.

**한 원인에 두 성격이 섞이면 줄을 쪼갠다.** `개념 이해 부족`의 교안 안내는 매니저가
직접 하고 강사 Q&A는 전달만이다 — 한 줄로 묶으면 소관 표시가 거짓이 된다.

**교안 위치에는 출처 교안명을 붙인다**(14번 4-3 — *"출처가 없으면 `3장 p.55`를 어느
문서에서 펼지 알 수 없다"*).

## 6. 상태 — 왜 그렇게 정했나

> **케이스 표는 목업에 있다** — [`manager/interview-brief.html#cases`](../wireframe/manager/interview-brief.html#cases).

| | |
|---|---|
| 지난 면담 없음 | ①의 세 번째 줄이 통째로 빠진다 |
| **무효 응시** | ①의 문장과 ②의 질문이 **통째로 다르다**(아래 절) |
| **③ 미체크** | ④ 자리에 *"고르지 않아도 저장할 수 있어요 — 면담이 항상 원인을 찾아내지는 않습니다"* |
| **난이도 상승 체크** | 그 개념이 **이미 반 문제로 판정됐으면** ④에 알린다(아래 절) |
| 개념 하나가 `코드 매칭 0` | 막힌 개념 목록에서 제외하고 각주로 표시 |
| 저장 실패 | 입력값을 유지한 채 재시도 — **면담 중이라 날리면 안 된다**(`#savefail`). 창을 닫으면 사라진다고 밝힌다 |

## 6-2. 무효 응시 브리프 — 여는 문장이 다르다

16번에 이 케이스가 없다. **`3개 중 0개`가 아니라 응시 자체를 안 한 것**이라 기본 브리프의
문장을 쓰면 말이 안 된다.

```
"이번 이해도 확인이 거의 비어 있어서 결과를 내지 않았어요.
 잘했는지 못했는지를 물으려는 게 아니라, 그날 무슨 일이 있었는지 알고 싶어서 불렀어요."

이 회차 결과 — 채점하지 않음
도달 단계도 위험 판정도 없습니다. 다시 응시하면 그게 1차가 됩니다.
```

**②의 질문도 3개로 바뀐다** — `그날 컨디션이나 일정 / 어디서부터 막혔나 / 다시 볼 시간`.
9-4의 원칙(**내용이 아니라 행동으로 판정한다**)을 그대로 따른 것이다.

**이탈 기록은 이 브리프에서만 보여준다.**

```
시스템이 본 것 · 판단은 하지 않습니다
3문항 중 2문항 무응답 · 나머지 1문항은 질문 문장을 그대로 복사 · 총 응답 시간 4분
```

14번 4-4가 *"플래그가 붙은 문답만 매니저 화면에 펼쳐 보여주고 판단은 사람이 한다"* 고
했다. **일반 브리프에 띄우지 않는 이유**는 그러면 면담이 **추궁**이 되기 때문이다 —
이 화면이 하려는 일은 *"다음 한 주를 어디에 쓸지"* 를 정하는 것이다(16번 ①).

> **못한 것과 안 한 것은 다르다.** ②의 경고문이 그것을 매니저에게 상기시킨다 —
> *"왜 안 했는지를 캐묻는 자리가 아니라 다시 볼 수 있게 만드는 자리입니다."*

## 6-3. 난이도 상승 — 매니저가 세지 않게 한다

16번 ④의 목적지가 *"반 절반 이상이면 개인 아님 → 기관 보고"*(9-6)인데, **절반인지
아닌지를 매니저가 세게 하면 안 된다.** 판정은 이미 시스템에 있다.

```
⚠ Graph 구성은 이미 반 문제로 판정됐습니다 — A반 23명 중 12명이 2단 이하(9-6).
  세어보지 않아도 됩니다. 이 개념은 개인 위험 사유에서 빠지고 반 전체 안내 대상입니다.
```

## 7. 안 하는 것

| | 어디에 |
|---|---|
| 회차별 도달 격자 | **MG-02**(직전 1회만 인용) |
| 문답 원문 전체 | **MG-06**(여기서는 막힌 문항만) |
| 원인 자동 판정 | **하지 않는다** — 시스템은 어디서 막혔는지만 안다 |
| 기술 질문·개념 설명 | **하지 않는다** |
| ② 질문 고르기 | **하지 않는다** — 고르게 하면 *"뭘 물을지"* 부담이 생기고, 그게 이 화면이 없애려던 것이다 |
| 일반 브리프의 이탈 기록 | **무효 응시 브리프에서만**(6-2) — 띄우면 면담이 추궁이 된다 |
| 약속 이행 추적 | **하지 않는다** — 만나면 종결이고, 다음 회차 브리프 ①칸이 인용한다 |
