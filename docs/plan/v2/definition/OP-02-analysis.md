# OP-02 · 분석 — 어디가 기수에서 벗어나나

## 1. 한 줄

**무엇과 견줘야만 읽히는 값을 견주는 자리.** 반 ↔ 기수 전체(회차 흐름) ·
7기 ↔ 6기(기수 간 비교).

> **이름을 두 번 바꿨다.** 원안 `분석`(18번 2-2 — 위험·우수 + 히트맵)은 **고유 질문이
> 없어서** 매니저 화면의 확대판이었고, 그래서 `추이`로 바꿨다. 그런데 재설계하면서
> **"미프끼리는 값을 비교할 수 없다"** 를 못 박고 방향 열까지 지우자 `추이`가
> **화면이 금지한 읽기를 이름으로 약속하는** 꼴이 됐다. 고유 질문이 생겼으므로
> **`분석`으로 되돌린다** — 17번 원칙 5(*"이름은 그 화면이 실제로 하는 일"*)가 경계한 것은
> **진단을 안 하면서 분석이라 부르는 것**인데, 지금은 범위를 좁히고 다음 화면으로 보낸다.
>
> `히트맵`은 쓰지 않는다 — **매니저 nav에 이미 있고**(MG-02), 그쪽은 가로축이 **검증 개념**에
> 색이 **도달 단계 절대 눈금**이라 **겹쳐 보이는데 속이 다르다.** 두 역할이 같이 이야기할 때
> *"히트맵 봤어요?"* 가 서로 다른 것을 가리킨다. 형태 이름이라 **기수 간 비교 탭도 못 덮는다.**

## 2. 이 화면을 네 번 다시 만든 이유 — 고유 질문이 없었다

오퍼레이터의 질문을 전부 나열하면 **대부분 다른 화면이 답한다.**

| 질문 | 답하는 화면 |
|---|---|
| 지금 회차가 정상인가 | **OP-01** 파이프라인 |
| 조치할 게 있나 | **OP-01** 조치 필요 |
| 어느 반이 처지나 | **OP-01** 반 비교 |
| 이 회차 설계가 완결됐나 | **OP-03** |
| 반별 제출·응시율 · 개념 공백 | **OP-04 현황** |
| 교안에 뭐가 있나 | **OP-06 교안** |
| 매니저 배정 | **OP-06** |
| 비용 | **OP-01 · OP-06** |

그래서 히트맵을 그려도, 발견 카드를 그려도, 반 비교표를 그려도 **다른 화면의 변형**이었다.

**18번이 정한 두 탭도 그렇다** — `위험·우수`는 MG-03과 모집단이 같고(오퍼레이터는 처리
못 한다), `히트맵`은 MG-02와 같다. **둘 다 매니저 화면의 확대판**이다.

> **답이 없던 질문은 하나** — *"우리가 나아지고 있나."* OP-01은 **지금**만 본다.

## 3. 미프끼리는 값을 비교할 수 없다 — 기수 대비만 읽는다

**이 화면을 네 번째로 갈아엎은 이유.** 앞선 버전은 `12% → 16% → 19%`를 *"세 회차 연속
올랐다"* 고 읽었는데 **그 읽기가 무효**다.

| | |
|---|---|
| **각 미프는 독립이다** | 회차마다 **개념도 코드도 난이도도 다르다**(6-3 — 검증 개념은 프로젝트마다 다른 3건). `19%`가 `12%`보다 높은 것이 **나빠진 것인지 그 회차가 어려웠던 것인지** 값만으로는 갈리지 않는다 |
| **판정 기준이 같은 것과 값이 비교되는 것은 다른 문제다** | 9-2가 개념 **개수**로 정의됐으므로 *"위험자"* 의 뜻은 회차마다 같다. 하지만 **같은 잣대로 다른 시험을 채점한 것**이라 점수끼리는 여전히 못 비교한다 |

### 난이도는 기수 전체를 빼면 상쇄된다

**같은 회차·같은 개념을 10반이 다 본다.** 그 회차가 어려웠다면 **모든 반에 똑같이**
걸린다 — 기수 전체를 빼면 난이도가 지워지고 **그 반에 대해서만 말할 수 있는 것**이 남는다.

```
        1차   2차   3차
기수    12%   16%   19%    ← 기준선. 색이 없다(자기 자신과 비교할 수 없다)
C반     16%   24%   32%    ← 세 칸 다 붉다
G반      8%   12%   12%    ← 세 칸 다 초록
```

**색은 부호만 말한다** — `기수보다 좋다 / 같다 / 나쁘다` 셋이다.

| | |
|---|---|
| **폭을 정하지 않는다** | `N 이상 벌어지면 심각` 은 **기획에 그 숫자가 없다.** 한때 `±3p / ±10p` 5단계를 썼는데 **내가 만든 임계값**이었고, 색에서 조건 필터와 같은 잘못을 한 것이다(E8) |
| **`p`를 쓰지 않는다** | *"퍼센트 포인트"* 도 **기획에 없는 단위**다. 값 차이를 숫자로 쓰면 곧 *"몇 이상이면 나쁜가"* 를 묻게 되고, 답할 근거가 없다 |
| **얼마나 이어지는지는 가로줄이 말한다** | `계속 붉은 반`은 **줄 모양**으로 보인다 — MG-02 히트맵이 세로줄로 *"이 개념이 반 전체 문제"* 를 보이는 것과 같다 |

### 셀은 값 하나다

MG-02 히트맵의 칸은 **값 하나 + 튀는 칸에만 라벨**이다. 이 표도 같다.

| 셀에 | |
|---|---|
| **보이는 것** | 위험자 비율 하나 |
| **호버** | `위험자 4명 / 채점 25명 · 기수보다 나쁨` |

한때 칸마다 **값 / 분모 / 차이 3줄**을 넣었다. **격자는 색으로 읽는 것**인데 칸마다
글자가 셋이면 **색을 못 읽는다** — 표가 아니라 목록이 된다.

### OP-01 반 비교와의 관계

OP-01 반 비교 막대는 **가장 최근 발행 회차의 값**이고, 그것이 이 표의 **그 회차 열**이다 —
클릭해서 넘어왔을 때 **숫자가 이어져야** 한다. 다만 **순위는 이어지지 않는다**:
OP-01에서 하위인 반이 여기서는 **기수와 비슷**일 수 있다(그 회차가 전체적으로 어려웠던
경우). **값 순위와 기수 대비는 다른 것**이고, 그 차이를 보는 것이 이 화면의 일이다.

**9-6으로 빠진 개념도 같이 빠진다**(같은 계산이어야 두 화면이 안 어긋난다).

## 4. 뷰 — 탭 2개

```
[ 회차 흐름 ] [ 기수 간 비교 ]
```

### ① 회차 흐름

```
[반별|팀] [반 전체 10반 ▾] [회차 1차 – 4차 ▾] [정렬 최근 회차 나쁜 순 ▾]
──────────────────────────────────────────────────────────────────
           회차 격자 · 열 머리 클릭 → 그 회차 현황      │ 제외
 반          1차     2차     3차     4차              │ 미집계
 숫자=위험자 비율                                      │
 색=기수보다 좋다/나쁘다
 기수 전체    12%     16%     19%   집계 전            │ 16 ▮▮▮▯
 250명      K8s배포 REST API LangGraph RAG           │
 C반 25명     16%     24%     32%   집계 전            │  4 ▮▮▯
 G반 25명      8%     12%     12%   집계 전            │  1 ▮
──────────────────────────────────────────────────────────────────
 기수보다 좋음 ■□■ 기수보다 나쁨  ▨ 값이 아직 없음  미집계 ■미응시 ■무효 ■중단
⚠ C반 · D반 · I반 · A반 · F반이 세 회차 내리 붉다
```

**호버**: `위험자 4명 / 채점 25명 · 기수보다 나쁨`

### 표를 세 블록으로 나눈다

**측정값과 미집계는 의미도 기능도 다르다.** 한 줄에 같은 무게로 늘어놓으면
어디까지가 측정값이고 어디부터가 파생인지 안 갈린다.

| 블록 | 무엇 | 읽는 법 |
|---|---|---|
| **회차 격자** | 측정값 | **색으로** 읽는다 — 붉으면 기수보다 나쁘다 |
| **제외** | 격자에 **안 들어간 것** | 막대 모양으로 **쏠림**을 본다 |

두 블록뿐이다. **요약(방향) 열은 지웠다**(4-2).

**열 머리는 2단**이다(`1차` + 프로젝트명) — MG-02 히트맵이 열 머리를 프로젝트/개념 2단으로
둔 것과 같은 이유로, **프로젝트 이름이 없으면 어느 회차인지 짚을 수 없다.** 열 머리를
누르면 **그 회차 현황**(OP-04)으로 간다.

**반 이름 열은 가로 스크롤에도 남는다**(sticky) — 어느 반의 값인지 모르면 표가 아니다.

### 회차가 하나여도 색은 읽힌다

색이 **그 회차 기수보다 좋았나 나빴나**만 말하므로 **1회차부터 읽힌다.** 다만
**가로로 이어지는 줄**이 짧아서 *"계속 그런 반"* 인지는 회차가 쌓여야 보인다.

**`3회차부터 방향을 말한다`는 규칙을 지웠다** — 방향 열 자체가 없어졌고, 그 규칙의
`3회`도 **내가 정한 숫자**였다.

### 전체가 오르는 것과 한 반만 붉은 것

| | 뜻 | 목적지 |
|---|---|---|
| **전체가 오른다** | **그 회차가 어려웠다는 뜻일 뿐**이다 — 색이 안 붙으면 **말할 것이 없다** | 기수 간 비교 |
| **한 반만 붉다** | **회차 난이도로 설명되지 않는다** — 같은 회차·같은 개념을 본 나머지 반이 붉지 않기 때문이다 | 그 반 **팀 계층**(이 화면 안) |

**한 반만 붉을 때 화면이 원인을 말하지 않는다.** 이 표에 있는 것은 *"이 반만 다르다"*
까지이고, 왜인지는 **그 반 안**(팀·개념)을 열어야 나온다.

### 계층이 선택 방식을 정한다 — 반별 | 팀

```
[반별|팀] [반 전체 10반 ▾] ...        ← 반 복수 선택 (체크박스)
[반별|팀] [반 C반 ▾] [팀 전체 6팀 ▾]  ← 반 단일 선택(라디오) + 팀 복수 선택
```

| 계층 | 반 선택 | 왜 |
|---|---|---|
| **반별** | **복수**(체크박스) | 나란히 놓고 비교하는 것이 이 화면의 일이다 |
| **팀** | **단일**(라디오) + 팀 복수 | 팀 번호는 **반 안에서만 유일**하다(`C반 3팀` vs `D반 3팀`) — 반이 여럿이면 **같은 이름의 다른 팀**이 한 표에 섞인다 |

**컨트롤 모양이 곧 규칙이다** — 체크박스면 복수, 라디오면 단일. 안내 문장을 쓰지 않는다.
단일 선택일 때는 **개수 배지(`×1`)도 빼는데**, 붙어 있으면 더 고를 수 있는 것처럼 보인다.

### 드릴다운이 이 화면 안에 있어야 한다

한때 반 이름 클릭을 **MG-02 히트맵**으로 보냈다. **틀렸다** — 오퍼레이터는 **매니저 화면에
갈 수 없다**(17번 3-2 — 오퍼레이터 nav에 `분석`은 있어도 매니저 화면은 없다).

17번 106줄이 오퍼레이터에게 교육생 메뉴를 안 준 대신 *"개인을 보려면 **히트맵 드릴다운의
끝**으로 간다"* 고 한 것은 **오퍼레이터 화면 안의 드릴다운**을 말한 것이고, 그것이
**이 계층 이동**이다.

| 계층 | 행 | 기준선 |
|---|---|---|
| **반별** | 10개 반 | **기수 전체** |
| **팀** | 그 반의 팀 | **그 반** — 팀은 **같은 반 안에서** 비교해야 뜻이 있다 |

**기준선이 바뀌면 라벨도 같이 바뀐다** — 축 라벨(`색 = C반보다 좋다 / 나쁘다`)과
범례(`C반보다 좋음 → C반보다 나쁨`)가 따라간다. 안 바꾸면 **무엇과 비교한 색인지**
알 수 없다.

### 팀 계층에는 방향이 없다

**팀은 프로젝트마다 재편성된다**(TeamMembership). 가로로 이으면 **다른 사람들의 값을
잇는 것**이라 방향이 뜻을 갖지 않는다.

**자리를 비우지 않고 `방향 없음 · 회차마다 팀을 다시 짠다`로 왜 없는지를 쓴다** — 빈칸이면
데이터가 없는 것으로 읽힌다.

**세로로만 읽는다**: *"이번 회차에 어느 팀이 무너졌나."* 4명 팀에서 1명이면 25%라
비율이 튀므로 **실수를 같이** 쓴다.

### 개인까지 내려가지 않는다

개인은 **이름과 답변**이 있어야 뜻이 생기고, 이 격자에 이름을 넣으면 **회차마다 다른
개념의 값을 한 줄로 잇는 것**이 된다. 개인은 **회차 단위 화면**(OP-04)의 일이고,
팀 판정 줄의 `3차 · 2팀 명단`이 그리로 간다.

### ② 기수 간 비교 — 같은 교안 · 같은 개념만

```
[비교 6기 ▾] [같은 교안 · 같은 개념만] [정렬 나빠진 순 ▾]
──────────────────────────────────────────────────────────────────
                              기수          │ 요약        │ 출처
 검증 개념                   6기     7기    │ 변화        │ 교안 버전
 숫자=평균 도달 단계
 색=절대 눈금 1~4단
 Graph 구성                  2.9     2.5    │ ↘나빠짐     │ v1 → v2
  교안 AI_LLMOps·4장 p.62·미프3차           │  -0.4단     │
 HITL Trigger                2.7     2.8    │ — 비슷      │ v2 · 그대로
 State 관리                   ▨      3.3    │ 비교 대상아님│ v2
                          없던 개념          │ 6기에 없던  │
──────────────────────────────────────────────────────────────────
 1단 ■■■■■ 4단   ▨ 그 기수에 없던 개념        MG-02 히트맵과 같은 눈금
⚠ Graph 구성이 교안을 v2로 바꾼 뒤 오히려 나빠졌다
```

**회차 흐름 탭과 같은 격자로 그린다** — 두 탭이 다른 표처럼 생기면 **같은 화면으로
안 읽힌다.** 행이 검증 개념이고 열이 기수라는 것만 다르다.

**여기서는 절대 눈금**이다 — 같은 개념·같은 교안이라 **1~4단이 두 기수에서 같은 뜻**이다.
회차 흐름 탭이 기수 대비 부호를 쓰는 것과 **값의 성격이 다르다**: 저기는 회차마다 다른 것을
물어서 값끼리 못 비교하고, 여기는 **같은 것을 물어서** 비교된다.

**커리큘럼이 같으면 같은 것을 물은 값**이라 비교가 성립한다. 14번 61줄이 근거다 —
*"평소엔 개인, **기수 끝나면 수업(다음 기수 개선)**"*.

| | |
|---|---|
| **여기서는 평균 도달을 쓴다** | 같은 개념이므로 비교 가능하다 — 회차 흐름과 값이 다른 이유 |
| **회차가 달라도 된다** | 6기 미프 2차와 7기 미프 3차에서 같은 개념을 물었다면 **개념끼리** 비교한다 |
| **교안 버전을 함께 쓴다** | *"교안을 고친 것이 효과가 있었나"* 가 이 표의 핵심 질문이고 버전이 없으면 답할 수 없다 |
| **새 개념은 비교 대상이 아니라고 말한다** | 빈칸으로 두면 *"0점"* 이나 *"나빠졌다"* 로 읽힌다 |

**다른 기관 평균을 만들지 않는다** — 커리큘럼이 다른 값이다. 기수가 하나면 이 탭은
빈 상태를 보여준다.

## 4-2. 케이스별 처리 — 검수에서 나온 것

### 분모는 채점된 사람이다

`47/250`이라 쓰면 250명 중 47명으로 읽히지만 **위험 판정은 채점된 사람만** 받는다 —
미응시·무효 응시·중단은 **판정과 평균에서 빠진다**(14-1 · 9-4).

```
19%  44/234              ← 분모가 234명
미집계 16  미응시 9 · 무효 5 · 중단 2     ← 별도 열
```

**미집계를 3종으로 분해해 두는 이유** — 총계만 쓰면 *"분모가 깎였다"* 까지만 알고
**어디를 볼지**가 안 나온다. 세 종류가 서로 다른 곳을 가리킨다.

| 쏠린 종류 | 오퍼레이터가 볼 곳 |
|---|---|
| **미응시** | 응시 창 안내·독촉이 도는지 — 반 운영 |
| **무효 응시** | 세션 설계나 응시 태도. 9-4가 *"위험 목록에 눈에 띄게"* 라 한 종류 |
| **중단** | 세션이 끊기는 것 — 기술 문제일 수 있다 |

**개별 건은 오퍼레이터의 일이 아니다** — 무효 확인은 매니저(9-4 *"목록에 올리고 매니저가
확인한다"*)이고 독촉도 매니저다. 이 열은 **비율의 신뢰도**와 **쏠림**만 본다.

**14-1이 *"평균에서 빼고 위험 목록에는 올린다"*** 고 했으므로 **없애지 않고 옆에 센다** —
미집계가 한 반에 몰리면 그 자체가 신호다(F반 5건).

### 리포트 미발행 회차는 `집계 전`

위험 판정은 **리포트 발행 시점에 켜진다**(9-2 · 10-2 일괄 발행). OP-01 반 비교가
*"미프 2차 기준 — 미프 3차는 미발행"* 이라 쓰는 것과 같은 이유다.

**추세 계산에서도 뺀다** — 없는 값을 0으로 읽으면 방향이 뒤집힌다.

### 요약(방향) 열을 지웠다

`↗ 격차 벌어짐 · 3회 연속 · 지금 +13p` 라는 열을 뒀다가 **통째로 뺐다.**

| | |
|---|---|
| **만든 단위** | `p`(퍼센트 포인트)가 기획에 없다 |
| **만든 임계값** | `±3p 안이면 비슷` · `3회 이상이면 연속` — 둘 다 내가 정했다 |
| **색이 이미 하는 일** | *"계속 기수보다 나쁘다"* 는 **가로로 붉은 줄이 이어지는 것**으로 보인다. 같은 말을 글자로 한 번 더 쓴 것이다 |

**정렬은 남는다** — `기수보다 나쁜 회차가 많은 순`의 키는 **붉은 칸 개수**이고,
그 키가 **격자에 그대로 보인다**(E2).

### 셀 색 — 네 번 바꿨다

| | |
|---|---|
| **① 값에 6단계 경계** | `8/14/20/26/32%`. **경계값을 내가 정했다** — 색이 판정이 됐다(E8) |
| **② 색을 뺐다** | 숫자만 남기니 10행 × 5열이 **읽히지 않았다** |
| **③ 값에 상대 농도** | 표 안 최대값 기준. 경계는 없앴지만 **여전히 값에 칠한 것**이라 *"3차가 제일 붉다"* 가 **그 회차가 어려웠다는 뜻**인지 구분이 안 됐다 |
| **④ 지금 — 기수 대비 부호** | `#df6150` 나쁨 / 중립 / `#57b083` 좋음. **회차 난이도가 상쇄된 뒤**라 색이 그 반에 대해 말하고, **폭을 정하지 않아** 만든 숫자가 없다 |

**MG-02와 램프가 같아야 하는 이유** — 오퍼레이터와 매니저가 **같은 회차를 두고
이야기**한다. 한쪽 화면의 붉은색이 다른 뜻이면 **말이 안 통한다.**

**5단계가 아니라 3단계인 것이 손해가 아니다** — 5단계를 쓰려면 **중간 경계 넷**이
필요하고 그 넷에 근거가 없다. MG-02가 5단계를 쓸 수 있는 것은 **도달 단계 1~4단이
기획에 정의된 눈금**이기 때문이다.

**값의 뜻은 좌상단 축 라벨, 색·미집계 범례는 표 바로 아래**(MG-02와 같은 자리).

### 담당 매니저 이름을 쓰지 않는다

**반 값 옆에 사람 이름이 붙으면 그 반의 값이 그 사람 성적으로 읽힌다** — 18번 116줄
*"매니저 줄세우기가 되면 그 지표를 관리하려는 행동이 나온다"* 가 정확히 이 배치를
가리킨다. 누구와 이야기할지는 **OP-06 반·명단**과 **OP-01 조치 필요**에서 안다.

### 모집단이 회차마다 변한다 — 뺐다

`↓ 24명 (중도 이탈 1)`을 행에 썼는데 **`중도 이탈`은 기획에 없는 개념**이다. 문서의
`이탈`은 전부 **세션 창 이탈**(14번 4-4 `visibilitychange`)이고, 명부의 상태는
`활성 / 초대 대기 / 비활성`뿐이다(MG-05). 게다가 MG-05가 *"초대 대기·비활성은
히트맵·면담·대시보드 어디에도 안 나온다 — 측정 대상이 아니다"* 라고 못 박았으므로
**이 화면에도 나오지 않는다.**

분모 변화는 **미집계 열**이 이미 설명한다.

### 회차 열은 등록된 프로젝트만큼이다 — 8 고정이 아니었다

`1차~8차` 8칸을 그려놓고 5칸을 회색 해치로 채웠다. **틀렸다.**

| | |
|---|---|
| **미프 회차 수는 기수마다 다르다** | 14번 1274줄 *"미프 **6~8차**(4~7일)"* · 17번 109줄 *"기수마다 **6~8번** 반복"*. `8`은 **범위의 상한**이지 상수가 아니다 |
| **회차를 만드는 것은 오퍼레이터다** | 프로젝트를 등록하는 만큼 회차가 생긴다(OP-03 `[+ 프로젝트 생성]`). 시스템이 개수를 미리 알 방법이 없다 |
| **8칸을 그리면 없는 사실을 주장한다** | 5칸이 해치면 *"이 기수는 8회를 한다"* 로 읽힌다. 6회로 끝나는 기수에서는 **거짓**이다 |

**열 = 그 기수에 등록된 미프 프로젝트(회차 순).** 등록 안 된 회차는 **열이 없다.**
툴바 `회차 등록 5회`가 데이터에서 나온 수다.

| 열 상태 | 언제 |
|---|---|
| 값 | 리포트 발행됨 |
| `집계 전` `리포트 미발행` | 진행 중이거나 마감됐지만 미발행(10-1) |
| `—` `시작 전` | **등록됐지만** 아직 시작 안 한 프로젝트(OP-03 `준비 중`·`준비됨`) |

## 4-2-1. 열마다 데이터가 어디서 오나

이 화면이 그리는 값 전부의 출처다. **화면이 만들어낸 값이 없어야 한다.**

| 화면의 것 | 계산 | 원천 | 만들어지는 시점 |
|---|---|---|---|
| **위험자 비율** | `2단 이하 개념 ≥2인 학생 ÷ 채점 인원` | 9-2 판정 · 세션 채점 | **리포트 일괄 발행**(10-1) |
| **위험자 수 / 채점 인원** | 분자 = 위 판정 통과자, 분모 = 명부 − 미집계 | 명부(OP-06 반·명단) · 세션 상태 | 발행 시점 |
| **미집계 3종** | 미응시 / 무효 응시 / 중단 | 14-1 상태 3종 · 9-4 무효 판정 | 응시 창 종료 시점(개인별 24h · 10-1) |
| **`집계 전`** | 리포트 발행 여부 | 10-1 일괄 발행 | 회차 마감 |
| **`시작 전`** | 프로젝트 상태 | OP-03 `준비 중`·`준비됨` | 오퍼레이터가 등록할 때 |
| **회차 열 자체** | 등록된 미프 프로젝트 | OP-03 프로젝트 목록 | 오퍼레이터가 등록할 때 |
| **기수 대비 부호** | `그 반 비율`과 `기준선 비율`의 대소 | 위 값의 파생 | 같은 시점 |
| **반 / 팀** | 반 = 기수 고정 · 팀 = **프로젝트 종속** | OP-06 반·명단 / TeamMembership | 반은 기수 세팅, 팀은 회차마다 |
| **기수 간 비교 평균 도달** | 같은 개념의 도달 단계 평균 | 세션 채점 · 교안 `teaches` | 두 기수 모두 발행 후 |
| **교안 버전** | 그 회차에 연결된 교안의 버전 | OP-06 교안 | 프로젝트 구성 시점 |

**추가로 받아야 하는 데이터가 없다** — 전부 다른 화면이 이미 쓰는 값이다. 이 화면의
고유 기여는 **가로로 늘어놓는 것**뿐이다.

## 4-3. 필터와 정렬

| | |
|---|---|
| **계층** | **반별 / 팀** (개인 없음) — 계층이 반 선택 방식을 정한다 |
| **반 선택** | 반별=**복수**(체크박스) · 팀=**단일**(라디오) |
| **팀 선택** | **복수 선택** — 팀 계층에서만 나온다 |
| **회차 범위** | **시작 · 끝을 직접** — 기본 `1차 – 4차`(발행 + 진행 중) |
| **정렬** | 4종 (아래) — 기본 `최근 회차 나쁜 순` |

### 회차 범위 — 시작과 끝을 직접 고른다

`발행된 회차만` / `최근 3회` 같은 **프리셋으로 묶지 않는다.** 그 묶음의 근거를 기획에서
댈 수 없고(E8), 회차 수가 기수마다 6~8로 다르므로 **어느 기수에서는 안 맞는다.**

```
   시작        끝
 ✓ 1차       1차
   2차       2차
   3차       3차
   4차 미발행 ✓ 4차 미발행
   5차 시작전  5차 시작전
 ─────────────────────
 범위 밖 회차는 열이 없다 — 색도 그 구간에서만 읽는다
```

**기본은 `1차 – 4차`(발행 + 진행 중)** — 시작 전 회차를 열로 띄우면 **값 없는 칸이 표 폭을
먹는다.** 8차까지 가는 기수면 등록된 것을 전부 열로 두는 순간 가로 스크롤이 된다.

**범위 밖 회차는 열이 없다** — 색도 그 구간에서만 읽힌다. 좁히면 **앞 회차의 색이
사라지므로** `계속 붉은 반`이 안 보일 수 있다.

### 정렬 4개는 서로 다른 질문이다

| 정렬 | 질문 |
|---|---|
| **`최근 회차 나쁜 순`** | *"지금 어디가 제일 나쁜가"* — **기본.** OP-01 반 비교에서 넘어왔을 때 **거기서 본 순서와 같아야** 한다 |
| `기수보다 나쁜 회차가 많은 순` | *"어디가 계속 그런가"* — 키가 **붉은 칸 개수**이고 격자에 그대로 보인다 |
| `미집계 많은 순` | *"어느 반의 값을 믿기 어려운가"* — 분모가 많이 깎인 반 |
| `반 이름순` | *"내가 아는 그 반을 찾겠다"* — 위치가 고정된다 |

**정렬 키가 격자에 보인다**(E2) — 붉은 칸 개수는 **이미 화면에 있다.** 요약 열이 없어도
*"왜 이 순서인지"* 를 묻지 않는다.

**값 순위와 기수 대비는 다르다** — 최근 값이 가장 높은 반이 **그 회차가 전체적으로
어려웠던 탓이면 붉지 않다.** 기본을 값 순위로 두는 것은 **OP-01과 이어지기 위해서**이고,
이 화면이 하는 말은 색 쪽이다.

**`기수 전체` 행은 정렬에서 빠진다** — 비교 기준선이라 위치가 움직이면 기준이 아니게 된다.

**반은 복수 선택이다** — 나란히 놓고 비교하는 표이므로 단일 선택이면 쓸 수 없다.
10반을 한 번에 띄우면 **표가 아니라 목록**이 되고, 하나만 고르면 **기수 전체와만**
비교된다. **OP-01 반 비교에서 누르고 온 반들은 여기서 그대로 켜져 있어야** 한다.

**칩에 고른 이름을 나열하고 개수 배지를 붙인다** — 무엇을 보고 있는지가 툴바에 남는다.
드롭다운에 안내 문장을 쓰지 않는다 — **컨트롤 모양이 이미 그 말**이다.

**선택은 행만 줄인다** — 회차 열과 값은 그대로다.

### 조건 필터를 만들지 않는다 — 되돌린 것

한때 `⚠ 매 회차 오르는 반만` · `담당 없는 반만` 두 조건 필터와 그것만 남긴 뷰포트를
그렸다. **둘 다 걷어냈다.**

| 무엇 | 왜 틀렸나 |
|---|---|
| `⚠ 매 회차 오르는 반만` | **화면이 기준을 정해 걸러낸 것**이다. 어느 반을 볼지는 오퍼레이터가 정한다 — 임계값을 정하지 않는다는 이 화면의 규칙(4-2)을 **필터에서 어겼다** |
| `담당 없는 반만` | `미배정 반`은 **18번 99줄 OP-01 `조치 필요`의 한 줄**이고 *"조직 구조 문제"*(114줄)다. 이 화면의 **비교 축이 아니다** |
| `F반 담당 없음` 상태 표기 | 그 상태를 근거로 *"매니저 공백이 시작된 회차부터 벌어졌다"* 는 **인과를 화면이 만들었다.** 기획에 없는 서술이다 |
| 기본 정렬 `매 회차 오름 → 최근 높은 순` | 단조성을 1차 키로 쓰면 **정렬이 곧 판정**이 된다. `최근 회차 나쁜 순`으로 되돌렸다 |

**방향 열은 남는다** — 격차의 **단조성 표기**이고 걸러내지 않는다. 걸러내는 것과
**표시하는 것**은 다르다.

**담당 매니저 이름은 남는다** — 공백을 보기 위한 것이 아니라 **누구와 이야기할지**를
위해서다. 빨간 `담당 없음` 상태는 없다.

## 9. 판정 줄과 액션 버튼을 지웠다

표 아래에 `⚠ 이번 회차는 2팀·5팀에 몰렸다 — 지난 회차의 그 팀이 아니다 …` 같은 줄과
버튼을 뒀다가 **전부 뺐다.**

| 줄이 하던 일 | 문제 |
|---|---|
| 화면의 숫자를 문장으로 다시 읽음 | `2팀 3/4`는 격자에 이미 있다 |
| **읽는 법을 가르침** | *"가로로 읽으면 안 된다"* — 화면이 사용법을 가르치는 것 |
| 해석을 대신함 | *"어느 팀이 무너졌나"* — 오퍼레이터가 할 판단 |

**시스템만 아는 것은 이미 격자 위에 있다** — 색(기수 대비 부호) · `집계 전` · `시작 전` ·
미집계 막대. 문장은 그걸 반복한 것이었다.

**문장은 데이터가 다르면 거짓말을 한다.** v1이 `AI 요약 일치검증`을 만들어야 했던
이유이고 15번이 그 기능을 삭제했다 — 사람이 쓴 판정 문장은 검증 없는 AI 요약이다.

### 버튼 7개 중 살아남은 것이 없다

| 버튼 | 왜 뺐나 |
|---|---|
| `3차 · 2팀 명단` | **그런 화면이 없다** — OP-04 현황은 *반별* 제출·응시율이다 |
| `기수 리포트에 기록` | OP-05가 *"집단 미달은 발생 사실만, 처리 기록을 화면이 요구하지 않는다"* 로 정했다 — **모순** |
| `C반 팀별로 보기` | 반 이름 클릭이 이미 한다 |
| `반별로 돌아가기` | 계층 토글이 이미 있다 |
| `기수 간 비교` | 탭이 이미 있다 |
| `회차 설계 보기` · `교안에서 보기` | 존재하는 화면이지만 **판정 줄이 없어지면 붙을 자리가 없다** |

**남긴 것** — 셀 안 `아직 판단 안 함 · 2회 · 3회부터`처럼 **값이 왜 없는지** 말하는 것과
빈 상태 설명(반 미선택 · 비교 기수 없음). 해석이 아니라 부재의 이유다.

## 10. 뷰포트

**뷰포트는 기능이 아니다.** 이 화면은 **탭 2개**이고, 뷰포트 7개는 그 두 탭이 **상태·계층·
데이터에 따라 어떻게 보이는지**를 나눠 그린 것이다(I2 — 상태마다 `.rpage`를 나눈다).

| # | | 성격 | 왜 나눠 그리나 |
|---|---|---|---|
| ① | 회차 흐름 | **화면** | 기본 상태 |
| ② | 반 복수 선택 | **인터랙션** | 드롭다운 열린 결과(I1) |
| ③ | 회차 범위 | **인터랙션** | 시작·끝 선택 |
| ④ | 정렬 | **인터랙션** | 정렬 키 4개가 서로 다른 질문 |
| ⑤ | 팀 | **계층 전환** | 반이 **단일 선택**이 되고 기준선·범례가 그 반으로 바뀐다 |
| ⑥ | 기수 간 비교 | **다른 탭** | 값이 평균 도달로 · 색이 절대 눈금으로 바뀐다 |
| ⑦ | 비교할 기수 없음 | **빈 상태** | 첫 기수 |

**데이터 케이스 뷰포트를 지웠다.** `한 반만 오를 때`와 `2회차까지` 둘을 그렸는데,
전자는 **같은 표의 다른 데이터**일 뿐이고(판정 줄만 다르다), 후자는 **색이 1회차부터
읽히면서 특별한 상태가 아니게** 됐다. 남은 것은 전부 **인터랙션·계층·빈 상태**다.
