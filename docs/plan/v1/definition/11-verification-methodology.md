# 이해도 검증 방법론 (확정)

> **이 문서가 10번을 대체한다.** 10번은 "5축이 적절한가"를 검토한 제안 문서였고, 이 문서는 그 논의를 거쳐 확정된 방법론이다. 10번은 논의 경로로만 남긴다.
> 재시험·리포트·화면·비용·운영 결정은 [09번](09-design-answers.md)에 있다.
>
> **아직 안 정한 것은 11절에 모아뒀다.** 본문에 적힌 것은 결정된 것이다.
>
> ⚠️ **5-1 · 5-3 · 5-5는 [12번 채점·진행 규칙](12-scoring-rules.md)으로 갱신되었다.** 그쪽이 최신이다 — 종료 규칙의 단위, 4단 범위, 힌트 단계가 바뀌었다.

## 0. 한 장 요약

| | 결정 |
|---|---|
| **재는 방식** | 항목별 점수 합계가 아니라 **도달 단계(계단)** |
| **계단** | 0 무응답 · 1 기술 · 2 한계 · 3 대안 · **4 판단(왜 이걸 골랐나)** |
| **5축 루브릭** | 유지. 계단은 "어디까지", 루브릭은 "그 안에서 얼마나" |
| **무엇에 대해** | 학습목표(무엇을 물을지) + 코드 지점(어디서 물을지) **2층 앵커** |
| **종료 규칙** | **2연속 실패**까지는 계속 물어본다 |
| **시간** | 단계 통과마다 예산 지급 · 중위 15분 · 상한 24분 |
| **4단 범위** | 3문제 중 **가장 잘 답한 1문제만** |
| **힌트** | 3단 규격(재진술 / 위치 / 선택지) · 단계당 2회 · 선택지는 세션당 1회 |
| **미프 시점** | 제출 후 24시간 안 · **세션은 분산, 리포트는 일괄** |
| **빅프 시점** | 첫 동작 코드 → +2주 → 마감. **3회** |
| **위험 판정** | **절대** — 2단 이하 학습목표 |
| **우수 교육생** | **반 상위 1~2명** (상대). 반마다 존재. 근거를 함께 표시 |
| **피드백** | 막힌 만큼 두껍게. **못한 학생이 더 많이 받는다** |
| **개발 전** | 검증 A(표현·30분) + 검증 B(위계·1시간) **필수** |

## 1. 무엇을 재는가

제품의 주장은 하나다.

> 학생이 제출한 코드를, 그 학생이 실제로 이해하고 있는지 확인한다.

AI로 코드를 만들 수 있으니 **산출물만으로는 학습 여부를 알 수 없다.** 그래서 대화로 확인한다.

그리고 이 도구의 성격이 정해졌다.

| | |
|---|---|
| **무엇인가** | **매니징 도구(B2B LMS)** + 이해도 검증이라는 특수 기능 |
| **1순위 사용자** | **매니저** |
| **평가인가 학습인가** | **둘 다.** 평가이되 학습 지원 |
| **개인 진단인가 수업 진단인가** | 평소엔 **개인 진단**, 기수 끝나면 **수업 진단**(다음 기수 개선) |
| **결과물 목표** | **v1 MVP.** 현실적 구현 가능성이 우선. 선택과 집중 |

**이 다섯 줄이 아래 모든 결정의 기준이다.** 판단이 갈릴 때는 여기로 돌아온다.

## 2. 계단 — 왜 점수 합계를 버리는가

### 2-1. 기존 방식의 문제

5축 × 5점 = 25점 합계에는 두 가지 문제가 있었다.

**① 서로 다른 것을 같은 가중으로 더했다.** 5개 축 중 일부는 이해도를 재고 일부는 다른 것을 쟀다. 그 합계로 위험 학생을 찾으니 잘 맞지 않았다.

**② 하나의 이해도를 여러 축이 다르게 잘라놓았다.** 실측 사례로 보면 명확하다.

주차 위반 탐지 프로젝트를 낸 학생이다.

> **반례 질문:** "악의적 사용자가 킥보드가 아닌 물체를 위장하면?"
> **답변:** "아닙니다. 킥보드인지를 확인하고가 먼저입니다." → **반례 대응 2점**
>
> **마지막 질문:** "이 판단이 문제가 될 수 있다는 점을 생각해보면?"
> **답변:** "일단 해당 문제는 저희도 인지를 했습니다. 그렇기에 연속 촬영을 하고 threshold와 시간 기반 검증 로직을 구성했습니다." → **자기 수정 4점**

점수만 보면 **"반례에 약한데 자기 수정은 잘한다"** 로 읽힌다. 무엇을 가르쳐야 할지 알 수 없다.

실제로는 **이 학생이 그 문제를 이미 알고 대비까지 해뒀다.** 처음엔 방어적으로 답했을 뿐이다. **이해도는 하나인데 축 두 개가 그것을 다르게 잘라놨다.**

### 2-2. 확정 계단

이해했다는 것은 **얼마나 깊이까지 설명할 수 있는가**다. 그리고 그 깊이는 항목이 아니라 **순서가 있는 단계**다.

| 단계 | 이름 | 학생이 할 수 있는 것 | 질문 |
|---|---|---|---|
| **0** | 무응답 | — | (답이 없거나 요점을 놓침) |
| **1** | **기술** | 무엇을 하고 어떻게 연결되는지 말한다 | "이 부분이 무슨 일을 하나요? 어디랑 연결되나요?" |
| **2** | **한계** | 언제 깨지는지 말한다 | (구체적 상황을 던지고) "이러면 어떻게 되나요?" |
| **3** | **대안** | 다른 방법이 있다는 것을 말한다 | "다른 방식으로 할 수도 있었을까요?" |
| **4** | **판단** | 그중 왜 이걸 골랐는지 말한다 | "그 대안들 중에 왜 지금 방식을 골랐나요?" |

**이 순서는 위계다.** 3단을 설명하는 학생은 2단도 설명할 수 있다. 그래서 하나의 숫자로 적어도 정보가 손실되지 않는다.

### 2-3. 왜 최상위가 "왜 골랐나"인가

이 순서를 정하는 데 근거가 넷이다.

**① SOLO 분류가 우리 상황에 맞는다.**

Bloom은 "가르칠 목표"의 위계이고, **SOLO taxonomy**(Biggs & Collis, 1982)는 **"학생 답변의 구조"** 를 판정하는 틀이다. 우리가 하는 일이 정확히 그것이다.

| SOLO | 답변의 모습 |
|---|---|
| Prestructural | 요점을 놓친 답 |
| Unistructural | 한 가지 측면만 |
| Multistructural | 요소를 나열하나 **연결을 못 함** |
| Relational | 요소들을 **통합해 관계로** 설명 |
| Extended abstract | **새 맥락으로 일반화·전이** |

**② 기존 루브릭이 이미 SOLO로 쓰여 있다.** 이게 결정적이다.

| 기존 코드_이해 루브릭 | SOLO |
|---|---|
| 1점 "그냥 이렇게 했습니다" | Prestructural |
| 2점 개별 요소는 되나 전체 구조 파악 안 됨 | Unistructural |
| **3점 각 구성 요소는 알지만 연결 관계 설명 불가** | **Multistructural** |
| **5점 구성 요소 간 관계와 데이터 흐름을 정확히 설명** | **Relational** |

**우연이 아니다.** 루브릭을 쓴 사람이 이미 옳은 축을 잡았다. **계단은 새 발명이 아니라 그 축을 명시화하는 것이다.** 그래서 루브릭을 버리지 않는다(3절).

**③ "왜"는 두 종류이고, 순서가 낮은 쪽을 걸러낸다.**

반론이 있었다 — "AI가 짠 코드를 낸 학생은 '왜'에 아예 답할 수 없으니, '왜'는 최상위가 아니라 최하위 필터 아닌가."

**틀렸다. "왜"가 두 종류이기 때문이다.**

| | 예 | 성격 |
|---|---|---|
| **의도 진술** | "성능 때문에요" | 사후 합리화가 쉽다 → 낮은 단계 |
| **선택 정당화** | "A와 B가 있었는데 우리 제약이 C라서 A를 골랐다" | 대안 공간 인식이 필수 → **최상위** |

기존 루브릭이 이걸 이미 알고 있다. **설계_논리 2점 = "의도를 물으면 사후적으로 짜맞추는 티가 남".**

**그래서 순서가 오염 필터가 된다.** 대안(3단)을 못 낸 학생에게 "왜 골랐나"를 물으면 사후 합리화만 나온다. **대안을 먼저 요구하고 그다음에 선택 이유를 물으면 짜맞추기가 구조적으로 어려워진다.**

**④ 검증이 어려운 지표를 최상위에 두는 것이 맞다.**

- "언제 깨지나" — 구체적 조건을 대야 하고 코드로 확인 가능 → **검증 쉬움**
- "왜 골랐나" — 진술이므로 → **검증 어려움**

최상위는 소수만 도달하므로 오판의 영향 범위가 작다. 반면 위험 학생 판정은 검증 쉬운 하위 단계에서 이뤄진다. **오판 비용이 큰 쪽에 검증 쉬운 지표를 놓는 것**이 측정 설계의 기본이다.

### 2-4. 계단으로 바꾸면 풀리는 것

**총점을 만들 필요가 없다.** "코드 이해 3점 + 설계 논리 4점 = 7점"이 무슨 뜻인지 아무도 설명할 수 없었다. 도달 단계는 더할 필요가 없다.

**매니저가 바로 읽는다.**

> **지금:** 코드 이해 3 · 설계 논리 3 · 대안 비교 5 · 반례 대응 4 · 자기 수정 미검증
> **계단:** 왜 그렇게 했는지까지는 설명함. 언제 문제가 되는지는 설명하지 못함. **(2단)**

두 번째는 설명이 필요 없고 **무엇을 가르쳐야 하는지가 문장에 들어 있다.** 비전공자 매니저가 실사용자이므로 이건 취향이 아니라 요구사항이다.

**결측이 사라진다.** 기존 방식은 조기에 잘 방어한 학생이 마지막 질문까지 가지 않아서 자기 수정 점수가 비어 있었다. 잘한 학생은 4개 축, 못한 학생은 5개 축으로 채점되어 나란히 놓을 수 없었다. 계단은 어디서 멈췄든 **그것이 답이다.**

**"안 한 것"과 "못한 것"이 갈린다.** 0단을 따로 두면 무성의 응시가 실력 판정으로 흘러들지 않는다.

## 3. 5축 루브릭의 자리 — 버리지 않는다

**계단은 "어디까지 갔나"만 말한다. "그 단계 안에서 얼마나 좋았나"는 말하지 않는다.** 그래서 두 층으로 쓴다.

| | 쓰임 |
|---|---|
| **도달 단계** | **판정용** — 위험·우수, 재시험 대상, 히트맵 |
| **축별 서술** | **진단용** — 리포트에 "무엇이 어떻게 부족했는지" |

기존 루브릭 문장이 좋다. 예를 들어 설계 논리 2점이 *"의도를 물으면 사후적으로 짜맞추는 티가 남"* 이다. **이건 실제로 사람을 여러 번 겪어본 사람이 쓴 문장이고, 새로 쓰면 이 수준이 안 나온다.**

### 축과 단계의 대응

| 단계 | 대응하는 축 |
|---|---|
| 1단 기술 | 코드 이해 |
| 2단 한계 | 반례 대응 |
| 3단 대안 | 대안 비교 |
| 4단 판단 | 설계 논리 |
| (전 단계) | 자기 수정 — **판정에서 빼고 관찰 항목으로** |

**자기 수정을 판정에서 빼는 이유:** 이건 이해도가 아니라 태도·메타인지다. 그리고 측정 조건에 결함이 있다 — 질문 설계가 "학생이 스스로 인정하도록 **유도**"하게 되어 있는데 채점 기준은 "**스스로** 제시"였다. 유도해놓고 자발성을 채점할 수는 없다.

**대신 관찰 항목으로 남긴다.** "실력은 부족하지만 지적을 받아들이는 학생"과 "인정하지 않는 학생"은 개입 방법이 다르다. **성적이 아니라 개입 설계 정보다.**

> **대안 비교 축은 3단으로 복귀했다.** 10번 문서에서 "지식·경험의 폭이라 이해도가 아니다"라며 제외했는데, 그건 4단 순서를 잘못 잡은 데서 나온 부작용이었다. 순서를 바로잡으면 대안 인식은 위계의 정당한 중간 단계다.

## 4. 무엇에 대해 묻는가 — 앵커 2층

### 4-1. 지금 방식의 문제

문항 소재를 **코드에서 자동으로** 뽑고 있었다. 코드를 훑어서 구조적으로 이상한 지점(중복 정의, 관심사 분리 안 됨 등)을 찾고 거기에 질문을 붙인다.

**두 가지가 깨진다.**

**① 난이도가 통제되지 않는다.** 학생이 우연히 복잡하게 짰으면 어려운 질문을 받고, 단순하게 잘 짰으면 쉬운 질문을 받는다. **잘 짤수록 불리하다.**

**② 교안과 무관하다.** 팀이 세운 원칙이 *"학습 목표가 평가와 연결이 되어야 개념 이해 여부를 판단할 수 있다"* 인데, 코드 스멜은 배운 것과 상관없다.

### 4-2. 2층으로 나눈다

```
학습목표  = 무엇을 물을지   → 반 전체가 같음 (난이도·비교 가능성)
코드 지점 = 어디서 물을지   → 학생마다 다름 (개인화)
```

**두 층을 나누는 것이 핵심이다.** 학습목표만 앵커로 쓰면 팀원 전원이 거의 같은 질문을 받는다(미프는 팀당 레포 하나일 수 있다). 그러면 문제 공간이 코드 전체에서 학습목표 3개로 좁아진다.

**같은 "Service 역할 분리"를 A는 `ingress.yaml`에서, B는 `service.yaml`에서 묻는다.** 비교 가능성은 유지되고 개인화는 확보된다.

### 4-3. 미프 / 빅프

| | 미프 | 빅프 |
|---|---|---|
| **앵커** | **학습목표** (교안 기반) | **본인 커밋 영역** |
| 문제 수 | 3개 | 1~2개 |
| 범위 | 전체 코드 | 자기 영역 |
| 성적 | 반영 | **미반영** — 성장 지표 + 팀 내부 파악 |

**계단은 양쪽 동일하다.** 앵커만 다르다. 그래서 **미프와 빅프의 계단 값을 비교할 수 있다** — 이게 성장 지표가 성립하는 근거다(7-2).

### 4-4. 학습목표는 매니저가 3~5줄 입력한다

**PDF 자동 추출을 만들지 않는다.** 그걸 만들면 완성되기 전까지 아무것도 못 하고, 실제 교안은 암호가 걸려 있어 파싱이 바로 막힌다.

> 프로젝트 만들 때 → **"이번 프로젝트 학습목표"** 3~5줄 입력

매니저는 강의계획서에 있는 내용을 옮겨 적으면 된다. 개발은 텍스트 배열 저장, **반나절.**

**실제 교안 확인 결과, 학습목표가 이미 적정 입도로 적혀 있다.** 받은 Kubernetes·CICD 교안(76쪽)의 두 번째 슬라이드가 일자별 일정표인데 사실상 학습목표 목록이었다.

| | 항목 |
|---|---|
| 1일차 | 쿠버네티스 아키텍처 · 컨테이너 오케스트레이션 원리 · Kubernetes 기본 리소스 |
| 2일차 | Service·Ingress · 볼륨과 환경변수(ConfigMap/Secret) · CICD Pipeline 개요 |
| 3일차 | AWS CodePipeline · CodeBuild로 빌드 · CodeDeploy로 배포 |

**12개, 그대로 문항 소재로 쓸 수 있다.**

> 나중에 자동 추출을 만들 때 **볼 곳과 보면 안 되는 곳**이 있다.
> **볼 곳** — 일정표 슬라이드, 챕터 제목, 챕터별 Summary 슬라이드
> **보면 안 되는 곳** — "과정 목표" 슬라이드. *"운영 효율화 역량 확보"* 수준으로 추상적이라 질문 생성에 못 쓴다

### 4-5. 부수 효과 — 교안이 선행 필수가 아니게 된다

지금은 `교안 등록 → 매핑 승인 → 질문 생성`이라 교안 없이는 아무것도 안 된다. 바꾸면 `학습목표 입력 → 질문 생성`이고, 교안은 리포트의 "참고 위치"를 풍부하게 하는 부가 입력이 된다.

**암호 걸린 PDF 하나가 기수 개설 전체를 막는 상황이 사라진다.**

## 5. 세션 흐름

### 5-1. 종료 규칙 — 2연속 실패까지 물어본다

> **→ [12번 2절](12-scoring-rules.md)로 갱신.** "2연속"의 단위가 정의돼 있지 않았다(힌트인지 단계인지). 12번에서 **단계 단위**로 확정.

한 단계 실패로 종료하지 않는다.

```
1단 실패 → 2단을 물어본다 → 2단도 실패 → 종료
1단 실패 → 2단 통과       → 계속 (1단은 표현 문제였던 것)
```

**두 가지 이유다.**

**① 위계가 아직 검증되지 않았다.** 조기 종료의 논리는 "1단을 못 했으니 2·3·4단도 못 할 것"인데, 이건 위계가 엄격할 때만 성립한다. 그리고 예외가 반드시 있다 — 설명하는 게 약해서 1단에서 막혔지만 한계는 아는 학생, 오래돼서 잊었지만 개념은 아는 학생. **검증 안 된 가정의 비용을 잘라진 학생이 혼자 부담하게 할 수 없다.**

**② 이 구조가 위계 검증을 겸한다.** "1단 실패 후 2단 통과"가 자주 나오면 위계가 틀린 것이고, 그 데이터가 운영 중에 자동으로 쌓인다.

### 5-2. 시간 — 단계 통과마다 예산을 지급한다

**고정 상한을 두지 않는다.** 계단은 정의상 **능력 검사**(어디까지 가나)이고 속도 검사(정해진 시간에 몇 개)가 아니다. 시간으로 자르면 잘라낸 곳이 능력의 한계가 아니라 시간의 한계가 된다.

그리고 시간을 촘촘히 잡으면 **재려는 것이 아닌 것**(타이핑 속도, 코드 읽는 속도)이 점수에 섞인다. 4단은 가장 생각할 게 많은 단계라 이 오염이 가장 크다.

**해법 — 예산을 미리 나눠주지 않고 단계를 통과할 때마다 지급한다.**

| 단계 | 지급 | 누적 |
|---|---|---|
| 1단 기술 | **3분** (코드 읽기 포함) | 3분 |
| 2단 한계 | +2분 | 5분 |
| 3단 대안 | +2분 | 7분 |
| **4단 판단** | **+3분** ← 트리거 | 10분 |

**얕게 끝나는 학생은 시간이 필요 없다.** 1단에서 막힌 학생에게 30분을 줘도 결과가 같다.

| 학생 | 문제당 | 3문제 총 |
|---|---|---|
| 1단에서 막힘 | 3~5분 | **9~15분** |
| 2단 정지 (중위 예상) | 5분 | **15분** |
| 3단까지 | 7분 | 21분 |
| 4단까지 | 10분 | 24분 |

**중위 15분, 상한 24분.**

### 5-3. 4단은 3문제 중 1문제만

> **→ [12번 4절](12-scoring-rules.md)에서 철회.** **3문제 전부 이어서 간다.** 상한도 24분 → 30분.

**4단(선택 정당화)은 우수 판별용이고 위험 판별에는 필요 없다.** 그리고 측정 원리상 **최상위 능력은 한 번의 명확한 시연으로 충분하다** — 3번 반복해야 확신이 생기는 건 경계선 판정이고, 4단 도달은 거의 이진적이다.

> 3문제 전부 1~3단 → 그중 **가장 잘 답한 1문제만** 4단 추가

### 5-4. 답변 길이는 3~5문장으로 안내한다

실측 답변이 대부분 3~5문장이었고 **한 문장 답변은 1점을 받았다.** 즉 그 길이면 판정에 충분하다. 그리고 기존 명세에도 "장황함 편향은 길이 페널티"가 이미 적혀 있다 — 길게 쓰는 게 유리하면 안 된다.

**하드 제한이 아니라 안내로 둔다.** 제한하면 그것도 재려는 것이 아닌 것을 재게 된다.

### 5-5. 힌트 규격 — 3단 고정

> **→ [12번 3절](12-scoring-rules.md)로 갱신. 2단으로 축소** — 선택지 힌트는 측정 가치가 0이라 삭제.

**힌트를 즉흥적으로 주면 안 된다.** 같은 실력의 두 학생이 한 명은 1번, 한 명은 3번 받으면, 그 차이가 학생 차이가 아니라 생성 차이가 된다. 그러면 "혼자 갔는지"가 신호로 쓸 수 없다.

이건 이미 확립된 방법이 있다. **동적 평가(dynamic assessment)** 계열의 **graduated prompting**(Campione & Brown, 1987)이다. 힌트를 약한 것부터 강한 것 순서로 **미리 고정**해두고, **몇 번째 힌트에서 통과했는지**를 지표로 쓴다. Vygotsky의 근접발달영역을 측정에 옮긴 것으로, "혼자 할 수 있는 것"과 "도움받으면 할 수 있는 것"의 거리를 잰다.

| | 힌트 | 내용 | 자력 판정 |
|---|---|---|---|
| **1** | **재진술** | 질문을 다르게 표현. 정보 추가 없음 | 자력 유지 |
| **2** | **위치 제시** | "이 파일의 이 함수를 보세요". 답은 없음 | 부분 자력 |
| **3** | **선택지 제시** | "A와 B 중 어느 쪽일까요" | **자력 아님** |

**단계당 최대 2회. 3번 힌트는 세션 전체에서 1회만.**

> **이게 기존 결함 하나를 같이 고친다.** 실측에서 질문에 보기 세 개가 들어가 있었고, 학생이 "저는 3번"이라고 답해 **대안 비교 5점**을 받았다. 대안을 제시한 게 아니라 골랐다. 반면 보기가 없던 질문을 받은 학생은 1점이었다.
> **보기를 주는 것은 3번 힌트다.** 힌트로 명시되고 기록되어야 하며, **그 답에 만점을 줄 수 없다.**

### 5-6. 붙여넣기와 시간 제한

| 할 것 | 비용 |
|---|---|
| 붙여넣기 이벤트 **차단** | JS 몇 줄 |
| 차단해도 **시도는 기록** | 매니저 화면에 플래그 |
| **단계별 시간 예산**(5-2) | 다른 AI에 물어볼 여유를 없앰 |

우회는 가능하다. 하지만 마찰을 만드는 것으로 충분하고, 예외를 무한히 가정하면 끝이 없다. **자동 부정행위 판정은 하지 않는다** — 오탐 비용이 크고 "확정은 사람이" 원칙에도 걸린다.

**그리고 이 한계는 명시해야 한다.** 세션 중에 학생이 다른 AI에 물어보는 것을 방법론으로는 막을 수 없다. 지금 실제로 작동하는 방어는 **자기 코드의 특정 라인을 근거로 묻는 것** 하나이고, 여기에 **시간 압박**이 더해지는 정도다. "계단으로 바꾸면 AI 대필을 잡을 수 있다"는 기대는 성립하지 않는다.

## 6. 동등성 설계 — 이걸 안 하면 계단은 실패한다

계단은 학생마다 다른 수의 질문을 받게 만든다. **그게 학생에게서 무언가를 빼앗는다는 지적이 있었고, 그 지적이 맞다.** 세 갈래의 근거가 있다.

### 6-1. 무엇이 문제인가

**① 적응형 시험의 알려진 대가.** GRE·GMAT 같은 적응형 시험은 학생마다 다른 문항을 준다. 시간당 측정 정확도를 최대화하는 대신 **표면 타당도**와 **체감 공정성**을 잃는다. Messick의 타당도 논의에 **결과 타당도**라는 축이 있는데, **학생이 불공정하다고 인식하면 도구가 기술적으로 정확해도 정당성을 잃는다.**

**② 학습 가치가 거꾸로 간다.** 설명하게 하는 것 자체가 학습이다(self-explanation effect, Chi et al. 1994). 그런데 못하는 학생은 3개 질문, 잘하는 학생은 최대 12개를 받는다. **도움이 가장 필요한 학생이 가장 적게 받는다.** 교육학에서 **마태 효과**(Stanovich, 1986)라 부르는 구조다. 학습 지원 도구에서 이건 설계 실패다.

**③ 그런데 전원 동일 4턴도 답이 아니다.** 도달 범위 밖의 질문은 학습을 만들지 않는다(ZPD). 1단을 못 한 학생에게 4단을 물으면 배우는 게 아니라 **무력감을 학습한다** — 실측에서 이미 봤다. 어떤 학생은 마지막 질문에 **질문 문장을 그대로 복사해 붙였다.** 그게 무력감의 모습이다. 그리고 그 답변도 점수가 되어 전 축 1점이 나왔다.

### 6-2. 해결 — 측정은 적응적으로, 받는 것은 동등하게

**계단은 채점 모델이지 세션 흐름이 아니다.** 둘을 분리하면 양쪽을 얻는다.

**장치 ① 2연속 실패까지 보장** (5-1) — 한 번 막혔다고 끝나지 않는다.

**장치 ② 막힌 만큼 피드백이 두꺼워진다.**

측정이 끝난 뒤, **막힌 단계에 대한 해설과 교안 위치를 제공한다. 채점하지 않는다.**

| | 측정 | 피드백 | 총량 |
|---|---|---|---|
| 못하는 학생 | 짧음 (9~15분) | **두꺼움** | 비슷 |
| 잘하는 학생 | 김 (24분) | 얇음 | 비슷 |

**받는 것의 총량이 비슷해지고 내용이 반대로 배분된다.** 잘하는 학생에게는 더 어려운 질문을, 못하는 학생에게는 더 많은 설명을. **이게 차별화 수업의 원칙과 일치한다** — 동일한 것을 주는 게 형평이 아니라, 필요에 맞게 다르게 주는 것이 형평이다.

**MVP에서는 리포트로 갈음한다.** 세션 안에 학습 구간을 넣으면 개발이 늘고, 이미 정한 리포트 구성에 그게 들어 있다(문제별 "어디가 부족했는지 + 교안 참고 위치"). 여유가 생기면 세션 안에서 즉시 해설 + 다시 설명해볼 기회로 확장한다.

**장치 ③ 문구 — 비용 0, 체감 개선**

> ❌ "세션이 종료되었습니다"
> ✅ "이 부분은 리포트에서 자세히 설명해드릴게요"

"잘려나간 것"이 아니라 "여기가 볼 지점"으로 읽힌다.

### 6-3. 동등함을 어디서 지키는가

| | 다르게 | 같게 |
|---|---|---|
| 질문 개수·깊이 | ✓ | |
| **기회** | | ✓ 2연속 실패까지 보장 |
| **세션 시간** | | ✓ 측정 + 피드백 합계가 비슷 |
| **받는 정보량** | | ✓ 내용이 반대 배분 |
| **판정 기준** | | ✓ 같은 계단·같은 루브릭 |

**"같은 문제를 받는 것"이 아니라 "같은 자로 재고 같은 만큼 돌려받는 것"이 동등성이다.** 앞의 것은 지킬 수 없고 지킬 필요도 없다.

## 7. 언제 검증하는가

**미프와 빅프는 순차다.** 미프가 앞에서 몇 개월, 빅프가 마지막. 겹치지 않으므로 일정 충돌이 없다.

### 7-1. 미프 — 세션은 분산, 리포트는 일괄

두 요구가 충돌하지 않는다. **시점을 나누면 된다.**

```
학생 제출 → (그 시점부터 24시간 안) 세션      ← 분산
                                    ↓
              미프 마감 → 리포트 일괄 발행     ← 매니저는 한꺼번에
```

**세션을 제출 직후에 붙이는 이유** — 시간이 지나면 **"잊어서 못 답한 것"과 "이해 못 한 것"이 섞인다.** 미프는 4~7일짜리라 하루만 지나도 세부가 날아간다. 그러면 측정하는 게 이해도가 아니라 기억이 된다.

**부수 효과가 둘이다.** 먼저 끝낸 학생이 먼저 보므로 **자연 분산**되어 동시 접속이 흩어진다. 그리고 리포트를 마감 후 일괄 발행하면 **먼저 본 학생이 답을 흘리는 경로**도 줄어든다.

**리포트를 일괄로 하는 이유** — 매니저는 25명을 한 번에 훑어야 한다. 며칠에 걸쳐 하나씩 오면 매번 맥락을 다시 잡아야 한다.

### 7-2. 빅프 — 3회, 2주 간격

빅프의 목적은 **성장 지표** + **팀 내부에서 잘하는/못하는 사람 파악**이다.

**첫 측정 시점을 주차로 정하지 않는다.** 기획이 길어지든 짧아지든, **"첫 동작하는 코드가 나온 시점"** 이 자연스러운 기준점이다. 그때는 "정할 게 많아서 시간이 간다"는 문제도 없다 — 이미 뭔가 만들어진 상태다.

| | 시점 | 역할 |
|---|---|---|
| **1회차** | 첫 기능이 동작할 때 | **기준점.** 성장 계산의 시작값 |
| **2회차** | 1회차 + 2주 | **개입 트리거.** 여기서 발견하면 고칠 시간이 남는다 |
| **3회차** | 마감 | **성장 확인.** 개입용이 아니므로 마감에 붙여도 된다 |

**기준점을 건너뛰면 안 된다.** 성장을 재려면 시작 값이 있어야 한다. 중간과 끝만 있으면 그 사이 변화만 보이고 초반의 낮은 상태가 기록되지 않는다.

**2회차가 가장 중요하다.** 형성평가의 기본은 "고칠 시간이 남아 있을 때 측정하는 것"이다. 마감 직전에만 재면 진단만 하고 처방을 못 한다.

> **줄여야 한다면 3회차를 뺀다.** 성장 확인은 나중에 해도 되지만 **개입 기회는 지나가면 없다.** 1·2회차만 있어도 그 사이 변화로 성장이 읽힌다.

**성장 서술이 미프까지 이어진다.** 순차이므로 미프 구간 전체의 계단 평균이 있고, 빅프 1회차를 그것과 비교할 수 있다.

> 미프 평균 2단 → 빅프 1회차 2단 → 빅프 3회차 3단
> = "미프 수준을 유지하다가 빅프 후반에 올라갔다"

## 8. 판정

### 8-1. 위험 — 절대 기준

**2단 이하인 학습목표가 있으면 위험 신호다.** 기준선 숫자를 정하는 논쟁이 필요 없다.

반 평균이 낮아도 못하는 사람은 못하는 것이다. **기준에 못 미치면 도와야 하므로 절대 기준이 맞다.**

### 8-2. 위험 유형

| 이름 | 정의 | 최소 표본 |
|---|---|---|
| **단계 하락** | 이전 미프보다 도달 단계가 내려감 | 미프 2개 |
| **지속 저점** | 여러 미프에서 계속 2단 이하 | 미프 2~3개 |
| **무효 응시** | 0단 (8-4) | 1개 · 즉시 |
| **코드 대비 이해 부족** | 빅프 — 기여도 높음 · 계단 낮음 | 빅프 1회 |
| **참여 저조** | 빅프 — 기여도 낮음 · 계단 낮음 | 빅프 1회 |

**"기초 공백"을 "지속 저점"으로 바꾼 이유** — 데이터가 말해주는 것은 "계속 낮다"(결과)이고 "기초가 비어 있다"(원인)가 아니다. 계속 낮은 이유는 기초 부족일 수도, 참여 부족일 수도, 말로 설명하는 게 약한 것일 수도 있다. **원인을 이름에 박으면 매니저가 진단을 건너뛰고 처방부터 한다.**

실제로 오분류가 관측됐다(8-4).

**유형은 겹칠 수 있다.** 한 학생이 미프에서 "지속 저점"이면서 빅프에서 "코드 대비 이해 부족"인 건 흔하다. 하나만 고르게 만들면 우선순위 규칙이 필요한데 그 규칙에 근거가 없다.

**정렬은 "2단 이하 학습목표 개수"로 한다.** 근거가 있고 계산이 명확하다. 반이 25명이라 한 화면에 다 들어오므로 정렬이 완벽하지 않아도 매니저가 전체를 훑을 수 있다.

### 8-3. 우수 교육생 — 반 상위 1~2명

**반마다 존재한다.** 그 반에서 가장 높은 1~2명이 우수 교육생이다.

**왜 상대 기준인가** — 용도가 상대적 질문이다. "누구를 팀 리더로 쓸까", "이 반에서 눈여겨볼 사람이 누구인가"는 그 반 안에서의 비교다. 그리고 매니저가 25명 중 진짜 눈여겨볼 사람은 1~2명이다. 3명을 넘어가면 "눈여겨본다"가 아니라 "목록을 관리한다"가 되어 실용 가치가 떨어진다.

**근거를 함께 표시한다.** "우수 교육생"이라는 라벨만 있으면 강도를 알 수 없다. 4단에 자력으로 갔는지, 3단에서 그친 반 1등인지가 보여야 한다. 이건 기존 규범(근거 없는 라벨 단독 노출 금지)이 이미 요구하는 것이다.

> 우수 교육생 · 김OO — **4단 자력 도달 · 미프 3차**
> 우수 교육생 · 이OO — 3단 도달(힌트 1회) · 미프 3차

두 번째 줄을 보면 매니저가 **"이 반은 전체적으로 얕다"** 를 읽을 수 있다.

**프로젝트별로 따로 뽑는다.** 프로젝트마다 판정이 달라진다("프론트 우수가 클라우드 위험일 수 있다"). 미프 6~8회 × 반당 1~2명이면 누적되어 **프로젝트별 프로필**이 쌓인다.

**팀 구성에 쓰는 것은 우수 명단이 아니라 그 프로필이다.** "이 학생은 클라우드에서 4단, CI에서 2단"이 팀 짤 때 필요한 정보다.

### 8-4. 무효 응시 (0단)

**채점하지 않고 판정과 평균에서 뺀다.**

실측에서 오분류가 나왔다. 어떤 학생은 5개 축이 전부 1점이었는데 답변이 이랬다.

> **첫 질문:** "시간이라는 형식이 깨지지 않기 위해서입니다." (한 문장)
> **마지막 질문:** 질문 문장을 그대로 복사해 붙임

**실력이 아니라 응시를 안 한 것이다.** 그런데 시스템은 "전 항목 1점"이라는 실력 판정을 냈고, 그게 "기초가 없는 학생"으로 이어진다. **같은 학생이 다른 세션에서는 4~5점을 받았다.**

판정 재료는 이미 다 있다.

| 신호 | 기준 예시 |
|---|---|
| 답변 길이 | 질문당 20자 미만이 절반 이상 |
| 질문 복붙 | 답변이 질문 문장과 거의 같음 |
| 소요 시간 | 질문당 15초 미만 |

**임계값은 가정값이다.** 검증에서 실제 답변 분포를 보고 조정한다.

**위험 목록에는 눈에 띄게 올린다.** 못하는 것보다 **안 하는 것**이 더 급하고, 개입 방법도 다르다 — 학습 지원이 아니라 면담이다.

### 8-5. 유형이 켜지는 시점

미프가 6~8차라는 게 이 문제를 푼다.

| 시점 | 무엇이 보이나 |
|---|---|
| **미프 1차** | **"관찰"** — 유형 없이 낮은 학생만 표시 |
| **미프 2차** | 단계 하락 확정 |
| **미프 3차** | 지속 저점 확정 |

1회차만 보고 판정하지 않는다는 원칙과 표본 부족 시 가짜 수치를 만들지 않는다는 원칙을 지키면 첫 미프 직후엔 아무 유형도 안 켜진다. 그런데 목적이 "못 따라오는 학생을 일찍 찾는 것"이라 공백을 메워야 한다.

**미프가 4~7일씩이니 1차 관찰은 1주차, 확정은 2주차다.** 충분히 이르다.

## 9. 피드백과 리포트

### 9-1. 학생에게 점수를 보여주지 않는다

기존 결정(결과 리포트 점수 표기 금지)과 재시험 사유 설명이 충돌했다. **학습목표 단위로 말하면 숫자 없이 설명된다.**

> "Service와 Ingress의 역할 분리에서, 왜 그렇게 했는지는 설명했지만 언제 문제가 되는지는 확인되지 않았습니다. 교안 3장(36~46쪽)을 보고 다시 응시하세요."

숫자가 없고, 사유가 있고, 무엇을 공부해야 하는지도 있다. **처방은 하지 않고 위치 안내까지**라는 기존 원칙 안에 정확히 들어간다.

**히트맵은 학생에게 보여주지 않는다.** 자기 위치를 반 평균 대비로 보게 되면 낙인 문제가 생긴다. 학생 화면에는 자기 학습목표별 상태만 둔다.

### 9-2. 학생용 / 매니저용

| | 학생 | 매니저 |
|---|---|---|
| 종합 | 학습목표별 도달 단계 + 서술 | 문제 3개 종합 |
| 문제별 | **전체 문답 + 어디서 막혔는지 해설** | **요약 + 핵심만** |
| 교안 | 참고 위치 | 같음 |
| 점수 | **없음** | 도달 단계 + 축별 서술 |
| 원문 문답 | 있음 | **화면에 없음** (저장은 함) |

**매니저 화면에서 원문을 빼는 것은 저장을 안 한다는 뜻이 아니다.** 채점 이의 조사, 나중에 기능 추가, 재채점 실험의 입력이 전부 원문이다.

### 9-3. 히트맵 — 열이 학습목표가 된다

기술영역 히트맵을 없앤 뒤 열의 정의가 비어 있었다. **학습목표가 그 자리에 들어간다.**

| | |
|---|---|
| **행** | 조직 단위 (기수 → 반 → 프로젝트 → 팀 → 개인) |
| **열** | **학습목표** |
| **값** | 평균 도달 단계 |

**기술영역보다 나은 이유 둘.** "우리 반은 롤링 업데이트에서 다 무너진다"가 보이면 무엇을 다시 가르쳐야 하는지 안다 — **행동으로 연결된다.** 그리고 여러 반이 같은 학습목표에서 무너지면 그건 교안이나 강의 문제다 — **다음 기수 개선으로 돌아온다.**

**크기** — 반 10개 × 학습목표 12개 = **120칸.** 운영자 화면이 한 눈에 들어온다.

**드릴다운에 프로젝트 계층이 반드시 들어간다.** 팀은 프로젝트마다 새로 짜이므로, 빼면 "어느 프로젝트의 팀인지"가 사라진다.

### 9-4. 이해 단계 L1~L5는 계단으로 대체된다

기존 정의는 "L1~L5는 5축 점수에서 파생된 표현"인데 **파생 규칙이 어디에도 없었다.** 계단(0~4단)이 이름에 더 맞는 정의다.

## 10. 개발 전에 할 검증 2건

**여기까지는 설계안이다.** 개발을 시작하기 전에 싸게 확인해야 한다.

### 먼저 — 있는 테스트 기록으로는 이 문서를 검증할 수 없다

그 8세션은 계단으로 물어본 게 아니다. **코드에서 따로 뽑은 독립적인 질문 세 개**였고, 루브릭도 지금 것이 아니며 소재도 교안과 무관했다. **"이 학생은 3단까지 갔다"를 매길 수가 없다.**

| 그 기록으로 확인된 것 | 확인 안 되는 것 |
|---|---|
| 축 두 개가 같은 답변으로 같은 점수를 냈다 | 계단이 5축보다 나은가 |
| 질문에 보기가 붙으면 만점이 나왔다 | 기준선을 어디로 둘까 |
| 채점이 자기 루브릭과 어긋났다 | 난이도가 적정한가 |
| 무성의 응답이 실력 1점으로 처리됐다 | 학생을 잘 구분하는가 |

**왼쪽이 이 문서 2·5·8절의 근거다.** 오른쪽은 아래 검증이 답한다.

### 검증 A — 이 표현이 읽히는가 (데이터 불필요, 30분)

같은 학생 상태를 두 방식으로 적어 나란히 놓는다.

> **①** 코드 이해 3 · 설계 논리 3 · 대안 비교 5 · 반례 대응 4 · 자기 수정 미검증
> **②** 왜 그렇게 했는지까지는 설명했으나, 언제 문제가 되는지는 설명하지 못함 **(2단)**

**개발 안 하는 팀원에게 딱 하나만 묻는다** — "이 학생에게 무엇을 해줘야 할 것 같나요?"

①을 보고 답을 못 하거나 사람마다 다른 말을 하면 그 표현은 실패다.

### 검증 B — 계단이 실제로 계단인가 (사람이 손으로, 1시간)

**이게 이 문서의 생사다.** 위계가 성립하지 않으면 계단이라는 발상 자체가 무너진다. LLM도 코드도 필요 없다.

팀원 2~3명이 각자 **자기가 최근에 쓴 코드 한 군데**를 고른다. 다른 사람이 옆에서 순서대로 묻는다.

1. 이게 무슨 일을 하는 코드인가요? 어디랑 연결되나요?
2. (상황을 하나 던지고) 이러면 어떻게 되나요?
3. 다른 방식으로 할 수도 있었을까요?
4. 그 대안들 중에 왜 지금 방식을 골랐나요?

묻는 사람은 답변마다 **"여기까지는 됐다 / 여기서 막혔다"** 만 표시한다.

**결과를 이렇게 읽는다.**

| 관측 | 뜻 | 대응 |
|---|---|---|
| 순서가 안 뒤집힘 · 단계 매김이 두 사람 사이에 일치 | 위계 성립 | **계단으로 간다** |
| **특정 순서가 일관되게 뒤집힘** | 순서가 틀렸다 | **순서를 교체한다** (폐기 아님) |
| 사람마다 다른 순서로 뒤집힘 | 위계가 아니다 | **계단을 버리고 5축을 다듬는다** |

**두 번째와 세 번째를 구분하는 것이 중요하다.** 한 순서가 일관되게 뒤집히면 그건 계단이 틀린 게 아니라 순서가 틀린 것이다.

**3명 × 20분이면 끝난다.** 그리고 이때 나온 대화 기록이 그대로 질문 생성 프롬프트의 참고 예시가 된다 — 버리는 작업이 아니다.

### 검증을 통과하면 개발 순서

| 순서 | 할 일 | 왜 이 순서인가 |
|---|---|---|
| 1 | **학습목표 입력칸** | 무엇에 대한 이해인지가 정해지지 않으면 나머지가 흔들린다 |
| 2 | **학습목표 → 코드 지점 배정 → 질문 생성** | 난이도·개인화가 여기서 잡힌다 |
| 3 | **도달 단계 저장** + 힌트 횟수 | 분류 로직이 이미 있으므로 연결만 |
| 4 | **0단(무효 응시) 판정** | 위험 판정의 신뢰도가 여기 걸린다 |
| 5 | **단계별 시간 예산** + 붙여넣기 차단 | |
| 6 | **리포트·히트맵을 단계 기준으로** | 위가 되면 표시만 바꾸는 일 |

**마지막에 다시 측정한다.** 팀원 7명이 교안 기반 코드로 응시하면 3문제씩 21세션이 나온다. 학생 없이 가능하고, 이번엔 조건이 맞으므로(교안 기반·학습목표 앵커·문항을 고르지 않음) **여기서 나온 분포로 기준선을 정한다.**

| **무효 응시 임계값** (몇 자·몇 초) | 검증에서 실제 답변 분포를 봐야 한다 |
| **개별 상세의 5축 그래프 화면** | "팀 평균 vs 개인을 5축별 그래프로" 결정이 계단과 충돌한다. 검증 B 통과 후 다시 본다 |
| **채점 모델 선택** | 모델별 점수 차이 데이터가 0건. 기존 세션 로그를 다른 모델로 재채점하면 반나절에 나온다 |
| **재시험 대상 통보·기간** | [09번 1-4](09-design-answers.md)에 기본안이 있으나 기준선이 확정돼야 한다 |

**모델 선택은 근거 하나가 이미 있다** — 모델을 바꿨을 때 채점이 실패한 이력이 코드 주석에 기록돼 있다. 출력 길이 예산이 부족해 채점 결과가 문장 중간에 끊기는 사고가 6번 중 3번 났다. **기관마다 다른 모델을 쓰게 하면 안 된다.**
