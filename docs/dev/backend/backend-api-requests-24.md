# 백엔드 API — 24차 요청 · 리포트 연동에서 나온 것들

> **교육생 리포트(TR-04)를 실서버에 붙였습니다.** 23차에 고쳐 주신 `level`이 그대로
> 화면에 나옵니다 — 실계정으로 회차 6개를 다 열어 확인했습니다.
>
> `GET /reports` 하나가 회차 목록과 본문을 다 줘서 **회차를 바꿔도 요청이 없습니다.**
> 봉투(`rounds` + `reportsById`)를 그 모양으로 주신 것이 그대로 효과를 냈습니다.
>
> **가장 급한 것은 R4입니다** — 홈과 리포트가 같은 학생에게 **다른 회차 목록**을 줍니다.
> 어느 쪽이 맞는지에 따라 학생이 제출을 통째로 놓칠 수 있습니다.

## 1. 🔴 R4 — 두 API가 같은 학생에게 다른 회차 목록을 줍니다

**같은 계정(`trainee01`)으로 두 API를 같은 시각에 불렀습니다.**

```
GET /assessment-rounds   →  5개   current: 미니프로젝트 5차 (ASSESSMENT_WINDOW_CLOSED / NONE)
                                  past:    1차 · 4차 · 3차 · 2차
GET /reports             →  6개   6차 · 5차 · 4차 · 3차 · 2차 · 1차
```

**6차가 `/reports`에만 있습니다.** 홈 응답에는 `current`·`upcoming`·`past` 어디에도
없습니다. `/reports`에서는 이렇게 옵니다.

```json
{ "id": "ad9fb0a0-…", "label": "미니프로젝트 6차 이해도 확인", "status": "NOT_ATTEMPTED" }
```

### 어느 쪽이 맞는지 저희가 판단할 수 없습니다

두 가지로 읽힙니다.

1. **`trainee01`은 6차 대상이다** → 홈이 빠뜨린 것입니다. 23차 회신 §7 표에
   *"`trainee01`의 6차 — `SUBMISSION_REQUIRED / SUBMIT_CODE`"* 로 적어 주셨는데,
   지금 홈 응답에는 그 회차가 아예 없습니다
2. **`trainee01`은 6차 대상이 아니다** → `/reports`가 남의 회차를 목록에 넣은 것입니다.
   그러면 학생 화면에 **자기와 무관한 회차**가 한 줄 더 보입니다

> ⚠️ **저희가 앞서 근거로 삼으려던 대조가 성립하지 않아 밝혀 둡니다.**
> `trainee-draft`로 부르면 6차가 `current`로 오는데, **그 계정은 D반이고
> `trainee01`은 C반**이라(둘 다 9기) 반이 다릅니다. 회차 배정이 반마다 다르면
> 정상일 수 있어 **비교 근거로 쓸 수 없습니다.**

### 화면이 어떻게 되나 — 1번이면 학생이 제출을 놓칩니다

`trainee01`의 홈은 **5차(응시 창 닫힘 · 할 일 없음)** 를 보여줍니다.

- 홈 카드 — 5차 `할 일 없음`
- 제출 화면 — 홈의 `current.projectId`로 조회하므로 **5차 제출 현황**(이미 잠김)
- 리포트 화면 — 여기만 6차가 보이는데 `NOT_ATTEMPTED`

**세 화면이 서로 다른 회차를 말합니다.** 6차 제출 마감이 8/21로 남아 있는데도
학생은 그 사실을 어디에서도 알 수 없습니다.

2번(대상이 아님)이면 화면은 지금도 맞습니다 — 리포트 목록에 한 줄이 남을 뿐입니다.

### 요청

**`trainee01`이 6차 대상인지만 알려 주세요.** 그에 따라 고칠 쪽이 정해집니다.

- **대상이 맞다** → `/assessment-rounds`가 6차를 `current`로 내 주세요
- **대상이 아니다** → `/reports`의 `rounds[]`에서 빼 주세요

> 🔴 **곁들여 — `NOT_ATTEMPTED`는 어느 쪽이든 이릅니다.** 6차는 제출 마감(8/21)이
> 아직 안 지났습니다. 그런데 화면 문구가 *"이해도 확인에 응시하지 않아 만들 내용이
> 없습니다"* 라 **끝난 일에 대한 판정**으로 읽힙니다. 아직 시작도 안 한 회차라면
> "아직"을 뜻하는 상태가 맞습니다 — 지금은 학생이 **이미 놓친 줄 알게 됩니다.**

## 2. 🔴 R1 — 다시 볼 문제가 0개인데 "다시 보기" 상태입니다

`trainee01`의 2차 리포트 실응답입니다.

```json
{
  "label": "미니프로젝트 2차 이해도 확인",
  "retryState": "PENDING",
  "disclosureScope": "SUMMARY",
  "concepts": [
    { "name": "예외 처리와 롤백 전략",  "level": 3, "isRetryTarget": false },
    { "name": "API 응답 계약 설계",     "level": 2, "isRetryTarget": false },
    { "name": "영속성 매핑과 지연 로딩", "level": 2, "isRetryTarget": false }
  ]
}
```

목록 응답의 `rounds[]`도 같은 회차에 `hasPendingRetry: true`입니다.

### 화면이 어떻게 되나

**"다시 볼 수 있는 문제가 0개 있어요"** 라는 배너가 뜨고, 그 옆 [다시 보기] 버튼을
누르면 **빈 세션으로 들어갑니다.** 좌측 회차 목록에도 `다시 볼 문제 0개`가 붙습니다.

게다가 이 리포트는 `SUMMARY`라 **세 개념 모두 해설이 잠겨 있고**, 화면은 그 이유를
*"다시 보기를 마치면 열려요"* 라고 말합니다. 그런데 다시 볼 것이 없으니 **영원히
열리지 않습니다.** 학생은 열 수 없는 자물쇠를 세 개 보게 됩니다.

### 왜 이렇게 됐다고 보나

23차 R2에서 `isRetryTarget`을 **`level < 2`로 판정**하도록 고쳐 주셨습니다. 그 규칙은
맞습니다 — 이 회차는 도달 단계가 3·2·2라 재시험 대상이 하나도 없는 것이 정상입니다.

그런데 **`retryState`와 `hasPendingRetry`는 그 수정을 따라가지 않은 것으로 보입니다.**
예전 판정(AI의 `retest`)으로 만들어진 값이 그대로 남아 있는 것 같습니다.

### 요청

**`retryState`를 `isRetryTarget`과 같은 원천에서 내 주세요.** 대상이 0개면 `PENDING`이
아니라 `NONE`이어야 합니다. `rounds[].hasPendingRetry`도 같은 판정을 따라야 합니다 —
지금은 세 값이 서로 다른 말을 합니다.

```
isRetryTarget 이 하나도 없다  →  retryState: NONE · hasPendingRetry: false
```

**화면은 일단 막아 뒀습니다** — 대상이 0개면 배너와 레일 문구를 접습니다. 다만 그러면
`SUMMARY` 잠금이 열릴 길이 없다는 문제는 그대로 남습니다(아래 질문).

### ❓ 곁들여 — 재시험 대상이 없는데 `SUMMARY`인 리포트는 무엇인가요

공개 범위와 재시험이 원래 짝이라고 이해하고 있었습니다.

```
SUMMARY  →  다시 보기를 마치면 FULL로 열린다
```

그런데 이 회차는 **다시 볼 것이 없는데 SUMMARY**입니다. 두 가지로 읽힙니다.

1. `retryState`가 잘못된 것이고 원래 대상이 있었다 → R1을 고치면 같이 풀립니다
2. **공개 범위는 매니저가 따로 정하는 값**이고 재시험과 무관하다 → 그러면 화면 문구
   *"다시 보기를 마치면 열려요"* 가 틀린 말입니다. **"매니저가 공개하면 열려요"** 로
   바꿔야 합니다

**어느 쪽인지 알려 주세요.** 2번이면 문구만 고치면 됩니다.

## 3. 🟡 R5 — 지난 회차를 정렬할 키가 없습니다

`/assessment-rounds`의 `past[]`가 이 순서로 옵니다.

```
past[0]  roundNo 1  미니프로젝트 1차
past[1]  roundNo 1  미니프로젝트 4차
past[2]  roundNo 1  미니프로젝트 3차
past[3]  roundNo 1  미니프로젝트 2차
```

**배열 순서가 `1·4·3·2`이고, `roundNo`는 전부 `1`입니다.**

`roundNo`가 다 1인 것은 스펙대로입니다 — *"프로젝트 안에서만 유일하다"* 고 적혀 있고
미니프로젝트 1~6차가 각각 별개 프로젝트니까요. 그래서 **정렬에 쓸 수 없습니다.**

응답에 다른 정렬 기준도 없습니다. `PastRoundResponse`의 필드는
`assessmentRoundId · roundNo · roundName · representativeStatus · reviewStatus ·
completedReviewCount · reportId · canViewReport` 뿐이라 **날짜가 하나도 없습니다.**

### 화면이 어떻게 되나

홈의 지난 회차 목록이 **1차 · 4차 · 3차 · 2차** 순으로 그려집니다. 서버 순서를 그대로
쓰기 때문입니다 — 화면이 정렬하려 해도 기준이 없습니다.

`roundName`에서 숫자를 뽑아 정렬할 수는 있지만, **화면이 이름을 파싱해 순서를 정하는
것**이라 회차 이름 규칙이 조금만 달라져도 깨집니다. 그래서 하지 않았습니다.

### 요청

**둘 중 하나면 됩니다.**

1. **배열을 최신순으로 정렬해서 내 주세요** — 화면은 받은 순서를 그대로 그립니다
2. **정렬용 필드를 하나 주세요** — 회차 시작일이나 종료일이면 충분합니다

`/reports`의 `rounds[]`는 이미 **6→1 역순으로 잘 옵니다.** 같은 규칙을 쓰시면 됩니다.

> 참고로 `PastRoundResponse`에 날짜가 하나도 없어서, 지난 회차 줄에 *"언제 회차였나"* 를
> 못 씁니다. 지금은 이름만 나옵니다. 1번으로 해결되면 순서만으로도 충분하니
> 날짜는 급하지 않습니다.

## 4. 🟡 R6 — 배지와 서술이 같은 카드에서 서로 반대입니다

23차 §2에서 **3단·4단 축 순서를 확정 모델에 맞춰 뒤집어** 주셨고, 이미 발행된 리포트는
스냅샷이라 옛 문구가 남는다고 알려 주셨습니다. 저희도 *"새로 발행되는 것부터 맞으면
충분하다"* 고 답했습니다.

**화면에 그려 보니 생각보다 셉니다.** 발행된 리포트 4건의 **개념 12개가 전부**
배지와 문장이 한 카드 안에서 정반대를 말합니다(예외 0건).

```
┌ 트랜잭션 경계 설정                        [ 가능한 다른 방법까지 ]  ← level 3 = 대안 비교 통과
│ …실패 조건까지 짚었지만, 같은 요구사항을 다른 방법으로
│  구현하는 대안은 제시하지 못했습니다.                              ← 대안 비교 실패
└
```

**"대안까지 도달했다"는 배지 바로 아래에 "대안은 제시하지 못했다"가 붙습니다.**
`level: 2`(설계 논리까지)인 개념도 3단(대안 비교)을 건너뛰고 4단(반례) 얘기를 합니다.

```
level 3  →  "…대안은 제시하지 못했습니다"      7건   (3단 통과인데 3단 실패를 말함)
level 2  →  "…어떤 상황에서 깨지는지 답 못함"  5건   (3단 실패여야 하는데 4단을 말함)
```

옛 축 순서(3단 = 반례 대응)로 읽으면 문장과 `level`이 서로 맞습니다. 즉 **데이터는
일관되고, 새 축 순서로 붙인 저희 배지와만 어긋납니다.**

### 확인 부탁 — 이 리포트들에 실사용자가 있나요

**전부 시드 데이터라면 그냥 두겠습니다.** 새로 발행되는 것부터 맞으면 됩니다.

**실제 교육생이 이미 받아 본 리포트가 섞여 있다면** 처리가 필요합니다. 그 학생은
지금 앞뒤가 안 맞는 문장을 보고 있습니다. 그때는 이렇게 하겠습니다.

- **교정 시점을 알려 주세요** — 그 이전에 발행된 리포트는 화면에서 **서술을 감추고**
  배지와 교안만 보여주겠습니다. 틀린 문장을 보여주는 것보다 안 보여주는 편이 낫습니다
- 또는 **대상만 골라 재생성**해 주셔도 됩니다. 23차 회신에 그 경로가 있다고 하셨는데,
  AI 호출 비용이 든다고도 하셨으니 **대상이 적을 때만** 그쪽이 낫겠습니다

**어느 쪽인지만 알려 주시면 저희가 맞추겠습니다.**

## 5. 🟡 R2 — `explain`이 한 번도 오지 않습니다

`FULL`로 열린 리포트에서도 `explain` 배열이 비어 있습니다. 실계정 리포트 4건을
전부 확인했습니다.

| 리포트 | `disclosureScope` | `qa` | `explain` |
|---|---|---|---|
| 미프 4차 | `FULL` | 개념마다 3건 ✅ | **0건** |
| 미프 3차 | `FULL` | 개념마다 3건 ✅ | **0건** |
| 미프 2차 | `SUMMARY` | 0건(정상) | 0건(정상) |
| 미프 1차 | `SUMMARY` | 0건(정상) | 0건(정상) |

`qa`는 잘 오는데 `explain`만 비어 있어서, **공개 범위 문제가 아니라 값 자체가
안 채워지는 것**으로 보입니다.

### 화면에서 무엇이 비나

**"어디서 막혔나"** 섹션입니다. 다시 보기를 마친 학생에게 열어 주는 자리인데,
지금은 열려도 그 안이 비어 있습니다. 문답 원문은 나오지만 *"왜 막혔는지"* 를
짚어 주는 문장이 없습니다.

지금은 값이 없으면 섹션 자체를 안 그리도록 해 두어서 **깨지지는 않습니다.**

### 요청

**의도된 것인지만 알려 주세요.**

- AI가 아직 이 필드를 안 채운다 → 언제 채워질지
- 이 필드를 쓰지 않기로 했다 → **저희가 화면에서 지우겠습니다.** 지금은 "언젠가 올
  값"으로 두고 있어 코드가 남아 있습니다
- 특정 조건(예: 도달 2단 미만)에서만 온다 → 그 조건을 알려 주시면 그렇게 이해하겠습니다

## 6. 🟡 R3 — 제출 마감이 서버 재개일보다 앞섭니다

23차 회신 §0에서 제출 API 2개가 다시 `사용 불가`가 됐고 **8/23 재개 예정**이라고
알려 주셨습니다.

```
POST /api/v0/submissions        x-readiness: unavailable
POST /api/v0/submissions/zip    x-readiness: unavailable
```

그런데 지금 열려 있는 회차의 **제출 마감이 8/21**입니다.

```
9기 / 미니프로젝트 6차 이해도 확인   제출 마감 2026-08-21   서버 재개 2026-08-23
```

**이 회차는 아무도 제출할 수 없습니다.** 마감이 지난 뒤에야 서버가 열립니다.
R8로 만들어 주신 `trainee-draft` 계정도 폼까지는 열리지만 제출은 못 합니다.

### 저희 쪽 처리

**`사용 가능`이 아닌 오퍼레이션은 호출하지 않는다**는 규칙이라 제출 버튼을 막아
뒀습니다. 폼은 남기고 사유를 띄웁니다 — 그리고 **재개일이 마감보다 뒤면 문구가
달라집니다.**

```
재개일 < 마감  →  "서버 점검으로 8월 23일까지 제출을 받지 않아요 — 열리면 그때 올려 주세요"
재개일 > 마감  →  "…— 이 회차 제출 마감보다 늦게 열려요. 매니저에게 알려 주세요"
```

*"마감 전에 다시 열려요"* 같은 약속은 넣지 않았습니다. 못 지킬 약속을 하면 학생이
기다리다 마감을 넘깁니다.

### 요청

**운영 판단이 필요합니다 — 둘 중 하나를 정해 주세요.**

1. **6차 제출 마감을 8/23 이후로 미룬다** → 이 회차가 정상 진행됩니다
2. **이 회차는 제출을 받지 않기로 한다** → 그러면 매니저에게 알려야 하고, 저희는
   화면에서 그 사실을 더 분명히 말하겠습니다

**저희가 정할 수 있는 일이 아니라 알려만 드립니다.** 8/23에 서버가 열려도 이 회차는
이미 마감이라, 그때 가서 알게 되면 늦습니다.

> AI 서버 복구가 앞당겨질 수 있으면 그것이 제일 낫습니다. 재개일이 정해지면
> 알려 주세요 — 저희 쪽은 상수 한 줄이라 바로 반영합니다.
