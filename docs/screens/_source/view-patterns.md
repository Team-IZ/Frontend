# 화면별 최적 뷰 패턴 결정서 (View Pattern Decisions)

제품 레지스터 기준(도구는 태스크 속으로 사라져야 한다 — Linear/Stripe급 제품 UI의 기준)으로, 각 화면·파트별 기능에 대해 **어떤 뷰 패턴이 왜 최적인지**를 결정한 문서. 와이어프레임 v2 재구성의 설계 근거이며, design-system-anchor.md(시각 토큰)·ux-principles.md(행동 규범)와 함께 3대 공유 소스를 이룬다.

**판단 기준 3가지:**
1. **의사결정 속도** — 매니저 루프(브리핑→위험식별→상세→개입→회복확인)의 각 단계에서 다음 행동까지의 클릭 수와 시선 이동을 최소화
2. **스캔 효율** — 같은 정보라면 카드 그리드보다 밀도 높은 리스트/테이블이 비교·훑기에 우수(제품 UI 원칙: 카드는 게으른 기본값)
3. **맥락 유지** — 화면 이동 대신 분할 뷰·패널·인라인 확장으로 작업 흐름 보존(모달은 최후 수단)

## 매니저 트랙

### SC-M01 브리핑·대시보드 → **우선순위 인박스 + 상황판 레일**

**문제 진단:** v1은 카드 그리드 나열 — 13개 FR의 위젯이 동급으로 펼쳐져 "어디를 먼저 볼지"라는 화면의 존재 이유(DASH-01 의사결정 지원)를 레이아웃이 배반한다.

**결정:**
- **상단 브리핑 스트립** (DASH-02): "지난 확인 이후 신규 위험 N건 · 미처리 개입 M건" 한 줄 + 시각. 로그인 직후 첫 시선이 닿는 유일한 풀폭 요소.
- **주 영역(좌 2/3) = 우선순위 인박스**: 시그널을 카드가 아닌 **행(row) 리스트**로. 각 행 = 순위 + 배지 + 이름 + 근거 1줄 + 타이밍 문구 + 인라인 quick action("개입 생성"). 행 클릭 → SC-M06. 이유: 우선순위 목록은 순서 비교가 본질이고, 행 리스트가 카드 대비 2~3배 스캔 밀도를 제공. C2(순위 사유 문구)는 행 내 서브텍스트로.
- **우측 레일(1/3) = 상황판**: 응시율·미처리 개입·팀 진행 콤팩트 스탯(각 클릭 시 해당 화면 이동) + 안정성 배지·벤치마크 칩(온디맨드 B2) 등 보조 위젯. 주 영역과 시각 위계 명확히 분리(제목 크기·배경 톤).
- P1/P2 위젯 자리는 레일 하단 점선 placeholder로 격리(주 영역 오염 금지).

### SC-M04 시그널 분석 → **마스터-디테일 분할 뷰 (트리아지 패턴)**

**문제 진단:** v1은 카드 목록 → 상세는 SC-M06 이동. 시그널 20건 검토 = 20회 화면 왕복. 트리아지 작업의 맥락이 매번 끊긴다.

**결정:**
- **좌측(마스터, ~380px)**: 콤팩트 시그널 행 리스트. 상단에 유형 세그먼트 필터(위험/불균형/에이스/팀 이상 — 탭 대신 세그먼트 컨트롤, 후속 배치 유형은 disabled+P1 배지). 행 = 배지+이름+근거 요약.
- **우측(디테일)**: 선택 시그널의 근거 전개 — 해당 축 추이 미니 스파크라인, 근거 문구 전문, 세션 발췌 링크, 하단 고정 액션 바("개입 생성" primary / "교육생 상세" secondary). 키보드 ↑↓로 리스트 순회 가능(연속 검토).
- A2(라벨+근거 세트)는 구조적으로 보장 — 디테일 패널 없이는 라벨이 존재할 수 없는 레이아웃.
- SC-M06 전체 이동은 "더 깊은 맥락(세션 전문·이력)이 필요할 때"의 선택지로 격하.

### SC-M06 교육생 상세 → **아이덴티티 헤더 + 요약 스트립 + 프로그레시브 탭**

**문제 진단:** v1은 5탭 구획까지는 왔으나 초기 뷰의 정보 위계가 평탄.

**결정:**
- **헤더**: 아바타+이름+소속+활성 배지(근거 툴팁 동반) — 1줄 고정.
- **요약 스트립**(헤더 직하): ①최근 5축 추이 스파크라인 ②활성 시그널 요약 ③마지막 개입 상태 — 3칸 콤팩트. "이 학생 지금 어떤 상태인가"를 3초 안에.
- **탭 5개**(추이/세션 기록/채점 근거/기여 분석/개입·상담 이력): 초기 진입은 '추이' 탭. 세션 기록은 **회차 아코디언**(펼치기 전 로드 금지 — B1), 채점 근거는 축별 점수 행 클릭 시 근거 span 전개. 기여 분석은 기여율+이해도 교차 산점 표시(A3 구조 보장).
- 우상단 고정 액션: "개입 생성" primary, "면담 질문 추출"(P1, disabled placeholder).

### SC-M07 개입 관리 → **상태 칸반 보드 + 상세 사이드 패널**

**문제 진단:** v1은 테이블+다이얼로그. 개입 건의 본질은 상태(대기/진행/완료) 흐름 관리인데 테이블은 상태 전환을 표현하지 못한다.

**결정:**
- **3열 칸반**(대기/진행/완료): 카드 = 대상 이름+개입 유형+연결 시그널 배지+담당자. 드래그 또는 카드 내 상태 버튼으로 전환. 완료 열 카드에는 효과 판정 배지(회복/미회복/판정대기 — INTV-06, P1은 placeholder).
- **카드 클릭 → 우측 사이드 패널**(모달 아님): 연결 시그널 근거, 메모, 상태 이력, 재알림. 보드 맥락 유지한 채 상세 조회.
- **개입 생성은 패널 폼**: 시그널에서 진입 시 대상·근거 자동 채움, 추천 유형은 '추천' 배지 + 수동 선택 UI(E1).
- 건수가 수백 건을 넘는 운영이 확인되면 테이블 뷰 토글 추가(현 단계 YAGNI).

### SC-M08 종합 리포트 → **문서형 레이아웃 + 앵커 목차 + 온디맨드 근거 패널**

**결정:**
- 리포트는 "읽는 문서"다 — 대시보드 위젯 그리드가 아니라 **세로 문서 흐름**(요약 → 이해도 분포 → 취약 구간 → 개입·회복 → 커리큘럼 제안). 본문 최대폭 ~760px.
- **좌측 고정 앵커 목차**(스크롤 스파이) — 긴 리포트의 섹션 점프.
- 수치 클릭 → **우측 슬라이드 근거 패널**(RPT-05 온디맨드, B1). 클릭 전 로드 금지.
- **상단 고정 바**: 기수/버전 선택 + Export 버튼(내부 보고용) — 이 화면의 최종 행동.

### SC-M09 이의 검토 → **검토 대기열 + 원문 대조 2패널**

**문제 진단:** 이의 검토의 본질은 "교육생 주장 vs 세션 원문·채점 근거"의 **대조**다. v1의 순차 나열로는 대조 시 스크롤 왕복이 발생.

**결정:**
- **좌측 얇은 대기열**(~300px): 이의 건 리스트(교육생·회차·사유 요약·경과일). 처리 순서 관리.
- **중앙: 원문 대조 뷰** — 상단에 이의 사유(교육생 주장), 그 아래 해당 문항의 세션 전문 + 채점 근거 span 하이라이트를 **같은 스크롤 안에서** 대조.
- **우측 판정 패널**(고정): 현재 판정 → 수정 판정 선택(radio) → 사유 입력(기각 시 필수, 미입력 시 제출 차단 — E3) → 제출. before/after/reason 이력 자동 기록 안내.

### SC-M11 교육생 목록 → **테이블 유지 + 미세 개선** (패턴 변경 없음)

v1의 테이블 선택이 옳다. 개선만: ①검색 입력 즉시(디바운스) 필터 ②행 전체 클릭 영역 ③측정 상태는 칩(진행중/완료/미시작) ④빈 검색 결과에 검색어 초기화 CTA. 시그널 라벨 비표시(A2 구조 보장) 유지.

### SC-M02 기수 생성 → **최초 생성 = 스텝퍼 마법사 / 이후 = 탭 편집**

**문제 진단:** v1은 3탭 병렬 — 그러나 기수 생성은 순서가 있는 작업(기수 정보 → 명단 → 팀/프로젝트 매핑)이고, ORG-02·03은 ORG-01 없이는 존재할 수 없다. 순서가 정보를 담으므로 스텝퍼가 정당(임의 번호 장식이 아님).

**결정:**
- **신규 생성 모드**: 3단계 스텝퍼(①기수 정보 ②교육생 명단 ③팀·프로젝트 매핑). 명단은 CSV 업로드 + 결과 인라인 그리드(오류 행 red 하이라이트+사유).
- **기존 기수 편집 모드**: 동일 3구획을 탭으로(순서 강제 불필요).
- 초대 발송 상태는 명단 그리드 내 칩(대기/발송/실패+재발송 버튼).

### SC-M03 측정 계획 → **타임라인(일정) + 설정 폼 분리**

**문제 진단:** v1은 폼 나열. 체크포인트 일정(PLAN-01)은 시간 위에 놓인 데이터인데 폼 행으로는 간격·중복을 눈으로 검증할 수 없다.

**결정:**
- **상단: 수평 타임라인** — 기수 기간 축 위에 회차 마커(일자·응시 기한). 겹침/유효기간 밖 회차는 red 마커(case 대응 시각화). 마커 클릭 → 해당 회차 설정으로 스크롤.
- **하단: 회차 행 리스트** — 행 확장(아코디언)으로 회차별 세부(기한·포커스 영역 P1) 편집.
- **질문 추출 범위(PLAN-02)**: 프로젝트별 라디오 그룹(전체 코드/커밋 기여분) + 각 옵션에 "언제 적합한가" 1줄 설명. 포커스 영역(P1)엔 "교육생에게 노출되지 않습니다" 잠금 아이콘 상시 표기(D2).

### SC-S01 슈퍼어드민 → **테이블 + 행 확장 드로어** (경미 개선)

기관 목록 테이블 유지. 개선: 행 클릭 → 우측 드로어(사용량 집계·매니저 초대 이력·상태 변경). 기관 생성은 상단 primary 버튼 → 드로어 폼(모달 대신).

## 교육생 트랙

### SC-T02 코드 제출 → **단일 태스크 퍼널 + 실시간 진행 스테퍼**

**결정:**
- **1단계 화면 = 제출 방식 선택**: GitHub URL을 기본(권장 배지, 큰 입력 1개), ZIP은 보조 접이식. OS별 git log export 명령어는 코드 블록+복사 버튼(탭: macOS/Windows/Linux).
- **제출 후 = 진행 스테퍼 화면 전환**: 제출 완료 → 기여 분석 → DP 추출 → 세션 준비. 각 단계 실시간 상태(완료 채움/진행 스피너/대기 회색 — 앵커 §7 스테퍼). 실패 단계는 red + 사유 + 재시도. ATTRIBUTION_REQUIRED(귀속 0건)는 스테퍼 중단 + 이메일 재확인 CTA.
- 세션 준비 완료 시 "세션 시작" primary가 화면 유일 CTA로 등장.

### SC-T04 검증 세션 → **코드 컨텍스트 고정 2패널 (핵심 재구성)**

**문제 진단(가장 중요):** 질문은 코드 종속형("이 파일의 이 함수는 왜...")인데 v1은 채팅 단일 컬럼 — 교육생이 자기 코드를 따로 열어봐야 답할 수 있다. 화면이 태스크를 방해하는 구조.

**결정:**
- **좌측(~45%): 코드 컨텍스트 패널** — 현재 질문이 참조하는 파일·함수의 해당 구간을 자동 표시(파일명·라인 표기, 모노스페이스). 질문이 바뀌면 패널 내용 동기 전환. 코드는 읽기 전용.
- **우측(~55%): 대화 패널** — 질문/답변 버블, 스트리밍 타이핑 인디케이터, 하단 고정 입력.
- **상단 미니멀 바**: DP 진행(n/m) + 세션 잔여 시간. 타이머는 압박을 줄이기 위해 잔여 20% 미만에서만 amber 강조.
- 재연결·시간 초과·건너뛰기 안내는 대화 흐름 내 인라인 시스템 메시지(중립 톤, A5).
- 모바일(<1024px): 코드 패널이 질문 버블 내 접이식 코드 블록으로 강등.

### SC-T05 결과 리포트 → **세로 내러티브** (경미 개선)

v1 구조 유지하되 서사 순서 고정: ①이번 회차 요약(등급 아님 — 중간 회차는 추이만, A4) ②축별 강약점 서술형 ③성장 추이(회차 축 라인) ④취약점→교안 위치 안내(D4 한계 명시) ⑤이의제기 진입(조용한 텍스트 링크 — 유도하지도 숨기지도 않음). 공개범위(D5)에 따라 섹션 단위 마스킹.

### SC-T01 초대·활성화 / SC-A01 로그인 / SC-A02 인증 → **중앙 카드 유지** (패턴 변경 없음)

단일 태스크 인증 플로우에 중앙 카드는 이미 최적. 마이크로카피·오류 안내 구체화만 유지 대상.

## 정보설계 2차 재검토 (전 화면 렌더 대조 후)

### SC-M07 개입 관리 — 정체 신호 추가 (실질 결함)

**문제 진단:** 칸반 구조 자체는 옳다(상태 흐름 관리). 그러나 **개입 관리의 핵심 실패 모드는 "만들어놓고 방치"인데 화면이 그것을 전혀 잡아주지 못했다.** 카드에는 생성일만 있고 경과·정체 신호가 없었다. 같은 제품의 SC-M09 대기열은 "5일 경과"를, SC-M01 인박스는 "지금 확인이 필요합니다"를 이미 제공하고 있어 **일관성 위반이기도 했다.**

**결정:** ① 카드 메타에 경과일 배지, 7일 이상은 red "N일 경과 · 정체" ② 페이지 상단 요약에 "정체 N건 (7일 이상 상태 변화 없음)"을 red로 ③ 완료 열은 "최근 3건 · 전체 보기"로 상한 — 완료는 무한 누적되는데 매니저의 행동 대상은 대기·진행뿐이므로 화면의 1/3을 영구 점유할 이유가 없다 ④ 카드 우상단 `⋮` 제거 — 액션은 이미 카드 하단 버튼에 있어 중복 어포던스였다.

**이유:** 이 화면에서 매니저가 내리는 결정은 "다음에 무엇을 진행시킬까"다. 그 결정에 필요한 것은 생성일이 아니라 **얼마나 멈춰 있었는가**다.

### SC-T05 결과 리포트 — 강점/성장 여지 분리

**문제 진단:** DP별 결과를 동일 크기 카드로 강점·성장여지 **섞어서** 순서대로 나열했다. 교육생이 이 화면에서 답을 얻어야 할 질문은 "무엇을 더 살펴봐야 하는가" 하나인데, 행동 대상(성장 여지)이 강점 카드 사이에 파묻혀 스캔되지 않았다. 동일 카드 그리드는 정보 위계가 평탄하다는 신호다.

**결정:** "더 살펴볼 부분"(성장 여지, 상세 카드 + 교안 위치) → "확인된 강점"(압축 리스트)로 **분리하고 순서를 고정**. 카드 우상단 `⋮` 제거(교육생이 카드에서 할 수 있는 액션은 하단 이의제기뿐).

**규범 확인:** D4(처방형 콘텐츠 배제)는 그대로 지킨다 — 진단과 **교안 위치 안내까지만**, 문제 추천은 없다. 순서 재배치는 D 규칙 어디에도 저촉되지 않는다(규범가 확인 완료).
