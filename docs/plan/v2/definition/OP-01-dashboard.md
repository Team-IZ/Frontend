# OP-01 · 오퍼레이터 대시보드 — 지표판

## 1. 한 줄

**운영이 정상으로 돌고 있는지**를 본다. 학생 위험이 아니라 **운영 이상**이 대상이다.

> 스코프가 250명·10반이라 개인은 볼 수 없다. 개별 학생 위험은 매니저가 처리하므로,
> 여기에는 **반 단위 이상에서만 보이고 오퍼레이터만 조치할 수 있는 것**만 올린다.

## 2. 진입 · 이탈

로그인 직후 · 좌측 네비 → 각 줄에서 해당 화면으로.

### 회차는 전체 중 몇 번째로 쓴다

`미프 3차`가 아니라 **`미프 3차 / 8회`**다. 오퍼레이터는 기수를 **운영**하는 사람이라
*"아직 5회 남았다"* 와 *"마지막 회차다"* 는 판단이 완전히 다르다 — 개념 교체를 다음
회차에 넣을 수 있는지가 여기서 갈린다.

**매니저 대시보드에는 없던 정보다.** 매니저는 이번 회차만 처리하면 된다.

### 정렬 — 되돌리기 어려운 순서

| 순위 | | 왜 |
|---|---|---|
| **1** | 미배정 | 구조 문제라 **그 반 전체가 방치된다** |
| **2** | 개념 공백 | **다음 회차 설계에 반영해야** 늦지 않는다 |
| **3** | 집단 미달 | 반 공지·재투입 |
| **4** | 면담 적체 | 인력 조정 |

MG-01처럼 **띠에 이유를 쓰지 않는다** — 순서가 이미 우선순위를 말한다.

### 막대는 9-6으로 빠진 개념을 뺀 뒤 센다

막대가 *"2단 이하 개념이 2개 이상인 학생 비율"*(9-2 판정과 같은 값)인데, **집단 미달로
판정된 개념을 그대로 세면 그 반 막대만 통째로 올라간다.** 그러면 **개인 위험이 많은
반처럼** 보이지만 실제로는 반 전체가 같은 지점에서 멈춘 것이다 — 처방이 정반대다.

**집단 미달은 `조치 필요`가 따로 말한다.** 두 곳이 같은 사실을 다르게 그리지 않는다.

### 면담 적체는 회차 경과다

`대기 최장 11일`로 썼다가 고쳤다. **리포트가 일괄 발행되므로**(10-2) 등재일이 회차 안에서
전부 같다 — MG-03에서 확인한 것과 같은 이유다. 개인 편차가 없으므로 *"가장 오래 기다린
사람"* 이 아니라 **그 반 면담이 며칠째 안 끝났나**가 정확한 표현이다.

```
D반 · 미프 2차 면담이 11일째 안 끝났습니다
예정 7명 · 다른 반은 3~5일
```

**다른 반과의 비교를 함께 준다** — 11일이 긴 건지 아닌지는 그것으로만 판단된다.

### 비용 — 세 값을 나란히

절대 금액은 쓰지 않는다. 판단 기준이 없고, **세션당 LLM 비용 산식이 어느 문서에도
정의된 적이 없다.**

| | |
|---|---|
| 이번 달 | 전월 대비 **+12%** |
| 세션 수 | 전월 대비 **+9%** |
| 세션당 | 전월 대비 **+3%** |

**세 값을 나란히 두면 양이 늘어서인지 단가가 올라서인지가 갈린다.** 하나만 두면 어느
쪽인지 모른 채 놀라기만 한다.

**`조치 필요` 네 줄이 이 화면의 존재 이유다.**

| | 왜 오퍼레이터인가 |
|---|---|
| 집단 미달 | 반 절반이 한 개념에서 미달하면 **개인 문제가 아니다.** 반 공지·재투입 판단 |
| 항목 공백 | 문항이 안 만들어진 팀이 전반이면 **항목 선택이 프로젝트와 안 맞은 것**. 다음 회차에 교체 |
| 면담 적체 | 매니저가 못 돌고 있다는 신호. 반 재배정·인원 조정 |
| 미배정 반 | 조직 구조 문제 |

**반 비교에 등수를 붙이지 않는다.** 막대만 둔다 — **매니저 줄세우기가 되면 그 지표를
관리하려는 행동이 나온다.**

## 4. 데이터

회차 파이프라인(제출·**분석 실패는 팀 단위** — 제출이 팀 단위이므로·응시·발행) · 반별 위험 비율 · 집단 미달(9-6) ·
항목별 문항 생성 0 비율 · 반별 면담 대기 최장 · 매니저 미배정 반 · 월 비용 증감.

## 5. 액션

**여기서 처리하지 않는다** — 요약과 링크만. **지표판이 작업대를 겸하면 둘 다 못 한다.**

| 줄 | 목적지 | 왜 그곳인가 |
|---|---|---|
| 미배정 | **OP-06 매니저** | 반 배정 |
| 개념 공백 | **OP-04 현황** | 다음 회차에 개념 교체 |
| 집단 미달 | **OP-04 구성** | 9-6은 *"시스템은 표시까지만 하고 이후 처리는 기관 판단"*이라 했다. 그중 **오퍼레이터만 할 수 있는 건 다음 회차 개념 교체** |
| 면담 적체 | **OP-06 매니저** | 반 재배정·인원 조정 |
| 파이프라인 `분석 실패` | **OP-04 현황** | 유일하게 붉은 값인데 갈 곳이 없으면 안 된다 |
| 반 비교 | **OP-02 분석** | 더 자세히 |
| 비용 | **OP-06 비용** | 기관 총량·기수/반 |

**`반 전체 공지`는 만들지 않는다.** 9-6이 후속 예시로 들었지만(*"반 전체 공지 한 번"*)
**공지 기능이 어느 문서에도 정의된 적 없다** — 채널도 대상도 문구 규약도 없다.
기능이 생기면 그때 목적지를 추가한다.

## 6. 상태 — 왜 그렇게 정했나

> **케이스 표는 목업에 있다** — [`operator/dashboard.html#cases`](../wireframe/operator/dashboard.html#cases).

### 조치 필요 0에 무엇이 없는지를 쓴다

빈 목록만 두면 **이슈가 없는 것**인지 **아직 안 본 것**인지 구분되지 않는다 → `집단 미달 · 개념 공백 · 면담 적체 · 미배정` 넷을 나열하고 전부 없다고 말한다.

### 집단 미달이 여러 반이면 반 문제가 아니다

같은 개념에서 여러 반이 미달하면 **개념 선택 자체**를 다시 봐야 한다.

| | |
|---|---|
| **한 반** | 그 반에 안내 |
| **여러 반** | `7개 반에서 "Graph 구성"`으로 **묶어서** 보여준다 — 반마다 공지를 보내면 원인을 못 고친다 |

### 회차 시작 전 반 비교는 직전 회차 값이다

강조하지 않으면 **지금 회차 결과로 읽는다.** 파이프라인은 `0/250`인데 반 비교에 숫자가 차 있으면 특히 그렇다.

### 순위를 붙이지 않는다

반 비교는 막대만 두고 1위·2위를 쓰지 않는다 — 줄세우기가 되면 그 지표를 관리하려는 행동이 나온다.
## 7. 안 하는 것

| | 어디에 |
|---|---|
| 개별 학생 위험 목록 | **매니저 소관**(MG-01·MG-03) |
| 면담 목록 | **없다** — 담당 반이 없다 |
| 개념별 상세 분포 | **OP-02** |
| 등수·순위표 | **어디에도 없다** — 매니저 줄세우기가 되면 그 지표를 관리하려는 행동이 나온다 |
| 처리 액션 | **없다** — 요약과 링크만. 지표판이 작업대를 겸하면 둘 다 못 한다 |
