> **이 문서는 순서다.** 화면 하나를 시작할 때 위에서부터 따라간다.

> 사본이 생기면 드리프트가 시작되고, 규약이 3개면 지켜지는 건 0개다.

## 0. 왜 이 문서가 있나

API가 없는 동안 화면을 만들면 **목 데이터·기획 상수·표시 규칙·UI 상태가 한 파일에
섞인다.** 그러면 연동할 때 무엇을 지워야 하는지 아무도 모르고, 화면을 다시 짜게 된다.

실제로 OP-03에서 그 일이 일어났다 — 전량 배열을 화면에서 `filter`·`sort`·`reduce`로
돌리게 짰다가, **실제 API는 그 결과를 서버가 준다**는 것을 깨닫고 전부 옮겼다.
표·목록 화면이 **15개** 남아 있으므로 그 재작업을 15번 하지 않으려고 순서를 적는다.

## 1. 착수 전 — 30분 안에 끝난다

### 1-1. 있는 것부터 센다. 손으로 만들기 전에 `grep`한다

| 어디 | 무엇이 있나 |
|---|---|
| `src/components/ui/` | shadcn 프리미티브 **33개** |
| `src/components/common/` | `PageHeader` · `TableFrame` · `Wordmark` |
| `src/app/InputCompositionsPreview.tsx` | **입력 10범주가 지금 컴포넌트로 되는지 실제로 조립해 둔 화면** |
| [component-page-map.md](component-page-map.md) | 어느 화면이 어느 프리미티브를 쓰는지 |
| `src/features/auth/` | 폼·상태·목 API의 **참조 구현** |

> ### 실제로 어긴 것
> `Field`/`FieldLabel`이 있는데 `<div className="flex flex-col gap-1.5"> + <Label>`을
> 다섯 번 손으로 만들었다. `ButtonGroup`이 있는데 2지 토글을 `<Button>` 두 개로 만들었다 —
> **`InputCompositionsPreview.tsx`에 "2지 토글 — ButtonGroup"이라고 적혀 있는데도.**
> `Badge`가 있는데 칩을 인라인 클래스로 다시 그렸다.
>
> 그 프리미티브 목록은 **"되는지 확인해 둔 결과"** 다. 안 보고 짜면 그 확인이 버려진다.

### 1-2. 문서의 「반영 완료」류 표를 믿지 않는다

`01-design-checklist.md`가 `ConsoleShell`에 본문 폭 상한이 **있다고** 적어 뒀는데
실제 코드엔 없었다. 같은 표의 `TraineeShell.tsx`는 **존재하지 않는 파일**이었다.

**`grep`으로 확인한다.** 문서는 사람이 쓰고 코드는 안 따라온다.

### 1-3. 읽을 것 — 정의서와 목업, 둘 다

| | 담는 것 |
|---|---|
| **정의서**(`definition/XX-*.md`) | 왜 그렇게 정했나 · 안 하는 것 · 다른 화면과의 경계 |
| **목업**(`wireframe/*/*.html`) | **케이스 표(`#cases`)가 계약** · 상태별 그림 |

**정의서와 목업이 어긋나면 목업이 이긴다**(케이스·문구 한정 — `00-index.md`).
실제로 OP-03에서 정의서 §3 스케치는 `진행·조치` 열이 있는데 목업 `doc-head`는
*"진행·조치 열을 두지 않는다"* 고 명시적으로 반박한다.

## 2. 목업에서 값을 옮길 때

### 2-1. 토큰 이름이 아니라 **px 값**을 옮긴다

**목업 간격 토큰의 번호는 Tailwind 번호가 아니다.**

| 목업 | px | 같은 번호 Tailwind | |
|---|---|---|---|
| `--sp-1` ~ `--sp-4` | 4·8·12·16 | `1`~`4` | 일치 |
| **`--sp-5`** | **24** | `p-5` = 20px | **4px 부족** |
| **`--sp-6`** | **32** | `p-6` = 24px | **8px 부족** |
| **`--sp-8`** | **48** | `p-8` = 32px | **16px 부족** |

오퍼레이터 목업 5장에서만 이 구간이 **78회** 쓰인다. 이름을 보고 옮기면 전부 좁아진다.

**어긋나는 축은 간격 하나뿐이다** — `--fs-*`·`--r-*`는 `--text-*`·`--radius-*`와 값이
전부 같아서 이름을 그대로 믿어도 된다. (D21)

### 2-2. 목업은 반응형이 아니다 — 비교하려면 1920으로 본다

```css
.viewport{ width:1920px; zoom:.6625 }   /* 1920으로 그린 뒤 축소 */
```

**창을 어떻게 놓든 항상 1920 레이아웃을 축소해 보여준다.** 실제 앱은 창 폭을 따라가므로
1512 창에서 좌우 여백이 32px뿐인 것이 **정상**이다(상한 1280에 안 닿으므로).

목업의 226px와 다른 것은 버그가 아니다. **브라우저를 1920으로 맞추거나 축소해서 본다.**

### 2-3. 레이아웃 수치는 우리가 정한다. 문구·상태·케이스는 목업이 계약이다

| | 주인 |
|---|---|
| 컬럼 폭 · 여백 · 정렬 tie-break | **우리** — 목업이 규칙을 어긴 자리가 있다 |
| 케이스 표의 문구 · 에러코드 · 상태 이름 | **목업** — 보안 규칙이 문구에 실려 있다 |

> ### 목업이 규칙을 어긴 실제 예
> `operator/projects.html`은 표 **6열 전부에 폭을 줬다.** `table-layout:fixed`는 모든
> 열에 폭이 있으면 남는 폭을 **비례 분배**하므로, 선언한 112·64·180·230·124·108이
> 실제로는 175·100·281·359·194·169로 렌더됐다 — **462px가 흩어져 선언값이 무의미**했다.
>
> 체크리스트가 이미 *"마지막 열에만 폭을 주지 않는다"* 고 정해 뒀고, 먼저 만든 MG-05는
> 지키고 있다. **목업 px을 베끼지 말고 실제 콘텐츠를 재서 8배수로 올린다.** (D22)

### 2-4. 값을 지어내지 않는다

목업에 있는 숫자를 그대로 옮긴다. **화면마다 목을 따로 만들면 같은 회차가 화면마다
다른 값을 갖는다** — OP-01 파이프라인과 OP-04 현황이 같은 `미프 3차`를 읽는다.

## 3. 구조 — 화면은 목을 몰라야 한다

### 3-1. 파일 배치

```
features/{역할}/{도메인}/
├─ types.ts       계약 — 서버와 주고받는 모양 · 에러코드      (백엔드 합의 대상)
├─ rules.ts       기획 상수 — 서버도 같은 값을 검증한다        (연동해도 남는다)
├─ labels.ts      표시 라벨 — 화면 것                          (연동해도 남는다)
├─ api.ts         ★ 경계 — 화면이 유일하게 의존하는 곳
├─ mockDb.ts      목 데이터                                    (연동 시 파일째 삭제)
├─ useAsync.ts    조회 훅
├─ components/    목록·상세가 같이 쓰는 조각
├─ list/          목록 전용 (화면 · 필터 상태 · 셀 · 모달)
└─ detail/        상세 전용
```

**공유물을 `list/` 안에 넣지 않는다.** 상세가 같은 타입·규칙·라벨을 쓴다 — 넣으면
상세를 만들 때 도로 꺼내야 한다. 반대로 목록 셀은 상세가 다르게 그리므로 `list/` 전용이다.

**auth가 이미 이 방식이다**(`authApi.ts` · `mockDb.ts` · `authTypes.ts`). 새 패턴이 아니다.

### 3-2. 표식을 남긴다 — 검색 한 번으로 지울 것이 다 나와야 한다

```ts
// mockDb.ts 머리
// ⚠️ Mock 전용 데이터 — 백엔드 연동 시 이 파일을 통째로 삭제하세요.

// api.ts 각 함수 안
// ===== Mock 버전 (현재 활성) =====
...
// return http<T>(`/cohorts/${id}/projects?${params}`)   ← 실제 버전을 주석으로 같이 둔다
```

### 3-3. 화면이 서버 일을 하지 않게 한다

**이게 가장 자주 틀리는 지점이다.** 목이 배열이라 화면에서 도는 게 되지만, 실제 API는
그 결과를 준다 — 그대로 두면 연동이 재작성이 된다.

| 화면이 하면 안 되는 것 | 왜 |
|---|---|
| 전량을 받아 `filter` | **쿼리 파라미터**가 된다 |
| 배열 `sort` | 페이지가 나뉘면 **현재 페이지 안에서만** 맞다 |
| 상태별 집계 `reduce` | 전체 모집단 기준이라 **페이지가 나뉘면 못 센다** |
| 연관 목록에서 개수 합산 | 그 목록 전량을 받아야만 셀 수 있다 → 서버가 숫자로 준다 |

> **지금 화면은 "전량을 받아 내가 거른다", 실제는 "거른 결과를 받는다"** — 이 둘은
> 화면 코드 모양이 다르다. 목 단계에서 후자로 맞춰 둔다.

**목 안에서는 그 로직을 그대로 쓴다** — 지우는 게 아니라 **서버 자리(`api.ts`)로 옮기는 것**이다.

### 3-4. 목 전용 값도 경계를 통해 나간다

```ts
// ✗ 화면이 목 파일을 연다 — mockDb를 지우는 순간 화면이 깨진다
import { MOCK_TODAY } from '../mockDb'

// ⭕ 경계가 준다 — 연동 시 api.ts 한 줄만 바뀐다
export function getToday() {
  return MOCK_TODAY                                  // ===== Mock =====
  // return new Date().toISOString().slice(0, 10)
}
```

**날짜를 얼리는 이유:** 실제 `new Date()`를 쓰면 값이 매일 달라져 목업과 대조할 때
무엇이 맞는지 알 수 없다. **기준일만 고정하고 계산은 실제로 한다** — 하드코딩 표를
두면 목에 없는 값이 조용히 사라진다.

### 3-5. `Promise`가 되면 로딩·에러가 따라온다

이건 부담이 아니라 **완료 조건**이다(git-convention §6). 나중에 붙이면 화면을 또 고친다.

경합을 막는다 — 필터를 빠르게 바꾸면 **먼저 보낸 요청이 나중에 도착**할 수 있다.

```ts
useEffect(() => {
  let alive = true
  load().then(v => { if (alive) setData(v) })
  return () => { alive = false }
}, [load])
```

## 4. 기획에 없는 값을 만나면

**화면이 기준을 만들지 않는다**(체크리스트 E8). 임계값·색 구간·단위·조건 필터가 전부 포함된다.

그런데 화면을 그리려면 정해야만 하는 경우가 있다. 그때는 **숨기지 말고 표시한다.**

```ts
/*
  ⚠ 이 숫자는 기획에 없다 — 프론트가 정한 값이다.
  목록의 유일한 경고가 "마감 임박 + 준비 중" 조합인데 임박의 정의가 어느 문서에도 없다.
  일주일을 고른 이유는 "다음 주 회차를 이번 주에 준비한다"는 것뿐이다.
  기획에서 값이 나오면 여기만 바꾼다.
*/
export const DUE_SOON_DAYS = 7
```

그리고 **PR 본문과 이슈에 질문으로 남긴다.** 코드에만 적으면 아무도 안 본다.

## 5. YAGNI — 안 쓰는 것을 계약에 먼저 넣지 않는다

목 단계에서는 "나중에 필요할 것 같은" 필드를 넣기 쉽다. 실제로 넣었다가 지운 것들:

| | 왜 지웠나 |
|---|---|
| `isApiError()` · `ApiError` | **사용 0회.** 쓰지도 않는 타입 가드 |
| `'NETWORK'` 에러코드 | **케이스 표에 없다.** 문구도 다음 행동도 정해진 게 없어 화면이 받아도 쓸 수 없다 |
| `page` · `size` 쿼리 | 아무도 안 보낸다. 페이저를 그리지 않으므로(E7) 실제로 나뉘어야 하는 화면에서 더한다 |

**지운 자리에 왜 안 넣었는지를 남긴다** — 다음 사람이 다시 넣는다.

반대로 **남길 근거**: 화면이 실제로 렌더하거나(`total`), 계약 모양이 그것을 전제하면 남긴다.

## 6. 완료 판정

[git-convention §6](../handbook/git-convention.md)이 정의를 갖는다. 실무 점검:

```
□ 케이스 표의 상태를 전부 그렸나 (정상·로딩·에러·빈 상태 2종)
□ 목 데이터로 실제 동작하나 (누르면 결과가 나오나)
□ 키보드로 되나 — 행 클릭만 있으면 Tab·Enter로 상세에 못 간다
   → 이름을 <Link>로. 새 탭·주소 복사 같은 브라우저 기본 동작도 따라온다
□ 화면이 mockDb를 import하지 않나 (grep)
□ 안 쓰는 타입·상수가 남지 않았나 (grep)
□ typecheck · lint · check:design · build
□ 1920·1512에서 실제로 렌더해 봤나
```

**추측하지 말고 잰다.** "폭이 안 맞는 것 같다"는 실측으로만 갈린다 — 실제로 죽은 포트를
보고 있었던 적도, 목업의 `zoom` 때문에 착시였던 적도 있다.

## 7. 크기 — 한 PR에 다 넣지 않는다

팀이 실제로 한 화면 커밋:

| | 파일 | 줄 |
|---|---|---|
| MG-05 교육생 명부 | 4 | +704 |
| AU-01 로그인 | 11 | +773 |
| AU-03 비밀번호 재설정 | 8 | +629 |
| **OP-03 (한 번에 넣은 것)** | **21** | **+1816** |

규약은 **10파일 이내 권장**이다. OP-03은 두 배가 넘었다 — 리뷰어가 30분 안에 못 본다.

**성격이 다른 것부터 자른다.**

| | 리뷰어가 답할 질문 |
|---|---|
| **문서**(계약·경계) | *"백엔드와 이 계약이 맞나"* — **반드시 분리.** 화면 diff에 묻히면 아무도 안 본다 |
| 도메인 경계(types·rules·api·mock) | *"이 모양이 맞나"* |
| 화면 | *"스펙대로 그렸나"* |

## 8. 자주 틀린 것 — 한 줄 요약

| | |
|---|---|
| 손으로 만들기 전에 `grep` | `Field`·`ButtonGroup`·`Badge`를 세 번 다시 만들었다 |
| 토큰 **이름**이 아니라 **px** | `--sp-6`은 32px, `p-6`은 24px |
| 목업 px을 베끼지 말고 잰다 | 6열 전부에 폭을 주면 `table-fixed`가 비례 분배한다 |
| 화면이 `filter`·`sort`·`reduce` 하면 서버 일을 뺏은 것 | 연동 시 재작성 |
| 화면이 `mockDb`를 import하면 경계가 뚫린 것 | 목을 지우면 화면이 깨진다 |
| 기획에 없는 값은 **표시하고 질문** | 조용히 정하면 근거를 못 댄다 |
| 안 쓰는 필드는 넣지 않는다 | 계약에 남아 백엔드가 만든다 |
| 문서의 "반영 완료"를 믿지 않는다 | 실제로 틀려 있었다 |
