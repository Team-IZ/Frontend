# SA-02 · 기관 상세 — 탭 4

## 1. 한 줄

한 기관의 **계약·계정·사용량**을 본다. 내부 운영에는 들어가지 않는다.

## 2. 진입 · 이탈

SA-01 행 → 여기.

## 3. 뷰

```
그린컴퍼니 부트캠프                                      활성
[ 개요 ] [ 오퍼레이터 ] [ 사용량 · 비용 ] [ 설정 ]
```

| 탭 | 내용 |
|---|---|
| **개요** | 상태 · 기수 목록(진행/종료) · 교육생 수 · 오퍼레이터 |
| **오퍼레이터** | 계정 목록 · `[+ 오퍼레이터 초대]` · 정지/재활성 |
| **사용량 · 비용** | 모델별 호출·토큰·단가 · 월 추이 |
| **설정** | 계약 한도 · 기능 토글 · 테넌트 정책 |

**`오퍼레이터` 탭은 계정 관리이지 매니저 관리가 아니다.** 반 담당 매니저는 기관 안에서
오퍼레이터가 초대한다 — 슈퍼어드민은 **첫 오퍼레이터 하나만** 넣는다(부트스트랩).

### 초대 모달

이메일만. 기수 배정 없음 — 오퍼레이터는 기관 전체를 본다.

## 4. 데이터

기관 메타 · 기수 목록 · 오퍼레이터 계정 · 모델별 사용량·단가 · 한도.

## 5. 액션

초대 · 정지/재활성 · 한도 수정.

## 6. 상태 — 왜 그렇게 정했나

> **케이스 표는 목업에 있다** — [`superadmin/console.html#cases-sa02`](../wireframe/superadmin/console.html#cases-sa02).

### 집계 실패를 0으로 보여주지 않는다

**안 쓴 것**과 **못 읽은 것**은 다르다. 0으로 그리면 **청구액이 실제보다 작아 보인다** — SA-03의 `단가 미설정`과 같은 원칙이다.

**실패는 그 영역만 막는다.** 기관 정보·다른 탭은 그대로 볼 수 있어야 한다. 사용량 하나 때문에 화면 전체를 에러로 덮으면 지원 업무가 멈춘다.

### 초대 메일이 실패해도 자리를 지우지 않는다

지우면 같은 주소로 다시 초대했을 때 **중복 초대인지 재시도인지 구분되지 않는다.** `지정됨 · 메일 발송 실패`로 남기고 재발송을 붙인다.

### 마지막 오퍼레이터는 정지할 수 없다

정지하면 **기관에 들어갈 수 있는 사람이 아무도 없어진다.** 기수·반·명단을 만들 사람이 없으니 그 기관은 아무것도 못 한다 — 슈퍼어드민이 다시 초대해야만 풀린다.

## 7. 안 하는 것

| | 어디에 |
|---|---|
| 기수 개설 · 반 편성 · 명단 | **오퍼레이터**(OP-06) |
| 학생 데이터 열람 | **테넌트 경계 밖** |

### 기관 삭제 — 즉시 파기가 아니다

설정 탭 맨 아래 위험존에 **[기관 삭제]**가 있다. 누르면 **확인 모달**이 뜨고 **기관명을 직접 입력**해야 진행된다.

| | |
|---|---|
| **소프트 삭제만** | 보존기간(180일)이 지난 뒤 파기된다. 그전까지는 **복구할 수 있다** |
| **보존기간 전 파기는 차단** | 즉시 물리 삭제 경로를 두지 않는다 — 실수로 지우면 되돌릴 방법이 없다 |
| **정지와 다르다** | 계약만 끝났으면 **`기관 상태`를 정지**로 두면 된다(계정 유지 · 로그인만 차단). 삭제는 데이터를 파기 대상으로 넘기는 것이다 |

**기관명 입력을 요구하는 이유** — 소속 오퍼레이터·매니저·교육생 전원이 못 들어오게 되는 액션이라, 버튼 한 번으로 끝나면 안 된다.
