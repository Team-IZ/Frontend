## 1. 🔴 R1 — 발행 전 기수의 리포트가 응답하지 않습니다

`GET /api/v0/reports/class-diagnosis?cohortId=`

### 재현 — 기수 4개 전수 (curl, 55초 상한)

| 기수 | `status` | 결과 |
|---|---|---|
| **10기** | **PLANNED** | **HTTP 000 · 55초 타임아웃** |
| 9기 | RUNNING | 200 · TTFB **2.00초** · `IN_PROGRESS` |
| 8기 | CLOSED | 200 · TTFB **2.83초** · `CONFIRMED` |
| 7기 | CLOSED | 200 · TTFB **2.46초** · `CONFIRMED` |

**아직 시작하지 않은 기수에서만** 응답이 오지 않습니다. 진행 중·종료 기수는 전부 2~3초로
일정합니다.

### 프론트는 이미 준비돼 있습니다

**404 `COHORT_REPORT_NOT_FOUND`를 「아직 발행 전」으로 그리는 코드가 이미 있습니다**
(`lib/errorCopy` — 「없는 것」 3종 중 **유형 1 `아직`** 으로 판정하고, 다시 눌러도 리포트가
생기지 않으므로 **재시도 버튼도 안 그립니다**).

그런데 **그 404가 오지 않아서 그 분기에 도달하지 못합니다.** 화면은 스켈레톤인 채로
멈춰 있고, 12초가 지나면 「예상보다 오래 걸립니다」라는 안내만 뜹니다.

**404만 주시면 화면은 바로 맞게 동작합니다.** 프론트에서 고칠 것이 없습니다.

### 왜 급한가

**새 조직의 첫 기수는 `PLANNED`입니다.** 처음 쓰는 사람이 리포트 메뉴를 누르면
이 상태를 만납니다.

### 18차와 묶어서 보시면 좋겠습니다

| 엔드포인트 | 정상 | **무응답** | |
|---|---|---|---|
| `/curricula/{id}/sections` | 분석된 교안 (2.0~2.5초) | **분석 전 교안** | 18차 R1 |
| `/projects/{id}` | 존재하는 회차 (2.1초) | **없는 회차** | 18차 R7 |
| `/projects/{id}/class-progress` | 시작·종료된 회차 (2.2~2.8초) | **시작 전 회차** | 18차 R8 |
| `/reports/class-diagnosis` | 진행 중·종료 기수 (2.0~2.8초) | **시작 전 기수** | **이번** |

네 곳이 같은 규칙으로 갈립니다 — **「보여 줄 데이터가 아직 없는 상태」에서만 매답니다.**
정상 경로는 전부 2~3초로 일정하고, 실패 경로만 에러 없이 커넥션이 열린 채 남습니다.
형식이 틀린 값(`/projects/abc`)은 **0.7초에 400**으로 정확히 오므로 라우팅·검증 층은
정상입니다.

**공통 층(집계 대기·비동기 파이프라인 조회 등)의 문제로 보입니다** — 한 곳을 고치면
넷이 같이 풀릴 것으로 봅니다. 네 개가 다 같은 증상이라 그 가능성이 더 높아졌습니다.

## 2. 🟡 Q1 — `publishedAt`만 타임스탬프입니다

`ClassDiagnosisReport` 응답에서 날짜 필드의 형식이 갈립니다.

```jsonc
"publishedAt":  "2026-03-05T00:00:00Z",   // ← 타임스탬프
"periodStart":  "2025-09-01",             // ← 날짜
"periodEnd":    "2026-02-27"              // ← 날짜
```

시각이 `00:00:00Z`로 고정이라 **정보가 없는 시각**입니다. 그대로 그리면 문서 표지에
이렇게 찍힙니다.

```
2026-03-05T00:00:00Z 미니프로젝트 전체 6회 완료 시점으로 고정
```

**화면은 날짜만 잘라 쓰도록 고쳤습니다**(표지·CSV 내용·파일명). 다만 셋이 **같은 문서
안의 날짜**인데 형식이 갈리는 것이 의도인지 확인하고 싶습니다.

- **발행 시각이 실제로 의미가 있다면**(예: 같은 날 두 번 발행될 수 있다면) 지금 그대로
  두시고, 알려만 주시면 화면이 시각까지 그리겠습니다.
- **날짜만 의미가 있다면** `periodStart`처럼 `format: date`로 맞춰 주시면 좋겠습니다.

## 3. 🟡 Q2 — 리포트의 두 목록이 반 이름순으로 옵니다

`classRisk` · `groupShortfalls` 둘 다 **반 이름 오름차순**입니다(8기 실측).

```
classRisk         A 17% · B 17% · C 16% · D 21% · E 13% · F 17% · G 12% · H 19%
                                          ↑ 가장 나쁜 반이 4번째

groupShortfalls   A반 → H반 (11건)
                  가장 나쁜 H반 88%가 11번째, 즉 맨 아래
```

이 섹션이 답하려는 질문이 *"어느 반이 가장 나쁜가"* 라서 **화면에서 나쁜 순으로 다시
정렬했습니다.** 프론트 쪽은 해결됐습니다.

확인하고 싶은 것은 **의도**입니다.

- 반 이름순이 **의도한 계약**이면 그대로 두시면 됩니다 — 화면이 정렬 책임을 갖겠습니다.
- 심각도 순으로 주실 생각이었다면 지금 구현이 다릅니다.

> 저희 쪽 코드 주석에 *"이미 나쁜 순으로 정렬된 데이터가 온다"* 고 적혀 있었는데
> 실제와 달랐습니다. 어느 쪽이든 **한 번 정해 주시면 그대로 따르겠습니다** — 화면이
> 정렬하면 CSV·PDF도 같은 순서로 나갑니다.

## 4. 🟡 Q3 — `groupShortfalls[].round`가 빈 문자열입니다

`ClassDiagnosisReport.groupShortfalls`

```jsonc
{
  "conceptName":   "트랜잭션 경계 설정",
  "curriculumName":"Spring 백엔드 설계",
  "section":       "서비스 계층 트랜잭션 (p.22–24)",
  "round":         "",            // ← 8기 11건 전부
  "className":     "A반",
  "shortfallCount": 15,
  "totalCount":     22
}
```

집단 미달 표의 「회차 · 반」 열이 `{round} · {className}`이라 화면에 **`· H반`** 처럼
구분점만 매달렸습니다. **화면은 빈 값이면 구분자를 안 그리도록 고쳤습니다** — 값이
오면 그대로 붙습니다.

같은 응답의 `classRiskRoundLabel`은 `미니프로젝트 6차 이해도 확인`으로 잘 옵니다.
집단 미달이 **어느 회차의 것인지**가 이 필드로만 알 수 있어서, 값이 있어야 하는 자리로
보입니다. 확인 부탁드립니다.

- **회차 개념이 없는 집계라면**(전 회차 합산 등) 필드를 빼 주시거나 `null`로 주시면
  화면이 「전 회차」로 읽겠습니다.
- **회차별 집계라면** `classRiskRoundLabel`과 같은 형식으로 채워 주시면 됩니다.
