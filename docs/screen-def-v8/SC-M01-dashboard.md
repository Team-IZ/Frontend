# SC-M01 · 대시보드

> 소스: 기능명세서 v8 DASH-01(통합 현황) + DASH-02(자동 브리핑) + DASH-03(우선순위 정렬) + DASH-04(벤치마크) + DASH-05(개입 타이밍 문구) + DASH-06(채점 안정성) + DASH-07(추천 성능) + DASH-08(표본부족) + DASH-09(채점 근거 원본) + INTV-01(개입 추천) + INTV-02(실행 초안) + INTV-03(추천 이의).
> 배치: P0. 매니저 앱 셸 공유. **모든 화면을 집계하는 홈** — 가장 마지막에 설계(다른 화면 확정 후).

## 2. 목적 & UX 설계 근거

- **대시보드는 전경(overview) → 조치다(view-patterns·D61).** 먼저 **기수 전체 상태를 한눈에**(KPI·추이·취약·개입 파이프라인) 보여주고, 그다음 **Priority 정렬 인박스**로 "지금 누구부터"를 잇는다. 전경을 죽이고 할 일 목록만 두면 대시보드의 본질이 흐려진다(D61).
- **로그인 즉시 브리핑(DASH-02).** "마지막 확인 이후 신규 위험 N건" 요약을 최상단에. 확인 시 마지막 확인 시각 갱신. 신규 위험 없으면 정상 메시지. 중복·동일 원인 시그널은 요약.
- **통합 현황은 요약 지표 줄(DASH-01).** 이해도·참여도·팀 진행률·응시율·활성 시그널·미처리 개입. 결측 지표는 "데이터 없음", 기준 시각 병기, 대량 지연 시 캐시 우선+갱신 표기.
- **순위는 근거와 함께(DASH-03·A2).** Priority=S×(0.5+R) (S=(기수평균−개인)/σ, R=라플라스 (회복+1)/(전체+2)). 각 행에 **순위·실제값·수식 구성요소·사유 문구**. **근거 문구 없으면 순위 표시 차단**. 표본<2·σ=0이면 S 생략·표본 부족(DASH-08). 축은 v1 동일가중.
- **타이밍 문구는 항상 표시, 상태만 전환(DASH-05·A7).** 즉시 확인 필요 / 경과 관찰(쿨다운) / 회복 확인 / 추가 확인 필요(상충) / 데이터 부족. **매니저가 방치해도 카드에서 조용히 사라지지 않는다**(모순 문구 금지). 권고형(과도한 확정 표현 제거).
- **추천은 배타적 결정리스트(INTV-01).** 낮은 축(≤2) 개수로 트리 분기: 3개↑→멘토링 / 1~2개+반례·자기수정→면담 / 1~2개+기술영역→보강 / 0개+팀편차→팀조정 / 그 외→모니터링. **최초 매칭 1건만**, 근거 없으면 차단. 초안(INTV-02)은 슬롯 템플릿+편집 플래그.
- **확정은 사람이 한다(GOV-02).** 추천·초안은 제안, [개입 생성]은 매니저 액션 → SC-M07. 표본 부족(DASH-08)이 매니저의 다른 선택을 막지 않음(사유 필수).
- **추천 품질(접힌 메타 strip) = 신뢰 신호.** 추천 성능(DASH-07 자연빈도 우선·N<5 진행바), 규칙 재검토(INTV-03 최근5건 중 3건 기각), 채점 안정성(DASH-06 2상태). 매일 쓰는 게 아니라 배지로 압축, 펼치면 상세. 채점 근거 원본(DASH-09)은 매니저 전용 온디맨드.
- **온디맨드 패널:** 벤치마크(DASH-04 due_at 스냅샷 고정), 초안(INTV-02), 근거 원본(DASH-09).

## 3. 정보 구조 & 레이아웃 (매니저 앱 셸 · 데스크톱)

**3계층 — 전경(본질) → 조치 → 품질(메타). 대시보드는 먼저 "기수 전체가 지금 어떤 상태인가"를 한눈에 보여주고, 그다음 조치로 이어진다.**

0. **브리핑 배너(DASH-02):** 지난 방문 이후 변화 요약 + 확정 대기/즉시/회복 칩 + [브리핑 확인].

**① 기수 전경 (Overview · prominent):**
- **KPI 6(DASH-01):** 위험 인원·이해도·응시율·활성 시그널·참여도·팀 진행률. 각 지표에 **방향(Δ·ENG-02)** + **[ⓘ 출처]**(데이터 계보). 결측·정의 미비 명시.
- **전경 3패널:** **이해도 추이**(회차별 기수 평균 line → 회차 비교), **취약 지점**(5축 mini bar, 최약 강조 → 히트맵 SC-M05), **개입 파이프라인**(대기/진행/완료 + 회복률 자연빈도 → SC-M07).

**② 확인·조치 필요 (Action):**
- **우선순위 인박스(DASH-03):** Priority 정렬 + **트리아지 필터**(확정 대기/관찰/회복/표본 부족) + **변화 마커**(NEW·회복).
- 행 = 순위·이름·Priority·수식칩·**타이밍(DASH-05)**·사유·**신뢰(표본 회차)**·**추천(INTV-01)** + **초안(INTV-02·온디맨드)** + [✓확정→SC-M07]·[수정]·[미루기].
- **묶음 검토**(같은 유형 배치·각각 개별 기록). 관찰·회복·표본 부족은 **접힌 그룹**(개수만).

**③ 추천 품질 (Meta · compact):** 접힌 strip — 채점 안정성(DASH-06)·추천 성능(DASH-07)·규칙 재검토(INTV-03) 배지, 펼치면 상세.

**온디맨드:** [초안]→INTV-02, [벤치마크]→DASH-04 스냅샷, [근거 원본]→DASH-09 매니저 전용, [ⓘ 출처]→데이터 계보 패널(원천→처리→시각·[03-data-flow.md](03-data-flow.md)).

> **설계 원칙(D61):** 자동화의 마지막 1cm = 확정 대기 큐(AI가 추천·초안까지 작성, 매니저는 검토·확정만·GOV-02). 단 이것이 대시보드의 본질인 **전경 파악**을 가리지 않도록 전경을 상단에 prominent하게 둔다.

반응형: 웹 기준(모바일은 KPI 2~3열·전경 세로 스택).

## 6. 상태별 UI (예외 case 전량 — 게이트 A)

**DASH-01 6 + 02 6 + 03 8 + 04 6 + 05 8 + 06 6 + 07 7 + 08 6 + 09 7 + INTV-01 8 + 02 7 + 03 7 = 82.**

와이어프레임 §상태 매핑에 12개 FR × 전 case 82행을 pill 처리 유형(차단/보류/유지/N-A)과 함께 수록. 대표:
- **DASH-03:** 근거 문구 생성 실패 → 순위 표시 차단(A2) / 표본<2·σ=0 → S 생략·DASH-08 / 회복 0건 → 라플라스 R=0.5.
- **DASH-05:** 쿨다운 → 경과 관찰 / 상충 → 추가 확인 필요 / 회복세 → 회복 확인. 항상 표시(A7).
- **DASH-06:** 3단계 이상 요청 차단(2상태만).

## 7. 인터랙션 & 화면 전이

- [브리핑 확인] → 마지막 확인 시각 갱신 → 신규 diff 초기화.

- 행/상세 → **SC-M06**(개별 상세), 위험 목록 → **SC-M04**.
- **환류:** 규칙 재검토 플래그 → 추천 규칙 개선(사람 검토·flow-contract).
