프로젝트 — 목록 · 상세

회차를 만들고 무엇으로 잴지 정하는 화면. 프로젝트 생성 시 교안 연결(1개 이상) + 검증 개념 3건을 확정한다 — 이 3건이 그 회차 모든 학생의 문항 3개가 되고, 팀·반이 달라도 같은 축으로 비교된다. 한 회차가 교안 하나에만 걸치지 않으므로 교안은 여러 개를 붙일 수 있고, 검증 개념 후보는 연결한 교안들이 가르친 항목을 합쳐서 만든다. 요구사항은 교안과 별개 입력이고 구현 P/F에만 쓴다. 팀 편성·독촉·리포트는 매니저 화면(MG-08) 소관이라 여기 없다.

Supervisor 패턴의 HITL 실행 흐름p.53

HITL 개념 정의p.48
HITL은 LLM 시스템의 의사결정을 통제하기 위한 Control Layer로, 실행 결과를 검증·차단·수정한다.
AI_LLMOps v2 · 역할 기반 설계 (p.37–46)
✓
Supervisor 패턴과 역할 분리 구조p.41
Supervisor 패턴은 전체 흐름을 통제하는 중앙 조정자가 Planner, Executor, Critic Worker를 호출해 역할을 분리하는 아키텍처이다.
Critic 역할p.40
Critic은 실행 결과를 독립적으로 검토하여 정확성·일관성·정책 준수 여부를 평가하고, 필요 시 재실행을 요청한다.
AI_LLMOps v2 · 시점 관리 (p.62–75)
✓
Snapshot 개념과 구성 요소p.63
실행 중 특정 시점의 State를 저장해 이후 재개·디버깅에 쓰는 구조와 그 구성 요소를 다룬다.
Streamlit 실습 v1 · 세션 상태 (p.18–31)
세션 상태와 재실행p.22
위젯을 조작하면 스크립트가 처음부터 다시 실행되며, 유지해야 할 값은 session_state에 둔다.
후보는 교안 분석이 내놓은 `가르친 항목`이고, 교안 · 섹션으로 묶어 보여준다. 합쳐서 늘어놓으면 p.53이 어느 교안 어느 섹션의 53쪽인지 알 수 없다.
