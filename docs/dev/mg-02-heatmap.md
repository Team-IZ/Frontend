- **정의서·목업 밖에서 이번 세션이 직접 채운 빈틈 4건:**
  1. **툴바 `반별/팀/개인` 버튼으로 반을 아직 안 고른 채 팀·개인으로 바로 넘어갈 때** — OP-02 `RoundToolbar`는 팝오버를 강제로 열어 사용자가 직접 고르게 하지만, MG-02의 반 select는 항상 값이 있어야 하는 일반 `Select`라 그 패턴을 그대로 가져오면 오히려 복잡해진다. **첫 반(A반)을 기본값으로 둔다**로 판단 — 정의서가 이 갈림길을 명시하지 않았다.
  2. **정렬 "낮은 순"의 기준** — 정의서는 존재만 말하고 무엇 기준인지는 안 정했다. **그 행의 3개 개념 평균의 평균**(class/team) 또는 **그 사람의 응시한 개념 평균**(person) 오름차순으로 판단 — "문제 있는 쪽이 위로 온다"는 툴바 라벨의 뜻을 가장 직접적으로 구현하는 값이다. 미응시·결석은 정렬에서 맨 뒤로 보낸다(값이 없는 걸 "낮다"로 취급하지 않는다).
  3. **개인 뷰 "위험만" 필터의 뜻** — 오른쪽 배지 열(단계 하락·지속 저점)이 있는 사람만으로 판단(정의서가 별도 정의를 안 줬다). 반별 "⚠ 반 문제만"과 대구를 이루게, "그 행에 시스템 판정이 실제로 붙어 있는가"로 두 필터의 기준을 통일했다.
  4. **범례(색 스케일 + 개인 뷰 단계 뜻) 위치** — 정의서 본문은 "표 아래 한 줄"이라고 적었는데, 같은 문서가 원천이라 명시한 목업 HTML(`heatmap.html`)은 실제로 **표 위**(우측 정렬)에 그렸다. 케이스 계약은 목업이 원천이라는 §6 원칙대로 **목업을 따랐다** — 본문 표현은 "세로로 안 쌓고 한 줄로 압축한다"는 취지를 말한 것으로 읽었다.

6. **개인 히트맵에서 교육생 클릭 → 상세 → 뒤로가기가 명부로 가버림** — 원인은 `trainees/components/DetailHeader.tsx`(MG-06)가 뒤로가기를 `/manager/trainees`(명부) 고정 링크로 하드코딩해서였다. 이 화면은 명부·면담 목록·히트맵 등 여러 입구에서 들어오는데 고정 링크면 항상 명부로만 돌아간다 — `navigate(-1)`(브라우저 히스토리)로 바꿔 **들어온 곳으로 그대로 돌아가게** 했다. 다만 히트맵은 화면 상태(회차·계층·반·팀·정렬·필터)가 URL이 아니라 React state에만 있어서(정의서 "3장면이 같은 주소") `navigate(-1)`만으로는 주소는 돌아와도 어떤 반·팀을 보고 있었는지는 리셋된다 — `heatmap/viewState.ts`를 새로 만들어(`interviews/filterState.ts`와 같은 세션 전역 패턴) 마운트 시 마지막 상태를 복원하게 했다. `DetailHeader.tsx`는 `git log --follow` 확인 결과 이 세션(사용자, vneed154) 단독 저작이라 CLAUDE.md §7 확인 없이 바로 진행.

**같은 세션 이어서 — 위험 토글이 0행이 되면 조용히 비어 보이는 문제 → 빈 결과 안내 문구:**

**같은 세션 이어서 — 팀 계층에도 위험 필터 추가 + 빈 결과 문구 가운데 정렬 버그:**
- **배경:** 두 가지 요청. ① "팀에도 위험 : 팀 필터가 있으면 좋지 않을까?"(제안형 질문) — 팀 행도 반 행과 똑같이 `cell.flagged`(집단 미달)를 갖고 있어 반별과 같은 필터를 그대로 재사용할 수 있다고 판단, 되묻지 않고 바로 추가했다. ② 방금 넣은 "위험에 해당하는 팀원이 없습니다." 문구가 스크린샷으로 보니 히트맵(색칠된 3칸) 중심보다 왼쪽에 치우쳐 있었다 — "히트맵에 중간선을 그었을 때 같은 선상에 있으면 좋겠다"는 지적.
- **① 팀 필터:** `mockData.ts`의 `HeatmapQuery.problemOnly`를 "반별에서만"에서 "반별·팀에서"로 넓히고, `getHeatmap`의 `team` 분기에도 반별과 같은 필터(`rows.filter(r => r.cells.some(c => c.kind==='value' && c.flagged))`)를 추가했다. `HeatmapToolbar.tsx`는 새 상태를 안 만들고 **기존 `problemOnly` 하나를 반·팀이 공유**하게 했다 — 두 탭은 서로 배타적으로만 보여서 상태를 같이 써도 꼬이지 않는다. 토글 라벨도 계층에 맞게 동적으로 바뀐다: `⚠ 반 : 위험`(반별) / `⚠ 팀 : 위험`(팀).
- **② 가운데 정렬 버그:** `EmptyFilterRow`가 처음엔 4칸(y축 220px + 개념 3칸)을 통째로 `colSpan`해서 `text-center`를 줬는데, y축 열까지 정렬 기준에 포함되면서 중심이 왼쪽으로 밀렸다. y축 칸은 빈 `<td>`로 남겨 `colgroup` 폭만 차지하게 하고, 나머지 개념 3칸만 `colSpan={3}`으로 묶어 그 안에서만 가운데 정렬하도록 고쳤다 — 이제 문구 중심이 히트맵 3칸의 중심과 정확히 겹친다. 팀 계층용 빈 메시지("위험에 해당하는 팀이 없습니다.")도 같은 컴포넌트로 추가했다.
- **검산:** `tsx`로 `getHeatmap` 팀 분기를 반 3개 × 회차 3개 전수 실행 — 1차 A반·B반은 `[]`(빈 결과, `EmptyFilterRow`가 뜨는 조건 재현), 2차 A반은 `['2팀']`(부분 필터링도 재현), 나머지도 예상대로 동작 확인. `/tmp` 격리 재검증 — `tsc --noEmit`(app·node)·`prettier --check`·`check-design.mjs` 전부 1차 통과.
