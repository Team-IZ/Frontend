# 화면 그릴 때 점검표

> 14~18번 결정과 [PRODUCT.md](../../../PRODUCT.md)에서 뽑았다. **화면 하나를 끝내기 전에 이 목록을 훑는다.**
>
> `⚠ 실제로 어긴 것` 표시는 v2 작업 중 실제로 발생한 사례다. 추상적 원칙이 아니라 **일어난 일**이라 남겨 둔다.

## A. 숫자와 판정

| # | 규칙 | 어기면 |
|---|---|---|
| **A1** | **합산 가능한 숫자를 화면에 두지 않는다** — 총점·평균·백분위·5점 만점 | 사람들이 그것으로 서로를 비교한다. 비보상 원칙이 사용자 머릿속에서 무너진다 |
| **A2** | 0~5 루브릭은 **내부 값**이다. 화면에는 도달 단계(0~4단)·힌트 횟수·서술만 | 축별 점수를 보면 반드시 머릿속에서 평균을 낸다 |
| **A3** | **확정 안 된 판정을 당사자에게 보여주지 않는다** | 사실이 아닌 것을 사실로 준다 |
| **A4** | **모르는 값을 아는 척하지 않는다** — 진행률 %, 남은 시간 예측, 소수점 정밀도 | 틀린 예측은 안 하느니만 못하다 |
| **A5** | 위험 판정은 **개념 단위**로 본다. 평균 내지 않는다 | `평균 2.7단`은 아무 처방도 못 낳는다. `Service에서 1단`은 낳는다 |
| **A6** | 순위·등수를 붙이지 않는다 (반 비교 막대는 되지만 1위·2위는 안 됨) | 줄세우기가 되면 그 지표를 관리하려는 행동이 나온다 |
| **A7** | **판정은 문장이 아니라 데이터 위의 마크로.** 배지·색·라벨·테두리 | 문장은 **데이터가 다르면 거짓말을 한다.** v1이 `AI 요약 일치검증`을 만들어야 했던 이유이고, 15번이 그 기능을 삭제했다 |
| **A8** | **화면의 숫자를 문장으로 다시 읽어주지 않는다** | `23명 중 12명`이 셀에 있는데 아래에 또 쓰면 중복이고, 해석은 사용자가 한다 |

### A7 — 문장으로 쓰면 안 되는 이유 셋

**① 거짓말한다.** `"10개 반 중 8반이 같은 방향"` 은 실제 값이 다르면 틀린다.

**② 판정 로직이 두 곳에 생긴다.** 프론트에서 조건 분기를 짜면 SSOT가 깨지고, 서버가
문장을 내려주면 규칙이 바뀔 때마다 문구·테스트가 따라온다. **배지·색은 이미 계산된
플래그를 표시만 하므로 추가 부담이 0이다.**

**③ 사용법을 가르치게 된다.** *"가로로 읽으면 안 된다"* 까지 가면 그건 판정이 아니라
매뉴얼이다.

> **남기는 것 하나 —** *"값이 왜 없는지"*. `이번이 첫 회차라 단계 하락을 판정하지 않습니다`
> 는 해석이 아니라 **부재의 이유**다(F1·F3).

> **⚠ 실제로 어긴 것 — A3.** TR-02 제출 화면에 요구사항 충족 `✓ / ? / ✗`를 그렸다. `?`는 매니저가 확인해야 확정되는 값이라 학생이 먼저 볼 것이 아니었다. → MG-08로 이동.
>
> **⚠ 실제로 어긴 것 — A4.** 분석 중 화면에 `코드 구조 파악 ▓▓▓░ 62%` 막대를 그렸다. 실제로 알 수 없는 값이다. → 삭제하고 "예상을 드리지 않는다"고 밝힘.

### E8 — 세 번 어겼다

**① 조건 필터** `⚠ 매 회차 오르는 반만` · `담당 없는 반만`(아래).
**② 색 경계** 위험자 비율을 `8/14/20/26/32%` 로 나눴다 — 경계값에 근거가 없었다.
**③ 요약 열** `격차 +13p · 3회 연속`에서 **`p` 단위와 `±3p` · `3회` 임계값**을 만들었다.

**색을 뺐다가 다시 넣으면서 같은 잘못을 다른 자리에서 반복했다.** 규칙은
*"화면이 기준을 정하지 않는다"* 이고, 그 기준에는 **필터·색 구간·요약 문구·단위**가
전부 포함된다.

> **정량화의 유혹이 재발 지점이다.** 비교를 보여주려면 *"얼마나"* 를 쓰고 싶어지는데,
> 그 순간 없는 눈금을 만들게 된다. **부호(좋다/같다/나쁘다)까지만** 쓰면 근거가 필요 없다.

### 처음 어긴 것

OP-02에 `⚠ 매 회차 오르는 반만` · `담당 없는 반만` 두 필터와 그 뷰포트를 그렸다.
**같은 화면이 "임계값을 정하지 않는다"고 써 놓고 필터에서 어겼다.** `미배정 반`은
**18번 99줄 OP-01 `조치 필요`의 한 줄**인데 분석의 비교 축으로 확대했고, 그 상태를 근거로
*"매니저 공백이 시작된 회차부터 벌어졌다"* 는 **인과까지 화면이 만들었다.**

**그 방향 열도 결국 지웠다** — `격차 +13p · 3회 연속`이 되면서 **단위와 임계값을
새로 만들었기** 때문이다. 남은 것은 **색의 부호**뿐이고, 거기엔 정할 것이 없다.

| **H8** | **본문에 폭 상한 1280px + 가운데.** 상한 없는 레이아웃을 만들지 않는다 | 1920에서 남는 폭이 전부 죽은 여백이 된다. 표는 컬럼이 퍼져 스캔이 안 되고, 좌우 분할은 두 덩어리가 서로 멀어진다 |
| **H9** | 좌우 분할(인증)은 **배경만 꽉 채우고 내용은 가운데 이음선에 붙인다** | 각 절반의 중앙에 두면 화면이 넓어질수록 둘이 멀어진다 |
| **H10** | **카드는 흰 바탕이 필요한 것에만** — 행 구분선으로 읽는 표·폼·모달. **자체 색을 가진 격자**(히트맵 셀·분포 막대)는 캔버스 위에 그대로 | 카드를 씌우면 중첩이 되고(H7), 셀 색과 카드 흰색이 두 겹으로 싸운다 |
| **H11** | **빈 상태는 정상 상태와 같은 컨테이너·같은 폭** | 폭이 다르면 **같은 자리가 아닌 것**처럼 보인다 |
| **H12** | **카드 없는 영역의 빈 상태는 점선 테두리 + 캔버스 배경** | 흰 박스를 쓰면 *"값이 없는데 오히려 더 눈에 띈다"* |
| **H13** | **격자·표는 컨테이너 폭을 채운다**(`width:100%` + `table-layout:fixed`). 열 폭은 **첫 열 고정 · 시각 요소가 남는 폭** | 열이 auto면 이름 칸이 남는 폭을 다 먹고 **막대 앞이 비고 숫자 칸이 좁아진다** |

### H10~H12 — 실제로 어긴 것

MG-02 히트맵은 **465px**인데 같은 자리의 빈 상태는 **720px 흰 박스**였다. *"결과가 없는
회차가 있는 회차보다 크고 눈에 띄는"* 상태였다.

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 히트맵 | 465px · 캔버스 위 | **720px** · 캔버스 위 |
| 빈 상태 | 720px · **흰 카드** | **720px** · **점선 테두리** |

OP-05는 반대였다 — 표가 **캔버스 위에 그냥** 놓여 행 구분선이 회색 위에서 흐렸다.
→ **표만 흰 카드로**(`.rcard`) 감싸고, 분포 막대·반 비교 막대는 그 안에서 폭을 채운다.

### H13 — 열 폭

`검증 개념` 열이 auto라 **남는 폭을 전부 먹었다.** 결과: 분포 막대 왼쪽에 빈 공간,
`133 / 234명`이 92px에서 줄바꿈.

```
검증 개념 264px │ 도달 단계 분포 auto │ 2단 이하 116px │ 묻지 못함 116px
```

**첫 열은 고정, 시각 요소(막대)가 남는 폭**을 가져간다 — 막대가 길수록 분포가 잘 읽힌다.

> **⚠ 실제로 어긴 것 — H3.** 교육생 상세를 `종합 / 세션 / 면담` 탭으로 갈랐다. 셋 다 같은 시간축의 이벤트라 *"7/18 재시험이 7/21 면담보다 먼저"* 라는 순서가 사라졌다. → 타임라인 + 유형 필터.
>
> **⚠ 실제로 어긴 것 — H9.** 로그인을 좌 브랜드·우 폼 50/50으로 두고 **양쪽 내용을 각 절반의 중앙**에 놓았다. 목업(1232px)에서는 몰랐는데 실제 1920에서 **가운데 540px가 통째로 비었다**(1512에서 340px). 화면이 넓어질수록 벌어지는 구조였다. → 양쪽을 이음선에 붙여 **간격을 128px로 고정**(폭과 무관).
>
> **⚠ 실제로 어긴 것 — H8.** 인증 3화면이 서로 달랐다 — 로그인·초대가입은 상한 없는 full-bleed, 비밀번호 재설정만 `max-w-4xl` 카드. 같은 `BrandPanel`·`AuthForm`을 쓰는데 껍데기가 갈렸다. → 셋 다 full-bleed로 통일.

### 폭 2층 — 셸 상한 위에 읽기 measure를 얹는다

**아래 값이 더 좁으면 그것이 이긴다.** 새 화면은 아무것도 안 해도 1280px 안에서 안전하고,
좁혀야 하는 화면만 예외를 선언한다 — 기본이 안전, 예외가 명시.

| 층 | 폭 | Tailwind | 적용 |
|---|---|---|---|
| **1 · 셸 기본** | **1280px** | `mx-auto max-w-7xl` | 표·목록·대시보드 — 전 콘솔 화면 |
| **2 · 읽기·입력** | 620 / 640 / 720 / 820 / 860 | 화면별 | 제출 · 세션 · 히트맵 · 브리프 · 리포트·홈 |

**1280을 고른 근거** — 1512(맥북 14)에서 본문 가용폭이 `1512 − 184(나브) − 64(패딩) = 1264px`다.
즉 **팀이 실제로 쓰는 화면에서는 이 상한에 닿지 않고**, 1920 이상에서만 걸린다. 임의의 숫자가 아니라 그 경계값이다.

**상한은 배경을 채우는 컨테이너가 아니라 그 안쪽에 건다.** 컨테이너를 좁히면 배경이 같이 좁아져
캔버스와 이음선이 생긴다 → `<main class="bg-canvas p-6"><div class="mx-auto max-w-7xl">`.

## H+. 상태 메시지 — 하나의 컴포넌트

**"아이콘 + 제목 + 설명 + 보조 + 액션" 카드는 전부 같은 컴포넌트다.** 흐름 안에 놓이든
배경을 깔고 뜨든 **배치만 다르고 생김새는 같다.** 클래스를 나누면(`.fin` / `.odlg`처럼)
폭·아이콘 크기·여백이 화면마다 어긋난다.

| 값 | |
|---|---|
| **폭** | **460px 고정.** `max-width`로 두면 내용이 짧은 카드가 쪼그라들어 화면마다 크기가 달라진다 |
| 아이콘 | 48px · 라운드 15px · tone별 배경 |
| 구성 | `아이콘 → 제목(fs-lg) → 설명(fs-sm) → 보조(fs-xs) → 액션` |
| tone | 기본 / `ok` / `warn` / `bad` — **아이콘 색만 바뀐다.** 카드 배경은 항상 흰색 |

### 어느 배치를 쓰나 — 사용자가 무엇을 해야 하는가로 정한다

| 배치 | 언제 | 예 |
|---|---|---|
| **흐름 안** | 화면이 그 상태로 **전환**됐다. 다음 행동이 하나뿐 | 문제 종료 · 다음 문제로 · 세션 종료 |
| **오버레이** | 진행이 **막혔다.** 뒤 화면은 그대로 있고 해결되면 돌아간다 | 연결 끊김 |
| **토스트** | 알리되 **막지 않는다.** 액션이 없다 | 창 이탈 복귀 |

**오버레이 뒤에는 실제 화면이 있어야 한다.** 빈 자리표시자를 깔면 "돌아갈 곳이 있다"는
사실이 사라진다 — 연결이 끊겼을 때 학생이 가장 불안해하는 지점이 그것이다.

**액션이 없으면 오버레이를 쓰지 않는다.** 닫을 방법이 없는 오버레이는 갇힌 화면이다.

### I3 — 두 번 어겼다

각주를 `.trwrap` **안**(`.trnote`)이나 표 아래(`.hint3`)에 두면 **화면이 사용자에게
읽어주는 안내문**처럼 보인다. MG-06에서 지적받아 고쳤는데 **OP-02에서 되풀이했다.**
설명은 `.rpage` 안 `.viewport` **뒤**에 `.note2`로 붙인다 — 목업만 보고 만들 수 있어야
한다.

```python
def page(pid, ..., out=''):     # out = 크롬 밖 각주
    return '<div class="rpage">...<div class="viewport">...</div>' \
           + ('<div class="note2">%s</div>' % out if out else '') + '</div>'
```

### I8 — 왜 비율이 아니라 좌표계인가

목업 프레임이 **1232×600(2.05:1)** 이었다. 실제는 1920×1080(1.78:1)이라 세로가 짧고,
무엇보다 **폭이 좁아서 그 안의 384px 폼이 실제보다 1.56배 크게** 보였다. 비율만 맞춰도
절대 크기가 틀리므로, **1920 좌표계로 그린 뒤 축소**해야 목업 안의 모든 px이 실제와 1:1이 된다.

```css
:root{ --screen-w:1920px; --screen-h:1080px; --k:.6625 }  /* --k는 JS가 보이는 폭으로 계산 */
.viewport{ width:var(--screen-w); zoom:var(--k) }          /* 1920으로 그린 뒤 축소 */
.app, .split{ height:var(--screen-h) }                     /* 브라우저 뷰포트 높이 */
```

`--k`를 JS로 계산하는 이유 — 카탈로그 iframe 폭이 화면마다 다르다(1512 화면 → 1232px).
고정값이면 좁은 창에서 넘친다.

> **⚠ 실제로 어긴 것 — I8.** 1232px 목업에서 내린 판단이 실제에서 줄줄이 틀렸다.
> ① 인증 좌우 분할이 벌어짐(H9) ② 브랜드 패널 `space-between`이 1080px에서 극단으로 벌어짐
> ③ 표 컬럼이 늘어짐 ④ 히트맵 빈 상태 박스가 쪼그라듦. **전부 목업에서는 안 보였다.**

## 표 열 폭 표준

**같은 뜻의 열은 어느 표에서나 같은 폭이다.** 표마다 자동 폭에 맡기면 화면을 오갈 때
이름 열이 좌우로 흔들려 시선이 매번 다시 찾는다.

### 전제 두 개 — 이게 없으면 아래 폭은 지켜지지 않는다

| | |
|---|---|
| **`table-layout: fixed`** | 없으면 선언한 폭은 **힌트일 뿐**이다. auto 레이아웃은 남는 폭을 전 컬럼에 비례 분배해서, 폭을 다 적어놔도 화면·상태마다 달라진다 |
| **마지막 열에만 폭을 주지 않는다** | 남는 폭을 흡수하는 유일한 칸. 전부 고정이면 다시 비례 분배되고, **주 식별자가 흡수하게 하면** `8기` 뒤에 470px가 빈다. 마지막 칸이 흡수하면 데이터가 왼쪽에 붙어 스캔되고 액션은 오른쪽 끝에 남는다 |

### 유형별 폭 — 1벌

| 토큰 | 폭 | 쓰는 곳 |
|---|---|---|
| `--col-chk` | **40px** | 체크박스 |
| `--col-num` | **92px** | 숫자 · 개수(`2/3` · 반 · 교육생 · 섹션 · 호출) |
| `--col-money` | **116px** | 금액(`$2,140`) |
| `--col-badge` | **108px** | 상태 배지(예정·종결 / 활성·정지 / 제출·분석) |
| `--col-date` | **124px** | 날짜 · 계정 · 최근 접속 |
| `--col-period` | **168px** | 기간(`2025-08 ~ 2026-02`) |
| `--col-email` | **196px** | 이메일 |
| `--col-person` | **132px** | 담당자 이름 |
| `--col-cls` | **110px** | 반 이름(`A반`) |
| `--col-name` | **200px** | 주 식별자(기관명 · 교안 · 매니저 · 팀) |
| `--col-act` | **96px** | 행 액션 |
| *(마지막 열)* | **미지정** | 남는 폭 흡수 — 서술 열(`마지막 활동` · `우수 누적`)이면 가장 좋다 |

**체크박스가 맨 앞이면 그다음 칸이 주 식별자다.** `교육생`처럼 같은 라벨이 어떤 표에서는
집계 숫자, 어떤 표에서는 이름이라 라벨만 보고 정하면 이름 열이 92px로 눌린다.

### 기존 `.c-*`와의 관계

`.dtbl`을 쓰는 4화면(교육생·면담·프로젝트 목록)은 `.c-*` 클래스를 그대로 두고 값만 토큰을 가리킨다.
`.c-nm 150` · `.c-bg 112` · `.c-lv 124` · `.c-ty 64` · `.c-ac 176` · `.c-pg 132` 등 화면 고유값은 유지.

> **⚠ 실제로 어긴 것.** 같은 `상태` 배지가 `.c-st` **108px**와 `.c-st2` **88px**로 갈려 있었다.
> → `--col-badge` 하나로 통일.
>
> **⚠ 실제로 어긴 것.** 표가 가장 많은 두 화면(`operator/admin` 11개 · `superadmin/console` 10개)에
> **폭 지정이 아예 없었다.** 1232px 목업에서는 그럭저럭 보였고 1920에서 드러났다.

### 미반영 — 코드에 아직 없다

| | 무엇 | 왜 필요한가 |
|---|---|---|
| **표 컬럼 토큰** | `--col-*` 1벌 + `table-layout: fixed` + 마지막 열 미지정 | 목업에만 있다. 실제 콘솔 표는 `기수`·`매니저`·`교육생`이 120px씩 벌어져 있어 목업만큼 촘촘하지 않다 |
| **DESIGN.md 타입 램프** | 배지용 **10px** 단계가 없다(32·26·20·14·13·11) | 목업 `.nav .item .bg`와 코드 `text-[10px]`은 **서로 일치**하는데 DESIGN.md만 비어 있다. 11px로 올릴지, 램프에 마이크로 단계를 추가할지 결정 필요 |

### 목업에서 결정했으나 코드에 해당 화면이 아직 없는 것

라우트가 있는 화면은 `/superadmin/console` · `/manager/curriculum` · `/manager/dashboard` 셋뿐이다.
나머지 화면을 구현할 때 **H8(1280 상한)은 셸이 이미 처리**하므로 화면 쪽에서 다시 걸지 않는다 —
2층(읽기 measure)이 필요한 화면만 더 좁은 값을 선언한다.
