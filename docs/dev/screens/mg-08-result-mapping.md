# MG-08 결과 탭 — 서버 값과 화면 표시의 전체 대응

> 「이 글자가 어느 필드에서 왔나」를 한 장에 모은다. 화면 문구를 고칠 때 **무엇이
> 같이 움직이는지** 보려고 만든다.
>
> 원천 둘 — `GET /projects/{id}/evaluations`(요약·명단) ·
> `GET /projects/{id}/evaluations/{userId}`(개인)
>
> 🔴 예전엔 셋째로 `GET /reports/managed`(공개 상태)가 있었다 — 백엔드가 리포트
> 공개/비공개 개념을 폐지하면서(2026-08-19 배포, PR #287) 이 화면에서 걷어냈다.
> 자세한 경위는 `mg-08-report-release.md`.

## 1. 왼쪽 레일 — 개인 행 · `evaluations.trainees[]`

한 행에 축 하나 — **채점 결과**뿐이다(예전엔 공개 여부가 나란히 있었는데 그 축이
없어졌다).

```
노주안   막힘 1
문유진   응시 완료
백은우   응시 중
```

| `resultStatus` | `stuckConceptCount` | 화면 | 색 |
|---|---|---|---|
| `AVAILABLE` | `> 0` | `막힘 N` | 주황 · 툴팁 「불합격 — 막힌 개념 N개」 |
| `AVAILABLE` | `0` | `응시 완료` | 회색 |
| `IN_PROGRESS` | — | `응시 중` | 회색 |
| `INCOMPLETE` | — | `중단` | 회색 |
| `NOT_ATTENDED` | — | `미응시` | 회색 |
| `INVALID` | — | `무효` | 회색 |

**축이 셋인데 한 칸에 들어간다.**

```
판정 축   합격 · 불합격    응시를 마친 사람에게만 붙는다(스펙 🔴)
근거 축   막힌 개념 N개    개념별 표가 「막힌 사람」이라 부르는 그 값
상태 축   응시 중 · 중단 · 미응시 · 무효
```

실측으로 `summary.failedCount`(4명)와 `stuckConceptCount > 0`인 사람이 같다 —
**막힘 N이 불합격의 근거**다. 그래서 불합격인 사람에게는 판정 대신 근거를 보여주고
(다음에 할 일이 거기서 나온다) 판정 이름은 툴팁에 남긴다.

🔴 한때 막힘 0을 `—`로 그렸다. 표에서 대시는 「값 없음」이라 **가장 좋은 결과가
아직 안 한 상태로** 읽혔다(같은 칸에 「응시 중」이 섞여 있어 더 그랬다).

⚠ **응시를 마친 사람만 「막힘 N」을 말한다.** 응시 중인 사람이 「막힘 0」으로 보이면
통과한 것처럼 읽힌다 — 그 밖에는 왜 결과가 없는지를 대신 적는다.

## 2. 요약 화면 — `프로젝트 종합`

### 2-1. 머리 줄

| 서버 값 | 화면 |
|---|---|
| `reportPublished: true` | `발행 완료` 배지(초록) |
| `reportPublished: false` | `발행 전` 배지(회색) |

🔴 예전엔 이 옆에 매니저가 누르는 「리포트 공개」 버튼이 있었다 — 폐지됨. 지금은
배지 하나뿐이고 매니저가 하는 액션이 없다(발행도 서버가 회차 마감 후 한꺼번에 한다).

### 2-2. 진행 막대 — `trainees[].resultStatus` 집계

명단 전원을 진행 상태별로 묶어 **끝난 만큼만 채워지는** 막대로 보여준다. 판정을
다시 하는 게 아니라 서버가 준 `resultStatus`를 그대로 묶는다.

| `resultStatus` | 막대 구간 | 색 |
|---|---|---|
| `AVAILABLE` | 응시 완료 | `bg-primary` |
| `IN_PROGRESS` | 응시 중 | `bg-border-strong`(중립 — 문제 상태 아님) |
| `INCOMPLETE` | 중단 | `bg-warning` |
| `NOT_ATTENDED` | 미응시 | `bg-danger` |
| `INVALID` | 무효 | `bg-fg-subtle` |

값이 0인 구간은 막대·이름표 둘 다 안 그린다. 전원이 응시를 마쳤으면 이름표 대신
"모두 응시를 마쳤어요" 한 줄만 남는다(`funnelCaption`).

### 2-3. 카드 둘

| 카드 | 서버 값 | 캡션 |
|---|---|---|
| 응시 완료 | `attendedCount / totalCount` | `funnelCaption` — 응시 중·중단·미응시·무효 중 0이 아닌 것만 나열 |
| 다시 보기 대상 | `retryTargetCount(s)` = `failedCount + notAttendedCount`(**화면이 더한다**) | `retryCaption` — 막힘 N·미응시 M 중 0이 아닌 것만 나열 |

🔴 **예전엔 카드가 셋이었다**(응시·불합격·리포트 공개). 「불합격」과 「다시 보기
대상」이 항상 같은 값이라 사용자가 지적했고(미응시가 늘 0이라 `failedCount`와
`retryTargetCount`가 같았다), 세 번째 「리포트 공개」 카드는 그 개념 자체가
없어졌다 — 그래서 둘로 줄이고 이름을 판정어(불합격)가 아니라 매니저가 할 일(다시
보기 대상)로 바꿨다.

### 2-4. 집단 미달 — `classWarnings[]`

```
{concept} — 반 절반 이상이 여기서 막혔어요 ({stuckCount}/{assessedCount})
```

유효 응시자의 **절반을 넘는** 인원이 막힌 개념일 때만 서버가 준다(경고 톤).

### 2-5. 개념별 표 — `conceptAggregates[]`

| 열 | 서버 값 | 0일 때 |
|---|---|---|
| 개념 | `concept` | — |
| 막힌 사람 | `stuckCount`명 · `stuck[].name` | `—`(회색) |
| 코드에 없던 사람 | `notInCodeCount`명 · `notInCode[].name` | `—`(회색) |

⚠ **「코드에 없던 사람」은 못한 것이 아니다**(스펙 명시). 막힌 사람과 한 칸에 넣으면
매니저가 둘을 구분하지 못한다 — 그래서 열을 가르고 색도 다르다(막힘은 주황, 없던
사람은 회색).

여기서는 `—`를 그대로 쓴다. **이 칸은 인원 수라 0이 「없음」이 맞다** — 1의 `—`가
문제였던 것은 그 자리가 「상태」였기 때문이다.

## 3. 개인 결과 패널 — `evaluations/{userId}`

### 3-1. 결과가 없을 때

| `resultStatus` | 문구 |
|---|---|
| `IN_PROGRESS` | 아직 응시 중이라 결과가 없습니다. |
| `INCOMPLETE` | 끝내지 못한 채 응시 창이 닫혔습니다. |
| `NOT_ATTENDED` | 응시 창이 닫히도록 응시하지 않았습니다. |
| `INVALID` | 무효 확정된 수행이라 결과를 세지 않습니다. |

### 3-2. 개념 카드 — 도달 단계

`concept.reachLevel`(0~4)을 `N단`으로 쓰고 `REACH_STYLE`로 색을 준다.
**도달 단계가 주 판정값이고 축별 점수는 내부 값이다**(화면에 그렇게 적어 둔다).

### 3-3. 축 사다리 — `steps[]`

| `stepNo` | 이름 |
|---|---|
| 1 | 코드이해 |
| 2 | 설계논리 |
| 3 | 대안비교 |
| 4 | 반례대응 |

| 서버 값 | 화면 | 톤 |
|---|---|---|
| `passed: false` | `불합격` | danger |
| `passed: true` · `helpCount: 0` | `합격` | success |
| `passed: true` · `helpCount: 1` | `합격(도움 1회)` | info |
| `passed: true` · `helpCount: ≥2` | `합격(도움 N회)` | warning |

⚠ **없는 축은 「미도달」 빈 칸으로 그린다** — 0점·불합격과 다르다.
