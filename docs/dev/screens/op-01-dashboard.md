## 2. 목업을 그대로 옮기지 않았다 — 먼저 대조했다

이 화면은 **"효과적으로 보여서 전달하려는 바가 한눈에 들어오는 것"** 이 목적 자체라,
목업을 옮기기 전에 **두 장을 기계로 대조**하고 UI/UX 관점에서 전수 검토했다.
목업이 계약인 것은 **케이스·문구**이고 값과 배치는 검증 대상이라는
[D22](../decision-log.md)의 경계를 그대로 적용한 것이다.

| 무엇 | 어떻게 |
|---|---|
| 값 정합성 | 목업 두 장의 표·막대를 파싱해 **교차 대조** |
| 색 | OKLab ΔE · 색각 이상 분리 · 대비 검증기 |
| 슬롭·타입 램프 | 결정적 스캐너 |
| 레이아웃·상태 | **케이스 6종을 실제로 렌더**해 실측 |

**눈으로 봤으면 하나도 못 잡았다.** 아래는 전부 도구가 먼저 말한 것이다.

## 3. 기획 결함 3건 — 화면을 그리기 전에 확정했다

목업이 손으로 채운 값이라 **화면이 존재할 수 없는 상태**를 그리고 있었다.

### ① 반 비교 값이 존재할 수 없는 값이었다

```
목업 라벨 : "미프 2차 기준 — 미프 3차는 미발행"
목업 값   : A24 B20 C32 D28 E16 F24 G12 H20 I28 J16
분석 2차  : A20 B16 C24 D20 E12 F20 G12 H16 I20 J12   ← 안 맞음
분석 3차  : A25 B20 C32 D28 E16 F24 G12 H20 I28 J16   ← 일치
```

라벨은 2차인데 값은 3차다. 그런데 같은 화면이 `3차 리포트 미발행`이라 말한다 —
**위험 판정은 발행 시점에 켜지므로**(9-2 · 10-2) 그 값은 아직 존재할 수 없다.

**→ 분석 격자에 맞춘다.** 1~3차 발행 / 4차 진행 중 / 5차 시작 전.
대시보드 기본 화면이 `4차 진행 중 · 3차 기준`이 된다.

### ② 기수 전체 행이 반의 합과 달랐다

| | 3차 위험자 | 3차 채점 |
|---|---|---|
| 목업 기수 행 | 44 | 234 |
| 반 10개 합 | **55** | **250** |

같은 모집단인데 25% 차이다.

**→ 반의 합으로 계산한다**(`cohortRounds.ts`의 `sumCells`). 사용자가 더해보면 바로
드러나는 종류의 불일치이고, **이 값이 반 비교의 기준선**이라 어느 쪽을 쓰느냐로 반의
색이 뒤집힌다. 반의 합(22%)을 쓰자 5개 반이 위·5개가 아래로 갈려 **기준선이 실제로
작동**하게 됐다.

### ③ 응시 분모가 산술적으로 틀렸다

`분석 실패 2팀`인데 응시 분모가 **제출 전량(231)** 이었다. 실패한 팀은 응시 창이 안
열린다 — 기산점이 코드 분석 완료다(B4).

**→ 응시 분모 = 분석 완료 수.** 파이프라인에 `분석` 단계를 실제로 넣었다.

## 4. 반 비교에 기수 기준선을 넣었다 — 이 화면 최대 개선

**막대만 두면 `32%`가 나쁜 값인지 이 회차가 원래 그런지 화면에서 알 수 없다.**
목업은 상위 몇 개를 경고색으로 칠했는데 **그 경계에 근거가 없었다** — 화면이 기준을
정하는 것이라 E8이 금지한 것이다.

**OP-02는 같은 문제를 만나 색을 네 번 바꾼 끝에 *"값에 칠하지 않고 기수 대비 부호만
쓴다"* 로 결론냈는데, OP-01에는 그 결론이 반영되지 않았다.** 그것을 옮겼다.

```
C반  ███████████████│░░░░░        32% · 8/25명   ← 기준선 넘음
G반  ██████│░░░░░░░░░░░░░░        12% · 3/25명
              ↑ 기수 전체 22%
```

| | |
|---|---|
| **E8에 안 걸리는 이유** | 기수 평균은 **관측값**이지 우리가 정한 임계값이 아니다. `N% 이상 위험`과 근본이 다르다 |
| **A6에 안 걸리는 이유** | 기준선이지 등수가 아니다. 나쁜 순으로 정렬하되 **순위 숫자는 없다** — 금지된 것은 순위 표기이지 정렬이 아니고, 이 블록의 질문이 *"어느 반이 처지나"* 다 |
| **부수 효과** | OP-02 기본 정렬(`최근 회차 나쁜 순`)의 근거가 *"OP-01에서 본 순서와 같아야 한다"* 인데 목업은 여기가 이름순이라 **넘어가면 순서가 뒤집혔다.** 같이 해결됐다 |

**눈금은 0~100%가 아니라 데이터 범위(최대 × 1.15)에 맞춘다.** 값이 12~32%인데 100%
트랙이면 막대가 전부 왼쪽 1/3에 몰려 차이가 안 보인다.

> ⚠ **회차가 바뀌면 눈금 상한도 바뀐다** — 막대 길이를 회차끼리 비교하면 안 된다.
> 그 비교는 OP-02 격자의 일이고, 여기는 같은 회차 안에서 반끼리만 견준다.

## 5. 파이프라인 — 단위가 다른 값을 화살표로 잇고 있었다

```
목업   제출 231/250  →  분석 실패 2팀  →  응시 198/231          명 → 팀 → 명
지금   제출 231/250  →  분석 223/231   →  응시 198/223  →  리포트 미발행
                        ⚠ 2팀 실패 ↗
```

문제가 셋 겹쳐 있었다.

1. **실패는 단계가 아니라 예외**인데 `분석` 자리를 차지했다
2. 단위가 명↔팀으로 튀어 *"231명 중 2팀이 실패"* 로 읽힌다
3. 위 §3-③의 산술 모순

**단계를 정직하게 넷으로 두고 실패를 그 단계의 보조로 내리면 셋이 같이 풀린다.**

## 6. 블록 순서를 바꿨다 — 정의서 §3과 달라진다

정의서가 *"`조치 필요` 네 줄이 이 화면의 존재 이유고 나머지는 배경"* 이라 해놓고,
목업은 **조치 필요를 세 번째**에 두고 **네 블록의 시각 무게를 완전히 같게** 뒀다.
주인공이 배경보다 아래에 있고 면적도 작으면 위계가 내용과 반대가 된다.

**이번 회차(1줄 컨텍스트) → 조치 필요(주인공) → 반 비교(근거) → 비용.**
읽는 순서가 *"지금 어느 회차인가 → 무엇을 해야 하나 → 왜"* 가 된다.

> **정의서 §3 스케치도 같이 고쳐야 한다.** 아직 안 고쳤다.

## 8-1. 지표판인데 판별선이 없었다 — 두 번째 패스

블록 배치를 고치고 나서도 *"기획적으로 빈틈이 많다"* 는 지적을 받았다. 다시 재보니
**숫자만 있고 판단이 없었다.**

| 블록 | 판별선 | |
|---|---|---|
| 반 비교 | ⭕ 기수 기준선 | §4에서 넣음 |
| **파이프라인** | ❌ **없음** | 분수만 있고 *"몇 명이 빠졌나"* 를 사용자가 뺐다 |
| 조치 필요 | ⭕ 그 자체가 판별 | |

### 마감이 판별선이다

```
제출 231/250      분석 223/231     응시 198/223     리포트 미발행
19명 미제출       ⚠ 2팀 실패 ↗    25명 미응시      마감 후 일괄 발행
```

**같은 `19명 미제출`이라도 마감 전이면 진행 중이고 마감 후면 사고다.** 전에는 마감
시각을 오른쪽 구석에 회색으로만 써서 사용자가 오늘 날짜와 비교해 판단해야 했다 —
지금은 마감이 지나면 그 수가 붉어지고 마감 시각에 `지남`이 붙는다.

### 시점이 섞이는 것은 구조다 — 없앨 수 없다

리포트가 **일괄 발행**되므로(10-1) 진행 중 회차에는 판정값이 아예 없다. 그래서 *"지금"*
과 *"판정된 것"* 은 **항상 다른 회차**다.

**MG-01이 같은 문제를 먼저 풀었다** — *"행마다 회차를 적는다. 회차 표기가 없으면
**전부 이번 회차 것으로 읽힌다**"*. OP-01 정의서에는 그 규칙이 없어서 시점이 본문에
묻혀 있었다. 조치 행마다 시점 열을 뒀다.

```
미배정      상시
개념 공백   미프 3차     ← 코드 매칭은 분석 완료 시점에 나온다
집단 미달   미프 2차     ← 9-6 판정은 리포트 발행 시점
면담 적체   미프 2차     ← 면담은 리포트와 함께 등재(10-2)
```

**본문에 있던 회차는 뺐다**(중복). 한 열이 시점 축이라 세로로 훑으면 지금 것과 지난
것이 갈린다.

### 비용 블록을 뺐다

나머지가 전부 **회차 단위**인데 비용만 **월 단위**였다 — E6이 *"이 제품의 시간 단위는
프로젝트 회차"* 라 했는데 예외 근거가 없었다. 그리고 지표판이 조치할 수 없는 것을
올리면 *"요약과 링크만"* 이라는 §5 원칙과도 어긋난다. **OP-06 비용 탭에 이미 있다.**

### 프로젝트별 대시보드를 만들지 않는다

*"차라리 프로젝트별로 대시보드를 보게 하는 게 낫나"* 라는 검토가 있었고 **기각했다.**

| 왜 | |
|---|---|
| **조치 4종 중 3종이 프로젝트에 안 붙는다** | 미배정=조직 구조 · 면담 적체=반 운영 · 비용=기관 월 단위. 프로젝트 하위로 내리면 **갈 곳이 없어진다** |
| **OP-04 현황 탭이 이미 그것이다** | 반별 제출·응시율 + 개념별 코드 매칭. 또 만들면 D1 위반 |
| **IA가 깨진다** | 대시보드가 프로젝트 하위가 되면 nav에서 사라진다(17번) |

**진행 중 회차가 하나뿐인 것은 기획 의도다** — 회차는 순차로 돌아서 **일정 충돌이
없다**(14번 841줄).

## 10. 구조에서 정한 것

### 블록마다 실패가 갈린다

```ts
type Block<T> = { ok: true; value: T } | { ok: false }
```

**부분 실패는 그 줄만 실패로 그린다**(F2). 응답 전체를 한 덩어리로 두면 반 비교 하나가
실패했을 때 화면을 통째로 비우게 된다. `BlockBody`가 그 분기를 한 번만 조립한다.

### 조치 필요는 문장을 서버에서 받지 않는다

종류별 판별 유니온으로 **사실만** 받고 문구는 화면이 만든다. 판정을 문장으로 내려주면
규칙이 바뀔 때마다 문구·테스트가 따라오고, 데이터가 다르면 그 문장이 거짓말을 한다(A7).

### 빈 상태에 `Empty`를 쓰지 않은 자리

블록 머리줄이 **카드 밖**이라 실패·0건일 때 **카드가 그 자리를 그대로 차지한다.**
빈 상태를 카드 *안에* 또 넣으면 중첩이다(H7 · 02-layout §4-1).

### 목 케이스 스위치

`?case=ok|pre|multi|assign|partial` — 케이스 6종을 실제로 렌더해 봐야 완료 판정이
된다. `mockDb`와 함께 사라진다.

### 링크가 빈 화면으로 가던 것

`/operator/admin/managers`가 **아무 라우트에도 안 걸려 빈 화면**이었다(조치 4줄 중 3줄).

## 12. 남은 것

### 백엔드에 물을 것

1. **팀 인원** — `분석 223`은 실패 2팀 × 4명으로 뺀 값인데, 목업 `8팀 중 6팀`이 기수
   전체인지 한 반인지 안 갈린다(전체면 팀당 29명이 된다)
2. **미집계와 채점 분모** — 호버가 `4명 / 채점 25명`인데 그 반 미집계가 4명이면 채점은
   21명이어야 한다. 목업 구조를 유지했고, 고치면 반 비율이 전부 달라져 대조가 불가능해진다
3. **계획 회차 수** — OP-01 정의서는 `3차 / 8회`인데 OP-02는 *"8은 상한이지 상수가
   아니다"* 라고 못 박았다. **등록된 프로젝트 수**로 갔다

### 코드에 남은 것

- 이슈 번호 연결(`git config branch.feature/op-01-dashboard.issue N`)
- **정의서 §3 스케치** — 블록 순서(§6)와 비용 블록 제거(§8-1)를 반영해야 한다
- 막대에 `role="img"` + 값 텍스트 — 스크린리더에서 막대가 장식으로만 읽힌다

### 데이터 원천이 계약에 없는 것 2건 ⚠

조치 4종 중 **둘은 어느 화면 계약에도 원천이 없다.** 지금은 목으로 그리고 있어 화면은
되지만, 연동 시 그 두 줄이 데이터를 못 받는다.

| 종류 | 필요한 것 | 상태 |
|---|---|---|
| 미배정 | 반별 담당 매니저 | ⭕ `ClassProgress.manager`(OP-03 계약) |
| 개념 공백 | 개념별 코드 매칭·미매칭 팀 수 | ⭕ `ConceptMatch`(OP-04 계약) |
| **집단 미달** | `(반 × 개념 × 2단 이하 인원)` 집계 | 🔺 **없다.** OP-04는 코드 매칭만 갖는다 |
| **면담 적체** | 반별 면담 미종결 일수 | 🔺 **없다.** MG-03이 화면에 쓰고 있으니 서버엔 있을 것 |

**집단 미달이 특히 문제다.** OP-04 정의서가 *"시스템은 표시까지만 한다"*(9-6)고 했는데
**그 "표시"의 원천이 정의된 적이 없다.**
