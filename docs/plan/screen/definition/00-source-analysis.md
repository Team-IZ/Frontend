## 2. 영역별 분석 (12 도메인)

각 영역: **화면 / 핵심 처리 / 주요 데이터·엔티티(ERD 힌트) / 핵심 규범 / 예외 case 특이점**.

### 1) 시스템 기반 [SYS] — SC-S01, 전역
- **화면**: SC-S01(슈퍼어드민 전용).
- **처리**: 기관 생성 → org_id 발급 → 최초 매니저 초대 토큰·메일 → 교육생수·세션수·저장량 + **AI 비용(토큰·모델단가)** 집계 대시보드.
- **데이터**: `Organization`(org_id, status=ACTIVE, soft-delete·보존기간), `사용량 집계`(교육생/세션/저장량/AI비용). SYS-02는 엔티티가 아니라 **모든 쿼리에 강제되는 org_id 필터 규칙**.
- **규범**: org별 데이터는 org_id 격리(A-격리). 삭제는 soft-delete 후 보존기간 경과 시 파기. 타 기관 접근 403.
- **예외**: SYS-01 8건(중복명·이메일형식·롤백·메일재시도·토큰보류·집계실패·물리삭제금지·보존기간). SYS-02 8건(전부 격리 위반 차단).

### 2) 인증·권한·공통 [AUTH] — SC-A01/A02/A03, 공통헤더, 전역
- **화면**: A01(로그인), A02(가입·활성화), A03(비번재설정), 공통 헤더(AUTH-08 프로필).
- **처리**: 매니저는 초대토큰→가입(AUTH-01)→이메일인증(AUTH-02); 교육생은 명단등록→초대메일→활성화(AUTH-06). 로그인(AUTH-03)은 JWT Access(30분)+Refresh(7일 DB·HttpOnly). **v8: 로그인 실패 시 로그인 화면 유지**(비번재설정 자동이동 없음). AUTH-07은 교육생 GitHub 커밋 이메일 등록·검증(SC-T02, 로그인 인증과 분리).
- **데이터**: `User`(role=SUPER_ADMIN/MANAGER/TRAINEE, org_id, is_email_verified, status), `InviteToken`, `RefreshToken`, `커밋이메일`(verified 플래그), `AuditLog`, `Permission Matrix`, `can_view_all_manager_history` 플래그.
- **규범**: 명단 외 이메일 활성화 불가(AUTH-06). RBAC default deny·최소권한(AUTH-09). 미검증 커밋이메일은 귀속 분석서 **경고 표기**(AUTH-07). 관리이력 전체열람은 기본 false(AUTH-11). GOV-02 자동확정은 RBAC에서도 차단.
- **예외**: AUTH-01 8, 02 8, 03(로그인) 9, 04 8, 05 9, 06 8, 07 8, 08 8, 09(RBAC) 9, 10 8, 11 7. 토큰 만료·재사용·위변조 계열이 반복.

### 3) 조직·프로젝트 [ORG] — SC-M02
- **화면**: SC-M02(기수·팀·프로젝트 = 한 화면 3영역/탭 후보).
- **처리**: 기수 생성+명단(ORG-01, 신규 교육생 AUTH-06 트리거) / 팀 구성·재배정(ORG-02, **이력 보존** to_at/from_at) / 프로젝트 생성·매핑(ORG-03, 유형·레포URL·커밋이메일·extract_scope 기본값).
- **데이터**: `Cohort`(기수·기간·단계), `TeamMembership`(from_at/to_at 이력형), `Project`(유형 개인/팀, repo_url, requirements, extract_scope), `커밋이메일 매핑`.
- **규범**: 명단 이메일 검증·중복제거. **동일 시점 중복 팀 소속 금지**. 레포 URL 유효성·접근권한. 미검증 커밋이메일 매핑은 유지하되 귀속 경고.
- **예외**: 각 8건. 재배정 이력 무결성(to_at>from_at 역전 차단)이 핵심.

### 4) 측정 계획 [PLAN] — SC-M03
- **화면**: SC-M03(체크포인트·추출범위·포커스·응시현황 = 한 화면 다영역).
- **처리**: 체크포인트 일정(PLAN-01, **is_final 단 1건**) / 추출범위(PLAN-02, 전체코드 vs 본인커밋기여분 → MEAS-02 라우팅) / 검증 포커스(PLAN-03, **교육생 비노출**) / 응시현황·독촉(PLAN-04, AUTH-10 연계).
- **데이터**: `Checkpoint`(회차, due_at, is_final), `extract_scope`(설정 버전·변경자), `focus_area`(비노출·버전), `응시상태`.
- **규범(의미)**: 기한 역순·중복 방지. 개인 프로젝트는 **전체코드 권장 기본**. **focus_area는 교육생 화면·API 응답에서 제외**(게이밍 방지). 최종 회차 단 1건.
- **예외**: PLAN-01 8, PLAN-02 7, PLAN-03 7, PLAN-04 8.

### 5) 교안 관리 [CUR] — SC-M12

## 3. 교차 화면 계약 (서비스플로우 v3 — FR 행에 없는 관계)

FR 단위 역추출로는 **구조적으로 못 보는** 화면 사이 계약. 정의서의 "인터랙션·화면 전이" 섹션 소스.

1. **재개입 페루프**: SC-M07 재측정 회복 판정 → 회복 안됨(NOT_RECOVERED/DETERIORATED) → 개입 재실행 루프.
2. **회차 반복 독립성**: T05 결과 → 다음 회차 도래 → **신규 커밋 스냅샷**으로 T02(MEAS-01)부터 새로 시작. **기존 컨텍스트 미사용**.
3. **선행조건**: 교안 등록·매핑 승인(SC-M12·CUR)은 **회차 시작 전 완료**. 미승인 시 T05 교안 위치 안내 생략.
4. **환류(feedback)**: (a) 추천 기각 사유(INTV-03) → 추천 규칙 개선 신호. (b) 채점·회차 결과(ENG-01/02) → 시그널 산출(ENG-04) 재입력.
5. **권한 분리선**: 매니저 라인(위)/교육생 라인(아래). 채점 근거·루브릭은 **매니저 전용**. 교육생은 결과 리포트 **위치 안내까지만**.
6. **등급 부여 시점**: **최종 회차만**. 중간 회차는 추이·시그널.
7. **자동확정 금지(GOV-02)**: 확정 판단은 **전부 매니저 승인**. 전 구간.
8. **테넌트 격리(SYS-02)**: 전 구간 org_id 격리.
9. **열람 범위 통제(GOV-03)**: 전체/요약/비공개 → T05 노출 필터.
10. **취약점 → 교안 위치 안내(처방 금지)**: CUR-02 승인 시에만.
11. **리포트 트리거 분리**: RPT-04(체크포인트 종료마다)·RPT-01(누적, 동일 집계)·RPT-02(최종 회차만, 등급 부여).
12. **제외 선언(범례)**: MEAS-04/05 미수용, MEAS-03(귀속확인·오귀속제외·SC-T03) 고도화 보류, **재응시 기능 없음**.
