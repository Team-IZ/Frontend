# MG-09 · 교안 (매니저)

## 1. 한 줄

**이 기수가 무엇을 가르쳤나.** 오퍼레이터 화면(OP-06 › 교안)에서 **생성·편집만 뺀** 것이다.

> **목적은 어휘와 맥락**이다. 히트맵·대시보드·브리프가 `HITL Trigger` `Graph 구성` 같은
> 이름을 쓰는데, **8회차 × 3개 = 24개 낯선 용어**가 지나가도 그것이 커리큘럼 어디쯤인지
> 알려주는 화면이 없었다 — **새로 배정된 매니저에게는 자기 화면이 외국어다.**

## 2. 목적을 두 번 잘못 잡았다 — 기록

| 내가 든 근거 | 왜 틀렸나 |
|---|---|
| **위치 검증** — 브리프가 찝은 `3장 36–46쪽`이 맞는지 확인 | 목차에 `3장 HITL`이라 쓰여 있어도 **그게 맞는 위치인지 판단하려면 HITL이 뭔지 알아야** 한다. 매니저는 전공자가 아닐 수 있다 — **볼 수는 있고 판단은 못 하는 화면**이 된다 |
| **낭독 보조** — 정의문을 학생에게 읽어준다 | 16번이 *"개념 이름만 읽어주세요. **설명은 하지 않아도 됩니다**"* 로 **면제했다.** 학생이 되물으면 **"그건 강사님께"** 가 정답이다 |

**맞는 근거는 세 번째였다** — 매니저가 **자기 화면을 읽기 위해** 어휘를 갖는 것. 16번의
면제는 **학생에게** 설명하지 말라는 것이고, 매니저가 스스로 맥락을 아는 것은 다른 문제다.

## 3. 진입 · 이탈

| | |
|---|---|
| 진입 | **좌측 네비 `교안`** · 브리프 ④칸·히트맵·MG-08 결과의 교안 위치 `↗` **새 탭** |
| 이탈 | 뒤로 · `← 교안 목록` |

**메뉴에 자리를 준다.** 17번 4-2는 *"링크로만 가면 되는 화면은 메뉴 자리를 안 준다"* 고
했지만 **그 전제가 깨졌다** — 어휘 습득이 목적이면 **스스로 열어야** 하고, 링크로만이면
**면담 대상이 있을 때만** 볼 수 있다.

**매니저 nav 5개 → 6개**(대시보드 · 히트맵 · 면담 · 교육생 · 프로젝트 · **교안**).

**모달·오버레이를 만들지 않는다.** 브리프가 모드라 나가면 낭독문을 잃지만 **새 탭이면
그대로 남는다** — `↗`가 이미 그 뜻이다.

### OP-06에서 빼는 것 — 권한과 범위뿐

| | |
|---|---|
| **빼는 것** | `+ 교안 등록` · `↻ 다시 분석` · `새 버전 올리기` · 정제 결과 편집 · 검색 |
| **좁히는 것** | 기관 전체 → **이 기수 회차에 연결된 교안** |
| **그대로** | 목록 · 섹션 탭(좌 섹션 → 우 가르친 항목) · **`연결된 프로젝트` → `쓰인 회차`** |

**검색을 뺀 이유:** 기수당 교안이 3~5개라 목록으로 충분하다.

**`연결된 프로젝트`를 남긴 이유:** 한때 *"자산 관점이라 오퍼레이터 것"* 이라며 뺐다가
되돌렸다 — **매니저에게 오히려 가장 쓸모 있다.** 히트맵에서 본 이름이 **어느 회차 것인지**
여기서 연결된다. 같은 데이터가 양쪽에 유효한데 없는 경계를 그었던 것이다.

### ★가 검증 개념으로 쓰인 항목

**한 섹션이 가르친 것이 9개인데 그중 하나만 문항이 됐다.** 이 사실이 매니저의 화면을
읽는 열쇠다 — `Graph 구성 미달 12명`이 뜰 때 *"교안에는 더 있지만 이것만 물었다"* 가
읽힌다.

## 7. 상태 — 왜 그렇게 정했나

> **케이스 표는 목업에 있다** — [`manager/curriculum.html#cases`](../wireframe/manager/curriculum.html#cases).

### 추출이 덜 된 것과 원래 없는 것을 구분한다

정의문이 안 나온 항목을 **빈칸으로 두면 교안에 원래 없는 줄 알게 된다** → `정의문이 추출되지 않았습니다`라고 쓴다.

분석이 통째로 실패한 교안도 **목록에서 지우지 않는다** — `분석 실패` 배지를 달고 섹션·항목 수를 `―`로 둔다. 회차에는 연결돼 있으므로 **없는 것처럼 보이면 안 된다.**

### 열 수는 있게 둔다

분석 실패한 교안도 상세로 들어갈 수 있다. 다만 **섹션이 없다.** 재분석은 **오퍼레이터 소관**(OP-06)이라 여기서는 상태만 보여준다.

### 빈 상태에 등록 유도를 넣지 않는다

교안 등록은 오퍼레이터가 한다. 매니저에게 권하면 **할 수 없는 일을 권하는 것**이다(F6).
## 8. 안 하는 것

| | 어디에 |
|---|---|
| 등록 · 재분석 · 새 버전 · 연결 변경 | **OP-06 › 교안** |
| 검증 개념 확정 | **OP-04** |
| 원문 PDF | **없다** — 7-2가 뽑는 것은 개념명·페이지·식별자뿐이고 *"암호가 걸려 있어 파싱이 막힐 수 있다"*(4-3). 교안 PDF는 학생과 매니저가 이미 가지고 있다 |
| 코드 식별자 | **없다** — 코드 매칭용 내부 값이다. 정의문 안에 들어간 것은 **교안이 쓴 문장**이라 다르다 |
| 검색 | **없다**(교안 3~5개) |
| 학생용 뷰어 | **만들지 않는다** — TR-04는 텍스트 안내로 충분하다 |
