# 데이터 계약 — 무엇이 값을 만들고, 화면은 무엇을 받는가

**이 문서가 정의서·와이어프레임보다 먼저다.** 화면의 형식은 취향이 아니라 **생산자가 정한다**. 같은 "위험 근거 한 줄"이라도 백엔드 템플릿이 만든 것과 LLM이 만든 것은 뷰 계약이 다르다 — 전자는 슬롯을 강조하고 재현 가능하며 감사에 걸 수 있고, 후자는 "AI 생성" 라벨·근거 인용·편집 경로가 **의무**다.

명세는 12곳에서 LLM을 언급하고 8곳에서 출력 형태(칩/배지/문구/줄/초안)를 못박았다. 그러나 **명세가 말하지 않은 곳이 훨씬 많고, 거기가 결정해야 할 곳이다.** 이 문서는 받아쓰기가 아니라 판정이다.

---

## 1. 진짜 축은 "LLM이냐 백엔드냐"가 아니다

그 질문은 절반만 묻는다. 실제로 아키텍처를 가르는 축은 두 개다.

|  | **구조화 산출**<br>(정수·enum·span·스키마) | **자유 텍스트 산출**<br>(문장·문단) |
|---|---|---|
| **쓰기 시점**<br>(1회·비동기·굳는다) | **Q1 — 이 제품의 기본형**<br>ENG-01 축별 점수+근거span, MEAS-02B DP 세트, MEAS-06 답변등급 | **Q2 — 문서형만**<br>RPT-01 자연어 요약, MEAS-07 교육생 리포트 (생성 후 스냅샷) |
| **조회 시점**<br>(매 렌더·매번 과금) | **Q3 — 결정론이면 정상**<br>DASH-03 Priority, DASH-07 회복률 (SQL·수식) | **Q4 — 금지**<br>대시보드 문구를 LLM이 매번 짓는 것 |

**Q1이 이 제품의 심장이다.** LLM을 쓰기 시점에 한 번 돌려서 **구조화된 값으로 굳히고**, 화면은 굳은 값을 읽는다. 그러면 조회는 전부 SQL이 되고, 통계·집계·정렬·비교가 공짜로 따라온다.

**Q4는 절대 금지 구역이다.** 그리고 이건 명세가 금지해서가 아니라, 이 제품이 감당할 수 없어서다:

- **재현성** — 사람을 판정하는 도구다. GOV-01 이의제기가 들어오면 *"그때 매니저 화면에 뭐라고 떠 있었는가"* 를 재현해야 한다. 매 렌더마다 문장이 새로 생성되면 재현이 불가능하고, 감사 로그는 거짓말이 된다.
- **비용** — SYS-01이 기관별 AI 호출 수·토큰·추정 비용을 집계하고 예산 상한 경고까지 건다. **AI 호출은 과금 단위다.** 매니저는 대시보드를 하루에 수십 번 스캔한다(design-standards §0). 조회 시점 LLM은 스캔 횟수에 정비례해 과금된다.
- **지연** — 대시보드의 일은 스캔이다. LLM 지연이 끼면 스캔이 죽는다.
- **일관성** — RPT-04 규칙: *"동일 지표가 RPT-01과 다른 값으로 보이면 안 됨(집계 로직 통합 필수)"*. 조회 시점 생성은 이걸 구조적으로 보장할 방법이 없다.

> **철칙 D1. LLM은 쓰기 시점에 한 번 돌고, 구조화된 값으로 굳는다. 화면은 굳은 값을 읽는다.**
> 예외는 SC-T04 세션 대화 하나뿐 — 그건 실시간 대화이지 데이터 표시가 아니다.

## 2. AI를 쓸 것인가 — 판정 3문

명세에 안 쓰여 있어도 이 세 질문으로 판정한다. 순서대로 묻는다.

**Q1. 정답이 열려 있는가?**
닫혀 있으면(수식·임계값·조건 교차로 답이 정해지면) **LLM 금지**. 비싸고 흔들리고 감사가 안 된다.
열려 있으면(코드에서 좋은 질문 뽑기, 답변이 얼마나 이해했는지 판정) → 다음 질문.

**Q2. 틀렸을 때 누가 잡는가?**
- 사람이 반드시 통과한다(승인·편집) → 허용. CUR-02 매핑 승인, INTV-02 초안 편집.
- 다른 신호와 교차 검증된다 → 허용. CUR-02 llm_rank는 keyword_overlap·embedding_similarity·upstream_quality와 **병행 표시**된다.
- **아무도 안 잡는데 사람 판정에 직결된다 → 금지.**

**Q3. 결정론으로 같은 품질이 나오는가?**
나오면 결정론. LLM은 마지막 수단이다.

### 이 판정이 뒤집는 것 — 문구는 LLM의 자리가 아니다

가장 유혹적인 오답이 여기다. "위험 근거 한 줄"과 "개입 타이밍 문구"를 LLM한테 시키면 자연스러워 보인다. **하지만 이 문장들의 변수는 5개뿐이다** — 축·시작회차·연속횟수·점수시퀀스·비교기준. 결정론으로 같은 품질이 나온다(Q3 탈락).

더 결정적으로, **낙인 제약을 코드로 걸 수 없게 된다.** ENG-04는 *"확정형 명사 라벨은 근거 트레이스 동반 없이 단독 노출 금지 — 자동화 편향·낙인 효과 방지"* 를 요구한다. 템플릿이면 문구 집합이 유한하고 사람이 전수 리뷰할 수 있다. LLM 자유 서술이면 이 제약은 프롬프트에 적은 희망사항이 된다.

> **철칙 D2. 낙인 위험이 있는 모든 문구는 템플릿이다.** 사람에 대한 판정을 서술하는 문장은 유한 집합이어야 하고, 그 집합은 리뷰를 통과해야 한다.

> **철칙 D3. LLM이 숫자를 말하게 하지 않는다.** 숫자는 언제나 별도 필드로 존재하고, 화면은 그 필드를 렌더한다. RPT-01 step9가 *"원본 집계값과 자연어 수치 일치 검증"* 을 요구하는 것은 곧 **수치가 서술문과 별도로 존재한다는 뜻**이다. 서술문 안의 숫자를 진실로 취급하지 않는다.

## 3. 판정 결과

### 3.1 AI가 도는 곳 — 12지점

전부 쓰기 시점이고, 전부 게이트를 통과한 뒤에야 레코드가 된다.

| # | FR | AI가 뱉는 것 | 산출 타입 | 게이트 (틀렸을 때 잡는 장치) |
|---|---|---|---|---|
| 1 | **ENG-01** step3 | 축별 채점 | **정수 1~5 + 근거 span** | step5 점수-근거 일치·근거 부재 검증 → step6 순서 스왑 재채점 → ENG-05 재채점 편차 |
| 2 | **MEAS-02B** step3 | DP 후보 | 구조화 객체 | step4 근거성·관련성 평가 → step5 중복·근거부족 제거 → step6 예산 N 랭킹 |
| 3 | **MEAS-06** step4·6·7 | L1/L2/L3 질문 | **자유 텍스트 (유일한 실시간 스트림)** | 원본 코드 근거 강제, depth·시간 상한 |
| 4 | **MEAS-06** step5 | 답변 평가 | **enum** SURFACE/PARTIAL/DEFENDED | 방어답변도 최소 L2 1회 태움 |
| 5 | **MEAS-07** step2 | 교육생 리포트 요약 | 서술 | GOV-03 ViewSetting 필터 → 스냅샷 |
| 6 | **CUR-01** step6 | 모듈 경계 추론 | 구조화 + 신뢰도 | 휴리스틱 폴백(fallback_used), extraction_status |
| 7 | **CUR-02** step6 | 매핑 추천 순위 | **llm_rank (보조 신호 1/4)** | 3개 다른 신호와 병행 표시 + **매니저 승인 전까지 추천 상태** |
| 8 | **RPT-01** step8 | 자연어 요약·커리큘럼 제안 | 서술 | step9 **원본 집계값과 수치 일치 검증** |
| 9 | **RPT-03** step6 | 면담 질문 | 질문 + 근거 | **온디맨드 필수(자동 생성 금지)**, 근거 없는 질문 제거 |
| 10 | **RPT-04** step4 | 변화 하이라이트 | 서술 | RPT-01 집계 재사용 + 수치 일치 검증 |
| 11 | **DASH-02** step4 | 브리핑 요약문 | 서술 | (P2) |
| 12 | **INTV-07** step3 | 취약 축 export 요약 | 서술 | 교육생 원문·근거 미포함 |

**패턴이 보인다.** 12곳 중 **자유 텍스트를 화면에 그대로 뿌리는 건 5곳뿐**(5·8·10·11·12)이고 전부 **문서·리포트·export**다. 나머지 7곳에서 LLM은 **구조화된 값을 만드는 엔진**이지, 글을 쓰는 작가가 아니다.

### 3.2 AI 금지 구역 — 명세에 없어도 금지

| 대상 | 왜 금지인가 |
|---|---|
| **DASH-03 Priority 순위** | 수식이 있다(`S×(0.5+R)`). LLM으로 순위를 매기면 이의제기 때 재현이 불가능하다 |
| **INTV-01 개입 유형 추천** | 명세가 **결정 트리**로 만든 이유가 *"나열식의 평가 순서 미정의 문제 해결"* 이라고 적혀 있다. LLM으로 바꾸면 5개 유형의 **배타적 매칭 보장이 깨진다** |
| **ENG-04 시그널 생성** | 조건 교차(기여편차 AND 이해도저조 AND 지속성). LLM이면 *"단일 지표만으로 확정 시그널이 생성되지 않는다"* 는 **assertion을 코드로 걸 수 없다** (step7이 요구) |
| **INTV-06 회복 판정** | 임계값(`Δ≥1 AND post≥3`). 사람의 회복 여부를 확률적으로 판정하지 않는다 |
| **DASH-06 안정성 배지** | *"두 상태 외 임의 문구 금지"* — LLM은 중간 상태를 지어낸다 |
| **모든 위험·낙인 문구** | 철칙 D2 (DASH-03 사유, DASH-05 타이밍, DASH-10 근거, DASH-11 불균형 표현, INTV-02 초안) |
| **확정 액션의 결과물** | GOV-02 — AI 결과는 추천 상태로만 유지, 확정은 매니저 액션 |
| **교육생용 처방** | GOV-03 — 처방형 기능 배제. 위치 안내까지만 |

## 4. 명세에 없지만 넣어야 할 것 — 쓰기 시점 구조화의 복리 효과

여기가 이 문서의 본론이다. **AI를 쓰기 시점에 돌려 구조화해 저장하면, 그 값들이 쌓여 조회 시점의 통계가 공짜로 나온다.** 지금 명세는 이 복리를 세 군데서 놓치고 있다.

### 제안 1. ENG-01이 근거 span에 **failure_tag(enum)** 를 함께 뱉게 한다 — P0에 넣을 값어치

**문제.** DASH-15(기술영역 취약 히트맵)는 기술 영역을 **DP의 파일·함수·의존성**에서 뽑는다. 그런데 실패는 코드가 아니라 **답변**에서 일어난다. "이 학생은 인증 파일에서 질문받았다"와 "이 학생은 인증을 이해 못 했다"는 다른 사실이고, 지금 설계는 앞의 것만 집계한다.

**제안.** ENG-01이 이미 축별로 LLM-as-judge를 돌리고 근거 span을 인용한다(step4). **같은 호출에서 `failure_tag`를 하나 더 뱉게 한다** — 사전 정의된 enum(예: `상태관리-생명주기`, `동시성-경합`, `인증-토큰수명`). 추가 LLM 호출 0회, 추가 비용 0에 가깝다.

**복리.** 그러면 read-time에서 `GROUP BY failure_tag` 한 줄로:
- DASH-15가 **진짜 취약 영역**(답변 기준)을 집계한다
- CUR-02 교안 매핑의 **정답 라벨**이 생긴다 — 지금은 매니저 승인 로그만 라벨로 쓴다(step9)
- INTV-01 3순위 분기(*"특정 기술영역 집중"*)가 실제 근거를 갖는다

**게이트.** enum이므로 자유 창작 불가. 미분류는 `unmapped`로 떨어뜨리고 그 비율 자체를 품질 지표로 본다.

### 제안 2. GOV-01 이의 사유를 **분류해서 저장**한다

**문제.** 지금 이의 사유는 자유 텍스트로 불변 저장만 된다(step3). 읽는 사람은 매니저 한 명이고, **아무 통계도 안 나온다.**

**제안.** 이의 접수 시점에 LLM으로 **이의 유형 enum**(근거 불충분 / 축 오적용 / 답변 오독 / 코드 맥락 누락 / 점수 과소)을 붙여 저장한다. 쓰기 시점 1회, 이의당 1호출 — 이의는 드물다. 비용 무시 가능.

**복리.** ENG-05(재채점 편차)와 **짝을 이룬다.**
- ENG-05는 *기계가 스스로 흔들리는가* 를 본다 (동일 답변 재채점 편차)
- 이의 분류는 *사람이 무엇을 부당하다고 느끼는가* 를 본다

둘은 다른 실패를 잡는다. 채점이 안정적이면서(ENG-05 STABLE) 특정 축에 이의가 몰리면, 그건 **루브릭 자체가 틀렸다는 신호**다 — ENG-05는 이걸 구조적으로 못 잡는다. INTV-03이 추천 규칙에 대해 이미 하는 일(*"최근 5건 중 3건 이상 기각 → 규칙 재검토 플래그"*)을 **채점 루브릭에 대해서도** 하는 것이다.

### 제안 3. INTV-02 초안은 v1에서 **반드시 템플릿이어야 한다** — LLM을 쓰면 실험이 불가능해진다

명세가 슬롯 템플릿으로 못박고 *"편집 여부를 별도 플래그로 기록"* 하라고 한다. 이게 왜 중요한지 명세는 설명하지 않으니 여기 적는다.

**편집률이 곧 실험이다.** 템플릿 초안의 편집률이 쌓여야 "LLM을 도입할 가치가 있는가"를 **데이터로** 판단할 수 있다. 처음부터 LLM으로 시작하면 **비교 대상(baseline)이 없다.** 편집률 70%면 톤이 틀린 것이고, 5%면 LLM은 낭비다.

> **이게 일반 원칙이다: LLM 도입은 결정론 baseline의 실패로 정당화한다.** 반대 순서로 하면 영원히 "LLM이 더 나은가"를 알 수 없다.

### 제안 4. MEAS-06 세션 로그는 **DP × depth × 등급**으로 이미 구조화돼 있다 — 이걸 화면이 안 쓰고 있다

MEAS-06 step8이 *"DP별 최종 이해 상태·도달 depth·취약 유형 저장"* 을 한다. 즉 **모든 세션이 이미 구조화된 궤적을 남긴다.** 그런데 SC-M06 세션 탭은 이걸 대화 전문으로만 보여준다.

**복리.** 이 값들만으로 read-time 집계가 나온다:
- "이 기수는 L2(설계논리)까지는 가는데 L3(대안비교)에서 무너진다" → DASH-14 히트맵이 이미 원하는 것
- "이 학생은 DEFENDED 비율이 높은데 총점이 낮다" → 방어는 잘하나 이해가 얕은 패턴

추가 AI 호출 0회. **이미 저장하고 있는 값을 화면이 안 읽고 있을 뿐이다.**

## 5. 표현 계약 — 생산자가 형식을 정한다

| 생산자 | 값 타입 | 뷰 형식 | 의무 | 금지 |
|---|---|---|---|---|
| **결정론 · 수식** | 숫자 | 값 + 수식 구성요소 (온디맨드) | 검산 가능해야 함 | 문장 속에 숫자를 숨기기 |
| **결정론 · 템플릿** | 슬롯 문장 | 슬롯 값을 `<b>` 강조 | 슬롯이 어디인지 보여야 함 | "AI가 분석했습니다" 류 어휘 |
| **결정론 · enum** | enum | 배지 (의미축 6개) | 다음 행동과 연결 | 임의 중간 상태 |
| **LLM · 구조화** | 스키마 객체 | 필드별 렌더 | 근거 span 동반 | 모델 원문 노출 |
| **LLM · 스코어** | 정수 1~5 | 표·차트 + 근거 인용 | 근거 없는 점수 표시 금지 | 소수점, 100점 스케일 |
| **LLM · 서술** | 자유 텍스트 | 산문 블록 | **① "AI 생성" 라벨 ② 수치는 별도 필드 ③ 편집·승인 경로** | 서술문 속 숫자를 진실로 취급 |
| **LLM · 대화** | 스트림 | 말풍선 | 코드 근거 고정 패널 | — |

**매니저 화면에서는 AI 산출물과 계산값을 시각적으로 구분한다.** GOV-02가 확정 권한을 매니저에게 준 이상, 매니저는 **자기가 무엇에 책임지는지** 알아야 한다. AI가 제안한 것은 검토 대상이고, 수식이 계산한 것은 검산 대상이다 — 다른 종류의 신뢰다.

**교육생 화면에서도 출처는 밝힌다 — 단 내부는 감춘다.**

> ⚠️ **이 규칙은 처음에 반대로 썼다가 감사에서 뒤집혔다.** 최초 판정은 *"교육생에게는 확정 권한이 없으므로 출처 구분이 행동을 바꾸지 않는다"* 였다. **틀렸다. 교육생에게도 행동이 있다 — GOV-01 이의제기다.**
> 이의를 제기하려면 *"이 판정을 무엇이 내렸는가"* 를 알아야 한다. 출처를 감춘 채 이의제기 버튼만 주는 건 권리를 형식으로만 주는 것이다.

| 교육생에게 밝힌다 | 교육생에게 감춘다 |
|---|---|
| 이 서술·점수는 **AI 평가에 근거한다** | 루브릭 원문, 프롬프트, 모델·프롬프트 버전 |
| 이의를 제기할 수 있다 (GOV-01) | 채점 근거 원본 (DASH-09 — 매니저 전용) |

감추는 쪽은 **다음 회차 게이밍 방지**가 이유고(DASH-09·GOV-03이 같은 근거를 든다), 밝히는 쪽은 **이의제기권의 실질**이 이유다. 둘은 충돌하지 않는다 — "AI가 평가했다"는 사실은 버전 노출이 아니다.

## 6. 단위 경제학 — 최소 인풋 · 최대 아웃풋

AI 호출은 과금 단위다(SYS-01이 기관별로 집계하고 예산 상한 경고까지 건다). 그러니 **호출당 산출 가치**로 판정한다. 원칙은 하나다.

> **철칙 D4. 한 번 호출할 때 최대한 많이 뽑고, 그 결과를 굳혀서 무한히 재사용한다.**
> 비싼 건 호출 횟수가 아니라 **같은 값을 다시 만드는 것**이다.

### 6.1 실제로 세어 본다 — 교육생 1명 · 회차 1회

| 단계 | 호출 수 | 입력 크기 | 비고 |
|---|---|---|---|
| MEAS-02B DP 추출 | 1~2 | **큼 (코드)** | 백엔드가 의미 단위 조각으로 미리 잘라 넣는다(step2) |
| MEAS-06 세션 | **N개 DP × 평균 2.5턴 ≈ 13** | 중간 (대화) | **여기가 최대 비용** |
| ENG-01 5축 채점 | **5** (축별 원자 평가) | 중간 (세션 로그) | 5회 전부 **입력이 동일** |
| MEAS-07 리포트 | 1 | 작음 | |
| **합계** | **≈ 20** | | |

30명 기수 × 6회차 = **약 3,600 호출**. 이게 이 제품의 정상 예산이다.

### 6.2 그런데 — 조회 시점 LLM 하나가 이 예산을 무너뜨린다

매니저 1명이 대시보드를 **하루 20번 × 30일 = 600회** 연다(design-standards §0: "하루에 수십 번 스캔").

**브리핑 요약문 하나만 조회 시점 LLM으로 만들면 월 600 호출이다.** 교육생 30명 전원의 ENG-01 5축 채점 전체(30×6×5 = 900회)에 육박한다. **아무 새 정보도 만들지 않으면서.**

이게 §1의 Q4 금지가 원칙론이 아니라 **산수**인 이유다. 굳혀서 저장하면 재조회 비용은 **0**이다.

### 6.3 최소 인풋 — 네 가지 장치

**① 입력을 백엔드가 미리 깎는다.** MEAS-02B step2가 코드에서 *의미 단위 조각*을 먼저 추출한 뒤 LLM에 넘긴다. 레포를 통째로 넣지 않는다. `extract_scope=본인커밋기여분`은 그 자체로 입력 축소 장치다.

**② 세션 컨텍스트를 O(n²)로 키우지 않는다.** 세션이 턴마다 전체 대화를 재전송하면 토큰이 제곱으로 는다 — 13턴이면 마지막 턴 입력이 첫 턴의 13배다. **DP 경계에서 컨텍스트를 자른다.** 명세가 이미 DP별로 *"최종 이해 상태·도달 depth·취약 유형"* 을 저장하므로(MEAS-06 step8), 이전 DP는 **enum + 한 줄**로 압축해 넘기면 된다. 이건 성능 최적화가 아니라 **명세가 이미 허용한 구조**다.

**③ 회차 간 컨텍스트를 쓰지 않는다.** MEAS-02B 규칙이 이미 못박았다(v8): *"이전 회차 DP·세션 결과를 입력으로 쓰지 않고 해당 회차 커밋 스냅샷만으로 추출"*. 측정 독립성을 위한 규칙이지만, **비용상으로도 정확히 옳다.**

**④ ENG-01 5축은 입력이 같다 → 프롬프트 캐싱.** 축별 원자 평가는 정확도 때문에 5회를 부르지만, **5회 모두 같은 세션 로그를 입력으로 받는다.** 입력을 캐싱하면 실질 입력 과금은 1회분이다. 5축 원자 평가는 **비싸 보이지만 실은 싸다** — 정확도는 5배, 입력 비용은 1배.

### 6.4 최대 아웃풋 — 이미 부르는 호출에 얹는다

§4 제안 1(`failure_tag`)이 정확히 이 원리다. ENG-01은 **어차피** 축별로 답변을 읽고 근거 span을 인용한다. 그 호출에 enum 하나를 더 뱉게 하는 건 **추가 호출 0회, 추가 입력 0토큰**이고, 출력은 몇 토큰 늘 뿐이다. 그 대가로 DASH-15가 진짜 취약 영역을 집계하고, CUR-02가 정답 라벨을 얻는다.

**반대로 §4 제안 2(이의 사유 분류)는 새 호출이지만 정당하다** — 이의는 드물고(월 수십 건), 그 대가로 **루브릭 자체가 틀렸는지**를 잡는다. ENG-05가 구조적으로 못 잡는 실패다. 호출당 가치가 압도적이다.

### 6.5 판정표

| | 호출 시점 | 재사용 | 판정 |
|---|---|---|---|
| ENG-01 5축 + failure_tag | 쓰기 1회 | **영구** — 추이·히트맵·시그널·리포트가 전부 이 값을 읽는다 | ✅ 최고 효율 |
| MEAS-06 세션 | 쓰기 N회 | 세션 로그로 영구 보존 | ✅ 제품의 본질. 대신 컨텍스트를 깎는다 |
| 이의 사유 분류 | 쓰기 1회/이의 | 루브릭 품질 신호로 누적 | ✅ 희소 × 고가치 |
| INTV-02 초안 | — | — | ❌ 템플릿. LLM은 편집률 데이터로 정당화된 뒤에 |
| 대시보드 문구 | **조회마다** | **없음** | ❌ 월 600회 과금, 산출은 템플릿과 동일 |

## 7. 화면별 데이터 출처 지도

| 화면 | 결정론(백엔드) | LLM (쓰기시점 · 굳은 값) | 실시간 LLM |

| **SC-M08** 리포트 | 집계 수치 전부 | 자연어 요약·커리큘럼 제안(RPT-01) | 없음 |

**핵심 사실: SC-M01은 LLM이 만든 텍스트가 사실상 없다.** 우선순위 인박스의 세 텍스트 슬롯은 전부 백엔드다 —
- `row-reason` ← DASH-10 step5 서술형 근거 (변수: 축·시작회차·연속수·점수시퀀스)
- `row-timing` ← DASH-05 (명세가 *"템플릿 선택"·"템플릿 버전 기록"* 이라고 명시)
- `calc-body` ← DASH-03 step10 수식 구성요소 (순수 숫자)

**"벤치마크 쪽 형태가 다양하다"의 진짜 이유**도 여기 있다. 다양한 게 아니라, **8개의 다른 FR이 각자 다른 출력 형태를 지정받아** 한 카드에 모여 있는 것이다 — DASH-04는 "칩(온디맨드)", DASH-05는 "문구(항상 표시, 상태만 전환)", DASH-06은 "배지", DASH-07은 "지표 줄 + 신뢰등급 아이콘", DASH-08은 "배지 + 기본값", INTV-01은 "추천: 유형 — 트리 경로 근거", INTV-02는 "편집 가능 초안 + 버튼".

그리고 그 형태 차이는 자의적이지 않다. DASH-06 규칙이 원리를 말한다: **"배지는 매니저의 다음 행동과 연결될 때만 의미 있다."** 칩은 참고, 배지는 분기, 문구는 타이밍, 초안은 편집 — **형태가 곧 매니저가 취할 행동의 종류다.**

## 8. 감사 결과 (2026-07-13, 16개 화면 전수)

이 계약으로 화면을 감사했다. **결과는 좋다 — 위반 2건, 그리고 계약 자체의 오류 1건.**

| 검사 | 결과 |
|---|---|
| **D1** 조회 시점 LLM 없음 | ✅ 16/16. 실시간 LLM은 SC-T04 세션 대화 하나뿐(설계대로) |
| **D2** 낙인 문구 = 템플릿 + 슬롯 강조 | ❌ **SC-M04 3건** — M01과 같은 생산자인데 슬롯 강조가 없었다 → 통일 |
| **D3** LLM이 숫자를 말하지 않음 | ✅ SC-M08이 모든 수치를 `<span class="num" data-label>`로 감싸 서술과 분리 |
| **LLM 서술 3종 의무** (AI 라벨·수치 분리·편집/승인) | ❌ **SC-T05 누락** → 출처 배지 + 이의제기 근거 추가 |
| **역방향 오류** (결정론 값을 "AI"라 부름) | ✅ 0건 |

### 모범 사례 — SC-M08

RPT-01 자연어 요약이 세 의무를 전부 지킨다: `AI 생성 요약` 배지 + *"자동 확정되지 않습니다 — 판단·개입은 매니저의 결정입니다"* + 모든 수치를 클릭 가능한 별도 필드로. **AI 요약 생성 실패 상태까지 있고, 그때 문구가 *"정형 지표는 정상 제공됩니다"*** — LLM이 죽어도 결정론 층은 살아 있다는 계층 구조를 화면이 그대로 보여준다. 다른 LLM 서술 화면은 이걸 따른다.

### 위반 1 — SC-T05에 출처 표시가 없었다

MEAS-07(요구사항 12번: *"교육생용 AI 리포트가 생성된다"*)인데 화면 어디에도 AI 유래임을 밝히지 않았다. → 세션 개요 카드에 `AI 평가 기반` 배지, 이의제기 줄에 *"이 진단은 세션 답변에 대한 **AI 평가**에 근거합니다"* 추가.

### 위반 2 — SC-M04의 근거 문장에 슬롯 강조가 없었다

SC-M01과 **같은 생산자(결정론 템플릿)** 인데 M01은 슬롯을 `<b>`로 강조하고 M04는 평문이었다. 같은 값이 화면마다 다르게 읽힌다. → M01 패턴으로 통일(`.row-evidence b`).

### 계약 자체의 오류 — §5를 뒤집었다

최초 §5는 *"교육생 화면에서는 출처를 구분하지 않는다 — 확정 권한이 없으므로"* 였다. **틀렸다. 교육생에게도 GOV-01 이의제기라는 행동이 있다.** 판정의 출처를 모르면 이의를 제기할 근거가 없다. 출처를 감춘 채 이의제기 버튼만 주는 건 권리를 형식으로만 주는 것이다.

> **교훈: "이 사용자에게 이 정보가 행동을 바꾸는가"를 물을 때, 그 사용자의 행동 목록을 먼저 전수로 적어야 한다.** 확정 권한만 보고 이의제기권을 빠뜨렸다.
