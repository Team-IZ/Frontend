# 화면 정의서 공통 디자인 시스템 앵커

모든 화면(P0 16종 + 이후 배치)의 정의서·와이어프레임 작성자는 이 문서, **`tokens.css`(토큰·컴포넌트 클래스 단일 소스)**, **`design-standards.md`(검사 가능한 통일성 계약)**, **`ux-principles.md`(노출·표현·정보밀도 행동 규범)**를 먼저 읽는다. 네 문서는 층이 다르다 — 이 문서는 **레이아웃·셸·패턴**(무엇을 어디에 놓는가), `tokens.css`는 **색·컴포넌트 클래스**(무엇을 복사해 쓰는가), `design-standards.md`는 **grep으로 셀 수 있는 계약**(무엇을 어기면 안 되는가), `ux-principles.md`는 **노출 통제**(무엇을 보여주면 안 되는가). 여기 명시된 값·패턴·용어를 벗어나지 않는다. 여기 없는 결정이 필요하면 이 문서에 새 항목으로 추가하고, 이미 작성된 화면이 있다면 소급 반영한다.

**2026-07-13 개정 배경 — 왜 토큰을 별도 파일로 뺐는가:** 초판 앵커는 토큰·색 매핑을 이 문서의 산문 표로만 규정했고, 16개 와이어프레임 각자가 그 표를 손으로 `<style>`에 옮겨 적었다. 재량 색상 팔레트(red/amber/green/gray/blue/accent)는 16개 전 화면이 완전히 일치했지만, **그 팔레트를 어느 컴포넌트에 연결할지는 화면마다 즉석으로 결정**했다 — 그 결과 SC-M08의 최종 등급 "표면"이 amber가 아니라 accent(보라)로, SC-T05의 공개범위 배너가 gray가 아니라 accent(보라)로 렌더되는 사고가 났다. 둘 다 "색은 맞는데 그 색을 이 요소에 처음 연결하는 사람이 매번 새로 판단"해서 생겼다. 해법은 색 이름을 도메인별로 더 쪼개는 것이 아니다 — 그건 이미 한 번 시도했다가 되돌린 접근이다(`design-standards.md` C2: SC-M01이 한때 `--risk-text`/`--imbalance-text`/`--ace-text`를 만들었고, "같은 의미에 다른 이름을 만들지 않는다"는 계약 위반으로 6축 어휘로 되돌렸다). 해법은 **컴포넌트 클래스를 캐노니컬화**하는 것이다 — `tokens.css` §2가 `.grade-hero .g.surface`, `.banner--neutral` 같은 클래스로 "이 컴포넌트는 이 톤"을 한 곳에서만 결정하고, 화면은 raw 토큰을 새로 연결하지 않고 그 클래스를 그대로 쓴다.

## 1. 디자인 토큰 — `tokens.css` 참조

토큰·의미색·배지/배너/등급/Primary 버튼의 캐노니컬 컴포넌트 클래스, 접근성 상수(포커스 링·reduced-motion), 고정 목업 상수는 **`docs/screens/_source/tokens.css`에 단일 정의**되어 있다. 새 화면을 작성할 때는 그 파일의 `:root` 블록과 컴포넌트 클래스를 `<style>`에 그대로 복사한다(앵커는 링크 금지 — 아래 §1.1 참조). 이 절은 그 파일의 요약이며, 값이 어긋나면 `tokens.css`가 정답이다.

### 1.1 자립형 필수 (변경 없음)

**와이어프레임 HTML은 반드시 자립형(self-contained)이어야 한다 — Tailwind 유틸리티 클래스 사용 금지, CDN·외부 스타일시트·웹폰트 링크 금지, `tokens.css`도 링크 금지(복사만).** 모든 스타일은 `<style>` 안에 인라인으로 쓴다. 이유: 와이어프레임은 Artifact로 발행되는데 Artifact의 CSP가 외부 스크립트/스타일 요청을 전부 차단한다. `cdn.tailwindcss.com`을 참조하면 **로컬 브라우저에서는 멀쩡히 렌더되지만 발행본에서는 모든 유틸리티 클래스가 죽어 레이아웃이 붕괴한다**(실제로 SC-A02에서 발생: 로고가 빈 원, 정책 칩이 전체폭 막대). 실제 앱 코드에서 Tailwind를 쓰는 것과는 무관한 문제다.

### 1.2 브랜드 보라 — 채움/텍스트 분리 (혼용 금지)

`--accent-fill: rgba(170,59,255,1)`은 **채움·보더·아이콘 등 비텍스트 전용**이다. 흰 배경 위 텍스트로 쓰면 **대비 4.39로 미달**한다. 텍스트(링크·강조 문구·배지 글자·Primary 버튼 글자)는 반드시 `--accent-solid: #7e22ce`(6.98:1)를 쓴다. 브랜드 색 자체를 바꾸는 대신 텍스트용 토큰을 분리한 것 — 아이덴티티는 보존하면서 가독성을 확보하는 표준 해법이다. **실제 사고:** SC-A01이 이 규칙을 어기고 상태 라벨 텍스트에 `--accent-fill`을 직접 써 4.39:1로 렌더된 적이 있다(수정됨). 정확한 값·전체 토큰 목록은 `tokens.css` §1을 참조.

### 1.3 보더 — 두 종류 (같은 값을 쓰면 안 된다)

`--border`(장식적 구획 — 카드 테두리·표 구분선, WCAG 대상 아님)와 `--border-interactive`(입력 필드·선택 가능한 컨트롤의 경계, 3:1 필수)는 용도가 다르다. WCAG 1.4.11은 "지각되어야 하는 UI 컴포넌트"에 적용되는데, 입력 필드 경계는 **어디에 입력해야 하는지 알려주는 정보**라 3:1이 필수지만 카드 테두리는 순수 구획이라 면제다. **계산기가 시키는 대로 전 보더를 어둡게 하면 3:1은 통과하고 디자인은 죽는다** — 구분해서 적용하라.

### 1.4 타이포·스페이싱

- 폰트: Geist Variable(본문·제목 공통), 모노는 `ui-monospace`
- 기준 폰트 크기 18px/145%, letter-spacing 0.18px, **1024px 이하는 반드시 16px로 낮춘다** — `@media (max-width:1024px)` 블록이 없는 화면은 이 규칙을 지킬 수 없으므로 신규 화면은 처음부터 포함한다.
- spacing은 실제 앱과 동일하게 Tailwind 기본 스케일(4px 배수)을 따른다.

## 2. 상태·등급 색상·용어 매핑 (전 화면 공통, 임의 변경 금지)

기능명세서에 등장하는 용어를 그대로 쓰고, 색만 아래로 고정한다. **화면에서 이 색을 직접 골라 쓰지 않는다** — `tokens.css` §2의 캐노니컬 클래스(`.badge-risk`/`.badge-warn`/`.badge-ok`/`.grade-hero .g.surface`/`.banner--neutral` 등)를 그대로 쓴다. 아래 표는 "이 도메인 용어가 어느 클래스에 매핑되는가"의 사전이지, 화면마다 새로 `color:var(--amber-text)`를 연결하라는 뜻이 아니다 — 그렇게 즉석 연결하다가 SC-M08(표면 등급)·SC-T05(공개범위 배너)가 색을 놓쳤다.

배지 텍스트 색은 **모두 Tailwind 700 램프**다(600은 연한 배경 위에서 4.5:1을 넘지 못한다 — 실측 2.86~4.24). 배경 틴트는 100 램프 그대로 유지해 색 인지를 보존한다.

| 용어 | 의미 | 배지 텍스트 / 배경 | 대비 |
|---|---|---|---|
| 위험 | 이해도 연속 하락 등 위험 시그널 | `#b91c1c` (red-700) / `#fee2e2` | 5.30 |
| 기여·이해도 불균형 (구 '프리라이더 의심' — **이 명칭 UI 사용 금지**, ux-principles.md A1) | 기여 저조 × 이해도 저조 교차 | `#92400e` (amber-**800**) / `#fef3c7` | 6.37 |
| 에이스 | 이해도·성장률·설명력 동시 상위 | `#15803d` (green-700) / `#dcfce7` | 4.57 |
| 팀 이상 | 팀 내 편차 급증 | `#7e22ce` (purple-700) / `#f7ecff` | 6.12 |
| 소유 / 표면 / 미흡 (최종 등급) | 최종 회차에만 부여 | 소유=green, 표면=amber, 미흡=red — 위 팔레트 재사용 |  |
| 대기 / 진행 / 완료 (개입 상태) | 개입 건 상태 | 대기=`#5b6270`/`#f3f4f6`, 진행=`#1d4ed8` (blue-700)/`#dbeafe`, 완료=green | 5.57 / 5.49 |

**amber만 800인 이유:** 노랑 계열은 고유 명도가 높아 700(`#b45309`)이 4.51로 겨우 걸친다. 여유(headroom)가 없는 값은 폰트 렌더링·디스플레이 차이로 실패하므로 한 단계 더 내렸다. 램프 일관성보다 가독성이 우선이다.
| 상 / 중 / 하 (중요도) | 뱃지가 아니라 툴팁·비고에만 사용, 교육생 화면에는 절대 노출 금지 | — |
| 회복 / 부분회복 / 미회복 / 악화 / 판정대기 (개입 효과 판정, P1·INTV-06) | 개입 후 다음 회차 비교 결과 | 회복=green, 부분회복=amber, 미회복=gray, 악화=red, 판정대기=gray — 위 위험/에이스/개입상태 팔레트 재사용 |

**규칙:** 같은 의미는 항상 같은 색이다. 화면마다 "위험"을 다른 색으로 칠하지 않는다.

**범용 상태 재사용 규칙(Task 18에서 추가):** 위 팔레트는 도메인 배지 전용이 아니다. 배너·토스트·폼 검증 상태(검증완료/미검증/진행중/실패 등)처럼 화면마다 반복 등장하는 범용 상태에도 새 색을 만들지 않고 그대로 재사용한다 — 성공/완료=green, 주의·경고·검토대기=amber, 실패·오류·차단=red, 중립·대기=gray.

## 3. 매니저 셸(SC-M*, SC-S01 공통 레이아웃)

모든 매니저/슈퍼어드민 화면은 아래 셸 안에 콘텐츠 영역만 바뀌어 들어간다.

- **좌측 사이드바** (고정, 폭 240px): 로고/기관명 → 메뉴 항목 순서 고정:
  1. 브리핑·대시보드 (SC-M01)
  2. 시그널 분석 — 위험/불균형/에이스 (SC-M04)
  3. 교육생 목록 (SC-M11)
  4. 개입 관리 (SC-M07)
  5. 리포트 (SC-M08)
  6. 이의 검토 (SC-M09)
  7. 설정 — 기수/측정계획 (SC-M02, SC-M03)
  (슈퍼어드민 SC-S01은 이 사이드바 대신 별도 최소 셸: 로고 + "기관 관리" 단일 메뉴)
- **상단 헤더** (고정, 높이 64px): 현재 기수 선택 드롭다운(좌측) + 프로필/로그아웃(우측)
- **콘텐츠 영역**: 헤더 아래, 사이드바 우측, 여백 `padding: 24px`, 최대폭 제한 없음(대시보드는 풀블리드)
- **1024px 이하 접힘**: 사이드바를 64px 아이콘 레일로 접는다. **항목당 고유 아이콘 글리프 + `title` 속성**을 쓴다 — 항목 1~7 각각: 🧭 브리핑·대시보드 / 📡 시그널 분석 / 👥 교육생 목록 / 🛠 개입 관리 / 📄 리포트 / ⚖ 이의 검토 / ⚙ 설정. **번호(1~7)는 쓰지 않는다** — §10의 "장식용 번호 마커 금지"를 사이드바 자신이 어기면 앵커가 스스로를 위반하는 꼴이다(2026-07-13 발견: `design-standards.md` C5 감사가 "라벨을 숨기면 메뉴 식별 불가"라는 문제를 번호로 풀었는데, 그 자체가 §10 금지 패턴이었다 — 아이콘은 hover 없이도 식별 가능해 두 문제를 동시에 푼다).

## 4. 교육생 셸(SC-T*)

매니저 셸과 의도적으로 다르게: 사이드바 없음(교육생 플로우는 선형이라 자유 탐색이 필요 없음).

- **상단 헤더** (높이 56px, 더 미니멀): 기관 로고만 좌측, 진행 상태 표시(예: "체크포인트 2/5") 우측
- **콘텐츠 영역**: 중앙 정렬, 최대폭 720px (읽기·응답에 집중하는 세로 플로우)
- **예외(Task 18에서 추가):** 체크포인트가 아직 시작되지 않은 화면(예: 계정 활성화 직후 SC-T01)에서는 우측 진행 상태 슬롯에 "체크포인트 N/M" 대신 화면 상태를 나타내는 짧은 텍스트(예: "활성화 완료")를 대체 표시할 수 있다.

## 5. 인증 화면(SC-A*)

셸 없음. 중앙 정렬 카드 1개(최대폭 400px), 배경은 `--bg`, 로고 상단.

**카드 내부 상태 치환(Task 18에서 추가):** 정상 폼이 있던 카드 슬롯 자리에 오류·대기 안내 콘텐츠를 그대로 치환해 넣는다 — 카드의 위치·크기·보더는 유지하고 내부 콘텐츠만 전환한다(토큰 검증 실패, 이메일 인증 대기, 초대 링크 만료 등).

## 6. 카드 패턴 (대시보드류 공통)

모든 "OO 카드"(위험 카드, 에이스 카드, 개입 카드 등)는 다음 구조를 따른다:

```
┌─────────────────────────────┐
│ [배지: 위/프/에/등 색상]  ⋮   │  ← 상단: 상태 배지 + 더보기 메뉴
│ 이름/제목 (제목 텍스트 색)     │
│ 핵심 근거 문구 1줄 (본문 텍스트)│  ← "어느 축이 언제부터" 식 근거, 라벨 단독 금지
│ [보조 메타 정보]               │
│ [액션 버튼]                    │  ← 있는 경우만
└─────────────────────────────┘
```
보더: `1px solid var(--border)`, radius `12px`, 그림자는 hover 시에만.

**예외(Task 18에서 추가):**
- 확인/웰컴형 카드(예: 계정 활성화 완료 확인처럼 상태 배지가 핵심이 아닌 카드)는 상단 배지 슬롯을 아이콘으로 대체하거나 생략할 수 있다.
- "팀 이상" 카드도 위 카드 패턴을 동일하게 따른다(배지 색만 팀 이상 톤으로 교체, 구조는 동일).

**공개범위 배너(Task 18에서 추가):** GOV-03 공개범위(전체/요약/비공개) 값을 보여주는 화면(예: SC-M06, SC-M08, SC-T05)은 공통 배너를 쓴다 — 위치는 교육생 화면 최상단 / 매니저 화면은 상세 패널 헤더 하단, gray 톤 인라인 배너, 고정 문구 "{역할} 공개범위: {값}" + 적용 사유 한 줄.

## 7. 빈 상태 / 에러 / 로딩 공통 패턴

- **빈 상태**: 중앙 정렬, 회색 아이콘 + 1줄 안내 문구(+ 있으면 CTA 버튼). 예: "활성 시그널이 없습니다"
- **에러**: 콘텐츠 영역 상단 인라인 배너, red 톤, 재시도 버튼 포함
- **로딩**: 스켈레톤(카드/표 모양 그대로 회색 블록), 스피너는 버튼 내부 액션에만 사용
- **배너 색상(Task 18에서 추가)**: 성공/경고/오류 3톤 범용 안내 배너는 2번의 배지 팔레트를 그대로 재사용한다(성공=green, 경고=amber, 오류=red) — 새 색을 만들지 않는다.
- **토스트/스낵바(Task 18에서 추가)**: 액션 성공 후 비침습적 알림(예: 초대 재발송 완료, 개입 생성 완료, 임시저장 완료). 화면 우하단 고정, 4초 후 자동 소멸, 성공=gray 톤/실패=red 톤, 액션이 있으면 텍스트 링크 1개만 둔다.
- **다단계 진행 스테퍼(Task 18에서 추가)**: 여러 백그라운드 단계를 순차로 보여줘야 하는 화면(예: 제출→분석→세션 진입)에 쓰는 가로 스텝 인디케이터. 완료=강조 보더로 채움, 진행중=강조 보더 아웃라인+스피너, 대기=회색.
- **미구현(P1/P2) 자리 표시(Task 18에서 추가)**: 이번 배치에 없는 기능의 레이아웃 자리를 남길 때 — 카드 테두리는 점선(보더 색 재사용), 내부 콘텐츠는 40% 불투명도로 흐리게, 우상단에 gray 톤 "P1 예정"(또는 "P2 예정") 배지, 클릭 시 `cursor: not-allowed` + 화면 전이 없음(툴팁으로 "다음 배치에서 제공됩니다" 안내).

## 10. 와이어프레임 렌더링 함정 (전 화면 공통, 발행 전 필수 확인)

실제 시각 검증에서 반복 발생한 결함들. 정의서·FR 커버리지가 완벽해도 화면은 따로 깨진다.

| 함정 | 증상 | 규칙 |
|---|---|---|
| 외부 CDN 참조 | 로컬은 정상, 발행본만 레이아웃 붕괴 | §1 참조 — 모든 CSS 인라인, 자립형 HTML |
| 온디맨드 패널을 오버레이로 | 패널이 본문을 덮어 대조 대상(수치·차트·표)이 가려짐 | 근거·상세 패널은 **in-flow 컬럼**. 열리면 본문이 좁아지며 리플로우될 뿐 가려지지 않는다. `position:absolute` + `translateX` 오버레이 금지 |
| 코드/모노스페이스 블록 가로 잘림 | 긴 줄이 패널 밖에서 잘려 읽을 수 없음 | `white-space:pre` 행은 `width:max-content; min-width:100%`로 부모 스크롤 컨테이너를 밀어낸다 |
| SVG `width="100%"` + 고정 `height` | 기본 `preserveAspectRatio`가 콘텐츠를 가운데로 몰아 한쪽이 빔 | viewBox 비율을 실제 렌더 박스 비율에 맞춘다. `preserveAspectRatio="none"`은 **텍스트가 늘어나므로** 텍스트 없는 스파크라인에만 |
| 차트 y축을 0부터 | 점수 62~82 차이가 일직선으로 뭉개져 아무것도 안 보임 | y축을 실제 데이터 범위로 좁히고 그리드라인·축 라벨을 넣는다 |
| 내부 산출값 상시 노출 | 행마다 원값이 붙어 스캔 불가 | 표시 의무가 있는 값(예: DASH-03의 S·R·Priority)은 **디스클로저로 접어** 온디맨드 제공(B1). 값 자체는 최초 응답에 포함 |
| 장식용 번호 마커 | 사이드바 `1~7` 등 정보 없는 순번 | 순서가 정보를 담을 때만 번호를 쓴다. 내비게이션 메뉴에는 금지 — 접힘 상태 아이콘 규격은 §3 참조 |
| 목업 데이터 불일치 | 화면마다 기관·기수명·이메일이 다름(2026-07-13 발견: SC-A01·A02·T01이 각각 "기관명"/"이즈커리어 부트캠프"/"코드스쿼드"로 다 달랐다) | 전 화면 고정 상수는 `tokens.css` §4를 그대로 복사: 기관 `IZ · 코드스쿼드`, 기수 `7기 백엔드 부트캠프`, 매니저 `manager@codesquad.io`. 새 화면 작성 시 즉석으로 지어내지 않는다 |

**발행 전 필수:** 전 화면을 헤드리스 크롬으로 렌더해 눈으로 본다.
`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --hide-scrollbars --window-size=1600,1150 --screenshot=out.png "file://$PWD/SC-XXX.html"`

## 11. 전역 권한·확정 계약 (AUTH-09 · GOV-02 — **모든 화면 공통, P0/상**)

두 FR은 `화면 흐름 = 전역`이라 화면 역추출에서 통째로 빠졌다. 화면이 없는 게 아니라 **모든 화면에 있어야 한다.** 16개 정의서 전부 이 절을 인용한다.

### 11.1 권한 (AUTH-09 · RBAC)

| 상황 | 화면 처리 | 근거 |
|---|---|---|
| 토큰 부재·위변조·만료 | **401** → 세션 만료 안내 후 SC-A01 로그인으로 이동. "권한 없음"과 **문구·화면이 달라야 한다** | AUTH-09 예외 |
| 권한 밖 리소스·오퍼레이션 | **403** → 화면 유지 + `권한없음` 상태 UI. 데이터·액션 버튼을 렌더하지 않는다(비활성만으론 부족 — 응답 스키마 레벨에서 필터) | AUTH-09 비즈니스 규칙 |
| 미정의 role / 미등록 operation | **default deny** + 보안 로그. 화면은 403과 동일하게 취급 | AUTH-09 예외 |
| 교육생 토큰의 매니저 전용 액션 호출 | **403 + 감사 로그**. 매니저 전용 데이터(세션 원문·채점 근거·프롬프트·루브릭)는 교육생 응답에서 제거 | AUTH-09, D1 |

- 모든 조회는 `org_id` 테넌트 격리(SYS-02)와 **Permission Matrix 조회**를 함께 통과해야 한다.
- **AuditLog 대상**: 민감 데이터 조회(세션 원문·채점 근거 열람), 권한 거부, 권한 변경.
- `권한없음` 상태는 각 정의서 **상태별 UI 표에 행으로 존재**해야 한다(정상/로딩/빈/에러와 동급).

### 11.2 확정 (GOV-02 · 자동확정 금지)

**확정 액션**이란 시스템 상태를 되돌리기 어렵게 바꾸는 매니저의 명시적 승인이다 — 교안 매핑 승인(PLAN-05), 회차 확정, 점수 판정 수정·이의 기각(RVW-02), 개입 상태 전환, 기관·매니저 상태 변경.

| 규칙 | 화면 처리 |
|---|---|
| AI·시스템 자동 확정 요청 **차단** | 추천·제안·AI 요약에는 항상 "자동 반영되지 않습니다 — 결정은 매니저" 문구. 확정 버튼은 **사람의 클릭에서만** 발생 |
| 명시적 매니저 액션 부재 시 **상태 변경 차단** | 화면 진입·조회만으로 상태가 바뀌는 경로를 만들지 않는다 |
| **승인자·시각·근거 기록** 후 확정 전후 상태 AuditLog 저장 | 확정 다이얼로그에 근거 입력 필드. 기각은 **사유 필수** |
| **AuditLog 실패 시 확정 트랜잭션 롤백** | 확정 API는 원자적. 실패 시 "확정되지 않았습니다 — 다시 시도" 에러 상태로 되돌리고, **성공 토스트를 먼저 띄우지 않는다**(낙관적 UI 금지) |
| 중복 승인 **멱등 처리** | 같은 확정 요청이 두 번 오면 두 번째는 no-op. 버튼 연타·새로고침 후 재요청에서 상태가 두 번 바뀌지 않는다 |

각 정의서의 **화면 액션 → API 표**에서 확정 액션 행은 `응답·부수효과` 칸에 반드시 `AuditLog(승인자·시각·근거·전후 상태) · 실패 시 롤백 · 멱등`을 적는다.
