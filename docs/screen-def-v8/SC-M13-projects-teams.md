# SC-M13 · 프로젝트 · 팀

> **⚠ D77/78 흡수 + D90 권한 분리:** 이 화면은 `manager/project-workspace.html`(SC-M13 워크스페이스)로 실장 흡수됨 — 와이어프레임 실물은 §10 참조. **권한 경계(D90, FB-F5):** 프로젝트 생성(ORG-03) = **총괄**(측정 무결성·프로젝트가 기수의 자식이라 같은 오너 계층) / 팀 편성·레포(ORG-02) = **담당**(반·프로젝트마다 계속 생기는 운영을 총괄이 다 못 함 — 규모 근거).
> 소스: 기능명세서 v8 ORG-03(프로젝트 생성·매핑) + ORG-02(팀 구성·재배정) + 도메인 계층(`02-domain-hierarchy.md`: 팀=프로젝트 종속).
> 배치: P0 · SC-M02에서 분리(D18). 프로젝트는 기수 내내 반복되는 **운영** 활동 → 별도 화면.
> ⚠️ 명세 보완: 레포는 프로젝트 단일값이 아니라 **팀별(팀 프로젝트)·학생별(개인 프로젝트)** — 프로젝트 표엔 기간·상태·레포 연결 현황만(D18).

## 2. 목적 & UX 설계 근거

- **프로젝트는 반복 운영이다.** 한 기수/반에서 개인·팀 프로젝트가 기간에 걸쳐 여러 개 돈다. 그래서 '설정'이 아니라 **목록·상세로 관리하는 운영 화면**(SC-M02에서 분리, D18).
- **레포는 프로젝트 속성이 아니다.** 팀 프로젝트는 **팀마다**, 개인 프로젝트는 **학생마다** 레포가 다르다. 프로젝트 표엔 넣을 수 없다 → 표엔 **유형·대상 반·기간·상태·레포 연결 현황(N/M)**, 실제 URL은 **팀 카드/학생별**에서 입력. (측정 대상 코드가 여기서 나옴 — MEAS-01.)
- **팀은 프로젝트마다 새로 편성.** 팀은 그 프로젝트 전용. 다음 프로젝트 = 새 팀. 재편성은 이력 보존(TeamMembership from/to). 각 팀 = 팀명·팀원·레포·상태(D16).
- **기간이 핵심 축.** 제출 기한(측정 회차와 연동)이 프로젝트의 1급 정보 → 표·상세 상단.
- **커밋 이메일 검증.** 팀원/학생의 커밋 이메일 미검증은 귀속 경고(AUTH-07, 규범 A8).

## 3. 정보 구조 & 레이아웃 (매니저 앱 셸 · 데스크톱)

**매니저 앱 셸** 공유(SC-M02와 동일). 좌측 네비 '프로젝트' 활성.

**뷰 1 — 프로젝트 목록(마스터):**
- 상단: [프로젝트 생성](유형·대상 반·기간·요구사항)
- 테이블: **프로젝트명 · 유형(개인/팀) · 대상 반 · 기간(시작~마감) · 레포 연결(N/M) · 상태**
- 필터: 반 · 유형 · 상태

**뷰 2 — 프로젝트 상세(행 클릭):** 브레드크럼 + 개요(유형·대상·기간·요구사항 연결) +
- **팀 프로젝트:** **팀 편성** — 팀 카드(팀명 · 팀원 chips · **레포 URL** · 상태) + **미배정 풀**(다중 선택 → [선택 N명 팀 배정]) + [팀 추가] + **[⚄ 자동 배분]**(균등/랜덤·D19). 커밋 이메일 검증 상태 표기.
- **개인 프로젝트:** 학생별 레포 목록 + **벌크 바**(다중 선택 → 제출 독촉·레포 안내 재발송·D19).
- 상단 개요: 프로젝트 **유형·대상·기간·요구사항 연결 + 추출 범위(본인 커밋 기여분/전체 코드) + 측정 계획 링크 + 적용 교안(D98)**.
- **적용 교안(D98·총괄):** 개요 탭에 "적용 교안" 블록 + [교안 연결] 모달 — 이 기수 교안 라이브러리에서 다중 선택(선택적 다대다·D91, 비워도 됨). 커버 기술영역·커버리지 요약(프로젝트 기술영역 대비 미커버 표기). 리포트 위치 안내(MEAS-07)의 프로젝트↔교안 링크를 *거는* 지점 — 교안 쪽(SC-M12)은 결과(적용 프로젝트 열·자동 매핑)를 봄. 추출 실패 교안은 연결 불가.
- **개인 프로젝트:** **학생별 레포** — 목록(이름 · 레포 URL · 커밋 이메일 검증 · 제출 상태).

반응형: 웹 기준.
