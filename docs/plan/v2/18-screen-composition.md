# 화면 구성 설계 — nav 아래 무엇이 있는가

> [17번](17-ia-menu-tree.md)이 메뉴를 정했다. 이 문서는 **각 메뉴를 열면 어떤 화면들이 나오는가**를 정한다.
> 화면 안쪽의 필드·문구는 15번 차수에서 그린다. **여기서는 뷰의 종류와 배치까지.**

---

## 0. 뷰 어휘 — 다섯 가지만 쓴다

| 뷰 | 언제 | 규칙 |
|---|---|---|
| **목록** | 같은 것이 여러 개 | 헤더(제목+총개수 좌 / +추가 우) · 툴바(검색·필터·정렬 **전부 좌**) · 푸터(범위개수 좌 + 페이저 중앙) |
| **상세** | 하나를 깊게 | **탭 또는 마스터-디테일.** 세로 스택 5~6블록 금지 |
| **모드** | 작업하는 동안만 | 전체화면 · 사이드바 가림 · 끝나면 원래 자리로 |
| **모달** | 한 번에 끝나는 입력 | 생성·배정 확인. **읽기 전용 모달은 만들지 않는다** |
| **뷰어** | 링크로만 도달 | 단일 화면 · 목록도 검색도 없음 |

**상세를 고를 때**

```
탭            항목이 서로 독립  ·  3~4개  →  교육생 상세(종합/세션/면담)
마스터-디테일   좌 목차 → 우 한 섹션      →  리포트 · 운영 관리
```

**둘 다 "한 뷰포트 안에서 전환"이다.** 앵커 스크롤은 쓰지 않는다 — 목차를 눌렀는데 스크롤이 튀면 지금 어디인지가 사라진다.

**대시보드는 둘 중 하나를 고른다.**

| | 언제 | 이 제품에서 |
|---|---|---|
| **인박스** | 대상이 사람이고 수가 적다 | **매니저**(25명) |
| **지표판** | 대상이 집단이고 개인을 못 본다 | **오퍼레이터**(250명·10반) |

**같은 nav 자리지만 다른 화면이다** — 범위가 아니라 장르가 다르다.

## 1. 슈퍼어드민 — 실질 1화면

**nav 3개는 과하다.** `플랫폼 관리`(계정 몇 개)와 `설정`(모델 티어·단가)은 화면이라기보다 **설정 항목**이다.

```
nav              화면
────────────    ──────────────────────────────────
기관             기관 목록  →  기관 상세 (탭 4)
⚙ (우상단)       플랫폼 설정 (탭 2)
```

### 1-1. 기관 목록

| | |
|---|---|
| 헤더 | `기관` + 총 14 / **[+ 기관 생성]** |
| 툴바 | 검색 · 상태 필터(활성/정지) · 정렬 |
| 행 | 기관명 · 상태 · 기수 수 · 교육생 수 · **오퍼레이터 미배정 배지** · 이번 달 비용 |
| 푸터 | 1–14 / 14 · 페이저 |

`[+ 기관 생성]` → **모달**(기관명·도메인) → 생성 직후 `오퍼레이터 미배정` 상태로 목록 복귀.

### 1-2. 기관 상세 — 탭 4

| 탭 | 내용 |
|---|---|
| **개요** | 상태 · 기수 목록(진행/종료) · 교육생 수 · 오퍼레이터 |
| **오퍼레이터** | 계정 목록 · **[+ 오퍼레이터 초대]** 모달 · 정지/재활성 |
| **사용량 · 비용** | 모델별 호출·토큰·단가 · 월 추이 |
| **설정** | 계약 한도 · 기능 토글 · 테넌트 정책 |

> **`총괄 매니저` 탭을 `오퍼레이터`로 바꾼다.** 이름이 바뀌었을 뿐 아니라 **이 탭은 계정 관리이지 매니저 관리가 아니다** — 반 담당 매니저는 기관 안에서 오퍼레이터가 초대한다.

### 1-3. 플랫폼 설정 — 탭 2

`모델 티어·단가` / `슈퍼어드민 계정`. **nav가 아니라 우상단 톱니**에서 연다.

## 2. 오퍼레이터 — 5 nav

### 2-1. 대시보드 — 지표판

**오퍼레이터 스코프는 250명 · 10반이다.** 개인은 볼 수 없고 볼 필요도 없다 — **개별 학생 위험은 매니저가 처리한다.**

> **오퍼레이터가 봐야 하는 것은 학생 위험이 아니라 운영 이상이다.** 반 단위 이상에서만 보이고, **오퍼레이터만 조치할 수 있는 것**만 올린다.

```
┌ 이번 회차 ──────────────────────────────────────────────────┐
│  미프 3차 · 제출 231/250 · 분석 실패 3 · 응시 198/231 · 리포트 미발행 │
└──────────────────────────────────────────────────────────────┘

┌ 반 비교 ────────────────────────────────────────────────────┐
│  A반 ███████░░  B반 █████░░░░  C반 ████████░  … J반          │
│  막대 = 2단 이하 개념이 2개 이상인 학생 비율                  │
└──────────────────────────────────────────────────────────────┘

┌ 조치 필요 ──────────────────────────────────────────────────┐
│  ⚠ 집단 미달   C반 · "Graph 구성" 14/25 미달   → 반 단위 처리 │
│  ⚠ 개념 공백   미프 3차 · "State 관리" 코드 매칭 0 (팀 6/8)   │
│  ⚠ 면담 적체   D반 · 대기 최장 11일                           │
│  ○ 미배정      F반 담당 매니저 없음                           │
└──────────────────────────────────────────────────────────────┘

┌ 비용 ───────────────────────────────────────────────────────┐
│  이번 달 · 전월 대비 증감 (절대량 아님)                        │
└──────────────────────────────────────────────────────────────┘
```

**`조치 필요` 네 줄이 이 화면의 존재 이유다.**

| | 왜 오퍼레이터인가 |
|---|---|
| **집단 미달** | 반 절반이 한 개념에서 미달하면 **개인 문제가 아니다**(14번 9-6). 반 공지·재투입은 오퍼레이터 판단 |
| **개념 공백** | 코드 매칭 0이 팀 전반이면 **개념 선택이 프로젝트와 안 맞은 것**. 다음 회차에 교체할 사람이 오퍼레이터 |
| **면담 적체** | 매니저가 못 돌고 있다는 신호. 반 재배정·인원 조정은 오퍼레이터 |
| **미배정 반** | 조직 구조 문제 |

**반 비교를 순위표로 만들지 않는다.** 막대만 두고 숫자 등수를 붙이지 않는다 — **매니저 줄세우기가 되면 그 지표를 관리하려는 행동이 나온다.**

### 2-2. 분석 — 서브탭 2

| 탭 | |
|---|---|
| **위험·우수** | 프로젝트 회차 **필수 선택** · 기본 위험만 · 우수 토글 · 반 필터 |
| **히트맵** | 열 머리 2단(프로젝트/개념) · 행 = 기수→반→팀→개인 드릴다운 |

**셀·행 클릭 → 교육생 상세**(오퍼레이터는 메뉴가 없고 여기로만 닿는다).

### 2-3. 프로젝트 — 목록 → 상세 탭 3

**목록**: 회차 · 유형(미프/빅프) · 교안 · **질문에 쓸 항목 3건** · 제출 마감 · 상태. `[+ 프로젝트 생성]` 모달.

| 탭 | 내용 |
|---|---|
| **구성** | 교안 연결(**1개 이상**) · **질문에 쓸 항목 3건**(연결한 교안들의 `teaches`에서 선택 · 출처 교안·섹션 표시) · 요구사항(줄 단위) |
| **일정** | 제출 마감 · 분석 완료 → 응시 창 24h · 재시험 창 |
| **현황** | 반별 제출·응시율 · **코드 매칭 0인 개념 경고** |

> **`현황` 탭이 오퍼레이터에게 필요한 이유:** 팀 전원에서 같은 개념이 비면 **학생 문제가 아니라 개념 선택이 프로젝트와 안 맞았다는 신호**다. 다음 회차에 교체할 사람이 오퍼레이터다.

### 2-4. 리포트 — 마스터-디테일

```
좌 목차                     우 본문
─────────────              ──────────────────────
기수 종합                   선택한 섹션 하나
  개념별 도달 분포
  반 비교
  집단 미달
개인 최종                   ← 개인 선택 시 그 사람 최종 리포트
```

**섹션 전환이지 스크롤이 아니다.**

**분석과 겹치는 것처럼 보이지만 상태가 다르다.**

| | |
|---|---|
| 분석 | **실시간 탐색** — 드릴다운·필터·지금 값 |
| 리포트 | **고정 시점 스냅샷** — 기수 말 1회 · 외부 제출용 |

**리포트 본문은 분석 컴포넌트를 재사용한다.** 반 비교·집단 미달을 새로 그리지 않고 **그 시점 값으로 얼린 것**을 넣는다.

### 2-5. 운영 관리 — 탭 5

| 탭 | 내용 | 특이 |
|---|---|---|
| **기수** | 목록 · 생성 · 종료 | |
| **반·명단** | 반 목록 + 명단 · **[배정] → 모드** | 좌 반 레일 + 우 미배정 명단, 반복 배정 |
| **매니저** | 초대 · 반 배정 · 정지 | |
| **교안** | 목록 · 등록 · 재분석 · **가르친 항목** | 3-2 |
| **비용** | 기관 총량 + 기수/반 | |

**`반·명단`을 한 탭으로 합친다.** 반을 만드는 것과 명단을 넣는 것은 **한 흐름**인데 탭이 갈려 있으면 오간다. 배정은 표가 아니라 **작업이라 모드로 연다**.

#### 교안 탭 (오퍼레이터 쪽)

```
교안 목록  →  교안 상세 — 탭 2
              ├ 섹션            좌 섹션 목록 → 우 가르친 항목(이름·정의·페이지)
              └ 연결된 프로젝트   이 교안을 쓰는 회차 · 안전장치
```

## 3. 매니저 — 5 nav

### 3-1. 대시보드 — 인박스

**매니저 스코프는 25명이다. 이 규모에서 집계는 정보를 거의 주지 않는다** — 평균·추이를 볼 바에 명단을 본다.

> ### 매니저 대시보드는 지표판이 아니라 **오늘 할 일 목록**이다.

**카드 그리드를 쓰지 않는 이유:** 매니저의 질문은 *"무엇이 얼마인가"*가 아니라 *"누구부터인가"*다. 카드는 여러 상자를 훑어 사용자가 직접 순서를 합성하게 만든다. **단일 정렬 목록은 순서를 그냥 준다.**

```
미프 3차 · 제출 23/25 · 응시 19/23 · 리포트 발행 전     ← 한 줄. KPI 카드 아님

오늘 할 일  6                             지난 방문 이후 ▾

  ⏳ 미응시     최OO   응시 창 D-3h                       [독촉]
  ⏳ 재시험     정OO   마감 내일                          [독촉]
  ⚠ 무효 응시   박OO   미프 3차 Q2 · 질문 복붙            [세션 확인]
  ✎ 이의제기    한OO   미프 2차                           [검토]
  ● 면담        김OO   지속 저점 2/3 · 대기 6일           [브리프]
  ● 면담        이OO   단계 하락 0/3 → 2/3 · 대기 2일     [브리프]

  ─ 처리됨 3 ▾
```

**정렬 = 마감이 있는 것부터**

| 순위 | | 왜 |
|---|---|---|
| **1** | 창이 닫히기 직전 (응시 D-3h · 재시험 D-1) | **지나면 복구가 안 된다** |
| **2** | 확인해야 판정이 확정되는 것 (무효 응시 · 이의제기) | 방치하면 잘못된 판정이 굳는다 |
| **3** | 면담 대기 (오래된 순) | 오늘 못 하면 내일 해도 된다 |
| **4** | 미제출 | 〃 |

**"지난 방문 이후"가 기본 필터다.** 매일 열면 대부분 같은 화면인데, **델타가 없으면 훑지 않게 된다.**

**행에서 바로 처리한다.** 대시보드를 거쳐 다른 화면에 가서 다시 찾는 동선을 만들지 않는다 — `[브리프]`는 브리프 모드를 바로 열고, `[독촉]`은 그 자리에서 발송한다.

### 3-2. 히트맵 — 단일 뷰

**위험·우수 테이블은 매니저에게 없다**(17번 5절) — 위험은 `면담`이, 오늘 것은 대시보드가 담는다. 남는 것은 히트맵 하나이므로 메뉴 이름도 `히트맵`이다.

```
        │      미프 2차       │      미프 3차       │
        │ Service Deploy Conf │ HITL  Graph  State  │
────────┼─────────────────────┼─────────────────────┤
 A팀    │  3.2    2.8    3.5  │  2.1   3.0    2.4   │
  김OO  │  3      2      4    │  2      ―     2     │
  이OO  │  4      3      3    │  2     3      3     │
 B팀    │ …
```

| | |
|---|---|
| 행 | **반 → 팀 → 개인** (매니저 스코프는 반에서 시작) |
| 열 | 프로젝트 / 개념 2단 · 프로젝트 단위 접기 |
| 셀 | 평균 도달 단계 · `―` = 코드 매칭 0(0단과 다른 색) |
| 클릭 | 개인 행 → 교육생 상세 |

**25명 × 개념이면 반 전체 패턴이 한 화면에 들어온다.** 집단 미달(한 열이 통째로 낮음)이 여기서 눈으로 보인다.

### 3-3. 면담 — 목록 → **브리프(모드)**

**목록**

| | |
|---|---|
| 헤더 | `면담` + 예정 4·후속 2·종결 9 |
| 툴바 | **프로젝트 회차** · 상태 · 검색 — 전부 좌 |
| 경고 | **대기 최장 6일** |
| 행 | 이름 · 위험 유형 배지 · `2단미달 2/3` 또는 `0/3 → 2/3` · 대기 일수 · **[브리프 열기]** |

**브리프(모드)** — 전체화면 · 사이드바 가림 · 저장하면 목록으로.

```
[코드 이야기는 하지 마세요. 왜 막혔는지만 들으세요]

① 이렇게 여세요      중립 문구 · 막힌 개념 이름
② 이것만 물어보세요   개방형 질문 4
③ 체크               원인 7개 (학생과 함께)
④ 여기로 보내세요     ③을 고르면 목적지가 뜬다
─────────────────────────────────────
기록 3칸                              [저장]
```

**하단 좌측에 `전체 이력 ↗`** — 교육생 상세로 나가는 유일한 링크.

### 3-4. 교육생 — 명부 → 상세(타임라인)

**명부**: 이름 · 반·팀 · 최근 도달 · `2단미달 n/3` · **위험 / 우수 배지** · 즐겨찾기(개인 북마크). 정렬에 **우수**가 들어간다 — 우수는 면담 대상이 아니고 **팀을 짤 때 필요한 정보**라 명부가 제자리다(14번 9-3).

#### 상세 — 탭을 쓰지 않는다

```
김OO · A반 3팀                                      [지속 저점]

미프1 ███ ███ ██    미프2 ██ ███ █    미프3 █ ██ █   ← 히트맵 1행 재사용
──────────────────────────────────────────────────────
미프 3차
  7/12  세션 · 2단미달 2/3                        ▾ 문답 요약
  7/15  리포트 발행 · 재시험 2건

**왜 탭 3개(종합/세션/면담)를 버리나**

| | |
|---|---|
| **종합** | 격자는 **히트맵 개인 행과 같은 데이터**다. 개인까지 드릴다운한 히트맵 행이 이미 회차 × 개념이다 — 다시 그리면 복사가 된다 |
| **세션 · 면담** | 같은 시간축의 **이벤트 유형**일 뿐이다. 탭으로 가르면 "7/18 재시험이 7/21 면담보다 먼저"라는 **순서가 사라진다** |

**이 화면의 고유 가치는 격자가 아니라 시간축이다.** 히트맵은 도달 단계만 주고 **그 사이에 무슨 일이 있었는지**는 주지 않는다 — 재시험을 봤는지, 면담에서 뭐라고 했는지, 약속한 것을 했는지.

| 무엇을 | 어디서 |
|---|---|
| 격자 | **히트맵**(그 행을 헤더에 잘라 붙임) |
| 팀·반 비교 | **히트맵**(이웃 행) — 여기서 안 그린다 |
| **이벤트 이력** | **여기** |
| 문답 원문 요약 | 여기(이벤트 펼침) |
| 면담 기록 3칸 | 여기(읽기) · 쓰기는 브리프 |

**필터는 탭이 아니라 우하단 토글**이다. 기본 `전체`이고, 순서를 깨지 않으면서 유형만 걸러낸다.

**귀속 탭은 삭제한다**(미프는 기여도를 쓰지 않는다).

### 3-5. 프로젝트 — 목록 → 상세 탭 3

**목록**: 오퍼레이터와 같은 목록, 담당 반 범위. **생성 버튼 없음.**

| 탭 | 내용 |
|---|---|
| **팀** | 팀 편성 · 자동 배분 · 팀 추가 |
| **제출 현황** | 학생별 제출·분석·응시 상태 · **[벌크 독촉]** 모달 |
| **결과** | 개념별 반 평균 · **리포트**(반 종합 / 개인) · 발행 상태 · 재시험 진행 |

**`결과` 탭이 리포트를 겸한다.** 리포트는 **항상 어느 회차의 리포트**라 독립 메뉴로 두면 들어갈 때마다 회차부터 고르게 된다(17번 5절). 좌 목차(반 종합 / 개인 25명) → 우 본문의 마스터-디테일이고, **숫자 점수는 어디에도 없다.**

**`구성` 탭이 없다** — 교안·질문 항목·요구사항은 오퍼레이터가 정한다. **읽기만 필요하면 상세 헤더에 한 줄로 띄운다.**

```
미프 3차 · 교안 AI_LLMOps · 질문 항목 HITL 실행 흐름 · Supervisor 역할 분리 · Snapshot 구성
```

```
이번 회차 카드
  미제출        → [코드 제출]        화면

| 진입 | 뷰 |

| 검증 세션 | **모드** — 전체화면 · 이탈 감지 · 나브 없음 |

### 4-2. 내 리포트 — 마스터-디테일

```
좌 회차 목록              우 본문
────────────             ─────────────────────
미프 3차  ●              개념별 도달 상태 + 서술
  1차 / 재시험 나란히      막힌 단계 해설
미프 2차                  교안 위치
미프 1차                  [문답 보기] → 아카이브
```

**문답 아카이브는 같은 화면의 토글**이다. 별도 메뉴로 빼지 않는다.

**히트맵·점수·다른 학생 정보는 없다.**

| 교육생 | 4 | 홈 · 제출 · **세션** · 내 리포트 |

**모드 3개** — 검증 세션 · 면담 브리프 · 반 배정.
**탭을 안 쓰는 상세 하나** — 교육생 상세(타임라인 + 유형 필터).
**뷰어 1개** — 교안 개념 상세(매니저용, 링크로만).

> 매니저 8은 목록+상세를 각각 센 값이다. 목업 파일로는 목록·상세가 한 장에 들어가는 경우가 많아 **5~6장**이다.
>
> **nav는 5개인데 라우트는 8개다.** 브리프(모드)·교육생 상세·프로젝트 상세가 메뉴 없이 진입하기 때문이다 — 17번 4절의 결과다.
