슈퍼어드민 플랫폼 콘솔 — 기관 · 플랫폼 설정

v1 콘솔 셸을 그대로 쓴다. 지표 카드 · 예산 바 · 저장량 구성 · 설정 행 패턴이 전부 유지되고, 바뀐 것은 IA와 호칭이다.

  • 나브가 3개에서 1개로 줄었다. `슈퍼어드민 관리`와 `설정`은 계정 몇 개와 단가 표라 화면이라기보다 설정 항목이다 — 우상단 톱니로 옮겨 탭 2개로 합쳤다.
  • `총괄 매니저` → `오퍼레이터`. 매니저가 한 종류뿐이라 "담당"이 붙을 이유가 없어졌다. 이 탭은 계정 관리이지 매니저 관리가 아니라서 v1이 읽기전용으로 보여주던 담당 매니저 목록을 뺐다 — 매니저는 기관 안에서 오퍼레이터가 초대한다.
  • 모델 · 단가가 새로 생겼다(SA-03). 채점 모델은 플랫폼이 고정하고 기관은 티어 이름만 고른다 — 모델이 단종돼도 기관 쪽에서 할 일이 없다.
  • 고아 기관을 만들지 않는다. 마지막 오퍼레이터 정지는 차단한다 — 기관에 들어갈 수 있는 사람이 아무도 없어진다.
케이스 계약 · SA-01 기관 목록 (구현 근거)
#상태에러코드 · API문구 · 다음 행동목업
—목록 · 요약GET /admin/orgs기관 표 + 요약 지표 4→ 행 클릭 → 상세#list
—기관 0—아직 등록된 기관이 없습니다 + 생성 유도→ 생성#empty
1중복 기관명ORG_NAME_TAKEN입력 중 ✗ + 이미 있는 기관명입니다 · 제출 버튼 비활성→ 이름 변경 — 제출 전에 막는다#dupname
3생성 실패 · 롤백ORG_CREATE_FAILED기관을 만들지 못했습니다 · 입력값 유지→ 재시도 — 아무것도 만들어지지 않는다#createfail
· 중복 기관명은 제출 전에 막는다. 생성 모달이 "실시간 중복 확인"이라고 써 놓고 ✗ 화면이 없었다 — 눌러 보고 실패하면 그때까지 입력한 것이 헛일이 된다.
· 생성 실패는 아무것도 남기지 않는다. 활성 · 오퍼레이터 미배정이 정상 흐름이라 반쯤 만들어진 기관이 목록에 있으면 정상인지 실패인지 구분되지 않는다.
· 정지 기관을 숨기지 않는다. 숨기면 "우리 기관이 안 보인다"는 문의에 정지인지 삭제인지 화면으로 확인할 방법이 없다.
· 왜 그렇게 정했는지는 정의 문서에 있다.
케이스 계약 · SA-02 기관 상세 (구현 근거)
#상태에러코드 · API문구 · 다음 행동목업
오퍼레이터 — 슈퍼어드민은 첫 한 명만 넣는다
—오퍼레이터 0—오퍼레이터가 없어 이 기관은 아직 시작되지 않았습니다→ 초대 — 이 목록의 핵심 신호#noop
2·N1이메일 형식 · 중복 · 도메인 밖INVALID_EMAIL
ALREADY_INVITED
DOMAIN_NOT_ALLOWED		모달 필드 하단 · 제출 전 차단→ 재입력 — 기관 도메인 밖 주소는 초대할 수 없다#invite
4·5초대 메일 실패 · 토큰 생성 실패INVITE_MAIL_FAILED
INVITE_TOKEN_FAILED		지정됐지만 초대 메일이 나가지 않았습니다 + [재발송]→ 재발송 — 자리는 지우지 않는다(중복 초대와 재시도를 구분하려고)#mailfail
N2마지막 오퍼레이터 정지LAST_OPERATOR차단 — 정지할 수 없다고 말한다→ 다른 오퍼레이터를 먼저 초대 — 고아 기관 방지#lastblock
사용량 · 설정
6사용량 집계 실패USAGE_UNAVAILABLE사용량을 불러오지 못했습니다 · 이 영역만 실패, 기관 정보는 그대로→ 재조회 — 0으로 보여주지 않는다#usagefail
—기관 정지PATCH /admin/orgs/{id}소속 전원 로그인 차단 · 데이터는 보존→ 설정 탭#settings
기관 삭제
7기관 삭제 요청DELETE /admin/orgs/{id}확인 모달 — 기관명을 입력해야 삭제된다 · 즉시 파기 아님→ soft-delete · 보존기간(180일) 경과 후 파기 · 그전까지 복구 가능#deleteconfirm
8보존기간 경과 전 파기 요청RETENTION_NOT_MET차단 — 보존기간이 남아 파기할 수 없다고 말한다→ 대기 · 그림 없음(운영자가 API로 요청하는 경로)—
· 집계 실패를 0으로 보여주지 않는다. 안 쓴 것과 못 읽은 것은 다르다 — 0으로 그리면 청구액이 실제보다 작아 보인다.
· 실패는 그 영역만 막는다. 사용량 하나 때문에 화면 전체를 에러로 덮으면 지원 업무가 멈춘다.
· 초대 메일이 실패해도 자리를 지우지 않는다. 지우면 같은 주소로 다시 초대했을 때 중복 초대인지 재시도인지 구분되지 않는다.
· 마지막 오퍼레이터는 정지할 수 없다. 기관에 들어갈 수 있는 사람이 아무도 없어진다.
· 삭제는 즉시 파기가 아니다. 보존기간이 지나야 지워지고 그전까지 복구할 수 있다 — 계약 종료만 하려면 정지로 충분하다.
· 왜 그렇게 정했는지는 정의 문서에 있다.
케이스 계약 · SA-03 플랫폼 설정 (구현 근거)
#상태에러코드 · API문구 · 다음 행동목업
—채점 모델 변경—확인 모달 — 전 기관 재캘리브레이션→ 확정 시 버전이 다른 결과끼리 비교를 막는다#modelchange
—단가 미입력—비용 화면에 단가 미설정 · 금액에 합산하지 않는다→ 단가 입력 — 0으로 계산하면 청구액이 작아 보인다#nopricing
—마지막 슈퍼어드민 정지LAST_SUPERADMIN차단→ —#accounts
그림 없음
N3권한 없는 접근403슈퍼어드민이 아니면 콘솔 자체에 닿지 않는다→ 로그인 — 서버가 초기 화면을 정한다—
· 단가 미입력을 0으로 계산하지 않는다. 0으로 합산하면 청구액이 실제보다 작아 보이고, 그 화면을 보고 예산이 남았다고 판단하면 틀린 결정이 쌓인다 — SA-02의 집계 실패와 같은 원칙이다.
· 채점 모델 변경은 되돌릴 수 없다고 먼저 말한다. 전 기관 재캘리브레이션이 필요하고 버전이 다른 결과끼리는 비교가 성립하지 않는다.
· 마지막 슈퍼어드민은 정지할 수 없다. 풀어 줄 상위 권한이 아예 없어 기관보다 더 치명적이다.
· 왜 그렇게 정했는지는 정의 문서에 있다.
