# 백엔드 API — 40차 요청 · 마지막 질문이라고 잘못 알려줍니다

> **37차·39차를 반영해 주셔서 감사합니다.** 답변 채점이 90초 끊김에서 **4.5~8초**로
> 돌아왔고, `problemTimeLimitAt`·`teachLabel`·`sourcePages`가 신설됐고, 관찰 신호가
> `voidEvidence`로 되돌아오게 됐습니다.
>
> **그 덕에 세션을 처음으로 끝까지 돌려 봤습니다** — 3문제 · 12질문 · 자동 힌트 · 문제
> 접힘 · 세션 종료까지 전 구간을 실데이터로 확인했습니다. 아래는 그 과정에서 나온
> 것들입니다.

## 1. 🔴 R1 — 마지막이 아닌데 마지막이라고 합니다

### 무엇이 일어났나

`e036@green.com`(문제 3개)으로 **문제 1**을 풀던 중입니다.

```
GET /problems/1  →  current.sequenceNo: 4 · lastTurnOfSession: true
                     ↑ 문제 1의 마지막 질문(L4)일 뿐, 세션은 2·3번이 남아 있습니다
```

화면은 이 값을 **세션의 마지막 답변**으로 읽어 이렇게 그립니다(스펙대로).

```
버튼    답변 제출하고 마치기
안내    마지막 답변이에요 · 제출하면 끝납니다
```

**그런데 제출했더니 `NEXT_PROBLEM`이 왔고 문제 2로 넘어갔습니다.**

### 왜 문제인가

학생 입장에서 **"이제 끝이다"와 "아직 3분의 1이다"는 완전히 다른 상황**입니다.

- 끝나는 줄 알고 남은 힘을 다 쏟았는데 두 문제가 더 남아 있습니다
- 반대로 **진짜 마지막**에 이 신호가 안 오면 준비 없이 세션이 끝납니다

실제로 마지막 문제의 마지막 질문에서도 같은 값이 오는지는 확인하지 못했습니다 —
어느 쪽이든 **지금은 이 필드로 마지막을 가릴 수 없습니다.**

### 스펙과 다릅니다

| | |
|---|---|
| 스펙 | *"이 답변이 세션의 마지막인지. 버튼 문구가 `답변 제출하고 마치기`로 바뀐다"* |
| 실제 | **문제의 마지막 질문**마다 `true` |

### 저희가 못 고칩니다

`problemNo === problemTotal`을 함께 보면 유추할 수는 있습니다. 하지만 그러면

- **"세션이 언제 끝나는가"를 화면이 다시 판정**하게 됩니다. 그 규칙이 서버와 두 벌이
  되고, 한쪽이 바뀌면 반드시 어긋납니다
- 이 API를 만드신 이유(*"진행 위치는 서버 커서가 정본"*)와도 정면으로 어긋납니다

**서버가 세션 기준으로 판정해 주시는 것이 맞다고 봅니다.**

> 만약 이 필드의 뜻이 *"이 문제의 마지막 질문"* 이라면 이름과 설명을 그렇게 고쳐 주세요.
> 그러면 저희는 **문제 경계 안내**로 쓰고, 세션 마지막은 다른 방법을 찾겠습니다.

## 2. 🟡 R2 — 무효 처리 경로가 아직 닫혀 있습니다

39차 R2를 반영해 주셔서 **관찰 신호가 매니저에게 돌아오게** 됐습니다.

```
VoidEvidenceResponse
  windowLeaveCount · connectionLossCount · firstKeystrokeDelayMs   ← 신설 감사합니다
  unanswered · totalQuestions · copied · durationMin
```

이제 사슬에서 **마지막 칸 하나**가 남았습니다.

```
학생 이탈 → POST /activity ✅ → 서버 저장 ✅ → 매니저가 봄 ✅ → 무효 처리 🔴 사용 불가
```

`PATCH /api/v0/assessment-attempts/{attemptId}/validity`가 열려야 매니저가 실제로 조치할
수 있습니다. **저희 쪽 자리는 이미 있습니다**(면담 케이스가 `attemptId`·`voidReviewPending`·
`voidConfirmed`를 주고 있고 화면 타입에도 들어와 있습니다).

**언제쯤 열릴지만 알려 주세요.** 그 전까지는 무효 확인 UI를 만들지 않겠습니다 — 누르면
안 되는 버튼을 먼저 만들면 고장으로 보입니다.

## 3. 🟡 R3 — `references`가 비어 옵니다

39차 R4로 `Reference.path`를 nullable로 고쳐 주시고 **`teachLabel`·`sourcePages`도
신설**해 주셨는데, **정작 배열 자체가 비어 옵니다.**

```
GET /problems/1  →  code.references: []
```

`s002@algohouse.io`(문제 3개)에서 확인했습니다. 어제 `e036`에서는 넷이 왔는데
(`CURRICULUM_EVIDENCE` 1 + `CALLER` 3) 지금은 하나도 없습니다.

**두 가지를 여쭙습니다.**

**① 언제 채워지나요** — 분석 시점에 만들어지는 값이라면, 최근에 분석된 계정에서만
나오는 것인지 알고 싶습니다.

**② `teachLabel`·`sourcePages`를 어디에 그리면 되나요** — 지금 화면은 `CALLER`만
호출부 패널에 쓰고 `CURRICULUM_EVIDENCE`는 버리고 있습니다. 교안 라벨과 페이지가
채워진다면 **세션 중에 보여줘야 하는 값인지**, 아니면 리포트 전용인지 판단이 필요합니다.

> 응시 중에 교안을 알려주면 **답을 찾아보게 될 수 있어** 저희 판단으로는 리포트 쪽이
> 맞아 보입니다. 다만 그 필드가 세션 응답에 들어온 이유가 있을 것 같아 여쭙습니다.

## 4. ❓ Q1 — 문제당 20분이 질문 수와 무관하게 고정입니까

실측입니다.

```
문제 1 시작   14:05:40   problemTimeLimitAt 14:25:40   (20분)
  질문 1 통과 → 질문 2 → 질문 3 → 질문 4        ← 상한은 14:25:40 그대로
문제 2 시작   14:23:40   problemTimeLimitAt 14:43:40   (새로 20분)
```

**질문이 하나든 넷이든 20분**입니다. 4단계까지 간 학생은 같은 20분 안에 네 번 답해야
하고, **잘 답할수록 시간이 빠듯해집니다.** L4는 가장 어려운 질문인데 앞선 셋을 통과하느라
시간을 다 쓴 상태에서 만납니다.

의도된 설계라면 그대로 두겠습니다. 다만 **잘하는 학생이 불리해지는 구조**로 보여 확인을
부탁드립니다.

## 5. 확인한 것 ✅ — 세션 전 구간이 처음으로 돌았습니다

37차·39차 반영 덕분에 **되돌릴 수 없는 구간까지 전부** 밟아 봤습니다.

```
문제 1   L1 → L2 → L3 → L4 완주 → NEXT_PROBLEM
문제 2   나쁜 답 ×3 → 자동 힌트 ×2 → PROBLEM_CLOSED
문제 3   나쁜 답 ×3 → SESSION_ENDED
```

| | 결과 |
|---|---|
| **답변 채점** | ✅ **4.5~8.2초** (전에는 90초 끊김) |
| `problemTimeLimitAt` | ✅ 받아서 문제별 카운트다운을 되살렸습니다 |
| **자동 힌트** | ✅ 미달이면 응답에 실려 옵니다 · 화면이 `POST /hints`를 **또 부르지 않습니다** |
| **힌트 초기화** | ✅ 질문이 바뀌면 다시 2개 |
| **문제 접힘** | ✅ `PROBLEM_CLOSED` → *"이 문제는 여기까지 볼게요"* |
| **문제 전환** | ✅ 다음 문제 이름·파일까지 정확합니다 |
| **세션 종료** | ✅ `SESSION_ENDED` |
| **다시 보기 힌트** | ✅ 스펙 문구가 *"다시 보기도 1차와 같다(2회)"* 로 바뀐 것을 확인했습니다 |

### 저희가 함께 고친 것

실데이터를 보고서야 드러난 것들입니다.

| 무엇 | 무엇이 문제였나 |
|---|---|
| 종료 화면 | 마지막 답변이 성공하면 조회가 무효화돼 `204`가 오고, **「세션 없음」이 종료 화면을 덮었습니다** |
| 힌트 로딩 | 요청이 끝나는 순간 로딩이 꺼져 **화면이 비었다가 답이 튀어나왔습니다** |
| 축 이름 | `코드 이해`·`대안 비교` 같은 라벨이 **무엇을 답할지 알려주는 힌트**여서 `질문 N`으로 바꿨습니다 |
