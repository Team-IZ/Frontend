# MG-09 교안 — 상황 기록

실계정(이담 · 매니저 · 9기 C반)으로 목록과 `Spring 백엔드 설계`
(`2e390105-f94c-78ad-7e64-9598805b02ff`) 상세를 띄워 확인했다.

## 붙인 것

| 화면 | 오퍼레이션 | 확인 |
|---|---|---|
| 목록 | `findCohortLinkedCurricula` | ✅ 교안 2개 |
| 상세 머리글 | `findCurriculum` | ✅ 제목·v1·분석 완료·7섹션·120쪽 |
| 섹션 탭 | `findSections` | ✅ 7섹션 · 가르친 항목 7개 |
| 쓰인 회차 탭 | `findUsedProjects` | ✅ 26회차(7기~10기) |

목록 조회는 **30차 Q2로 새로 생긴 것**이다 — 그전에는 이 목록을 주는 API가 없어
기수 회차 수만큼 상세를 불러야 했다.

## 렌더에서 잡은 것 — **둘 다 "실데이터가 목보다 훨씬 크다"가 원인이다**

### 🔴 목록의 `쓰인 회차` 열이 표를 넘겼다
목은 회차 1~2개였는데 실데이터는 한 교안이 **회차 여덟 개 이상**에 걸린다. 이름을
전부 이으니 표가 컨테이너보다 넓어져 **오른쪽 `분석` 열이 통째로 잘렸다.**
앞 둘만 링크로 두고 나머지는 `외 N개`로 접었다(전체는 마우스 오버 · 상세 탭).

### 🔴 상세의 ★ 배지가 항목 이름을 덮었다
한 항목이 7기~10기 **열한 회차**의 검증 개념이라 배지가 두 줄로 깔렸다. 이 화면이
답하는 질문은 「가르친 것 중 무엇이 문항이 됐나」라 **쓰였다는 사실**이 먼저다 —
`★ 검증 개념 · 10개 회차` 하나로 접었다.

두 건 다 **목이 작은 데이터로만 그려져 안 보이던 것**이다. 스펙을 읽는 것만으로는
안 나오고 실응답을 그려야 나온다(integration-process §6).

## 목과 갈린 어휘

- **분석 상태가 4종 + `null`이다.** 목은 `DONE`·`FAILED` 둘뿐이었다. 서버는
  `PENDING·RUNNING·SUCCEEDED·FAILED`이고 **한 번도 분석하지 않은 교안은 값 자체가
  null**이다 — 스펙이 「실패와 구분해야 해서 값을 만들어 넣지 않는다」고 못박았다.
  목이었다면 미분석 교안이 "분석 실패"로 보였다
- **`definitionMissing`이 따로 온다.** 목은 `definition === null`로 판정하고 원인은
  `isSummary`로 갈랐다 — 두 사정이 한 필드에 겹쳐 있었다
- **`usedRoundLabels`가 배열이다.** 목 `verifiedAs`는 회차 하나만 담을 수 있어 한
  항목이 여러 회차에 쓰이면 버려야 했다(위 렌더 문제의 뿌리이기도 하다)
- **`쓰인 회차`에 다른 기수도 온다.** 교안 축 조회라 기수로 안 좁혀진다. 서버가
  `roundLabel`(기수 포함)과 `cohortName`을 함께 주는 이유가 그것이라 거르지 않는다 —
  다른 기수가 이 교안을 어떻게 쓰는지가 재분석 판단의 근거다
- **URL이 `materialId`다.** 상세 조회 셋이 전부 그 축을 받는다. `versionId`를 넣으면
  늘 빈 배열이 온다(13차 R1에서 실제로 겪은 사고)
- **분석 전 섹션 조회는 409다**(`CURRICULUM_ANALYSIS_NOT_COMPLETED`, 18차 R1).
  실패가 아니라 아직 안 끝난 것이라 **에러가 아니라 빈 상태**로 그리고 재시도도 끈다.
  목은 `sections === null` 하나로 실패·미분석을 같이 처리했다

## 목에서 뺀 것 — 서버에 자리가 없다

| 뺀 것 | 있던 자리 | 사정 |
|---|---|---|
| 섹션 수 | 목록 열 | 기수 연결 목록에 없다(상세에만). 행마다 상세를 부르면 이 조회가 없애려던 모양 그대로다 |
| `개념 3` 순번 | ★ 배지 | 회차 안 몇 번째인지가 오지 않는다 |
| `응시 58/71` | 쓰인 회차 열 | `attendedCount`(분자)만 온다 — 분모가 없어 비율을 못 만든다 |
| 결과(발행 완료·발행 전·예정) | 쓰인 회차 열 | 회차 조회에 아예 없다 |

전부 32차 요청서로 올린다.

## 🔴 버전 축이 둘이다 — 32차 질문

목록(`CohortCurriculumResponse`)은 **이 기수가 연결한 버전**(`versionId`·`versionNo`)을
주는데, 상세 조회 셋은 `materialId`를 받아 **최신 버전**으로 해석한다(스펙 명시).
둘이 다르면 목록 행과 상세 화면이 서로 다른 버전을 말한다. 화면이 고를 수 있는
문제가 아니다.

지금 데이터로는 둘 다 v1이라 드러나지 않았다.

## 미검증

- **분석 전(`null`)·분석 중·분석 실패 교안** — 이 기수 교안 둘 다 `SUCCEEDED`다.
  `분석 전`·`분석 중`·`분석 실패` 배지와 409 빈 상태를 못 봤다
- **섹션이 0개인 교안** — 빈 상태 분기 미확인
- **정의문 미추출 항목**(`definitionMissing: true`) — 본 항목은 전부 정의문이 있었다
- **버전이 갈린 교안**(위 32차 질문) — 대조군이 없다

### 🔴 없는 `materialId`는 404가 아니라 매달린다

**상관이 완전하다.**

```
존재하는 UUID   → 200, 2.3초
없는 UUID (2건) → 무응답, 65초까지 기다려도 답 없음
형식 오류 문자열 → 400, 1.7초
```

형식이 틀리면 400을 제대로 내는데, **형식은 맞고 없는 ID면 매단다.** 지워진 교안
링크를 열면 예산(90초)이 끝날 때까지 화면이 스피너만 돈다 — 실제로 60초 동안 문구
한 줄 없었다.

**고침** — `SlowNotice`를 붙였다(13초에 「주소가 맞는지 확인해 주세요」). 끊지는
않는다: 잠든 서버는 깨는 데 76초라 끊으면 정상 요청을 죽인다.

**같은 일이 회차에서 이미 있었다**(18차 R7 — `Loading.tsx` 주석에 적혀 있다).
교안에서 재발했으므로 32차로 올린다.

**훑었더니 매니저 화면 14곳에 `SlowNotice`가 하나도 없었다**(오퍼레이터는 4곳에서
쓴다). 이번엔 교안 둘만 붙였다 — 나머지는 화면별 하드닝에서 함께 한다.

### 🔴 5xx가 무한 재시도였다

`useSections`가 409만 걸러내려고 `retry: (_count, error) => !isAnalysisIncomplete(error)`
를 줬는데, **`count`를 안 봐서 전역 정책을 통째로 덮었다.** 500을 가로채니 재시도가
6회를 세고도 안 멈췄다.

`main.tsx`가 이미 「5xx·네트워크만 3회, 타임아웃은 안 함」을 정해 뒀다 — 그 판단을
여기서 다시 만들지 않고 그대로 곱한다. 고친 뒤 **정확히 4회**(첫 시도 + 3)에서 멈춘다.

### 🔴 서버 오류를 교안 탓으로 말했다

500일 때 화면이 「구조를 추출하지 못했습니다 · **재분석은 오퍼레이터가 진행합니다**」
라고 했다. 서버가 실패한 것을 **교안 분석이 실패한 것으로** 옮겨 읽히고, 매니저가
오퍼레이터에게 없는 재분석을 요청하게 된다.

`lib/errorCopy`로 바꿨다 → 「섹션을 불러오지 못했습니다 · 잠시 후 다시 시도해 주세요」.

### ⚠ 목록은 8회차, 상세 배지는 26

같은 교안인데 숫자가 3배로 뛴다. 둘 다 맞다 — 목록은 **이 기수가 연결한** 회차,
상세는 **이 교안을 쓴 모든 기수**의 회차다(교안 축 조회라 기수로 안 좁혀진다).
화면이 그 말을 안 해서 어느 쪽이 틀린 것처럼 보였다 — 쓰인 회차 탭에 한 줄 붙였다.

### 가로채기 — 먹었는지부터 확인했다

처음엔 탭을 왕복시켜 재조회를 노렸는데 **캐시라 요청이 안 나갔고**, 화면이 정상
데이터를 그대로 그렸다. 그걸 보고 「빈 상태 처리 잘 돼 있음」이라고 적을 뻔했다
(문서 §2 경고 그대로). 다른 교안으로 이동해 새 쿼리 키를 만들고, **발동 횟수를 세서**
확인한 뒤에 판정했다.

| 만든 상태 | 발동 | 화면이 한 말 | 판정 |
|---|---|---|---|
| `409 CURRICULUM_ANALYSIS_NOT_COMPLETED` | 1 | 「분석이 아직 끝나지 않았습니다」 | ✅ |
| `sections: []` | 1 | 「섹션이 없습니다 · 분석이 구조를 하나도 만들지 못했습니다」 | ✅ |
| `500` | 4 | 「섹션을 불러오지 못했습니다」 | ✅ (고친 뒤) |

⚠ **발동이 5로 보일 때가 있다 — 재시도가 아니다.** 목록에서 눌러 들어가며 재보니
타임스탬프가 `0 · 0 · 716 · 1765 · 3586ms`였다. 뒤 셋이 지수 백오프(3회)이고 **앞
둘이 같은 시각**이다 — `StrictMode`의 개발 모드 이중 마운트이며 프로덕션 빌드에는
없다. 재시도 정책 자체는 한 사슬당 **4회(첫 시도 + 3)**로 정확하다.

### 컨트롤 — 전수로 눌렀다

섹션 7개를 **하나씩 다** 눌러 오른쪽이 바뀌는 것을 확인했다(7/7). 탭 전환도 왕복했다.

**오측 하나** — 처음엔 `.flex-1`로 오른쪽 내용을 읽었는데 그게 컨테이너라 7개가 전부
같아 보였다. 「섹션 전환이 안 된다」로 적을 뻔했다. `h3`(가장 안쪽 제목)로 다시 재니
7개가 정확히 갈렸다(문서 §2 「측정 대상을 확인한다」).

**오측 둘** — 두 번째 교안의 `materialId`를 8자만 보고 지어내 썼다가 3개 조회가 전부
80초 타임아웃이 났다. 「이 교안이 고장났다」로 적을 뻔했다 — 실제 ID로는 정상이었고,
그 무응답이 위 §「없는 `materialId`」 발견의 출발점이 됐다.

### 관찰 — ★가 전부다

두 교안 모두 **가르친 항목 전부가 검증 개념**이다(7/7 · 2/2). 이 화면의 §4 메시지
「한 섹션이 가르친 것 9개 중 1개만 문항이 됐다」와 문구 「이 중 **일부**를 골라」가
지금 데이터에서는 대비를 못 보여준다. 섹션마다 항목이 1개씩이라 그렇다 — 화면 문제는
아니고, 항목이 많은 교안이 들어오면 다시 본다.

## 하드닝 2차 — 규칙 A~L 대조와 API 전수 (2026-08-18)

> 중간에 브라우저 도구(MCP)가 끊겨 한때 코드 대조만으로 적었다가, **`playwright-core`를
> 직접 띄워 5단계·5-2단계를 전부 다시 돌았다.** 아래는 렌더까지 확인한 것이다.

### 도구가 끊겨도 브라우저는 띄울 수 있다

MCP 플러그인이 사라졌을 때 「렌더 확인 불가」로 적고 넘어갔는데, **필요한 것이 다 로컬에
있었다.**

```
playwright-core   ~/.npm/_npx/<hash>/node_modules/playwright-core   (npx 캐시)
chromium          ~/Library/Caches/ms-playwright/chromium-1223/…/Google Chrome for Testing
```

`chromium.launch({ executablePath })`로 붙이면 그대로 돈다. **「도구가 없다」가 아니라
「도구를 안 찾아봤다」였다** — 규칙 G(「화면을 띄워 눌러 본다」)를 포기할 이유가 아니었다.

### 토큰을 스스로 얻는 법 — `Origin`이 필요하다

브라우저 없이 재려고 로그인부터 막혔다.

```
POST /auth/login                          → 403 LOGIN_ORIGIN_NOT_ALLOWED
POST /auth/login + Origin: localhost:5175 → 200 accessToken
```

문서 §2의 `curl` 예시에는 `Origin`이 없다 — 그대로 쓰면 403이다. 앞으로 이 레포에서
서버에 직접 물을 때는 `Origin`·`Referer`를 같이 보낸다.

### 고친 것 (하드닝 2차)

| | 무엇 | 규칙 |
|---|---|---|
| 1 | 🔴 **`쓰인 회차` 조회가 실패하면 「아직 없습니다」라고 했다** | I |
| 2 | 🔴 **늘 「1」 한 칸짜리 가짜 페이저** | E7 |
| 3 | 🔴 **`쓰인 회차` 순서가 `10기 → 9기 → 7기 → 8기`** | D |
| 4 | 스피너 4곳 → 스켈레톤 | E |
| 5 | `isPending` 조회 분기 3곳 → 값 유무 | E |
| 6 | 탭이 주소에 없었다 | J |
| 7 | 섹션 목록에 `aria-current` | 접근성 |

#### 1. 🔴 실패를 「아직 없다」로 그렸다

`쓰인 회차` 탭의 분기가 **`isPending`과 그 나머지** 둘뿐이었다.

```tsx
{used.isPending ? <스피너/> : <UsedRoundsTable rounds={used.data ?? []} />}
```

조회가 500이면 `used.data`가 `undefined`가 되고 `?? []`가 **빈 배열**로 만들어
「이 교안을 쓰는 회차가 아직 없습니다」가 뜬다. **26개 회차가 쓰고 있는 교안**인데
화면이 하나도 없다고 말한다.

이 표는 **재분석해도 되는지 판단하는 근거**다 — 「없다」로 읽히면 매니저가 마음 놓고
오퍼레이터에게 재분석을 요청하고, 그러면 이미 응시한 208명의 리포트가 어긋난다.

규칙 E의 `?? []` 금지와 규칙 I의 「「아직」과 「실패」는 다르다」가 **같은 한 줄에서
동시에** 깨져 있었다. `errorCopy`로 갈랐다.

#### 2. 🔴 누를 수 없는 페이저

파일 머리 주석은 **「페이지네이션이 없다. 응답이 배열 하나라 페이지 개념 자체가 없다」**
라고 적어 두고, 정작 UI는 이걸 그리고 있었다.

```tsx
<Pagination><PaginationItem><PaginationLink isActive>1</PaginationLink></PaginationItem></Pagination>
```

**주석과 코드가 반대말을 하고 있었다.** 눌러도 아무 일이 없고, 페이저 모양이라
「더 있을지도 모른다」고 거짓말한다(규칙 E7 — 누를 수 없는 컨트롤은 장식이다).
범위 개수 `1–2 / 2개`도 머리의 「2개」와 같은 말이라 함께 뺐다(규칙 D).

#### 3. 🔴 기수 순서에 규칙이 없다

`쓰인 회차` 26줄의 서버 순서다.

```
10기 1~6차 · 9기 1~8차 · 7기 1~6차 · 8기 1~6차
└──────────────────────┘
   최신순도 오래된 순도 아니다 — 기수 축만 흔들린다(안쪽 차수는 정렬돼 있다)
```

항목 배지의 회차 라벨도 같다.

```
["9기 미프 4차","7기 미프 5차","7기 미프 6차","8기 미프 5차",…]   ← 열네 개가 이 순서로 한 줄에
```

MG-08 팀 목록에서 한 판단과 같다 — **서버 판정을 뒤집는 게 아니라 표시 순서**라 경계
문제가 아니고, 정렬 파라미터도 없다. **최신 기수를 위로** 둔다(재분석 판단은 지금 도는
기수부터 본다).

##### 그러다 회귀를 하나 만들었다

라벨을 못 읽는 행을 「맨 뒤로」 보내려고 `Infinity`를 뒀는데, **기수가 내림차순**이라
그게 1등이 됐다.

```
✗ 깨짐 : 이름만 | 10기 미프 1차 | 9기 미프 2차     ← 맨 앞
○ 깨짐 : 10기 미프 1차 | 9기 미프 2차 | 이름만     ← -Infinity로 고침
```

문서 §「고친 것이 만든 회귀를 바로 다시 본다」 그대로다. **검산을 안 돌렸으면 못 봤다.**

##### 검산(재현 가능)

테스트 인프라가 없어(이 레포는 `src`에 테스트가 하나도 없다) 여기에 입출력을 남긴다.

```
정상    [7기 3차, 10기 2차, 9기 1차, 10기 1차, 8기 2차]
     → 10기 1차 | 10기 2차 | 9기 1차 | 8기 2차 | 7기 3차
깨짐    [9기 2차, (라벨 없음), 10기 1차]      → 10기 1차 | 9기 2차 | (라벨 없음)
전부깨짐 [A, B]                              → A | B          (원래 순서 유지)
차수없음 [9기 특강, 9기 미프 1차]              → 9기 미프 1차 | 9기 특강
```

#### 4·5. 스켈레톤 — 차용값으로 뒀다가 **실측해서 두 번 고쳤다**

처음엔 MG-08 값을 빌려 썼는데, 재 보니 **둘 다 틀렸다.**

```
목록  행 53 → 42.7   푸터 28 → 0(페이저를 뺐으니)   진입 튐 −101px → −42px
상세  틀 h-[36rem] 고정 → max-h + 항목 53.7          섹션 도착 튐 −185px → 0px
```

**상세 쪽이 더 큰 실수였다** — 실제 틀은 `max-h`라 내용에 맞춰 줄어드는데 내가 높이를
박아 182px 큰 스켈레톤을 만들었다. 좌 항목 수가 높이를 정하게 두니 저절로 맞았다.

목록에 **−42px가 남는다.** 이 목록은 페이지가 없어(응답이 배열 하나) 「페이지 크기와
맞춘다」는 기준을 쓸 자리가 없고, 9기는 2개인데 3으로 두었기 때문이다. 한 기수의 씨앗에
맞추면 다른 기수에서 더 크게 어긋나므로 **남은 오차로 둔다.**

#### 6. 탭 숫자는 **여기서는 남겼다**

규칙 E가 「탭 이름 옆 숫자를 두지 않는다」고 하는데 이 화면은 `섹션 7` · `쓰인 회차 26`을
유지했다. 금지하는 **이유**가 「조회가 도착해야 아는 값인데 탭 줄은 진입 즉시 그려져 폭이
튄다」인데, 이 둘은 **탭 줄을 그리는 것과 같은 응답**(`head`)에서 온다 — 탭 줄이
나타나는 순간 이미 확정이라 튈 구간이 없다.

MG-08은 배지가 **다른 세 조회**에서 와서 8·34·38px씩 튀었고 그래서 거기서는 뺐다.
**규칙을 글자가 아니라 이유로 적용한 자리**라 근거를 남긴다.

## 🔴 대비 — 세 화면 재서 **공용 배지에서 미달을 찾았다**

MG-05·06·08에서 세 번 미룬 것을 이번에 캔버스 픽셀로 쟀다(문서 §5-2 「눈으로 판단하지
않는다」). 195개 글자 중 **1건**이 걸렸다.

```
🔴 3.93:1  「7개 섹션 · 120쪽」  11px/600   <Badge variant="neutral">
```

토큰으로 확인하니 화면 하나의 문제가 아니었다.

```
fg-subtle on neutral-soft   3.93:1   🔴   ← Badge neutral이 쓰던 조합
fg-subtle on surface        5.05:1   ✅   ← 이 값이 정해진 기준
fg-muted  on neutral-soft   4.87:1   ✅   ← 옮긴 곳
```

`fg-subtle`은 **흰 면 기준으로 맞춘 값**이라(토큰 주석에 「SSOT는 3.14로 AA 미달 →
4.63(canvas 위)」이라고 적혀 있다) 회색 배지 면에서는 못 미친다. `Badge`의 `neutral`을
`fg-muted`로 옮겼다 — 이 배지는 「비활성·보류」라 원래도 강조 색이 아니라 **더 진해져도
뜻이 안 바뀐다.**

같은 조합이 `trainee/report`에도 하나 더 있어(`bg-neutral-soft` + `text-fg-subtle`)
함께 고쳤다.

### 🔴 가드에 구멍이 있었다

`check:design`이 대비를 보는데 **왜 이게 통과했나**를 봤다.

```
['primary','primary-soft'] ['danger','danger-soft'] ['warning','warning-soft']
['success','success-soft'] ['info','info-soft']
                                        ← `neutral-soft`만 짝이 없다
```

다른 `-soft` 배경은 전부 짝이 있는데 **회색만 빠져 있었다.** `['fg-muted','neutral-soft']`를
넣었다(21쌍 → 22쌍).

**일부러 되돌려서 잡히는지 확인했다**(문서 §L).

```
짝을 fg-subtle로 되돌림 → ✗ 대비 AA 미달 1건    ← 잡는다
원래대로               → ✓ 통과 (색 41개 · 대비 22쌍)
```

### 공용 파일을 건드렸다 — 회귀 확인

`components/ui/Badge.tsx`는 공유라 「추가만, 수정은 조율」이 원칙이다. **색만 진해지고
레이아웃이 안 바뀌는 한 줄**이라 고쳤고, 다른 화면을 다시 재서 회귀가 없는 것을 봤다.


**`neutral` 배지를 쓰는 파일이 8개**다(오퍼레이터·슈퍼어드민 포함) — 전부 읽기 쉬워지는
