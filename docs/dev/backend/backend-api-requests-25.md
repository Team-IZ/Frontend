## 1. 🟠 R1 — `status`에 값을 둘 보내면 절반만 옵니다

`GET /organizations/{organizationId}/curricula?status=…`

```
status=SUCCEEDED                200 ·  4건
status=FAILED                   200 ·  8건
status=SUCCEEDED&status=FAILED  200 ·  4건   ← 두 번째 값을 조용히 버립니다
status=PENDING,RUNNING          400
```

(2026-08-15 재측정 — 교안 13건 기준. 반복 파라미터가 **첫 값만 적용한 목록**을 200으로
줍니다.)

콤마 형식은 `400`으로 막으시는데, **반복 파라미터는 `200`에 첫 값만 적용한 목록**이
옵니다. 화면은 그것이 전부인 줄 알고 그립니다 — **없는 것을 없다고 말하게 됩니다.**

최소한 **반복 파라미터도 `400`으로** 맞춰 주시면 조용히 틀리지는 않습니다.

### 그런데 진짜 부탁은 **배열을 받아 주시는 것**입니다

저희 화면은 `PENDING`과 `RUNNING`을 **한 라벨(`분석 중`)로 묶어** 씁니다 — 운영자가
그 둘로 할 일이 같기 때문입니다(기다린다). 그런데 `status`가 값 하나라 **둘을 한 번에
못 거릅니다.**

그래서 지금 **필터에서 「분석 중」을 아예 뺐습니다.**

```
화면 머리   분석 완료 2 · 분석 중 1 · 실패 2 · 분석 전 2   = 7
상태 필터   전체 7 / 완료 2 / 분석 실패 2 / 분석 전 2      = 6
                                        ↑ 분석 중 1건을 고를 방법이 없습니다
```

선택지를 `PENDING`·`RUNNING` 둘로 늘리면 화면에 **똑같이 생긴 `분석 중`이 두 줄** 나와서,
사용자가 무엇이 다른지 알 수 없습니다. 그렇다고 한쪽만 보내면 절반만 나옵니다.

`status`가 배열(또는 위 반복 파라미터)을 제대로 받으면 필터를 되살립니다.

> 14차에 같은 요청을 드렸습니다. 그때는 「선택지가 두 줄로 보인다」가 이유였는데,
> 이번에 재보니 **반복 파라미터가 조용히 통과한다**는 것이 같이 나와서 다시 올립니다.

## 2. 🟠 R2 — 재분석에 「이미 진행 중」이 없습니다

`POST /api/v0/curricula/{materialId}/analyses`

스펙의 에러 코드가 **둘뿐**입니다.

```
ACCESS_DENIED · CURRICULUM_MATERIAL_NOT_FOUND · UNAUTHENTICATED
```

**분석이 `PENDING`·`RUNNING`인 교안에 다시 요청해도 `202`로 접수됩니다.**
즉 운영자가 「분석 중」 화면에서 버튼을 세 번 누르면 **AI 분석이 세 번 걸립니다.**

### 화면 쪽은 저희가 막아 뒀습니다 — 다만 잠그지는 못합니다

다이얼로그가 먼저 말하게 했습니다.

> 이 교안은 지금 분석 중입니다 — 다시 요청하면 **처음부터 다시** 분석합니다.
> 돌고 있는 것이 빨라지지는 않습니다. 오래 멈춰 있을 때만 누르세요.

**버튼을 잠그지는 않았습니다.** `PENDING`에서 오래 멈춰 있는 교안이 실제로 있어서
(지금 기관에 1건), 잠그면 그것을 풀 방법이 사라집니다 — 여기가 유일한 출구입니다.

### 부탁

**이미 진행 중이면 `409`에 코드 하나**를 주세요(예: `CURRICULUM_ANALYSIS_IN_PROGRESS`).
그러면 화면이 *"이미 돌고 있습니다"* 로 정확히 답하고, **중복 요청이 서버에서 막힙니다.**

강제로 다시 돌려야 하는 경우(멈춘 분석)를 위해 `?force=true` 같은 것이 있으면 저희가
확인을 한 번 더 받고 보내겠습니다. 없으면 **409만으로도 충분합니다** — 운영자에게
「기다리세요」라고 말할 근거가 생깁니다.

## 3. 🟡 R3 — 반 생성의 `CLASSROOM_NAME_TAKEN`이 **스펙에만 없습니다**(동작은 맞습니다)

> ⚠ **처음에 「서버가 안 준다」고 적었는데 틀렸습니다.** 다시 재보니 **서버는 제대로
> 줍니다** — 스펙에 안 적혀 있을 뿐입니다. 정정합니다.
>
> ```
> POST /cohorts/{id}/classrooms  {"name":"중복테스트반"}  → 201
> 같은 이름으로 한 번 더                                  → 409 CLASSROOM_NAME_TAKEN
>                                    "이미 존재하는 반 이름입니다: 중복테스트반"
> ```
>
> 남은 것은 **스펙과 동작이 다르다**는 것뿐입니다. 저희는 코드로 분기하게 고쳤고
> 화면은 이미 「같은 이름의 반이 이미 있습니다」로 정확히 말합니다.

같은 일을 하는 두 엔드포인트가 서로 다른 코드 목록을 갖고 있습니다.

| | 도메인 에러 코드 |
|---|---|
| `PATCH /cohorts/{id}/classrooms/{classroomId}` (수정) | `CLASSROOM_NAME_TAKEN` · `CLASSROOM_NOT_FOUND` · `CLASSROOM_UPDATE_EMPTY` |
| **`POST /cohorts/{id}/classrooms`** (생성) | **`COHORT_NOT_FOUND` 하나뿐** |

같은 기수 안에서 반 이름이 겹치면 안 된다는 규칙은 **생성에도 똑같이 적용**되는데,
그때 무엇이 오는지 스펙이 말하지 않습니다.

### 이것 때문에 화면이 원인을 지어내고 있었습니다

반 추가가 실패하면 저희 화면이 이렇게 말했습니다.

> 추가하지 못했습니다. **같은 이름의 반이 있는지 확인해 주세요.**

인증이 끊겼거나 네트워크가 죽어도 같은 말을 했습니다 — 분기할 근거가 없어서
**가장 그럴듯한 원인을 고정으로 띄운 것**입니다. 이번에 코드로 판정하게 고쳤고,
지금은 이렇게 갈립니다.

```
409 CLASSROOM_NAME_TAKEN  →  같은 이름의 반이 이미 있습니다
401                       →  다시 로그인해 주세요
500                       →  반을 추가하지 못했습니다 · 잠시 후 다시 시도해 주세요
```

**스펙의 에러 목록에 `CLASSROOM_NAME_TAKEN`을 적어 주시면** 됩니다 — 동작은 이미 맞으니
문서만 맞추는 일입니다. 저희는 스펙을 보고 분기 대상을 정하므로, 안 적혀 있으면
**다음 사람이 또 「없다」고 읽습니다.**

> 같은 모양이 하나 더 있습니다 — `PATCH /cohorts/{id}/classrooms/{classroomId}/managers`
> (담당 매니저 변경)에 `CLASSROOM_NOT_FOUND`만 있고 `MANAGER_NOT_FOUND`가 없습니다.
> 매니저 쪽(`PUT …/managers/{managerId}/classrooms`)에는 둘 다 있습니다. 급하지 않지만
> 같이 맞춰 주시면 좋겠습니다.

## 4. 🚨 R4 — 22차 R7·R6의 404가 **안 옵니다.** 그리고 「프록시 층」이 아닙니다

22차 회신에서 세 자리에 `COHORT_NOT_FOUND`(404)를, 회차 없는 프로젝트에
`PROJECT_ROUND_NOT_CREATED`(404)를 넣어 주셨습니다. **스펙에는 들어와 있습니다**
(`COHORT_NOT_FOUND` 54회 · `PROJECT_ROUND_NOT_CREATED` 3회 확인).

**그런데 실서버가 그 404를 주지 않고 매답니다.**

> **2026-08-14에 한 번 더 쟀고 그대로였습니다.** 배포가 그 사이에 있었더라도 이 자리는
> 안 바뀌었습니다 — 같은 시각 `대조 9기 목록`은 **200 · 2.5초**로 정상입니다.

```
대조 — 있는 것
  GET /cohorts/{9기}/projects                200 ·  2.1초
  GET /cohorts/{9기}                         200 ·  1.6초

없는 것 — 전부 무응답 (12초 상한 · 150초까지도 안 옴 · 응답 헤더 0줄)
  GET /cohorts/{없는id}/projects             ⚠
  GET /cohorts/{없는id}/curricula            ⚠
  GET /cohorts/{없는id}/classrooms           ⚠
  GET /cohorts/{없는id}/projects/current     ⚠
  GET /projects/{없는id}                     ⚠
  GET /projects/{없는id}/class-progress      ⚠
  GET /projects/{회차없는}/class-progress     ⚠
  GET /curricula/{없는id}                    ⚠
```

### 🔴 프록시 층이 아닙니다 — 근거 둘

**① 프록시는 기수가 있는지 모릅니다.**
`/cohorts/{있는id}/projects`와 `/cohorts/{없는id}/projects`는 **URL 모양이 같습니다.**
앞은 2초에 오고 뒤는 안 옵니다. 앞단이 갈라낼 수 있는 차이가 아닙니다.

**② 앱은 에러를 잘 답합니다 — DB 조회 전이면.**

| 요청 | 결과 |
|---|---|
| `GET /cohorts/not-a-uuid/projects` | **400 · 1.7초** |
| `GET /cohorts/{9기}/projects?status=BOGUS` | **400 · 0.9초** |
| 없는 반 경로 | **405 · 1.6초** |
| **「없다」가 DB에서 확인되어야 하는 조회** | **전부 무응답** |

형식 검증에서 나는 400은 1초에 돌아옵니다. **조회까지 가서 「없음」이 확정되는 경로에서만**
멈춥니다. 프록시가 끊는 것이라면 400도 못 돌아옵니다.

### `server` 헤더는 못 잡았습니다 — 그럴 것이 없습니다

*"다음 측정 때 응답 헤더의 `server` 값을 같이 잡아 주시면"* 이라고 하셨는데,
**무응답이라 헤더가 한 줄도 없습니다.** 그리고 **성공한 200 응답에도 `server` 헤더가
없습니다**(App Runner/프록시 어느 쪽도 안 싣습니다). 그래서 그 값으로는 못 가릅니다 —
대신 위의 **「형식 400은 오고 조회 404는 안 온다」** 대조를 근거로 드립니다.

### 부탁

`COHORT_NOT_FOUND`를 던지는 경로를 **로컬이나 스테이징에서 한 번만** 눌러 봐 주세요.
저희 추측은 **예외를 던지기 전에 무언가를 더 하고 있거나**(추가 조회 · 재시도),
**404 매핑이 배포에 안 실렸을** 가능성입니다. 스펙에는 있는데 동작이 안 따라오는 상태라
저희가 화면에서 확인할 방법이 없습니다.

> 22차 R6에서 *"`findRound`는 유니크 인덱스 한 방이고 회차가 없으면 즉시 404"* 라고
> 하셨는데, 실서버는 그 자리에서 150초를 넘겨도 응답이 없습니다. **코드와 배포된 것이
> 다를 수 있습니다.**

## 5. 🟡 R5 — `RECENT_ENROLLED`가 등록 안 한 사람을 맨 앞에 놓습니다

> 2026-08-15 재측정 — 앞 3행이 `강재진 · 강하연 · 권나찬`, 모두 `joinedAt: null`입니다.

`GET /cohorts/{id}/trainees?sort=RECENT_ENROLLED`

```
장서준   joinedAt=null   INVITED
이주원   joinedAt=null   INVITED
안예은   joinedAt=null   INVITED
…앞 8행이 전부 joinedAt=null
```

`joinedAt`이 `null`인 행(**초대 수락 전**)이 위로 옵니다. 화면의 등록일 열은 그때 `—`라,
**「최근 등록순」을 골랐는데 등록일이 없는 사람들이 맨 위에 쌓입니다.**

**`null`을 뒤로 보내 주시면 좋겠습니다**(`NULLS LAST`). 등록 안 한 사람은 등록순에서
가장 나중이라고 읽는 것이 자연스럽습니다.

> 「최근 초대순」이 의도셨다면 그건 다른 정렬이라 이름을 나눠 주시는 편이 낫겠습니다 —
> 지금은 한 정렬이 두 뜻을 섞고 있습니다.

## 6. 🔴 R7 — 반 **이동**이 한 번에 안 됩니다 · `DATA_INTEGRITY_VIOLATION`이 샙니다

`PATCH /cohorts/{id}/classrooms/trainee-assignments`를 조합으로 전부 돌렸습니다.

| 보낸 것 | 결과 |
|---|---|
| 미배정 활성 → 1반 | **200** `assigned=1` |
| **A반 소속 → 같은 A반** | **409 `DATA_INTEGRITY_VIOLATION`** |
| **A반 소속 → B반 (이동)** | **409 `DATA_INTEGRITY_VIOLATION`** |
| 비활성 → 1반 | 400 `TRAINEE_NOT_IN_COHORT` |
| 초대 대기 → 1반 | 400 `TRAINEE_NOT_IN_COHORT` |
| 없는 학생 | 400 `TRAINEE_NOT_IN_COHORT` |
| 빈 배열 | 400 `VALIDATION_FAILED` |
| 같은 사람 두 번 | **200** `assigned=1` (중복은 서버가 정리) |
| **없는 반 ID** | **무응답** — §8에 따로 적습니다 |

### ① 이동이 없습니다 — 「배정」만 있습니다

**이미 어느 반에 있는 사람은 다시 배정할 수 없습니다.** 같은 반이든 다른 반이든 409입니다
(2026-08-15 재측정 — `A반 소속 → B반` 여전히 `409 DATA_INTEGRITY_VIOLATION`).
되돌리기를 먼저 부르면 통과합니다.

```
PATCH …/rollback                 → 200
PATCH …/trainee-assignments B반  → 200      ← 그제서야 된다
```

그런데 **반 통폐합·중도 합류 때 사람을 옮기는 일이 실제로 있습니다.** 저희 화면은
「범위 = 전체」로 이미 배정된 사람도 고를 수 있게 두고 있었고, 그래서 **누르면 409가
났습니다.**

**지금은 저희가 두 번 부릅니다** — 옮길 사람만 골라 `rollback`하고 이어서 배정합니다.
사용자는 한 번 누릅니다. 다만 **그 사이에 실패하면 그 사람들이 미배정으로 남습니다.**
원자적이지 않아서, 이동 중 실패가 데이터를 중간 상태로 만듭니다.

**배정이 이동까지 받아 주시면**(이미 있으면 옮기는 upsert) 이 두 단계와 그 위험이
같이 사라집니다.

### ② `DATA_INTEGRITY_VIOLATION`은 도메인 코드가 아닙니다

스펙의 이 엔드포인트 에러 목록은 `CLASSROOM_NOT_FOUND` · `TRAINEE_NOT_IN_COHORT`
둘뿐입니다. 지금 오는 것은 **DB 유니크 제약이 그대로 새어 나온 것**으로 보입니다.

```json
{ "status": 409, "code": "DATA_INTEGRITY_VIOLATION",
  "message": "요청을 처리할 수 없습니다. 데이터 제약 조건에 맞지 않습니다." }
```

문구가 **화면에 그대로 쓸 수 없는 말**입니다 — 운영자에게 「데이터 제약 조건」은 아무
의미가 없습니다. ①을 고치시면 이 코드는 사라지겠지만, 남긴다면
`TRAINEE_ALREADY_ASSIGNED` 같은 이름으로 주시면 저희가 *"이미 반에 들어가 있습니다"* 로
정확히 씁니다.

## 8. 🟡 R9 — 매니저 이름을 이메일 앞자리로 채우지 말아 주세요

이름 없이 초대하면 목록에 `name: null`로 옵니다 — **맞습니다.** 그런데 그 초대를
**취소(정지)하면 이름 자리에 이메일 앞자리가 들어옵니다.**

```
POST manager-invitations {"email":"nulltest-probe@example.com"}  → name: null              ✅
DELETE manager-invitations/{tokenId}  (취소)                     → name: "nulltest-probe"  ⚠
```

(2026-08-15 재측정 — 새 계정으로 다시 확인했습니다.)

**`null`을 유지해 주시면 좋겠습니다.**

- **되돌릴 수 없습니다.** 한 번 박히면 「이름을 모른다」는 사실이 사라집니다. 나중에
  본인이 실명으로 가입해도 그 값이 남을 수 있습니다.
- **거짓을 사실처럼 만듭니다.** `dkdkdk`는 그 사람의 이름이 아니라 이메일 조각인데,
  목록에서 실명과 나란히 서면 구분이 안 됩니다.
- **화면은 이미 `null`을 제대로 그립니다** — 이름 칸에 `—`를 쓰고 상태는 배지가 말합니다.
  표시는 화면의 몫이라 서버가 채워 주실 필요가 없습니다.

## 9. 🟡 Q1 — CSV가 좁습니다 · 엑셀 파일은 어떻게 할까요

**지금 서버가 받는 것을 전수로 쟀습니다.**

| 올린 것 | 결과 |
|---|---|
| `이름,이메일` UTF-8 | **200** ✅ |
| BOM 붙은 UTF-8 | **200** ✅ |
| 열 순서 다름 · 열 추가(`번호,이메일,소속,이름`) | 400 `CSV_FORMAT_INVALID` *"헤더는 '이름', '이메일' 두 열이어야 합니다"* |
| **CP949**(윈도우 엑셀의 「CSV(쉼표로 분리)」 기본) | 400 `CSV_FORMAT_INVALID` *"UTF-8 인코딩이어야 합니다"* |
| 머리글 없음 | 400 `CSV_FORMAT_INVALID` |

**화면은 서버 규칙을 그대로 지키게 맞춰 뒀습니다** — 미리보기에서 같은 이유를 먼저
말하고 등록 버튼을 잠급니다. 그래서 **지금 당장 깨지는 것은 없습니다.**

### 다만 실무에서 걸립니다

운영자가 받는 명단은 대개 **엑셀 파일**이고, 거기서 「CSV로 저장」하면 **CP949**가
나옵니다. 지금은 사람이 「CSV UTF-8」을 골라야 하고, 열도 딱 두 개만 남겨야 합니다.

**셋 중 어느 쪽이 좋을지 의견을 주세요.**

| | 누가 | 내용 |
|---|---|---|
| **가** | 프런트 | 인코딩·열을 프런트가 읽어 **`이름,이메일` UTF-8로 정규화해 전송**. 서버 계약 변경 0 |
| **나** | 백엔드 | 서버가 CP949를 받고, 머리글에서 두 열을 **이름으로** 찾는다 |
| **다** | 백엔드 | `.xlsx`도 받는다 |

**저희는 「가」를 할 수 있습니다.** 다만 `.xlsx`는 프런트에서 파싱하려면 라이브러리가
필요해(약 200KB) 「다」쪽이 깔끔합니다.

> ⚠ **어느 쪽이든 크기 상한이 걸립니다.** 앞단 Lambda 프록시가 **6MB**에서 끊고
> base64로 부풀어 실질 4.5MB입니다(22차 R2). 명단 CSV가 그 크기에 닿진 않지만,
> 엑셀 파일은 서식·이미지 때문에 커질 수 있어 **`.xlsx`를 받으신다면 같이 봐 주세요.**

## 12. 🚨 R12 — `TraineeTimelineEvent.type`이 enum인데 제약이 없습니다

**2026-08-15 스펙으로 저희 CI가 다시 빨간불입니다.**

```
❌ [nullable] 설명에는 null이라 적혀 있는데 타입이 null을 허용하지 않는다 — 1건
     · TraineeTimelineEvent.type
```

```jsonc
"type": {
  "type": "string",                    // ← enum 제약이 없습니다
  "example": "ASSESSMENT",
  "description": "`ASSESSMENT`(이해도 확인) · `REPORT`(리포트 발행) · `REVIEW`(다시 보기) ·
                  `REVIEW_CLOSED`(다시 보기 창 마감) · `INTERVIEW`(면담).
                  유형마다 아래 블록 중 하나만 채워진다 — 나머지는 `null`이거나 빈 배열"
}
```

**두 가지가 겹쳐 있습니다.**

- **설명은 값 다섯 개를 못 박는데 스키마는 아무 문자열이나 받습니다.** 그러면 생성 타입이
  `string`이 되어 화면의 `switch`가 exhaustive해지지 않습니다 — 값이 하나 늘어도
  컴파일러가 안 알려 줍니다. 17차에서 정리한 것과 같은 자리입니다.
- **그 설명의 「나머지는 `null`」이 저희 검사기를 때립니다.** 그 문장은 *형제 필드*
  얘기인데 `type`의 설명란에 있어서, 「설명엔 null인데 타입이 안 받는다」로 잡힙니다.

**`enum`을 달아 주시면 둘 다 풀립니다.** 형제 필드의 nullable 여부는 그 필드 설명으로
옮겨 주시면 검사기도 정확히 읽습니다.

## 13. 🟡 R13 — 타임라인 응답에 커서와 `totalElements`가 섞여 있습니다

```

아니라 「전체 수」임을 설명에 적어** 주세요.

## 14. 🟡 Q2 — 새 팀 API 12개는 어느 화면 것인가요

2026-08-15 배포에서 팀 관련 오퍼레이션이 한꺼번에 생겼습니다.

> **비동기로 바뀐 것**인지, 그렇다면 저희 등록 화면이 그 조회로 진행률을 봐야 하는지요.
