# SC-A03 · 비밀번호 재설정

> 소스: 기능명세서 v8 AUTH-05(비밀번호 재설정). 진입은 SC-A01 '비밀번호 찾기'(v8: 로그인 실패 자동 진입 아님).
> 배치: **P2 · 중요도 상**(계정 탈취 경로 — 대충 만들면 계정 열거·토큰 재사용 노출). 인증 화면 셸·컴포넌트는 SC-A01 재사용.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 역할 | 공통(슈퍼어드민 / 매니저 / 교육생) — 인증 전 화면 |
| 진입 경로 | **SC-A01 '비밀번호를 잊으셨나요?'** 링크로만(AUTH-05는 사용자 선택 경로·v8) / 재설정 메일 링크 → 2단계 |
| 연계 FR | **AUTH-05(주)**, AUTH-03(변경 후 재로그인), 전역: SYS-02·AUTH-09 |
| 이번 배치 범위 | ① 재설정 요청(이메일) · ② 비밀번호 변경(토큰+새 비밀번호) 2단계 |
| 후속 확장 | 없음(명세 범위 내 완결) |
| 만들지 않음 | 재설정 토큰 TTL·정책값 노출 화면(백엔드 정책) · 계정 존재 여부 표시(계정 열거 방지) |
| 핵심 규범 | **계정 존재 비노출**(동일 202) · **토큰 1회성·TTL** · **요청/변경 2 API 분리** · **현재 비밀번호와 동일 금지** · **변경 성공 시 전 세션 무효화·재로그인** |

## 2. 목적 & UX 설계 근거

- **2단계 분리 — 요청과 변경은 다른 API·다른 화면(AUTH-05).** 재설정 요청(이메일 입력)과 실제 변경(토큰+새 비밀번호)은 별도 API. 화면도 ① 요청 ② 변경 2단계로 분리하고, ②는 **메일 링크(reset_token)로만** 진입. 경로 혼용은 400으로 안내(case9).
- **계정 존재를 노출하지 않는다(AUTH-05 case1).** 요청 단계는 **계정 존재 여부와 무관하게 동일한 202 응답·동일 안내 문구**("입력하신 주소로 메일을 보냈습니다"). 존재/부재를 구분하면 계정 열거 표면이 된다 → SC-A01의 단일 문구 원칙과 동일.
- **토큰은 1회성·TTL, 위변조·목적 불일치는 차단(AUTH-05).** 변경 단계는 토큰 서명·TTL·1회성 사용·목적(password_reset) 일치를 검증. 만료(case2)·재사용(case3)·위변조/목적불일치(case4)는 각각 재요청 안내·차단·보안 로그.
- **현재 비밀번호 재사용 금지(case6).** 새 비밀번호가 현재와 동일하면 변경 차단(재사용 금지 = 현재 1건 기준). 정책 미충족은 실패 규칙을 돌려준다(case5).
- **변경 성공은 전 세션을 끊는다(AUTH-05).** 변경 확정 시 기존 Refresh Token 전부 폐기·활성 세션 무효화 후 **로그인 화면으로 보내 재로그인**. 저장 실패는 세션 폐기 전 롤백(case7), 세션 폐기 실패는 변경은 유지하되 강제 로그아웃 재시도 등록(case8).
- 중앙 폼 유지: SC-A01과 동일한 2단 분할 인증 셸·컴포넌트 재사용(뷰 패턴 신설 없음).

## 3. 정보 구조 & 레이아웃

**데스크톱 2단 분할**(SC-A01 셸 재사용). 좌 `BrandPanel` + 우 `AuthForm`. 폼 내용만 단계별로 교체.

**① 재설정 요청(`AuthForm`):**
1. 제목 "비밀번호 재설정" + 보조 문구
2. `InlineAlert` 슬롯(상태 발생 시)
3. `TextField` 이메일
4. `PrimaryButton` "재설정 링크 받기"
5. `TextLink` "← 로그인으로" → SC-A01
6. 제출 후 → **동일 확인 안내**("입력하신 주소가 계정에 등록돼 있으면 메일을 보냈습니다") — 계정 존재 비노출

**② 비밀번호 변경(메일 링크 진입):**
1. 제목 "새 비밀번호 설정"
2. `InlineAlert` 슬롯(토큰 만료/사용됨/위변조 등)
3. `PasswordField` 새 비밀번호(표시 토글, 정책 힌트)
4. `PasswordField` 새 비밀번호 확인
5. `PrimaryButton` "비밀번호 변경"
6. 성공 → 안내 + `PrimaryButton` "로그인하기" → SC-A01

**반응형(웹 기준):** 데스크톱 2단 분할, 모바일은 브랜드 패널 축소·폼 단일 컬럼(별도 화면 아님).

## 7. 인터랙션 & 화면 전이

- SC-A01 '비밀번호를 잊으셨나요?' → **SC-A03 ①요청**.
- ①요청 제출 → 동일 확인 안내(성공/부재 무관) → 메일 발송(유효 계정만).
- 메일 '비밀번호 재설정' 링크 → **SC-A03 ②변경**(reset_token).
- ②변경 성공 → 전 세션 무효화 → **SC-A01 재로그인**.
- 토큰 만료/사용됨(case2·3) → [재요청] → ①요청.
- ← "로그인으로" → SC-A01.
