## 1. 🔴 R1 — 버전 2개부터 `GET /curricula/{materialId}`가 404, 기관 목록에서도 실종

### 재현 (버려도 되는 교안으로 실제 실행)

```
대상  AI_데이터 분석_교안 (materialId c6c588ce-533f-4f4e-8cbe-ee880ab43d98) · v1 SUCCEEDED

POST /curricula/{materialId}/versions   → 201  (v2 정상 생성)

그 직후:
GET /curricula/{materialId}                        → 404 CURRICULUM_MATERIAL_NOT_FOUND
GET /organizations/{organizationId}/curricula       → content[]에 이 교안 자체가 없음(행 실종)
GET /curricula/{materialId}/versions                → 200, v1·v2 둘 다 정상 나옴
GET /cohorts/{cohortId}/curricula(연결 후보)         → v1·v2 둘 다 후보로 나옴
```

**버전이 하나뿐인 다른 교안**(`Spring 백엔드 설계`)으로 같은 상세 조회를 하면 200이
정상 옵니다 — **버전이 2개가 되는 순간부터만 깨집니다.**

### 왜 급한가

- **OP-06 교안 탭 자체가 그 교안을 잃습니다.** 목록 조회가 그 행을 안 주니 오퍼레이터가
  "방금 새 버전 올린 교안"을 화면에서 다시 찾을 방법이 없습니다.
- **상세 페이지가 열리지 않습니다.** 목록에 남은 링크(북마크·최근 방문)로 들어가도 404.
- **삭제 판정에도 영향이 있을 수 있습니다.** `CURRICULUM_MATERIAL_IN_USE`가 `usedProjectCount`
  기준인데 그 값을 주는 상세 조회 자체가 404라 삭제 시도 흐름도 같이 막힐 가능성이 있습니다
  (이 부분은 저희가 아직 직접 재현하지 않았습니다 — 확인 부탁드립니다).
- **44차에서 요청한 44차 R1(`versionId` 지원)이 도착해도 이 버그가 안 풀리면 소용없습니다.**
  상세 조회 자체가 최신 버전도 못 찾는 상태라, `versionId`를 추가로 받게 해도 여전히 404입니다.

### 부가 관찰 — `analysisStatus`가 버전 조회에서 `null`로 보입니다

v2를 만들기 **전에도** `GET .../versions`가 v1의 `analysisStatus`를 `null`로 줬습니다
(기관 목록 조회는 같은 시점에 `SUCCEEDED`라고 답했습니다). 이게 R1과 같은 원인인지
별개인지는 저희가 판단할 수 없어 그대로 적어 둡니다.

### 요청

- 버전이 2개 이상인 교안에서 `GET /curricula/{materialId}`(상세)·
  `GET /organizations/{organizationId}/curricula`(목록)가 왜 그 교안을 못 찾는지 확인 부탁드립니다.
- 재현에 쓴 교안(`c6c588ce-533f-4f4e-8cbe-ee880ab43d98`)을 그대로 남겨 뒀습니다 — 필요하시면
  이 교안으로 바로 재현하실 수 있습니다.

## 2. 🟡 R2 — `POST /versions` 스펙이 자기모순입니다 (실측으로 답은 나왔습니다)

같은 오퍼레이션 설명 안에 **서로 반대되는 문장이 같이 있습니다.**

```
(위쪽, 이번에 추가된 문장)
"등록 직후엔 이 버전만의 분석이 안 된 상태다 … 분석을 자동으로 걸지 않는다"

(아래쪽, 이전부터 있던 문장 — 그대로 남아 있음)
"바뀌는 것은 상태 하나뿐이다 — 기존 최신 버전이 INACTIVE로 넘어가
GET /cohorts/{cohortId}/curricula 같은 조회에서 새 버전에게 자리를 내준다"
```

**실측으로 확인했습니다 — 아래 문장(`INACTIVE`)이 지금 사실과 다릅니다.** 위 §1의
재현에서 v2를 만든 뒤 `GET /cohorts/{cohortId}/curricula`를 조회하면 **v1·v2가 둘 다**
후보로 나옵니다. v1이 `INACTIVE`로 넘어가 자리를 내주는 동작이 지금은 일어나지 않습니다
(현재 배포 상태 안내 문서도 "여러 버전이 동시에 ACTIVE로 남습니다"라고 확인해 주셨습니다 —
그쪽과 일치합니다).

### 요청

`INACTIVE` 문장을 지우거나, 의도한 동작이 맞다면(여러 버전이 동시에 후보로 남는 것이
설계라면) 그렇게 정정해 주세요. 저희는 **현재 실측대로**(여러 버전이 동시에 활성)를
전제로 화면을 설계하겠습니다 — R2가 오면 그때 §3(44차)의 회차별 버전 표시가 그 전제를
그대로 씁니다.

"R1·R4가 온 뒤에 켠다"고 적었는데, 이번 발견으로 그 조건에 **§1 해결**이 하나 더
붙습니다.
