# 비동기 상태 부채 — 어떻게 고칠 것인가

> [async-states.md](async-states.md)가 **무엇을 그릴지**를 정한다면, 이 문서는 그 §7에 적힌
> **부채 14건을 어떤 방법으로 해소할지**와 그 방법을 고른 근거를 갖는다.
>
> 결론만 필요하면 [7절 순서](#7-순서와-근거)를 본다.

## 0. 전제 — 이것이 방법 선택을 지배한다

**레포가 둘로 갈렸다.** 이 레포(`IZ-op-projects`)는 **오퍼레이터 전담**, `IZ-frontend`는
**auth·슈퍼어드민**이다. 둘은 같은 `src/components/ui` · `lib` · `main.tsx` · `routes.tsx` ·
`shells/`를 공유한다.

여기서 법칙이 하나 나온다.

> **새 파일은 충돌하지 않는다. 기존 공용 파일의 *수정*이 충돌한다.**
> 그리고 공용 파일 수정은 충돌보다 나쁜 것을 만든다 — **남의 화면이 조용히 바뀐다.**

그래서 이 계획의 기본값은 **"추가는 공용에, 수정은 오퍼레이터 안에서"** 다.

## 1. 전략 세 가지 — 비교

| | **A. 화면별 수선**<br>6화면 각각 고침 | **B. 프리미티브 일괄**<br>`Empty` 기본값·전역 옵션 | **C. 정책 레이어**<br>경계에 정책, 공용은 추가만 |
|---|---|---|---|
| 전 화면 일관성 | ✗ 같은 결정을 6번 반복 | ○ 한 번에 | ○ 한 곳에 **코드로** 존재 |
| 다른 레포 영향 | 없음 | **✗ 조용히 바뀐다** | 없음(추가만) |
| 충돌 | 적음 | **✗ 폭탄** | 적음 |
| 회귀 방지 | ✗ 문서에만 존재 | △ | ○ 안 거치면 CI가 잡는다 |
| 중간 상태 | **✗ 화면마다 다르게 보인다 = 지금 문제의 재발** | ○ | ○ 도메인 단위로 완결 |
| 오작동 위험 | 낮음 | **✗ 전역 기본값이 틀리는 자리가 있다(2절)** | 낮음 |

### → C를 고른다. 근거 셋

1. **이 레포엔 이미 그 경계가 있다.** `projects/queries.ts` · `analysis/_/api/api.ts` ·
   `report/_/api/api.ts` — 생성 훅과 화면 사이의 도메인 래퍼가 이미 층으로 존재한다.
   **새 층을 만드는 게 아니라 비어 있는 층에 정책을 넣는 것**이다.
2. **표준이 문서가 아니라 호출 시그니처가 된다.** *"목록 훅을 이 래퍼로 만들면
   `keepPreviousData`·디바운스가 자동으로 붙는다"* 가 되면 **지키는 게 안 지키는 것보다
   쉬워진다.** 규율에 기대는 표준은 사람이 바뀌면 무너진다.
3. **다른 레포와의 계약이 "추가만"으로 단순해진다.** 조율할 일이 사실상 사라진다
   (예외 하나는 7절 각주 — `Header.tsx`).

## 2. 왜 전역 기본값이 답이 아닌가 — 결정적 반례

가장 큰 🔴(조건 변경 시 표가 사라짐)은 **한 줄로 없앨 수 있다.**

```ts
// main.tsx — 유혹적이지만 틀리다
defaultOptions: { queries: { placeholderData: keepPreviousData } }
```

이게 틀리는 자리 — **OP-04 상세에서 회차 A → B로 이동하면 B의 주소에 A의 내용이 남는다.**
목록에서는 "이전 결과 유지"가 친절이지만, 상세에서는 **다른 회차의 값을 그 회차 것처럼
보여주는 것**이다. 데이터 화면에서 이건 불편이 아니라 사고다.

> **이전 값 유지는 "같은 것의 다른 조각"일 때만 맞다. "다른 것"으로 이동할 때는 틀리다.**
>
> | | 예 | 유지 |
> |---|---|---|
> | 같은 것의 다른 조각 | 목록의 필터·검색·정렬·페이지 | **○** |
> | 다른 것 | 상세의 `id`, 다른 기수 | **✗** |

그래서 정책은 전역이 아니라 **목록 래퍼**에 붙는다.

```ts
// features/operator/_shared/listQuery.ts  (새 파일 — 충돌 없음)
export const listQueryOptions = { placeholderData: keepPreviousData } as const
```

같은 래퍼가 검색어 디바운스(1-5)도 품는다 — **정적 검사로는 못 막는 규칙을 구조로 막는다**
(6절 참고).

## 3. `Empty` — 기본값 뒤집기를 "지금" 하면 안 되는 이유

| | 옵션 1 · 기본값 즉시 뒤집기 | 옵션 2 · `className` 계속(현행) | **옵션 3 · expand → migrate → contract** |
|---|---|---|---|
| 오퍼레이터 10곳 | 고쳐진다 | 하나씩 손으로 | 고쳐진다 |
| 다른 레포 화면 | **의도가 `아직`인 자리까지 조용히 실선으로** | 무영향 | 무영향 |
| 의도가 코드에 남나 | ✗ 기본값에 숨는다 | ✗ `border-solid`는 스타일이지 의도가 아니다 | ○ `variant="pending" \| "empty" \| "failed"` |
| 되돌리기 | 어렵다 | — | 단계마다 가능 |

### → 옵션 3

1. **expand** — `variant` prop을 **추가**한다. 기본값은 그대로 두어 기존 호출부 전부 무영향
   (추가라 충돌도 없다).
2. **migrate** — 오퍼레이터 호출부를 `variant`로 이관한다. 저쪽은 자기 속도로.
3. **contract** — 양쪽이 끝나면 기본값을 `empty`(실선)로 뒤집고 `variant`를 필수로 만든다.

`className="border-solid"`로 고치는 것은 **증상만 고치는 것**이다. 다음 사람이 또 `<Empty>`를
그냥 쓴다. 셋 중 하나를 **고르게 강제**해야 기본값 사고가 구조적으로 사라진다.

## 4. 실패 문구 — 가장 근본적인 지점

| 옵션 | 문제 |
|---|---|
| 화면마다 `status` 분기 | 6화면 × 4갈래 = 문구 24개. 한 달 뒤 서로 다른 말을 한다 |
| 훅에서 던지기 전에 문구로 변환 | 에러 원본이 사라져 로깅·분기가 막힌다. **층을 잘못 고른 것** |
| **`errorCopy(error)` 순수 함수 하나** | — |

```ts
// lib/errorCopy.ts  (새 파일)
errorCopy(error, { subject: '회차' })
// → { title, description, retry: boolean, back?: { label, to } }
```

**고르는 이유가 "문구 통일"이 아니다.** `403 → retry: false`가 되는 순간 **누를 수 없는
"다시 시도"를 그릴 방법 자체가 없어진다.**

지금 OP-05는 *"아직 발행 전"*(`COHORT_REPORT_NOT_FOUND`)에 다시 시도를 붙여 두고 주석에
*"구분은 이번 범위 밖"* 이라 적어 두었다. 판단을 한 곳에 모으면 **그것이 범위 밖일 수가
없게 된다** — 도메인 코드 우선 규칙(async-states §3-1)이 이 함수 첫 줄이 되기 때문이다.

**화면은 "어느 자리에 그리나"만 정하고 "무슨 말을 하나"는 정하지 않는다.**

## 5. 스켈레톤 — 어디까지 자동화할 것인가

| 옵션 | 판단 |
|---|---|
| 화면마다 손으로 | 6화면이 조금씩 달라진다. 지금 슈퍼어드민 ↔ 오퍼레이터가 갈린 이유 그대로 |
| 컬럼 정의에서 자동 생성 | 이론상 최고. **그러나 이 레포는 표를 각 화면이 `<table>`로 직접 쓴다** — `TableFrame`이 컬럼 정의를 안 갖는 것은 의도된 결정이다(그 파일 주석). 컬럼 추상화를 새로 들이는 것은 구조를 뒤집는 것 = YAGNI 위반 |
| **`TableSkeleton rows cols`** | ✓ |

```tsx
<TableSkeleton rows={ROSTER_PAGE_SIZE} cols={['w-[200px]', 'w-[108px]', 'w-[168px]', null]} />
```

화면이 **이미 갖고 있는 폭 토큰을 그대로 넘긴다.** 5줄짜리 컴포넌트이고, 구조를 건드리지
않으면서 *"행 수 = 페이지 크기, 폭 = 실제 열 폭"* 이라는 규칙이 **인자로 강제된다.**

## 6. 회귀 방지 — 문서는 지켜지지 않는다

| 옵션 | 판단 |
|---|---|
| 리뷰 체크리스트만 | **지금 상태가 그 결과다** |
| 스토리북 · 상태 갤러리 | 새 의존성 + 유지비. 화면 6개에 과하다 |
| **CI 스캐너 `check-async-states.mjs`** | ✓ `check-design.mjs`(하드코딩 hex 금지)라는 **선례가 이미 이 레포에 있다** |

검사 둘이면 충분하다.

```
1) features/operator/** 렌더 분기에서 isPending 금지 → isLoading   (116:4를 다시 벌리지 않는다)
2) <Empty> 무인자 사용 금지 — variant 필수                        (3절 contract 단계에서 켠다)
```

세 번째로 넣고 싶은 *"검색 input에 디바운스 없이 쿼리 키를 연결하지 마라"* 는 **정적 검사가
안 된다.** 그래서 2절의 목록 래퍼가 디바운스까지 품게 해서 **구조로 막는다** — 검사할 수
없는 규칙은 규칙으로 두지 않고 구조로 옮긴다.

## 7. 순서와 근거

기준은 둘 — **거짓말하고 있는 것 먼저**, **나중에 하면 두 번 만지게 되는 것 먼저.**

| # | 무엇 | 해소되는 부채 | 왜 이 순서인가 |
|---|---|---|---|
| 1 | `errorCopy` + `errorElement` | 🟠 OP-05 발행 전 · 🟠 OP-04 문구 · 🔴 errorElement | 유일하게 **화면이 사용자에게 틀린 말을 하는** 항목. 새 파일 2개라 충돌 0 |
| 2 | 목록 래퍼(`placeholderData` + 디바운스) | 🔴 OP-03 검색 · 🔴 조건 변경 | 체감이 가장 크다. OP-03·OP-06이 즉시 나아진다 |
| 3 | `Empty` variant expand + 오퍼레이터 이관 | 🔴 Empty 기본값 | 저쪽에 미리 알려야 하므로 **일찍 시작**한다 |
| 4 | `AsyncState` 공용화 + `TableSkeleton` | 🟡 복붙 2벌 · 🟠 첫 진입 스피너 · 🟠 헤더 사라짐 | 3에서 어차피 그 자리를 다 열게 된다 |
| 5 | `isLoading` 일괄 + CI 스캐너 | 🟡 116:4 · 🟡 재시도 연타 | 3·4를 하며 대부분 바뀐다. **먼저 하면 두 번 만진다** |
| 6 | OP-05 react-query 이관 · 기수 URL 통일 | 🟡 useAsync · 🟠 하드코딩 기수 | 가장 크고, 1~5가 끝나야 재작업이 없다 |

### 6번의 단서 두 개

- **기수를 URL로 옮기는 것은 헤더 기수 스위처와 같이 간다.** 스위처 없이 주소만 바꾸면
  사용자에게는 **바꿀 수단이 없는 상태**가 된다. 표준(async-states §5)은 "URL이 갖는다"까지고,
  **고르는 UI가 없으면 그 표준은 사용자에게 아무것도 아니다.**
- `shells/Header.tsx`는 공용이라 **이 계획에서 저쪽과 조율이 필요한 유일한 파일**이다.
  미리 알린다.
