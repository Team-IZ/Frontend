# OP-06 · MG-09 교안 버전 — 착수 전 계획

> API 변경 상태 · 우리 화면 현재 상태 · 이미 정한 기획 결정을 한 곳에 모은다.
> 백엔드 요청 원문은 [44차](../backend/backend-api-requests-44.md) ·
> [45차](../backend/backend-api-requests-45.md).

---

## 1. 지금 못 만드는 이유 — 막힌 것부터

**착수 전제 하나.** [45차 §1](../backend/backend-api-requests-45.md#1--r1--버전-2개부터-get-curriculamaterialid가-404-기관-목록에서도-실종)이
안 풀리면 「새 버전 올리기」 버튼을 만들 수 없다 — 버튼을 누르는 순간 그 교안이
목록·상세에서 사라지는 것을 실측으로 확인했다. 44차 R1(상세가 `versionId`를 못
받는 것)이 와도 이 버그가 안 풀리면 상세 조회 자체가 404라 소용없다.

**그래서 3단계(새 버전 올리기)·4단계(버전 이력 UI)는 45차 §1 + 44차 R1이 둘 다
온 뒤에 착수한다.** 아래 §3(회차 → 교안 링크, URL 버전화)은 지금 가진 API만으로
되므로 먼저 간다.

## 2. API 상태 — 뭐가 되고 뭐가 안 되나

| 오퍼레이션 | 상태 | 우리가 쓸 수 있나 |
|---|---|---|
| `GET /curricula/{materialId}/versions`(버전 이력) | ✅ available | 쓸 수 있다 — 4단계 재료 |
| `GET /curricula/{materialId}/sections?versionId=`(옛 버전 섹션) | ✅ available | 쓸 수 있다 |
| `POST /curricula/{materialId}/versions`(새 버전 등록) | ✅ available, 자동 분석 **없음**(44차 R4 회신) | 3단계에서 `POST /analyses`를 직접 이어 붙여야 함 |
| `GET /curricula/{materialId}`(상세) | `versionId` 못 받음(44차 R1, 접수·미구현) **+ 버전 2개부터 404(45차 R1, 접수 대기)** | ❌ 막힘 — 3·4단계 전제 |
| `GET /organizations/{organizationId}/curricula`(목록) | 버전 2개부터 그 교안이 실종(45차 R1) | ❌ 막힘 |
| `GET /cohorts/{cohortId}/linked-curricula`(MG-09 목록) | `versionId`·`versionNo` 단수 — 회차마다 다른 버전이면 못 가른다(44차 R2, 접수·미구현) | 🟡 지금 있는 것만으로 §3 진행 가능(아래 참고) |
| `GET /curricula/{materialId}/projects`(쓰인 회차) | `versionId`로 못 좁힘, 전 버전 합만 옴(44차 R3, 접수·미구현) | 🟡 최신 버전 상세에서만 신뢰 가능 |
| 제목만 수정 | API 자체가 없음(44차 R5, 접수·미구현) | ❌ 새 버전 다이얼로그의 title란으로 우회(§5) |

## 3. 지금 만든다 — 회차 → 교안 링크 + URL 버전화

API 변경 없이 되는 두 가지.

### 3-1. 회차 상세 → 교안 상세 링크 신설

지금 회차 상세(MG-08)에 교안 이름과 `v1`은 보이는데 클릭해서 교안 상세로 넘어갈
링크가 없다(사용자 지적, "회차가 v1에 붙어있으면 v1 보여줘야지" 답변 §4-2 참고).

- 서버는 이미 `ProjectLinkedCurriculum`에 `materialId`·`curriculumVersionId`·
  `versionNo`를 준다 — 추가 조회 없이 링크를 만들 수 있다.
- 클릭하면 **그 회차가 실제로 연결한 버전**의 상세로 간다(§4-1의 URL 버전화를 그대로 씀).

### 3-2. 교안 상세 URL에 버전을 담기

지금 `/manager/curriculum/:materialId` · `/operator/curricula/:materialId`다.
1기의 v1과 7기의 v2가 **같은 주소**가 된다(사용자 확인, "ㅇㅇ" — §4-2).

```
/manager/curriculum/:materialId?version=1
/operator/curricula/:materialId?version=2
```

버전 생략 시 최신으로 해석(§4 참고). 새로고침·링크 공유에도 버전이 살아남는다.

> ⚠ **지금은 실제로 쓸 데가 없다.** `GET /curricula/{materialId}`가 아직 `versionId`를
> 못 받으니(44차 R1) 이 쿼리 파라미터를 화면이 읽어도 상세 조회에 못 먹인다. 지금은
> 3-1의 링크가 이 쿼리를 **의도만 담아 보내는** 수준이고, 44차 R1이 오면 그 순간부터
> 실제로 다른 버전을 그린다. §1에서 3·4단계를 미루는 것과 같은 이유로, 이 부분도
> "만들어 두되 아직 동작은 안 한다"로 남는다 — 링크 자체는 지금 가치가 있다(다른
> 버전이어도 최소한 그 교안 상세로는 간다).

## 4. 기획 결정 — 사용자 확인 완료 (2026-08-20)

### 4-1. 목록은 항상 최신, 예전 버전은 표시만 하고 클릭하면 그 버전으로

> "목록에서는 최신이 보일거니까 그거 누르면 최신 상세가 나오겠지. 그리고 예전 버전이
> 있음을 어딘가에 표시해주고, 그걸 누르면 그 예전 버전의 상세가 나와야지."

- OP-06 교안 탭 · MG-09 교안 화면 둘 다 **한 행 = 최신 버전**. 목록 클릭 → 최신 상세.
- 상세 화면 안에 "이전 버전 3개 · v1 · v2 · v3" 같은 자리를 두고, 그걸 누르면 그
  버전의 상세로 이동(§3-2 URL로).
- **최신이 아닌 버전을 보고 있을 때는 쓰기 액션(새 버전 올리기·재분석·삭제)을 안
  그린다** — 셋 다 최신 버전에 작용하는 오퍼레이션이라, 옛 버전 화면에 두면 "이
  버전을 재분석/삭제한다"로 잘못 읽힌다(필자 판단, 뒤집을 사유 없으면 유지).

### 4-2. 매니저는 담당 기수가 실제로 쓴 버전만, 오퍼레이터는 최신 관리

> "매니저는 최신만 봄." → 이후 정정: "회차가 v1에 붙어있으면 v1 보여줘야지. 1기의
> 1차프로젝트는 v1쓰고 7기의 1차프로젝트는 v2를 썼다고 하면 클릭해서 들어갔을 때
> 각각에 맞게 줘야지."

**최종 규칙 — 화면마다 다르다.**

| 화면 | 진입 경로 | 보여줄 버전 |
|---|---|---|
| MG-09(매니저 교안 목록) | 기수의 `linked-curricula` | 그 기수가 실제 연결한 버전(회차마다 다를 수 있음) |
| MG-08 회차 상세 → 교안 링크(§3-1) | `ProjectLinkedCurriculum` | 그 회차가 연결한 버전 그대로 |
| OP-06(오퍼레이터 교안 탭) | 기관 전체 목록 | **최신 버전**(관리자는 최신을 관리) |

MG-09는 44차 R2(linked-curricula 버전 분리)가 와야 "회차마다 다른 버전"을 행으로
정확히 가를 수 있다 — 오기 전까지는 지금처럼 교안당 한 행(대표 버전)으로 두고,
회차별로 다른 버전을 쓰는 경우는 3-1의 회차 링크로 우회한다(회차 상세에서 들어가면
그 회차의 버전이 정확히 나온다 — R1이 오면).

### 4-3. 새 버전은 분석이 자동으로 돌아야 한다 — 백엔드는 거절, 우리가 이어 붙인다

> "새 버전 올리면 자동으로 돌아야지. 기존 버전과 새 버전은 다른 파일이잖아. 내용만
> 비슷한."

44차 R4로 요청했으나 **거절**(44차 회신, §2 참고) — `POST /versions`는 분석을 자동으로
안 건다. `RegisterCurriculumDialog`(새 교안 등록)가 이미 쓰는 패턴을 새 버전
다이얼로그에도 그대로 넣는다.

```
POST /curricula/{materialId}/versions  → 201, versionId 받음
POST /curricula/{materialId}/analyses  → 곧바로 이어 붙임(같은 요청 흐름 안에서)
```

### 4-4. 제목은 새 버전 다이얼로그에서만 — "비우면 유지"로 안내

> "ㅇㅇ 좋네." (제목란을 두되 별도 제목 수정 API는 백엔드에 요청)

새 버전 다이얼로그에 제목 입력란을 두고 **비우면 기존 제목 유지**로 안내한다.
44차 R5(제목만 고치는 API)가 오기 전까지 이게 유일한 제목 수정 경로다 — 파일은
그대로인데 제목만 고치려는 사람도 이 다이얼로그를 써야 한다(원치 않는 버전이 하나
생기는 것은 감수).

### 4-5. 회차 → 교안 링크는 만든다

> "만들어야지." → §3-1로 반영.

## 5. 순서 — 확정

```
1단계  ✅ 에러 문구 정정(errorCopy.ts) — CURRICULUM_ANALYSIS_FAILED 신설,
          DATA_INTEGRITY_VIOLATION 일반화. 완료(uncommitted, 이 브랜치)
2단계  §3 — 회차→교안 링크 + URL 버전화(동작은 아직 부분적)
─────────────────────────────────────────────────  ← 45차 §1 + 44차 R1 대기선
3단계  새 버전 올리기 다이얼로그(§4-3·4-4) — MG-08/OP-06 교안 상세
4단계  버전 이력 UI(§4-1) + MG-09 버전별 행 분리(44차 R2 옴)
```

2단계는 지금 착수 가능. 3·4단계는 대기선 위 두 항목이 와야 연다.
