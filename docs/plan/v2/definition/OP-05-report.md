# OP-05 · 리포트

## 1. 한 줄

미니프로젝트 이해도 검증 결과를 **미프 마지막 회차 종료 시점**에 얼려서 내보내는
고정 스냅샷 문서.

> **⚠ 이 문서는 원래 2종(탭 2개)이었다.** "수업 진단"(미프 종료 후 확정)과 "기수
> 결산"(빅프 종료 후 확정)으로 나뉘어 있었는데, **빅프로젝트가 제품에서 빠지면서**
> (사용자 결정 — "우리는 그냥 미니프로젝트들로만 이해도를 검증한다") 그 분리 근거가
> 사라졌다. 아래 §2는 예전에 "왜 둘인가"를 답했던 절인데, 지금은 "왜 하나로
> 합쳤나"로 뒤집혀 읽어야 한다.

## 2. 원래 둘이었던 이유 — 지금은 사라짐

예전 표(참고용으로 남긴다):

| | **수업 진단**(구) | **기수 결산**(구) |
|---|---|---|
| **앵커** | 교안 개념 | 본인 커밋 영역 |
| **재는 것** | 커리큘럼이 전달됐나 | 이 사람이 자기 코드를 아나 |
| **발행** | 미프 마지막 회차 후 | 빅프 종료 후 |

**둘 다 빅프에 의존했다** — "본인 커밋 영역"은 빅프의 정의였고, "빅프 종료 후"는
발행 시점을 가르는 기준이었다. 빅프가 없어지자:

- 앵커가 하나(교안 개념)만 남아 **가를 축이 없어졌다**.
- 발행 시점도 하나(미프 전체 회차 완료)만 남았다.
- 우수 교육생·반별 위험자 비율·집단 미달은 원래도 **순수 미프 판정**(9-3·9-2·9-6)
  이라 빅프를 기다릴 이유가 없었다 — "기수 결산" 탭에 있었던 건 편집상의 위치였지
  데이터 의존이 아니었다.

**"미프 → 빅프" 성장 지표 섹션(구 §6④)은 완전히 삭제됐다** — 그 섹션의 존재
이유(*"계단은 양쪽 동일하다. 앵커만 다르다. 그래서 미프와 빅프의 도달 단계를
비교할 수 있고, 그게 성장 지표의 근거다"*)가 빅프 삭제로 통째로 무너졌다. 이제
빅프가 없으니 비교할 "이후" 상태 자체가 없다.

### 셋 이상으로 늘리지 않는다 — 이 원칙은 유지

17번 294줄이 매니저 리포트를 프로젝트 하위로 흡수한 이유가 *"들어갈 때마다 회차부터
고르게 된다"* 였다. **회차별 리포트를 만들지 않는다** — 6~8개면 아무도 안 읽고,
회차 단위는 **OP-04 현황 탭**이 이미 답한다.

## 3. 이 문서가 될 수 없는 것

RealiZe이 재는 것은 **코드 이해도 하나**다. 취업률·수료율·출석·만족도를 재지 않고,
14번 1163줄이 `최종 성적 산출식`을 **범위 밖**으로, `수료생 리포트 열람`을
*"중요하지 않음"* 으로 뒀다.

> **이 문서는 "기수 종합 평가서"가 아니라 "이해도 측정 결과"다. 수료 판정을 하지 않는다.**

없는 것을 있는 척하면 **문서 전체가 못 믿을 것**이 된다.

## 4. 탐색 도구가 아니라 문서다

18번 2-4: *"고정 시점 스냅샷 · 기수 말 1회 · **외부 제출용**"*.

| | |
|---|---|
| **필터·드릴다운이 없다** | 있으면 **읽는 사람마다 다른 문서**가 된다 |
| **값이 얼어 있다** | `2026-08-25 미프 6차 발행 시점으로 고정` |
| **순서가 고정** | 목차가 곧 목차다 — **섹션 전환이지 앵커 스크롤이 아니다**(H2) |
| **나가는 링크가 없다** | **진행 중 상태에서만** OP-02로 유도한다(그건 아직 문서가 아니므로) |
| **분석 컴포넌트 재사용** | 반 비교를 새로 그리지 않고 **그 시점 값으로 얼린 것**을 넣는다(18번 명시) |

**화면 안에는 값·라벨·범례·분모만 둔다** — 설계 근거와 기획 조항 번호는 전부 크롬 밖(I3).

## 5. 섹션 5개

### ① 요약 — 무엇을 빼고 세었나

4칸(교육생 · 미프 회차 · 검증 개념 · 채점 응시) + 제외 한 줄.

**분모를 맨 앞에 둔다** — 외부 문서라 각주로 달면 **119건이 왜 빠졌는지**를 못 찾는다.

| 뺀 것 | 근거 |
|---|---|
| 미집계(미응시·무효·중단) | 14-1 · 9-4 |
| 재시험 결과 | 11장 — *"조직 단위 수치는 1차만"* |

### ② 개념별 도달 분포 — 본체

```
검증 개념              도달 단계 분포            2단 이하   묻지 못함
                                                            코드에 없어서
교안 AI_LLMOps v2 · 5건
Supervisor 패턴과 역할 분리 구조  ██62 ███71 ███58 ██37   57%   6명
 역할 p.41 · 3차·4차                                   133/234명
```

| 설계 결정 | 왜 |
|---|---|
| **행이 개념이지 회차가 아니다** | 같은 개념이 여러 회차에 쓰인다 — 회차로 나누면 **그 개념에 대한 기수 전체의 답**이 흩어진다 |
| **교안·섹션으로 묶는다** | 검증 개념은 **출처 교안·섹션을 달고 다니고**(14번 438줄), 고칠 대상이 **개념이 아니라 교안 그 페이지**다 |
| **`묻지 못함`이 검증 개념 선정의 레버** | 문항이 **만들어지지 않은 것**이라 못한 게 아니고(F3), 크면 **개념 선택이 프로젝트와 안 맞았다**는 신호(18번 137줄). 개념을 고르는 사람이 오퍼레이터(6-3) |
| **2단 이하를 센다** | 9-2 위험 판정선이자 11장 재시험 대상선 — **이미 정의된 경계** |
| **평균 도달을 쓰지 않는다** | 합칠 수 없는 값(A1·A2). `2.5`는 *"절반이 멈췄다"* 와 *"모두가 어중간하다"* 를 구분 못 한다 |
| **정렬은 심각도 내림차순**(교안 그룹도·그룹 안 개념도) | "교안을 고칠 곳"이 본체인데 나열 순서가 회차 등장 순(우연)이면 제일 심한 개념을 스캔해서 찾아야 한다 — 정렬이 순위를 말한다(E2) |

### 라벨을 두 번 바꿨다

| | |
|---|---|
| `코드에 없음` | *"코드가 없다"* 로 읽힌다 — **학생이 제출을 안 한 것**처럼 |
| `문항 없음` | 여전히 **무엇이 없다**는 말이라 뜻이 안 온다 |
| **`묻지 못함`** | **시스템이 물어보지 못한 것** — 일어난 일 그대로 |

MG-08은 `코드에 없던 사람`, OP-04는 `코드 매칭 0`이라 부르는데 **둘 다 "무엇이 없다"**
쪽이다. 열 머리에 `코드에 없어서`를 작게 붙여 **범례를 안 봐도 읽히게** 한다.

색은 **MG-02 램프 그대로**(1단 `#df6150` → 4단 `#57b083`). 도달 단계는 기획에 정의된
눈금이라 **절대 색**을 쓸 수 있다 — OP-02가 상대 색을 쓰는 것과 다르다. **몇 %부터
"심각"인지는 색으로 표시하지 않는다**(E8) — 위 정렬이 이미 순위를 말한다.

### ③ 회차별 — 어느 회차가 어려웠나

행 = 미프 1~N차, 그 회차 검증 개념 3건 + 분포 + 2단 이하.

**회차끼리 비교가 성립하는 이유** — 개념은 다르지만 **같은 250명이 봤다.** 3차가 무거운
것은 *"그 회차 개념 묶음이 어려웠다"* 로 읽는다. **반을 가로로 비교하는 OP-02와 축이 다르다.**

**반별 추이를 넣지 않는다** — *"어디로 가고 있나"* 는 **진행 중 도구**(OP-02)이고 끝난
기수에서는 최종 상태가 답이다.

### ④ 우수 교육생 — 명단 + 내보내기

**되돌린 것이다.** 17번 283줄이 오퍼레이터에게 남긴 테이블을 OP-02 재설계에서 같이
지웠었다.

> *"**오퍼레이터** | 250명이라 개인을 못 본다. **정렬·비교가 진짜 필요** → 테이블 유지"*
> *"**매니저** | 위험은 면담이, 오늘 것은 대시보드가 담는다 → 테이블 삭제"*

**17번이 지운 것은 매니저 쪽뿐**이고, 오퍼레이터는 **명부 메뉴가 없어**(17번 3-2) 갈 곳이
여기뿐이다.

### 위험과 우수는 대칭이 아니다

| | 집계로 되나 | |
|---|---|---|
| **위험** | ⭕ | 처리는 매니저가 한다. 오퍼레이터가 알 것은 **어느 반에 몰렸나**뿐 → 반 비교가 답함 |
| **우수** | ❌ | **누구인지가 정보 그 자체**다. `우수 N명`은 아무 말도 안 한다 |

### 9-3의 프로필이 여기서 완성된다

> *"미프 6~8회 × 반당 1~2명이면 **프로젝트별 프로필**이 쌓인다."*

`6회 중 5회 우수`는 **진행 중에는 안 나오는 값**이고, **1회짜리와 5회짜리는 다른 사람**이다.

| 열 | |
|---|---|
| 교육생 · 반 | |
| **미프 우수** | `5회 · 1·2·3·5·6차` — 회차 번호까지 |

> **⚠ 삭제됨 — "빅프 최저 도달" 열.** 예전엔 미프 우수(교안 개념을 안다) + 빅프
> 최저 도달(자기 코드를 안다) **둘 다면 진짜**라는 논리로 두 번째 열이 있었다.
> 빅프가 없어지면서 그 열도 같이 사라졌다 — 지금은 미프 우수 판정 하나뿐이다.

**용도를 화면이 정하지 않는다** — 이 제품은 취업 연계를 하지 않으므로 **명단을 내보내고
기관이 알아서 쓴다.** `추천`·`배치` 같은 말을 쓰면 **안 하는 일을 약속**하게 된다.

**위험자 명단은 넣지 않는다** — 기수 끝에 받아도 조치를 못 하고, *"수료했지만 이해도 낮음"*
명단은 **낙인**이다(A3).

**등수를 붙이지 않는다** — 우수 횟수 순으로 정렬만 한다.

**컷을 두지 않는다** — 회차마다 반당 1~2명씩 쌓인 결과라 미리 정한 상한이 아니다.
컷을 두면 그 컷이 내가 만든 임계값이 된다(E8). **대신 페이지네이션** — 문서라도 한
화면에 명단을 세로로 다 쌓지 않는다. 표 표준 그대로 **푸터에 범위 좌 + 페이저
중앙**(E3). **PDF에는 전부 들어간다** — 페이지네이션은 화면 사정이지 문서 내용이 아니다.

### ⑤ 반 · 집단 미달 — 운영

**둘을 한 섹션에 둔다.** 반 편차만 있으면 외부 독자가 *"C반 매니저 문제"* 로 읽는다.
**집단 미달은 개인 위험 사유에서 빠지고 반 단위로 처리된 건**이라(9-6), 같이 두면
**반 값의 일부가 개인이 아니라 구조에서 왔다**는 것이 보인다.

| | |
|---|---|
| **마지막 확정 회차 기준** | 9-2 위험 판정은 **회차 단위**이고 **기수 전체 위험자라는 개념이 기획에 없다.** 누적으로 세면 **새 정의를 만드는 것**(E8)이라, OP-01이 *"미프 2차 기준"* 이라 쓰는 것과 같이 **기준 회차를 밝힌다** |
| **등수·담당 매니저 이름을 쓰지 않는다** | 18번 116줄. **문서가 밖으로 나가면 그 통제가 안 먹으므로 애초에 넣지 않는다** |
| **기수 전체가 기준선** | 반 값만 늘어놓으면 *"이게 높은 건가"* 를 알 수 없다. **관측값이지 화면이 정한 임계값이 아니라 E8에 안 걸린다**(OP-01 실제 구현 `ClassCompareBlock.tsx`와 같은 로직 — 기준선을 넘는 반만 danger색) |
| **OP-02 마지막 회차 열과 같은 값** | 같은 계산이어야 두 화면이 안 어긋난다(D1) |
| **드릴다운이 없다** | 문서라서. 반 안을 보려면 OP-02를 연다 |

### 집단 미달은 발생 사실만 쓴다

9-6이 *"시스템은 표시까지만 한다"* 고 했고 처리는 기관 판단이다 — **사람이 쓴 처리 기록을
화면이 요구하지 않는다.** 무엇을 했는지는 문서 밖의 일이다.

`검증 개념 / 회차·반 / 미달 N of M` 세 칸이면 끝난다. **같은 개념이 여러 건이면 반복
횟수만 사실로 배지에 붙인다** — "반 운영이 아니라 교안 신호"라는 해석은 화면이 문장으로
단정하지 않는다(§4 "값·라벨·범례·분모만"). 판단은 읽는 사람(오퍼레이터)의 몫이고, 화면은
셀 수 있는 사실(반복 횟수)만 준다.

**빈 상태에 "없음"만 쓰지 않는다** — 외부 문서라 **0건이 무엇을 뜻하는지**를 같이 쓴다.
그리고 **섹션을 숨기지 않는다** — 목차에서 사라지면 *"안 봤는지 없었는지"* 구분이 안 된다.

**PDF가 확정 전에 잠기는 이유** — 확정 전 값을 내보내면 **나중 값과 다른 문서**가 돌아다닌다.

## 8. 액션

섹션 전환 · **PDF 내보내기** · **CSV 내보내기**(우수 교육생만). 그 외에 나가는 곳이 없다.

## 10. 기획에 없는데 넣은 것 — 명시

근거를 댈 수 있는 것과 **제가 정한 것**을 갈라 둔다.

| | 상태 |
|---|---|
| **③ 회차별 섹션** | 18번 2-4 목차는 `개념별/반비교/집단미달` 3개뿐. **추가한 것.** 근거는 *"회차 설계가 오퍼레이터 레버(OP-03)"* 라는 추론 |
| **명단 CSV**(우수 교육생) | 사용자 결정(*"리스트 뽑아서 회사 측에서 알아서 쓴다"*) |
| **우수 명단 페이지네이션** | 문서에 페이저를 두는 것은 **화면 사정**이지 기획 항목이 아니다 |
| **`묻지 못함` 라벨** | 기획 어휘는 `코드에 없던 사람`(MG-08) · `코드 매칭 0`(OP-04). **읽히게 고쳐 쓴 말** |
| **집단 미달 반복 배지** | "N건 반복"이라는 사실 표시는 §5⑤의 "값·라벨만" 원칙에서 파생한 **설계 판단** — 해석 문장은 안 쓰고 셀 수 있는 사실만 표시 |
| **반별 위험자 비율 배색**(기준선 + 초과 시 danger) | OP-01 대시보드가 **실제로 이미 구현한** `ClassCompareBlock.tsx` 로직을 그대로 따른 것 — 이 화면이 새로 만든 규칙이 아니다 |
