# 메뉴 트리 재설계

> **지금 확정하는 것이 새 기준이다.** 이전 명세서의 결정 번호나 현재 목업 구조에 맞출 이유가 없다 — **14·16번이 정한 제품에 가장 맞는 형태**로 다시 짠다.
>
> 이 문서는 **무엇이 메뉴가 되는가**까지만 정한다. 화면 안쪽은 15번 차수에서 그린다.

## 0. 결론

```
슈퍼어드민 (1)          오퍼레이터 (5)         매니저 (5)            교육생 (2)
──────────────         ──────────────        ──────────────        ──────────
기관                    대시보드               대시보드              홈
(⚙ 플랫폼 설정)         분석                   히트맵                내 리포트
                       프로젝트               면담      ● 4
                       리포트                 ─────────
                       ─────────             교육생
                       운영 관리              프로젝트
```

**메뉴에 없지만 존재하는 화면이 셋 있다** — 면담 브리프(모드) · 교안 뷰어(링크) · 교육생 상세(목록에서 진입). 4절.

## 1. 이 트리를 만든 원칙

| # | | 나온 결정 |
|---|---|---|
| **1** | **역할마다 하는 일이 다르면 메뉴도 다르다.** 상위 역할이 하위의 superset일 이유는 없다 | 오퍼레이터에 `면담`·`교육생` 없음 |

| **4** | **하루에 안 여는 것은 한 층 아래로** | 교안 → 운영 관리 (2026-08-18 수정: 교안은 기관 전체 자산이라 기수 스코프인 운영 관리와 안 맞아 `#217`에서 예외로 확정 — 사이드바 최상위. 6-1 참고) |

| **6** | **배지는 처리하면 줄어드는 숫자에만** | 면담 예정 ⭕ / 위험 인원 ❌ |

## 2. 역할 넷 — 각자 무엇을 하는 사람인가

메뉴를 정하기 전에 이걸 먼저 정해야 한다. **하는 일이 메뉴다.**

| 역할 | 한 문장 | 하루 동선 |
|---|---|---|
| **슈퍼어드민** | 기관을 만들고 플랫폼을 돌린다 | 기관 목록 → 사용량 |
| **오퍼레이터** | **조직을 세팅하고 기수 전체를 관측한다** | 대시보드 → 분석 → (기수 초에) 운영 관리·프로젝트 |
| **매니저** | **담당 반 학생을 관리하고 면담한다** | 대시보드 → 면담 → 교육생 |
| **교육생** | 제출하고 응시하고 결과를 본다 | 홈 → (세션) → 내 리포트 |

**오퍼레이터와 매니저의 차이가 이 설계의 축이다.**

```
오퍼레이터   조직을 세팅한다 · 전체를 본다      →  학생을 직접 상대하지 않는다
매니저       학생을 상대한다 · 담당 반만 본다    →  조직 구조를 바꾸지 않는다
```

**"오퍼레이터 = 매니저가 하는 것 전부 + 하나 더"가 아니다.** 담당 반이 없는 사람에게 면담 목록은 남의 일이고, 명단을 통째로 관리하는 사람에게 교육생 명부는 이미 손에 있는 것이다.

## 3. 메뉴 트리

### 3-1. 매니저 — 5

```
┌───────────────────────────────────────────────────┐
│  대시보드    오늘 할 일 (인박스)                   │
│  히트맵      반 × 개념 패턴 · 집단 미달            │
├───────────────────────────────────────────────────┤
│  면담  ● 4   위험자 큐 → [브리프 열기]             │
├───────────────────────────────────────────────────┤
│  교육생      명부(우수 배지) → 개인 상세           │
│  프로젝트    팀 · 제출 현황 · 결과(리포트)         │
└───────────────────────────────────────────────────┘
```

**구분선이 `보다 / 하다 / 찾다`를 나눈다.** 글자 라벨은 넣지 않는다 — **순서가 이미 말하고 있다.**

**`위험·우수 테이블`과 `리포트`가 메뉴에서 빠졌다.** 둘 다 다른 곳에 이미 있다(5절 후반).

| 배지 | |
|---|---|
| 면담 | 예정 건수 — 면담하면 줄어든다 |

### 3-2. 오퍼레이터 — 5

```
┌───────────────────────────────────────────────────┐
│  대시보드    기수 전체 · 반 필터                   │
│  분석        전체 · 히트맵 기수→반→팀→개인         │
├───────────────────────────────────────────────────┤
│  리포트      기수 종합 · 최종                      │
│  프로젝트    생성 · 교안 연결 · 질문 항목 3건      │
├───────────────────────────────────────────────────┤
│  운영 관리   기수 · 반 · 명단 · 매니저 · 교안 · 비용│
└───────────────────────────────────────────────────┘
```

**`면담`과 `교육생`이 없는 이유**

| | |
|---|---|
| **면담** | 담당 반이 없다. 면담은 배정된 학생과 하는 것이고, **적체 여부는 대시보드 지표로 본다** — 남의 면담 목록을 여는 화면은 만들지 않는다 |
| **교육생** | 명단은 `운영 관리 › 명단`에 이미 있다. 개인을 보려면 **히트맵 드릴다운의 끝**으로 간다 |

**`프로젝트`는 남는다.** 프로젝트를 만들고 교안을 연결하고 **질문에 쓸 항목 3건을 확정하는 것이 오퍼레이터의 일**이다(14번 6-3). 조직 세팅에 가깝지만 **기수마다 6~8번 반복**되므로 `운영 관리` 안에 묻으면 안 된다.

### 3-3. 교육생 — 2

```
  홈          이번 회차 · 제출 · 응시 · 재시험
  내 리포트   회차별 리포트 + 문답 아카이브
```

**아카이브를 `내 리포트` 안에 넣는다.** 별도 메뉴로 빼면 3개가 되는데 **"이번 것"과 "지난 것"은 같은 장소의 시제 차이**다.

**세션과 제출은 메뉴가 아니다.** 홈에서 진입하고, 세션은 전체화면이라 애초에 나브가 없다.

### 3-4. 슈퍼어드민 — 1

```
  기관        목록 → 기관 상세(개요 · 오퍼레이터 · 사용량·비용 · 설정)
  ⚙ 우상단    플랫폼 설정 (모델 티어·단가 / 슈퍼어드민 계정)
```

**실질 화면이 하나다.** 계정 몇 개와 단가 표는 화면이라기보다 **설정 항목**이라 nav 자리를 주지 않는다.

### 3-5. 한눈에

| | 슈퍼어드민 | 오퍼레이터 | 매니저 | 교육생 |
|---|---|---|---|---|
| 대시보드 | — | **지표판** | **인박스** | (홈) |
| 위험·우수 테이블 | — | ⭕ 분석 탭 | **❌** → 면담 | ❌ |
| 히트맵 | — | ⭕ 분석 탭 | **⭕ 단독 메뉴** | ❌ |
| **면담** | — | **❌** | **⭕** | ❌ |
| 리포트 | — | ⭕ 기수 종합 | **❌** → 프로젝트 › 결과 | 내 것만 |
| 교육생 | — | **❌** | ⭕ | — |
| 프로젝트 | — | **설정** | **운영 + 결과** | ❌ |
| 운영 관리 | — | ⭕ | ❌ | ❌ |
| 기관 | ⭕ | ❌ | ❌ | ❌ |
| **개수** | **1** | **5** | **5** | **2** |

**개수가 권한 순으로 늘지 않는다.** 그게 맞다 — **하는 일이 다르면 메뉴가 다르다.**

**오퍼레이터와 매니저가 5개로 같지만 겹치는 것은 둘뿐이다**(대시보드·프로젝트, 그나마 내용이 다르다). 같은 제품의 같은 층인데 **공유 메뉴가 40%밖에 안 된다** — 두 역할을 하나로 묶으면 안 되는 이유가 여기 있다.

## 4. 메뉴가 아닌 화면 셋

**모든 화면이 메뉴를 가질 필요는 없다.** 진입 경로는 세 가지다.

| 경로 | 성격 | 예 |
|---|---|---|
| **메뉴** | 아무 때나 가는 장소 | 대시보드 · 분석 · 면담 |
| **링크** | 다른 화면이 가리켜서 가는 곳 | 교안 뷰어 |
| **모드** | 작업하는 동안만 열리는 것 | 면담 브리프 · 검증 세션 |

### 4-1. 면담 브리프 = 모드

```
면담 목록 → [브리프 열기] → 전체화면 · 사이드바 가림 → [저장] → 목록
```

면담 30분 동안 다른 데로 갈 일이 없다. **화면이 다르게 생겼다는 것 자체가 "지금 작업 중"이라는 신호**이고, 검증 세션이 전체화면인 것과 같은 이유다.

**브리프는 열 때 만든다**(면담 직전 데이터로). 위험 학생 전원 것을 미리 만들어 둘 이유가 없다.

### 4-2. 교안 뷰어 = 링크

**매니저가 교안 목록을 훑을 시나리오가 없다.** 여는 순간은 둘뿐이고 둘 다 특정 개념을 가리킨다.

| 여는 순간 | 필요한 것 |
|---|---|
| 브리프의 `교안 3장 36~46쪽` | **그 개념 한 장** |
| 리포트의 교안 위치 안내 | 〃 |

```
오퍼레이터 · 사이드바 최상위 교안   매니저 · 메뉴 없음
────────────────────────         ────────────────────────
목록 · 등록 · 재분석 · 정제 결과    개념 상세 1장  ← 링크로만
가르친 항목                       위치 · 정의
```

(2026-08-18 수정: 원래는 `운영 관리 › 교안` 탭으로 뒀는데, 교안이 기수 스코프가 아니라
기관 전체 자산이라 `#217`에서 사이드바 최상위 `/operator/curricula`로 옮겼다 —
아래 6-1 참고.)

**매니저 쪽은 "교안 화면"이 아니라 뷰어다.** 목록도 검색도 없다. **필요한 것만 주면 화면 하나가 통째로 사라진다.**

### 4-3. 교육생 상세 ↔ 브리프 — 겹쳐 보이는 이유와 해소

데이터가 80% 겹친다. **그런데 다른 물건이다.**

| | 교육생 상세 | 면담 브리프 |
|---|---|---|
| **성격** | **조회** — 이 사람 어떤가 | **작업** — 지금 30분 무엇을 하나 |
| 진입 | 명부 · 위험 테이블 · 히트맵 셀 | **면담 목록에서만** |
| 범위 | **여러 회차 누적** | **이번 회차 1건** |
| 쓰기 | ❌ | ⭕ 기록 3칸 |
| 나가기 | 뒤로 | **[저장] → 상태 변경** |
| 사이드바 | 보인다 | **가린다** |

> ### 누적은 교육생 상세, 1건 처리는 브리프.

**중복을 없애는 배분**

| | 어디에 |
|---|---|
| 회차별 도달 **격자** | **히트맵.** 교육생 상세는 그 행을 잘라 쓰고 다시 그리지 않는다 |
| 회차 사이의 **이벤트 이력** | 교육생 상세(타임라인) — 브리프는 직전 면담 1건만 인용 |
| 문답 원문 | 교육생 상세(타임라인에서 펼침) · 브리프는 **막힌 문항만** |
| 면담 기록 | 브리프에서 **쓰고** 교육생 상세에서 **읽는다** |

**브리프는 교육생 상세의 축약본이 아니다.** 전체가 필요하면 브리프 안의 `전체 이력 ↗`로 간다 — **복사하지 않는다.**

**덤:** 오퍼레이터가 드릴다운으로 개인 상세에 닿아도 **브리프 버튼이 없다.** 브리프 진입로가 면담 목록 하나뿐이고 오퍼레이터에겐 그 목록이 없기 때문 — **권한 조건문 없이 구조로 막혔다.**

## 5. 두 역할이 같은 화면을 볼 때

현재 목업은 `curriculum`·`project-workspace`에서 **뷰 토글 + 흐린 버튼**으로 처리한다. 이 방식을 버린다.

> ### 범위만 다르면 한 화면. **할 수 있는 일이 다르면 다른 화면.** 흐린 버튼은 쓰지 않는다.

**흐린 버튼을 버리는 이유**

| | |
|---|---|
| 영원히 흐리다 | 역할이 고정이라 매니저가 언젠가 그 버튼을 쓸 일이 없다 |
| 설명이 없다 | 토글은 목업 데모 장치다. 실제 사용자는 자기 뷰만 보므로 **왜 흐린지 알 수 없다** |
| 더 비싸다 | 잠긴 액션마다 툴팁·에러·감사 로그 분기가 붙는다. **화면 두 장이 조건문 스무 개보다 싸다** |

**"나누면 유지보수 두 배"는 아니다.** 나누는 것은 **라우트**이고 표·카드·모달 **컴포넌트는 공유**한다.

### 화면별

| 화면 | 처리 | |
|---|---|---|
| **프로젝트** | **분리** | 하는 일이 안 겹친다 ↓ |
| **교안** | **분리 + 매니저 쪽 축소** | 4-2 |
| **분석 · 리포트** | **한 화면** | 구조 같고 범위만 다르다 |
| **대시보드** | **분리** | 장르가 다르다 ↓ |

**프로젝트 — 겹치지 않는다**

```
오퍼레이터                      매니저
──────────────────────         ──────────────────────
프로젝트 생성                    팀 편성
교안 연결                        제출 현황 · 독촉
질문 항목 3건 확정               결과 → 리포트 진입
요구사항 입력                    결과 공개 범위
일정 · 회차
```

**나브 라벨은 양쪽 다 `프로젝트`.** 각자에게 하나뿐이라 혼동이 없고, `설정`/`운영` 같은 접미사는 **자기가 못 보는 쪽의 존재를 알려주는 라벨**이라 필요 없다.

**대시보드 — 위젯이 아니라 장르가 다르다**

| | 매니저 (25명) | 오퍼레이터 (250명·10반) |
|---|---|---|
| 장르 | **인박스** — 오늘 할 일 목록 | **지표판** — 운영 이상 |
| 묻는 것 | **"누구부터?"** | **"어디가 처지나?"** |
| 형태 | 마감 순 단일 목록 | 회차 상태 + 반 비교 + 조치 필요 |

**25명 스코프에서 평균·추이는 정보를 거의 주지 않는다** — 명단을 직접 보면 된다. 집계가 의미를 갖는 것은 개인을 볼 수 없는 오퍼레이터 쪽이다. **범위가 아니라 화면이 하는 일이 다르므로 분리한다**(18번 2-1·3-1).


**위험·우수 테이블 — 매니저에게는 중복이다**

같은 행이 세 군데 있었다.

| 화면 | 행 |
|---|---|
| 대시보드 인박스 | 이름 · 유형 배지 · `2/3` · 대기 6일 · [브리프] |
| 분석 › 위험·우수 | 이름 · 유형 배지 · `2/3` · 최저 단계 · 힌트 |
| 면담 목록 | 이름 · 유형 배지 · `2/3` · 대기 일수 · [브리프] |

**위험 = 면담 대상이다.** 위험 유형이 켜지면 면담 목록에 자동 등재되므로(14번 9-2 · 16번) **두 목록의 모집단이 정의상 같다.** 면담 목록은 상태(예정/후속/종결)까지 관리하는데, 분석 테이블은 정렬만 다른 같은 사람들이다.

**25명 스코프에서 위험자는 5명 안팎이다.** 다섯 줄을 위해 화면을 하나 더 두지 않는다.

| | |
|---|---|
| **오퍼레이터** | 250명이라 개인을 못 본다. **정렬·비교가 진짜 필요** → 테이블 유지 |
| **매니저** | 위험은 **면담**이, 오늘 것은 **대시보드**가 담는다 → **테이블 삭제** |

그래서 매니저의 `분석`에는 히트맵만 남고, 이름도 **`히트맵`**으로 바꾼다(원칙 5).

**우수는 교육생 명부로 간다.** 우수는 면담 대상이 아니고 용도가 **팀 구성**이다(14번 9-3). 필요한 순간은 팀을 짤 때이고 그때 여는 화면은 명부다 — **배지와 정렬로 충분하다.**

**리포트 — 매니저에게는 프로젝트 산출물이다**

리포트는 **항상 "어느 회차의" 리포트**다. 독립 메뉴로 두면 들어갈 때마다 회차부터 고르게 되고, 현재 리포트 목록이 하는 일이 정확히 그것이다.

→ **`프로젝트 › 결과` 탭으로 흡수한다.** 개인 리포트 진입은 어차피 대부분 교육생 상세·브리프의 링크다.

**오퍼레이터 리포트는 남긴다.** 기수 종합·최종이라 프로젝트 아래가 아니다. 비대칭이지만 **하는 일이 다르니 맞다.**

**스코프 문구 규칙**

| 남길 것 | 지울 것 |
|---|---|
| `A·B·C반 138명` — 지금 보는 범위 | `총괄은 기수 전 반(480명)` — 남의 범위 |

**자기 화면에서 남의 권한 범위를 설명하지 않는다.**
