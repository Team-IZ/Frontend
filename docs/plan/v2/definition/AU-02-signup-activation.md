# AU-02 · 회원가입 · 계정 활성화

> **v1 구조 유지.** 변형 A/B 두 개 그대로, 교육생 이름 읽기전용 그대로.
> **바뀐 것은 하나** — 초대 모달의 `권한(담당/총괄)` 선택이 사라진다(총괄/담당 폐기).

## 1. 한 줄

초대 링크로 들어와 **비밀번호를 정하고 동의**하면 계정이 열린다.

**초대 링크 클릭이 이메일 소유 증명**이다. 별도 인증 메일 단계가 없고 이메일 필드는 초대값 읽기전용.

## 2. 진입 · 이탈

| | |
|---|---|
| 진입 | **초대 메일 링크만.** 직접 URL 접근 불가 |
| 이탈 | 완료 → AU-01 |

**토큰이 변형을 결정한다.** 사용자가 고르지 않는다.

## 3. 뷰 — 변형 2

### 변형 A · 회원가입 (오퍼레이터 · 매니저)

```
회원가입
  이메일    kim@green.com          (읽기전용 · 초대값)
  이름      [                    ]  ← 본인이 입력
  비밀번호  [                    ]  정책 힌트
  비밀번호 확인 [                ]
  ─────────────────────────────
  [필수] 이용약관                   전문 ↗
  [필수] 개인정보 수집·이용          전문 ↗
                          [가입하기]
```

### 변형 B · 계정 활성화 (교육생)

```
계정 활성화
  이메일    lee@student.com        (읽기전용 · 명단값)
  비밀번호  [                    ]  정책 힌트
  비밀번호 확인 [                ]
  ─────────────────────────────
  [필수] 이용약관 · 개인정보 수집·이용 · 코드/문답 AI 분석 · 기관 공유
         AI 분석 미동의 시 이해도 검증 불가
  [선택] 서비스 개선 활용
                        [활성화하기]
```

**교육생에게 이름을 다시 받지 않는 이유:** 명단(OP-06)에 이름+이메일이 이미 등록돼
있다. **활성화 전에도 반 편성·미제출 관리가 돌아야 하므로** 이름이 그때 필요하다.

**동의 항목 수가 다른 이유:** 교육생은 코드·문답·이탈 기록까지 처리 대상이다.
필수 전체 동의 전 제출 불가, 선택은 미동의해도 진행.

## 4. 데이터

| 읽는다 | 토큰(역할·기관·이메일, 교육생은 명단 이름) |
|---|---|
| 쓴다 | 비밀번호 해시 · `status=ACTIVE` · 토큰 사용완료 · 동의 기록(약관 버전·시각·항목) |

## 5. 액션

가입/활성화 · 전문 보기(펼침) · 만료 시 재발송.

## 6. 상태

| | |
|---|---|
| 토큰 만료 | `초대 링크가 만료되었습니다` + `[재발송]` |
| 토큰 재사용·위변조 | `유효하지 않은 링크입니다` + 문의 · 보안 로그 |
| 이미 가입/활성화 | `이미 활성화된 계정입니다` + `[로그인]` |
| 명단 외 이메일(B) | `명단에 등록되지 않은 계정입니다` + 문의 |
| 비밀번호 정책 미충족 | 필드 하단에 **못 채운 기준만** |
| 필수 미동의 | 제출 비활성 + 미체크 항목 강조 |
| 저장 실패 | 계정 생성 전 차단 + 재시도 (동의만 남는 상태를 만들지 않는다) |

## 7. 안 하는 것

| | 어디에 |
|---|---|
| 자유 회원가입 | **없다** — 초대 기반 |
| 역할 선택 | **없다** — 토큰이 정한다. **초대 모달에도 권한 선택이 없다**(초대하는 화면이 곧 역할) |
| 반·기수 배정 | **OP-06 › 매니저 · 배정 모드** |
| 이메일 변경 | 프로필 소관 |
