# MG-06 · 교육생 상세 — 타임라인

## 1. 한 줄

**한 사람에게 회차 사이에 무슨 일이 있었는지**를 시간 순으로 보여준다.

> 격자(회차 × 개념)는 히트맵이 이미 갖고 있다. 이 화면의 고유 가치는 **그 사이의
> 사건** — 다시 봤는지, 면담에서 뭐라고 했는지, 약속한 것을 했는지다.

## 3. 뷰 — 탭을 쓰지 않는다

```
김OO · A반 3팀                                      [지속 저점]

미프1 ███ ███ ██    미프2 ██ ███ █    미프3 █ ██ █   ← 히트맵 1행 재사용
──────────────────────────────────────────────────────
미프 3차
  7/12  세션 · 1단 · 2단 · 4단                     ▾ 근거 보기
  7/15  리포트 발행 · 다시 보기 2건 지정
  7/18  다시 보기 · HITL Trigger 1단 → 2단
  7/21  면담 · 시간 부족 → 일정 조정               ⚠ 다음: 흐름 그려오기 미확인
미프 2차
  ...
                                    [전체 ▾] 세션 · 면담 · 리포트
```

**탭 3개(종합/세션/면담)를 버린 이유**

| | |
|---|---|
| 종합 | 격자가 **히트맵 개인 행과 같은 데이터**다. 다시 그리면 복사가 된다 |
| 세션·면담 | 같은 시간축의 **이벤트 유형**일 뿐이다. 탭으로 가르면 *"7/18 다시 보기가 7/21 면담보다 먼저"* 라는 **순서가 사라진다** |

**필터는 탭이 아니라 토글.** 기본 `전체`이고 순서를 깨지 않는다.

| | 무엇을 답하나 |
|---|---|
| **전체** | 유형을 섞어야 순서가 보인다 — `다시 보기 → 면담` 인지 `면담 → 다시 보기` 인지 |
| **세션** | 회차마다 어디서 멈췄나 |
| **다시 보기** | 회복인가 미응시인가 |
| **리포트** | 언제 발행됐고 몇 건 지정됐나 |
| **면담** | 지난번에 뭐라고 했나 — **면담 전에 가장 많이 보는 뷰** |

**리포트가 유형에 들어가는 이유:** 발행일이 다시 보기 창의 기산점(11절 — `발행 +3일`)
이라 **몇 건 지정됐고 언제 닫히는지**를 따로 훑을 수 있어야 한다.

> **필터는 걸러내기만 한다.** 이벤트는 한 번만 정의하고 유형으로 뽑는다 — `면담`만
> 켰더니 `전체`에 없던 이벤트가 나오면 **필터의 정의가 깨진다.** 옆의 건수(`세션 2건`)가
> 그 계약을 눈에 보이게 한다.

**표기는 MG-08과 같다** — `1단 도달 · 다시 설명 2회`, 축별 `도달/미달`. 두 화면이 다른
말을 쓰면 매니저가 같은 값을 두 번 배운다.

## 4. 데이터

| 이벤트 | 펼치면 |
|---|---|
| 세션 | 개념별 도달 단계 + **축별 도달/미달 · 근거 한 줄**. 원문 문답은 없다(10-3) |
| 다시 보기 | `HITL Trigger 1단 → 2단` — 히트맵의 `↑`와 같은 사건 |
| 리포트 발행 | 다시 보기 지정 건수 |
| 다시 보기 | 어느 개념이 어떻게 바뀌었나. **미응시로 창이 닫혔으면 그것도 이벤트**다 |
| 면담 | 기록 3칸(무엇 때문 / 어디로 / 다음에 할 것) — **읽기만** |

헤더의 격자는 **MG-02의 그 행을 그대로 쓴다**(같은 색 스케일).

### 없는 기능을 화면이 만들지 않는다 — 검토에서 걸린 것

목업을 그리고 나서 **화면의 모든 값이 지금 플로우에서 실제로 나오는지** 역으로 대조했다.
두 개가 **없는 데이터**였다.

| 지웠다 | 왜 |
|---|---|
| `다음 면담 7/28 (금) 14:00` | **면담 일정 예약 기능이 없다.** 16번 4-1의 상태는 `예정/후속 필요/종결`이고 지표는 `대기 최장 N일`뿐 — 일시 필드가 없다. 칸반·완료율을 *"주 1~2건이라"* 버린 문서가 캘린더를 가질 리 없다 → **`면담 예정 · 대기 6일`** |
| `✓ 확인했습니다 · 7/26 확인` | **확인 처리 액션이 정의되어 있지 않다.** 16번엔 `미확인`만 있고 확인 체크도 일시도 없다 — **미확인은 있는데 확인이 없는 비대칭** → **다음 면담이 열리면 해소**(`7/26 면담에서 다뤘습니다`). 새 필드가 늘지 않고 16번의 *"다음 회차 브리프에 뜬다"* 와 정확히 맞는다 |

### 축별 도달/미달을 쓰지 않는다 — 도달 단계에서 100% 파생

세션을 펼치면 `코드이해 도달 · 설계논리 미달 · 대안비교 미달 · 반례대응 미달`을 그렸다가
지웠다. 3-1이 **계단**이다.

```
1단 = 코드이해   2단 = 설계논리   3단 = 대안비교   4단 = 반례대응
```

**`1단`이면 나머지가 자동으로 결정된다.** 같은 값을 두 번 그리는 것이다. 남기는 것은
**근거 서술**뿐이고, 그게 실제 데이터이자 매니저가 면담에서 쓰는 문장이다.

**힌트 기록은 개념별로 붙인다**(`재진술 2회` / `자력`). 세션 총합으로 쓰면 **어느 개념에서
썼는지 모른다** — 코드를 모르는 매니저에게 총합은 행동으로 이어지지 않는다.

### 반 문제(9-6)는 근거문에 섞지 않는다

`다른 구성과 비교에서 멈췄어요 — 이건 반 전체가 같은 지점입니다`라고 붙였다가 뗐다.
**출처가 다르다** — 앞은 AI 채점 근거(이 사람 답변), 뒤는 집계 판정이다. 한 문장으로
붙이면 **근거문이 반 통계를 아는 것처럼** 보인다. 근거 아래 별도 줄로 내린다.

### 세로선은 프로젝트 경계가 아니라 회차 경계다

v1의 *"프로젝트 경계에 구분선"* 을 그대로 가져왔다가 근거를 다시 봤다. **v1은 여러
회차가 한 프로젝트에 속할 수 있는 구조**였고, v2는 **1 프로젝트 = 1 회차**(미프 3차가
곧 프로젝트)라 **모든 열이 경계**다. 특별한 선이 아니다.

선은 두되 말하는 것을 바꾼다 — **회차마다 검증 개념도 과제도 다르므로 가로로 이어 읽지
않는다.** `3단 → 1단`은 같은 것이 나빠진 게 아니라 **다른 것을 물은 결과**일 수 있다.

### 미확인 약속을 헤더에 올리지 않는다 — 처음 판단을 뒤집었다

한때 헤더 맨 위에 `⚠ 다음에 할 것이 아직 확인되지 않았습니다`를 뒀다. 근거는
*"이 화면에서 가장 행동에 가까운 정보"* 였는데, **이 화면에서는 그걸로 할 수 있는 게
없다** — 조회 화면이라 확인 처리 버튼도, 브리프로 가는 길도 없다(17번 4-3).

게다가 **네 번째 자리**였다.

| 어디 | 무엇 |
|---|---|
| **MG-04 브리프** | 16번 4-3이 정한 자리 — *"다음 회차 브리프 ①칸 위에 ⚠와 함께 뜬다"* |
| **MG-03 면담 목록** | `◐ 후속 필요 · 1차 면담 7/21 · "다음에 할 것" 미확인` |
| MG-06 타임라인 | 면담 이벤트에 `⚠ 약속 미확인` + 펼치면 3칸에 한 번 더 |
| ~~MG-06 헤더~~ | ← 뺐다 |

**PRODUCT.md — 한 데이터는 한 곳에서만 그린다.** 이 화면 몫은 **면담 이벤트에 붙은
`⚠` 하나**다. 시간축 위에 있으니 *"7/21에 약속했고 그 뒤로 아무 일도 없다"* 가 위치로
읽힌다 — 헤더로 올리면 그 시간 정보가 사라진다.

**헤더에 남는 것:** 이름 · 위험 배지 · 판정식(`2단 이하 1개 → 2개`)뿐이다.

### 팀을 사람 옆에 박지 않는다

헤더에 `A반 1팀`이라고 썼다가 뺐다. **팀은 프로젝트마다 재편성되는 유동값**이라 사람에
고정으로 붙일 수 없다 — 미프 3차의 1팀이 미프 2차엔 3팀이었을 수 있고, 그러면 **바로
아래 격자 3회차와 어긋난다.**

| | |
|---|---|
| 헤더 · 이동 경로 | **기수 · 반**까지 (`7기 · A반`) — 반은 기수 내내 고정 |
| 회차 헤더 | **그 회차의 팀** (`미프 3차 · 1팀 · 7/12–7/21`) |

**팀은 회차의 속성이지 사람의 속성이 아니다.** 회차 줄에 붙이면 *"미프 2차엔 3팀이었네"*
가 시간축 위에서 그냥 읽힌다.

### 격자 — 최근 3회차 · 프로젝트 경계에 구분선

**3회차인 이유:** 위험 판정이 2회 비교(9-2)라 **3개면 추세가 보인다.** 그 이상은
헤더가 격자에 잡아먹힌다.

**경계에 점선을 긋는다**(v1에서 살린 것). 회차마다 과제가 달라 **경계를 넘는 등락은
퇴보가 아닐 수 있다.** 열 이름(검증 개념)도 회차마다 다르므로 **가로로 이어 읽지
않는다**는 것을 선으로 말한다.

### 회차가 늘면 접는다

**최근 2회차만 펼치고 이전은 접는다.** 미프가 10개면 스크롤이 끝나지 않는다.

## 5. 액션

이벤트 펼치기 · 유형 필터 · (없음 — 이 화면은 쓰지 않는다).

## 6. 상태 — 왜 그렇게 정했나

> **케이스 표는 목업에 있다** — [`manager/trainee-detail.html#cases`](../wireframe/manager/trainee-detail.html#cases).

### 빈 칸 셋은 뜻이 다르다

| 표기 | 무엇 | 처방 |
|---|---|---|
| `―` | 그 회차에 **그 개념 문항이 없었다** | 개념 선택 문제 |
| `0단` | 물었는데 못 했다 | 그 개념을 다룬다 |
| `아직 응시한 회차가 없습니다` | 아예 안 봤다 | 응시부터 |

**이벤트 0일 때 격자를 `문항 없음`으로 채우지 않는다** — 그건 코드에 개념이 없어 못 물은 것이고 여기는 아직 응시를 안 한 것이다.

### 위험이 없으면 아무것도 붙이지 않는다

배지도 약속 줄도 없다. **축하 문구를 넣으면** 다음 회차에 그것이 없을 때 나쁜 신호로 읽힌다.

### 면담 기록 미작성

브리프에서 저장하지 않은 경우 이벤트에 `기록 없음`으로 남는다 — **면담이 있었다는 사실 자체는 지우지 않는다.**
## 7. v1(SC-M06)에서 버린 것

v1은 **3탭 + 컴포넌트 스택 7개**였다. 매니저가 강사가 아니게 되면서 대부분 근거를 잃었다.

| v1 | 버리는 이유 |
|---|---|
| 5축 통합표 · 포커스 축 그래프 · 레이더 | **점수 전면 제거**(10-3) |
| 세션 질답 전문 · 채점 근거 구간 | 매니저 화면에 **원문 없음**. 코드를 판단하지 않는다 |
| 기여 귀속 카드 · 커밋 이메일 경고 | **미프는 기여도를 쓰지 않는다** |
| 에이스 배지 | 우수는 **명부**에 있다 — 팀을 짤 때 쓰는 정보(14번 9-3) |
| 개입 카드 스트림 | 개입 5종 → **면담 1종**. 타임라인 이벤트로 흡수 |

**하나만 살렸다** — *프로젝트 경계에 구분선.* 회차마다 과제가 다르다는 사실은 지금도
그대로다.

> **17번 4-3의 `문답 원문 → 교육생 상세(타임라인에서 펼침)`은 10-3과 충돌한다.**
> 10-3이 이긴다 — 매니저 화면에 원문 경로는 없다. 펼치면 **도달 단계 + 축별 도달/미달
> + 근거 한 줄**까지다.
