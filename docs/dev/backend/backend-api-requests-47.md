> 46차 R1 배포를 확인하다 반 두 개에서 실제로 부딪혔습니다. 46차 회신 §1-4·§5에서
> 미리 알려주신 바로 그 증상입니다 — **부분 UNIQUE 인덱스 마이그레이션이 아직
> 적용되지 않았습니다.** 코드는 고쳐졌고 목록에서는 정상으로 보이지만, 해체한
> 이름·번호를 다시 쓰려는 순간 매니저 실사용이 막힙니다.
>
> 측정 — 2026-08-25 · Lambda(그린컴퍼니 dev) · `minseo@naver.com`(매니저 · 7기 담당
> E반·G반)

## 0. 한눈에

|---|---|---|
| **R1** | G반: 팀 해체 후 같은 이름으로 재생성 → `409 TEAM_NAME_DUPLICATED` | 🔴 반 다시 짜기가 실사용에서 막힙니다 |

두 건 다 **새 버그가 아니라** 46차 회신 §1-4가 예고한 그대로입니다 — "적용 전까지는
해체한 팀이 목록에서는 사라지지만, 그 이름으로 다시 만들면 여전히 409입니다." 그
예고가 실제 사용 흐름(반 다시 짜기)을 막는 수준이라 다시 알려드립니다.

---

## 1. 🔴 R1 — G반, 해체한 이름을 다시 못 씁니다

### 재현

```
대상  미프 5차 (projectId 871802ba-d318-428b-ba14-855226e3ab9a)
      G반 (classId a7ec3075-a490-5285-ad8b-ba29d4809505)

DELETE /projects/{projectId}/teams/{"7팀"의 teamId}
  → 정상 처리 (팀 목록에서 사라짐, 팀원 2명이 미배정으로 정확히 돌아옴 — 46차 R1
    수정이 여기까지는 제대로 동작합니다)

POST /projects/{projectId}/teams  { classId: G반, name: "7팀" }
  → 409
```

응답 원문:

```json
{
  "timestamp": "2026-08-25T08:26:54.818646640Z",
  "status": 409,
  "error": "CONFLICT",
  "code": "TEAM_NAME_DUPLICATED",
  "message": "그 반에 같은 이름의 팀이 이미 있습니다."
}
```

화면에는 이 메시지를 그대로 옮긴 안내가 떴습니다 — "같은 이름의 팀이 이미 있습니다 ·
그 반 안에서 팀 이름은 겹칠 수 없습니다 — 다른 이름을 지어 주세요." 코드가 갈라진
덕에(46차 §4) 화면은 정확한 문구를 보여줄 수 있었지만, **매니저 입장에서는 목록에
없는 이름인데 "이미 있다"는 안내를 받는 것**이라 여전히 당황스럽습니다.

---

## 2. 🔴 R2 — E반, 자동 배분이 여전히 막힙니다

### 재현

```
대상  같은 프로젝트 · E반 (classId 5d5866b3-5522-56c6-abe1-da4ba3ef2dcd)
      팀 0개로 보임(46차 R1 조회 필터 수정으로 정상 표시) · 미배정 25명

자동 배분 실행(5명씩 · 무작위)
  → 409, 다이얼로그에 그대로 표시:
    "팀 번호가 겹쳤습니다 · 그 반에 같은 번호의 팀이 이미 있습니다. 다시 시도해 주세요."
```

46차 §2-3에서 "팀을 전부 해체한 반은 자동 배분을 영영 쓸 수 없었다"고 짚어 주신
그 케이스가, 코드 수정만으로는 아직 안 풀린다는 뜻입니다 — 이 반은 실제로 팀이
0개인데도 예전에 붙었던 팀 번호들이 여전히 자리를 잡고 있어 채번이 겹칩니다.

## 3. 부탁드리는 것

두 건 다 46차 §1-4에서 준비해 두셨다고 하신 부분 UNIQUE 인덱스 마이그레이션
(`WHERE deleted_at IS NULL`)이 적용되면 해소되는 것으로 이해하고 있습니다.

- 그 마이그레이션, 지금 적용된 상태인가요? 저희 쪽에서 보기엔 아직인 것 같습니다.
- `psql`/Docker가 없어 사전 검증을 못 하셨다고 하셨는데, 적용 자체도 같은 이유로
  막혀 있는 상태라면 저희가 도울 수 있는 부분이 있는지 알려주세요(예: 마이그레이션
  SQL을 함께 검토하거나, 반이 작은 테스트 환경에서 먼저 돌려보는 것 등).
- 재현에 쓴 G반 "7팀"(방금 다시 만들려다 막힌 이름)과 E반은 그대로 남겨 뒀습니다 —
  적용 후 바로 이 상태로 재확인하실 수 있습니다.
