# 이해도 검증 — 채점·진행 규칙

> 이 문서 하나로 **세션이 어떻게 돌아가고 점수가 어떻게 나오는지** 전부 알 수 있게 썼다. 개발·리뷰는 여기서 한다.
> 각 규칙마다 **왜 그렇게 정했는지**를 붙였다. 근거가 없는 항목은 "가정값"이라고 적었다 — 그건 반박해도 된다.

---

## 0. 한 장 요약

| | 규칙 |
|---|---|
| **재는 방식** | 항목별 점수 합계가 아니라 **도달 단계(계단)** |
| **계단** | 0 무응답 · 1 기술 · 2 한계 · 3 대안 · 4 판단 |
| **판정 구조** | 단계 진행은 **통과식(비보상)** · 단계 안의 질은 **루브릭 점수(연속)** |
| **총합 점수제** | 쓰지 않는다 — 안 물어본 문항을 0점으로 만들게 된다 |
| **용어** | "통과"가 아니라 **"도달"**. 1단 도달은 합격이 아니다 |
| **문항** | 학습목표 3개 = 문제 3개. 코드 지점은 학생마다 다르게 |
| **힌트** | **2단** — 재진술 / 위치 제시. **선택지 제공은 금지** |
| **한 단계 한도** | 힌트 2개까지. 다 쓰면 다음 단계로 |
| **종료** | **단계 2개 연속 미도달** |
| **4단 범위** | **3문제 전부** |
| **시간** | 단계 통과마다 예산 지급 · 중위 15분 · 상한 30분 |
| **3문제 종합** | 위험 = 학습목표 단위 · 우수 = 최저값 · 추이 = 평균 |
| **정렬값** | 자력 1.0 / 힌트1 0.7 / 힌트2 0.4 의 합 |
| **위험** | 2단 이하인 학습목표가 있으면 |
| **우수 교육생** | 반 상위 1~2명 · 근거 병기 |

## 1. 전제 — 무엇을 어떻게 재는가

### 1-1. 재려는 것

> 학생이 제출한 코드를, 그 학생이 실제로 이해하고 있는지 확인한다.

AI로 코드를 만들 수 있으니 **산출물만으로는 학습 여부를 알 수 없다.** 그래서 대화로 확인한다.

그리고 이 도구의 성격이 아래 모든 규칙의 기준이다.

| | |
|---|---|
| 무엇인가 | **매니징 도구(B2B LMS)** + 이해도 검증이라는 특수 기능 |
| 1순위 사용자 | **매니저** |
| 평가인가 학습인가 | **둘 다.** 평가이되 학습 지원 |
| 결과물 목표 | **v1 MVP.** 현실적 구현 가능성이 우선 |

### 1-2. 계단 — 항목별 점수가 아니라 도달 단계

이해했다는 것은 **얼마나 깊이까지 설명할 수 있는가**다. 그리고 그 깊이는 항목이 아니라 **순서가 있는 단계**다.

| 단계 | 이름 | 학생이 할 수 있는 것 | 질문 |
|---|---|---|---|
| **0** | 무응답 | — | (답이 없거나 요점을 놓침) |
| **1** | **기술** | 무엇을 하고 어떻게 연결되는지 말한다 | "이 부분이 무슨 일을 하나요? 어디랑 연결되나요?" |
| **2** | **한계** | 언제 깨지는지 말한다 | (구체적 상황을 던지고) "이러면 어떻게 되나요?" |
| **3** | **대안** | 다른 방법이 있다는 것을 말한다 | "다른 방식으로 할 수도 있었을까요?" |
| **4** | **판단** | 그중 왜 이걸 골랐는지 말한다 | "그 대안들 중에 왜 지금 방식을 골랐나요?" |

**이 순서는 위계다.** 3단을 설명하는 학생은 2단도 설명할 수 있다. 그래서 하나의 숫자로 적어도 정보가 손실되지 않는다.

**왜 최상위가 "왜 골랐나"인가 — 근거 셋**

**① 선택 정당화는 대안 인식을 전제한다.** 무엇을 안 고르고 이걸 골랐는지 말하려면 안 고른 게 무엇인지 알아야 한다. 그래서 3단(대안) 위에 온다.

**② "왜"는 두 종류이고, 순서가 낮은 쪽을 걸러낸다.**

| | 예 | 성격 |
|---|---|---|
| **의도 진술** | "성능 때문에요" | 사후 합리화가 쉽다 → 낮음 |
| **선택 정당화** | "A와 B가 있었는데 우리 제약이 C라서 A를 골랐다" | 대안 공간 인식 필수 → **최상위** |

대안(3단)을 못 낸 학생에게 "왜 골랐나"를 물으면 사후 합리화만 나온다. **대안을 먼저 요구하고 그다음에 선택 이유를 물으면 짜맞추기가 구조적으로 어려워진다.**

**③ 검증이 어려운 지표를 최상위에 둔다.** "언제 깨지나"는 구체적 조건을 대야 하고 코드로 확인 가능하다. "왜 골랐나"는 진술이라 검증이 어렵다. 최상위는 소수만 도달하므로 오판의 영향 범위가 작고, **위험 학생 판정은 검증 쉬운 하위 단계에서 이뤄진다.** 오판 비용이 큰 쪽에 검증 쉬운 지표를 놓는 것이 측정 설계의 기본이다.

### 1-3. 무엇에 대해 묻는가 — 앵커 2층

```
학습목표  = 무엇을 물을지   → 반 전체가 같음  (난이도·비교 가능성)
코드 지점 = 어디서 물을지   → 학생마다 다름  (개인화)
```

**두 층을 나누는 것이 핵심이다.** 학습목표만 앵커로 쓰면 팀원 전원이 거의 같은 질문을 받는다(미프는 팀당 레포 하나일 수 있다). 같은 "Service 역할 분리"를 A는 `ingress.yaml`에서, B는 `service.yaml`에서 물으면 비교 가능성은 유지되고 개인화는 확보된다.

**학습목표는 매니저가 프로젝트 생성 시 3~5줄 입력한다.** 강의계획서에 있는 내용을 옮겨 적으면 된다. PDF 자동 추출은 만들지 않는다 — 그걸 만들면 완성 전까지 아무것도 못 하고, 실제 교안은 암호가 걸려 있어 파싱이 바로 막힌다.

| | 미프 | 빅프 |
|---|---|---|
| **앵커** | **학습목표** (교안 기반) | **본인 커밋 영역** |
| 문제 수 | 3개 | 1~2개 |
| 범위 | 전체 코드 | 자기 영역 |
| 성적 | 반영 | **미반영** — 성장 지표 + 팀 내부 파악 |

**계단은 양쪽 동일하다.** 앵커만 다르다. 그래서 미프와 빅프의 계단 값을 비교할 수 있고, 그게 성장 지표가 성립하는 근거다.

### 1-4. 기존 5축 루브릭의 자리

**계단은 "어디까지 갔나"만 말한다. "그 단계 안에서 얼마나 좋았나"는 말하지 않는다.** 그래서 두 층으로 쓴다.

| | 쓰임 |
|---|---|
| **도달 단계** | **판정용** — 위험·우수, 재시험 대상, 히트맵 |
| **축별 서술** | **진단용** — 리포트에 "무엇이 어떻게 부족했는지" |

| 단계 | 대응 축 |
|---|---|
| 1단 기술 | 코드 이해 |
| 2단 한계 | 반례 대응 |
| 3단 대안 | 대안 비교 |
| 4단 판단 | 설계 논리 |
| (전 단계) | 자기 수정 — **판정에서 빼고 관찰 항목으로** |

**자기 수정을 판정에서 빼는 이유:** 이건 이해도가 아니라 태도·메타인지다. 그리고 측정 조건에 결함이 있었다 — 질문이 "학생이 스스로 인정하도록 **유도**"하게 설계돼 있는데 채점 기준은 "**스스로** 제시"였다. 유도해놓고 자발성을 채점할 수는 없다.

**대신 관찰 항목으로 남긴다.** "실력은 부족하지만 지적을 받아들이는 학생"과 "인정하지 않는 학생"은 개입 방법이 다르다. 성적이 아니라 **개입 설계 정보**다.

루브릭 원문은 부록에 있다.

## 2. 판정 방식 — 통과식과 점수를 섞는다

### 2-1. 왜 총합 점수제가 아닌가

**근거 ① 이 구인은 보상을 허용하지 않는다.**

| | 뜻 | 예 |
|---|---|---|
| 보상적(compensatory) | 한 곳이 낮아도 다른 곳이 높으면 상쇄 | 총점 합산 |
| **비보상적(conjunctive)** | 각 영역에서 최소 기준을 넘어야 함 | 운전면허 필기·실기 각각 통과 |

> 자기 코드가 무엇을 하는지 설명하지 못하는데 대안을 잘 알아서 총점이 높다.
> **이 학생은 코드를 이해한 것인가?**

아니다. 대안 지식은 일반 지식이지 **이 코드에 대한** 이해가 아니다. **1단을 못 하면 그 위는 의미가 없다.**

**근거 ② 총합 점수제는 결측을 0으로 만든다.**

1단에서 막혀 2·3단을 받지 않은 학생의 2·3단을 0점으로 계산하면 **"못한 것"과 "안 물어본 것"을 섞는 것**이다. 그러면 1단에서 막힌 학생은 총점이 자동으로 바닥이 되어 **전원 재시험 대상**이 된다.

미응시 학생을 0점으로 보면 안 되는 것과 정확히 같은 오류다. 실제 테스트에서 결과를 봤다 — 무성의 응시자가 "전 항목 1점"이라는 실력 판정을 받았다.

**계단은 이 문제가 원천적으로 없다.** "1단에서 멈춤"은 결측이 아니라 **완결된 관측값**이다. 메울 빈칸이 생기지 않는다.

### 2-2. 그런데 순수 통과제는 해상도가 없다

통과/미통과 이진이면 같은 "2단 도달" 안에서 잘한 사람과 겨우 넘은 사람이 구분되지 않는다. 위험 판별에는 충분하지만 **우수 판별이 안 된다.**

### 2-3. 확정 — 두 층

| 층 | 방식 | 쓰임 |
|---|---|---|
| **단계 진행** | 비보상적 통과 | 위험 판정 · 재시험 대상 |
| **단계 안의 질** | 5축 루브릭 점수 | 우수 판별 · 정렬 |

**결과 표기**

```
Service·Ingress 역할 분리    3단 도달 · 평균 3.7
```

3단 도달로 위험 여부가 갈리고, 3.7로 같은 3단 안에서 순위가 난다.

### 2-4. "통과"가 아니라 "도달"이다

**단계는 합격/불합격이 아니라 어디까지 갔는가**다.

> **1단 도달** = 무엇을 하는지는 설명함. **이것만으로 합격이 아니다.**

위험 기준이 **2단 이하**이므로 1단 도달자는 힌트를 받았든 안 받았든 여전히 위험이다. 화면·리포트·프롬프트 전부 "도달"로 쓴다.

## 3. 진행 규칙

### 3-1. 힌트와 단계 이동은 다른 축이다

- **힌트** = 같은 질문을 도와주는 것 (**같은 단계 안**)
- **단계 이동** = 다음 질문으로 가는 것

**이 구분이 없으면 "2연속 실패"가 정의되지 않는다.**

### 3-2. 한 단계의 흐름

```
[N단 질문] ── 답변
   │
   ├─ 도달 ─────────────────────────▶ [N+1단 질문]   (자력)
   │
   └─ 미도달
        │
      [힌트 1 · 재진술] ── 답변
        │
        ├─ 도달 ─────────────────────▶ [N+1단 질문]   (힌트1)
        │
        └─ 미도달
             │
           [힌트 2 · 위치 제시] ── 답변
             │
             ├─ 도달 ────────────────▶ [N+1단 질문]   (힌트2)
             │
             └─ 미도달
                  │
                  └──▶ N단 미도달 확정 = 실패 1회
```

### 3-3. 종료 규칙 — 단계 2개 연속 미도달

```
1단 미도달 (힌트 2개 소진) ── 실패 1회
   │
   └─▶ [2단 질문을 한 번 던진다]        ← 위계 오류 보험
          │
          ├─ 도달 → 위계 예외. 실패 카운트 초기화하고 3단으로 계속
          │
          └─ 미도달 ── 실패 2회 ─────▶ 종료. 도달 = 1단 미만
```

**왜 한 단계에 머물지 않는가**

1. 시간이 통제되지 않는다
2. 힌트를 더 주면 답을 알려주는 것이 되고, 그러고 도달로 치면 측정이 무의미하다
3. **막힌 학생을 계속 붙잡는 것은 교육적으로 해롭다** — 무력감을 학습한다. 실제 테스트에서 봤다. 어떤 학생은 마지막 질문에 **질문 문장을 그대로 복사해 붙였다**

**왜 그래도 다음 단계를 한 번은 던지는가**

위계가 아직 검증되지 않았다. 1단은 **말로 설명하는 게 약해서** 막혔는데 2단(언제 깨지나)은 아는 학생이 있을 수 있다. 그리고 **이 예외가 얼마나 자주 나오는지가 위계 검증 데이터로 운영 중에 자동 축적된다.**

### 3-4. 상태 전이표 (개발용)

| 현재 | 답변 판정 | 다음 | 기록 |
|---|---|---|---|
| N단 질문 | 도달 | N+1단 질문 | N단 = 자력 |
| N단 질문 | 미도달 | 힌트1 | — |
| N단 힌트1 | 도달 | N+1단 질문 | N단 = 힌트1 |
| N단 힌트1 | 미도달 | 힌트2 | — |
| N단 힌트2 | 도달 | N+1단 질문 | N단 = 힌트2 |
| N단 힌트2 | 미도달 | **N+1단 질문** | N단 = 미도달 · **실패 +1** |
| N+1단 (직전 실패 상태) | 도달 | N+2단 질문 | **실패 카운터 0으로** |
| N+1단 (직전 실패 상태) | 미도달 | **종료** | 실패 2 |
| 4단 | 도달/미도달 | 다음 문제 | 문제 종료 |

**최종 도달 단계 = 도달로 기록된 가장 높은 단계.**

### 3-5. 종료 문구

> ❌ "세션이 종료되었습니다"
> ✅ **"이 부분은 리포트에서 자세히 설명해드릴게요"**

"잘려나간 것"이 아니라 "여기가 볼 지점"으로 읽힌다. 비용 0.

## 4. 힌트 규격 — 2단

| | 힌트 | 내용 | 자력 판정 |
|---|---|---|---|
| **1** | **재진술** | 질문을 다르게 표현. **정보 추가 없음** | 힌트1 |
| **2** | **위치 제시** | "이 파일의 이 함수를 보세요". **답은 없음** | 힌트2 |

**단계당 최대 2회.** 세션 전체 한도는 따로 두지 않는다 — 단계별 한도가 이미 상한을 만든다.

### 왜 힌트를 규격화하는가

**즉흥적으로 주면 안 된다.** 같은 실력의 두 학생이 한 명은 1번, 한 명은 3번 받으면 그 차이가 **학생 차이가 아니라 생성 차이**가 된다. 그러면 "혼자 갔는지"를 신호로 쓸 수 없다.

동적 평가에서 쓰는 방법이다 — 힌트를 약한 것부터 강한 것 순서로 **미리 고정**해두고 **몇 번째 힌트에서 통과했는지**를 지표로 쓴다. "혼자 할 수 있는 것"과 "도움받으면 할 수 있는 것"의 거리를 재는 것이다.

### 선택지 제공은 금지 사항이다

"A와 B 중 어느 쪽일까요" 같은 보기 제시는 **힌트가 아니라 금지**다.

**① 측정 가치가 0이다.** 선택지를 주면 답을 주는 것이고, 그 답으로는 아무것도 판정할 수 없다.

**② 실제로 오염이 발생했다.** 테스트에서 질문 안에 보기 세 개가 들어가 있었고, 학생이 **"저는 3번"** 이라고 답해 **만점**을 받았다. 대안을 제시한 게 아니라 골랐다. 보기가 없던 질문을 받은 다른 학생은 1점이었다. **같은 축인데 질문에 보기가 붙었는지에 따라 1점과 5점이 갈렸다.**

**③ 학습 목적이라면 리포트에서 하면 된다.**

> **질문 생성 프롬프트에 "예시 보기를 제시하지 말 것"을 명시한다.**

## 5. 4단 범위와 시간

### 5-1. 4단은 3문제 전부에서 본다

**"가장 잘 답한 1문제만 4단"은 하지 않는다.**

**① 우수 판별은 반복 관측이 필요하다.** 한 문제에서 4단은 **그 주제를 원래 잘 알았을 수도** 있다. 세 문제에서 4단이라야 **주제와 무관한 일관된 능력**이다. 우수 판별은 결과가 무거운 판정(추천·팀 구성)이라 반복이 적어도 되는 게 아니라 **더 필요하다.**

**② 되돌아가면 맥락이 날아간다.** "가장 잘한 1문제"는 3문제를 다 끝내야 알 수 있다. 그러면 문제3까지 하고 다시 문제1로 돌아가 "아까 그거 왜 골랐어요?"를 물어야 한다.

**③ MVP에 불필요한 분기다.** 그냥 이어서 가면 로직이 없다.

### 5-2. 시간 — 단계 통과마다 예산을 지급한다

**고정 상한을 두지 않는다.** 계단은 정의상 **능력 검사**(어디까지 가나)이지 속도 검사(정해진 시간에 몇 개)가 아니다. 시간으로 자르면 잘라낸 곳이 능력의 한계가 아니라 시간의 한계가 된다.

그리고 시간을 촘촘히 잡으면 **재려는 것이 아닌 것**(타이핑 속도, 코드 읽는 속도)이 점수에 섞인다. 4단은 가장 생각할 게 많은 단계라 이 오염이 가장 크다.

**얕게 끝나는 학생은 시간이 필요 없다.** 1단에서 막힌 학생에게 30분을 줘도 결과가 같다. 그래서 **예산을 미리 나눠주지 않고 단계를 통과할 때마다 지급한다.**

| 단계 | 지급 | 누적 |
|---|---|---|
| 1단 기술 | **3분** (코드 읽기 포함) | 3분 |
| 2단 한계 | +2분 | 5분 |
| 3단 대안 | +2분 | 7분 |
| 4단 판단 | +3분 | 10분 |

| 학생 | 문제당 | 3문제 총 |
|---|---|---|
| 1단에서 막힘 | 3~5분 | **9~15분** |
| **2단 정지 (중위 예상)** | 5분 | **15분** |
| 3단까지 | 7분 | 21분 |
| 4단까지 전부 | 10분 | **30분** |

**중위 15분, 상한 30분.** 30분은 최상위 소수만 해당하고, 그 학생들에게는 부담이 아니라 학습 기회다.

> **"4단 진입 시 계속할지 물어보기"는 하지 않는다.** 선택권을 주면 우수 판별이 실력 있는 사람이 아니라 **의욕 있는 사람**을 잡게 된다.

### 5-3. 답변 길이는 3~5문장으로 안내한다

실제 테스트 답변이 대부분 3~5문장이었고 **한 문장 답변은 1점을 받았다.** 그 길이면 판정에 충분하다. 그리고 길게 쓰는 게 유리하면 안 된다(장황함 편향).

**하드 제한이 아니라 안내로 둔다.** 제한하면 그것도 재려는 것이 아닌 것을 재게 된다.

### 5-4. 붙여넣기

| 할 것 | 비용 |
|---|---|
| 붙여넣기 이벤트 **차단** | JS 몇 줄 |
| 차단해도 **시도는 기록** | 매니저 화면에 플래그 |
| **단계별 시간 예산**(5-2) | 다른 AI에 물어볼 여유를 없앰 |

우회는 가능하다. 마찰을 만드는 것으로 충분하고, 예외를 무한히 가정하면 끝이 없다. **자동 부정행위 판정은 하지 않는다** — 오탐 비용이 크고 "확정은 사람이" 원칙에도 걸린다.

**한계는 명시한다.** 세션 중에 학생이 다른 AI에 물어보는 것을 방법론으로는 막을 수 없다. 실제로 작동하는 방어는 **자기 코드의 특정 라인을 근거로 묻는 것**과 **시간 압박** 둘뿐이다.

## 6. 문제 3개를 어떻게 합치나

한 학생이 3문제에서 각각 다른 단계에 도달한다. **용도마다 합치는 방식이 다르고, 섞으면 안 된다.**

| 용도 | 방식 | 왜 |
|---|---|---|
| **위험 판정** | **합치지 않는다. 학습목표 단위로 본다** | 평균 내면 보상성이 되살아난다 |
| **우수 판별** | **최저값** (또는 전부 4단 도달) | 일관성이 조건 |
| **성장 추이** | 평균 | 시계열 비교용 |

### 위험을 평균으로 내면 안 되는 이유

> Service 1단 · Volume 4단 · CICD 3단 → **평균 2.7단**

평균 2.7이면 괜찮아 보인다. **그런데 이 학생은 Service를 전혀 모른다.** 한 목표에서 무너진 것을 다른 목표가 가려버린다 — 2절에서 배제한 보상성이 여기로 되돌아온다.

**학습목표 단위로 봐야 처방이 나온다.** "평균 2.7단"으로는 아무것도 못 하지만 **"Service에서 1단"** 이면 무엇을 다시 가르칠지가 바로 나온다.

### 재시험 대상도 학습목표 단위다

> 3문제 중 **2단 이하인 학습목표만** 재시험. 3개 전부가 아니다.

문제 단위 재시험이라는 결정과 정확히 맞물린다.

## 7. 정렬값 — 자력도를 가중치로

단계가 정수 4개뿐이라 우수 판별의 해상도가 부족하다. **자력도를 넣으면 풀린다.**

| 도달 방식 | 값 |
|---|---|
| 자력 도달 | **1.0** |
| 힌트1 후 도달 | **0.7** |
| 힌트2 후 도달 | **0.4** |
| 미도달 | 0 |

**학생 값 = 도달한 단계들의 합.**

| 예 | 계산 | 값 |
|---|---|---|
| 1단 자력 · 2단 자력 · 3단 힌트1 · 4단 미도달 | 1.0+1.0+0.7 | **2.7** |
| 1단 힌트2 · 2단 미도달 | 0.4 | **0.4** |
| 1~4단 전부 자력 | 1.0×4 | **4.0** |

### 화면과 내부값을 나눈다

```
화면   3단 도달 · 일부 도움 필요
내부   2.7
```

매니저는 읽기 쉬운 표현을 보고, 우수 판별과 위험 목록 정렬은 연속값으로 이뤄진다. **계산은 덧셈이라 구현 부담이 없다.**

> 가중치 1.0 / 0.7 / 0.4는 **가정값**이다. 운영 데이터로 조정한다.

## 8. 판정

### 8-1. 위험 — 절대 기준

**2단 이하인 학습목표가 있으면 위험 신호다.** 학습목표 단위로 본다(6절).

반 평균이 낮아도 못하는 사람은 못하는 것이다. **기준에 못 미치면 도와야 하므로 절대 기준이 맞다.**

### 8-2. 위험 유형

| 이름 | 정의 | 최소 표본 |
|---|---|---|
| **단계 하락** | 이전 미프보다 도달 단계가 내려감 | 미프 2개 |
| **지속 저점** | 여러 미프에서 계속 2단 이하 | 미프 2~3개 |
| **무효 응시** | 0단 (8-4) | 1개 · 즉시 |
| **코드 대비 이해 부족** | 빅프 — 기여도 높음 · 계단 낮음 | 빅프 1회 |
| **참여 저조** | 빅프 — 기여도 낮음 · 계단 낮음 | 빅프 1회 |

**"기초 공백"이 아니라 "지속 저점"인 이유** — 데이터가 말해주는 것은 "계속 낮다"(결과)이고 "기초가 비어 있다"(원인)가 아니다. 계속 낮은 이유는 기초 부족일 수도, 참여 부족일 수도, 말로 설명하는 게 약한 것일 수도 있다. **원인을 이름에 박으면 매니저가 진단을 건너뛰고 처방부터 한다.**

**유형은 겹칠 수 있다.** 하나만 고르게 만들면 우선순위 규칙이 필요한데 그 규칙에 근거가 없다.

**정렬은 "2단 이하 학습목표 개수"로 한다.** 근거가 있고 계산이 명확하다. 반이 25명이라 한 화면에 들어오므로 정렬이 완벽하지 않아도 매니저가 전체를 훑을 수 있다.

### 8-3. 우수 교육생 — 반 상위 1~2명

**반마다 존재한다.** 그 반에서 정렬값(7절)이 가장 높은 1~2명이다. 3문제 중 **최저값**으로 비교한다.

**왜 상대 기준인가** — 용도가 상대적 질문이다. "누구를 팀 리더로 쓸까", "이 반에서 눈여겨볼 사람이 누구인가"는 그 반 안에서의 비교다. 매니저가 25명 중 진짜 눈여겨볼 사람은 1~2명이고, 3명을 넘어가면 "눈여겨본다"가 아니라 "목록을 관리한다"가 되어 실용 가치가 떨어진다.

**근거를 함께 표시한다.** 라벨만 있으면 강도를 알 수 없다.

> 우수 교육생 · 김OO — **4단 자력 도달** · 미프 3차
> 우수 교육생 · 이OO — 3단 도달(힌트 1회) · 미프 3차

두 번째 줄을 보면 매니저가 **"이 반은 전체적으로 얕다"** 를 읽을 수 있다.

**프로젝트별로 따로 뽑는다.** 프로젝트마다 판정이 달라진다(프론트 우수가 클라우드 위험일 수 있다). 미프 6~8회 × 반당 1~2명이면 누적되어 **프로젝트별 프로필**이 쌓인다.

**팀 구성에 쓰는 것은 우수 명단이 아니라 그 프로필이다.** "이 학생은 클라우드에서 4단, CI에서 2단"이 팀 짤 때 필요한 정보다.

### 8-4. 무효 응시 (0단)

**채점하지 않고 판정과 평균에서 뺀다.**

실제 테스트에서 오분류가 나왔다. 어떤 학생은 5개 축이 전부 1점이었는데 답변이 이랬다.

> **첫 질문:** "시간이라는 형식이 깨지지 않기 위해서입니다." (한 문장)
> **마지막 질문:** 질문 문장을 그대로 복사해 붙임

**실력이 아니라 응시를 안 한 것이다.** 그런데 시스템은 "전 항목 1점"이라는 실력 판정을 냈고, 그게 "기초가 없는 학생"으로 이어진다. **같은 학생이 다른 세션에서는 4~5점을 받았다.**

판정 재료는 이미 다 있다.

| 신호 | 기준 (가정값) |
|---|---|
| 답변 길이 | 질문당 20자 미만이 절반 이상 |
| 질문 복붙 | 답변이 질문 문장과 거의 같음 |
| 소요 시간 | 질문당 15초 미만 |

**위험 목록에는 눈에 띄게 올린다.** 못하는 것보다 **안 하는 것**이 더 급하고, 개입 방법도 다르다 — 학습 지원이 아니라 면담이다.

### 8-5. 유형이 켜지는 시점

| 시점 | 무엇이 보이나 |
|---|---|
| **미프 1차** | **"관찰"** — 유형 없이 낮은 학생만 표시 |
| **미프 2차** | 단계 하락 확정 |
| **미프 3차** | 지속 저점 확정 |

1회차만 보고 판정하지 않는다는 원칙과 표본 부족 시 가짜 수치를 만들지 않는다는 원칙을 지키면 첫 미프 직후엔 아무 유형도 안 켜진다. 그런데 목적이 "못 따라오는 학생을 일찍 찾는 것"이라 공백을 메워야 한다.

**미프가 4~7일씩이니 1차 관찰은 1주차, 확정은 2주차다.** 충분히 이르다.

## 9. 학생에게 무엇을 보여주나

**점수는 보여주지 않는다. 학습목표별 도달 상태를 보여준다.**

> "Service와 Ingress의 역할 분리에서, 왜 그렇게 했는지는 설명했지만 언제 문제가 되는지는 확인되지 않았습니다. 교안 3장(36~46쪽)을 보고 다시 응시하세요."

숫자가 없고, 사유가 있고, 무엇을 공부해야 하는지도 있다.

**히트맵은 학생에게 보여주지 않는다.** 자기 위치를 반 평균 대비로 보게 되면 낙인 문제가 생긴다.

### 피드백은 막힌 만큼 두꺼워진다

계단은 학생마다 다른 수의 질문을 준다. 그대로 두면 **도움이 가장 필요한 학생이 가장 적게 받는다** — 잘하는 학생은 최대 12개 질문을 받고 못하는 학생은 3개를 받는다. 설명하는 것 자체가 학습이므로 격차가 벌어진다.

**막힌 단계에 대한 해설과 교안 위치를 리포트에서 제공한다.**

| | 측정 | 피드백 | 총량 |
|---|---|---|---|
| 못하는 학생 | 짧음 (9~15분) | **두꺼움** | 비슷 |
| 잘하는 학생 | 김 (30분) | 얇음 | 비슷 |

**받는 것의 총량이 비슷해지고 내용이 반대로 배분된다.** 잘하는 학생에게는 더 어려운 질문을, 못하는 학생에게는 더 많은 설명을.

|---|---|
| **"도달" 판정 기준** — 루브릭 몇 점 이상을 도달로 볼지 | 재측정 후. 지금은 **3점 이상**을 가정값으로 |
| **정렬 가중치** (1.0 / 0.7 / 0.4) | 운영 데이터로 조정 |
| **단계별 시간 예산** (3+2+2+3분) | 재측정 후 조정 |
| **무효 응시 임계값** | 실제 답변 분포 확인 후 |

**첫 항목이 가장 중요하다.** "도달"의 경계가 정해져야 이 문서 전체가 작동한다.

### 개발 전에 확인할 것 — 위계 검증 (1시간)

**계단의 전제는 "1→2→3→4가 위계"라는 것이다.** 이게 성립하지 않으면 계단이라는 발상 자체가 무너진다. LLM도 코드도 필요 없다.

팀원 2~3명이 각자 **자기가 최근에 쓴 코드 한 군데**를 고르고, 다른 사람이 옆에서 순서대로 묻는다.

1. 이게 무슨 일을 하는 코드인가요? 어디랑 연결되나요?
2. (상황을 하나 던지고) 이러면 어떻게 되나요?
3. 다른 방식으로 할 수도 있었을까요?
4. 그 대안들 중에 왜 지금 방식을 골랐나요?

묻는 사람은 답변마다 **"여기까지는 됐다 / 여기서 막혔다"** 만 표시한다.

| 관측 | 뜻 | 대응 |
|---|---|---|
| 순서가 안 뒤집힘 · 두 사람의 판정이 일치 | 위계 성립 | **계단으로 간다** |
| **특정 순서가 일관되게 뒤집힘** | 순서가 틀렸다 | **순서를 교체한다** (폐기 아님) |
| 사람마다 다른 순서로 뒤집힘 | 위계가 아니다 | **계단을 버리고 5축을 다듬는다** |

**두 번째와 세 번째를 구분하는 것이 중요하다.** 한 순서가 일관되게 뒤집히면 그건 계단이 틀린 게 아니라 순서가 틀린 것이다.

**3명 × 20분이면 끝난다.** 이때 나온 대화 기록이 그대로 질문 생성 프롬프트의 참고 예시가 된다.

## 부록. 5축 루브릭 원문

도달 판정과 리포트 서술에 쓴다. 새로 쓰지 않는다 — 이 문장들은 실무 관찰이 들어가 있어서 다시 쓰면 이 수준이 안 나온다.

**코드 이해** (1단)
5: 구성 요소 간 관계와 데이터 흐름을 정확히 설명 / 4: 흐름은 맞지만 일부 연결 관계 불명확 / 3: 각 구성 요소는 알지만 연결 관계 설명 불가 / 2: 개별 요소 설명은 가능하나 전체 구조 파악 안 됨 / 1: "그냥 이렇게 했습니다" 수준

**반례 대응** (2단)
5: 반례를 스스로 먼저 언급하거나 던졌을 때 즉각 인지 / 4: 반례를 이해하고 부분적 대응 가능 / 3: 이해는 하나 대안 없음 / 2: 인지했지만 "문제없다"고 주장 / 1: 던져도 이해 불가

**대안 비교** (3단)
5: 구체적인 기술적 대안을 즉시 제시 / 4: 방향은 명확하나 구현 방법 일부 불명확 / 3: 존재는 알지만 구체화 못함 / 2: 탐색 시도 없이 현재 방식 고수 / 1: 대안이라는 개념 자체를 이해 못함

**설계 논리** (4단)
5: 설계 의도와 제약조건(성능/시간/팀 상황 등)을 연결해 명확히 설명 / 4: 설계 의도는 설명하나 제약조건과의 연결은 부분적 / 3: "이렇게 하면 될 것 같아서"처럼 의도는 있으나 근거가 약함 / 2: **의도를 물으면 사후적으로 짜맞추는 티가 남** / 1: 왜 이렇게 했는지 설명 자체를 못함

**자기 수정** (판정 제외 · 관찰 항목)
5: 4개 신호 전부 제시 / 4: 자기오류인식 포함 3개 / 3: 자기오류인식만 있고 나머지 중 1개 / 2: 자기오류인식 없이 새판단이나 개선안만 / 1: 반례를 제시해도 오류를 전혀 인정 안 함

> **자기 수정 5점에서 "스스로"라는 조건을 뺐다.** 질문이 유도하도록 설계돼 있는데 자발성을 채점할 수는 없다. 실제로 "4개 신호 전부 제시"라고 적히고도 4점을 받은 사례가 있었다.
