## 결정 기록


## MG08-1 · MG-08 "다시 보기 대상" 판정 기준 정정 — `reach < 4` → `reach < 2`

- **배경:** 사용자가 결과 탭을 실제로 훑어보다 다시 보기 대상이 과다 선정된 것을 발견 — "2단 도달 시엔 대상이 아니고, 2단 도달에 실패했을 때만 대상"이라고 정정 지시. 코드는 `concept()`에서 `retryTarget: inCode && reach < 4`로, **4단(전부 자력 도달)이 아니면 전부 대상**이 되고 있었다.
- **검산:** mif-3 mock 데이터(9명) 기준 이전 규칙으론 8/9명이 대상이었다. `reach < 2`로 고치니 실제로 2단 미만인 3명(hitl 0~1단 그룹)만 남는다 — "너무 많이 걸린다"던 증상과 정확히 맞물린다.
- **판단:** `concept()`의 `retryTarget` 계산식을 `inCode && reach < 2`로 수정(`mockData.ts`). 기존에 수동으로 `retryTarget: true`를 박아둔 항목(t1 hitl, reachLevel 1)은 새 기준에서도 그대로 참이라 변경 불필요.
- **⚠ 발견한 문서 충돌:** `docs/plan/v1/definition/12-scoring-rules.md:361` "3문제 중 **2단 이하**인 학습목표만 재시험"은 경계값이 다르다(2단 자체도 포함). 이번 지시는 2단 도달을 제외하므로 v1 문서와 어긋난다 — v1은 구버전 스펙이라 이번 사용자 지시를 최신 기준으로 보고 반영했다. v1 문서 자체는 손대지 않았다(범위 밖).
- **목적·효과:** 매니저가 결과 탭에서 실제로 도움이 필요한 인원만 다시 보기 대상으로 보게 된다 — 과다 선정으로 "누구를 챙겨야 하는지"가 묻히는 문제를 없앤다.

## MG08-2 · 다시 보기 발송 — 기한 수동 지정 + 발송 현황 표

- **배경:** 두 건을 사용자가 연달아 지시. ① "다시 보기 날짜 시간을 매니저가 직접 정할수 있게 해줘" — 전엔 `+3일 18:00` 계산값을 문구로만 보여줬다. ② 발송 직후 "다시보기를 보내도 이전 창에 변화가 없어" — 발송해도 좌측 요약이 카운트 문구 하나(`N명 · 아직 보내지 않음`)로만 바뀌어 **누구에게 보냈는지 · 기한이 언제인지 · 응시했는지**가 전혀 안 보였다.
- **판단:**
  - `RetrySendDialog.tsx`에 날짜(Popover+Calendar) + `<input type="time">` 필드를 추가했다. 기본값은 그대로 +3일 18:00, 매니저가 자유롭게 바꿀 수 있다. 지난 날짜는 고를 수 없게 막았다(`disabled: [{ before: TODAY }]`).
  - 이 조합은 `SchedulePicker.tsx`(operator/projects, 팀장님 소유)가 이미 쓰는 패턴과 같다 — 교차 import가 막혀 있고(oxlint) 파일 소유권도 달라(CLAUDE.md §7) 가져다 쓸 수 없어 필요한 만큼만 복제했다.
  - `mockData.ts` `PersonResult`에 `retryDueAt`(발송 시 고른 기한)·`retryTakenAt`(다시 응시를 실제로 마친 시각) 두 필드를 추가. `sendRetry(id, traineeIds, dueAt)`가 발송 대상 전원에 `retrySentAt`과 함께 `retryDueAt`을 저장한다.
  - `ResultTab.tsx` "다시 보기" 영역을 카운트 문구 하나에서 **표**로 바꿨다 — 발송된 사람만 이름·기한·응시 여부(배지) 3열로, 미발송 인원은 그 아래 발송 버튼과 함께 남는다.
  - mif-3 mock에 시연용 상태 3종을 시드했다(임채원=발송+응시완료, 한소율=발송+미응시, 김민준=미발송) — 브라우저로 세 상태 전부 렌더 확인.
- **검산:** 브라우저에서 직접 미발송 대상(김민준)에게 발송 → 모달이 닫히자마자 표에 "김민준 · 2026-07-21(화) 18:00 · 미응시"가 추가되고 상단 카운트가 "발송 3명 · 미발송 0명"으로 바뀌며 발송 버튼이 사라짐(더 보낼 대상 없음)을 확인 — "화면이 안 바뀐다"던 증상이 재현되지 않는다.
- **목적·효과:** 매니저가 기한을 상황에 맞게 조정할 수 있고, 발송 후에도 누가 언제까지 무엇을 해야 하는지·했는지를 그 자리에서 바로 확인한다.

## MG08-3 · 결과 탭 이름·카드 정정 + 제출 현황 표 실측 오버플로 수정

- **배경:** 사용자가 결과 탭 스크린샷을 보고 4건 지적. ①"반 종합"이라 적혀 있는데 반 관련 통계가 없다(이 프로젝트는 A·B·C반이 섞여 있어 원래 "반" 단위가 아니었다). ②"막힌 개념 2개 이상"이 뭘 뜻하는지, "다시 보기 대상"과 무슨 관계인지 불분명. ③"D-19h" 표기가 다른 항목("D-2일" 등)과 단위가 안 맞고 실제로 안 쓰는 말투다. ④ 팀 행의 "✓2·✗1"(요구사항 충족)이 그 아래 개인 행에도 토씨 하나 안 틀리고 반복돼 있는데 뭘 가리키는지 안 밝혀져 있었다.
- **판단:**
  - `ResultTab.tsx`: "반 종합" → **"프로젝트 종합"**(사이드바 탭·헤더 전부). 반별 통계를 새로 넣는 대신 이름을 실제 내용에 맞췄다 — 반 × 개념 분포는 이미 MG-02 히트맵 소관으로 분리돼 있어 여기 넣으면 책임이 겹친다.
  - "막힌 개념 2개 이상" 카드 삭제 → **"불합격 인원"**(`retryTargetCount`, 개념 1개 이상 2단 미달)으로 교체. **"다시 보기 대상"**은 그 값에 **"마감이 지나도록 응시를 시작도 안 한 인원"**(`notStartedCount`, `AttendanceStatus.NOT_STARTED` 집계)을 더한 값으로 재정의(사용자 지시) — `mockData.ts`의 `ProjectResult`에 `notStartedCount` 필드 신규, `stuckTwoPlusCount`는 이제 아무 데서도 안 써서 제거. `BLOCKED`(코드 분석이 안 끝나 응시 자체가 안 열린 상태)는 여기 안 센다 — 그건 독촉 대상이지 다시 보기 대상이 아니다(타입 주석에 이미 있던 구분).
  - `mockData.ts` `MIF3_ATTENDANCE`의 `'D-19h'` → **`'19시간 남음'`**. 다른 항목은 전부 "D-N일"(일 단위)인데 이것만 시간 단위를 "D-"에 억지로 붙인 비표준 표기였다.
  - `SubmissionTab.tsx` 개인 행의 요구사항(✓·✗) 셀을 비웠다 — 요구사항은 "같은 코드를 쓰는 팀 단위" 값이라 팀 행 한 곳에만 있으면 충분하다(정의서 §3에도 이미 그렇게 정의돼 있었는데 구현이 개인 행에도 중복 출력하고 있었다).
  - **부수 발견·수정:** "19시간 남음"으로 바꾸자 제출 현황 표가 실측 712px vs 컨테이너 669px로 가로 오버플로가 났다(주범은 사실 레포 URL 열 — 이미 전부터 넘치고 있었는데 스크롤로 가려져 있었다). "레포·제출자" 셀을 URL만 말줄임(`truncate`, `title` 툴팁)되게 하고 제출자 이름은 항상 끝까지 보이도록 flex로 분리해 669px 안에 맞췄다(D22 기준 — 실측 후 조정, 지어내지 않음).
- **검산:** 브라우저에서 `container.scrollWidth > clientWidth`를 직접 측정 — 수정 전 712/669(오버플로), 수정 후 669/669(오버플로 없음). "프로젝트 종합"·"불합격 인원 3명" 렌더 확인, 리포트 발행 후 "다시 보기 대상 6명(불합격 3+미응시 3)"·캡션 "불합격 + 미응시" 확인. 제출 현황 표에서 이서준 행 "응시 가능 19시간 남음" 전체 노출, 팀 행에만 "✓·✗"가 있고 개인 행엔 빈칸인 것 확인.
- **목적·효과:** 카드 이름과 값이 실제로 보여주는 내용과 일치하고, 다시 보기 대상이 "응시했지만 떨어진 사람 + 아예 안 본 사람"을 모두 담아 매니저가 누락 없이 챙길 수 있다.

## MG08-4 · 제출 현황 컬럼 재구성 + 발행 게이팅 2건 (마감 전 경고·다시 보기 발행 후 전용)

- **배경:** 사용자가 6건을 한 번에 지적. ①"D-2일"이 다른 표기와 안 맞고 "응시가능 D-2일"이 라벨·값 구분이 안 됨. ②다시 보기 발송이 리포트 발행 전에도 가능해서 "다시 보기 대상" 카드가 "발행 후 정해짐"이라 숨겨둔 숫자로 보낼 수 있는 모순. ③리포트 발행에 마감 전 클릭을 막는 확인이 없음. ④"제출 · 분석"·"응시" 헤더가 서로 다른 두 축(제출 시각/분석 결과, 응시 상태)을 한 헤더에 욱여넣고 있었음. ⑤분석완료 배지가 팀 이름 칸에 얹혀 있어 어느 열 소속인지 불분명. ⑥제출 열의 날짜·시간이 이름 칸에 텍스트로 붙어 있어 왼쪽으로 쏠려 보이고, 팀 행만 있고 개인 행엔 그 사람이 실제로 응시를 마친 시각이 없었음.
- **판단:**
  - `mockData.ts` `MIF3_ATTENDANCE`의 `'D-2일'`류 → `'D-2'`(일 접미사 제거), `SubmissionTab.tsx`의 `AttendanceCell`이 라벨과 기한을 `"/"`로 갈라 그린다("응시 가능 / D-2", "응시 가능 / 19시간 남음").
  - `ResultTab.tsx`의 "다시 보기" 섹션(표+발송 버튼) 전체를 `result.reportPublished`로 게이팅. 발행 전엔 "다시 보기는 리포트 발행 후에 보낼 수 있어요" 안내만 보인다.
  - `mockData.ts`에 `deadlinePassed(dueAt, now)` 헬퍼 신규(마감 없으면 항상 true). `ProjectDetailScreen.tsx`가 `project.dueAt`을 `ResultTab`에 내려주고, "리포트 발행" 클릭 시 마감이 안 지났으면 바로 발행하지 않고 `AlertDialog`로 확인("그래도 발행"을 눌러야 `publishReport` 호출)받는다. 마감이 지났으면(대부분) 평소처럼 즉시 발행.
  - `SubmissionTab.tsx` 헤더 "제출 · 분석"→**"제출"**, "응시"→**"분석 · 응시"**. 팀 행의 이름 칸에 colSpan으로 얹혀 있던 제출 시각·분석 배지를 각자 칸으로 뺐다 — "제출" 열은 팀 행=제출 시각·개인 행=그 사람의 응시 완료 시각(`PersonAttendance.completedAt` 신규 필드), "분석 · 응시" 열은 팀 행=분석 배지·개인 행=응시 상태.
- **검산:** `/tmp` 격리 tsc·oxlint·prettier·vite build 전부 통과. 브라우저에서 ①"응시 가능 / D-2"·"응시 가능 / 19시간 남음" 렌더 ②발행 전엔 다시 보기 섹션이 안내 문구로만 보이고 발행 버튼/표가 없음 ③mif-3 dueAt을 임시로 미래로 바꿔(`2026-07-25`) "제출 마감 전인데 발행할까요?" 경고 팝업 확인 → "그래도 발행" 눌러 정상 발행 → dueAt 원복(`2026-07-16`) ④제출 현황 표에서 팀 행=제출 시각, 개인 행=응시 완료 시각(예: 강지우 `2026-07-14 10:20`), 분석완료 배지가 "분석 · 응시" 열로 이동 확인.
- **목적·효과:** 표기가 일관되고, 발행이라는 확정 행위 앞뒤로 되돌리기 힘든 실수(마감 전 발행·미공개 숫자로 발송)를 한 번 더 막는다.
- **확인 문구가 이제 사실과 맞는다** — 어느 반이 비는지 이름을 대고(`A반이(가) 담당 없음이 됩니다`), *"다시 활성화해도 담당 반은 자동으로 돌아오지 않습니다"* 를 적는다. 그 사이 다른 사람이 맡았을 수 있어 되돌리는 것은 배정이지 상태가 아니다.

- **연결:** [[OP06-8]] OP06-7 구현 · [[OP06-6]] 이메일 열 분리 · [[OP06-3]] 명단 탭

## MG08-5 · "다시 보기" → "재응시" 용어 통일 + 발송 버튼 상시 노출 + `retryStatus()` 단일 원천

- **배경:** 사용자가 결과 탭·재응시 발송 모달 스크린샷을 보고 3건 지적. ①"다시 보기"라는 말을 전부 "재응시"로 바꿔달라(카드 라벨 "다시 보기 대상"→"재응시 대상", 섹션·버튼 "다시 보기 발송"→"재응시 발송"). ②전원에게 발송을 마치면 `ResultTab.tsx`의 발송 버튼 자체가 사라져서 모달을 다시 열 방법이 없다 — 없어지지 말고 눌러서 열 수 있어야 한다. ③`RetrySendDialog.tsx`에서 발송된 사람에게 하드코딩해 붙이던 "이미 다시 봤어요"가 사실과 다르다 — 그건 **발송됐다**는 뜻이지 **실제로 다시 봤다**는 뜻이 아니다. 이전 화면(`ResultTab`)의 응시 여부 3분류(재응시 가능/재응시 발송 완료/재응시 완료)와 같게 맞춰달라.
- **판단:**
  - 용어 치환은 **사용자에게 보이는 문구만** 대상으로 했다 — `retryTarget`·`retrySentAt`·`retryTakenAt`·`sendRetry`·`retryConceptNames` 같은 코드 식별자는 바꾸지 않았다(의미가 같고 전면 리네임은 diff만 커진다). `mockData.ts`의 관련 주석, `PersonResultPanel.tsx`의 배지("재응시 대상"), `SubmissionTab.tsx` docblock 한 줄, `RetrySendDialog.tsx`의 제목·빈 상태 문구, `ResultTab.tsx`의 카드 라벨·안내문·섹션 헤더·버튼 문구까지 전부 갈았다.

## MG08-6 · 독촉 모달 — "미응시" 그룹을 "기한 임박"으로 교체 + 범위 확대

- **배경:** 사용자 지시 — "여기서 미응시 대신에 기간이 얼마 남지 않은 인원들에게 독촉을 보내는걸로 교체하자. 범위는 응시 완료한 개인을 제외한 모든 개인들에게 '응시 가능한 날짜가 N일 남았습니다.'" 전엔 `NudgeDialog.tsx`의 세 번째 그룹이 `NOT_STARTED`(응시를 아예 시작 안 한 사람)만 대상이었고, 이미 응시 창이 열려 카운트다운 중인 `AVAILABLE` 인원은 독촉 대상에 없었다.
- **판단:**
  - 대상을 `status === 'NOT_STARTED'` 단독에서 **`AVAILABLE` ∪ `NOT_STARTED`**로 넓혔다(`dueSoon`) — "기간이 얼마 남지 않았다"는 말이 실제로 맞으려면 이미 카운트다운 중인 `AVAILABLE`도 포함해야 한다.
  - **`BLOCKED`는 사용자 지시("응시 완료한 개인을 제외한 모든 개인")를 문자 그대로 따르면 포함되지만, 판단으로 뺐다.** `BLOCKED`는 타입 주석 그대로 "코드가 없거나 분석이 실패해 응시 자체가 열리지 않은 상태"라, "응시 가능한 날짜가 N일 남았습니다"를 보내면 응시가 가능한 것처럼 사실과 다르게 말하는 꼴이 된다 — [[MG08-5]]의 "이미 다시 봤어요" 오표기와 같은 종류의 문제라 같은 원칙(사실과 다른 문구는 안 보낸다)으로 제외했다. 필요하면 확인받고 되돌린다.
  - `NOT_STARTED`는 `mockData.ts`에서 애초에 `deadlineLabel: null`이었다(독촉 문구에 넣을 "N일"이 없었다). **같은 팀의 `AVAILABLE` 팀원과 같은 값을 채워 넣었다** — 응시 창은 "팀의 코드 분석 완료 시점"에 한 번에 열리므로(`docs/plan/v2/14-verification-design.md` "응시 창의 기산점은 제출이 아니라 코드 분석 완료") 같은 팀이면 마감도 같다. 2팀(t9·t10·t11) → t11=D-2(t10과 동일), 3팀(t1·t2·t3) → t3=19시간 남음(t2와 동일), 7팀(t18·t19·t20) → t20=D-1(t19와 동일). 추측이 아니라 팀 배정 데이터에서 역산한 값이다.
  - 그룹 제목 "미응시 N명" → **"기한 임박 N명"**, `names`에 각자의 `deadlineLabel`을 괄호로 붙여 보여준다("오태양(D-2) · 신다은(D-2) · …") — 문구 자체("응시 가능한 날짜가 N일 남았습니다")는 상태별 고정 템플릿(`mockData.ts` "독촉 — 상태별 고정 문구" 원칙)이라 그대로 두고, 매니저가 누가 얼마나 급한지는 이름 옆 라벨로 확인한다.
  - **부수 발견·수정:** `groupCount` 계산식이 `checkUnsub`·`checkFailed`만 세고 세 번째 그룹(`checkNotStarted`)을 애초부터 빠뜨리고 있었다 — 3그룹을 전부 체크해도 하단 요약이 "2그룹"으로 떴다(사용자가 준 스크린샷에서 "2그룹 · 11명"으로 실제로 나타나 있었음). `checkDueSoon && dueSoon.length > 0`을 배열에 추가해 고쳤다.
- **검산:** `/tmp` 격리 tsc·oxlint·prettier·vite build 전부 통과. 브라우저에서 ①제출 현황 표의 신다은·정하늘이 "미응시 / D-2"·"미응시 / 19시간 남음"으로 팀원과 같은 기한을 보여줌 ②독촉 모달에서 "기한 임박 7명 — 오태양(D-2)·신다은(D-2)·이서준(19시간 남음)·정하늘(19시간 남음)·노은채(D-1)·백승민(D-1)·유리안(D-3) 개인에게 — '응시 가능한 날짜가 N일 남았습니다'" 렌더 ③세 그룹 전부 체크 시 "3그룹 · 15명에게 발송"으로 정확히 집계(수정 전이었다면 "2그룹") 확인.
- **목적·효과:** 독촉이 "아예 안 한 사람"뿐 아니라 "곧 기한을 놓칠 사람"까지 챙기게 됐고, 사실과 다른 문구(응시 자체가 안 열린 사람에게 "응시 가능"이라 말하는 것)를 보내지 않으며, 그룹 카운트 표시도 실제 발송 범위와 일치한다.

## MG08-7 · 발송 완료 체크박스를 항상 잠긴 채 체크 표시 + 독촉 문구를 남은 시간 단위로 유동화

- **배경:** 사용자가 두 화면 스크린샷을 보고 지적. ①`RetrySendDialog.tsx`에서 이미 발송된 사람(예: 김민준)의 체크박스가 **체크된 채 잠기지 않고 빈 채로 잠겨** 있었다 — "포함돼 있어서 못 뺌"과 "안 담겨서 못 넣음"은 다른 뜻인데 후자로 보였다. ②[[MG08-6]]에서 만든 "기한 임박" 독촉 문구가 "응시 가능한 날짜가 N일 남았습니다"로 고정이라, 실제로는 "응시 가능한 기간이 N일, 24시간 미만일 경우 N시간 남았습니다"처럼 **남은 시간에 따라 단위(일/시간)가 유동적으로 바뀌어야** 한다.
- **판단:**
  - `RetrySendDialog.tsx`의 체크박스 `checked` prop을 `checked.has(id)` 단독에서 **`p.retrySentAt ? true : checked.has(id)`**로 바꿨다. 원인은 `checked` state가 다이얼로그를 처음 연 시점의 미발송자 목록으로만 초기화되고(useState 초기화 함수), 발송 후 다이얼로그가 리마운트 없이 갱신되면 그 사람의 체크 여부가 "발송 당시 체크돼 있었는지"에 따라 달라 세션마다 다르게 보였다 — 이제 `retrySentAt`이 있으면 내부 Set 값과 무관하게 항상 체크된 채로 그린다.
  - `mockData.ts`에 **`dueSoonMessage(deadlineLabel)`** 함수를 신규 — `"D-N"`은 `"응시 가능한 기간이 N일 남았습니다"`, `"N시간 남음"`은 `"응시 가능한 기간이 N시간 남았습니다"`로 변환(정규식 매칭). `NudgeDialog.tsx`의 "기한 임박" 그룹은 이제 이 함수로 계산한 문구가 **같은 사람끼리 묶어 문구별로 한 줄씩** 보여준다(`groupByDueSoonMessage`) — 기존 `GroupRow`는 그룹 전체가 문구 하나를 공유하는 구조라 사람마다 단위가 다른 이 그룹엔 안 맞아, 이 그룹만 별도로 렌더링했다. 문구 자체는 여전히 `dueSoonMessage(deadlineLabel)` 하나로 결정되는 상태별 고정값이라 "독촉 — 상태별 고정 문구, 커스텀 없음" 원칙은 안 깨졌다.
- **검산:** `/tmp` 격리 tsc·oxlint·prettier·vite build 전부 통과. 브라우저에서 ①`RetrySendDialog`를 다시 열어 김민준·임채원·한소율 **셋 다** 체크된 채 표시(임채원·한소율은 비활성) 확인 ②독촉 모달에서 "기한 임박 7명" 아래 "오태양·신다은 개인에게 — '응시 가능한 기간이 2일 남았습니다'" / "이서준·정하늘 개인에게 — '…19시간 남았습니다'" / "노은채·백승민 개인에게 — '…1일 남았습니다'" / "유리안 개인에게 — '…3일 남았습니다'" 4줄로 정확히 갈려 렌더됨을 확인.
- **목적·효과:** 체크박스 표시가 "발송 여부"라는 사실 하나로만 정해지고, 독촉 문구가 실제 남은 시간과 항상 맞게 나간다.

## MG08-9 · 잠긴 체크박스 회색 표시(공용 Checkbox의 `disabled:` 무동작 발견) + 재응시 발송 취소 기능

- **배경:** 사용자가 두 가지를 요청. ①[[MG08-7]]에서 발송완료 체크박스를 "항상 체크된 채로 잠근다"로 고쳤지만 색은 활성 체크와 똑같은 파랑이라 "클릭했을 때와 다른, 회색배경의 비활성화된 체크로 바꿔달라"고 지시. ②"재응시 발송을 했을 때, 재응시 발송 취소기능도 넣어줘, 재응시 완료한 경우는 제외"로 지시 — 발송만 되고 아직 안 본 사람(재응시 발송 완료)은 취소할 수 있어야 하고, 이미 다시 응시한 사람(재응시 완료)은 대상에서 뺀다.
- **판단(체크박스 색):**
  - 처음에 `disabled:data-checked:bg-neutral-soft` 같은 Tailwind `disabled:` 변형으로 덮어썼는데 **브라우저에서 전혀 안 먹혔다.** `getComputedStyle`로 직접 재보니 원인은 Base UI `Checkbox.Root`가 **`<span role="checkbox">`로 렌더돼 네이티브 `disabled` 속성 자체가 없고**, 비활성은 `data-disabled` 어트리뷰트로만 표시한다는 것 — Tailwind `disabled:`는 `:disabled` 가상 클래스라 `<span>`엔 애초에 매칭될 수 없다. **공용 `components/ui/Checkbox.tsx`의 `disabled:opacity-50`·`disabled:cursor-not-allowed`도 같은 이유로 처음부터 한 번도 작동한 적이 없었다**(실측 확인 — 비활성 체크박스가 opacity 1로 항상 완전 불투명이었다).
  - `RetrySendDialog.tsx`에서 선택자를 **`data-disabled:data-checked:*`**(어트리뷰트 선택자, 항상 매칭)로 고쳐 `neutral-soft` 배경·`border-strong` 테두리·`fg-subtle` 체크 아이콘으로 덮었다. `[data-disabled][data-checked]`는 2속성 선택자라 원래 `data-checked:bg-primary`(1속성)보다 스타일시트 순서와 무관하게 항상 우선한다.

## MG08-11 · PR 첫 CI 실패 2건 — (1) `tsc --noEmit -p .` 검산이 사실 아무것도 안 검사했음 (2) `bigp` 되돌림이 팀장님의 제품 결정을 되돌리는 셈이라는 것 확인
